17:47 Swift Testing has some similarities to XCTest,
17:49 but it also some important differences to be aware of.
17:52 Let’s compare three of the building blocks from earlier,
17:54 test functions, expectations, and suites.
17:58 Tests in XCTest are any method whose name begins with “test”.
18:02 But Swift Testing uses the @Test attribute to denote them explicitly,
18:06 so there’s no ambiguity.
18:08 Swift Testing supports more kinds of functions,
18:11 so you can still use instance methods in a type,
18:13 but also static or global functions if you prefer.
18:16 Unlike XCTest, Swift Testing supports traits
18:19 for specifying information either per-test or per-suite.
18:23 And Swift Testing takes a different approach to parallelization:
18:26 it runs in-process using Swift Concurrency,
18:29 and supports physical devices like iPhone and Apple Watch.
18:34 Expectations are very different between these two systems.
18:37 XCTest refers to this concept as assertions,
18:40 and it uses many functions beginning with XCTAssert to denote them.
18:44 Swift Testing takes a different approach:
18:47 it has just two basic macros — #expect and #require.
18:51 Instead of needing many specialized functions,
18:53 you can pass in ordinary expressions
18:55 and language operators to #expect or #require.
18:58 For example, you can use double-equals to check equality,
19:01 or the greater-than operator to compare two values.
19:05 And you can easily use
19:06 the opposite operator to negate any expectation.
19:11 Halting a test after a test failure occurs is also handled differently.
19:15 In XCTest,
19:16 you assign the continueAfterFailure property to false,
19:19 and then any subsequent assertion which fails will cause the test to halt.
19:23 In Swift Testing, any expectation can be made into a required one

19:40 XCTest only supports classes and they must inherit from XCTestCase.
19:45 In Swift Testing, you can use a struct, actor, or class,

19:55 Suites may be denoted explicitly by the @Suite attribute,
19:59 although it’s implicit for any type
