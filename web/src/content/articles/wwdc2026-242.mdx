## Highlight

> Dynamic Profiles 让同一个 `LanguageModelSession` 在不同阶段自动切换模型、工具和 Prompt——头脑风暴用高 temperature 的云端模型，审查阶段切到端侧模型，上下文自动裁剪，不再需要手写状态机管理 Agent 工作流。

---

## 核心内容

### 1. 这场演讲解决什么问题

用 LLM 做复杂任务时，开发者通常遇到三个难题：

1. **上下文爆炸**：长对话历史超出模型窗口，导致早期信息丢失或 token 费用飙升。
2. **能力错配**：简单任务用了大模型浪费资源，复杂任务用小模型质量不够。
3. **状态管理混乱**：手动维护多个 Session、拼接 Prompt、截断 Transcript，代码脆弱且容易出错。

Apple 的解法是 **Dynamic Profiles**——在同一个 Session 内，根据应用状态动态切换模型配置、工具集和 Prompt，同时提供声明式的上下文管理机制。

---

### 2. DynamicInstructions：条件化指令

`DynamicInstructions` 让你根据应用状态决定包含哪些指令和工具：

```swift
struct BrainstormFacilitator: DynamicInstructions {
    var orchestrator: CraftOrchestrator

    var body: some DynamicInstructions {
        Instructions {
            "You are a warm and friendly expert crafting brainstorm facilitator."
        }
        // 工具
        GenerateProjectTitle()
        // 条件化包含专业知识
        if orchestrator.techniques.contains(.origami) {
            OrigamiExpert()
        }
    }
}
```

关键点：

- `if` 语句让指令和工具可以条件化包含。
- 只有当 `orchestrator.techniques` 包含 `.origami` 时，`OrigamiExpert` 工具才会被注册。
- 这比手动拼接 Prompt 字符串更类型安全、更可维护。

---

### 3. DynamicProfile：阶段化模型配置

`DynamicProfile` 是 `DynamicInstructions` 的进阶版，可以切换模型和生成参数：

```swift
struct CraftProfile: LanguageModelSession.DynamicProfile {
    var orchestrator: CraftOrchestrator

    var body: some DynamicProfile {
        switch orchestrator.mode {
        case .brainstorming:
            Profile { BrainstormFacilitator(orchestrator: orchestrator) }
                .model(orchestrator.pccLanguageModel)
                .temperature(1)
        case .planning:
            Profile { TutorialAuthor(orchestrator: orchestrator) }
                .model(orchestrator.pccLanguageModel)
                .reasoningLevel(.deep)
        case .reviewing:
            Profile { CraftCoach() }
                .model(orchestrator.systemLanguageModel)
        }
    }
}

// 使用
let session = LanguageModelSession(profile: CraftProfile(orchestrator: orchestrator))
```

关键点：

- `switch` 根据 `orchestrator.mode` 切换完全不同的配置。
- 头脑风暴阶段用高 temperature（创造力强）、云端模型（能力强）。
- 审查阶段用端侧模型（响应快、零成本）。
- 切换 Profile 时，对话历史（transcript）默认保留，模型不会失忆。

### 4. Transcript 管理：自动裁剪历史

长对话会超出模型上下文窗口。Dynamic Profile 提供了 `historyTransform` 来自动裁剪：

```swift
struct CraftProfile: LanguageModelSession.DynamicProfile {
    var orchestrator: CraftOrchestrator

    var body: some DynamicProfile {
        switch orchestrator.mode {
        case .reviewing:
            Profile { CraftCoach() }
                .model(orchestrator.systemLanguageModel)
                .historyTransform { history in
                    guard let latestResponseIndex = lastResponseEntryIndex(history) else {
                        return history
                    }
                    // 只保留最近响应和工具调用记录
                    let filteredHistory = history[0..<latestResponseIndex].filter { entry in
                        isToolCallsOrToolOutput(entry)
                    }
                    return filteredHistory + history[latestResponseIndex...]
                }
        }
    }
}
```

**使用内置的 Utilities 包简化：**

```swift
import FoundationModelsUtilities

struct CraftProfile: LanguageModelSession.DynamicProfile {
    var orchestrator: CraftOrchestrator

    var body: some DynamicProfile {
        switch orchestrator.mode {
        case .reviewing:
            Profile { CraftCoach() }
                // 保留最近 10 条，同时丢弃已完成的工具调用
                .rollingWindow(size: .entries(10))
                .droppingCompletedToolCalls()
        }
    }
}
```

关键点：

- `rollingWindow` 限制历史条目数，防止上下文无限膨胀。
- `droppingCompletedToolCalls` 移除已经完成的工具调用记录，它们通常占用大量 token 但对后续对话价值有限。
- 这些操作是声明式的，不需要你手动拼接 Transcript。

### 5. 自定义 Modifier

你可以创建可复用的 Profile modifier：

```swift
struct DroppingToolCallsProfileModifier: LanguageModelSession.DynamicProfileModifier {
    func body(content: Content) -> some DynamicProfile {
        content
            .historyTransform { history in
                guard let latestResponseIndex = lastResponseEntryIndex(history) else {
                    return history
                }
                let filteredHistory = history[0..<latestResponseIndex].filter { entry in
                    isToolCallsOrToolOutput(entry)
                }
                return filteredHistory + history[latestResponseIndex...]
            }
    }
}

extension LanguageModelSession.DynamicProfile {
    func droppingCompletedToolCalls() -> some DynamicProfile {
        self.modifier(DroppingToolCallsProfileModifier())
    }
}
```

然后像 SwiftUI modifier 一样使用：

```swift
Profile { CraftCoach() }
    .rollingWindow(size: .entries(10))
    .droppingCompletedToolCalls()
```

### 6. Session 属性：跨 Profile 共享状态

有时候需要在不同 Profile 之间共享数据。用 `@SessionProperty`：

```swift
// 声明自定义属性
extension SessionPropertyValues {
    @SessionPropertyEntry var summary: String?
}

// 在 Profile 中读写
struct CraftProfile: LanguageModelSession.DynamicProfile {
    @SessionProperty(\.history) var history
    @SessionProperty(\.summary) var summary
    var orchestrator: CraftOrchestrator

    var body: some DynamicProfile {
        switch orchestrator.mode {
        case .planning:
            Profile {
                TutorialAuthor(orchestrator: orchestrator)
                if let summary {
                    Instructions { "Summary: \(summary)" }
                }
            }
            .onResponse {
                if history.count > 50, let responseIndex = lastResponse(history.prefix(40)) {
                    summary = try await summarize(history[0..<responseIndex])
                    history = history[responseIndex...]
                }
            }
        }
    }
}
```

关键点：

- `@SessionProperty(\.summary)` 在不同 Profile 之间共享同一个值。
- `.onResponse` 在每次模型响应后执行，可以在这里做摘要和裁剪。
- 当历史超过 50 条时，生成摘要并清空早期历史，保持上下文在窗口内。

### 7. Agent 编排模式

**Baton-pass（接力）模式**：多个 Profile 共享完整 transcript，通过工具切换当前激活的 Profile。

```swift
struct CraftProfile: LanguageModelSession.DynamicProfile {
    var orchestrator: CraftOrchestrator

    var body: some DynamicProfile {
        switch orchestrator.mode {
        case .brainstorm:
            Profile {
                BrainstormInstructions()
                BatonPassTool()
            }
            .onToolCall { orchestrator.mode = .tutorial }
            .model(orchestrator.serverModel)
        case .tutorial:
            Profile {
                TutorialInstructions()
                BatonPassTool()
            }
            .onToolCall { orchestrator.mode = .brainstorm }
            .model(orchestrator.systemModel)
        }
    }
}
```

- 头脑风暴 Profile 完成时调用 `BatonPassTool`，自动切换到教程 Profile。
- 两个 Profile 共享同一份 transcript，上下文连续。

**Phone-a-friend（求助）模式**：派生一个短生命周期的子 Session 处理子任务。

```swift
struct CraftProfile: LanguageModelSession.DynamicProfile {
    var body: some DynamicProfile {
        Profile {
            BrainstormInstructions()
            PhoneFriendTool(
                name: "generate_title",
                description: "Generate a creative project title",
                profile: TitleProfile()
            )
        }
    }
}

struct PhoneFriendTool<P: LanguageModelSession.DynamicProfile>: Tool {
    func call(arguments: GeneratedContent) async throws -> String {
        let session = LanguageModelSession(profile: profile())
        let response = try await session.respond(to: arguments)
        return response.content
    }
}
```

- 主 Session 遇到需要专业能力的子任务时，创建独立子 Session。
- 子 Session 隔离上下文，避免污染主对话历史。

### 8. 工具调用模式与防循环

控制模型何时调用工具：

```swift
struct OrigamiExpert: LanguageModelSession.DynamicProfile {
    var body: some LanguageModelSession.DynamicProfile {
        Profile {
            Instructions("You are an origami expert")
            QueryOrigamiDatabaseTool()
            ShowDirectionsTool()
        }
        .toolCallingMode(.required)
    }
}
```

工具调用模式：

- `.allowed` —— 模型可以选择是否调用工具（默认）。
- `.disallowed` —— 禁止调用工具，纯文本生成。
- `.required` —— 必须调用至少一个工具。

**防止工具调用死循环：**

```swift
struct OrigamiExpert: LanguageModelSession.DynamicProfile {
    let state: OrigamiAppState

    var body: some LanguageModelSession.DynamicProfile {
        Profile {
            Instructions("Answer questions about how to fold origami")
            QueryOrigamiDatabaseTool()
        }
        .toolCallingMode(state.queriedDatabase ? .disallowed : .required)
        .onToolCall { state.queriedDatabase = true }
    }
}
```

- 第一次必须查询数据库（`.required`）。
- 查询完成后禁止再次调用（`.disallowed`）。
- 避免模型陷入无限循环调用同一个工具。

**用异常终止工具调用：**

```swift
struct FinalAnswerTool: Tool {
    var output: String?

    @Generable struct Arguments {
        var answer: String
    }

    func call(arguments: Arguments) async throws -> Never {
        output = arguments.answer
        throw CancellationError()  // 终止后续工具调用
    }
}
```

### 9. 错误处理与 Transcript 保护

当工具调用出错时，控制 Transcript 的行为：

```swift
struct OrigamiExpert: LanguageModelSession.DynamicProfile {
    var body: some LanguageModelSession.DynamicProfile {
        Profile {
            Instructions("Answer questions about how to fold origami")
            QueryOrigamiDatabaseTool()
        }
        .transcriptErrorHandlingPolicy(.preserveTranscript)
    }
}
```

策略选项：

- `.revertTranscript` —— 出错后回滚到之前的状态（默认）。
- `.preserveTranscript` —— 保留出错后的状态，让模型有机会从错误中恢复。

也可以直接修改 Transcript：

```swift
let session = LanguageModelSession()
session.transcript = customTranscript  // 直接设置 transcript

// 注意：必须在非响应状态下修改
if !session.isResponding {
    session.transcript = filteredTranscript
}
```

## 最佳实践

- **用 DynamicProfile 替代手动状态管理**：如果你现在手动维护多个 Session、拼接 Prompt、截断 Transcript，迁移到 Dynamic Profiles。它能删掉几百行胶水代码，而且类型更安全。

- **优先用 Baton-pass 模式**：多个阶段需要共享上下文的场景，用 Baton-pass 让 Profile 接力切换。只有真正需要隔离上下文的子任务，才用 Phone-a-friend 创建子 Session。

- **防止工具调用死循环**：使用 `.required` 模式时，一定要给退出条件。条件化 `toolCallingMode`、设置状态标记、或提供抛出异常的终止工具，都是有效方案。

- **合理裁剪历史**：不要等上下文爆炸了才处理。用 `rollingWindow` 和 `droppingCompletedToolCalls` 保持 transcript 在合理大小，既省 token 又减少模型分心。

- **用 Session Property 共享状态**：跨 Profile 需要共享的数据（如摘要、用户偏好），用 `@SessionProperty` 而不是全局变量。它生命周期绑定到 Session，更安全。

- **测试不同 Profile 的切换**：确保切换 Profile 时，对话历史正确保留，工具集正确更新。这是 Agent 体验流畅的关键。
