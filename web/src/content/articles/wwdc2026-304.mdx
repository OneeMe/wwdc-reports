## Highlight

> iPhone 的 48MP 传感器已经硬件就绪，但你的 App 可能还在输出 12MP。这场演讲教你用 `AVCapturePhotoOutput` 的 `maxPhotoDimensions` 和 `photoQualityPrioritization` 来配置 24MP/48MP capture，并通过 deferred photo processing 让用户连拍时不再卡顿。

---

## 核心内容

### 1. 这场演讲解决什么问题

拍照 App 的一个常见痛点：预览流是屏幕分辨率，但用户期望得到高分辨率照片用于裁剪、放大或图像分析。iPhone 14 Pro 开始配备 48MP Quad 传感器，iPhone 15 开始支持 24MP 输出，但你的 App 可能还在用默认的 12MP。

这场演讲解决三个问题：

1. **什么时候该请求哪种分辨率** — 12MP、24MP 还是 48MP？
2. **怎么配置 capture session** 才能正确输出高分辨率？
3. **怎么处理高分辨率带来的处理延迟**，让 App 保持响应？

### 2. 四种高分辨率 capture 类型

| 类型 | 说明 | 适用场景 |
|---|---|---|
| Fully processed | 多帧融合，经过 Photonic Engine 处理 | 日常拍照，最佳画质 |
| Exposure brackets | 多张不同曝光帧 | HDR 合成，手动选曝光 |
| Bayer RAW | 传感器原始数据 | 后期处理，专业编辑 |
| Apple ProRAW | RAW + iPhone 图像处理 | 灵活编辑曝光、色彩 |

24MP 是 iPhone 15 开始的默认模式：先拍 12MP 多帧融合 HDR 图像，再与 48MP 全分辨率图像结合，输出 24MP。文件大小只比 12MP 增加约 50%，但分辨率翻倍。

48MP 是单帧输出，四倍于 12MP 的分辨率，适合需要极致细节的场景。

### 3. 配置 AVCaptureSession

关键配置点：

- **Session preset 必须是 `.photo`**，其他 preset 不支持 24MP/48MP
- **`maxPhotoQualityPrioritization`** 控制资源分配级别：`.speed`、`.balanced`、`.quality`
- **`maxPhotoDimensions`** 设置最大输出尺寸

```swift
import AVFoundation

private let session = AVCaptureSession()
private let photoOutput = AVCapturePhotoOutput()

private func configureSession() {
    session.beginConfiguration()
    session.sessionPreset = .photo
    
    // 设置为 quality 以支持所有分辨率级别
    photoOutput.maxPhotoQualityPrioritization = .quality
    
    // 选择设备支持的最大尺寸
    let supportedMaxPhotoDimensions = device?.activeFormat.supportedMaxPhotoDimensions ?? []
    if let largestDimension = supportedMaxPhotoDimensions.max(by: { lhs, rhs in
        Int(lhs.width) * Int(lhs.height) < Int(rhs.width) * Int(rhs.height)
    }) {
        photoOutput.maxPhotoDimensions = largestDimension
    }
    
    session.commitConfiguration()
    session.startRunning()
}
```

关键点：

- `supportedMaxPhotoDimensions` 从 iOS 16 开始可用，列出了当前 format 支持的所有尺寸
- 配置完成后要 `commitConfiguration()`，之后修改会触发耗时的 pipeline 重建
- `maxPhotoDimensions` 是请求而非保证，系统会根据光线、场景和可用处理能力选择最佳路径

### 4. Capture 设置与资源预分配

每次 capture 时创建新的 `AVCapturePhotoSettings`，设置当前 capture 的参数：

```swift
let settings = AVCapturePhotoSettings()
settings.maxPhotoDimensions = dimension.cmVideoDimensionsValue
settings.photoQualityPrioritization = .quality

var delegate: AVCapturePhotoCaptureDelegate?
if let delegate {
    photoOutput?.capturePhoto(with: settings, delegate: delegate)
}
```

高分辨率 capture 需要特定的资源分配。如果系统没有预先分配这些资源，会在 capture 时动态分配，导致延迟。用 `setPreparedPhotoSettingsArray` 提前告知系统你的 capture 计划：

```swift
let prepareSettings = AVCapturePhotoSettings()
prepareSettings.maxPhotoDimensions = photoOutput.maxPhotoDimensions
prepareSettings.photoQualityPrioritization = .quality

photoOutput.setPreparedPhotoSettingsArray([prepareSettings]) { prepared, error in
    if let error = error {
        print("Failed to prepare: \(error)")
        return
    }
    print("Pipeline prepared: \(prepared)")
}

// 实际 capture 时创建新的 settings，但配置要与 prepareSettings 匹配
let captureSettings = AVCapturePhotoSettings()
captureSettings.maxPhotoDimensions = photoOutput.maxPhotoDimensions
captureSettings.photoQualityPrioritization = .quality
photoOutput.capturePhoto(with: captureSettings, delegate: self)
```

关键点：

- `prepareSettings` 和 `captureSettings` 不能是同一个对象，但配置要匹配
- 在 48MP 模式激活后尽早调用 `setPreparedPhotoSettingsArray`
- 实际尺寸在 `AVCaptureResolvedSettings` 中返回

### 5. 保持 App 响应：Deferred Photo Processing

高分辨率照片处理可能需要数秒。如果等处理完成才能拍下一张，用户体验会很差。

**Photo quality prioritization 的处理时间差异：**

| 分辨率 | Speed | Balanced | Quality |
|---|---|---|---|
| 12MP | 支持 | 支持 | 支持 |
| 48MP | 不支持 | 支持 | 支持 |
| 24MP | 不支持 | 不支持 | 支持 |

**Deferred photo processing** 让系统先返回一个轻量处理的代理照片，最终处理在后台完成：

- 代理照片通过 `didFinishCapturingDeferredPhotoProxy` 回调立即交付
- 最终照片按需（从照片库请求时）或后台（设备空闲时）处理
- 不阻塞 capture pipeline，大幅降低 shot-to-shot 延迟

**Responsive capture** 允许重叠 capture：新 capture 可以在前一张照片的 capture 阶段完成后开始，不需要等处理完成。观察 `captureReadiness` 属性知道何时可以拍下一张。

## 最佳实践

- **选择合适的 prioritization**：日常用 `.balanced`，追求极致画质用 `.quality`，需要快速连拍用 `.speed`（仅限 12MP）
- **提前准备资源**：在模式切换后立刻调用 `setPreparedPhotoSettingsArray`，避免 capture 时的资源分配延迟
- **启用 deferred processing**：对于 24MP/48MP capture，这是保持响应的关键
- **检查 resolved settings**：`AVCaptureResolvedSettings.photoProcessingTimeRange` 告诉你预计处理时间
- **适配多摄像头**：24MP/48MP 支持已扩展到长焦（iPhone 16 Pro）和超广角（iPhone 17）
