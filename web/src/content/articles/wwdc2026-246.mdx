## Highlight

> `SpotlightSearchTool` 让 LLM 直接搜索你 App 的 Core Spotlight 索引，把基础搜索升级为检索增强生成（RAG）系统，几行代码就能让模型回答关于用户私有内容的问题。

---

## 核心内容

### 1. 这场演讲解决什么问题

你的 App 可能已经用 Core Spotlight 索引了用户内容，用户也能通过 Spotlight 搜索到这些内容。但 LLM 不知道这些内容的存在——当你问"我去过哪些徒步路线？"时，模型只能凭训练数据瞎猜。

这场演讲介绍 `SpotlightSearchTool`，一个让 LLM 直接搜索 Core Spotlight 索引的 tool。模型可以基于用户的实际数据来回答问题，实现真正的个性化 AI 体验。

### 2. SpotlightSearchTool 的基础用法

创建 tool 只需要一行代码：

```swift
import CoreSpotlight
import FoundationModels

// 基础配置：搜索 App 的 Core Spotlight 索引
let tool = SpotlightSearchTool()

// 自定义配置：只搜索文件路径
let fileTool = SpotlightSearchTool(
    configuration: .init(
        sources: [.files]
    )
)
```

把 tool 加入 `LanguageModelSession`：

```swift
let session = LanguageModelSession(
    model: model,
    tools: [tool],
    instructions: instructions
)

let response = try await session.respond(to: "What hikes have I gone on?")
```

模型会自动判断何时需要搜索索引，生成搜索查询，然后用搜索结果来生成回答。

### 3. 索引委托和动态加载

当模型请求特定 item 时，你需要实现 `CSSearchableIndexDelegate` 来提供完整的 searchable items：

```swift
class IndexDelegate: NSObject, CSSearchableIndexDelegate {
    func searchableItems(
        forIdentifiers identifiers: [String]
    ) async -> [CSSearchableItem] {
        let entries = await mystore.fetchEntries(ids: identifiers)
        return entries.map { makeSearchableItem(from: $0) }
    }
}
```

这种委托模式让索引可以按需加载，不需要把所有数据常驻内存。

### 4. Guidance Profile：控制搜索方向

你可以通过 Guidance Profile 告诉模型应该关注哪些属性：

```swift
let profile = SpotlightSearchTool.GuidanceProfile(
    textMatch: true,
    dates: true,
    people: false,
    attributes: [.title, .altitude, .completionDate]
)

let tool = SpotlightSearchTool(
    configuration: .init(
        guide: .init(level: .dynamic(profile))
    )
)
```

对于端侧模型（context 较小），建议使用 focused guidance：

```swift
let focusedTool = SpotlightSearchTool(
    configuration: .init(
        guide: .init(level: .focused(.items))
    )
)
```

### 5. ContactResolver：处理用户身份

如果搜索涉及联系人信息（如"我发给 Jane 的邮件"），可以实现 `ContactResolver`：

```swift
struct MyContactResolver: ContactResolver {
    func userIdentity() -> ResolvedContact {
        var contact = ResolvedContact(displayName: "Jane Doe")
        contact.emailAddresses = ["jane@example.com", "jdoe@work.com"]
        contact.names = ["Jane", "JD"]
        return contact
    }
}

tool.contactResolver = MyContactResolver()
```

### 6. 自定义 Pipeline Stage

你可以定义自定义的搜索处理阶段，比如情感分析：

```swift
@Generable
struct HappinessStage: CustomStage {
    static var name = "happiness"
    static var description = "Scores hike by how happy the author was"
    static var inputTypes: [SearchPipelineDataType] = [.items]
    static var outputTypes: [SearchPipelineDataType] = [.scoredItems]

    @Guide(description: "Minimum happiness score (0.0-1.0) to include in results")
    var threshold: Double?

    func execute(on input: SearchPipelineData) async throws -> SearchPipelineData {
        return SearchPipelineData(payload: .scoredItems(sorted))
    }
}

let tool = SpotlightSearchTool(configuration: .init(
    customStages: [.happinessBoost(threshold: 0.5)]
))
```

### 7. 搜索结果的处理

搜索结果是异步流，你可以处理不同类型的返回数据：

```swift
for await reply in tool.searchResults {
    if reply.queryToken != currentToken {
        currentToken = reply.queryToken
    }

    switch reply.content {
    case .items(let searchItems):
        // 普通搜索结果
    case .scoredItems(let scored):
        // 带分数的排序结果
    case .groupedItems(let groups):
        // 分组结果
    case .count(let count):
        // 计数结果
    case .table(let table):
        // 表格数据
    case .statistic(let statistic):
        // 统计数据
    case .text(let text):
        // 文本总结
    }
}
```

## 最佳实践

- **先确保 Core Spotlight 索引质量**：模型搜索的效果取决于索引数据的质量，确保属性完整、语义索引准确
- **使用 Guidance Profile 缩小搜索范围**：对于端侧模型，focused guidance 能显著提升搜索准确性
- **实现 IndexDelegate 按需加载**：不要一次性加载所有数据，用委托模式实现懒加载
- **用 Evaluations framework 测试搜索质量**：定义测试数据集来验证搜索结果覆盖率
- **处理 query token 变化**：用户输入可能触发多次搜索，用 token 追踪来管理结果刷新
