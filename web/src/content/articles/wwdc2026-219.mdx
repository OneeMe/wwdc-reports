## Highlight

> 做阅读类 App 的同事都知道，用多个 `UITextView` 或 `Text` 拼凑长页面时，VoiceOver 读到段落末尾就会"撞墙"，用户必须重新寻找下一个焦点。这次 Apple 给出了一套完整的解法：`accessibilityLinkedGroup` 和文本导航 API 把离散文本"缝合"起来，`UITextInput` 协议让自定义渲染的文本也能获得逐行探索和光标选择能力。

---

## 核心内容

### 1. 这场演讲解决什么问题

阅读长文本和普通的 UI 导航完全不同：用户需要**流畅地穿过文本**，而不是在控件之间跳来跳去。

当 App 用多个独立的文本视图拼接页面时（比如分页阅读器、图文混排），VoiceOver 和 Speak Screen 会遇到三个核心问题：

1. **颗粒度导航断裂**：读完一个段落，无法自然进入下一个段落
2. **连续阅读中断**：Speak Screen 读到一个文本视图末尾就停了，不会自动继续
3. **文本选择缺失**：自定义渲染的文本（如扫描文档、Canvas 绘制）无法被选中

### 2. 链接离散文本：导航 API 和 Linked Group

**UIKit 方案**：用 `accessibilityNextTextNavigationElement` 和 `accessibilityPreviousTextNavigationElement` 手动链接

```swift
class TravelGuidePageController: UIViewController {
    var paragraphs: [TravelGuideParagraph]

    func configureNavigationElements() {
        for (index, paragraph) in paragraphs.enumerated() {
            if index + 1 < paragraphs.count {
                paragraph.accessibilityNextTextNavigationElement = paragraphs[index + 1]
            }
            if index - 1 >= 0 {
                paragraph.accessibilityPreviousTextNavigationElement = paragraphs[index - 1]
            }
        }
    }
}
```

**SwiftUI 方案**：用 `accessibilityLinkedGroup` 更简洁

```swift
struct PageView: View {
    @Namespace private var pageNamespace
    var paragraphs: [String]
    var pageNumber: Int

    var body: some View {
        Text(paragraphs[0])
            .textSelection(.enabled)
            .accessibilityLinkedGroup(id: pageNumber, in: pageNamespace)

        Text(paragraphs[1])
            .textSelection(.enabled)
            .accessibilityLinkedGroup(id: pageNumber, in: pageNamespace)
    }
}
```

关键点：
- 同一个 `Namespace` 下的相同 `id` 会把多个文本元素视为一个整体
- VoiceOver 可以在它们之间按行、按词、按字自由导航
- Speak Screen 会连续读完所有链接的文本

### 3. 自动翻页：causesPageTurn

当 Speak Screen 或 VoiceOver 读到一个页面最后一个段落时，可以自动触发翻页：

```swift
class TravelGuidePageController: UIViewController {
    override func viewDidLoad() {
        super.viewDidLoad()
        self.lastParagraphView.accessibilityTraits.insert(.causesPageTurn)
    }

    override func accessibilityScroll(_ direction: UIAccessibilityScrollDirection) -> Bool {
        moveToPage(direction)
        var scrollString = "Page \(currentPage) of \(pages.count)"
        UIAccessibility.post(notification: .pageScrolled, argument: scrollString)
        return true
    }
}
```

### 4. 自定义操作和转子

给文本添加自定义操作（如"保存推荐"），并让它出现在 VoiceOver 的编辑转子中：

```swift
class TravelGuideParagraph: UITextView {
    override var accessibilityCustomActions: [UIAccessibilityCustomAction]? {
        get {
            let saveAction = UIAccessibilityCustomAction(name: "Save Recommendation") { _ in
                self.saveRecommendation()
            }
            saveAction.category = UIAccessibilityCustomAction.editCategory
            return (super.accessibilityCustomActions ?? []) + [saveAction]
        }
        set { }
    }
}
```

关键点：
- 必须设置 `category = .editCategory`，操作才会出现在编辑转子中
- 不设置的话，操作只会出现在通用的 Actions 菜单里，用户很难找到

### 5. 自定义文本渲染：实现 UITextInput

如果你用 CoreText、Canvas 或扫描文档做自定义文本渲染，只要完整实现 `UITextInput` 协议并挂载 `UITextInteraction`，VoiceOver 和 Speak Screen 就能像对待原生文本框一样工作：

```swift
class ScannedPage: UIView, UITextInput {
    override init(frame: CGRect) {
        super.init(frame: frame)
        let interaction = UITextInteraction(for: .nonEditable)
        interaction.textInput = self
        addInteraction(interaction)
    }

    func selectionRects(for range: UITextRange) -> [UITextSelectionRect] {
        // 返回选中区域的几何矩形
    }

    func text(in range: UITextRange) -> String? {
        // 返回指定范围内的文本
    }

    var tokenizer: any UITextInputTokenizer {
        CustomHandwritingTokenizer(textInput: self)
    }

    var selectedTextRange: UITextRange? {
        willSet { inputDelegate?.selectionWillChange(self) }
        didSet { inputDelegate?.selectionDidChange(self) }
    }
}
```

关键点：
- `UITextInteraction` 处理用户的触摸选择手势
- `tokenizer` 负责分词，决定 VoiceOver 按词导航的边界
- `selectedTextRange` 的 willSet/didSet 必须通知 `inputDelegate`，让辅助技术同步选择状态

## 最佳实践

- **已有项目迁移**：先排查现有 App 里的长文本页面。如果是多个 TextView 拼的，立刻加上 `accessibilityLinkedGroup` 或配置 Next/Previous 指针。如果是自绘文本，评估是否有必要上 `UITextInput`；如果只是为了让盲人"听"内容，先考虑 `accessibilityLabel` 结合 `UIAccessibilityReadingContent`，成本更低
- **新项目建议**：排版允许的话，无脑用 `TextEditor` 或单个大 `UITextView`。必须拆分 UI 时，优先使用 SwiftUI 的 Linked Group，把脏活累活交给框架
- **实战避坑**：如果你给文本选择添加了自定义操作（比如"高亮"、"保存"），在构建 `UIAccessibilityCustomAction` 时，一定要设置 `category = .editCategory`。如果不设置，这个操作只会出现在通用的 Actions 菜单里，而不会出现在 VoiceOver 文本编辑专属的转子中，用户根本找不到
