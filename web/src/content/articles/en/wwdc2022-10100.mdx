## Highlight

> WebKit 团队的 Devin Rousso 详细讲解了如何为 Safari 的 Web Inspector 创建扩展。Web Inspector 扩展基于跨浏览器 Web Extensions 标准和 DevTools API 构建，允许开发者在 Web Inspector 中添加自定义标签页。

---

## Core Content

Web Inspector is Safari’s main tool for debugging web pages.It has built-in tabs such as Elements and can also cover common network, DOM, style and script debugging tasks.

The problem is that real projects often have narrower requirements.You may want to debug a JavaScript framework, or you may just want to centrally display the Open Graph metadata in a web page.Such tools are too specific to be plugged directly into a general-purpose debugger.

([00:47](https://developer.apple.com/videos/play/wwdc2022/10100/?time=47)) Safari 16’s Web Inspector extensions give an entry.Developers can add their own tabs in Web Inspector based on cross-browser Web Extensions and DevTools API.

This session uses the Open Graph extension as an example.It reads the title, description, and image used for link previews in the web page and displays them in a custom tab in Web Inspector.

## Detailed Content

### Start with Safari Extension App

([02:00](https://developer.apple.com/videos/play/wwdc2022/10100/?time=120)) Web Inspector extension and Safari Web Extension follow the same distribution method: distributed through apps in the App Store.New projects can be created using Xcode’s Safari Extension App template.

如果已有其他浏览器的 web extension，可以使用 Xcode 附带的转换工具。session 里提到的命令是 `safari-web-extension-converter`，输入包含 `manifest.json` 的扩展目录后，它会生成一个可构建运行的 app 项目。

概念示例：

```bash
safari-web-extension-converter ./MyExtension
```

Key points:

- Line 1 calls the conversion tool that comes with Xcode.
- `./MyExtension` 指向已有 web extension 的目录。
- This directory needs to contain`manifest.json`, because manifest is the root configuration file of extension.

### manifest 里声明 devtools background page

（[03:06](https://developer.apple.com/videos/play/wwdc2022/10100/?time=186)）Web Inspector extension 的结构和普通 Safari Web Extension 很像，都有 manifest、图标、页面、脚本和样式。区别是它还需要一个专门的 devtools background page。

This page is responsible for the behind-the-scenes logic of the Web Inspector extension.It accesses the DevTools API and creates custom tabs that appear in the Web Inspector.

Concept example:

```json
{
  "devtools_page": "devtools_background.html"
}
```

Key points:

- 第 2 行在 manifest 中声明 devtools background page。
- `devtools_background.html` 会在 Web Inspector 打开时创建。
- 普通 background page、content scripts 和 popup 如果用不上，可以从项目和 manifest 中删除，减少扩展的运行面。

### Each Web Inspector has its own instance

（[03:43](https://developer.apple.com/videos/play/wwdc2022/10100/?time=223)）devtools background page 只服务一个 Web Inspector 窗口。如果用户同时检查多个页面，每个 Web Inspector 都会有自己的 devtools background page 实例。

这会影响状态管理。扩展不能默认把某个 tab page 的状态当作全局状态。每个被检查页面都可能对应一组独立的 devtools background page 和 devtools tab page。

### Create Web Inspector tab

（[06:54](https://developer.apple.com/videos/play/wwdc2022/10100/?time=414)）devtools background page 的核心任务，是创建 Web Inspector 里的自定义标签页。session 中的示例使用三个参数：标签名称、图标路径、标签页 HTML。

概念示例：

```js
browser.devtools.panels.create(
  browser.i18n.getMessage("extensionName"),
  "images/logo.svg",
  "devtools_tab.html"
);
```

Key points:

- Line 1 calls the DevTools panels create API to create a new Web Inspector tab.
- Line 2 passes`browser.i18n.getMessage()` 读取本地化后的扩展名称，避免把 UI 文案写死。
- 第 3 行传入标签图标路径。session 建议使用 SVG 矢量图，这样用户缩放界面时图标仍然清晰。
- 第 4 行指定实际显示给用户的 HTML 页面。

([07:02](https://developer.apple.com/videos/play/wwdc2022/10100/?time=422)) Devin Rousso recommends almost always creating a tab page.The reason is straightforward: If an extension requires permissions, Safari can display the permission prompt inside Web Inspector, and users can complete authorization while seeing the location of the tool.

### 在被检查页面里执行 JavaScript

（[11:45](https://developer.apple.com/videos/play/wwdc2022/10100/?time=705)）Web Inspector extension 常见任务是从被检查页面提取数据。Safari 16 提供了 `devtools.inspectedWindow.eval()`, which automatically locates the page being inspected by the Web Inspector that the current extension belongs to.

官方代码片段：

```js
// Evaluating scripts inside the inspected page

let result = await browser.devtools.inspectedWindow.eval("foo.bar()");
```

Key points:

- Line 3 calls`browser.devtools.inspectedWindow.eval()`。
- The passed in string will be executed in the checked page.
- `await` 等待执行结果返回，扩展随后可以把 `result` 渲染到自己的 devtools tab page。
- The API will automatically associate with the page corresponding to the current Web Inspector, which is suitable for users to inspect multiple pages at the same time.

### 指定 frame 执行代码

([12:27](https://developer.apple.com/videos/play/wwdc2022/10100/?time=747)) By default,`eval()` 会在被检查页面的 main frame 中执行表达式。如果页面有多个子 frame，扩展可以通过 `frameURL` 指定目标 frame。

Official code snippet:

```js
// Evaluating scripts inside a frame in the inspected page

let result = await browser.devtools.inspectedWindow.eval("foo.bar()", {
    frameURL: "http://example.com/",
});
```

Key points:

- 第 3 行仍然使用 `browser.devtools.inspectedWindow.eval()`。
- 第二个参数是选项对象。
- 第 4 行的 `frameURL` 指定要在哪个 frame 中执行表达式。
- This option is only required if you need to extract data from subframes; the Open Graph example only reads the main frame.

### Open Graph 扩展的数据流

（[13:05](https://developer.apple.com/videos/play/wwdc2022/10100/?time=785)）示例扩展把占位的 “Hello World” 替换成真正的 tab HTML、CSS 和 JavaScript。CSS 使用根级 `color-scheme`, to match the tab's appearance to the Web Inspector's.

（[14:09](https://developer.apple.com/videos/play/wwdc2022/10100/?time=849)）核心逻辑是把一段 JavaScript 传给 `inspectedWindow.eval()`。这段脚本在被检查页面中查询 DOM，读取常见 Open Graph 元数据：title、description、image，以及当前 `document` 的 ready state。

Concept example:

```js
let result = await browser.devtools.inspectedWindow.eval(`
  ({
    title: document.querySelector('meta[property="og:title"]')?.content,
    description: document.querySelector('meta[property="og:description"]')?.content,
    image: document.querySelector('meta[property="og:image"]')?.content,
    readyState: document.readyState,
  })
`);
```

Key points:

- 第 1 行通过 `inspectedWindow.eval()` 把脚本送到被检查页面。
- 第 3 行读取 `og:title` 元数据。
- 第 4 行读取 `og:description` 元数据。
- 第 5 行读取 `og:image` 元数据。
- Line 6`document.readyState` 一起返回，扩展可据此判断页面是否已准备好。
- 第 8 行拿到的 `result` 可用于更新 devtools tab page 中对应的 HTML 元素。

（[15:00](https://developer.apple.com/videos/play/wwdc2022/10100/?time=900)）示例还监听 `devtools.network.onNavigated`.When the inspected page is navigated, the extension re-reads the Open Graph data to ensure that the information displayed in Web Inspector is the current page.

概念示例：

```js
browser.devtools.network.onNavigated.addListener(() => {
  refreshOpenGraphMetadata();
});
```

Key points:

- 第 1 行注册页面导航监听器。
- `onNavigated` 来自 DevTools network API。
- 第 2 行在导航后重新读取被检查页面的数据。
- This writing method is suitable for users to continuously switch pages while Web Inspector remains open.

### User experience details

（[15:57](https://developer.apple.com/videos/play/wwdc2022/10100/?time=957)）session 最后给出三条实践建议。

First, create the devtools tab page from the devtools background page.This way the permission prompt will appear inside Web Inspector and the user won't have to jump elsewhere to authorize.

第二，优先使用 `activeTab` permission，而不是请求具体 host 权限。这样 Web Inspector extension 的访问范围更集中，只作用于当前被检查页面。

第三，用 CSS `color-scheme` 或 web extension devtools theme APIs 匹配 Web Inspector 主题。调试工具常常长时间打开，视觉一致性会直接影响可读性。

## Core Takeaways

### 1. 做一个框架状态检查标签页

- **做什么**：为内部前端框架做 Web Inspector 标签页，显示当前路由、页面状态和关键 store 数据。
- **为什么值得做**：session 展示了如何用 `inspectedWindow.eval()` 读取被检查页面的数据，并把结果显示在 devtools tab page 中。
- **怎么开始**：先创建 devtools background page，再用 `browser.devtools.panels.create()` 添加标签页，在 tab page 中通过 `browser.devtools.inspectedWindow.eval()` 调用页面内的调试入口函数。

### 2. 做一个 SEO 与社交分享检查器

- **做什么**：读取 Open Graph、Twitter Card、canonical URL 和页面标题，直接在 Web Inspector 中给出缺失项。
- **Why it's worth doing**: The Open Graph example has covered the path of reading meta tags, processing ready state, and rendering results.
- **How ​​to start**: From`document.querySelector()`Read the target meta tag; if the page is not ready, try again after a short delay; used during navigation`browser.devtools.network.onNavigated` 刷新结果。

### 3. 做一个 iframe 内容定位工具

- **做什么**：列出页面中的子 frame，并允许开发者选择某个 frame 执行检查脚本。
- **为什么值得做**：session 明确展示了 `frameURL` 选项，适合从多 frame 页面中提取目标数据。
- **怎么开始**：先在 main frame 收集 frame URL，再把用户选择的 URL 作为 `browser.devtools.inspectedWindow.eval()` 的 `frameURL` 参数。

### 4. 做一个项目规范审计工具

- **做什么**：检查页面是否符合团队规范，例如是否带有指定 data attribute、是否加载调试标记、是否输出必要埋点字段。
- **为什么值得做**：Web Inspector extension 适合个人或团队工作流，session 开头专门提到它能覆盖通用开发者工具不适合内置的场景。
- **怎么开始**：把规范检查写成在页面中执行的 JavaScript 表达式，再把结果返回到 devtools tab page，用列表展示通过项和失败项。
