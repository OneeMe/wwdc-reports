## Highlight

> App Store Connect 在 2020 年新增了 App Clip 测试与卡片配置、Game Center 挑战和周期排行榜、内购家庭共享，以及 200 多个 App Store Connect API 端点，让发版、测试和运营配置能在同一套后台流程里完成。

---

## 核心内容

发布一个 App 早就不只是上传二进制文件。一个团队可能要同时准备 App Clip 的入口 URL，给 TestFlight 测试者配置可点开的场景，给正式用户设置卡片文案，还要确认域名关联没有失效。游戏团队还要打开 Game Center 能力，订阅团队要决定家庭共享策略，负责发版的人则希望把版本元数据、价格、build 关联和审核提交写进脚本。

这场 Session 的核心变化，是 App Store Connect 开始承接这些发布后的运营入口。App Clip 的 build 会在 TestFlight 里多出专门的 App Clip 行；测试者可以从 TestFlight 直接启动指定 Invocation URL；正式发布前，开发者要在 iOS 版本页配置默认 App Clip Card metadata，也可以给 Apple Maps、NFC、QR code 等入口注册 advanced App Clip experiences。（[04:33](https://developer.apple.com/videos/play/wwdc2020/10651/?time=273)、[06:23](https://developer.apple.com/videos/play/wwdc2020/10651/?time=383)）

后台配置开始变成产品流程的一部分。Game Center 的挑战只需要在 Features 里的 Game Center 页面打开一个复选框；周期排行榜新增了开始时间、持续时间和重复规则。内购和订阅的家庭共享也在 App Store Connect 的 In-App Purchase detail page 上打开，但 live purchase 一旦启用就不能关闭。（[15:45](https://developer.apple.com/videos/play/wwdc2020/10651/?time=945)、[19:00](https://developer.apple.com/videos/play/wwdc2020/10651/?time=1140)）

最后一块是自动化。Apple 预告新增 App Metadata APIs 和 Power and Performance API，合计超过 200 个新端点。前者可以创建 App Store 版本、设置价格和可用地区、编辑元数据、关联 build、提交审核；后者可以下载 Xcode 性能分析工具背后的聚合数据。（[20:13](https://developer.apple.com/videos/play/wwdc2020/10651/?time=1213)）

## 详细内容

### App Clip 从测试 URL 走到正式卡片

（[01:51](https://developer.apple.com/videos/play/wwdc2020/10651/?time=111)）App Clip Invocation 是这场 App Clip 配置的基础概念。用户可以从 Safari、Messages、Maps、NFC tag、QR code 或位置触发 App Clip。大多数触发方式都会带一个 Invocation URL，系统用它决定 App Clip Card 显示哪套 metadata；App Clip 启动后，同一个 URL 会传给 App Clip，用来 deep link 到具体功能。

```text
forestexplorer.org
camp.forestexplorer.org/reserve + campground ID
camp.forestexplorer.org/check-in + campground ID + campsite number
```

关键点：
- 第一个 URL 对应 Safari 页面上的 App Clip Banner。
- 第二个 URL 对应从 Apple Maps 进入营地预约场景。
- 第三个 URL 对应在营地扫描 NFC tag 后进入具体 campsite check-in。
- 这些是 transcript 中用于说明 Invocation URL 的三类例子，不是官方代码片段。

（[04:33](https://developer.apple.com/videos/play/wwdc2020/10651/?time=273)）测试阶段从 build 开始。App Clip 不能独立打包，它和完整 App 一起由 Xcode 生成 build，再送进 App Store Connect。包含 App Clip 的 build 会在 TestFlight 详情里出现新的 App Clip Invocation section，开发者最多可以给测试者配置三个 Invocation URLs。每个条目包含一个 TestFlight 里显示的 title 和一个 Invocation URL，保存后立即对测试者生效。

关键点：
- TestFlight 是这场演讲里唯一不会先显示 App Clip Card 的 App Clip invocation case。
- 测试者点击 TestFlight 的 TEST 按钮后，系统会启动当前 build 里的 App Clip，并把配置好的 Invocation URL 传进去。
- 如果测试者遇到问题，TestFlight Feedback 可以像普通 App 一样收集反馈。

（[06:23](https://developer.apple.com/videos/play/wwdc2020/10651/?time=383)）正式发布时，App Clip Card 需要 metadata。默认体验在 iOS version page 配置，包括 header image、subtitle 和 call to action verb。默认 metadata 是所有 App Clip 都必须配置的内容，它只会用于 Safari 和 Messages 触发的 App Clip。

关键点：
- Safari 页面用名为 `apple-itunes-app` 的 meta tag 建立页面和 App Clip 的关联。
- 这个 meta tag 会加上 App Clip bundle ID attribute。
- 如果用户还在 iOS 13 或更早版本，页面可以通过 app ID attribute 指向完整 App 的 App Store 页面。

（[08:34](https://developer.apple.com/videos/play/wwdc2020/10651/?time=514)）如果一个 App Clip 需要按地点或 URL 展示不同卡片，就要注册 advanced App Clip experiences。演讲里的 Forest Explorer 为营地预约注册完整 URL，也为 campsite check-in 使用 URL prefix，让同一个 campground 下的多个 campsite 共用一套 metadata。

关键点：
- advanced experience 可以自定义 App Clip Card metadata。
- advanced experience 可以关联 Apple Maps 上的 place。
- 如果 URL 的后半段只是具体资源 ID，用前缀注册可以避免为每个资源重复维护同样的卡片。

（[13:50](https://developer.apple.com/videos/play/wwdc2020/10651/?time=830)）最后要验证域名。开发者先用 Associated Domains Entitlement 指定要和 App Clip 关联的域名，再在这些域名上提供 Apple App Site Association file，文件里要引用 App Clip App ID。App Store Connect 的 build details 页面可以查看 domain validation status，Load Debug Status 会实时访问服务器并检查文件中的 App Clip 部分。

关键点：
- cache status 会影响用户设备上的 App Clip invocation。
- 正在调试 Apple App Site Association file 时，Load Debug Status 比等待缓存刷新更直接。
- 这个部分和 Universal Links 共享很多概念，本场也指向了 What's new in Universal Links。

### Game Center 新增挑战和周期排行榜

（[15:45](https://developer.apple.com/videos/play/wwdc2020/10651/?time=945)）Game Center 的挑战让玩家可以要求其他玩家完成一个 achievement，或打破某个 leaderboard score。开发者在 App Store Connect 的 Features -> Game Center 页面打开 `Allow challenges in this game`，保存后玩家就可以互相发起挑战。

关键点：
- 这是 App Store Connect 里的开关，不是演讲中展示的 GameKit 代码。
- 挑战围绕 achievement 和 leaderboard score 两类目标。
- 开关保存后，能力会对玩家生效。

（[16:12](https://developer.apple.com/videos/play/wwdc2020/10651/?time=972)）Recurring Leaderboards 是新的排行榜类型，用于在预先设定的一段时间内收集分数，并按规则重复开启。演讲的例子是 10 月 13 日 18:00 第一次开始，持续 4 小时，然后每周重复一次。

```text
start time: October 13, 6:00 pm
duration: 4 hours
recurrence: every week
active window: Tuesday 6:00 pm to 10:00 pm
```

关键点：
- App Store Connect 的 recurring leaderboard 页面新增 start time、duration 和 recurrence rules。
- 每次重复开启都会生成一轮新的排行榜窗口。
- 这种配置适合每周赛、限时挑战和固定时间段活动。

### 内购家庭共享进入 App Store Connect

（[17:31](https://developer.apple.com/videos/play/wwdc2020/10651/?time=1051)）Apple 宣布从 2020 年秋季开始，订阅的 Family Sharing 会开放给所有 App 开发者。它适用于 auto-renewal subscriptions，也适用于 nonconsumable in-app purchases。购买一次后，家庭成员可以共享同一个购买项目。

关键点：
- 如果开发者把一个订阅做成 family shared subscription，可以把它设计成个人订阅的升级项。
- 启用家庭共享后，新购买者会自动和家庭成员共享。
- 现有订阅者需要主动 opt in，才会把当前订阅分享给家庭成员。

（[19:00](https://developer.apple.com/videos/play/wwdc2020/10651/?time=1140)）配置入口在 In-App Purchase detail page。开发者先检查 metadata，确认页面清楚说明这是 family shared in-app purchase，再点击 Turn On 并确认。对 live in-app purchase 启用后，不能再关闭。

```text
In-App Purchase detail page
-> review metadata
-> Turn On
-> confirm
-> Family Sharing takes effect immediately
```

关键点：
- metadata 必须提前说明购买项目会被家庭共享。
- live purchase 的开关不可逆，不能用线上产品试验。
- 打开后立即生效，适合先在产品策略上确认升级路径。

### App Store Connect API 扩展到发版和性能数据

（[20:13](https://developer.apple.com/videos/play/wwdc2020/10651/?time=1213)）App Store Connect API 最早支持 TestFlight、user management、provisioning 和 reporting。2020 年晚些时候，Apple 计划新增两组 API：App Metadata APIs 和 Power and Performance API，合计超过 200 个新端点。

```text
App Metadata APIs:
- create new App Store versions
- set pricing and availability
- edit app and version-level metadata
- associate builds to App Store versions
- submit versions for review

Power and Performance API:
- download the aggregate data used by Xcode power and performance analysis tools
```

关键点：
- App Metadata APIs 把 App Store presence 的维护流程开放给自动化脚本。
- Power and Performance API 面向性能数据下载，数据来源和 Xcode 中的新分析工具一致。
- 本场只列出能力范围，具体 walkthrough 指向 Expanding automation with the App Store Connect API。

## 核心启发

1. **做 App Clip 发布检查表**。
   做什么：把每个 Invocation URL、对应 App Clip Card metadata、Apple Maps place 关联和 domain validation status 放进一张发布前清单。
   为什么值得做：这场 Session 明确说明 URL 会同时决定卡片 metadata 和启动后的 deep link，域名缓存状态也会影响真实用户能否唤起 App Clip。
   怎么开始：先列出 Safari、Messages、Maps、NFC 和 QR code 入口，再逐个在 TestFlight 配置测试 URL，发布前用 View Status 和 Load Debug Status 检查域名。

2. **给游戏做固定时间窗口活动**。
   做什么：把每周赛、周末挑战或限时榜单做成 Recurring Leaderboards，并打开 Game Center challenges。
   为什么值得做：App Store Connect 已经提供 start time、duration 和 recurrence rules，挑战也可以围绕 achievement 或 leaderboard score 发起。
   怎么开始：选择一个低风险排行榜，设置第一次开启时间和持续时长，再把活动节奏固定为每周或固定间隔。

3. **把订阅升级路径改成家庭计划**。
   做什么：为自动续期订阅设计 family shared subscription，让个人订阅用户能升级到家庭共享。
   为什么值得做：演讲说明新购买者会自动共享，现有订阅者需要 opt in，适合做清晰的升级引导。
   怎么开始：先检查订阅 metadata，明确告诉用户这是共享购买，再在 In-App Purchase detail page 启用 Family Sharing。

4. **把发版脚本从 build 上传扩展到元数据提交**。
   做什么：把创建 App Store version、设置价格和可用地区、编辑版本 metadata、关联 build、提交审核纳入同一条发布流水线。
   为什么值得做：App Metadata APIs 的目标就是管理 App Store presence，减少发版前后的网页操作。
   怎么开始：先把 release checklist 拆成这些资源动作，再阅读 10004 的 API walkthrough，为每一步补上请求和失败处理。

5. **把线上质量数据接回团队 dashboard**。
   做什么：用 Power and Performance API 下载 Xcode 分析工具背后的聚合数据，展示在团队已有的质量看板里。
   为什么值得做：同一个数据源可以帮助发版负责人在 App Store Connect 外看到性能趋势。
   怎么开始：先决定要跟踪的 power 和 performance 指标，再把 API 拉取结果接到现有 dashboard 或回归检查流程。
