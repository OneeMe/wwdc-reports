## Highlight

> Apple 在 App Store 新增 In-App Events，开发者可以在 App Store Connect 创建、排期和衡量应用内活动，让限时挑战、首映和赛事直接出现在产品页、搜索结果、推荐位和编辑精选中。

## 核心内容

你已经在 app 里做了一场活动。游戏有周末竞赛，健身 app 有七天挑战，视频 app 有电影首映。问题是，用户要先打开 app 才能看见它。

以前的做法主要靠站外营销和推送。推送只能触达已安装用户。社交媒体需要用户离开 App Store 再回来。活动本身发生在 app 内，发现入口却散落在 app 外。

Apple 在 WWDC21 引入 In-App Events（应用内活动）。活动会变成 App Store 上的 event card（活动卡片）。卡片可以显示图片或视频、活动名称、短描述和自动更新的时间提示。

这样，活动就进入了 App Store 的发现链路。用户浏览产品页、搜索 app、打开 Games 和 Apps 标签页时，都可能看到活动。已安装用户点 Open 可以进入 app 内活动。未安装用户会看到活动详情页。

创建入口也放在 App Store Connect。开发者填写活动信息、可用地区、开始结束时间、发布时机、deep link（深层链接）和活动目的。活动通过审核后，会按排期自动发布。

这场 session 的重点是新的运营通道。它把 app 内的限时内容，接到了 App Store 的展示、提醒、搜索、推荐和分析系统。

## 详细内容

### 活动卡片：把 app 内活动放到 App Store

（[01:08](https://developer.apple.com/videos/play/wwdc2021/10171/?time=68)）In-App Events 会以 event card 的形式出现在 App Store。卡片支持图片或视频，并显示活动名称、短描述和时间指示器。时间指示器会随着活动临近和开始自动更新。

本场没有 Code tab 代码片段。这里用 App Store 展示结构表示核心字段。

```text
In-App Event Card
- Media: image or video
- Event Name
- Short Description
- Time Indicator: updates before and after start
- Action for installed users: Open
```

关键点：

- `Media` 是卡片视觉内容，可以是图片，也可以是视频。
- `Event Name` 是用户在 App Store 上看到的活动名称。
- `Short Description` 用一句短文案说明活动内容。
- `Time Indicator` 由 App Store 自动更新，用来提示活动即将开始或已经开始。
- `Open` 面向已安装用户，点击后直接进入 app。

（[01:33](https://developer.apple.com/videos/play/wwdc2021/10171/?time=93)）活动卡片首先出现在产品页。已下载 app 的用户会在截图上方看到活动；未下载用户会在截图下方看到活动。用户点卡片，会进入 event details page（活动详情页）。详情页有更长描述和更大的媒体资源。

```text
App Product Page
- Installed users: event cards above screenshots
- New users: event cards below screenshots
- Tap event card: Event Details Page
- Direct link: App Store URL + unique event ID
```

关键点：

- `Installed users` 的活动位置更靠前，因为这些用户可以立刻参与。
- `New users` 仍能看到活动，活动可以成为下载理由。
- `Event Details Page` 承载更完整的活动说明。
- `unique event ID` 可以追加到 app 的 App Store URL 后，用于外部营销链接。

### 发现入口：搜索、推荐和编辑精选

（[02:13](https://developer.apple.com/videos/play/wwdc2021/10171/?time=133)）开发者可以在活动开始前最多两周进行预热。用户可以请求活动开始时的通知。这个通知来自 App Store，并会把已安装用户带到 app 内活动。未安装用户会进入活动详情页。

```text
Before event starts
- Promote event up to 14 days early
- User requests notification
- App Store sends notification at event start
- Installed user: open app event
- New user: open event details page
```

关键点：

- `14 days` 是预热上限，活动不能无限期占用展示位。
- `notification` 由 App Store 发送，开发者不需要用自己的推送系统完成这件事。
- `Installed user` 收到通知后可以直接参与活动。
- `New user` 会先看到详情页，再决定是否下载。

（[02:35](https://developer.apple.com/videos/play/wwdc2021/10171/?time=155)）In-App Events 也会进入搜索结果。用户搜索 app 时，如果已经下载过该 app，会看到活动卡片和 app 一起出现。用户直接搜索活动时，活动卡片总会出现在 app 旁边。

```text
App Store discovery
- Product page
- Search by app name
- Search by event name
- Games tab and Apps tab personalized recommendations
- Today, Games, Apps editorial curation
```

关键点：

- `Search by app name` 面向已有用户，帮助他们知道 app 里正在发生什么。
- `Search by event name` 面向明确寻找活动的用户。
- `personalized recommendations` 会出现在 Games 和 Apps 标签页。
- `editorial curation` 由 Apple 编辑团队在 Today、Games、Apps 标签页策划。

### App Store Connect：创建活动元数据

（[03:28](https://developer.apple.com/videos/play/wwdc2021/10171/?time=208)）创建活动从 App Store Connect 开始。开发者进入某个 app，选择左侧 Features 下的 In-App Events，点击 Create In-App Event。第一步是填写 Reference Name。它只在 App Store Connect 内可见，最长 64 个字符。

```text
App Store Connect
→ Select app
→ Features
→ In-App Events
→ Create In-App Event
→ Reference Name: up to 64 characters, internal only
```

关键点：

- `Select app` 表示活动必须挂在某个已有 app 下面。
- `Features` 是 App Store Connect 左侧功能入口。
- `In-App Events` 是管理活动的页面。
- `Reference Name` 只给团队内部识别使用，不会显示在 App Store。

（[04:14](https://developer.apple.com/videos/play/wwdc2021/10171/?time=254)）活动信息字段都支持本地化。开发者需要填写活动名称、短描述、卡片媒体、长描述、详情页媒体和 badge（徽章）。名称最多 30 个字符，短描述最多 50 个字符，长描述最多 120 个字符。视频会循环播放，最长 30 秒。

```text
Event Information
- Event Name: up to 30 characters
- Short Description: up to 50 characters
- Event Card Media: image or video
- Long Description: up to 120 characters
- Event Details Media: image or video
- Video limit: 30 seconds, loops
- Badge: event type
```

关键点：

- `Event Name` 会显示在卡片和详情页。
- `Short Description` 用在活动卡片，负责快速说明活动。
- `Long Description` 用在详情页，可以加入奖励等更多信息。
- `Event Card Media` 决定卡片上的视觉内容。
- `Event Details Media` 用在详情页，尺寸更大。
- `Badge` 表示活动类型，帮助用户快速判断活动性质。

### 可用地区和排期：控制展示时间

（[05:57](https://developer.apple.com/videos/play/wwdc2021/10171/?time=357)）In-App Events 和 app、in-app purchases（应用内购买）一样，需要按国家或地区设置可用性。活动只能在父 app 已经可用的国家或地区发布。

```text
Availability
- Scope: Country or Region
- Constraint: event availability must be inside parent app availability
```

关键点：

- `Country or Region` 是活动可用性的粒度。
- `parent app availability` 是硬约束，活动不能发布到 app 不可用的地区。

（[06:20](https://developer.apple.com/videos/play/wwdc2021/10171/?time=380)）排期包含三个时间：start（活动在 app 内开始）、end（活动在 app 内结束）和 publish date（活动首次出现在 App Store）。活动最短 15 分钟，最长 31 天。发布日可以比开始日最多早 14 天。

```text
Schedule
- Event Start: when the event begins inside the app
- Event End: when the event ends inside the app
- Publish Date: when the event first appears on the App Store
- Duration: 15 minutes to 31 days
- Promotion window: up to 14 days before start
```

关键点：

- `Event Start` 对齐 app 内真实活动开始时间。
- `Event End` 对齐 app 内真实活动结束时间。
- `Publish Date` 控制 App Store 开始展示活动的时间。
- `Duration` 有明确上下限，活动不能短于 15 分钟，也不能长于 31 天。
- `Promotion window` 让开发者提前预热，但最多提前 14 天。

（[07:09](https://developer.apple.com/videos/play/wwdc2021/10171/?time=429)）活动结束后，它不会再通过浏览或搜索被发现。活动详情页仍可通过 App Store URL 访问 30 天。30 天后活动归档。这个 30 天窗口自动发生，不能配置。开发者可以通过修改可用性提前归档。

```text
After event ends
- Browsing and search discovery: stops
- Event details page URL: remains accessible for 30 days
- Archive: automatic after 30 days
- Early archive: edit availability in App Store Connect
```

关键点：

- `Browsing and search discovery` 会在活动结束时停止。
- `Event details page URL` 继续保留 30 天，方便外部营销链接短期内仍可打开。
- `Archive` 由系统自动执行。
- `Early archive` 通过 App Store Connect 修改可用性完成。

（[07:47](https://developer.apple.com/videos/play/wwdc2021/10171/?time=467)）开发者还可以按国家或地区自定义排期。自定义日期必须在默认日期的 48 小时内。这适合处理时区差异，例如欧洲地区的开始和结束时间要相对默认时间移动。

```text
Customize Dates and Times
→ Select Countries or Regions
→ Choose custom start, end, or publish dates
→ Custom dates must be within 48 hours of defaults
→ Done
```

关键点：

- `Customize Dates and Times` 是可选入口。
- `Select Countries or Regions` 决定哪些地区使用自定义时间。
- `custom start, end, or publish dates` 用来贴合本地时间。
- `48 hours` 是自定义时间相对默认时间的限制。

### Deep Link、活动目的和优先级

（[08:39](https://developer.apple.com/videos/play/wwdc2021/10171/?time=519)）Additional Information（附加信息）里必须提供 Event Deep Link。它可以是 universal link（通用链接），也可以是 custom URL（自定义 URL），目标是打开 app 内的特定位置。Apple 建议不要使用 URL 短链或会增加重定向的服务。

```text
Event Deep Link
- Type: universal link or custom URL
- Target: specific place in the app
- Avoid: URL shorteners
- Avoid: unnecessary redirects
```

关键点：

- `universal link` 可以把网页链接和 app 内页面关联起来。
- `custom URL` 可以用自定义 scheme 打开 app。
- `specific place in the app` 是活动落地页，用户不应该只到 app 首页。
- `URL shorteners` 和 `unnecessary redirects` 可能影响打开体验，应该避免。

（[09:04](https://developer.apple.com/videos/play/wwdc2021/10171/?time=544)）Event Purpose（活动目的）告诉 App Store 这场活动主要服务哪些用户：吸引新用户、通知活跃用户、召回流失用户，或者同时面向这些人群。这个选择会参与个性化推荐。App Store 使用 app 使用信息，并在设备端处理这些数据，以减少数据收集并提升隐私保护。

```text
Event Purpose
- Attract new users
- Keep active users informed
- Bring lapsed users back
- All purposes: default selection
- Used for personalized recommendations
- App usage information: processed on device
```

关键点：

- `Attract new users` 适合把活动作为下载理由。
- `Keep active users informed` 适合通知已经常用 app 的用户。
- `Bring lapsed users back` 适合召回一段时间没有打开 app 的用户。
- `All purposes` 是默认值，适合大多数活动。
- `processed on device` 是 App Store 个性化推荐中的隐私处理方式。

（[09:45](https://developer.apple.com/videos/play/wwdc2021/10171/?time=585)）Priority level（优先级）影响活动在产品页上的排序。高优先级活动排在普通活动前面；同一组内再按开始时间排序。开发者还要标明活动是否需要 in-app purchase 或 subscription（订阅）。这个信息会显示在卡片和详情页，也会影响审核体验。

```text
Product page ordering
1. High-priority events
2. Normal-priority events
3. Start time within each priority group

Monetization disclosure
- Requires In-App Purchase: yes/no
- Requires Subscription: yes/no
```

关键点：

- `High-priority events` 会先显示，适合最重要的活动。
- `Normal-priority events` 按常规顺序展示。
- `Start time` 负责同一优先级内的排序。
- `Requires In-App Purchase` 和 `Requires Subscription` 会在 App Store 上提示用户付费要求。

### 审核、状态生命周期和数量限制

（[10:34](https://developer.apple.com/videos/play/wwdc2021/10171/?time=634)）保存后，活动进入 draft（草稿）状态。活动发布前必须经过审核。开发者填完必需元数据后，可以把活动提交审核。这个过程不需要创建 app 新版本，也不需要上传新 binary（二进制包）。

```text
Submission
- Save event
- State: Draft
- Add for Review after required metadata is complete
- No new app version required
- No new binary required
```

关键点：

- `Save event` 会保存当前配置。
- `Draft` 表示活动还没有提交审核。
- `Add for Review` 是进入审核的动作。
- `No new app version required` 降低了运营活动的发布成本。
- `No new binary required` 表示只改 App Store Connect 元数据即可。

（[11:04](https://developer.apple.com/videos/play/wwdc2021/10171/?time=664)）活动通过审核后进入 approved（已批准）状态。未来发布的活动标记为 Set to Publish；已经到发布时间的活动标记为 Published。结束后进入 Past，详情页链接继续可访问 30 天。之后进入 Archived，链接不再可访问。

```text
In-App Event lifecycle
Draft
→ Review
→ Approved
→ Set to Publish
→ Published
→ Past
→ Archived
```

关键点：

- `Draft` 是编辑阶段。
- `Review` 是 App Store 审核阶段。
- `Approved` 表示审核通过。
- `Set to Publish` 表示等待未来的 publish date。
- `Published` 表示正在 App Store 展示。
- `Past` 表示活动已结束，但详情页链接还有 30 天可访问。
- `Archived` 表示活动归档，链接失效。

（[11:57](https://developer.apple.com/videos/play/wwdc2021/10171/?time=717)）每个 app 最多可以有 10 个 approved 状态的活动，并且最多同时有 5 个活动发布到 App Store。如果某个活动的排期会超过这两个限制，开发者不能把它提交审核。

```text
Limits per app
- Approved events: up to 10
- Published events at the same time: up to 5
- Review submission blocked if schedule exceeds limits
```

关键点：

- `Approved events` 包括已经审核通过、等待发布或发布中的活动。
- `Published events at the same time` 控制 App Store 同时展示的活动数量。
- `Review submission blocked` 会在排期导致超限时发生。

### App Analytics 和 App Store Connect API

（[12:13](https://developer.apple.com/videos/play/wwdc2021/10171/?time=733)）活动发布后，开发者可以在 App Analytics（应用分析）衡量表现。活动页面会直接链接到 App Analytics 中对应的活动数据。可用指标包括 impressions（展示次数）、用户打开 app 或详情页的次数、由活动带来的下载和重新下载，以及预约通知的用户数。

```text
App Analytics for In-App Events
- Impressions
- Where users saw the event: product page, search, other locations
- App opens
- Event details page opens
- Downloads and redownloads from the event
- Notification opt-ins
```

关键点：

- `Impressions` 表示活动在 App Store 被看到的次数。
- `product page`、`search` 和 `other locations` 用来拆分展示来源。
- `App opens` 表示活动带来的打开行为。
- `Event details page opens` 表示详情页访问行为。
- `Downloads and redownloads` 用来衡量活动对安装和召回的影响。
- `Notification opt-ins` 表示有多少用户预约了活动开始提醒。

（[13:17](https://developer.apple.com/videos/play/wwdc2021/10171/?time=797)）Apple 还宣布 In-App Event 的功能会支持 App Store Connect API。完整规格会在当年稍后提供。对于有固定活动节奏的团队，这意味着活动创建、排期和管理可以接入自动化发布流程。

```text
Automation entry
- App Store Connect API
- Scope: In-App Event functionality
- Spec availability: later in 2021
```

关键点：

- `App Store Connect API` 是自动化入口。
- `In-App Event functionality` 覆盖本场介绍的活动管理能力。
- `later in 2021` 是本场给出的规格发布时间。

## 核心启发

1. **做什么**：给手游做每周竞赛活动卡片。
   **为什么值得做**：活动可以提前最多 14 天出现在 App Store，用户能预约开始通知。
   **怎么开始**：在 App Store Connect → Features → In-App Events 创建活动，填写竞赛名称、短描述、30 秒以内视频和活动 deep link。

2. **做什么**：给健身 app 做地区化挑战赛。
   **为什么值得做**：不同国家或地区可以在默认时间 48 小时内设置自定义排期，适合按本地时间开始。
   **怎么开始**：先设置默认 start、end、publish date，再用 Customize Dates and Times 给目标地区调整时间。

3. **做什么**：给视频 app 做新片首映入口。
   **为什么值得做**：活动详情页可以使用长描述和更大媒体资源，未安装用户也能在 App Store 看到首映内容。
   **怎么开始**：为首映活动准备卡片媒体和详情页媒体，把 Event Deep Link 指向 app 内播放或预约页面。

4. **做什么**：给订阅 app 做限时会员直播。
   **为什么值得做**：活动卡片和详情页可以显示是否需要订阅，用户在进入前就知道参与条件。
   **怎么开始**：在 Additional Information 中准确标记 Requires Subscription，并在 long description 写清楚直播时间和会员要求。

5. **做什么**：建立活动复盘看板。
   **为什么值得做**：App Analytics 提供展示、来源、打开、下载、重新下载和通知预约数据，可以判断活动是否带来真实转化。
   **怎么开始**：活动发布后从 App Store Connect 的活动页面进入 App Analytics，按产品页、搜索和其他来源拆分 impressions。
