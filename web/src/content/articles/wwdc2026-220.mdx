## Highlight

> Apple 把自定义控件的辅助功能从"文本朗读"升级到了"空间与手势交互"。现在你可以用 `.adjustable` 让 VoiceOver 用户单指滑动调节数值，用 `accessibilityActivationPoint` 精确控制 Passthrough Gesture 的触发位置，用 `accessibilityDirectTouch` 让视障用户直接触摸交互复杂控件，再也不用为了无障碍去妥协 UI 设计。

---

## 核心内容

### 1. 这场演讲解决什么问题

自定义控件是 App 差异化的重要手段，但辅助功能往往是事后补丁：

- 手搓了一个酷炫的 2D 触控板，VoiceOver 用户只能听到"按钮"
- 做了一个捏合缩放控件，只能拆成四个方向键来适配
- 滑动调节数值时，VoiceOver 播报太频繁让人烦躁

这次 Apple 的核心思路是：**把视觉隐喻翻译成辅助技术能理解的语义**。

### 2. 四大指导原则

从视觉控件中，用户能获取四种信息。把这四种信息暴露给辅助技术，就是好的无障碍体验：

1. **目的**：这个控件是做什么的？（Label）
2. **数值**：当前值是多少？（Value）
3. **动作**：可以怎么操作？（Trait + Action）
4. **反馈**：操作后发生了什么？（Announcement）

### 3. 单轴调节控件：.adjustable

以咖啡机滑块为例，从完全不可用到完美无障碍，只需要几步：

```swift
struct CoffeeDispenserView: View {
    @State var coffee: Double = 0.0
    var body: some View {
        CoffeeSlider(value: coffee)
            .accessibilityElement()
            .accessibilityLabel("Coffee Dispenser")
            .accessibilityValue("\(Int(coffee)) ounces")
            .accessibilityAddTraits(.adjustable)
            .accessibilityAdjustableAction { direction in
                switch direction {
                case .increment:
                    increaseCoffeeAmount()
                case .decrement:
                    decreaseCoffeeAmount()
                }
            }
    }
}
```

VoiceOver 现在会播报："Coffee dispenser, 6 ounces, adjustable. Swipe up or down with one finger to adjust the value."

### 4. 精确控制：Passthrough Gesture 和 Activation Point

如果用户想要半盎司的精确控制，可以用 Passthrough Gesture：双击并按住，VoiceOver 会把触摸事件直接传给控件。

你可以控制这个手势从哪里开始：

```swift
struct CoffeeDispenserView: View {
    @State var coffee: Double = 0.0

    var body: some View {
        CoffeeSlider(value: coffee)
            .accessibilityActivationPoint(
                UnitPoint(x: 0.5, y: 1 - coffee)
            )
    }
}
```

`accessibilityActivationPoint` 定义了 Passthrough Gesture 的触发位置。对于咖啡滑块，把触发点设在当前液面高度，用户双击按住时手指正好在液面上，拖拽体验最自然。

### 5. 反馈控制：Announcement 防抖

数值变化时实时播报很重要，但不能太频繁：

```swift
struct CoffeeDispenserView: View {
    @State var coffee: Double = 0.0

    var body: some View {
        CoffeeSlider(value: coffee)
            .onChange(of: coffee) { _, newValue in
                if sufficientTimeSinceLastAnnouncement() && valueHasChanged() {
                    cacheLastSpokenValue(newValue)
                    AccessibilityNotification
                        .Announcement(newValue)
                        .post()
                }
            }
    }
}
```

关键点：
- 设置约 0.3 秒的防抖阈值
- 只有当数值真正变化时才播报
- 滑动很快时避免一秒钟播报 10 次，否则用户会关掉 App

### 6. 多轴和复杂控件：Custom Actions

对于 2D 均衡器等多轴控件，用 `accessibilityActions` 提供方向性操作：

```swift
struct EqualizerView: View {
    var body: some View {
        EqualizerPad()
            .accessibilityActions("Move Up") {
                increaseY(by: 10)
            }
            .accessibilityActions("Move Right") {
                increaseX(by: 10)
            }
            .accessibilityActions("Move Down") {
                decreaseY(by: 10)
            }
            .accessibilityActions("Move Left") {
                decreaseX(by: 10)
            }
    }
}
```

### 7. 直接触摸：Direct Touch

对于需要精细触摸交互的控件（如虚拟宠物），可以用 Direct Touch 让 VoiceOver 用户直接触摸操作：

```swift
struct VirtualCat: View {
    var cat: CatModel
    var body: some View {
        InteractiveCatSurface()
            .accessibilityLabel("Virtual Cat")
            .accessibilityValue(cat.currentReaction.description)
            .accessibilityDirectTouch([.requiresActivation])
    }
}
```

`.requiresActivation` 表示用户需要先双击激活，然后才能直接触摸交互。这避免了误触，同时保留了精细控制的能力。

## 最佳实践

- **已有项目迁移**：先排查项目里那些"为了好看而手搓的 UI"。如果是单轴的（如音量、进度），直接补上 `.adjustable` 和 `accessibilityAdjustableAction`；如果是多轴或画板类的，把隐藏的辅助按钮删掉，换成 `accessibilityActions`
- **新项目建议**：在设计自定义控件的第一天，就把 Accessibility 语义写进 API 设计里。不要等 UI 画完了再想怎么"加"无障碍，而是让控件本身就"是"无障碍的。比如设计一个 2D 摇杆，它的 Value 就应该返回极坐标或 XY 值，而不是只返回一个状态
- **实战避坑**：播报绝对不能滥用。像视频里提到的 0.3 秒防抖阈值是个很好的基准线。如果用户滑动很快，一秒钟播报 10 次"50%、51%、52%"会让 VoiceOver 用户直接关掉 App
