## Highlight

> iOS 27 和 watchOS 27 把心率区间和骑行功率区间直接内置到 HealthKit 中。你不再需要自己写算法计算区间、累加时间——系统会自动根据用户的年龄和静息心率生成个性化区间，实时推送跨区通知，并在训练结束后给出完整的时间分布。

---

## 核心内容

### 1. 这场演讲解决什么问题

健身 App 开发者一直面临一个工程难题：**如何把原始传感器数据转化为有意义的训练指导**？

以心率为例：

- 用户的心率从 135 bpm 跳到 150 bpm，这意味着什么？
- 用户在 Zone 3 待了多久？Zone 4 呢？
- 不同用户的心率区间完全不同（取决于年龄、静息心率）
- 骑行功率区间又有一套完全不同的计算逻辑（基于功能性阈值功率 FTP）

以前你需要：

1. 自己实现心率区间计算公式（如 Karvonen 公式）
2. 自己监听心率样本流
3. 自己处理传感器断连
4. 自己累加每个区间的停留时间
5. 自己存储和展示这些数据

现在 HealthKit 帮你做了所有这些。

---

### 2. 心率区间和骑行功率区间

#### 2.1 什么是 Workout Zones

**心率区间（Heart Rate Zones）**：

- 基于用户的年龄和静息心率计算
- 通常分为 5 个区间（Zone 1 到 Zone 5）
- 每个区间对应不同的训练强度
- 例如：Zone 1 是恢复区，Zone 5 是最大努力区

**骑行功率区间（Cycling Power Zones）**：

- 基于用户的**功能性阈值功率（Functional Threshold Power, FTP）**
- 以瓦特（watts）为单位测量功率输出
- 同样分为多个区间

#### 2.2 系统如何计算区间

HealthKit 使用以下信息生成个性化区间：

- 用户年龄（来自健康档案）
- 静息心率（历史数据）
- 功能性阈值功率（骑行，用户手动设置或通过测试获得）

系统会自动维护这些区间的准确性，用户也可以在设置中手动调整。

### 3. 从已完成的训练中读取区间数据

训练结束后，你可以从 `HKWorkout` 或 `HKWorkoutActivity` 中获取区间统计：

```swift
// 从已完成的训练读取心率区间数据
if let heartRateZoneGroup = workout.zoneGroupsByType?[HKQuantityType(.heartRate)] {
    let zones = ZoneDisplayData(
        zoneCount: heartRateZoneGroup.configuration.zones.count,
        currentZoneIndex: nil,
        durations: heartRateZoneGroup.zoneDurations.map(\.duration)
    )
}
```

`HKWorkoutZoneGroup` 包含两个核心属性：

- **configuration**：区间配置，包括数量类型（心率/功率）、来源（系统自动/用户手动/App 自定义）、每个区间的上下界
- **zoneDurations**：每个区间的停留时长数组

#### 3.1 区间配置（Configuration）

```swift
// 区间配置包含的信息
let config = heartRateZoneGroup.configuration
let quantityType = config.quantityType        // 心率或骑行功率
let source = config.source                     // .automatic / .user / .app
let zones = config.zones                       // 区间数组

// 每个区间的信息
for zone in zones {
    let index = zone.index                     // 区间编号
    let min = zone.minimumQuantity             // 下限
    let max = zone.maximumQuantity             // 上限
}
```

区间保证**连续且不重叠**，第一个区间没有下限，最后一个区间没有上限，确保所有可能的值都被覆盖。

#### 3.2 区间来源（Source）

- **.automatic**：系统自动生成，基于用户年龄和静息心率
- **.user**：用户在设置中手动调整
- **.app**：你的 App 在训练开始时提供了自定义区间

---

### 4. 实时区间更新

#### 4.1 在训练中监听区间变化

对于正在进行的训练，HealthKit 会在用户跨越区间边界时发送实时更新：

```swift
func workoutBuilder(
    _ workoutBuilder: HKLiveWorkoutBuilder,
    didUpdateWorkoutZone zoneUpdate: HKLiveWorkoutZoneUpdate
) {
    guard let zoneGroup = zoneUpdate.zoneGroup else {
        return
    }
    
    if let currentIndex = zoneUpdate.currentZoneDuration?.zone.index {
        let data = ZoneDisplayData(
            zoneCount: zoneGroup.configuration.zones.count,
            currentZoneIndex: currentIndex,
            durations: zoneGroup.zoneDurations.map(\.duration)
        )
        Task { @MainActor in
            self.heartRateZones = data
        }
    }
}
```

`HKLiveWorkoutZoneUpdate` 包含：

- **currentZone**：当前所在的区间
- **previousZone**：上一个区间（用于检测跨越）
- **zoneGroup**：完整的区间配置和所有区间的累计时间
- **timestamp**：最后处理的样本时间戳

#### 4.2 更新时机

更新只在**当前区间发生变化时**发送（如从 Zone 2 到 Zone 3），而不是每次心率样本都发送。这减少了不必要的回调，同时确保你不会错过重要的区间跨越事件。

### 5. 自定义区间配置

#### 5.1 检查用户是否已设置偏好区间

```swift
// 检查用户是否已设置心率区间偏好
if try await builder.zoneConfiguration(for: HKQuantityType(.heartRate)) == nil {
    // 用户没有设置，可以提供自定义区间
}
```

#### 5.2 创建自定义区间

如果你的 App 有特定的训练逻辑，可以提供自定义区间：

```swift
// 创建自定义心率区间边界
let defaultHeartRateZoneThresholds = [91.0, 114.0, 136.0, 158.0]
let bpmUnit = HKUnit.count().unitDivided(by: HKUnit.minute())
let boundaries = defaultHeartRateZoneThresholds.map {
    HKQuantity(unit: bpmUnit, doubleValue: $0)
}

// 创建区间配置
let heartRate = HKQuantityType(.heartRate)
let defaultConfiguration = try HKWorkoutZoneConfiguration(
    quantityType: heartRate,
    zoneBoundaries: boundaries
)

// 应用到训练
let builder: HKLiveWorkoutBuilder = ...
try await builder.setCustomZoneConfiguration(defaultConfiguration, for: heartRate)

// 开始数据收集
let startDate = Date()
try await builder.beginCollection(at: startDate)
```

关键点：

- 自定义区间只在当前训练期间生效
- 不会覆盖用户的系统偏好设置
- 训练结束后，区间数据会随训练记录一起保存

---

### 6. 骑行功率区间

骑行功率区间的使用方式与心率区间几乎完全相同，只需更换数量类型：

```swift
// 使用骑行功率区间
let cyclingPower = HKQuantityType(.cyclingPower)
if let powerZoneGroup = workout.zoneGroupsByType?[cyclingPower] {
    // 与心率区间相同的结构
}
```

骑行功率区间基于用户的功能性阈值功率（FTP），这是骑行训练中最重要的指标之一。

## 最佳实践

- **权限申请要完整**：读取区间数据需要同时申请 `HKWorkoutType` 和 `HKQuantityType(.heartRate)`（或 `.cyclingPower`）的读取权限。只申请 Workout 权限会导致 `zoneGroupsByType` 返回空字典。
- **优先使用系统区间**：如果用户已经设置了心率区间偏好，优先使用系统生成的区间。这些区间基于用户的真实生理数据（年龄、静息心率），比固定阈值更准确。
- **自定义区间用于特殊场景**：只有在你的 App 有特定训练协议时才提供自定义区间（如 HIIT 间歇训练的特定目标区间）。
- **实时 UI 反馈**：在训练中实时显示当前区间，并用颜色区分（Zone 1 绿色、Zone 5 红色）。当用户跨越区间时给出提示（如"进入 Zone 4，注意控制强度"）。
- **训练后分析**：利用 `zoneDurations` 生成训练报告。显示在每个区间停留的时间和百分比，帮助用户了解自己的训练分布。
- **多运动类型支持**：对于铁人三项等多运动训练，`zoneGroupsByType` 在 `HKWorkoutActivity` 级别可用，可以为每个运动阶段单独分析区间。
