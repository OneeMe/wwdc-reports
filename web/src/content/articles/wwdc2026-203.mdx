## Highlight

> iOS 27 把 Apple Notes 和 Freeform 里那个"随手写、随手搜"的手写识别能力开放给了所有开发者。`PKStrokeRecognizer` 支持 29 种语言，完全离线运行，三行代码就能把用户的手写笔迹转成可搜索的文本。

---

## 核心内容

### 1. 这场演讲解决什么问题

在 iPad 上用 Apple Pencil 手写笔记是一种很自然的体验，但手写内容的"数字化"一直是痛点：

- 写了很多笔记，但没法搜索里面的关键词
- 手写内容无法被 Spotlight 索引
- 教育类 App 无法自动批改学生的手写答案
- 需要依赖第三方 OCR 服务，有隐私和成本问题

PencilKit 今年新增的**手写识别 API** 解决了这些问题。而且它不是简单的 OCR —— 它是专为手写笔迹优化的识别引擎，理解笔画顺序、书写习惯和不同字母体系。

---

### 2. PKStrokeRecognizer：手写识别的核心 API

`PKStrokeRecognizer` 是一个 Swift actor，所有方法都是异步的，线程安全且不会阻塞主线程。

#### 2.1 识别文本（Recognized Text）

最基础的用法：把手写笔迹转成字符串。

```swift
import PencilKit

let recognizer = PKStrokeRecognizer()
await recognizer.updateDrawing(drawing)
myLabel.text = await recognizer.recognizedText()
```

关键点：

- 默认使用设备的系统语言进行识别
- 可以通过 `preferredLanguages` 显式指定语言
- 支持识别整个画布，也可以只识别指定的笔画子集
- iOS 27 支持 **29 种语言**，包括中文、日文、韩文等

```swift
// 查看支持的语言
let supportedLanguages = PKStrokeRecognizer.supportedLanguages

// 显式设置识别语言
let recognizer = PKStrokeRecognizer()
recognizer.preferredLanguages = ["zh-Hans", "en"]
```

注意：**Simulator 中手写识别只支持拉丁字符**。测试中文、日文等非拉丁语言必须在真机上进行。

#### 2.2 可索引内容（Indexable Content）

如果你想让手写内容能被 Spotlight 搜索到，用 `indexableContent`：

```swift
import PencilKit

let recognizer = PKStrokeRecognizer()
await recognizer.updateDrawing(drawing)
if let indexedContent = await recognizer.indexableContent {
    index(text: indexedContent)
}
```

`indexableContent` 返回一个标准化的字符串，适合用于：

- Spotlight 核心索引
- 全文搜索
- 内容摘要生成

#### 2.3 搜索手写内容（Find Text）

在手写笔记中搜索特定文字，并高亮匹配区域：

```swift
import PencilKit

let recognizer = PKStrokeRecognizer()
await recognizer.updateDrawing(drawing)
let results = await recognizer.search("apple")
for result in results {
    highlight(bounds: result.bounds)
}
```

`search(_:)` 返回每个匹配结果的边界框（bounds），你可以用它来：

- 高亮显示匹配的手写文字
- 自动滚动到第一个匹配位置
- 统计匹配次数

### 3. 手写识别的技术特点

#### 3.1 完全离线运行

手写识别模型**内置于操作系统**，不需要网络连接：

- 识别过程完全在设备端进行
- 没有数据上传到云端
- 没有 API 调用成本
- 支持所有能运行 iOS 27 的设备

#### 3.2 实时识别能力

`PKStrokeRecognizer` 支持增量更新。用户写字的同时，你可以实时获取识别结果：

```swift
// 用户每写完一笔，就更新识别结果
func drawingDidChange(_ drawing: PKDrawing) {
    Task {
        await recognizer.updateDrawing(drawing)
        let text = await recognizer.recognizedText()
        await MainActor.run {
            self.transcriptionLabel.text = text
        }
    }
}
```

这在教育类 App 中特别有用：学生写一个字，App 立即反馈是否正确。

#### 3.3 多语言混合识别

`PKStrokeRecognizer` 可以处理同一画布上的多语言混合书写。比如用户先写了一段英文，又写了一段中文，识别器能自动切换语言模型。

---

### 4. 与 PaperKit 的关系

iOS 26 引入了 PaperKit，它构建在 PencilKit 之上，提供了更完整的纸张体验（页面管理、笔记本结构等）。

**所有 PencilKit 的新 API 在 PaperKit 中同样可用**。如果你在使用 PaperKit 构建笔记 App，手写识别可以直接使用，不需要额外适配。

```swift
import PaperKit

// PaperKit 的 PKPaperView 内部使用 PencilKit 的 drawing
// 手写识别 API 完全兼容
let recognizer = PKStrokeRecognizer()
await recognizer.updateDrawing(paperView.currentPage.drawing)
```

## 最佳实践

- **延迟加载识别器**：`PKStrokeRecognizer` 的初始化会加载语言模型，有一定开销。建议在使用时才创建，而不是 App 启动时就初始化。
- **批量更新优于频繁更新**：虽然支持实时识别，但如果用户写字速度很快，过于频繁的 `updateDrawing` 调用会影响性能。可以设置一个节流（throttle）机制，比如每 0.5 秒更新一次。
- **处理识别失败**：手写识别不是 100% 准确的，特别是字迹潦草时。给用户提供编辑识别结果的入口，不要把识别文本设为只读。
- **教育场景的特殊考虑**：如果你在做语言学习 App，可以利用"部分识别"能力。即使用户没写完整个词，识别器也可能返回当前最可能的结果，可以用来做实时拼写检查。
- **测试覆盖多语言**：如果你的用户群体使用多种语言，确保在真机上测试每种语言的识别效果。Simulator 只支持拉丁字符，不能替代真机测试。
