## Highlight

> macOS Sonoma 的 Virtualization 框架新增了三个能力：虚拟机显示分辨率自动跟随窗口大小、暂停并保存运行中的虚拟机到文件后再恢复、以及通过 NBD（网络块设备）将虚拟机存储挂载到远程服务器。

## 核心内容

如果你在 Mac 上用过虚拟机，一定遇到过这些痛点：窗口放大后虚拟机屏幕不动，两边留大片黑边；做了一半的实验想暂停，但关闭虚拟机就得从头再来；想把虚拟机的磁盘放在 NAS 或远程服务器上，却没有原生支持。

macOS Sonoma 的 Virtualization 框架一次性解决了这三个问题。

### 自动调整显示分辨率

以前 `VZVirtualMachineView` 固定了虚拟机屏幕尺寸。你拖动窗口变大，虚拟机内部分辨率不变，结果就是黑边越来越多。Apple 在 WWDC22 介绍了 Virtualization 框架的基础用法，但显示适配问题一直留到了今年。

现在只需设置一个布尔属性 `automaticallyReconfiguresDisplay`，虚拟机内部分辨率就会自动匹配视图的实际大小。

具体做法：创建 `VZVirtualMachineView`，关联到 `VZVirtualMachine` 实例，然后把这个属性设为 `true`。

```swift
// virtualMachine 是一个 VZVirtualMachine 实例
let virtualMachineView = VZVirtualMachineView()
virtualMachineView.virtualMachine = virtualMachine

virtualMachineView.automaticallyReconfiguresDisplay = true
```

关键点：

- `VZVirtualMachineView` 是 macOS 上显示虚拟机画面的 NSView 子类
- `virtualMachine` 属性把视图绑定到虚拟机实例
- `automaticallyReconfiguresDisplay` 为 `true` 时，窗口大小变化会触发虚拟机内部分辨率同步调整
- 这行代码加在虚拟机配置完成后、启动前即可

### 保存和恢复虚拟机状态

以前关闭虚拟机意味着丢掉所有运行时状态——打开的文件、正在执行的进程、临时数据。下次启动只能从零开始。

macOS Sonoma 新增了 `saveMachineState` 和 `restoreMachineState` 两个异步方法。它们把虚拟机的完整状态（CPU 寄存器、内存、设备状态）序列化到一个 `.vzvmsave` 文件中。

**保存状态：**

```swift
// virtualMachine 是一个正在运行的 VZVirtualMachine
try await virtualMachine.pause()

let saveFileURL = URL(filePath: "SaveFile.vzvmsave", directoryHint: .notDirectory)
try await virtualMachine.saveMachineStateTo(url: saveFileURL)
```

关键点：

- 保存前必须先调用 `pause()`，确保状态一致性——正在写入的数据不会丢
- `saveFileURL` 使用 `.notDirectory` hint，告诉系统这是一个文件而非目录
- `saveMachineStateTo(url:)` 是异步方法，耗时取决于虚拟机内存大小
- 保存的文件是硬件加密的，绑定到当前 Mac 和用户——其他设备或账号无法读取

**恢复状态：**

```swift
let configuration = VZVirtualMachineConfiguration()
// 自定义配置...

let virtualMachine = VZVirtualMachine(configuration: configuration)

let saveFileURL = URL(filePath: "SaveFile.vzvmsave", directoryHint: .notDirectory)
try await virtualMachine.restoreMachineStateFrom(url: saveFileURL)

try await virtualMachine.resume()
```

关键点：

- 恢复时仍需要创建 `VZVirtualMachineConfiguration`——配置必须和保存时一致
- `restoreMachineStateFrom(url:)` 读取保存文件并重建虚拟机内部状态
- 恢复后调用 `resume()` 继续运行，而不是 `start()`——这是从保存点继续，不是全新启动
- 如果保存文件格式与当前框架版本不兼容，API 会抛出错误。处理方式是丢弃旧文件，用 `start()` 冷启动

### 网络块设备（NBD）

虚拟机存储通常是一个本地磁盘镜像文件。但数据中心场景需要把存储放在远程服务器上——比如 SAN、NAS、或分布式存储集群。

macOS Sonoma 引入了 `VZNetworkBlockDeviceStorageDeviceAttachment`，让 virtio block device 可以直接连接远程 NBD 服务器。

```swift
let url = URL(string: "nbd://localhost:10809/myDisk")!
let attachment = try VZNetworkBlockDeviceStorageDeviceAttachment(url: url)

let blockDevice = VZVirtioBlockDeviceConfiguration(attachment: attachment)
```

关键点：

- URL 使用 `nbd://` 协议，格式为 `nbd://host:port/exportName`
- `VZNetworkBlockDeviceStorageDeviceAttachment` 封装了 NBD 客户端连接
- 这个 attachment 可以直接传入 `VZVirtioBlockDeviceConfiguration`，和本地磁盘镜像用法完全一致
- 虚拟机内部看到的仍然是一个普通块设备，不需要感知底层是本地还是远程

NBD 连接可能随时断开。框架提供了 delegate 协议来处理网络中断：

```swift
let url = URL(string: "nbd://localhost:10809/myDisk")!
let attachment = try VZNetworkBlockDeviceStorageDeviceAttachment(url: url)

// NetworkBlockDeviceAttachmentDelegate 实现了 delegate 协议
let delegate = NetworkBlockDeviceAttachmentDelegate()
attachment.delegate = delegate

let blockDevice = VZVirtioBlockDeviceConfiguration(attachment: attachment)
```

关键点：

- delegate 需要实现 `VZNetworkBlockDeviceStorageDeviceAttachmentDelegate` 协议
- 协议包含连接断开、重连、错误处理等回调方法
- 数据中心环境中，网络存储断开是常态而非异常——delegate 处理让虚拟机更健壮

### NVMe 控制器和 Mac 键盘映射

除了 NBD，macOS Sonoma 还引入了两个辅助改进。

**NVMe 控制器**作为 virtio block device 的替代方案。`VZNVMExpressControllerConfiguration` 提供更低的 I/O 延迟和更高的吞吐量，适合对存储性能敏感的场景（数据库、编译缓存）。用法和 virtio 块设备类似，配置后添加到虚拟机的 `storageDevices` 数组即可。

**Mac 键盘映射**解决了 Apple 键盘上特殊按键的传递问题。Globe 键（地球键）、Touch ID、媒体键等在虚拟机里原本不可用。新的键盘映射机制让这些按键直接传递给虚拟 Mac，就像在物理机上使用一样。

## 核心启发

**1. 做一个"快照管理器" Mac 应用**

- **做什么**：在虚拟 Mac 上实现类似 Docker snapshot 的体验——一键保存当前状态、随时回滚。
- **为什么值得做**：`saveMachineState` / `restoreMachineState` 提供了底层能力，但缺少用户友好的管理界面。可以自动命名、带时间戳、支持备注。
- **怎么开始**：封装 `saveMachineStateTo(url:)` 调用，将 `.vzvmsave` 文件存到应用沙盒目录，用 NSTableView 展示快照列表，支持一键恢复。

**2. 开发一个"开发者环境即服务"工具**

- **做什么**：预配置 macOS 开发环境的虚拟机模板，团队成员一键启动，环境一致。
- **为什么值得做**：保存/恢复 + NBD 远程存储的组合，让"预装好 Xcode、Homebrew、Ruby 的 macOS VM"可以秒级启动。存储放在中央服务器，多人共享同一镜像。
- **怎么开始**：先用 `VZMacOSInstaller` 安装基础 macOS，配置开发工具链，`saveMachineStateTo(url:)` 保存为模板。分发时把 `.vzvmsave` 文件和 NBD 服务器地址一起给团队成员。

**3. 构建一个"远程实验室"服务**

- **做什么**：在 Mac 服务器上运行多个 macOS 虚拟机，通过 VNC 远程连接，用于 CI/CD 或自动化测试。
- **为什么值得做**：NBD 让虚拟机存储集中管理，NVMe 控制器提供接近原生的 I/O 性能。一台 Mac Pro 可以同时运行多个 macOS 实例作为 CI worker。
- **怎么开始**：用 NBD 服务器（如 `nbd-server`）托管磁盘镜像，`VZNetworkBlockDeviceStorageDeviceAttachment` 连接。配合 `saveMachineState` 实现测试环境的快速重置。

**4. 做一个虚拟机"无缝模式"增强工具**

- **做什么**：让虚拟机窗口和 Mac 原生桌面融合——虚拟机应用窗口出现在宿主 Dock 中，而非困在虚拟机窗口内。
- **为什么值得做**：`automaticallyReconfiguresDisplay` 已经解决了分辨率问题，但虚拟机和宿主的交互仍然割裂。结合键盘映射，可以让虚拟 Mac 的体验更接近原生。
- **怎么开始**：利用 Mac 键盘映射传递全局快捷键，结合 `VZVirtualMachineView` 的自定义渲染，实现窗口级别的融合。
