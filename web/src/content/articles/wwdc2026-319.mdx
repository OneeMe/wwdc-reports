## Highlight

> 端侧模型只有 4K 上下文，复杂任务力不从心。Private Cloud Compute 上的服务器模型把上下文拉到 32K，支持 reasoning，而且 API 和端侧模型完全统一 — 只需要改一行代码。没有 API Key、没有计费、隐私由 Apple 保障。

---

## 核心内容

### 1. 这场演讲解决什么问题

去年 Foundation Models framework 提供了端侧模型，但能力有限：

- 4K 上下文，处理长文档吃力
- 不支持复杂推理
- 大量 tool calls 或大输出时性能受限

开发者想上更强的模型，通常要自己接第三方 API，面临 API Key 管理、计费、隐私合规等问题。

Private Cloud Compute（PCC）解决了这些问题：提供服务器级模型能力，同时保持隐私保护，且无需开发者管理认证和计费。

### 2. 从端侧模型切换到 PCC：一行代码

```swift
import FoundationModels

// 端侧模型
let onDeviceSession = LanguageModelSession()
let response = try await onDeviceSession.respond(to: "Summarize this article: \(article)")

// 切换到 PCC 服务器模型 — 只改这一行
let pccSession = LanguageModelSession(
    model: PrivateCloudComputeLanguageModel()
)
let pccResponse = try await pccSession.respond(to: "Summarize this article: \(article)")
```

Foundation Models framework 提供统一的 Swift API，无论用哪个模型，结构化输出和 tool calling 的代码都不变：

```swift
import FoundationModels

@Generable
struct ArticleSummary {
    let oneLineSummary: String
    let keyPoints: [String]
}

struct FindRelatedArticlesTool: Tool {
    // Tool 实现...
}

let session = LanguageModelSession(
    model: PrivateCloudComputeLanguageModel(),
    tools: [FindRelatedArticlesTool.self]
)

let response = try await session.respond(
    to: "Summarize this article: \(article)",
    generating: ArticleSummary.self
)
```

### 3. 检查可用性

PCC 只在支持 Apple Intelligence 的设备上可用，必须检查并优雅降级：

```swift
import FoundationModels

struct ArticleSummarizationView: View {
    private var model = PrivateCloudComputeLanguageModel()

    var body: some View {
        if model.isAvailable {
            // 显示 AI 功能 UI
        } else {
            // 降级到端侧模型或其他方案
        }
    }
}
```

### 4. 端侧模型 vs PCC 模型对比

| 特性 | 端侧模型 | PCC 模型 |
|---|---|---|
| 隐私 | 本地处理 | 端到端加密，数据不存储 |
| 网络 | 离线可用 | 需要联网 |
| 请求限制 | 无限制 | 每日限额 |
| 上下文大小 | 4K（旧设备）/ 8K（新设备） | 32K |
| Reasoning | 不支持 | 支持 |

### 5. Reasoning 级别

PCC 模型支持三个 reasoning 级别：

```swift
let response = try await session.respond(
    to: prompt,
    contextOptions: ContextOptions(reasoningLevel: .light)
)
// .light, .moderate, .deep
```

Reasoning 让模型在生成响应前先"思考"，适合复杂推理任务。但 reasoning 文本占用 token 配额，且计入上下文限制。

可以通过观察 session transcript 中的 reasoning segment 来显示进度，特别是 `.deep` 级别可能需要较长时间。

### 6. 上下文大小查询

```swift
SystemLanguageModel().contextSize      // 4096 (26.0) 或 8192 (27.0 新设备)
PrivateCloudComputeLanguageModel().contextSize  // 32768
```

根据当前模型的 `contextSize` 动态截断历史对话和 prompt，避免超出限制抛错。

### 7. 处理使用限额

PCC 请求绑定用户的 iCloud 账号，每个用户有每日限额。需要优雅处理限额耗尽的情况：

```swift
struct ArticleSummarizationView: View {
    private var model = PrivateCloudComputeLanguageModel()

    var body: some View {
        // 接近限额时显示警告
        if case .belowLimit(let info) = model.quotaUsage.status {
            if info.isApproachingLimit {
                Text("Nearing usage limit.")
                    .foregroundStyle(Color.orange)
            }
        }
        
        // 限额已耗尽
        if model.quotaUsage.isLimitReached {
            Text("Usage limit exceeded.")
                .foregroundStyle(Color.red)
        }
        
        // 提供升级选项
        if let suggestion = model.quotaUsage.limitIncreaseSuggestion {
            Button("Show options") {
                suggestion.show()
            }
        }
    }
}
```

处理建议：

- 避免用 alert 显示限额信息，应该更新 UI 状态（如禁用按钮）
- 提供可操作的升级路径，让用户能提升限额
- 在接近限额时提前提示，让用户决定哪些请求值得做

Xcode 提供调试选项模拟限额状态：Scheme > Debug > Options > Simulate Apple Foundation Models Availability，可选择 "Quota Usage Limit Reached" 或 "Nearing Usage Limit"。

### 8. 评估与选择模型

不要凭感觉选择模型。用 Evaluations framework 评估你的具体任务：

- 端侧模型在某些任务上表现可能出乎意料地好
- 只有数据能告诉你该用哪个模型
- 可以结合使用：简单任务用端侧，复杂任务用 PCC

## 最佳实践

- **始终检查 `isAvailable`**：PCC 只在 Apple Intelligence 设备上可用
- **优雅处理限额**：更新 UI 状态而非弹 alert，提供升级路径
- **根据数据选择模型**：用 Evaluations framework 评估端侧模型是否足够
- **注意 reasoning 的 token 开销**：reasoning 文本计入上下文限制
- **动态截断上下文**：根据 `contextSize` 限制历史对话长度
- **新项目先上端侧**：跑通 MVP 后再评估是否需要 PCC
