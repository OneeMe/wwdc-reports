## Highlight

> Swift 6.3 和 6.4 没有搞大新闻，而是集中解决日常开发里的"小痛点"：`@available` 可以写 `anyAppleOS` 了，模块命名冲突有 `::` 选择器了，警告可以用 `@diagnose` 精细控制了。同时所有权系统（Ownership System）走向成熟，`~Copyable` 类型支持了更多协议，`borrow`/`mutate` 访问器让安全的高性能代码不再需要 unsafe 操作。

---

## 核心内容

### 1. 这场演讲解决什么问题

Swift 这几年在并发和类型安全上进步很大，但日常开发中积累了不少"语法债务"：

- 写多平台代码时 `@available(iOS 27, macOS 27, watchOS 27, tvOS 27, visionOS 27, *)` 长得离谱
- 两个模块导入了同名类型，Swift 报错但解决方案不够直观
- 某些 API 的 deprecation 警告在项目中刷屏，但又暂时没法替换
- 追求极致性能时，不得不写 unsafe 代码来避免拷贝开销

Swift 6.3/6.4 就是来还这些债的。

### 2. 日常 ergonomics 改进

**`anyAppleOS` 统一平台可用性**：

```swift
// 以前
@available(macOS 27, iOS 27, watchOS 27, tvOS 27, visionOS 27, *)
func showStatus() { ... }

#if os(macOS) || os(iOS) || os(watchOS) || os(tvOS) || os(visionOS)
func makeWidget() -> some Widget { ... }
#endif

// 现在
@available(anyAppleOS 27, *)
func showStatus() { ... }

#if os(anyAppleOS)
func makeWidget() -> some Widget { ... }
#endif
```

**模块选择器 `::` 解决命名冲突**：

```swift
import Rocket
import GiftShopToys

let rocket1 = SaturnV()            // 报错：ambiguous
let rocket2 = Rocket.SaturnV()     // 可能还是不对
let rocket3 = Rocket::SaturnV()    // 明确指向 Rocket 模块的 SaturnV

// 成员方法也适用
launchPadTechnician.HumanResources::fire()
```

**`@diagnose` 精细控制警告**：

```swift
@diagnose(DeprecatedDeclaration, as: ignored, reason: "暂时无法迁移")
func makeLegacyMission() -> Mission { ... }

@diagnose(StrictMemorySafety, as: warning)
func securityCriticalFunction() { ... }

@diagnose(ErrorInFutureSwiftVersion, as: error)
func prepareForNextSwift() { ... }
```

**并发诊断改进**：

- Task 中抛出的错误如果未被处理，现在会收到警告
- `defer` 块里可以调用 `await` 了
- `weak let` 让类可以自动满足 `Sendable`（不需要 `@unchecked`）
- `~Sendable` 语法显式声明一个类型不是 `Sendable`，但子类仍可以是

### 3. 所有权系统（Ownership System）走向成熟

**`~Copyable` 和 `~Escapable` 关联类型**：

```swift
protocol Iterable<Element, Failure>: ~Copyable, ~Escapable {
    associatedtype Element: ~Copyable
    associatedtype IterableIterator: IterableIteratorProtocol<Element, Failure>, ~Copyable, ~Escapable

    func makeIterableIterator() -> IterableIterator
}
```

**`borrow` 和 `mutate` 访问器**：

```swift
@safe public struct UniqueBox<Value: ~Copyable>: ~Copyable {
    private let valuePointer: UnsafeMutablePointer<Value>

    public var value: Value {
        borrow { valuePointer.pointee }
        mutate { &valuePointer.pointee }
    }
}
```

关键点：

- `borrow` 访问器提供只读借用，不触发拷贝
- `mutate` 访问器提供可变借用，编译器保证独占访问
- 配合 `@safe` 属性，可以在不写 `unsafe` 代码的情况下获得 C++ 级别的性能

**`@specialized` 加速泛型函数**：

```swift
@specialized(where Values == [UInt8])
func histogram<Values>(of values: Values) -> [256 of Int] where Values: Sequence<UInt8> {
    // 编译器会为 [UInt8] 生成专门的优化版本
}
```

### 4. 标准库和工具改进

- **Dictionary.mapKeyedValues**：映射字典值时保留 key 信息
- **新的 FilePath 类型**：正确处理 macOS 的 `..namedresource` 等特殊路径组件
- **Swift Testing 互操作**：在 XCTest 中调用 `#expect`，在 Swift Testing 中调用 `XCTAssertEqual`
- **Subprocess 输出流**：支持流式读取子进程输出
- **ProgressManager**：新的进度报告 API，支持并发和元数据

---

## 最佳实践

- **立刻替换 `@available`**：全局搜索 `@available(iOS *, macOS *, *)` 模式，替换为 `anyAppleOS`，代码清爽度提升明显
- **用 `::` 解决命名冲突**：排查项目中因为模块冲突而使用的 `typealias`  workaround，用 `Module::Type` 还原真实命名
- **渐进式尝试所有权系统**：不要一上来就把整个数据模型改成 `~Copyable`，先从"独占资源"（文件句柄、数据库连接、锁）开始
- **注意 `weak let` 的限制**：`weak let` 只能在初始化时赋值一次，如果设计模式依赖后续重新绑定弱引用，这个特性不适用
