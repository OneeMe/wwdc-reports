## Highlight

> Evaluations framework 让你用科学实验的方法迭代优化 AI 功能——先校准你的"模型裁判"（用 Cohen's kappa 衡量它和人类专家的一致性），再用控制变量法对比不同 prompt 和工具配置的效果，而不是靠拍脑袋调 prompt。

## 核心内容

### 1. 这场演讲解决什么问题

在 App 里集成 LLM 功能后，最大的挑战是：怎么知道你的改动真的让效果变好了？凭感觉调 prompt 很容易陷入"改了这里、坏了那里"的循环。这场演讲介绍了一套系统化的"爬山法"（hill-climbing）流程，用 Evaluations framework 量化每次改动的效果。

演讲用 Book Tracker App 的案例贯穿：根据用户的书评自动生成标签，通过 Evaluation 不断迭代提升标签质量。

### 2. Evaluation 的基本结构

一个 Evaluation 由三部分组成：Dataset（数据集）、Subject（被测对象）、Evaluators（评估器）。

```swift
struct BookTaggingEvaluation: Evaluation {
    // Dataset：加载测试样本
    var dataset = ArrayLoader(samples:
        Book.sampleBooks.map { book in
            ModelSample(prompt: book.review, expected: BookTags(tags: book.tags))
        }
    )

    // Subject：调用你的 AI 功能
    func subject(from sample: ModelSample<BookTags>) async throws -> ModelSubject<BookTags> {
        let result = try await BookTaggingService.generateTags(for: sample.promptDescription)
        return ModelSubject(value: result)
    }

    // Evaluators：定义评估标准
    var evaluators: Evaluators {
        // 1. 标签数量在 3-8 之间
        Evaluator { _, subject in
            let count = subject.value.tags.count
            if count >= 3 && count <= 8 {
                return tagCount.passing(rationale: "\(count) tags")
            }
            return tagCount.failing(rationale: "Got \(count) tags, expected 3-8")
        }

        // 2. 至少有一个标签是已知类型
        Evaluator { _, subject in
            let tags = subject.value.tags.map { $0.lowercased() }
            let knownGenres = await BookTaggingService.knownGenres
            for tag in tags {
                if knownGenres.contains(tag) {
                    return hasGenreTag.passing(rationale: "Matched \(tag)")
                }
            }
            return hasGenreTag.failing()
        }

        // 3. 无重复标签
        Evaluator { _, subject in
            let uniqueCount = Set(subject.value.tags.map { $0.lowercased() }).count
            if subject.value.tags.count - uniqueCount > 0 {
                return noDuplicates.failing(rationale: "Found duplicates")
            }
            return noDuplicates.passing()
        }

        // 4. 质量评估：用模型当裁判
        ModelJudgeEvaluator(
            judge: .default,
            dimensions: [relevance, usefulness],
            prompt: ModelJudgePrompt(
                instructions: "You are evaluating automatically generated tags...",
                evaluationTarget: { output in output.tags.joined(separator: ", ") },
                reference: { input, _ in
                    ["Expected Tags": input.expected?.tags.joined(separator: ", ") ?? ""]
                }
            )
        )
    }
}
```

关键点：

- `ModelSample` 包含输入 prompt 和期望输出（ground truth）
- `Evaluator` 可以是简单的启发式规则，也可以是 `ModelJudgeEvaluator`
- `ModelJudgeEvaluator` 用另一个 LLM 来评估输出质量，适合主观性强的指标
- `ScoreDimension` 定义评分维度和量表，让评估更结构化

### 3. 校准模型裁判：Cohen's Kappa

模型裁判本身可能和人类专家有偏差。演讲引入了 Cohen's kappa 来量化这种一致性：

```swift
func aggregateMetrics(using aggregator: inout MetricsAggregator) {
    let expertRelevance = Self.samples.map {
        Double($0.expected?.expertRelevanceScore ?? 0)
    }
    let expertUsefulness = Self.samples.map {
        Double($0.expected?.expertUsefulnessScore ?? 0)
    }

    aggregator.group("Relevance") { group in
        group.computeMean(of: relevance.metric)
        group.computeStandardDeviation(of: relevance.metric)
        group.custom(of: relevance.metric, label: "Relevance Alignment Score") { judge in
            cohensKappa(ratings1: expertRelevance, ratings2: judge) ?? 0
        }
    }
}
```

用 Swift Testing 验证裁判校准：

```swift
@Suite("Book Tag Judge Calibration")
struct BookTagJudgmentCalibrationTests {
    static let evaluation = BookTagJudgmentCalibration()

    @Test("Judge Calibration", .evaluates(evaluation))
    func evaluateJudgeCalibration() async throws {
        let result = EvaluationContext.current.result
        #expect(result.aggregateValue(
            .custom(label: "Relevance: Judge vs Expert")
        ) > 0.6)
        #expect(result.aggregateValue(
            .custom(label: "Usefulness: Judge vs Expert")
        ) > 0.6)
    }
}
```

关键点：

- Cohen's kappa 排除了随机一致的概率，比简单的准确率更可靠
- kappa > 0.6 通常被认为是"中等以上一致"，是裁判可用的门槛
- 如果裁判校准不通过，先优化裁判的 prompt 和 few-shot 示例，不要急着改业务 prompt

### 4. 迭代优化：Few-shot 和 Tool Calling

校准好裁判后，就可以用它指导业务改进了。演讲展示了两种提升方式：

**改进裁判 Prompt**：加入 few-shot 示例，让裁判理解评分标准

```swift
ModelJudgeEvaluator(
    judge: SystemLanguageModel(),
    dimensions: [relevance, usefulness],
    prompt: ModelJudgePrompt(
        instructions: """
            You are calibrating with an expert librarian...
            ## Worked examples
            ### Example A — clean fit (Pride and Prejudice)
            Tags: romance, historical-fiction, love, redemption, passion
            Librarian: Relevance 4, Usefulness 4

            ### Example E — flat genre contradiction (Frankenstein)
            Tags: horror, science-fiction, ... self-help
            Librarian: Relevance 2, Usefulness 3
            """,
        // ...
    )
)
```

**加入 Tool Calling**：给模型提供查找工具，提升标签准确性

```swift
struct BookLookupTool: Tool {
    let name = "lookupBook"

    }

        // 根据书评细节查找匹配的书籍
        // ...
    }

```

对比测试：有 tool 和没 tool 的效果

```swift
@Suite("Book Tag Evaluations")
struct BookTagEvaluationTests {
    static let evaluation = BookTaggingEvaluation()
    static let lookupEvaluation = BookTaggingWithLookupEvaluation()

    @Test("Book Tag Evaluations", .evaluates(evaluation))
    func evaluateBookTagging() async throws {
        let result = EvaluationContext.current.result
        #expect(result.aggregateValue(.mean(of: tagCount)) >= 0.8)
        #expect(result.aggregateValue(.mean(of: noDuplicates)) == 1)
    }

    @Test("Book Tag Evaluations (with BookLookupTool)",
          .evaluates(lookupEvaluation))
    func evaluateBookTaggingWithLookup() async throws {
        let result = EvaluationContext.current.result
        #expect(result.aggregateValue(.mean(of: tagCount)) >= 0.8)
        #expect(result.aggregateValue(.mean(of: noDuplicates)) == 1)
    }
}
```

## 最佳实践

- **先校准裁判，再优化业务**：如果 Model Judge 和人类专家的 kappa 低于 0.6，优化业务 prompt 的结果不可信
- **控制变量**：每次只改一个变量（prompt、model、tool），然后跑 evaluation 对比，不要同时改多个
- **用真实数据**：evaluation dataset 应该来自真实用户场景，不是人工构造的简单用例
- **关注维度间的 trade-off**：改进一个维度时可能损害另一个，演讲展示了 Relevance 提升但 Usefulness 下降的情况
- **把 evaluation 当作测试写**：用 Swift Testing 的 `.evaluates()` 宏把 evaluation 集成到 CI 中
