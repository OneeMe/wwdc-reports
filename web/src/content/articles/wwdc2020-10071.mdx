## Highlight

> Apple 把 Siri 语音体验拆成 System Intents、custom intents、Shortcuts、Suggestions、Automations 和 silent/voice modes，并给出判断哪些 App 功能适合语音、如何编写对话文案的设计准则。

## 核心内容

很多 App 的核心任务藏在几层界面后面。新用户需要菜单和层级来理解功能，熟练用户却经常只想直接完成一件事：播放某个艺术家的新专辑、点一碗常买的汤、打开一个不显眼的设置。把这些动作原样搬到语音里，让用户逐个回答表单字段，体验会变慢。

这场 session 的切入点是 Siri 的设计边界。Apple 先把 Siri 定义为 Voice、Touch 和 Automation 都能使用的系统能力，再把开发者能接入的部分分成 Intents、Shortcuts、Suggestions 和 Automations。System Intents 已经带有系统写好的自然语言流程；custom intents 则要求开发者自己梳理任务步骤、所需信息、询问顺序和失败反馈。

真正适合语音的功能有几个共同点：步骤多、重复频繁、用户目标明确，或者用户正在开车、走路、戴 AirPods，暂时不方便打开 App。语音在这里的价值是让用户越过已经熟悉的界面层级，直接到达目标动作。

Apple 还提醒开发者，语音体验要同时照顾 silent mode 和 voice mode。在 iOS 14 里，如果 iPhone 静音开关处于静音状态，Siri 默认不说话，而是用屏幕 UI 和文字对话呈现任务信息。custom intents 需要分别指定用户看屏幕和不看屏幕时的对话与 UI。

## 详细内容

### Siri 是一组入口（[00:32](https://developer.apple.com/videos/play/wwdc2020/10071/?time=32)）

session 引用 Siri Human Interface Guidelines 的定义：Siri 帮助用户通过 Voice、Touch 或 Automation 快速完成日常任务。讲者随后把 Voice 体验拆成 assistant、Intents、Shortcuts、Suggestions 和 Automations。开发者要做的事，是判断哪些 App 功能可以进入系统级入口。

关键点：

- Voice 只是 Siri 的一个模态，同一个任务在语音、触控和自动化里都应该可用。
- Intents 是开发者和 Siri 之间的共同语言，用来描述“发送消息”“点咖啡”这类任务需要什么信息。
- Shortcuts、Suggestions 和 Automations 会把 App 动作带到用户日常使用路径里。

### 先判断 System Intents 和 custom intents（[01:45](https://developer.apple.com/videos/play/wwdc2020/10071/?time=105)）

System Intents 覆盖了一些常见 domain。比如发送消息时，系统已经知道要收集收件人和消息内容，也准备好了完成请求所需的对话流程。开发者需要把自己的数据接进去，并检查这些数据放进系统对话后是否顺口，错误和不支持的情况是否能映射到 Siri 提供的反馈。

custom intents 用在系统 domain 覆盖不到的任务上。session 用“点咖啡”举例：App 团队最懂自己的业务，所以要自己定义对话流程。需要先回答三个问题：用户完成任务要走几步、每一步要提供什么信息、这些信息应该按什么顺序询问。

关键点：

- 能用 System Intents 时，优先利用系统已有的自然语言能力和对话流程。
- 使用 custom intents 时，设计工作从“写一句命令”变成“写一个可完成任务的对话”。
- 错误分支要单独设计，用户需要知道是缺少信息、内容不支持，还是 App 无法完成任务。

### Shortcuts 扩大动作的出现位置（[03:49](https://developer.apple.com/videos/play/wwdc2020/10071/?time=229)）

Shortcuts 是一组能力的统称。用户可以在 Shortcuts app 里找到预置动作，也可以创建自己的 routine，并把动作分享给别人。Siri Suggestions 可以建议用户至少做过一次的动作，也可以根据过往行为建议用户可能还没做过的动作。

Automations 让动作在设备上或 Home 环境里按条件运行，例如时间、位置或特定事件。Voice 则让 custom intents 支持用户不打开 App 也能完成任务，并把 App 动作加入自动化。

关键点：

- Shortcuts 不是单一入口，它包含 Suggestions、Shortcuts app、Automations 和 Voice。
- 动作被做成 Shortcut 后，才有机会出现在用户自己搭建的 routine 里。
- 语音入口适合承接“我现在就要完成”的任务，自动化适合承接“满足条件就执行”的任务。

### 选择适合语音的功能（[05:21](https://developer.apple.com/videos/play/wwdc2020/10071/?time=321)）

讲者明确说，Voice 不应该只是填写表单。好的语音任务通常能简化多步骤、频繁发生的交互。音乐例子里，用户不用打开 App、搜索艺术家、找到新专辑、再点播放，只要说出“播放 DaBaby 的最新专辑”，让 App 负责理解目标并执行。

Soup Chef 的例子更贴近普通 App。新用户需要先看菜单，熟客已经知道要点 tomato bisque。语音可以让熟客跳过菜单，直接下单。讲者还提到，某些不在主界面里的高级功能也适合语音，因为 power users 会用更快的方式直达它。

关键点：

- 适合语音的动作通常是高频、明确、可重复的任务。
- 语音可以绕过用户已经熟悉的导航层级。
- 驾车、走路、戴 AirPods 等场景会放大语音入口的价值。

### silent mode 和 voice mode 要分开设计（[07:16](https://developer.apple.com/videos/play/wwdc2020/10071/?time=436)）

iOS 14 中，如果 iPhone ringer switch 处于 muted 状态，Siri 默认进入 silent mode。这个模式下 Siri 不讲话，屏幕 UI 和文字对话负责呈现任务所需信息。voice mode 则会在可用屏幕继续显示 UI，同时把用户完成任务需要的信息说出来。

System Intents 已经内置这些模式的处理。custom intents 需要开发者指定：用户正在看屏幕时用什么 dialogue 和 UI，用户不看屏幕时用什么内容。Siri 会在合适的时间使用相应 pieces。

关键点：

- 同一 intent 在有屏幕和无屏幕状态下不能依赖同一套表达。
- 屏幕可见时，文字和 UI 可以承载细节。
- 无屏幕或 voice mode 下， spoken dialogue 必须短，并保留完成任务所需信息。

### 对话文案要像说话（[08:32](https://developer.apple.com/videos/play/wwdc2020/10071/?time=512)）

Siri 团队会在合适场景减少说话内容。用户第一次请求改变设置时，Siri 可以给更多信息；后续请求里，用户已经熟悉流程，就不需要同样的解释。Attribution 也是这样：如果 custom intent 做得好，用户频繁使用该 shortcut，Siri 会停止反复说明信息来源。

这会把责任交回开发者：custom intent 的 dialogue 必须自然。session 给出的规则很直接：需要用户继续提供信息时使用问题；避免业务术语；按 spoken English 写，不按 written English 写；尽量短，因为用户很难记住长段语音。

关键点：

- 问句是明确的对话标记，能告诉用户此处需要回答。
- 行话会让用户停下来思考，语音场景里尤其影响节奏。
- 熟悉后的短对话仍保留任务状态，只减少重复解释。

## 核心启发

### 1. 高频动作直达 Siri

**做什么**：把用户经常重复的动作做成可通过 Siri 触发的 intent，例如常点订单、常用设置、固定播放任务。

**为什么值得做**：session 里的音乐和 Soup Chef 例子都说明，语音最适合让熟练用户越过多层界面，直接完成明确目标。

**怎么开始**：先从日志里找重复率高、参数少、失败后容易解释的动作；如果有匹配的 System Intents，就接入系统 domain；如果没有，就用 custom intents 写清楚询问顺序和确认话术。

### 2. 给 custom intent 做双模态回复

**做什么**：为每个 custom intent 准备 silent mode 和 voice mode 两套回复策略。

**为什么值得做**：iOS 14 会根据静音开关让 Siri 默认不说话，用户看屏幕和不看屏幕时需要的信息密度不同。

**怎么开始**：把每个 intent 的结果拆成“必须说出的信息”和“可以显示在 UI 里的信息”；voice mode 只保留完成任务和确认状态所需的短句，silent mode 用界面补充细节。

### 3. 用 Shortcuts 承接用户自己的 routine

**做什么**：把 App 的可重复动作放进 Shortcuts app，让用户能把它们加入个人流程和 Automations。

**为什么值得做**：session 明确把 Shortcuts 视为 Suggestions、Shortcuts app、Automations 和 Voice 的集合，动作进入这个体系后才可能出现在更多系统入口。

**怎么开始**：挑选适合组合的动作，给参数取清晰名称，检查 Shortcuts app 中的动作描述，让用户知道这个动作会做什么、需要哪些输入。

### 4. 为语音入口建立对话审查表

**做什么**：在发布 Siri 集成前，用一张表逐条审查问题句、错误句、确认句和成功句。

**为什么值得做**：session 把自然对话归结为几个具体规则：需要回答时用问题，避免术语，使用口语表达，控制长度。

**怎么开始**：把每个 custom intent 的 happy path 和 error path 写成真实对话；逐句检查是否有行话、是否过长、是否让用户知道下一步该做什么。
