## Highlight

> LiveCommunicationKit 让 VoIP 应用获得了和系统电话完全一致的来电体验——锁屏全屏展示、Dynamic Island 实时状态、通话记录集成，用户甚至分不清这是原生电话还是第三方 App。

---

## 核心内容

### 1. 这场演讲解决什么问题

做实时通讯 App 的开发者都有一个共同的痛点：**自己的通话体验永远不如系统电话原生**。

来电时，系统电话有全屏锁屏界面、联系人头像、滑动接听手势；而第三方 VoIP App 通常只能弹一个本地通知，用户要点开通知、解锁、再进 App 才能接听。这种体验差距让用户觉得"这个 App 的通话功能很业余"。

Apple 在 iOS 26 推出了 **LiveCommunicationKit**，目标是让第三方通讯 App 获得和系统电话完全一致的体验：

- 锁屏时全屏展示来电，带联系人头像和滑动接听
- 通话中实时显示在 Dynamic Island，支持画中画多任务
- 通话记录自动进入 Phone App 的 Recents
- 支持从联系人详情直接发起通话

如果你现在还在用 `CXProvider` API，Apple 明确表示：是时候迁移了。

---

### 2. 核心概念：Conversation、Handle 和 Capabilities

LiveCommunicationKit 的核心是一个叫 **Conversation** 的对象。它代表一次实时通话，生命周期和通话本身绑定——有人加入就存在，所有人离开就销毁。

Conversation 有两个组成部分：

**Handle** —— 代表通话中的人：

```swift
let handle = Handle(
    type: .phoneNumber,           // .phoneNumber / .emailAddress / .generic
    value: "+1-650-555-0199",     // 实际标识符
    displayName: "Ryan Notch"     // 无法匹配联系人时显示的名称
)
```

关键点：

- `type` 设对很重要。如果设成 `.phoneNumber` 或 `.emailAddress`，系统会自动匹配通讯录，显示联系人姓名和头像。
- `value` 是系统用来查找联系人和回拨的标识符。
- `displayName` 是兜底方案，匹配不到联系人时显示这个名称。

**Capabilities** —— 告诉系统这次通话支持什么功能：

```swift
let capabilities: Conversation.Capabilities = [.video, .pausing, .merging]
```

系统根据 capabilities 决定显示哪些控件：

- `.video` —— 显示视频通话标识
- `.pausing` —— 长按静音按钮可以暂停通话（hold）
- `.merging` —— 支持合并通话（类似电话会议）
- `.unmerging` —— 支持拆分合并的通话

没有声明的 capability，对应的 UI 控件不会出现，避免给用户虚假的期待。

### 3. 初始化 ConversationManager

所有操作都通过 `ConversationManager` 完成。初始化时配置好全局参数：

```swift
import LiveCommunicationKit

let configuration = ConversationManager.Configuration(
    ringtoneName: "SampleRingtone.caf",
    iconTemplateImageData: UIImage(named: "SampleIcon")?.pngData(),
    maximumConversationGroups: 1,
    maximumConversationsPerConversationGroup: 2,
    includesConversationInRecents: true,
    supportsVideo: true,
    supportedHandleTypes: [.phoneNumber, .emailAddress]
)

let manager = ConversationManager(configuration: configuration)
manager.delegate = self
```

关键点：

- `ringtoneName` —— 自定义铃声，用 `.caf` 格式放在 App bundle 里。
- `iconTemplateImageData` —— 模板图，系统会用它渲染通话界面的 App 图标。
- `includesConversationInRecents` —— 设为 `true` 通话记录会出现在 Phone App 的最近通话中。
- `maximumConversationGroups` 和 `maximumConversationsPerConversationGroup` —— 限制并发通话数量，超出时系统自动拒绝新来电。
- `supportedHandleTypes` —— 声明你的 App 支持哪种联系方式，系统据此决定能否从联系人详情直接发起通话。

### 4. 接收来电：从 Push 到锁屏全屏展示

来电流程分三步：PushKit 唤醒 → 报告来电 → 系统展示全屏 UI。

```swift
import LiveCommunicationKit
import PushKit

final class SamplePushHandler: NSObject, PKPushRegistryDelegate {
    func pushRegistry(
        _ registry: PKPushRegistry,
        didReceiveIncomingVoIPPushWith payload: PKPushPayload,
        metadata: PKVoIPPushMetadata
    ) async {
        guard let (handle, uuid) = parseConversationPayload(from: payload) else { return }

        let capabilities: Conversation.Capabilities = [.video, .pausing, .merging]
        let update = Conversation.Update(members: [handle], capabilities: capabilities)
        try? await manager.reportNewIncomingConversation(uuid: uuid, update: update)
    }
}
```

关键点：

- 收到 VoIP Push 后，必须在几秒内调用 `reportNewIncomingConversation`，否则系统会杀死你的 App（这是 iOS 的老规矩）。
- `uuid` 是通话的唯一标识，后续所有操作都用它定位 Conversation。
- `update` 包含初始成员和能力集，系统据此渲染来电界面。

### 5. 处理用户操作：Delegate 模式

用户点击"接听"、"挂断"、"合并"等按钮后，系统通过 `ConversationManagerDelegate` 回调给你的 App：

```swift
final class SampleDelegate: ConversationManagerDelegate {
    func conversationManager(
        _ manager: ConversationManager,
        perform action: ConversationAction
    ) {
        switch action {
        case let action as JoinConversationAction:
            handleJoinAction(action)
        case let action as EndConversationAction:
            handleEndAction(action)
        case let action as StartConversationAction:
            handleStartAction(action)
        case let action as MergeConversationAction:
            handleMergeAction(action)
        default:
            action.fail()
        }
    }
}
```

每种 Action 都必须调用 `fulfill()` 或 `fail()`，否则系统会一直等待，UI 卡在转圈状态。

**处理接听（Join）：**

```swift
extension SampleDelegate {
    func handleJoinAction(_ action: JoinConversationAction) {
        guard let conversation = manager.conversations.first(where: { $0.uuid == action.conversationUUID }) else {
            return action.fail()
        }

        // 通知系统：正在连接
        manager.reportConversationEvent(
            .conversationStartedConnecting(.now),
            for: conversation
        )

        Task {
            do {
                try await setupMediaStream(with: action.conversationUUID)

                // 通知系统：已连接
                manager.reportConversationEvent(
                    .conversationConnected(.now),
                    for: conversation
                )
                action.fulfill(dateConnected: .now)
            } catch {
                action.fail()
            }
        }
    }
}
```

关键点：

- 先调用 `reportConversationEvent(.conversationStartedConnecting)`，系统会更新 UI 显示"连接中"。
- 媒体流建立成功后，调用 `.conversationConnected`，系统切换到通话中状态。
- `fulfill(dateConnected:)` 的日期会记录在通话详情里。
- 任何步骤出错都要调 `fail()`，否则用户界面会卡住。

### 6. 发起去电

从 App 内部发起通话也很直接：

```swift
let startAction = StartConversationAction(
    conversationUUID: UUID(),
    handles: [Handle(type: .phoneNumber, value: "+1-650-555-0199", displayName: "Ryan Notch")],
    isVideo: false
)
try await manager.perform([startAction])
```

系统会立即在 Dynamic Island 展示拨号状态，你的 Delegate 会收到 `StartConversationAction`，在那里建立媒体流。

### 7. 群组通话与通话合并

LiveCommunicationKit 原生支持群组通话。创建时传入多个 handle：

```swift
let adam = Handle(type: .emailAddress, value: "adam@icloud.com", displayName: "Adam Halwani")
let david = Handle(type: .emailAddress, value: "david@example.com", displayName: "David Evans")
let ryan = Handle(type: .phoneNumber, value: "+16505550199", displayName: "Ryan Notch")

let startAction = StartConversationAction(
    conversationUUID: UUID(),
    handles: [david, ryan],
    isVideo: false
)
try await manager.perform([startAction])
```

群组成员变化时，报告更新：

```swift
let update = Conversation.Update(
    localMember: adam,
    members: [david, ryan],
    activeRemoteMembers: [david, ryan],
    capabilities: [.merging, .pausing, .unmerging]
)

manager.reportConversationEvent(
    .conversationUpdated(update),
    for: conversation
)
```

**合并通话**（类似电话会议）的处理：

```swift
func handleMergeAction(_ action: MergeConversationAction) {
    let sourceUUID = action.conversationUUID
    let targetUUID = action.conversationUUIDToMergeWith

    guard manager.conversations.contains(where: { $0.uuid == sourceUUID }),
          manager.conversations.contains(where: { $0.uuid == targetUUID }) else {
        return action.fail()
    }

    Task {
        do {
            let update = try await combineStreams(from: sourceUUID, into: targetUUID)
            manager.reportConversationEvent(.conversationUpdated(update), for: target)
            action.fulfill()
        } catch {
            action.fail()
        }
    }
}
```

## 最佳实践

- **从 CXProvider 迁移**：如果你还在用 CallKit 的 `CXProvider`，建议尽快迁移到 LiveCommunicationKit。新 API 更灵活，支持更多通话类型（不只是语音电话），而且与系统的集成更深。

- **始终 fulfill 或 fail 每个 Action**：Delegate 收到 Action 后，无论成功失败，都必须调 `fulfill()` 或 `fail()`。遗漏会导致系统 UI 永久卡在等待状态。

- **正确设置 Handle 的 type**：把 `type` 设为 `.phoneNumber` 或 `.emailAddress` 能让系统自动匹配通讯录，显示联系人头像和姓名。设成 `.generic` 会丧失这个能力。

- **合理声明 Capabilities**：只声明你真正支持的功能。声明了 `.video` 但接通后没有视频流，用户会觉得 App 有 bug。

- **利用通话记录集成**：把 `includesConversationInRecents` 设为 `true`，用户可以从 Phone App 的最近通话直接回拨，这是提升留存的自然入口。
