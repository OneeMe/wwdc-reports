## Highlight

> iOS 26.5 引入了"12 个月承诺期的月度订阅"——用户按月付费降低决策门槛，但锁定 12 个月合约。StoreKit 新增了 `PricingTerms` 和 `billingPlanType` API，Server API 同步下发了 `commitmentInfo`，让你能追踪用户的履约进度。同时，Offer Code Redemption API 和 App Store Connect 提交流程也得到了显著改进。

---

## 核心内容

### 1. 这场演讲解决什么问题

订阅制 App 长期面临一个两难困境：

- **年度订阅**：一次性付费金额高，用户决策门槛高，转化率低
- **月度订阅**：用户随时可能取消，LTV（生命周期价值）不稳定

Apple 给出的解决方案是：**12 个月承诺期的月度订阅（Monthly subscriptions with a 12-month commitment）**。用户每月支付较低的金额，但承诺持续 12 个月。这既降低了用户的初始决策门槛，又保证了开发者的长期收入。

### 2. 12 个月承诺期月度订阅

#### 2.1 在 App Store Connect 中配置

配置流程：

1. 选择一个**一年期自动续期订阅**
2. 在"Monthly with a 12-month commitment availability"下选择 Set Up Availability
3. 按步骤配置计费方案
4. 可以为不同的计费方案类型配置不同的订阅优惠（如免费试用只给承诺期用户）

#### 2.2 StoreKit 中的 PricingTerms

`SubscriptionInfo` 新增了 `pricingTerms` 属性，返回该订阅的所有可用计费方案：

```swift
// 使用 StoreKit views 展示定价方案
import StoreKit
import SwiftUI

struct SubscriptionStore: View {
    var body: some View {
        SubscriptionStoreView(groupID: "3F19ED53") {
            // 自定义营销内容
        }
        .preferredSubscriptionPricingTerms { _, subscriptionInfo in
            subscriptionInfo.pricingTerms.first {
                $0.billingPlanType == .monthly
            }
        }
    }
}
```

每个自动续期订阅至少有一个计费方案：

- **.upFront**：默认的一次性预付方案（如年度一次性付费）
- **.monthly**：月度承诺方案（仅适用于 12 个月承诺订阅）

#### 2.3 自定义 UI 中的定价展示

如果你使用自定义 Store UI，可以手动获取和展示定价信息：

```swift
import StoreKit

var product: Product?
// 获取产品

// 获取月度承诺方案的定价信息
let pricingTerms = product?.subscription?.pricingTerms
    .first(where: { $0.billingPlanType == .monthly })

if let pricingTerms {
    let monthlyPrice = pricingTerms.billingDisplayPrice
    let totalCommitmentPrice = pricingTerms.commitmentInfo.price
    // 在 UI 中同时展示月付金额和总承诺金额
}

// 购买时指定计费方案
let result = try? await product?.purchase(options: [.billingPlanType(.monthly)])
switch result {
    // 验证交易、解锁内容、完成交易
}
```

注意：`billingPlanType` 只在用户所在 storefront 可用时才会返回。

#### 2.4 用户首次订阅时的披露 Sheet

用户首次订阅承诺方案时，App Store 会自动展示一个**披露 Sheet**：

- 显示需要支付的总期数（12 期）
- 提供取消指导
- 每个 Apple Account 只显示一次

你不需要自己实现这个 Sheet，但需要在 UI 中清晰标明"承诺 12 个月"。

#### 2.5 订阅管理

用户可以在 App Store 中管理自己的承诺期订阅：

- 查看所有可用方案
- 查看剩余支付期数
- 查看承诺期续订时间

你的 App 中也可以直接展示管理界面：

```swift
// 管理订阅 Sheet
struct ManageSubscriptionsButton: View {
    let subscriptionGroupID: String
    @State var presentingManageSubscriptionsSheet: Bool = false

    var body: some View {
        Button("Manage Subscriptions") {
            presentingManageSubscriptionsSheet = true
        }
        .manageSubscriptionsSheet(
            isPresented: $presentingManageSubscriptionsSheet,
            subscriptionGroupID: subscriptionGroupID
        )
    }
}
```

### 3. 服务器端 API 更新

#### 3.1 Transaction 中的 Commitment 信息

服务器收到的 `JWSTransaction` 包含了承诺期相关的字段：

```json
{
    "expiresDate": 1783503660000,
    "price": 10990,
    "productId": "plus.pro.annual",
    "purchaseDate": 1780911660000,
    "type": "Auto-Renewable Subscription",
    "billingPlanType": "MONTHLY",
    "commitmentInfo": {
        "billingPeriodNumber": 1,
        "totalBillingPeriods": 12,
        "commitmentExpiresDate": 1812447660000,
        "commitmentPrice": 131880
    }
}
```

`commitmentInfo` 包含：

- **billingPeriodNumber**：当前是第几期
- **totalBillingPeriods**：总期数（通常为 12）
- **commitmentExpiresDate**：承诺期到期时间
- **commitmentPrice**：承诺期总价

对于 `.upFront` 计费方案，`commitmentInfo` 为 `nil`。

#### 3.2 Renewal Info 中的 Commitment

`JWSRenewalInfo` 也包含了承诺期续订信息：

```json
{
    "renewalBillingPlanType": "MONTHLY",
    "commitmentInfo": {
        "commitmentAutoRenewProductId": "plus.standard.annual",
        "commitmentAutoRenewStatus": 0,
        "commitmentRenewalDate": 1812447660000,
        "commitmentRenewalPrice": 10990,
        "commitmentRenewalBillingPlanType": "BILLED_UPFRONT"
    }
}
```

这个例子显示：用户当前的承诺期结束后，会切换到一个一次性预付（BILLED_UPFRONT）的方案。

### 4. Bundles 和 Suites

#### 4.1 概念区分

Apple 引入了两种新的订阅组合方式：

**Bundle（捆绑包）**：

- 一组可以单独购买的订阅
- 以优惠价格一起出售
- 比单独购买所有订阅更便宜

**Suite（套件）**：

- 一组只能在 Suite 上下文中存在的订阅
- 不能单独购买
- 通常为相关的一组 App 提供服务

#### 4.2 测试时间线

Bundles 和 Suites 的 API 可以在 **Xcode 27** 中开始测试，更多项目细节将在 2026 年晚些时候公布。

### 5. Offer Code Redemption API 改进

#### 5.1 新的 Redemption Sheet

Offer Code 兑换 Sheet 现在支持回调结果：

```swift
struct OfferCodeRedemption: View {
    @State var presentingOfferCodeSheet: Bool = false

    var body: some View {
        Button("Redeem Offer Code") {
            presentingOfferCodeSheet = true
        }
        .offerCodeRedemption(
            options: [],
            isPresented: $presentingOfferCodeSheet
        ) { result in
            switch result {
            case .success(let verificationResult):
                switch verificationResult {
                    // 验证交易、解锁内容、完成交易
                }
            case .failure(let error):
                // 处理错误
            }
        }
    }
}
```

改进点：

- 可以准确知道用户是否兑换成功
- 可以获取兑换后的交易信息进行验证
- 更好的错误处理

### 6. Xcode 中的 StoreKit Testing

#### 6.1 配置 Billing Plan

在 Xcode 26.5+ 的 StoreKit Configuration 文件中：

1. 选择一个一年期自动续期订阅
2. 使用新的 Billing Plan picker
3. 选择"Monthly with a 12-month commitment"
4. 配置月付价格和承诺期设置
5. 可以为不同计费方案配置不同的优惠

#### 6.2 验证 CommitmentInfo

使用 Transaction Inspector 验证 `commitmentInfo` 字段，确保你的 App 正确处理了承诺期逻辑。

## 最佳实践

- **所有订阅 App 都加上承诺期选项**：12 个月承诺期按月订阅给了用户更多选择。建议与年度预付做 A/B 测试，看哪种方案在你的用户群体中转化率更高。
- **UI 要清晰展示承诺条款**：在付款按钮上方明确显示"承诺 12 个月"、月付金额和总承诺金额。透明的价格信息可以减少客诉和退款。
- **服务端状态机要处理承诺期**：确保你的服务器能正确解析 `commitmentInfo` 字段，跟踪用户的履约进度。承诺期中途取消的处理逻辑要与普通订阅不同。
- **测试异常场景**：在 Xcode StoreKit Testing 中模拟"用户中途取消"、"扣款失败"、"承诺期结束后切换方案"等场景，确保所有边界情况都被覆盖。
- **更新 CI/CD 流程**：如果你使用 Fastlane 或自定义脚本提交 IAP，检查是否需要适配新的 `reviewSubmissions` 集合 API。
- **利用 Renewal Info 做留存**：在承诺期即将结束时，通过 `commitmentRenewalDate` 和 `commitmentAutoRenewProductId` 提前引导用户选择续订方案。
