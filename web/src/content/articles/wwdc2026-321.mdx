## Highlight

> `LazyVStack` 不是魔法，它的性能来自"估算"和"预取"。这场演讲把底牌亮给你看：屏幕外视图的高度是猜出来的，滚动时提前几帧预渲染，但动态视图数量、条件渲染和 `onGeometryChange` 会打破这套机制。搞懂原理，才能写出不卡顿的长列表。

## 核心内容

### 1. 这场演讲解决什么问题

用 `LazyVStack` 做长列表时，开发者经常遇到"玄学问题"：

- 滚动条乱跳
- 快速滑动掉帧
- 旋转屏幕后滚动位置不对
- `onAppear` 里加载数据导致卡顿

这场演讲解释 `LazyVStack` 和 `LazyHStack` 的内部机制，让你明白这些问题的原因和解决方法。

### 2. Lazy Stack 的核心机制

**与 `VStack` 的区别**：

- `VStack` 一次性加载所有子视图
- `LazyVStack` 只加载可见区域的视图，屏幕外的视图不评估、不渲染

**估算高度**：

- Lazy stack 不知道屏幕外视图的实际高度
- 基于已渲染视图的平均高度来估算
- 滚动过程中会不断修正估算值

**理想尺寸**：

- `LazyVStack` 的宽度 = 第一个子视图的宽度（因为不是所有视图都加载了，无法找最大值）
- `LazyHStack` 的高度 = 第一个子视图的高度

### 3. 嵌套 Lazy Stack

```swift
struct ContentView: View {
    var body: some View {
        ScrollView {
            LazyVStack(pinnedViews: [.sectionHeaders]) {
                ForEach(steps) { step in
                    StepView(step: step)
                }
                Showcase()
            }
        }
    }
}

struct Showcase: View {
    var body: some View {
        Section {
            ForEach(photos) { photo in
                PhotoView(photo: photo)
            }
        } header: { /* ... */ }
    }
}
```

`LazyHStack` 嵌套在 `LazyVStack` 中也是性能友好的，因为不是所有人都会滚动到嵌套区域。

**注意**：`LazyHStack` 的高度由第一个子视图决定。如果照片有可变高度的描述文字，较长的会被截断。解决方案是固定高度或设置 `lineLimit`。

### 4. Scroll Transition 的陷阱

```swift
// 有问题：transform 把视图推出原始 frame，lazy stack 认为它已离开屏幕
PhotoView(photo: photo)
    .scrollTransition { effect, phase in
        effect
            .rotationEffect(.degrees(phase.value * 20))
            .scaleEffect(1 + phase.value * 0.2)
    }

// 安全：transform 不会把不可见视图推入可见区域
PhotoView(photo: photo)
    .scrollTransition { effect, phase in
        effect
            .scaleEffect(1 - abs(phase.value) * 0.1)
    }
```

Lazy stack 根据原始位置判断视图是否可见。如果 transform 把视图推出原始 frame，它会在应该可见时消失。

### 5. 状态管理与 Prefetching

**Prefetching** 是 lazy stack 保持滚动流畅的关键：

- 滚动时，lazy stack 在帧间隙预取即将进入屏幕的视图
- 把渲染工作拆分到多个帧，避免单帧 deadline 超限
- 预取可能调用 `body`，但不一定调用 `onAppear`

**不要在 `onAppear` 里做大量设置**：

```swift
// 不好：onAppear 导致视图尺寸突变，prefetching 的工作被浪费
struct StepView: View {
    let id: Step.ID
    @State var viewModel = StepViewModel()

    var body: some View {
        VStack {
            if let content = viewModel.content { /* ... */ }
        }
        .onAppear {
            viewModel.configure(with: id)
        }
    }
}

// 好：在 init 中设置，视图在出现前就已准备好
struct StepView: View {
    @State var viewModel: StepViewModel

    init(id: Step.ID) {
        _viewModel = State(initialValue: StepViewModel(id: id))
    }

    var body: some View { /* ... */ }
}
```

**用 `task` 加载异步数据**：

```swift
// 可以稍微提前加载
struct StepView: View {
    let step: Step
    @State var diagramLoader = DiagramLoader()
    @State var diagram: Diagram?

    var body: some View {
        VStack { /* ... */ }
            .task {
                diagram = await diagramLoader.loadDiagram(id: step.id)
            }
    }
}

// 更好：在 init 中启动加载，利用 prefetching
struct StepView: View {
    let step: Step
    @State var diagramLoader: DiagramLoader

    init(step: Step) {
        self.step = step
        _diagramLoader = State(initialValue: DiagramLoader(id: step.id))
    }

    var body: some View { /* ... */ }
}
```

### 6. 避免动态视图数量

```swift
// 有问题：StepView 可能返回 0 或 1 个子视图
struct StepView: View {
    let step: Step
    @Environment(\.detailLevel) var detailLevel

    var body: some View {
        if step.isVisible(in: detailLevel) {
            VStack { /* ... */ }
        }
    }
}
```

动态视图数量导致 lazy stack 必须保留更多视图状态（因为索引可能变化）。应该在数据层过滤：

```swift
// 好：在数据层过滤，ForEach 内部视图数量稳定
struct ContentView: View {
    @Query var steps: [Step]

    init(detailLevel: DetailLevel) {
        _steps = Query(filter: #Predicate<Step> { step in
            step.detailLevel >= detailLevel
        })
    }

    var body: some View {
        ScrollView {
            LazyVStack {
                ForEach(steps) { step in
                    StepView(step: step)
                }
            }
        }
    }
}
```

同样适用于 optional unwrapping：

```swift
// 不好：条件渲染导致动态视图数量
if let token {
    /* ... */
}

// 好：在外层处理未认证状态，不显示 lazy stack
```

### 7. 程序控制滚动

```swift
struct ContentView: View {
    @State var scrollPosition = ScrollPosition()

    var body: some View {
        ScrollView {
            LazyVStack { /* ... */ }
        }
        .scrollPosition($scrollPosition)
        .overlay(alignment: .bottom) {
            Button {
                scrollToShowcase()
            } label: { /* ... */ }
        }
    }

    func scrollToShowcase() {
        withAnimation {
            scrollPosition.scrollTo(id: "showcase-header")
        }
    }
}
```

程序滚动在 lazy stack 中有效，即使目标视图不在屏幕上。但性能取决于视图结构的稳定性：

- 每个 `ForEach` 项始终解析为单个子视图时最流畅
- 动态视图数量会降低性能

### 8. 避免布局后变化

```swift
// 不好：onGeometryChange 触发状态更新，改变布局
struct StepView: View {
    let step: Step
    @State var subtitleHeight: CGFloat?

    var body: some View {
        VStack {
            StepDiagram(diagram: step.diagram)
                .frame(height: diagramHeight(subtitleHeight: subtitleHeight))
            Title(step.title)
            Subtitle(step.subtitle)
                .onGeometryChange(for: CGFloat.self, of: \.size.height) { _, value in
                    subtitleHeight = value
                }
        }
    }
}

// 好：用自定义 Layout 代替状态驱动的布局
struct StepView: View {
    let step: Step

    var body: some View {
        StepLayout {
            StepDiagram(diagram: step.diagram)
            Title(step.title)
            Subtitle(step.subtitle)
        }
    }
}
```

## 最佳实践

- **在 init 中设置视图状态**：不要依赖 `onAppear` 来配置视图，让 prefetching 有效工作
- **在数据层过滤**：用 `Predicate` 或 `Query` 过滤数据，不要在视图 body 中用条件渲染
- **避免 `onGeometryChange` 驱动的布局**：用自定义 `Layout` 代替
- **scroll transition 不要推出可见区域**：确保不可见视图不会被 transform 推入可见 rect
- **用相对位置而非绝对 offset**：`onScrollTargetVisibilityChange` 比 `onScrollGeometryChange` 更稳定
- **状态提升到 model 或外层视图**：lazy stack 会释放滚动出屏幕的视图状态
