## Highlight

> Instruments 新增的 Foundation Models 模板让你能直接看到 LLM 的 prompt、response、tool call 和延迟数据，解决了"AI 功能黑盒难调试"的痛点，让 agentic 应用的性能优化有迹可循。

---

## 核心内容

### 1. 这场演讲解决什么问题

用 LLM 开发应用和传统开发完全不同：

- **输出不确定**：同样的输入可能得到不同的输出，传统单元测试失效
- **多模型协作**：一个功能可能涉及多个模型串联，数据流转复杂
- **可观测性差**：出问题的时候很难知道是哪一步出了问题

这场演讲教你用 Instruments 的 Foundation Models 模板来调试和优化基于 Foundation Models framework 构建的 agentic 体验。

### 2. LLM 应用的核心循环

一个 LLM 应用本质上在做三件事：

1. 用户发送 prompt
2. 模型推理并可能调用 tool
3. 用户得到 response

当功能需要更多信息时（当前时间、数据库记录、搜索结果），模型会调用 tool，形成循环：

```
用户 prompt → 模型推理 → 调用 tool → tool 执行 → 模型生成 response → 可能再次调用 tool
```

每一步都增加延迟，每一步都是潜在的故障点。理解这个循环是使用 Foundation Models Instrument 的基础。

### 3. Foundation Models Instrument 的使用

在 Xcode 中，选择 **Product → Profile**，然后从模板选择器中选择 **Foundation Models** 模板并开始录制。

这个 instrument 会捕获设备上的 prompt 和 response 数据（仅在 trace 期间开启，生产环境关闭）。

**Timeline 视图**展示了每次交互的概览：

- **Prompt**：用户发送的内容
- **Tool Call**：模型调用的工具
- **Response**：模型返回的内容
- **Latency**：每个步骤的耗时

**Prompt Inspector** 让你看到模型实际收到的完整 prompt，包括 system instructions、user message 和 tool definitions。这对于调试"模型为什么不按预期行动"至关重要。

**Tool Call Inspector** 展示了模型生成的 tool call 参数，以及 tool 返回的结果。你可以检查模型是否正确理解了用户的意图，以及 tool 是否返回了正确的数据。

### 4. 多 Session 和 Profile 的调试

复杂功能往往使用多个 `LanguageModelSession` 和 Dynamic Profiles。例如一个 craft app 的头脑风暴功能：

- **头脑风暴阶段**：使用高 temperature 的 Profile 生成创意
- **教程生成阶段**：切换到详细推理的 Profile 生成教程

Instruments 可以追踪不同 Session 之间的切换，显示每个 Profile 的配置和切换时机。你可以看到：

- 切换 Profile 是否导致了上下文丢失
- 不同 Profile 的延迟差异
- 模型在切换后是否保留了之前的对话历史

### 5. 性能优化

**延迟分析**：

- 识别耗时最长的 tool call
- 检查是否有不必要的模型调用
- 优化 prompt 长度以减少 token 消耗

**常见问题排查**：

- **响应慢**：检查是否有同步的网络请求阻塞了主线程
- **上下文丢失**：确认 DynamicInstructions 是否正确配置了对话历史
- **工具调用失败**：验证 tool 的 schema 定义是否与实现一致

---

## 最佳实践

- **在开发阶段始终使用 Instruments**：Foundation Models Instrument 只在开发和调试时可用，充分利用它来理解模型的行为
- **关注延迟瓶颈**：agentic 流程中每一步都增加延迟，用 Timeline 视图找出最慢的环节优先优化
- **验证 prompt 质量**：用 Prompt Inspector 检查模型实际收到的内容，确保 instructions 清晰、context 完整
- **测试多 Session 场景**：复杂功能涉及多个 Session 切换时，确保对话历史正确传递
- **区分开发和生产**：Instrument 的日志功能仅在 trace 期间开启，不会影响生产环境的性能
