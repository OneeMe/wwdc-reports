## Highlight

> Device Hub 是 Xcode 27 附带的独立 App，把真机和模拟器的管理、控制、配置全部整合到一个窗口里。你不需要打开 Xcode 就能操作设备屏幕、批量管理描述文件、模拟位置，甚至用 `devicectl` 命令行统一控制真机和模拟器。

---

## 核心内容

### 1. 这场演讲解决什么问题

过去开发者在设备管理上至少要开三个工具：

1. **Xcode 的 Devices and Simulators** — 管理真机，但界面老旧，功能有限
2. **Simulator.app** — 管理模拟器，和真机管理完全割裂
3. **各种第三方 CLI 工具** — `ios-deploy`、`xcrun simctl` 等，脚本里要写一堆条件分支

Device Hub 把这三件事合并成一个统一的体验。它既是日常开发的 GUI 工具，也是 CI/CD 自动化的 CLI 入口。

### 2. Device Hub 的两种模式

**Compact Mode（紧凑模式）**：

当你从 Xcode build & run 到模拟器时，Device Hub 自动以紧凑模式启动。只显示设备屏幕和底部控制栏（Home 键、截图、旋转）。控制按钮是上下文感知的：Apple TV 显示播放/暂停和导航按钮，Apple Vision Pro 显示环境切换和相机移动，Apple Watch 显示侧边按钮和 Digital Crown。

**Full Window（完整窗口）**：

点击展开按钮进入完整模式，获得三大能力：

- **Control（控制）**：Canvas 中直接点击、拖拽、滚动设备屏幕；支持捏合手势和双指滚动；Resize mode 自由调整 App 尺寸（配合 iOS 27 的可调整大小特性）；Capture keyboard 把 Mac 键盘输入直接路由到设备，方便测试快捷键
- **Organize（组织）**：侧边栏统一管理所有设备和模拟器，支持多 Tab 切换
- **Configure（配置）**：Inspector 面板管理 Provisioning profiles、Location simulation、网络条件模拟等

### 3. devicectl — 统一真机和模拟器的命令行工具

Device Hub 的底层是 `devicectl` 命令行工具。它统一了真机和模拟器的操作，终于不用在脚本里写 `if simulator then simctl else ideviceinstaller` 了。

关键能力包括：

- 安装/卸载 App（真机和模拟器同一套命令）
- 抓取设备日志和崩溃报告
- 模拟位置和网络条件
- 批量执行操作（JSON 输出方便脚本解析）
- 管理 Provisioning profiles 和证书

## 最佳实践

- **迁移 CI 脚本**：把 `xcrun simctl` 和第三方真机工具逐步替换为 `xcrun devicectl`。先在一个非核心 nightly build 跑一周，观察设备连接稳定性和 JSON 输出格式
- **QA 团队标准化测试矩阵**：利用 Device Hub 的多 Tab 和 Compact window，把常用测试机型（iPhone SE、iPad Pro、Apple Watch）固定在工作区
- **注意 GPU 占用**：Canvas 投屏连接多台高刷真机时会消耗大量 Mac GPU 资源。如果只是跑测试，在设置里关闭 "Live display" 或最小化窗口
