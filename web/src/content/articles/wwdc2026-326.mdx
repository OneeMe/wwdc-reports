## Highlight

> Apple 把 Qwen、Mistral、SAM3 等主流开源模型都优化好了，你只需要几行 Swift 代码就能在 App 里跑起来——从图像分割到多语言 LLM 推理，全部在设备本地完成，而且通过 `@Generable` 可以直接让模型输出结构化 Swift 类型。

## 核心内容

### 1. 这场演讲解决什么问题

"Meet Core AI" 和 "Dive into Core AI" 讲的是怎么转换和优化自己的模型。但大多数开发者其实想的是：有没有现成的、已经优化好的模型可以直接用？这场演讲回答的就是这个问题——Apple 整理了主流开源模型，预转换成了 Core AI 格式，并提供了高层 Swift API 让你快速集成。

演讲用一个语言学习 App 的案例贯穿：学生用相机拍一个物体，App 自动分割出物体、生成词汇卡片（中文词汇、英文释义、例句），全部在设备上完成。

### 2. 模型选择：分解问题，小模型组合

演讲的核心架构决策是：不用一个大而全的多模态模型，而是用两个专门的小模型：

- **SAM3**（Segment Anything Model 3）：做图像分割，从照片里抠出目标物体
- **Qwen3**（多语言 LLM）：接收英文标签，生成中文词汇、翻译和例句

两个模型都控制在 10 亿参数以内，总占用可控，而且可以独立升级。

```swift
import CoreAIImageSegmenter

// 加载 SAM3 分割模型
let segmenter = try await ImageSegmenter(resourcesAt: sam3ModelURL)

// 分割图像：根据 prompt 找出目标区域
let response = try await segmenter.segment(
    image: inputImage,
    prompt: "flower"
)
let mask = response.segments.first?.mask
```

### 3. 用 Foundation Models 接口跑 Core AI 模型

Core AI 模型可以通过 `CoreAILanguageModel` 包装，接入 Foundation Models framework 的统一接口。这意味着你可以用和系统模型完全相同的 API 来调用自定义模型。

```swift
import FoundationModels
import CoreAILanguageModels

// 创建 Core AI 语言模型实例
let model = try await CoreAILanguageModel(resourcesAt: qwen3ModelURL)

// 创建会话
let session = LanguageModelSession(model: model)

// 生成回复
let response = try await session.respond(to: "...")
```

关键点：

- `CoreAILanguageModel` 把 Core AI 的底层推理包装成 Foundation Models 协议
- 同一个 `LanguageModelSession` API，可以无缝切换系统模型、PCC 模型或 Core AI 模型
- 模型资源通过 `resourcesAt:` 指定本地路径，首次加载时会自动特化

### 4. 结构化输出：@Generable

让 LLM 输出结构化数据是常见需求（比如生成 JSON）。Foundation Models 提供了 `@Generable` 宏，让模型直接输出 Swift 类型：

```swift
import FoundationModels
import CoreAILanguageModels

@Generable
struct VocabCard {
    let chineseWord: String
    let englishMeaning: String
    let exampleSentence: String
}

let model = try await CoreAILanguageModel(resourcesAt: modelURL)
let session = LanguageModelSession(model: model)

let response = try await session.respond(
    to: "Create a vocab card for flower",
    generating: VocabCard.self
)

let card: VocabCard = response.content
print(card.chineseWord)      // "花"
print(card.exampleSentence)  // "这朵花很漂亮"
```

关键点：

- `@Generable` 宏自动生成 schema，指导模型输出符合类型结构的 JSON
- `generating:` 参数告诉会话期望的输出类型
- `response.content` 直接返回解码后的 Swift 值，不需要手动解析 JSON
- 底层由 guided generation 保证输出格式正确，不会返回 malformed JSON

### 5. AOT 编译：提前特化模型

模型首次在设备上加载时需要进行特化（specialization）——针对具体设备的 GPU/ANE 架构编译。这个过程在运行时做会拖慢首次体验，所以 Core AI 支持 Ahead-of-Time（AOT）编译：

```bash
# 在构建阶段提前编译模型
$ xcrun coreai-build compile MyModel.aimodel --platform iOS
```

AOT 编译后的模型在 App 首次加载时就能直接运行，无需等待特化。Xcode 27 还提供了 Core AI Instruments，可以分析模型推理的延迟、内存占用和 ANE/GPU 利用率。

## 最佳实践

- **分解问题，用多个小模型**：一个 1B 参数的专门模型往往比 7B 参数的全能模型效果更好、速度更快、占用更小
- **优先用高层 API**：`ImageSegmenter`、`CoreAILanguageModel` 等高层封装比直接操作 `AIModel` + `InferenceFunction` 更简单，除非你有特殊需求
- **AOT 编译生产环境必开**：开发阶段可以用运行时特化，但发布到 App Store 的模型应该提前编译
- **用 `@Generable` 替代手动 JSON 解析**：它保证了类型安全和格式正确，而且错误处理更优雅
- **监控模型缓存**：`AIModelCache` 可以查询模型是否已特化，据此决定是立即使用还是显示加载提示
