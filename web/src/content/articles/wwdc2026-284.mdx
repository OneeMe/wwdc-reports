## Highlight

> Apple 把工业软件标配的三种交互直接做进了 RealityKit：通过移动 `ManipulationComponent` 实现整体拖拽和零件拆解切换、`ClippingComponent` 一键剖切模型、自动爆炸图算法——做 CAD 审查和医疗设备展示终于不用自己算矩阵了。

## 核心内容

### 1. 这场演讲解决什么问题

在 visionOS 里展示复杂 3D 模型（发动机、建筑 BIM、医疗设备）时，开发者长期面临：

- 想让用户拆开外壳看内部零件，得自己写射线检测和手势冲突处理
- 想做剖面查看，得自己写 Shader 或用 CSG 减模型
- 想做爆炸图展示结构，得手算每个零件的位移向量

RealityKit 今年把这三项工业软件标配的交互原生化了。

### 2. 资产准备：层级结构是关键

没有层级结构的模型（所有 mesh 平铺在根节点下）在代码里几乎无法交互：

```
❌ 错误：扁平结构
Root
├── InteriorPart_01
├── InteriorPart_02
├── ...
├── Part_47

✅ 正确：层级结构
Root
├── EngineBlock
│   ├── Cylinder_1
│   ├── Cylinder_2
│   └── PistonAssembly
│       ├── Piston
│       └── ConnectingRod
├── Transmission
└── ExhaustSystem
```

关键点：

- 层级结构让代码可以按 assembly（装配体）操作，而不是按单个零件
- 导出 USDZ 时必须保留嵌套层级，不要接受扁平化的"死"模型
- 每个 assembly 节点应该有意义的名字，方便代码中查找和隔离

### 3. ManipulationComponent：切换整体和零件操作

通过在不同层级移动 `ManipulationComponent`，可以无缝切换"拖拽整体"和"拆解零件"两种模式：

**打开装配体（零件可单独操作）：**

```swift
func openAssembly() {
    // 移除父节点的操作能力
    components[ManipulationComponent.self] = nil
    components[InputTargetComponent.self] = nil

    // 给每个子零件添加操作能力
    for child in assemblyChildren {
        child.components.set(InputTargetComponent())

        var manipulation = ManipulationComponent()
        manipulation.releaseBehavior = .stay
        child.manipulationComponent = manipulation
    }
}
```

**关闭装配体（恢复整体操作）：**

```swift
func closeAssembly() {
    // 移除子零件的操作能力
    for child in assemblyChildren {
        child.manipulationComponent = nil
        child.components[InputTargetComponent.self] = nil
    }

    // 恢复父节点的操作能力
    components.set(InputTargetComponent())
    var manipulation = ManipulationComponent()
    manipulation.releaseBehavior = .stay
    manipulationComponent = manipulation
}
```

关键点：

- `InputTargetComponent` 让 entity 可以接收手势输入
- `ManipulationComponent` 让 entity 可以被用户抓取和移动
- `releaseBehavior = .stay` 表示松手后物体保持原位，不弹回
- 切换时只需要在 entity 树中上下移动这两个 component

### 4. ClippingComponent：剖切查看内部

`ClippingComponent` 用一个包围盒定义剖切区域，盒内的部分被裁掉，露出内部结构：

- 添加 `ClippingComponent` 到父 assembly
- 定义剖切平面的位置和方向
- 被裁切的 entity 内部自动可见

这比用 Shader 修改透明度或 CSG 布尔运算效率高得多，因为裁剪是在渲染管线底层做的。

### 5. 自动爆炸图（Autoexpansion）

爆炸图把装配体的各个子零件沿特定方向散开，展示内部结构。RealityKit 提供了基于体积加权方差的自动计算：

- 分析每个子零件的体积和分布
- 计算最适合展开的轴向
- 自动分配每个零件的位移距离

关键点：

- 不要硬编码沿 Z 轴展开，扁平模型（如键盘）会穿模
- 用体积加权方差计算轴向，或在美国DZ中预埋展开锚点
- 爆炸图动画可以配合 SharePlay，多用户同时查看同一个模型的展开状态

### 6. SharePlay 协作

这些交互能力配合 SharePlay，可以实现多人实时协作审查 3D 模型：

- 所有参与者看到同一个模型，相同的 fidelity，相同的空间位置
- 一个人拆解装配体，其他人同步看到
- 一个人做剖切，其他人看到相同的剖面
- 手势指向某个零件，其他人知道指的是哪个部分

## 最佳实践

- **已有项目重构**：如果之前用 Shader 透明度模拟剖切或用物理引擎做零件拆解，直接替换为 `ClippingComponent` 和 `ManipulationComponent`。性能提升明显，因为裁剪在渲染管线底层做
- **资产准备**：逼着美术或建模师保留深层嵌套的层级结构。没有合理的 Entity 树，代码根本没法隔离特定的活塞或主板
- **爆炸图轴选择**：不要自己拍脑袋硬编码展开轴向。用体积加权方差计算，或在 USDZ 里预埋展开锚点
- **SharePlay 集成**：参考 WWDC25 的 "Share visionOS experiences with nearby people" 实现多人协作
- **性能注意**：复杂模型（数万个零件）的爆炸图计算可能耗时，考虑异步计算或预计算
