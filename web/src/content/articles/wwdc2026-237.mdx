## Highlight

> Vision 框架的 tap-to-segment 让用户点一下就能抠出任意物体，Foundation Models 框架让 LLM 直接"看"图并调用 Vision 工具完成像素级任务——图像理解从"自己造轮子"变成了"组合系统能力"。

---

## 核心内容

### 1. 这场演讲解决什么问题

做图像相关功能的开发者，过去经常要在多个框架之间来回切换：

- 抠图用 Vision 的 `VNGeneratePersonSegmentationRequest`
- OCR 用 `VNRecognizeTextRequest`
- 图像描述要自己接云端 API 或训练 Core ML 模型
- 不同任务的结果还要自己拼接

今年 Apple 做了两件事，把这个 fragmented 的体验统一了：

1. **Vision 新增 tap-to-segment**：不限于人像，任意物体都能分割
2. **Foundation Models 支持图像输入**：LLM 能直接理解图片内容，还能调用 Vision 工具完成专业任务

---

### 2. Tap-to-Segment：点哪里抠哪里

Vision 之前有人像分割，但只能抠人。新的 `GenerateIterativeSegmentationRequest` 可以分割任意物体：

```swift
// 用种子点生成分割蒙版
let handler = ImageRequestHandler(image)
let request = GenerateIterativeSegmentationRequest(seed: point)
let observation = try await handler.perform(request)
let mask = observation?.pixelBuffer

// 用新点精修蒙版
request.addIncludedPoint(newPoint)
let refinedObservation = try await handler.perform(request)
```

支持多种交互方式：

- **单点**：点击物体上的一个点，自动分割出完整物体
- **bounding box**：画一个矩形框，框内的物体被分割
- **lasso**：手绘闭合曲线，精确圈选
- **scribble**：随意涂抹，覆盖多个物体同时分割
- **精修**：用 `addIncludedPoint` 添加区域，`addExcludedPoint` 移除区域

关键点：

- 分割是异步操作，第一次使用时需要下载模型。
- 模型下载可以用 `downloadAssets` API 提前在后台完成，避免用户等待。
- 返回的 `pixelBuffer` 可以直接用于图像合成、背景替换等后续操作。

---

### 3. Foundation Models 看懂图片

今年 Foundation Models 框架支持图像输入，API 和文本输入一样自然：

```swift
import FoundationModels

let prompt = Prompt {
    "Generate a caption for this image"
    Attachment(image)
}
let response = try await session.respond(to: prompt)
let caption = response.content
```

关键点：

- `Attachment(image)` 把图片插入到 prompt 中，模型会自动分析图像内容。
- 支持 `UIImage`、`CGImage`、`CVPixelBuffer` 等多种图像类型。
- 端侧模型就能处理，不需要联网，隐私完全本地保护。

演讲演示了一个场景：把随手拍的笔记照片传给模型，让它生成演讲大纲。模型识别出手写文字、理解内容结构、输出格式化的议程——全程在设备上完成。

### 4. 图像工具：让 LLM 调用 Vision 能力

LLM 擅长理解语义，但不擅长精确的像素级操作。Apple 的解法是**工具调用（Tool Calling）**：LLM 分析需求后，自动调用专门的 Vision 工具。

**创建自定义图像工具：**

```swift
struct PlantIdentifierTool: Tool {
    @SessionProperty(\.history) var history

    @Generable
    struct Arguments {
        var image: ImageReference
    }

    func call(arguments: Arguments) async throws -> String {
        let imageReference = arguments.image
        let transcript = Transcript(history)
        guard let imageAttachment = imageReference.resolve(in: transcript) else {
            throw AppError.imageNotFound
        }
        let image = try imageAttachment.pixelBuffer()
        return classifyPlant(image)
    }
}
```

关键点：

- `ImageReference` 是模型对图片的引用，不是实际的像素数据。
- `resolve(in: transcript)` 从对话历史中找回原始图片。
- 工具内部可以调用任意 Vision API 或自定义模型。

**内置 Vision 工具：**

```swift
import FoundationModels
import Vision

let session = LanguageModelSession(model: model, tools: [BarcodeReaderTool()])
let response = try await session.respond(generating: EventInfo.self) {
    "Get the date, location, and website from this flyer"
    Attachment(image)
        .label("flyer")
}
```

在这个例子中：

1. 用户给了一张活动传单的照片
2. LLM 理解任务：提取日期、地点和网站
3. LLM 发现需要读取条形码，自动调用 `BarcodeReaderTool`
4. Vision 框架读取条形码内容，返回给 LLM
5. LLM 综合所有信息，输出结构化的 `EventInfo`

这种模式把"语义理解"和"像素操作"解耦：LLM 负责理解用户意图，Vision 负责精确的图像处理。

### 5. Vision 上 watchOS

Vision 框架今年扩展到了 watchOS，让手表也能做图像分析：

```swift
// 生成突出主体的裁剪区域
func generateImageCrop(in image: CGImage) async throws -> NormalizedRect? {
    let request = GenerateObjectnessBasedSaliencyImageRequest()
    let observation = try await request.perform(on: image)
    let prominentObjects = observation.salientObjects
    return prominentObjects.first
}
```

典型应用场景：

- 手表收到图片通知，自动裁剪出最感兴趣的区域显示在小屏幕上
- 运动 App 分析用户上传的训练照片，识别器材和姿势
- 健康 App 扫描食物图片，估算营养成分

## 最佳实践

- **优先用系统工具，而不是自己跑 Core ML**：Vision 框架的内置模型经过 Apple 优化，功耗和内存占用通常比自定义 Core ML 模型更好。只有在系统工具无法满足需求时，才考虑自带模型。

- **LLM 做决策，Vision 做执行**：不要试图让 LLM 直接输出条形码内容或精确像素坐标。让 LLM 理解用户意图，然后调用 Vision 工具完成具体任务。这种分工比端到端方案更可靠。

- **提前下载模型**：Tap-to-segment 的模型是按需下载的。在 UI 上做好 loading 状态，或者用 `downloadAssets` API 在 App 启动时后台预加载，避免用户点了没反应。

- **利用图像标签**：给 `Attachment` 添加 `.label("flyer")` 这样的标签，帮助 LLM 在对话中正确引用图片。当用户说"分析这张传单"时，模型知道指的是哪张图。

- **测试不同分辨率的输入**：Foundation Models 对图像分辨率有上限。测试时确认你的图片在缩放后仍然能被模型正确理解，特别是包含小字或细节的图片。
