## Highlight

> visionOS 的 M 系列芯片算力虽然强，但想跑 X-Plane 12 或 iRacing 这种 PC 级的重度 OpenXR 仿真应用，依然吃力。FoveatedStreaming 框架让 PC 端跑渲染、visionOS 端做显示，利用眼动追踪实现动态注视点压缩，无线串流也能做到低延迟、高画质，还能和 SwiftUI、RealityKit 原生内容混排。

---

## 核心内容

### 1. 这场演讲解决什么问题

visionOS 上的空间计算应用有两种极端：一种是原生开发的轻量 App，另一种是 PC 上跑的重度仿真/游戏。以前想把后者搬上 Vision Pro，开发者只能自己凑一套视频推流方案——延迟高、画质糊，还无法和 visionOS 原生系统交互。

Apple 在 visionOS 26.4 推出了 `FoveatedStreaming` 框架，底层集成了 NVIDIA CloudXR SDK。核心思路是：**PC 端跑 OpenXR 渲染，把画面通过 Wi-Fi 传给头显，visionOS 负责显示和输入**。最绝的是它利用了 Apple Vision Pro 的眼动追踪，你盯着的地方传高清，余光部分疯狂压缩，硬生生把无线带宽和延迟压到了可用水平。

这对做工业仿真、大型 PC 游戏和建筑设计可视化的团队是巨大利好。你不需要用 Swift 和 RealityKit 重写整个渲染引擎，只要让 PC 端实现 Foveated Streaming Protocol，visionOS 端写个几十行的"薄客户端"接收画面，就能直接上架 App Store。

### 2. FoveatedStreaming 框架的核心 API

框架的使用极其简单。创建一个 `FoveatedStreamingSession`，调用 `connect()` 就能建立连接：

```swift
import SwiftUI
import FoveatedStreaming

struct ConnectView: View {
    let session: FoveatedStreamingSession

    var body: some View {
        Button("Connect") {
            Task {
                try await session.connect()
            }
        }
    }
}
```

关键点：

- `FoveatedStreamingSession` 管理整个串流会话的生命周期，包括配对、连接、断开重连。
- 连接是异步的，需要在 `Task` 中调用。
- 框架自动处理眼动追踪数据的采集和传输，你不需要直接操作 ARKit 的眼动 API。

### 3. 在 Immersive Space 中显示串流内容

最简单的用法是把串流会话直接绑定到一个 `ImmersiveSpace`：

```swift
import SwiftUI
import FoveatedStreaming

@main struct FoveatedStreamingSampleApp: App {
    private let session = FoveatedStreamingSession()

    var body: some SwiftUI.Scene {
        ImmersiveSpace(foveatedStreaming: session)
    }
}
```

但这只是起点。真正强大的是**把串流内容和原生 visionOS 内容混排**。你可以在串流画面上叠加 SwiftUI 控件，或者把 RealityKit 的 3D 对象和串流场景融合在一起：

```swift
import SwiftUI
import FoveatedStreaming

@main struct FoveatedStreamingSampleApp: App {
    private let session = FoveatedStreamingSession()
    private let appModel = AppModel()

    var body: some SwiftUI.Scene {
        Window("Main", id: appModel.mainWindowId) {
            ContentView(session: session)
                .environment(appModel)
                .environment(session)
        }

        ImmersiveSpace(foveatedStreaming: session) {
            SpatialContainer {
                ReopenMainWindowView().environment(appModel)
                TransformStreamWidgetView().environment(session)
            }
        }
    }
}
```

关键点：

- `SpatialContainer` 让你把 SwiftUI 视图和串流画面放在同一个空间坐标系里。
- 通过 `.environment(session)` 把会话对象注入到视图层级，子视图可以读取串流状态、控制连接。
- 主窗口和 Immersive Space 可以同时存在，用户可以在 2D 控制面板和 3D 沉浸体验之间切换。

### 4. 与 RealityKit 内容混排

如果你需要更底层的 3D 控制，可以用 `RealityView` 把串流内容和自定义的 RealityKit 实体放在一起：

```swift
import SwiftUI
import RealityKit
import FoveatedStreaming

@main struct FoveatedStreamingSampleApp: App {
    private let session = FoveatedStreamingSession()
    private let appModel = AppModel()

    var body: some SwiftUI.Scene {
        ImmersiveSpace(foveatedStreaming: session) {
            RealityView { content in
                // 在这里添加自定义的 RealityKit 实体
                // 串流画面作为底层，RealityKit 内容叠加在上面
            }
        }
    }
}
```

这种混排能力意味着：PC 端跑你的重度渲染引擎，visionOS 端用 ARKit 做空间锚定、用手势追踪做交互反馈。比如 iRacing 把虚拟方向盘对齐到物理方向盘上，X-Plane 把虚拟仪表盘和真实驾驶舱融合在一起。

## 最佳实践

- **已有 PC OpenXR 项目的迁移策略**：不要试图在 visionOS 端重写渲染逻辑。直接参考 Apple 在 GitHub 上的 `StreamingSession` Sample Code，它已经封装好了 Foveated Streaming Protocol 的 TCP 握手和 NVIDIA CloudXR 的对接。把精力放在 visionOS 端的"薄客户端"体验上，比如用 SwiftUI 做一套优雅的配对界面、断线重连提示。

- **新项目的架构建议**：把 PC 端当作渲染服务器，visionOS 端当作交互客户端。PC 端只负责输出视频帧，所有输入（手柄、手势、语音）都通过 visionOS 的 ARKit 采集后传给 PC。这样架构清晰，两边可以独立迭代。

- **实战中容易踩的坑**：网络环境是最大的变量。虽然框架支持云端串流，但首发强烈建议只支持局域网 Wi-Fi 6 环境。务必监听 `session.state` 的变化，当用户摘下头显时主动通知 PC 端暂停渲染。另外，眼动追踪数据是隐私敏感信息，框架会自动处理权限和加密，你不需要也不应该直接访问原始眼动数据。
