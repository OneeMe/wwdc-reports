## Highlight

> gRPC Swift 今年彻底翻新，底层换成了基于 SwiftNIO 的现代运行时，原生支持 `async/await` 和 `AsyncSequence`。通过 Xcode Build Plugin 直接从 `.proto` 文件生成 Swift 代码，iOS 端和 Swift Server 端共享同一份接口定义，双向流式 RPC 让实时通信变得像写本地函数一样自然。

---

## 核心内容

### 1. 这场演讲解决什么问题

在 iOS 端做实时双向通信一直是痛点：

- 手写 RESTful API 配 Codable，接口文档和实际代码经常对不上
- WebSocket 需要自己处理粘包、心跳、重连，容易出错
- 前后端类型不统一，联调时才发现字段名拼错或类型不匹配
- 服务端用 Swift 写时，缺少成熟的 RPC 框架

gRPC Swift 的解法是：**用 Protocol Buffers 定义接口，自动生成前后端代码，基于 HTTP/2 实现高性能双向流。**

### 2. 定义服务：.proto 文件是唯一的真相源

```protobuf
edition = "2024";

import "google/protobuf/timestamp.proto";

service SwiftKartService {
  rpc ListRaces(ListRacesRequest) returns (ListRacesResponse);
  rpc FollowRace(stream FollowRaceRequest) returns (stream FollowRaceResponse);
}

message ListRacesRequest {
  int32 limit = 1 [default = 100];
}

message ListRacesResponse {
  repeated Race races = 1;
}

message Race {
  string name = 1;
  string location = 2;
  google.protobuf.Timestamp start_time = 3;
  int32 laps = 4;
  string championship = 5;
  repeated string drivers = 6;
}
```

关键点：

- `.proto` 文件是服务端和客户端共享的接口契约
- 每个字段有唯一的编号，支持向后兼容的字段增删
- `stream` 关键字开启双向流，适合实时场景
- Xcode Build Plugin 自动把 `.proto` 编译成 Swift 代码，不需要手动跑 `protoc`

### 3. 客户端：从简单调用到连接管理

**单次 RPC 调用**：

```swift
import GRPCCore
import GRPCNIOTransportHTTP2
import SwiftProtobuf

.task {
    do {
        try await withGRPCClient(
            transport: .http2NIOTS(
                address: .ipv4(host: "127.0.0.1", port: 8080),
                transportSecurity: .tls
            )
        ) { client in
            let kart = SwiftKartService.Client(wrapping: client)
            let request = ListRacesRequest()
            let response = try await kart.listRaces(request)
            self.races = response.races.map { ... }
        }
    } catch {
        print("gRPC error: \(error)")
    }
}
```

**连接复用与生命周期管理**：

```swift
@Observable
final class ClientManager: Sendable {
    fileprivate let state = Mutex(State.disconnected)

    func withClient(
        body: (_ client: GRPCClient<HTTP2ClientTransport.TransportServices>) async throws -> Void
    ) async throws {
        let client = try connectIfNecessary()
        try await body(client)
    }

    func disconnect() {
        let client = self.state.withLock { state in state.disconnect() }
        client?.beginGracefulShutdown()
    }
}
```

通过 SwiftUI 的 `environment` 传递 `ClientManager`，在 App 进入后台时调用 `disconnect()`：

```swift
@main
struct SwiftKartApp: App {
    let manager = ClientManager()
    @Environment(\.scenePhase) private var scenePhase

    var body: some Scene {
        WindowGroup {
            RaceScheduleView()
                .environment(manager)
        }
        .onChange(of: scenePhase) { _, newPhase in
            if newPhase == .background { manager.disconnect() }
        }
    }
}
```

### 4. 双向流：实时数据的理想模型

```swift
func followRace(
    request: RPCAsyncSequence<FollowRaceRequest, any Error>,
    response: RPCWriter<FollowRaceResponse>,
    context: ServerContext
) async throws {
    try await withThrowingTaskGroup { group in
        var iterator = request.makeAsyncIterator()
        guard let first = try await iterator.next() else { return }
        let eventTypes = Mutex(Set(first.eventTypes))

        // 发送实时事件
        group.addTask {
            let events = tracker.events(forRace: first.raceName)
                .filter { eventTypes.withLock { $0.contains(event.type) } }
            for await event in events {
                var message = FollowRaceResponse()
                // ... 填充消息
                try await response.write(message)
            }
        }

        // 监听客户端订阅变化
        while let next = try await iterator.next() {
            eventTypes.withLock { $0 = Set(next.eventTypes) }
        }

        group.cancelAll()
    }
}
```

### 5. 服务端与部署

```swift
struct Service: SwiftKartService.SimpleServiceProtocol {
    private let database = RaceDB()

    func listRaces(
        request: ListRacesRequest,
        context: ServerContext
    ) async throws -> ListRacesResponse {
        var response = ListRacesResponse()
        response.races = await database.listRaces(atMost: request.limit)
        return response
    }
}

let server = GRPCServer(
    transport: .http2NIOPosix(
        address: .ipv4(host: "127.0.0.1", port: 8080),
        transportSecurity: .plaintext
    ),
    services: [Service()]
)
try await server.serve()
```

支持容器化部署到 Google Cloud Run 等云平台：

```dockerfile
FROM swift:latest AS builder
WORKDIR /app
COPY Package.swift Package.resolved .
COPY Sources/ Sources/
RUN swift build -c release --product server
RUN cp "$(swift build -c release --show-bin-path)/server" /usr/bin/server

FROM swift:slim
COPY --from=builder /usr/bin/server /usr/bin/server
EXPOSE 8080
ENTRYPOINT ["/usr/bin/server"]
```

## 最佳实践

- **渐进式迁移**：不要一步到位把 REST 全换成 gRPC。挑出实时接口（IM 聊天、位置共享、协同编辑）用 gRPC 重构，普通 CRUD 继续用 REST
- **维护连接单例**：HTTP/2 的精髓是多路复用，一个物理连接承载无数并发流。全局维护 `ClientManager`，通过 SwiftUI `environment` 传递
- **后台必须 disconnect**：iOS 对后台网络极其敏感，进后台必须调用 `disconnect()`，否则会被系统杀进程，还会耗尽服务端连接池
- **后端也是 Swift 时首选 gRPC**：一套 `.proto` 前后端共享，类型安全省掉 80% 联调时间
