## Highlight

> WWDC21 周五回顾用 70 秒总结了 ResearchKit/CareKit、Safari 15 标签栏、SwiftUI Mac 应用、CloudKit Console、async/await、Xcode Cloud、SharePlay、Metal、watchOS、Xcode、游戏和无障碍等整周主题。

## 核心内容

WWDC 最后一天，开发者面对的是资料过载。五天里出现了新的语言特性、开发工具、平台能力、设计原则和社区活动。真正的问题变成了：会后先看哪几场，哪些内容应该马上验证，哪些内容可以放进长期学习清单。

这段 Friday@WWDC21 回顾没有展开 API 细节。它把一周的关键词压缩成一条路线：先回到具体 App 场景，比如医疗研究、Safari 设计、Mac App 和 CloudKit；再把学习队列拉宽到 async/await、Xcode Cloud、SharePlay、Metal、watchOS、Xcode、游戏和无障碍。

对开发者来说，这个短片的价值是收束。它提醒你，WWDC21 的重点不只在首日发布，也在后续专题 session 里的落地路径。比如 ResearchKit/CareKit 对应真实护理流程，Safari 15 对应网站适配，CloudKit Console 对应数据调试，Swift concurrency 和 Xcode Cloud 对应日常工程效率。

## 详细内容

### ResearchKit/CareKit：把研究和护理流程做成 App

（[00:09](https://developer.apple.com/videos/play/wwdc2021/10325/?time=9)）回顾先提到 create apps for research and care。片段中出现的具体细节是 clinicians 提供 educational text（临床人员提供教育文本），以及 cutting-edge research 帮助更多人。

这指向的是 ResearchKit 与 CareKit 的组合工作流。研究 App 需要收集参与者数据，护理 App 需要安排任务和反馈进展。临床教育文本把医生的指导带进 App，用户不只是在填写表单，也能理解每个任务背后的护理目的。

关键点：

- `research and care` 是完整场景，不只是问卷收集。
- `educational text from the clinicians` 说明内容来源应该来自临床人员，而不是临时文案。
- `cutting-edge research` 指向数据回流后的研究价值，App 需要把用户任务、结果和解释串起来。

### Safari 15：为标签栏和视觉智能重新检查 Web 体验

（[00:19](https://developer.apple.com/videos/play/wwdc2021/10325/?time=19)）回顾接着提到 design for Safari 15's tab bar，并且把它和 visual intelligence 放在同一句里。

Safari 15 改变了浏览器 chrome 和网页内容之间的关系。对网站和 Web App 来说，适配重点不只是页面能不能打开，还包括颜色、顶部留白、滚动状态、标签栏背景和可点击区域是否协调。视觉智能则提醒开发者，图片和页面内容会被系统理解，网页中的文本、图片和控件需要更清楚。

关键点：

- `tab bar` 是具体设计对象，适配应该从首屏、滚动和交互状态开始检查。
- `visual intelligence` 说明系统会参与理解页面内容，图片里的文字和上下文也会影响用户体验。
- Safari 15 同时影响 iPhone、iPad 和 Mac，Web 产品不能只测一个尺寸。

### SwiftUI Mac App 与 CloudKit Console：从跨平台 UI 到数据工作台

（[00:30](https://developer.apple.com/videos/play/wwdc2021/10325/?time=30)）回顾提到 build Mac apps with SwiftUI，并补了一句 These APIs and concepts apply to all platforms。它把 SwiftUI 的 Mac App 开发放进跨平台语境中：同一套声明式 UI 思路要服务不同设备上的窗口、菜单、输入方式和布局。

（[00:36](https://developer.apple.com/videos/play/wwdc2021/10325/?time=36)）随后出现 CloudKit Console。短片中特别提到，下次打开 console 时，它会直接回到上次访问的 container。这个细节很小，但指向真实开发流程：调试 CloudKit 问题时，开发者会反复进入同一个容器、切换环境、查记录和看日志。

关键点：

- `SwiftUI Mac apps` 的重点是把 SwiftUI 的 API 和概念带到 Mac App 工作流。
- `apply to all platforms` 说明会后学习 SwiftUI 时要把 iOS、iPadOS 和 macOS 一起考虑。
- `last container I visited` 是 CloudKit Console 的效率细节，适合高频调试场景。

### 整周学习队列：把关键词变成会后行动

（[00:48](https://developer.apple.com/videos/play/wwdc2021/10325/?time=48)）短片最后用一串关键词收尾：async/await、Xcode Cloud、SharePlay、Metal、Mindful Cooldowns for coding、watchOS、Tiera Fletcher 的演讲、Xcode、gaming、accessibility。

这串列表不是同一类技术。它覆盖语言、CI/CD、共享体验、图形、健康提醒、手表、开发工具、游戏和无障碍。会后处理它的方式应该按项目需求分层：先挑影响当前代码库的内容，再安排需要原型验证的内容，最后保留设计和社区主题作为团队讨论材料。

关键点：

- `async/await` 影响现有异步代码，适合优先做小范围迁移实验。
- `Xcode Cloud` 影响构建、测试和分发流程，适合从一个分支或一个 App target 开始试点。
- `SharePlay` 适合媒体、协作、共同观看和共同操作场景。
- `Metal` 与 gaming 放在同一组提醒里，图形和游戏团队应该继续看专题 session。
- `accessibility` 出现在收尾列表里，说明无障碍贯穿整周主题，需要和功能设计一起推进。

## 核心启发

1. **做什么**：给康复、随访或慢病管理 App 增加临床教育卡片。
   **为什么值得做**：回顾明确提到 clinicians 提供 educational text，ResearchKit/CareKit 场景需要把任务和解释一起交给用户。
   **怎么开始**：先选一个高频护理任务，把医生说明拆成短文本、图片或 3D 内容，再把完成状态和用户反馈记录到护理计划中。

2. **做什么**：做一个 Safari 15 首屏适配检查清单。
   **为什么值得做**：短片点名 Safari 15 tab bar 和 visual intelligence，网站顶部区域、图片文字和滚动状态都可能影响用户理解。
   **怎么开始**：从产品首页、登录页和文章页开始，逐项检查标签栏背景、顶部安全区、图片中的文字、深色模式和 iPad/Mac 尺寸。

3. **做什么**：为使用 CloudKit 的团队做一个容器调试入口页。
   **为什么值得做**：CloudKit Console 会记住上次访问的 container，说明 Apple 在优化高频容器调试流程。
   **怎么开始**：列出开发环境和生产环境的容器链接、常用查询、Schema 部署步骤和日志排查入口，让团队成员不用每次重新找位置。

4. **做什么**：把一个回调式网络流程改成 async/await 原型。
   **为什么值得做**：async/await 出现在周五收尾列表中，说明 Swift concurrency 是 WWDC21 会后必须验证的语言主题。
   **怎么开始**：选择一个低风险的 URLSession 请求，保留旧实现，新增 async 版本，对比错误处理、取消、加载状态和测试写法。

5. **做什么**：给媒体或协作 App 做一个 SharePlay 候选流程图。
   **为什么值得做**：SharePlay 被放进整周关键词，适合把共同观看、共同聆听或共同操作变成系统级体验。
   **怎么开始**：先定义哪些内容需要同步、谁能控制进度、参与者离开时怎样恢复，再继续阅读 Group Activities 相关 session。
