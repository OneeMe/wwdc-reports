## Highlight

> `@Observable` 的自动追踪能力现在直接支持 AppKit 和 UIKit 了——在 `draw(_:)`、`layout()`、`updateConstraints()` 里读取 `@Observable` 模型的属性，视图会自动重绘，不需要手动写 `needsDisplay = true`。同时 `NSGestureRecognizerRepresentable`、`NSHostingMenu`、`NSHostingSceneRepresentation` 让 SwiftUI 和原生框架的互操作达到了前所未有的深度。

---

## 核心内容

### 1. 这场演讲解决什么问题

老项目想逐步采用 SwiftUI，但面临几个障碍：

- 状态管理割裂：SwiftUI 用 `@Observable`，AppKit/UIKit 还要手动 KVO 或写 `needsDisplay = true`
- 互操作单向：只能用 `NSViewRepresentable` 把老视图塞进 SwiftUI，反向操作困难
- 菜单、手势、Scene 等系统级组件难以用 SwiftUI 替换
- 担心重写成本太高，不敢开始迁移

今年的更新让 SwiftUI 和原生框架的缝合线被官方 API 彻底熨平。

### 2. Observation 框架支持 AppKit/UIKit

**核心机制**：在 `draw(_:)`、`layout()`、`updateConstraints()`、`updateLayer()` 等方法中读取 `@Observable` 属性，系统会自动注册依赖追踪。属性变化时，视图自动重绘。

```swift
import Observation

@Observable @MainActor
final class ColorModel {
    var hue: Double = 0.6
    var saturation: Double = 1.0
    var brightness: Double = 1.0
}
```

AppKit 的 `NSSliderCell` 在 `drawKnob` 里读取 `ColorModel` 的属性：

```swift
class CustomSliderCell: NSSliderCell {
    var model: ColorModel

    override func drawKnob(_ knobRect: NSRect) {
        // 读取 model 属性，系统自动注册追踪
        let color = NSColor(hue: model.hue, saturation: model.saturation,
                           brightness: model.brightness, alpha: 1.0)
        // 绘制旋钮...
    }
}
```

当 `model.hue` 变化时，所有在 `drawKnob` 里读过 `model` 的 slider 自动重绘——不需要写 `needsDisplay = true`。

**支持的方法列表**：

- AppKit: `draw(_:)`, `updateConstraints()`, `layout()`, `updateLayer()`, `NSViewController` 对应方法
- UIKit: `UIView.draw(_:)`, `UIViewController` 方法, `UIButton`, `UICollectionViewCell` 等

**向后部署**：

- macOS 15: 在 Info.plist 中添加 `NSObservationTrackingEnabled`
- iOS 18: 在 Info.plist 中添加 `UIObservationTrackingEnabled`
- macOS 26 / iOS 26 及以后：默认开启

### 3. 把 SwiftUI 视图嵌入 AppKit

```swift
let hostingView = NSHostingView(
    rootView: HSBColorPicker(model: model)
)
// 像普通 NSView 一样添加到视图层级
containerView.addSubview(hostingView)
```

`NSHostingView` 已经是成熟方案，今年的改进是 SwiftUI 视图可以更好地和 AppKit 的手势、菜单、窗口系统集成。

### 4. 把 AppKit 手势带入 SwiftUI

```swift
import SwiftUI
import AppKit

struct ForceClickReset: NSGestureRecognizerRepresentable {
    var model: ColorModel

    func makeNSGestureRecognizer(context: Context) -> ForceClickGestureRecognizer {
        ForceClickGestureRecognizer()
    }

    func handleNSGestureRecognizerAction(_ recognizer: ForceClickGestureRecognizer, context: Context) {
        withAnimation {
            model.saturation = 1
            model.brightness = 1
        }
    }
}

final class ForceClickGestureRecognizer: NSGestureRecognizer {
    private var didActivate = false

    override func pressureChange(with event: NSEvent) {
        if event.stage >= 2 && !didActivate {
            didActivate = true
            state = .ended
        }
    }

    override func mouseDown(with event: NSEvent) {
        didActivate = false
        state = .possible
    }

    override func mouseUp(with event: NSEvent) {
        didActivate = false
        state = .possible
    }
}
```

在 SwiftUI 中使用：

```swift
HSBColorPicker(model: model)
    .gesture(ForceClickReset(model: model))
```

关键点：

- `NSGestureRecognizerRepresentable` 协议让自定义 `NSGestureRecognizer` 可以在 SwiftUI 中使用
- `makeNSGestureRecognizer` 创建手势识别器
- `handleNSGestureRecognizerAction` 处理手势触发

### 5. SwiftUI 菜单嵌入 AppKit 主菜单

```swift
struct ColorMenu: View {
    var model: ColorModel

    var body: some View {
        Button("Full Intensity") {
            withAnimation { model.saturation = 1; model.brightness = 1 }
        }
        .keyboardShortcut(.upArrow, modifiers: [.command, .shift])

        Divider()

        Picker("Color", selection: Bindable(model).hue) {
            ForEach(Self.hues, id: \.hue) { entry in
                Label(entry.name, systemImage: "circle.fill")
                    .tint(Color(hue: entry.hue, saturation: 1, brightness: 1))
                    .tag(entry.hue)
            }
        }
        .pickerStyle(.palette)
    }
}

@MainActor
class AppDelegate: NSObject, NSApplicationDelegate {
    let colorModel = ColorModel()

    func setupMainMenu() {
        let mainMenu = NSMenu()
        let colorMenu = NSHostingMenu(rootView: ColorMenu(model: colorModel))
        colorMenu.title = "Color"

        let colorMenuItem = NSMenuItem()
        colorMenuItem.submenu = colorMenu
        mainMenu.addItem(colorMenuItem)
    }
}
```

- `NSHostingMenu` 把 SwiftUI `View` 包装成 `NSMenu`
- 支持 `keyboardShortcut`、Picker、Divider 等 SwiftUI 控件
- 菜单项的状态和 `@Observable` 模型自动同步

### 6. 动态添加 SwiftUI Scene

在现有的 `NSApplicationDelegate` 里动态挂载 SwiftUI Scene：

```swift
@MainActor
class AppDelegate: NSObject, NSApplicationDelegate {
    let model = AppModel()
    var openSettingsAction: (() -> Void)?

    func applicationWillFinishLaunching(_ notification: Notification) {
        let scenes = NSHostingSceneRepresentation {
            LightMenuBarExtra(appModel: model)
            LightSettings(appModel: model)
        }
        NSApplication.shared.addSceneRepresentation(scenes)
        openSettingsAction = {
            scenes.environment.openSettings()
        }
    }
}

struct LightMenuBarExtra: Scene {
    var appModel: AppModel

    var body: some Scene {
        MenuBarExtra("Light Mix", systemImage: "lightbulb.fill",
                     isInserted: Bindable(appModel).showMenuBarExtra) {
            MenuBarContent(appModel: appModel)
        }
        .menuBarExtraStyle(.window)
    }
}

struct LightSettings: Scene {
    var appModel: AppModel

    var body: some Scene {
        Settings {
            SettingsView(appModel: appModel)
        }
    }
}
```

关键点：

- `NSHostingSceneRepresentation` 在 AppKit 的 App Delegate 里创建 SwiftUI Scene
- `NSApplication.shared.addSceneRepresentation()` 动态挂载
- 支持 `MenuBarExtra`、`Settings` 等 SwiftUI Scene 类型
- 不需要改变整体架构，像搭积木一样逐步替换

## 最佳实践

- **起手式：给核心模型加 `@Observable`**：让现有 NSView/UIView 享受自动刷新，零成本获得第一个收益
- **新增模块用 SwiftUI 写**：设置面板、复杂图表、菜单栏扩展等独立模块，通过 `NSHostingView` 嵌入
- **边缘 Scene 用 `NSHostingSceneRepresentation`**：MenuBarExtra、Settings 等不需要重写 App Delegate
- **注意 Info.plist 开关**：支持 macOS 15 / iOS 18 时，必须手动添加 `NSObservationTrackingEnabled` / `UIObservationTrackingEnabled`
- **不要主动引入混编**：新项目除非需要极度底层的自定义控件，否则直接用纯 SwiftUI
