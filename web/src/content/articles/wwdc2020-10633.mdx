## Highlight

> ReplayKit 在 WWDC 2020 登陆 macOS，让 Mac 应用可以在应用内录制、获取音视频样本、发起第三方直播，并通过游戏手柄按钮触发录制。

---

## 核心内容

如果你在 2020 年以前做 Mac 游戏，想让玩家录一段操作过程，通常要把问题丢给系统录屏或第三方工具。应用拿不到统一的录制入口，也很难把录制、预览、保存、分享这些步骤放进自己的界面。直播更麻烦，用户要离开应用去找推流工具，开发者还要自己处理音频、画面、麦克风和隐私提示。

ReplayKit 原来已经服务 iOS 和 tvOS。Johnny Trenh 在开场说明，WWDC 2020 的变化是把这些能力带到 Mac：Mac 应用现在可以录制应用画面、应用音频和麦克风，可以把样本直接交回应用进程，也可以连接第三方直播服务。Apple 同时保留了 HD 质量、较低性能影响和内建隐私保护。

这场演讲按三个按钮讲完整个流程。第一个按钮控制应用内录制，结束后交给 `RPPreviewViewController` 让用户裁剪、保存或分享。第二个按钮控制应用内捕获，`startCapture` 会持续把视频、应用音频、麦克风样本送回回调。第三个按钮控制直播，`RPBroadcastActivityController` 在 Mac 上显示服务选择器，用户选好服务后，应用拿到 `RPBroadcastController` 来开始和结束直播。

Mac 版本还有两个细节值得单独记住。录制、捕获或直播进行时，菜单栏会出现 ReplayKit 图标，用户可以从那里停止会话。手柄也有新入口：PS4 手柄的 Share 按钮或 Xbox 手柄的 Select 按钮双击可以开始录制，再次双击停止，iOS 保存到照片，macOS 保存到桌面。

## 详细内容

### 应用内录制：先交给 ReplayKit 生成影片

（[01:41](https://developer.apple.com/videos/play/wwdc2020/10633/?time=101)）屏幕录制的基本路径很短。应用从 `RPScreenRecorder` 取得共享实例，调用 `startRecording` 后，ReplayKit 捕获应用画面、应用音频和麦克风，并写入影片文件。停止时，ReplayKit 保存录制内容，并通过 `RPPreviewViewController` 交给用户编辑、保存或分享。

```swift
let recorder = RPScreenRecorder.shared()

recorder.startRecording { error in
    guard error == nil else {
        print(error!)
        return
    }

    recordingState = true
    recordButton.title = "Stop Recording"
}
```

关键点：

- `RPScreenRecorder.shared()` 取得 ReplayKit 的共享录制器，演讲中所有录制、捕获流程都从它开始。
- `startRecording` 启动应用内录制，ReplayKit 开始收集画面、应用音频和麦克风。
- 回调里的 `error` 用来判断录制是否真正启动。
- `recordingState` 和按钮标题是示例工程的 UI 状态，作用是让同一个按钮再次点击时进入停止流程。

（[04:35](https://developer.apple.com/videos/play/wwdc2020/10633/?time=275)）停止录制时，演讲重点放在 `previewViewController`。应用要保留它、设置代理，并用 Mac 的 sheet 方式展示。用户点保存或关闭以后，代理方法会通知应用收起预览界面。

```swift
let recorder = RPScreenRecorder.shared()

recorder.stopRecording { previewViewController, error in
    guard error == nil else {
        print(error!)
        return
    }

    guard let previewViewController else { return }

    self.previewViewController = previewViewController
    previewViewController.previewControllerDelegate = self
    view.window?.beginSheet(previewViewController.view.window!)
}
```

关键点：

- `stopRecording` 结束录制，并把预览控制器传回应用。
- `previewViewController` 承载裁剪、保存和分享流程，Mac 上保存会走标准文件保存体验。
- 设置 `previewControllerDelegate` 是为了在用户完成预览后收到回调。
- `beginSheet` 对应演讲中的 Mac 展示方式，实际项目可以按自己的窗口结构展示。

### 新的停止录制 URL：让应用读到影片文件

（[07:20](https://developer.apple.com/videos/play/wwdc2020/10633/?time=440)）传统应用内录制不把影片文件直接暴露给应用。ReplayKit 负责创建影片，用户在预览界面决定保存或分享。很多开发者想把录制结果放进自己的素材库或编辑器，所以这一年增加了带目标 URL 的停止录制方式。

```swift
let outputURL = replaysDirectory.appendingPathComponent("last-run.mov")

RPScreenRecorder.shared().stopRecording(withOutput: outputURL) { error in
    guard error == nil else {
        print(error!)
        return
    }

    importReplay(at: outputURL)
}
```

关键点：

- 演讲把这个能力称为新的 `stopRecordingWithURL`，应用提供目标 URL。
- ReplayKit 把录制影片写到这个 URL，应用获得读取权限。
- `importReplay(at:)` 代表应用自己的后续流程，例如建立回放列表或进入自定义剪辑界面。
- 这个模式适合需要管理录制文件的 Mac 应用，而不是只让用户点系统分享面板。

### 应用内捕获：直接处理音视频样本

（[08:44](https://developer.apple.com/videos/play/wwdc2020/10633/?time=524)）如果你不想让 ReplayKit 生成影片，可以改用应用内捕获。`startCapture` 不负责保存影片，它会把应用视频、应用音频、麦克风样本持续送回应用进程。演讲示例用 `switch` 分别处理三类样本。

```swift
let recorder = RPScreenRecorder.shared()

recorder.startCapture(handler: { sampleBuffer, sampleType, error in
    guard error == nil else {
        print(error!)
        return
    }

    switch sampleType {
    case .video:
        processAppVideoSample(sampleBuffer)
    case .audioApp:
        processAppAudioSample(sampleBuffer)
    case .audioMic:
        processMicAudioSample(sampleBuffer)
    @unknown default:
        break
    }
}, completionHandler: { error in
    guard error == nil else {
        print(error!)
        return
    }

    captureState = true
})
```

关键点：

- `startCapture` 接收两个回调：样本回调会反复执行，完成回调只在捕获启动时执行一次。
- `sampleBuffer` 是每次送回的音视频样本。
- `sampleType` 区分应用视频、应用音频和麦克风。
- 你可以把视频样本用于截图、游戏 HUD、叠加层或自己的编码管线。
- 完成回调用来更新按钮状态、禁用其他 ReplayKit 功能按钮，并按需启动摄像头画中画。

### 直播：用 Mac 版广播选择器连接第三方服务

（[14:21](https://developer.apple.com/videos/play/wwdc2020/10633/?time=861)）直播流程分三步。应用先显示广播服务选择器；用户选中第三方服务后，ReplayKit 建立与广播扩展的连接；应用拿到 `RPBroadcastController`，再调用它开始、暂停或结束直播。

```swift
let pickerOrigin = CGPoint(x: broadcastButton.frame.minX,
                           y: broadcastButton.frame.minY)

RPBroadcastActivityController.showBroadcastPicker(
    at: pickerOrigin,
    from: view.window,
    preferredExtension: nil
) { activityController, error in
    guard error == nil else {
        print(error!)
        return
    }

    self.activityController = activityController
    activityController?.delegate = self
}
```

关键点：

- macOS 使用 `RPBroadcastActivityController`，不是 iOS 的 `RPBroadcastActivityViewController`。
- `showBroadcastPicker` 需要一个 `CGPoint` 和窗口引用，因为 Mac 有多窗口、多屏幕。
- `preferredExtension` 可以指定某个广播服务；传 `nil` 时展示可用的第三方服务列表。
- 设置代理很关键，用户选完服务后，应用要从代理回调里取得广播控制器。

（[17:34](https://developer.apple.com/videos/play/wwdc2020/10633/?time=1054)）拿到广播控制器后，应用马上可以开始直播。结束时不要重新寻找控制器，直接使用之前保存的引用调用完成广播。

```swift
func broadcastActivityController(
    _ broadcastActivityController: RPBroadcastActivityController,
    didFinishWith broadcastController: RPBroadcastController?,
    error: Error?
) {
    guard error == nil else {
        print(error!)
        return
    }

    self.broadcastController = broadcastController

    broadcastController?.startBroadcast { error in
        guard error == nil else {
            print(error!)
            return
        }

        broadcastState = true
    }
}

broadcastController?.finishBroadcast { error in
    guard error == nil else {
        print(error!)
        return
    }

    broadcastState = false
}
```

关键点：

- 代理方法返回的 `RPBroadcastController` 是直播控制入口。
- `startBroadcast` 成功后，应用的音频和视频会发送到用户选择的第三方服务。
- 保存 `broadcastController` 是为了后续暂停、停止或更新状态。
- `finishBroadcast` 结束直播，随后应用恢复按钮状态和摄像头等 UI。

### 隐私入口和手柄入口：应用要跟上外部停止动作

（[20:48](https://developer.apple.com/videos/play/wwdc2020/10633/?time=1248)）macOS 上只要存在活跃的录制、捕获或直播会话，菜单栏就会显示 ReplayKit 图标。这个图标提示用户正在进行 ReplayKit 会话，也允许用户从应用外停止会话。应用需要实现 `RPScreenRecorderDelegate` 的停止回调。

```swift
func screenRecorder(
    _ screenRecorder: RPScreenRecorder,
    didStopRecordingWith previewViewController: RPPreviewViewController?,
    error: Error?
) {
    recordingState = false
    captureState = false
    broadcastState = false

    if let previewViewController {
        self.previewViewController = previewViewController
        previewViewController.previewControllerDelegate = self
    }
}
```

关键点：

- 用户可能从菜单栏停止 ReplayKit，会话结束不一定来自应用按钮。
- `didStopRecordingWithPreviewViewController` 是演讲点名要求遵守的代理回调。
- 捕获和直播场景下，传入的 `RPPreviewViewController` 会是 `nil`。
- 应用要在这里同步内部状态，避免按钮还显示“正在录制”。

（[21:42](https://developer.apple.com/videos/play/wwdc2020/10633/?time=1302)）Game Controller 框架也内建了 ReplayKit。PS4 手柄双击 Share，Xbox 手柄双击 Select，可以开始应用内录制；再次双击会停止录制，并在 iOS 保存到照片、在 macOS 保存到桌面。应用应该观察 `RPScreenRecorder` 的 `availability` 和 `recording` 属性，并在停止回调中修正 UI。

```swift
let recorder = RPScreenRecorder.shared()

recorder.addObserver(self, forKeyPath: "available", options: [.new], context: nil)
recorder.addObserver(self, forKeyPath: "recording", options: [.new], context: nil)
recorder.delegate = self
```

关键点：

- 手柄可以在应用按钮之外启动或停止录制。
- 观察可用性和录制状态，应用才能及时更新按钮、叠加层和提示文字。
- 设置 `delegate` 后，应用能收到外部停止事件。
- 这个入口适合游戏，玩家不用离开手柄就能保存高光片段。

## 核心启发

- **做一个游戏高光回放库**：玩家按按钮录制一局关键操作，结束时用带 URL 的停止录制把影片写入应用目录。这样应用可以展示最近回放、重命名片段、加标签。起步入口是 `RPScreenRecorder.shared()`、`startRecording` 和带目标 URL 的停止录制。

- **做带实时叠加层的教学录制**：教学类 Mac 应用可以用 `startCapture` 取得视频样本，再叠加鼠标位置、快捷键、步骤编号。这样录制结果能直接表达用户做了什么。起步时先区分 `.video`、`.audioApp`、`.audioMic`，再把视频样本送入自己的处理管线。

- **做应用内直播开播按钮**：创作工具或游戏可以把直播入口放在主窗口，点击后显示 `RPBroadcastActivityController` 的服务选择器。用户选好服务后，应用保存 `RPBroadcastController`，再用它开始和结束直播。

- **做手柄驱动的录制状态 UI**：游戏不要假设录制只来自屏幕按钮。监听 `RPScreenRecorder` 的可用性和录制状态，再实现停止代理回调。玩家用手柄双击触发录制时，HUD 能同步显示红点和时长。

- **做尊重隐私的会话恢复逻辑**：macOS 菜单栏图标允许用户从应用外停止 ReplayKit。应用应该在代理回调里统一清理录制、捕获、直播状态，重新启用被禁用的按钮，并避免继续显示摄像头画中画。
