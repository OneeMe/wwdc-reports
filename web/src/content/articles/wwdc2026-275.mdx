## Highlight

> 这场 Code-along 手把手教你把纯内存的 SwiftUI App 改造成用 SwiftData 持久化：加一行 `@Model` 宏、配一个 `ModelContainer`、用 `@Query` 替换手动过滤，数据就能自动存到磁盘并在所有视图间同步——不需要写 Core Data 的 boilerplate。

---

## 核心内容

### 1. 这场演讲解决什么问题

很多 SwiftUI 教程示例都用 `@Observable` + 内存数组管理数据，演示时没问题，但一关 App 数据全丢。要加持久化，传统做法是引入 Core Data，然后面对一堆模板代码：

- 手写 `NSManagedObject` 子类
- 自己管理 `NSPersistentContainer`
- 写 `NSFetchRequest` 查询数据
- 处理上下文合并和线程安全

SwiftData 把这整套流程压缩成了几个声明式 API。这场演讲用一个真实的旅行规划 App「Wishlist」做例子，从纯内存实现一步步迁移到 SwiftData 持久化。

### 2. 从 `@Observable` 到 `@Model`

第一步是把数据模型改成 SwiftData 的 `Model`。`@Model` 宏会自动生成 `Observable` conformance，所以视图层的 `@State` 和绑定不需要改。

```swift
import Foundation
import SwiftData

// 之前用 @Observable，现在换成 @Model
@Model
class Activity {
    var name: String
    var isComplete: Bool = false
    var dateCreated = Date.now
    var dateEdited = Date.now
}
```

关键点：

- `@Model` 会自动处理 `Observable` 的 conformance，视图可以照常监听变化
- SwiftData 支持的类型包括基础类型（String、Int、Bool、Date 等）、可选类型、数组、以及符合 `Codable` 的自定义类型
- 复杂类型（比如枚举）需要显式声明 `Codable` conformance

```swift
enum TripCollection: String, CaseIterable, RawRepresentable, Codable {
    case springEscapes
    case summerVibes
    case fallGetaways
    case winterRetreats
}
```

### 3. 定义模型关系

SwiftData 的关系定义比 Core Data 直观得多。用 `@Relationship` 宏标注关联，并指定 `deleteRule` 和 `inverse`：

```swift
@Model
class Trip {
    var name: String
    var collection: TripCollection

    var photo: TripImage
    var thumbnailData: Data?

    @Relationship(deleteRule: .cascade, inverse: \Activity.trip)
    var activities: [Activity] = []

    private(set) var creationDate = Date.now
    var subtitle: String?
    var isComplete: Bool = false
}
```

关键点：

- `deleteRule: .cascade` 表示删除 Trip 时自动级联删除关联的 Activity
- `inverse: \Activity.trip` 建立双向关系，SwiftData 会自动维护一致性
- 关系属性必须是可选或带默认值的数组，因为加载时可能延迟获取

### 4. 配置 ModelContainer 和注入环境

在 App 的入口点创建 `ModelContainer`，并通过 `.modelContainer()` modifier 注入到整个视图树：

```swift
import SwiftUI
import SwiftData

@main
struct WishlistApp: App {
    let container: ModelContainer = {
        do {
            let modelContainer = try ModelContainer(
                for: Trip.self, Activity.self, TripImage.self,
                Goal.self, TripGoal.self, ActivityGoal.self
            )
            try SampleData.seedIfNeeded(in: modelContainer.mainContext)
            return modelContainer
        } catch {
            fatalError("Could not create model container: \(error)")
        }
    }()

    var body: some Scene {
        WindowGroup {
            ContentView()
                .preferredColorScheme(.dark)
        }
        .modelContainer(container)
    }
}
```

关键点：

- `ModelContainer(for:)` 的参数列表就是 schema 定义，不需要单独的 xcdatamodeld 文件
- `mainContext` 是主线程的 model context，适合 UI 操作
- `.modelContainer()` 会把 container 注入到 SwiftUI 环境，子视图通过 `@Environment(\.modelContext)` 获取

### 5. 用 @Query 替换手动数据过滤

`@Query` 是 SwiftData 最核心的视图层 API。它把数据库查询变成声明式属性包装器，数据变化时视图自动刷新。

**基础查询：**

```swift
@Query(filter: #Predicate<Goal> { $0.isAchieved }, sort: \Goal.dateAchieved, order: .reverse)
private var achievedGoals: [Goal]

@Query(filter: #Predicate<Goal> { !$0.isAchieved }, sort: \Goal.sortOrder)
private var upcomingGoals: [Goal]
```

**带限制和排序的复杂查询：**

```swift
@Query(FetchDescriptor<Trip>(
    sortBy: [SortDescriptor(\Trip.creationDate, order: .reverse)],
    fetchLimit: 5
))
private var trips: [Trip]
```

**动态构造查询（在 init 中）：**

```swift
init(tripCollection: TripCollection, cardSize: TripCard.Size, namespace: Namespace.ID) {
    _trips = Query(filter: #Predicate<Trip> { $0.collection == tripCollection }, sort: \Trip.name)
    self.tripCollection = tripCollection
    self.cardSize = cardSize
    self.namespace = namespace
}
```

**搜索查询：**

```swift
init(searchText: String, namespace: Namespace.ID) {
    self.searchText = searchText
    self.namespace = namespace

    if searchText.isEmpty {
        _trips = Query(FetchDescriptor(sortBy: [
            SortDescriptor(\Trip.creationDate, order: .reverse)
        ], fetchLimit: 3))
        _activities = Query(filter: #Predicate<Activity> { _ in false })
    } else {
        let tripSearchPredicate = #Predicate<Trip> {
            $0.name.localizedStandardContains(searchText)
        }
        _trips = Query(filter: tripSearchPredicate, sort: \Trip.name)

        let activitySearchPredicate = #Predicate<Activity> {
            $0.trip != nil && $0.name.localizedStandardContains(searchText)
        }
        _activities = Query(filter: activitySearchPredicate, sort: \Activity.name)
    }
}
```

关键点：

- `#Predicate` 是 Swift 宏，把闭包编译成 SwiftData 的查询表达式，类型安全且支持代码补全
- `@Query` 在 `init` 中通过 `_trips` 赋值，因为属性包装器的初始化语法限制
- `FetchDescriptor` 提供更细粒度的控制：排序、限制、偏移、预取关系等

### 6. 用 Observation 替代 didSet 副作用

SwiftData 模型不支持 `didSet` 属性观察器，因为 `@Model` 宏会重写属性访问。演讲展示了用 `withContinuousObservation` 替代：

```swift
init(activity: Activity, isLast: Bool, isEditing: Bool) {
    activity.token = withContinuousObservation(options: .didSet) { event in
        _ = activity.name
        _ = activity.isComplete

        if event.matches(\Activity.name) {
            activity.dateEdited = .now
        }

        if event.matches(\Activity.isComplete) {
            activity.dateEdited = .now
            activity.trip?.isComplete = activity.trip?.activities.isEmpty == false
                && activity.trip?.activities.allSatisfy { $0.isComplete } == true
        }
    }
    // ...
}
```

关键点：

- `withContinuousObservation` 监听模型的属性变化，比 `didSet` 更灵活
- `event.matches(\Activity.name)` 精确匹配特定属性的变化
- 可以在一个观察块中处理多个属性的副作用

## 最佳实践

- **从 `@Observable` 迁移到 `@Model` 时**，先确认所有属性类型都受 SwiftData 支持。不支持的类型（如复杂 struct）可以包装成 `Codable` 或拆成独立模型
- **关系设计遵循「谁拥有谁 cascade」原则**：如果删除父对象应该连带删除子对象，用 `.cascade`；如果子对象应该独立存在，用 `.nullify`
- **查询性能**：`@Query` 默认在主线程执行，大数据量时用 `FetchDescriptor` 的 `fetchLimit` 分页，或考虑后台 context
- **错误处理**：SwiftData 操作会抛出错误，建议在视图中用 `.alert(error:)` 统一处理，而不是 `fatalError`
- **预置数据**：在 `ModelContainer` 初始化时通过 `mainContext` 插入 sample data，配合 `seedIfNeeded` 避免重复插入
