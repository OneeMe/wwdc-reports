## Highlight

> Foundation Models 框架现在向第三方 LLM 开放——只要实现 `LanguageModel` 和 `LanguageModelExecutor` 两个协议，你的模型（无论是本地 Core AI 模型、MLX 社区模型、还是云端 Claude/Gemini）就能被 App 开发者用同一套 `LanguageModelSession` API 调用，换模型就像换皮肤一样简单。

---

## 核心内容

### 1. 这场演讲解决什么问题

以前在 iOS App 里接入不同的大模型，每个都要写一套网络请求、流式解析、上下文管理的样板代码。Claude 一套、Gemini 一套、本地 MLX 模型又一套，换模型等于重构一半逻辑。

今年 Apple 把 Foundation Models 框架开放给了第三方。Anthropic 和 Google 会推出官方 Swift Package，社区开发者也可以自己包装模型。对 App 开发者来说，所有模型统一用 `LanguageModelSession` 调用；对模型提供商来说，这是一个明确的信号——接入 Foundation Models 生态就能被开发者无痛集成。

### 2. 四种内置模型选项

在实现自己的模型之前，先看看已有的选择：

```swift
import FoundationModels
import MLXFoundationModels

// 端侧 Apple 基础模型
let model = SystemLanguageModel()

// Private Cloud Compute（云端，隐私保护）
// let model = PrivateCloudComputeLanguageModel()

// 自定义 Core AI 模型
// let model = try await CoreAILanguageModel(resourcesAt: modelURL)

// HuggingFace 上的 MLX 社区模型
// let model = MLXLanguageModel(modelID: "mlx-community/my-model")

let session = LanguageModelSession(model: model)
let response = try await session.respond(to: "...")
```

所有模型都遵循同一个 `LanguageModel` 协议，所以切换模型不需要改业务代码。

### 3. 实现 LanguageModel 协议

把自定义模型接入框架需要四步：打包 → 实现协议 → 认证 → 定制。这里重点讲协议实现。

首先配置 Swift Package：

```swift
// Package.swift
let package = Package(
    name: "MyModel",
    platforms: [.macOS(.v27), .iOS(.v27), .visionOS(.v27), .watchOS(.v27)],
    products: [.library(name: "MyModel", targets: ["MyModel"])],
    targets: [
        .target(name: "MyModelRuntime"),
        .target(name: "MyModel", dependencies: ["MyModelRuntime"]),
        .testTarget(name: "MyModelTests", dependencies: ["MyModel"])
    ]
)
```

然后实现两个核心协议：

```swift
// LanguageModel 协议：描述模型的能力
public struct MyLanguageModel: LanguageModel {
    typealias Executor = MyLanguageModelExecutor

    public var capabilities: LanguageModelCapabilities {
        LanguageModelCapabilities(capabilities: [
            .toolCalling, .guidedGeneration, .reasoning
        ])
    }

    public var executorConfiguration: Executor.Configuration {
        Executor.Configuration(/* ... */)
    }
}

// LanguageModelExecutor 协议：实际执行推理
public struct MyLanguageModelExecutor: LanguageModelExecutor {
    public typealias Model = MyLanguageModel

    public struct Configuration: Hashable, Sendable { /* ... */ }

    public init(configuration: Configuration) throws { /* ... */ }

    public func respond(
        to request: LanguageModelExecutorGenerationRequest,
        model: MyLanguageModel,
        streamingInto channel: LanguageModelExecutorGenerationChannel
    ) async throws { /* ... */ }
}
```

关键点：

- `LanguageModel` 是轻量级描述对象，声明模型支持的能力（tool calling、guided generation 等）
- `LanguageModelExecutor` 是实际干活的类型，管理模型资源和执行推理
- 两者通过关联类型（`typealias Executor` / `typealias Model`）互相引用
- `Sendable` 约束确保线程安全

### 4. 管理模型资源和流式输出

`prewarm` 和 `respond` 是 executor 的两个核心方法。`prewarm` 在会话创建时预加载模型权重，`respond` 处理实际的生成请求：

```swift
struct MyLanguageModelExecutor: LanguageModelExecutor {
    private mutating func loadModelIfNeeded() throws -> LoadedWeights {
        let weights = try loadedModel ?? loadWeights()
        loadedModel = weights
        return weights
    }

    func prewarm(transcript: Transcript) {
        loadedModel = try? loadModelIfNeeded()
    }

    func respond(
        to request: LanguageModelExecutorGenerationRequest,
        model: MyLanguageModel,
        streamingInto channel: LanguageModelExecutorGenerationChannel
    ) async throws {
        let weights = try loadModelIfNeeded()
        // ... 用 weights 生成回复 ...
    }
}
```

流式输出通过 `channel` 发送：

```swift
func respond(...) async throws {
    // 1. 报告元数据
    await channel.send(.response(action: .updateMetadata([
        "modelID": "my-model-2026-06-08",
        "requestID": request.id.uuidString
    ])))

    // 2. 报告输入 token 用量
    await channel.send(.response(action: .updateUsage(
        input: .init(totalTokenCount: promptTokens, cachedTokenCount: cachedTokens),
        output: .init(totalTokenCount: 0, reasoningTokenCount: 0)
    )))

    // 3. 流式发送生成的 token
    for try await token in tokens {
        await channel.send(.response(action: .appendText(token)))
    }
}
```

关键点：

- `prewarm` 是优化首次响应延迟的关键，应该在这里完成模型加载和权重初始化
- `channel` 是双向通信管道，可以发送文本、元数据、使用统计、错误信息
- 支持发送自定义 segment 类型（如音频文件、搜索结果等）

### 5. Transcript 和错误处理

`Transcript` 是会话的历史记录，包含多种 segment 类型：

```swift
let transcript = Transcript(entries: [
    .instructions("You are a helpful assistant"),
    .prompt("What's the weather in Pittsburgh?"),
    .toolCalls(getWeather(location: "Pittsburgh")),
    .toolOutput("65°F, sunny"),
    .response("It's 65°F and sunny in Pittsburgh"),
    .prompt("What's the address of Apple Park?"),
    .response("One Apple Park Way, Cupertino, CA 95014")
])
```

Foundation Models 定义了一套标准错误类型：

```swift
public enum LanguageModelError: LocalizedError {
    case contextSizeExceeded    // 超出上下文窗口，需要裁剪历史
    case rateLimited           // 请求过于频繁
    case refusal               // 模型拒绝回答
    case guardrailViolation    // 安全护栏触发
    case unsupportedCapability // 模型不支持某项功能
    case unsupportedTranscriptContent // prompt 包含无法处理的内容
    case unsupportedGenerationGuide   // 生成引导不被支持
    case unsupportedLanguageOrLocale  // 不支持的语种
    case timeout               // 请求超时
}
```

你也可以定义自己的错误类型：

```swift
public enum MyModelError: Error {
    case exceededSubscriptionTierLimit
    case modelNotProvisioned
    case accountSuspended

    public var errorDescription: String? {
        switch self {
        case .exceededSubscriptionTierLimit:
            String(localized: "Your plan limit has been reached.")
        // ...
        }
    }
}
```

### 6. 自定义 Segment 和 Server-side Tools

你可以扩展 Transcript 支持自定义 segment 类型：

```swift
public struct AudioSegment: Transcript.CustomSegment {
    public var id: String
    public var content: URL
}

// 在 prompt 中使用
let recording = AudioSegment(id: UUID().uuidString,
                              content: URL(filePath: "/path/to/recording.m4a"))
let response = try await session.respond {
    "Where was Frank Lloyd Wright's original architecture school located?"
    recording
}
```

对于云端模型，可以实现 server-side tools（如网页搜索）：

```swift
public struct MyLanguageModel: LanguageModel {
    public struct ServerTool: Sendable {
        public static let webSearch: ServerTool = ...
    }
    public init(serverTools: [ServerTool] = []) { }
}
```

## 最佳实践

- **从高层能力声明开始**：`capabilities` 要诚实声明模型支持什么，不要虚报。App 开发者会根据这个值决定启用哪些功能
- **prewarm 做重量级初始化**：模型加载、权重解码、KV cache 分配都应该在 `prewarm` 中完成
- **流式输出要完整**：除了文本 token，还要发送 metadata 和 usage 信息，让上层 UI 可以显示模型来源和 token 消耗
- **错误处理要具体**：用 `LanguageModelError` 的标准错误类型，让 App 知道如何优雅降级（如 context size exceeded 时自动裁剪历史）
- **凭证管理要安全**：不要在初始化器里直接接收 String 类型的 API Key，用 Keychain 存储，云端服务结合 App Attest 做设备认证
- **支持自定义 segment**：如果你的模型有独特能力（如生成音频、图片），定义自定义 segment 类型让 App 可以充分利用
