## Highlight

> iPhone 17 系列换上了一块正方形超广角前置传感器，配合 iOS 27 的新 API，你的相机 App 可以在不重建 Capture Session 的情况下丝滑切换 5 种画幅比例，还能自动追踪人脸做智能构图。视频通话场景直接调用系统级 Center Stage，连防抖都帮你做好了。

---

## 核心内容

### 1. 这场演讲解决什么问题

以前用前置摄像头拍合照或视频，最怕的就是画幅不够。老款 iPhone 的前置传感器是 4:3 的矩形，横屏和竖屏切换时，要么画面被严重裁切，要么得重建 `AVCaptureSession` 导致预览黑屏卡顿。而且视野角不够大，人稍微动一下就出画了。

iPhone 17 系列（包括 iPhone Air 和 iPhone 17 Pro）直接换了硬件，上了一块 **95 度超广角的正方形图像传感器 (square image sensor)**。配合 iOS 27 新增的 API，第三方相机 App 和视频会议软件也能用上以前只有 FaceTime 才有的智能构图能力。

### 2. Dynamic Aspect Ratio — 不重建 Session 切换画幅

iOS 27 给 `AVCaptureDevice` 新增了 `dynamicAspectRatio` 属性。设置这个属性时，系统直接从正方形传感器里裁切你指定的比例，**不需要重建 capture session，也不会中断预览**。

```swift
import AVFoundation

let deviceDiscoverySession = AVCaptureDevice.DiscoverySession(
    deviceTypes: [.builtInUltraWideCamera],
    mediaType: .video,
    position: .front
)

guard let camera = deviceDiscoverySession.devices.first else {
    print("Failed to find the capture device")
    return
}

// 找一个支持 4:3 比例的格式
for format in camera.formats {
    if format.supportedDynamicAspectRatios.contains(.ratio4x3) {
        try! camera.lockForConfiguration()
        camera.activeFormat = format
        camera.unlockForConfiguration()
        break
    }
}

// 设置动态画幅比例
try! camera.lockForConfiguration()
let timestamp = try! await camera.setDynamicAspectRatio(.ratio4x3)
print("Applied dynamic aspect ratio at timestamp: \(timestamp)")
camera.unlockForConfiguration()
```

关键点：

- 需要 `.builtInUltraWideCamera` 设备类型，位置为 `.front`
- 只支持正方形格式，分辨率范围从 1280 到 4032
- 五种比例可选：`ratio3x4`、`ratio4x3`、`ratio9x16`、`ratio16x9`、`ratio1x1`
- 4032 分辨率只支持 3:4 和 4:3（最高照片分辨率）

### 3. Smart Framing Monitor — 自动追踪人脸构图

`AVCaptureSmartFramingMonitor` 是自动构图的核心。它基于人脸和视线检测，实时给出构图建议（长宽比 + 缩放因子），你的 App 只需要监听并应用。

```swift
// 找一个支持 smart framing 的格式
for format in camera.formats {
    if format.isSmartFramingSupported {
        try! camera.lockForConfiguration()
        camera.activeFormat = format
        camera.unlockForConfiguration()
        break
    }
}

// 配置 smart framing monitor
let monitor = camera.smartFramingMonitor!
try! camera.lockForConfiguration()
monitor.enabledFramings = monitor.supportedFramings
camera.unlockForConfiguration()

// 监听构图建议
observation = monitor.observe(\.recommendedFraming, options: [.new]) { monitor, change in
    if let framing = monitor.recommendedFraming {
        Task {
            try! camera.lockForConfiguration()
            try! await camera.setDynamicAspectRatio(framing.aspectRatio)
            camera.videoZoomFactor = CGFloat(framing.zoomFactor)
            camera.unlockForConfiguration()
        }
    }
}

// 启动监控
try! monitor.startMonitoring()

// 停止时清理
observation?.invalidate()
observation = nil
monitor.stopMonitoring()
```

关键点：

- `enabledFramings` 控制启用哪些构图模式，建议直接设为 `supportedFramings`
- `recommendedFraming` 包含 `aspectRatio` 和 `zoomFactor` 两个值
- 切换是异步的，用 `Task` 包裹避免阻塞主线程
- 记得在 `stopMonitoring()` 前 `invalidate()` KVO observation

### 4. Center Stage for Video Calls — 视频会议一键接入

对于视频通话场景，Apple 提供了更简单的接入方式。不需要自己处理 smart framing monitor，直接开启系统级的 Center Stage 即可。

```swift
// 找一个支持 Center Stage 的格式
for format in camera.formats {
    if format.isCenterStageSupported {
        try! camera.lockForConfiguration()
        camera.activeFormat = format
        camera.unlockForConfiguration()
        break
    }
}

// 开启 Center Stage
AVCaptureDevice.centerStageControlMode = .cooperative
AVCaptureDevice.isCenterStageEnabled = true
```

`.cooperative` 模式意味着你的 App 和系统共享 Center Stage 的控制权。系统会自动调整构图让人物居中，同时保留你通过 `videoZoomFactor` 做额外缩放的能力。

### 5. 传感器方向补偿

iPhone 17 的前置传感器物理安装方向变成了竖屏 (portrait)，而老款 iPhone 是横屏左 (landscape left)。`AVCapturePhotoOutput` 默认开启了 `cameraSensorOrientationCompensationEnabled`，会自动把照片转回横屏左并修改 EXIF，对 JPEG 和 HEIC 完全透明。

**但如果你拍的是 Bayer RAW 或 Apple ProRAW，系统不会自动补偿。** 处理 RAW 格式时，必须自己用 `AVCaptureRotationCoordinator` 去处理旋转。

## 最佳实践

- **已有项目迁移**：先检查你的代码是否硬编码了前置摄像头的旋转角度。如果有，替换为 `AVCaptureRotationCoordinator`。然后逐步引入 `dynamicAspectRatio`，把原来的手动裁切逻辑删掉。
- **新项目建议**：直接拥抱 `AVCaptureSmartFramingMonitor`。不要自己跑 Vision 框架做人脸检测然后算裁切框，不仅耗电，延迟也比系统底层的 Center Stage 高得多。
- **容易踩的坑**：Center Stage 和 Smart Framing 需要特定的格式支持。在设置 `activeFormat` 前务必检查 `isCenterStageSupported` 或 `isSmartFramingSupported`，否则 API 会静默失败。
