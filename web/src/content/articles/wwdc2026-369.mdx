## Highlight

> 以前做蓝牙配件测距只能捏着鼻子用 RSSI，隔着承重墙和面对面信号一样强。Bluetooth 6.3 的 Channel Sounding 通过多信道相位差直接测算物理距离，不需要加 UWB 芯片。只测距离用 Core Bluetooth，要距离加方向用 Nearby Interaction。

---

## 核心内容

### 1. 这场演讲解决什么问题

做蓝牙配件的开发者长期面临一个痛点：想知道配件离手机多远，只能用 RSSI (接收信号强度)。但 RSSI 受环境干扰极大，信号穿墙衰减和距离增加造成的衰减无法区分，用户体验很差。

加 UWB (超宽带) 芯片可以精准测距，但成本和功耗劝退一堆中小硬件厂。

Bluetooth 6.3 带来的 Channel Sounding (信道探测) 是中间路线：不需要改硬件 BOM 表加 UWB，用现有的蓝牙芯片就能拿到相对靠谱的测距数据。

### 2. Channel Sounding 原理

iPhone 作为 initiator，向配件 (reflector) 发送信号，配件反射回来。iPhone 测量信号在 2.4GHz 频段各信道上的相位变化率，以此估算物理距离。

这个过程叫一个 "procedure"，iOS 会重复执行多个 procedure 来持续更新距离。

### 3. 纯距离测量：Core Bluetooth

如果你只需要距离数字，Core Bluetooth API 就够了：

```swift
import CoreBluetooth

// 检查设备是否支持 Channel Sounding
func isChannelSoundingSupported() -> Bool {
    guard centralManager.state == .poweredOn else { return false }
    if #available(iOS 27.0, *) {
        return CBCentralManager.supportsFeatures(.channelSounding)
    }
    return false
}

// 启动 Channel Sounding session
func startChannelSounding(_ peripheral: CBPeripheral) {
    guard peripheral.isConnected else { return }
    if #available(iOS 27.0, *) {
        let config = CBChannelSoundingSessionConfiguration(role: .initiator)
        peripheral.startChannelSoundingSession(config)
    }
}

// 接收距离结果
func peripheral(_ peripheral: CBPeripheral,
                didReceive results: CBChannelSoundingProcedureResults?,
                error: Error?) {
    guard let results = results else { return }
    let distance = results.distance  // 单位：米
    // 用距离更新 UI...
}

// 结束 session
func cancelChannelSounding(_ peripheral: CBPeripheral) {
    guard peripheral.isConnected else { return }
    if #available(iOS 27.0, *) {
        peripheral.cancelChannelSoundingSession(config)
    }
}

func peripheral(_ peripheral: CBPeripheral,
                didCompleteChannelSoundingSession error: Error?) {
    // Session 结束，做清理...
}
```

关键点：

- 配件必须先通过 AccessorySetupKit 配对并连接
- 用 `CBCentralManager.supportsFeatures(.channelSounding)` 检查设备支持
- 距离结果通过 delegate 回调返回，单位是米
- 记得在不需要时调用 `cancelChannelSoundingSession` 节省电量

### 4. 距离 + 方向：Nearby Interaction

如果你还需要方向信息（比如"配件在你右前方 3 米"），用 Nearby Interaction 框架：

```swift
import CoreBluetooth
import NearbyInteraction

func startChannelSoundingThroughNearbyInteraction(_ peripheral: CBPeripheral) {
    if #available(iOS 27.0, *) {
        // 检查设备支持
        guard NISession.deviceCapabilities.supportsBluetoothChannelSounding else { return }

        // 创建配置
        let config = NINearbyAccessoryConfiguration(
            bluetoothChannelSoundingIdentifier: peripheral.identifier,
            previousChannelSoundingIdentifier: nil
        )

        // 启用相机辅助方向检测
        if NISession.deviceCapabilities.supportsCameraAssistance {
            config.isCameraAssistanceEnabled = true
        }

        // 创建并运行 session
        let session = NISession()
        session.delegate = self
        session.run(config)
    }
}
```

### 5. 配件端要求

配件硬件需要支持：

- Bluetooth 6.3 协议栈
- PCT (Phase-based Ranging，基于相位的测距) 功能
- Mode-0 和 Mode-2 支持
- T_FCS (音调间隔时序) 至少达到 100µs

如果你的配件还在用蓝牙 5.x 芯片，这套 API 对你无效，需要升级硬件。

## 最佳实践

- **已有项目迁移**：如果你的配件还在用老旧的蓝牙 5.x 芯片，这套 API 对你毫无意义。赶紧催促硬件团队选型支持 Bluetooth 6.3 且包含 PCT 功能的芯片。
- **新项目交互设计**：请彻底放弃"后台自动弹窗提示距离"的幻想。把测距功能包装成"精准查找"模式，引导用户在前台主动触发。同时实现优雅的降级策略：当设备不支持或用户拒绝相机权限时，自动从 Nearby Interaction 降级到 Core Bluetooth 仅显示距离数字，甚至最终降级回传统的 RSSI 信号强度条。
- **实战避坑**：Channel Sounding 的精度受多径效应影响。在反射面多的环境（如电梯、停车场）里，距离读数可能跳动。建议在 UI 上做平滑处理，或者告诉用户"请到开阔地带重新测量"。
