## ハイライト

> iOS 14 では、背景/コンテンツ構成と、コレクション ビューとテーブル ビュー セルの構成状態が導入されています。開発者は軽量の値型構成を使用してコンテンツ、背景、状態の外観を記述します。UIKit は新しい構成をビューに一度に適用します。

## 主な内容

iOS 13 では、テーブルのセルを記述する最も一般的な方法は、「UITableViewCell」に付属の「imageView」と「textLabel」を直接設定することです。このモデルは単純ですが、コンテンツ、スタイル、ビュー階層をセル クラスに結び付けます。コレクション ビューのセル、ヘッダー、またはフッターに切り替えると、コードをそのままでは再利用できません。

iOS 14 では、これを構成オブジェクトに分割します。コンテンツ構成は画像、テキスト、テキスト スタイルを記述し、背景構成は背景の塗りつぶし、ぼかし、ストローク、角丸を記述します。構成自体は、作成コストが低い軽量の Swift 値タイプにすぎず、実際のレンダリングは、それをセルに戻した瞬間に行われます。

これにより、重要な変更がもたらされます。同じ構成コードをテーブル ビューのセル、コレクション ビューのセル、コンテンツ構成をサポートするヘッダーとフッターに使用できます。開発者は、新しい設定を取得し、コンテンツを入力して、それを「contentConfiguration」に渡すだけで済み、UIKit が内部ビューの更新を担当します。

さらに厄介なのはステータスです。リストのセルは強調表示、選択、無効化、フォーカスされ、編集、スワイプ、展開、またはドラッグ アンド ドロップ状態になる可能性があります。 iOS 14 では、構成状態を使用して特性、システム状態、カスタム状態をまとめ、状態に基づいて構成が新しい外観を生成できるようにします。

この API の目的は、追加のカプセル化層を提供することではありません。これにより、構成が 1 つのエントリに集中化され、セルが状態を変更するたびに現在の状態から外観を再生成できるようになります。この講演で紹介されている実践方法は簡単です。古い構成を読んでからパッチを適用するのではなく、常に新しい構成から始めて、必要なプロパティを設定し、それらをすべて一度に適用します。

##詳細

### サブビューの直接設定からコンテンツ構成まで

([01:31](https://developer.apple.com/videos/play/wwdc2020/10027/?time=91)) 古い書き込みメソッドは、`UITableViewCell` の組み込みサブビューに直接触れます。```swift
cell.imageView?.image = UIImage(systemName: "star")
cell.textLabel?.text = "Hello WWDC!"
```キーポイント:

- `cell.imageView`はセルの画像を設定します。
- `cell.textLabel` はセルのメインテキストを設定します。
- このコードは `UITableViewCell` の組み込みビューに依存しています。

([01:59](https://developer.apple.com/videos/play/wwdc2020/10027/?time=119)) 新しい書き込みメソッドは、最初にセルにデフォルトのコンテンツ構成を要求し、コンテンツを設定してから、その構成をセルに返します。```swift
var content = cell.defaultContentConfiguration()

content.image = UIImage(systemName: "star")
content.text = "Hello WWDC!"

cell.contentConfiguration = content
```キーポイント:

- `defaultContentConfiguration()` は、現在のセルおよびテーブル ビュー スタイルのデフォルト スタイルを含む新しい設定を返します。
- `content.image` と `content.text` はローカル設定値を変更しますが、現時点ではセルは更新されていません。
- `cell.contentConfiguration = content` により、セルで画像とテキストをレンダリングできるようになります。
- この構成コードは、コンテンツ構成をサポートするヘッダーとフッターだけでなく、コレクション ビューのセルにも使用できます。

### 構成状態で外観を更新

([13:10](https://developer.apple.com/videos/play/wwdc2020/10027/?time=790)) バックグラウンド構成とコンテンツ構成の両方が、状態に基づいて新しい更新されたコピーを返すことができます。```swift
let updatedConfiguration = configuration.updated(for: state)
```キーポイント:

- `updated(for:)` は現在の設定状態を受け取ります。
- 戻り値は新しい構成であり、元の構成は変更されません。
- 特定のプロパティをすでに設定している場合、このプロパティは更新された構成でも保持されます。
- デフォルトでは、セルの構成状態が変更されると、システムは自動的に更新された構成を要求し、それを再適用します。

([16:33](https://developer.apple.com/videos/play/wwdc2020/10027/?time=993)) 状態の外観をカスタマイズする必要がある場合は、ロジックを「updateConfiguration(using:)」に集中させます。```swift
override func updateConfiguration(using state: UICellConfigurationState) {
    var content = self.defaultContentConfiguration().updated(for: state)

    content.image = self.item.icon
    content.text = self.item.title

    if state.isHighlighted || state.isSelected {
        content.imageProperties.tintColor = .white
        content.textProperties.color = .white
    }

    self.contentConfiguration = content
}
```キーポイント:

- `updateConfiguration(using:)` はセルが初めて表示される前に呼び出され、構成状態が変更される可能性があるときに再度呼び出されます。
- `defaultContentConfiguration().updated(for:state)` まず、現在の状態のシステムデフォルトスタイルを取得します。
- `content.image` と `content.text` には、現在のアイテムのコンテンツが入力されます。
- `state.isHighlighted || state.isSelected` は、強調表示された状態と選択された状態のみを処理します。
- `self.contentConfiguration = content` は、このラウンドのステータスに対応する設定をセルに適用します。
- 再構成を積極的に要求する必要がある場合は、`setNeedsUpdateConfiguration` を呼び出すことができます。

### デフォルトの背景とコンテンツのスタイルを選択します

([19:45](https://developer.apple.com/videos/play/wwdc2020/10027/?time=1185)) コレクション ビュー リスト セル、テーブル ビュー セル、テーブル ビュー ヘッダーおよびフッターは、コンテナー スタイルに従ってデフォルトの背景設定を自動的に取得します。コンテンツ構成は、セルから、またはタイプから直接取得できます。```swift
var background = UIBackgroundConfiguration.listSidebarCell()

var content = UIListContentConfiguration.sidebarCell()
```キーポイント:

- `UIBackgroundConfiguration.listSidebarCell()` は、サイドバー セルのデフォルトの背景設定を作成します。
- `UIListContentConfiguration.sidebarCell()` は、サイドバー セルのデフォルトのコンテンツ構成を作成します。
- グループ化、差し込みグループ化、プレーン、サイドバー プレーンおよびサイドバー これらのリストの外観の視覚的な違いは、デフォルトの背景とコンテンツの構成から派生します。
- コンテンツ構成は動的フォントをサポートします。アクセシビリティ テキスト サイズを最大にすると、テキストが画像の周りを回り込み、コンテンツのためのスペースが増えます。

([22:32](https://developer.apple.com/videos/play/wwdc2020/10027/?time=1352)) リスト コンテンツの設定は自己サイズ設定セルで機能します。レイアウトの余白とパディングを通じて固有の高さに影響を与え、デバイス サイズ、動的フォント、コンテンツのボリュームに基づいてセルの高さを自動的に調整できるようになります。

([23:44](https://developer.apple.com/videos/play/wwdc2020/10027/?time=1424)) 複数行のセルの画像幅が異なる場合、テキストの位置合わせが失われます。スピーチで説明された方法は、同じ予約されたレイアウト幅を画像に割り当て、画像を固定領域の中央に配置し、同じ領域を基準にしてテキストを入力するというものです。 SF シンボルは標準の予約済みレイアウト サイズを自動的に取得し、非シンボル画像は開発者がオンデマンドで要求する必要があります。

### 移行時に古い属性を混合しないでください

([24:52](https://developer.apple.com/videos/play/wwdc2020/10027/?time=1492)) 古いセルを移行するときは、同じ外観を持つ 2 セットの書き込みメソッドを使用しないでください。背景設定を設定すると、`backgroundColor` と `backgroundView` が `nil` にリセットされ、これらの古いプロパティを逆に設定すると、背景設定にも影響します。

コンテンツ設定は、組み込みコンテンツ サブビュー `imageView`、`textLabel`、および `detailTextLabel` も置き換えます。これらの古いコンテンツ プロパティは将来のリリースでは非推奨になるため、講演ではコンテンツ構成の採用を明示的に推奨しています。

### カスタム ビューでのシステム コンテンツのレンダリングを再利用する

([26:23](https://developer.apple.com/videos/play/wwdc2020/10027/?time=1583)) より複雑なセルが必要な場合は、「UIListContentView」を直接作成し、それを独自のカスタム ビューと組み合わせることができます。```swift
var content = UIListContentConfiguration.cell()

// Set up the content configuration as desired...

let contentView = UIListContentView(configuration: content)
```キーポイント:

- `UIListContentConfiguration.cell()` は、標準のセル コンテンツ構成を作成します。
- 注釈の場所は、画像、テキスト、スタイル、レイアウトのプロパティが設定される場所です。
- `UIListContentView(configuration:)` は、この設定を使用して、レンダリングを担当するビューを作成します。
- このビューはカスタム セルに配置することも、通常の `UIStackView` に個別に配置することもできます。

セルが完全にカスタマイズされている場合でも、システム構成は引き続き役立ちます。これは、デフォルトのフォント、色、余白のソースと考えることができます。より高度なシナリオでは、カスタム コンテンツ構成を作成し、それをレンダリングを担当するコンテンツ ビューと照合して、リスト コンテンツ構成のようにセルで使用できるようにすることができます。

## 重要なポイント

### 1. 自動ステータス適応機能を備えた iPad サイドバー

**手順**: プロジェクト、ラベル、またはフォルダーのサイドバーを作成し、選択した項目と強調表示された項目のテキストとアイコンの色を自動的に切り替えます。

**実行する価値がある理由**: このスピーチでは、サイドバーのリスト セルが強調表示、選択などの状態で異なるデフォルトの外観になることを示し、また、`updateConfiguration(using:)` で色をオーバーライドする方法についても説明しました。

**開始方法**: コレクション ビュー リストを使用してサイドバーの外観を作成します。セル内では、「defaultContentConfiguration().updated(for:state)」から開始して項目アイコンとタイトルを設定し、選択/強調表示されたときの色合いとテキストの色のみをオーバーライドします。

### 2. 動的フォント対応設定ページ

**何をすべきか**: アイコン、タイトル、および説明のコピーを含む各行が大きなフォント サイズで自動的に拡大される設定ページまたは環境設定ページを作成します。

**実行する価値がある理由**: コンテンツ構成では、セルの自動サイズ調整、レイアウト余白、パディング、およびアクセシビリティのテキスト サイズでの特別なレイアウト モードがサポートされています。

**開始方法**: `defaultContentConfiguration()` を使用して画像、テキスト、およびオプションのセカンダリ テキストを設定します。セルの高さを固定せず、構成上のマージンとパディングによって組版を制御し、コンテンツに応じて高さを変更します。

### 3. ビジネスステータスを含むメッセージリスト

**何をすべきか**: メッセージまたはトランザクションのリストを作成し、アーカイブ済み、フラグ付き、処理済みなどのビジネス状態がセルの外観に直接影響するようにします。

**実行する価値がある理由**: 構成状態はカスタム状態をサポートします。このスピーチでは、例としてメッセージング アプリのアーカイブ/フラグ設定と支払いアプリの処理を使用して、これらの状態がセル構成に参加できることを示しています。

**開始方法**: ビジネス ステータスを設定入力として使用し、`updateConfiguration(using:)` で状態を読み取り、最初に `updated(for:)` を使用してシステム状態の外観を取得し、次にビジネス アイコン、タイトル、色を設定します。

### 4. 標準コンテンツとカスタムバッジを含むセル

**やるべきこと**: リスト セルを作成し、左側でシステム イメージ/テキスト/セカンダリ テキスト レイアウトを引き続き使用し、右側に独自の進行状況、バッジ、またはステータス ラベルを追加します。

**実行する価値がある理由**: `UIListContentView` はカスタム ビューと並べて使用でき、動的フォント、デフォルト スタイル、システム コンテンツ構成のステータス更新を保持できます。

**開始方法**: `UIListContentConfiguration.cell()` を作成し、コンテンツを設定して `UIListContentView(configuration:)` を生成し、カスタム バッジ ビューとともにセルのビュー階層に配置します。
