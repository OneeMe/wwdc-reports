## ハイライト

> Apple は、iOS 17、macOS 14、および tvOS 17 の音声処理 API に 2 つの新機能を追加しました。それは、その他の音声ダッキングのきめ細かい制御と、ミュート話者検出です。これにより、VoIP アプリケーションは、バックグラウンドの音量をインテリジェントに調整し、FaceTime のようにユーザーにミュートを解除するよう促すことができます。

## 主な内容

### 背景音の回避: 万能の制御からきめ細かい制御まで

音声通話アプリケーションの開発者は皆、このシナリオに遭遇したことがあります。つまり、ユーザーが通話中に同時に音楽や他のオーディオを再生し、背景音が大きすぎて人間の声が聞こえなくなるということです。 Apple の音声処理 API は他の音声の音量を自動的に下げていましたが、ダッキングの量は固定されており、一部のアプリは多すぎると感じ、一部のアプリは十分ではないと感じていました。

([03:16](https://developer.apple.com/videos/play/wwdc2023/10235/?time=196)) 今年、Apple は新しい回避設定 API を AUVoiceIO と AVAudioEngine の両方に追加しました。開発者は、回避スタイル (高度な動的回避が有効かどうか) と回避強度 (4 レベル) の 2 つの次元を制御できるようになりました。

高度なダイナミック ダッキングは、FaceTime SharePlay と同様に機能します。どちらかの当事者が話すと、メディアの音量が自動的に下がります。誰も話さないと、音量が元に戻ります。これにより、通話とバックグラウンドオーディオが自然に共存できます。

### 無言話者の検出: 「マイクがオンになっていないことに気づくまでに長い間話してしまった」という問題に別れを告げましょう。

オンライン会議で最も恥ずかしい場面の 1 つは、ユーザーが熱心に話しているのに、マイクがミュートになっていることに気づくということです。

([07:58](https://developer.apple.com/videos/play/wwdc2023/10235/?time=478)) Apple は iOS 15 でサイレントスピーカー検出を導入し、今年それを macOS 14 と tvOS 17 に拡張しました。ユーザーが音声処理 API のミュート インターフェイスを通じてミュートされている限り、システムはユーザーがミュート中に話しているかどうかを検出し、アプリケーションに通知します。アプリは通知を受信した後、ユーザーにサウンドのミュートを解除するよう求めることができます。

Apple の音声処理 API にまだアクセスしていない macOS アプリケーションの場合、Apple は代替手段として Core Audio HAL レベルの音声アクティビティ検出属性も提供しています。

### その他のオーディオダッキング構成

Apple は、基礎となる AUVoiceIO (Audio Unit) と高レベルの AVAudioEngine という 2 つのアクセス方法を提供します。

#### AUVoiceIO メソッド

([05:50](https://developer.apple.com/videos/play/wwdc2023/10235/?time=350)) AUVoiceIO は C 構造体を使用してダッキング パラメーターを構成します。

```c
typedef CF_ENUM(UInt32, AUVoiceIOOtherAudioDuckingLevel) {
    kAUVoiceIOOtherAudioDuckingLevelDefault = 0,
    kAUVoiceIOOtherAudioDuckingLevelMin = 10,
    kAUVoiceIOOtherAudioDuckingLevelMid = 20,
    kAUVoiceIOOtherAudioDuckingLevelMax = 30
};

struct AUVoiceIOOtherAudioDuckingConfiguration {
    Boolean mEnableAdvancedDucking;
    AUVoiceIOOtherAudioDuckingLevel mDuckingLevel;
};
```

構成を作成して適用します。

```c
const AUVoiceIOOtherAudioDuckingConfiguration duckingConfig = {
    .mEnableAdvancedDucking = true,
    .mDuckingLevel = AUVoiceIOOtherAudioDuckingLevel::kAUVoiceIOOtherAudioDuckingLevelMin
};

OSStatus err = AudioUnitSetProperty(
    auVoiceIO,
    kAUVoiceIOProperty_OtherAudioDuckingConfiguration,
    kAudioUnitScope_Global,
    0,
    &duckingConfig,
    sizeof(duckingConfig)
);
```

キーポイント:
- `mEnableAdvancedDucking`のために`true`、システムは双方の音声アクティビティに基づいて回避量を動的に調整します。
-`mDuckingLevel`次の 4 つのレベルがあります。`default`(以前の動作と一致します)、`min`(最小の回避、最大の背景音)、`mid`、`max`(最大限の回避、最もクリアなボーカル)
- 2 つの制御次元は互いに独立しており、組み合わせて使用してほとんどのシナリオをカバーできます。

#### AVAudioEngine メソッド

([07:20](https://developer.apple.com/videos/play/wwdc2023/10235/?time=440)) AVAudioEngine は、対応する Swift API を提供します。

```swift
let engine = AVAudioEngine()
let inputNode = engine.inputNode

do {
    try inputNode.setVoiceProcessingEnabled(true)
} catch {
    print("Could not enable voice processing \(error)")
}

let duckingConfig = AVAudioVoiceProcessingOtherAudioDuckingConfiguration(
    enableAdvancedDucking: false,
    duckingLevel: .max
)

inputNode.voiceProcessingOtherAudioDuckingConfiguration = duckingConfig
```

キーポイント:
- まずは電話してください`setVoiceProcessingEnabled(true)`音声処理モードを有効にする
-`AVAudioVoiceProcessingOtherAudioDuckingConfiguration`は Swift 構造体であり、パラメーター名は C バージョンとは若干異なります。
- に直接割り当てる`inputNode.voiceProcessingOtherAudioDuckingConfiguration`効果が出ますよ

### 無音話者の検出

#### AUVoiceIO の実装

（[07:32](https://developer.apple.com/videos/play/wwdc2023/10235/?time=452)）

```c
AUVoiceIOMutedSpeechActivityEventListener listener = ^(AUVoiceIOMutedSpeechActivityEvent event) {
    if (event == kAUVoiceIOSpeechActivityHasStarted) {
        // 用户静音时开始说话，提示解除静音
    } else if (event == kAUVoiceIOSpeechActivityHasEnded) {
        // 用户停止说话
    }
};

OSStatus err = AudioUnitSetProperty(
    auVoiceIO,
    kAUVoiceIOProperty_MutedSpeechActivityEventListener,
    kAudioUnitScope_Global,
    0,
    &listener,
    sizeof(AUVoiceIOMutedSpeechActivityEventListener)
);

// 用户点击静音时
UInt32 muteUplinkOutput = 1;
AudioUnitSetProperty(
    auVoiceIO,
    kAUVoiceIOProperty_MuteOutput,
    kAudioUnitScope_Global,
    0,
    &muteUplinkOutput,
    sizeof(muteUplinkOutput)
);
```

キーポイント:
- リスナーは、音声アクティビティのステータスが変化した場合にのみトリガーされ、継続的に呼び出されることはありません。
- 必ず合格してください`kAUVoiceIOProperty_MuteOutput`システムが API を正しく検出できるように、API をミュートする必要があります。
- イベントには次の 2 種類のみがあります。`kAUVoiceIOSpeechActivityHasStarted`そして`kAUVoiceIOSpeechActivityHasEnded`

#### AVAudioEngine の実装

（[11:08](https://developer.apple.com/videos/play/wwdc2023/10235/?time=668)）

```swift
let listener = { (event: AVAudioVoiceProcessingSpeechActivityEvent) in
    if event == .started {
        // 用户静音时开始说话，提示解除静音
    } else if event == .ended {
        // 用户停止说话
    }
}

inputNode.setMutedSpeechActivityEventListener(listener)

// 用户点击静音时
inputNode.isVoiceProcessingInputMuted = true
```

キーポイント:
- `setMutedSpeechActivityEventListener`リスナーの登録
- ミュートが必要です`isVoiceProcessingInputMuted`プロパティ、他の方法では使用できません
- Swift の列挙値は`.started`そして`.ended`、C バージョンよりも簡潔です

### Core Audio HAL 音声アクティビティ検出 (macOS のみ)

([12:31](https://developer.apple.com/videos/play/wwdc2023/10235/?time=751)) Apple の音声処理 API に接続されていない macOS アプリケーションの場合は、HAL API を使用できます。

```c
// 启用输入设备的语音活动检测
const AudioObjectPropertyAddress kVoiceActivityDetectionEnable = {
    kAudioDevicePropertyVoiceActivityDetectionEnable,
    kAudioDevicePropertyScopeInput,
    kAudioObjectPropertyElementMain
};

UInt32 shouldEnable = 1;
AudioObjectSetPropertyData(deviceID, &kVoiceActivityDetectionEnable, 0, NULL, sizeof(UInt32), &shouldEnable);

// 注册状态监听器
const AudioObjectPropertyAddress kVoiceActivityDetectionState = {
    kAudioDevicePropertyVoiceActivityDetectionState,
    kAudioDevicePropertyScopeInput,
    kAudioObjectPropertyElementMain
};

AudioObjectAddPropertyListener(deviceID, &kVoiceActivityDetectionState, listener_callback, NULL);
```

リスナーの実装:

```c
OSStatus listener_callback(
    AudioObjectID inObjectID,
    UInt32 inNumberAddresses,
    const AudioObjectPropertyAddress* inAddresses,
    void* inClientData
) {
    UInt32 voiceDetected = 0;
    UInt32 propertySize = sizeof(UInt32);
    OSStatus status = AudioObjectGetPropertyData(
        inObjectID, &kVoiceActivityDetectionState, 0, NULL, &propertySize, &voiceDetected
    );

    if (status == kAudioHardwareNoError) {
        if (voiceDetected == 1) {
            // 检测到语音活动
        } else {
            // 未检测到语音活动
        }
    }
    return status;
}
```

キーポイント:
- エコーキャンセル後にマイク入力を検出し、音声通話シナリオに適しています
- 検出はアプリケーションのミュート状態とは関係ありません。アプリケーションはミュート状態に基づいて独自に判断する必要があります。
- HAL のプロセス ミュート API を使用することをお勧めします。これにより、メニュー バーの録音インジケーター ライトがオフになり、ユーザーのプライバシーが保護されます。

## 重要なポイント

1. **インテリジェントな音量調整機能を備えた通話アプリケーション**
   - **対処法**: 音声通話中のBGM/効果音の音量を自動的に調整し、話しているときは下げ、話していないときは元に戻します。
   - **実行する価値がある理由**: 以前は、開発者は独自のオーディオ分析とボリューム制御ロジックを作成する必要がありましたが、現在では`enableAdvancedDucking`1 行のコードで FaceTime レベルのスマート回避を実現できます
   - **開始方法**: AVAudioEngine で音声処理を有効にする、設定`voiceProcessingOtherAudioDuckingConfiguration`、通話以外の音声を別のノードにルーティングする

2. **「ミュートされています」というプロンプトを含む会議アプリケーションを作成します**
   - **何をすべきか**: ミュート時にユーザーが話しているかどうかを検出し、インターフェイスにプロンプトをポップアップ表示します。
   - **実行する価値がある理由**: これは FaceTime にすでに備わっている機能であり、ユーザーはこの対話に期待しています。使用`setMutedSpeechActivityEventListener`ほんの数行のコードで実現できます
   - **開始方法**: リスナーを登録した後、`.started`「あなたはミュートで話しています」というフローティング レイヤー プロンプトがイベントに表示され、ワンクリックでミュート解除ボタンが表示されます。

3. **ポッドキャスティング/ライブストリーミング用の音声トリガーツール**
   - **対処方法**: 音声アクティビティ検出を使用して、アンカーの発話が検出されたときに自動的にシーンを切り替えたり、字幕を表示したりするなど、音声トリガー機能を実装します。
   - **価値がある理由**: HAL API によって提供される音声アクティビティ検出は、エコー キャンセル後の純粋な音声に基づいており、単純な音量しきい値よりも正確です。
   - **開始方法**: macOS で使用します`kAudioDevicePropertyVoiceActivityDetectionEnable`独自のビジネス ロジックに基づいて、検出を有効にし、リスナーを登録し、アクションをトリガーします

4. **マルチプレイヤー ゲームのボイスチャットを行う**
   - **対処法**: ゲーム内ボイスチャット中、ゲームの効果音とチームメイトの声が共存でき、システムが音量をインテリジェントに調整します。
   - **価値がある理由**: tvOS 17 は音声処理 API を初めてサポートします。 Continuity Camera と組み合わせると、Apple TV 上のゲームでも高品質のボイスチャットが可能になります。
   - **開始方法**: tvOS で AUVoiceIO または AVAudioEngine の音声処理モードを有効にし、ゲームのシナリオに応じて選択します`min`(ゲームの雰囲気を維持) または`max`(指示が明確であることを確認してください) 回避レベル
