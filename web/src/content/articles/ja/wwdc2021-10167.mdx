## ハイライト

> DocC のドキュメント カタログは記事と拡張機能をサポートし、トピックを使用して API ナビゲーションを整理し、フレームワーク ドキュメントを自動生成されたリストからストーリーを含む構造化コンテンツに変換します。

## 主な内容

フレームワークには 50 のパブリック API があります。 DocC はデフォルトでアルファベット順になっており、ユーザーは長いリストを見てどこから始めればよいのかわかりません。これらの API を整理して、ユーザーに「まずこれを学習してから、あれを学習してください」と伝える方法が必要です。

DocC の記事と拡張ファイル メカニズムにより、この問題が解決されます。

＃＃詳細

### Documentation Catalog

（[03:59](https://developer.apple.com/videos/play/wwdc2021/10167/?time=239)）

ドキュメント カタログは、すべてのドキュメント ファイルが含まれる特別なディレクトリです。

```
SlothCreator.docc/
  SlothCreator.md          # 框架概述文章
  GettingStarted.md        # 入门教程文章
  Sloth.md                 # 类型扩展文件
  Resources/
    sloth.png              # 图片资源
```

作成方法：XcodeのSourcesディレクトリを右クリック→新規ファイル→ドキュメントカタログ。

（[04:55](https://developer.apple.com/videos/play/wwdc2021/10167/?time=295)）

**キーポイント:**
- `.docc`サフィックスディレクトリ
- Markdown 記事と拡張ファイルが含まれています
- Resources サブディレクトリには画像やその他のリソースが保存されます
- ソースコードと同じターゲットに配置します。

### トップレベルの記事

（[05:00](https://developer.apple.com/videos/play/wwdc2021/10167/?time=300)）

トップレベルの記事はユーザーが最初に目にするページであり、「このフレームワークは何をするものですか?」という質問に答える必要があります。

```markdown
# SlothCreator

Create and care for adorable virtual sloths.

## Overview

SlothCreator provides everything you need to research,
create, and care for sloths in your app.

![A cute sloth](sloth)

## Topics

### Essentials

- ``Sloth``
- ``Habitat``

### Creating Sloths

- ``SlothGenerator``
- ``Sloth/name``
```

（[05:00](https://developer.apple.com/videos/play/wwdc2021/10167/?time=300)）

**キーポイント:**
- タイトルはフレーム名です
- 最初の段落は 1 行の要約です
- 概要により詳細なコンテキストが提供されます
- トピック いくつかの組織関連のシンボル
- 写真用`![alt](filename)`文法

### トピックの構成

（[09:14](https://developer.apple.com/videos/play/wwdc2021/10167/?time=554)）

トピックでは、3 レベルの見出しを使用してシンボルを整理します。

```markdown
## Topics

### Essentials

- ``GettingStarted``
- ``Sloth``

### Research

- ``SlothGenerator``
- ``Sloth/name``

### Care

- ``Habitat``
- ``Habitat/comfortLevel``
```

（[10:00](https://developer.apple.com/videos/play/wwdc2021/10167/?time=600)）

**キーポイント:**
- `## Topics`サブタイトルです
- `### GroupName`これはグループ化を定義する第 3 レベルの見出しです。
- シンボルは二重バッククォートでリンクされています
- 記事はファイル名（拡張子なし）でリンクされています
- グループは、複雑さの低いものから高いものへと配置されます。

### 拡張ファイル

（[13:56](https://developer.apple.com/videos/play/wwdc2021/10167/?time=836)）

拡張ファイルを使用すると、ソース コードを変更せずにトピック組織をタイプに追加できます。

```markdown
# ``SlothCreator/Sloth``

## Topics

### Creating a Sloth

- ``init(name:color:power:)``
- ``init?(from:)``

### Inspecting a Sloth

- ``name``
- ``color``
- ``power``

### Caring for a Sloth

- ``sleep(in:for:)``
- ``eat(_:quantity:)``
```

（[15:00](https://developer.apple.com/videos/play/wwdc2021/10167/?time=900)）

**キーポイント:**
・ ファイル名は任意ですが、展開されたシンボルと同じ名前にすることを推奨します。
- タイトルには ` を使用します` `ModuleName/SymbolName` `` 形式
- コンテンツとソース コードにマージされたドキュメント コメント
- トピック構成をソースコードから分離するのに適しています

### 画像リソース

（[05:28](https://developer.apple.com/videos/play/wwdc2021/10167/?time=328)）

DocC はダーク モード画像と 2 倍の解像度をサポートします。

```
sloth.png          # 默认图片
sloth~dark.png     # Dark Mode 版本
sloth@2x.png       # 2x 分辨率
sloth~dark@2x.png  # Dark Mode + 2x
```

基本ファイル名のみが Markdown で記述されます。

```markdown
![A cute sloth](sloth)
```

（[06:02](https://developer.apple.com/videos/play/wwdc2021/10167/?time=362)）

**キーポイント:**
- 修飾子のないベースファイル名
- DocC は正しいバリアントを自動的に選択します
- 2倍の解像度を推奨
- ダークモードの写真`~dark`サフィックス

## 重要なポイント

1. **フレームワークのトップレベルの概要記事**を作成します。 「このフレームワークは何をするのですか?」という質問に答えるには、概要を説明します。エントリ API: ドキュメント カタログ + 最上位のマークダウン ファイル。

2. **トピックを使用して API をストーリーラインに編成します**。基本的なものから高度な機能まで機能別にグループ化されています。入口API：`## Topics` + `### GroupName`。

3. **拡張ファイルを使用してトピック組織を分離します**。ソース コードをシンプルにし、ドキュメント構造を別のファイルに維持します。エントリ API: 拡張ファイル + `` `ModuleName/SymbolName` `タイトル。

4. **ダーク モード互換の画像を提供します**。使用`~dark`ダーク モード バージョンという名前のサフィックス。入口API：`sloth~dark.png`。

5. **複合型のタスク記事を作成します**。 API をリストするのではなく、特定のタスクを完了するようにユーザーに教えます。入口 API: 独立した Markdown 記事。
