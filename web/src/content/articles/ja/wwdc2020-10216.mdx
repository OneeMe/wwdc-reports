## ハイライト

> ResearchKit 2020 アップデートでは、インフォームド・コンセントの署名、HealthKit の許可リクエスト、アンケートのレビュー、3D モデルの表示、カスタマイズされたアクティブ タスクが同じ研究タスク プロセスのセットに統合されているため、開発者はより少ない自作インターフェイスでより正確な研究データを収集できます。

## 主要内容

医学研究アプリの最初のハードルは、多くの場合、アルゴリズムだけではなくプロセスです。参加者は研究の目的を理解し、インフォームドコンセントを完了し、健康データを承認し、アンケートに答え、いくつかの積極的なタスクを実行する必要があります。各ステップでは、解釈、入力、検証、結果の保存が必要です。以前は、開発者は承認、署名、レビュー、マルチメディア インタラクションを接続するために、ResearchKit の外部にカスタム インターフェイスを追加する必要がよくありました。

このセッションで示された変更は、これらのブレークポイントを ResearchKit のタスク フローに復元することです。`ORKInstructionStep`より豊富な説明コンテンツを掲載できるため、`ORKWebViewStep`署名は同じ HTML 同意ページの下で収集でき、新しい HealthKit 許可ステップにより研究プロセスに健康データの承認が導入され、アンケートには「わからない」オプション、文字数プロンプト、クリア ボタン、レビュー ページが追加されます。 ([02:54](https://developer.apple.com/videos/play/wwdc2020/10216/?time=174))

後半では、アクティブなタスクの境界が拡張され続けます。リサーチアプリも利用可能`ORK3DModelStep`USDZ または BioDigital の 3D 人体モデルを表示して、体の部位や病変を視覚的に説明します。開発者も使用できます`ORKActiveStep`独自のフロント カメラ タスクの実装を開始し、ビデオ ファイルを収集し、再試行回数を記録して、結果を返します。`ORKTaskViewController`。（[12:24](https://developer.apple.com/videos/play/wwdc2020/10216/?time=744)）

ここでの ResearchKit は、研究プロセスの骨格として機能します。開発者は、何を調査するか、何をモデル化するか、結果をどのように処理するかを決定しますが、共通リンクごとに一連のインターフェイスを書き直す必要はありません。参加者は継続的なタスクを目の当たりにし、研究チームは構造化された結果を受け取りました。

## 詳細

### オンボーディング: 説明ステップと Web 表示ステップを使用して、参加のしきい値を下げます。

([03:24](https://developer.apple.com/videos/play/wwdc2020/10216/?time=204)) アプリのオンボーディング (参加プロセス) を調査するには、まず調査とは何かを明確に説明する必要があります。セッション用`ORKInstructionStep`タイトル、説明、画像を含むウェルカム ページを作成します。

```swift
let instructionStep = ORKInstructionStep(identifier: "InstructionStepIdentifier")
instructionStep.title = "Welcome!"
instructionStep.detailText = "Thank you for joining our study. Tap Next to learn more before signing up."
instructionStep.image =  UIImage(named: "health_blocks")!
```

キーポイント:

- `ORKInstructionStep`は、コンテンツを記述するために使用される ResearchKit のステップです。
-`identifier`このステップに安定したアイデンティティを与えると、その後の結果とプロセスはそれに依存します。
-`title`そして`detailText`現在のステップの目的を説明する責任があります。
-`image`研究の説明を単なる文章の段落以上のものにしましょう。研究テーマの写真や案内写真を入れるのに適しています。

([04:08](https://developer.apple.com/videos/play/wwdc2020/10216/?time=248)) 同じ命令ステップを追加することもできます`ORKBodyItem`。 SF Symbols のハート型アイコンを使用して、事前のインフォームド・コンセントの指示をスキャンしやすい項目に分割するデモンストレーションを行います。

```swift
let informedConsentInstructionStep = ORKInstructionStep(identifier: "ConsentStepIdentifier")
informedConsentInstructionStep.title = "Before You Join"
informedConsentInstructionStep.image = UIImage(named: "informed_consent")!

let heartBodyItem = ORKBodyItem(text: exampleText,
                                detailText: nil,
                                image: UIImage(systemName: "heart.fill"),
                                learnMoreItem: nil,
                                bodyItemStyle: .image)

informedConsentInstructionStep.bodyItems = [heartBodyItem]
```

キーポイント:

- `ORKBodyItem`説明コンテンツ、アイコン、スタイルの一部を再利用可能なプロジェクトにカプセル化します。
-`UIImage(systemName:)`ここで SF シンボルを直接使用できることに注意してください。
-`bodyItemStyle: .image`アイコンを画像として表示します。
-`bodyItems`これは、リスク、リターン、データ使用量を複数の命令に分割するのに適した配列です。

([05:04](https://developer.apple.com/videos/play/wwdc2020/10216/?time=304)) インフォームド・コンセントの署名も組み込まれています`ORKWebViewStep`。同意書の表示と署名の収集には、以前は 2 つのステップが必要でした。 HTML コンテンツの下に署名領域を表示するプロパティを設定できるようになりました。

```swift
let webViewStep = ORKWebViewStep(identifier: String(describing: Identifier.webViewStep), html: exampleHtml)
webViewStep.showSignatureAfterContent = true
```

キーポイント:

- `ORKWebViewStep`同意フォームまたはドキュメントを HTML 形式で表示する責任を負います。
-`html`パラメータは表示されるコンテンツに渡されます。
-`showSignatureAfterContent = true`コンテンツの後に署名ビューが表示されます。
- 参加者は文書を読んで 1 ページに署名するため、プロセスが短縮され、カスタム インターフェイスが 1 つ減ります。

([05:25](https://developer.apple.com/videos/play/wwdc2020/10216/?time=325)) HealthKit の承認もオンボーディングに含まれます。トランスクリプトでは、新しいリクエスト許可ステップについて明示的に言及しています: 開発者は書きたいコンテンツを渡します`HKSampleType`コレクションして読みたい`HKObjectType`コレクション、創作`ORKHealthKitPermissionType`、そしてそれを置きます`ORKHealthKitPermissionStep`。このようにして、医療データの認証を ResearchKit プロセスとは別に実装する必要はありません。

```text
HealthKit permission flow in ResearchKit
1. Create a set of HKSampleTypes for data the app wants write access to.
2. Create a set of HKObjectTypes for data the app wants read access to.
3. Create ORKHealthKitPermissionType with those two sets.
4. Create ORKHealthKitPermissionStep with the permission type array.
```

キーポイント:

- `HKSampleType`書き込み許可に対応しており、収集した健康サンプルを保存する研究アプリに適しています。
-`HKObjectType`読み取り権限に対応しており、既存の健康データを研究コンテキストとして読み込むのに適しています。
-`ORKHealthKitPermissionType`読み取りタイプと書き込みタイプを組み合わせます。
-`ORKHealthKitPermissionStep`システム認証リクエストを ResearchKit タスク フローに追加します。

### アンケート: 無効な回答を減らし、参加者が確認できるようにします

([07:43](https://developer.apple.com/videos/play/wwdc2020/10216/?time=463)) アンケートセクションを新たに追加`ORKSESAnswerFormat`。段階的なスケール表示に適しており、参加者は自分の状態に近い「最適な健康状態」と「悪い健康状態」を選択できます。

```swift
let sesAnswerFormat = ORKSESAnswerFormat(topRungText: "Optimal Health",
                                         bottomRungText: "Poor Health")

let sesFormItem = ORKFormItem(identifier: "sesIdentifier",
                                      text: exampleText,
                                      answerFormat: sesAnswerFormat)
```

キーポイント:

- `ORKSESAnswerFormat`ラダースケールの問題を担当します。
-`topRungText`そして`bottomRungText`スケールの両端のセマンティクスを定義します。
-`ORKFormItem`質問のテキストと回答の書式をフォームに結合します。
- これらの質問は、主観的な健康状態、生活の質、または自己評価スケールに適しています。

([08:47](https://developer.apple.com/videos/play/wwdc2020/10216/?time=527)) スケールの質問には、新しい「わからない」ボタンもあります。研究の現場では、参加者に不確実な質問への回答を強制すると、ノイズが発生する可能性があります。`shouldShowDontKnowButton`そして`customDontKnowButtonText`参加者に、答えられないことを明確にしてもらいます。

```swift
let scaleAnswerFormat = ORKScaleAnswerFormat(maximumValue: 10, minimumValue: 1, defaultValue: 11, step: 1)
scaleAnswerFormat.shouldShowDontKnowButton = true
scaleAnswerFormat.customDontKnowButtonText = "Prefer not to answer"

let scaleAnswerFormItem = ORKFormItem(identifier: "ScaleAnswerFormItemIdentifier",
                                      text: "What is your current pain level?",
                                      answerFormat: scaleAnswerFormat)
```

キーポイント:

- `ORKScaleAnswerFormat`痛みの強さのスケールを 1 から 10 まで定義します。
-`shouldShowDontKnowButton = true`「わからない」の項目を表示します。
-`customDontKnowButtonText`デフォルトのコピーは置き換えることができるため、プライバシーに配慮した問題に適しています。
-`ORKFormItem`この回答形式を特定の質問に結び付けます。

([09:47](https://developer.apple.com/videos/play/wwdc2020/10216/?time=587)) フリーテキスト入力も更新されました。セッションでは、最大文字数のプロンプトとクリア ボタンについて言及しているため、参加者はさらにどのくらいの内容を入力できるかを知り、すぐにクリアして書き直すことができます。

```swift
let textAnswerFormat = ORKAnswerFormat.textAnswerFormat()
textAnswerFormat.multipleLines = true
textAnswerFormat.maximumLength = 280;
textAnswerFormat.hideWordCountLabel = false
textAnswerFormat.hideClearButton = false
```

キーポイント:

- `textAnswerFormat()`テキスト回答形式を作成します。
-`multipleLines = true`長文の回答も可能です。
-`maximumLength = 280`入力長を制限します。
-`hideWordCountLabel = false`文字番号プロンプトを表示します。
-`hideClearButton = false`クリアボタンを表示します。

([11:00](https://developer.apple.com/videos/play/wwdc2020/10216/?time=660)) アンケートを送信する前に、`ORKReviewViewController`参加者がすべての質問と回答を確認し、編集を通じて回答を更新できるようにします。セッション氏は、これを「データの正確性の向上」という文脈で説明しています。つまり、人々は間違った情報を入力するでしょう、そしてシステムはそれをチェックする機会を与えるべきです。

```swift
let reviewVC = ORKReviewViewController(task: taskViewController.task,
                                       result: taskViewController.result,
                                       delegate: self)
reviewVC.reviewTitle = "Review your response"
reviewVC.text = "Please take a moment to review your responses below. If you need to change any answers just tap the edit button to update your response."
```

キーポイント:

- `taskViewController.task`オリジナルのタスク構造を提供します。
-`taskViewController.result`これまでに収集された回答を提供します。
-`delegate: self`結果の更新と未完了のセルの選択に関連するメソッドを実装する必要があります。
-`reviewTitle`そして`text`レビューページの目的を説明する責任があります。

### アクティブなタスク: リスニングタスクから 3D モデルまで

([11:48](https://developer.apple.com/videos/play/wwdc2020/10216/?time=708)) ResearchKit のヒアリング タスクの更新は、エクスペリエンスの詳細に偏っています。環境 SPL メーターには、バックグラウンド ノイズがしきい値内にあるかどうかを確認するための新しいアニメーションが追加されます。 dB HL トーン聴力測定ステップでは、ボタン、触覚フィードバック、進行状況表示が更新され、AirPods Pro キャリブレーション データのサポートが追加されます。ここには公式のコード スニペットはありません。核心は、リスニングテスト中の誤操作と不確実性を軽減することです。

```text
Hearing task updates
- Environment SPL meter shows a clearer threshold animation.
- dB HL tone audiometry step updates button UI and haptics.
- Progress indicator changes to a label.
- Calibration data supports AirPods Pro.
```

キーポイント:

- SPL メーターのアニメーションは、参加者がテスト環境が適格であるかどうかを判断するのに役立ちます。
- ボタンと触覚フィードバックにより、テスト中の運用コストが削減されます。
- テキストによる進行状況は、抽象的な進行状況バーよりも理解しやすいです。
- AirPods Pro キャリブレーション データにより、このタイプのハードウェアを関連するリスニング タスクに使用できるようになります。

([14:30](https://developer.apple.com/videos/play/wwdc2020/10216/?time=870)) 3D モデルは機能をさらに拡張します。リサーチキット新規`ORK3DModelStep`そして`ORKUSDZModelManager`。開発者は USDZ ファイルを Xcode プロジェクトに追加し、モデル マネージャーを作成して、それを表示のために 3D ステップに送信します。

```swift
let usdzModelManager = ORKUSDZModelManager(usdzFileName: "toy_drummer")
usdzModelManager.allowsSelection = false
usdzModelManager.highlightColor = .yellow
usdzModelManager.enableContinueAfterSelection = false
usdzModelManager.identifiersOfObjectsToHighlight = arrayOfIdentifiers

let threeDimensionalModelStep = ORK3DModelStep(identifier: drummerModelIdentifier,
                                               modelManager: usdzModelManager)
```

キーポイント:

- `ORKUSDZModelManager`プロジェクト内の USDZ モデルを読み取ります。
-`allowsSelection`ユーザーがモデルパーツを選択できるかどうかを制御します。
-`highlightColor`ハイライトカラーを設定します。
-`enableContinueAfterSelection`[続行] ボタンが選択動作に依存するかどうかを制御します。
-`identifiersOfObjectsToHighlight`モデル内の指定されたオブジェクトを事前にハイライト表示できます。
-`ORK3DModelStep`モデル マネージャーを ResearchKit タスク フローに接続します。

（[15:31](https://developer.apple.com/videos/play/wwdc2020/10216/?time=931)）`ORK3DModelManager`は、Apple がコミュニティに明示的に継承することを望んでいる抽象親クラスです。 BioDigital が提供するものを紹介するセッション`ORKBioDigitalModelManager`: モデルは Web 経由でロードされ、管理者または SDK で更新でき、ラベル、色、注釈を追加できます。デモンストレーションのシナリオには、ユーザーにマネキンの痛みのある部分を指摘してもらうことや、心臓モデルを使用して冠状動脈閉塞の位置を説明することが含まれます。

```text
BioDigital model manager workflow
1. Import ResearchKit and BioDigital's HumanKit.
2. Create an ORKBioDigitalModelManager instance.
3. Set inherited properties such as highlight color and identifiers to highlight.
4. Use BioDigital-specific APIs to hide objects, load a model ID, and annotate an object.
5. Create ORK3DModelStep with that manager.
```

キーポイント:

- `ORK3DModelManager`責任は、3D モデル エクスペリエンスを抽象化するために必要な共通の機能です。
-`ORKBioDigitalModelManager`これはコミュニティ拡張機能であり、Apple の組み込み USDZ マネージャーではありません。
- Web ローディング モデルの利点は、コンテンツの更新に必ずしもアプリの新しいバージョンのリリースを必要としないことです。
- ラベルと注釈は、医学教育、痛みの位置特定、および検査結果の医師の解釈に適しています。

### カスタムアクティブタスク: フロントカメラタスクの構造

([20:35](https://developer.apple.com/videos/play/wwdc2020/10216/?time=1235)) アクティブなタスクをカスタマイズするための基本パスは次のとおりです: アプリの作成`ORKTask`に一連の手順を渡します。`ORKTaskViewController`表示、完了後にデリゲート経由で取得`ORKTaskResult`。セッションの例としては、フロント カメラ タスクが挙げられます。このタスクでは、ユーザーはリアルタイムでプレビュー、録画の開始、録画の停止、ビデオの確認、再試行を行うことができます。

```text
ResearchKit task roundtrip
1. The app creates an ORKTask object.
2. ORKTaskViewController receives the task and presents each step.
3. Each active step collects its own result.
4. ORKTaskViewControllerDelegate returns ORKTaskResult to the app.
```

キーポイント:

- `ORKTask`手順をまとめたものです。
-`ORKTaskViewController`ステップの表示を担当し、アプリはそれを継承する必要はありません。
-`ORKTaskResult`各ステップの結果を要約します。
- デリゲートは、ResearchKit を終了してビジネス コードに戻ります。

([21:51](https://developer.apple.com/videos/play/wwdc2020/10216/?time=1311)) フロントカメラタスクを実装する際、スピーカーは`ORKFrontFacingCameraStep`、から継承`ORKActiveStep`に、最大録画時間、レビューを許可するかどうか、リトライを許可するかどうかの 3 つの設定項目を追加します。次に、このステップで独自のビュー コントローラー クラスを返します。

```text
ORKFrontFacingCameraStep design
- subclass ORKActiveStep
- add maximumDuration
- add allowsReview
- add allowsRetry
- override stepViewControllerClass
- return ORKFrontFacingCameraStepViewController
```

キーポイント:

- `ORKActiveStep`センサー、タイミング、音声およびビデオの記録などのアクティブな収集が必要なタスクに適しています。
- 構成アイテムは、タスクを組み立てるときにこのタスクの動作を決定しやすくするためにステップ上に配置されます。
-`stepViewControllerClass`データ モデルをプレゼンテーション ロジックに接続します。
- カスタムビューコントローラーの継承`ORKActiveStepViewController`。

([23:23](https://developer.apple.com/videos/play/wwdc2020/10216/?time=1403)) インターフェイス層はカスタマイズを使用します`UIView`。それは受け取ります`AVCaptureSession`ライブ プレビューを表示し、ボタン イベントをビュー コントローラーに返し、タイマーと録画後のオプションを提供します。ここで重要な点は、カメラ コードは引き続きアプリによって管理され、ResearchKit はアクティブなタスクの結果、プロセス、プレゼンテーション用のスロットを提供するということです。

```text
Front-facing camera content view responsibilities
- receive AVCaptureSession
- set up an AVCaptureVideoPreviewLayer
- pass view events back through a block
- start a timer with the maximum duration
- show review and retry options before submission
```

キーポイント:

- `AVCaptureSession`まだAVFoundationからのものです。
- コンテンツ ビューは、プレビュー、タイミング、およびインタラクション イベントのみを担当します。
- イベントはブロックを通じて返され、ビュー コントローラーが応答方法を決定します。
- レビューおよび再試行機能はステップ構成から提供され、インターフェイスには構成に従ってオプションが表示されます。

([24:46](https://developer.apple.com/videos/play/wwdc2020/10216/?time=1486)) 結果レイヤーの継承`ORKFileResult`。例では`ORKFrontFacingCameraStepResult`ビデオファイルのURLを記録し、追加します`retryCount`、ユーザーが削除して再入力した回数を記録するために使用されます。ビューコントローラーのオーバーライド`result`カスタム結果を現在の結果コレクションに追加するメソッド。

```text
Front-facing camera result
- subclass ORKFileResult
- store contentType
- store fileURL
- add retryCount
- append ORKFrontFacingCameraStepResult to the current results collection
```

キーポイント:

- ビデオは結果ファイルです。使用します`ORKFileResult`データ形式に近い。
-`fileURL`タスクの終了後にアプリに録音ファイルを見つけさせます。
-`retryCount`これは研究における貴重な行動データであり、タスクの難しさやユーザーの躊躇を反映している可能性があります。
- カバレッジ`result`メソッドは、カスタム取得データを ResearchKit に戻すための鍵となります。

## 重要ポイント

- **やるべきこと**: 慢性疾患研究アプリへの完全な参加プロセスを作成します。
  **実行する価値がある理由**:`ORKInstructionStep`、`ORKBodyItem`、`ORKWebViewStep`署名表示では、指示、同意書、署名をオーバーレイできます。
  **開始方法**: まず、指示ステップを使用して研究目的を書き留め、次に Web ビューステップを使用して HTML 同意フォームを表示し、`showSignatureAfterContent`開ける。

- **やるべきこと**: 研究登録プロセスに健康データの承認を組み込みます。
  **実行する価値がある理由**: 新しい HealthKit 権限ステップにより、承認のために ResearchKit を終了する必要がなくなり、必要なカスタム インターフェイスが少なくなります。
  **始め方**:書きたいことを整理する`HKSampleType`そして読まれること`HKObjectType`、作成する`ORKHealthKitPermissionType`、そしてそれを置きます`ORKHealthKitPermissionStep`。

- **対処法**: レビュー ページと症状アンケートに「わからない」オプションを追加します。
  **実行する価値がある理由**:`ORKDontKnow`ボタンは強制的な回答によって引き起こされるダーティなデータを削減し、`ORKReviewViewController`送信する前に参加者にエラーを修正してもらいます。
  **開始方法**: スケール回答形式をオンにします`shouldShowDontKnowButton`、アンケート完了後にタスクと結果で初期化されます。`ORKReviewViewController`。

- **やるべきこと**: 人体の部位の選択または病気の教育タスクを実行します。
  **実行する価値がある理由**:`ORK3DModelStep`そして`ORKUSDZModelManager`インタラクティブな 3D モデルを ResearchKit フローに配置する機能。痛みの場所、筋肉グループ、またはテスト結果の解釈に適しています。
  **開始方法**: USDZ モデルを準備し、強調表示する必要があるオブジェクト識別子を配列に収集し、`ORKUSDZModelManager`後で引き渡されました`ORK3DModelStep`。

- **やるべきこと**: ビデオ キャプチャ アクティブ タスクを構築します。
  **実行する価値がある理由**: セッションはフロント カメラ タスクの完全な構造を示し、ビデオ ファイルと再試行回数の両方を ResearchKit の結果として返すことができます。
  **開始方法**: 継承`ORKActiveStep`構成、継承の定義`ORKActiveStepViewController`管理`AVCaptureSession`、使用`ORKFileResult`録画ファイルの URL を保存します。
