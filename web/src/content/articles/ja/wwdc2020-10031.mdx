## ハイライト

> SwiftUI 2020 では、`LazyVStack`、`LazyHStack`、`LazyVGrid`、`LazyHGrid`、`List(children:)`、`OutlineGroup`、および `DisclosureGroup` が追加され、複合ビューを使用して長いリスト、グリッド レイアウト、階層データ、およびインスペクター コントロールを直接実装できるようになります。

---

## 主な内容

コーディはサンドイッチギャラリーについて話し始めました。最初の実装は非常に自然です。「HeroView」を「ForEach」に配置し、それを「VStack」のレイヤーで覆い、次に「ScrollView」を使用してスクロールを担当します。データが小さい場合は問題ありません。写真の数が増えると、ページを開いたときに最初にすべての写真を作成して測定する必要があり、最初の画面の応答が遅くなり、メモリも増加します。

SwiftUI 2020 の答えは遅延スタックです。外側のスクロール コンテナーが `LazyVStack` に置き換えられると、最初の画面には表示されるサンドイッチ カードのみがレンダリングされ、ユーザーが近くをスクロールした後に後続のコンテンツが作成されます。内部スコアリングの `HStack` と画像オーバーレイを遅延に変更する必要はありません。これは、`HeroView` が画面に表示されるときに、内部のコンテンツが同時に表示されるためです。

次に、同じギャラリーを iPad に移動しました。単一列の画像は大きな画面でスペースを無駄にするため、セッションでは `LazyVGrid` と `LazyHGrid` が導入されます。開発者は `GridItem` を使用して列または行のサイズを記述します。これには、3 つの列を固定するか、`.adaptive(minimum:)` を使用して列数を利用可能な幅に応じて変化させます。

後半では、macOS、iPadOS、iOS で動作するドキュメントベースのアプリである ShapeEdit に切り替えました。最初にキャンバス上にグラフィックのフラットなリストを表示するだけで済みます。 「グラフィックグループにはグラフィックグループを含めることができる」を追加すると、データは任意の深さのツリーになります。 `List(children:)` は子のキー パスに沿ってツリーを直接展開でき、`OutlineGroup` は同じ機能をカスタム リスト構造に組み込みます。

最後にインスペクターパネルがあります。塗りつぶし、影、テキスト、その他のコントロールをすべて広げると、混雑しすぎます。 「DisclosureGroup」を使用すると、コントロールの各グループがタイトル、展開された状態、およびコンテンツ領域を持つことができます。 「Label」とブール値バインディングを使用して、デフォルトの展開グループを設定することもできます。これにより、SwiftUI のレイアウトのストーリーが「ビューの配置」から「情報の漸進的な表示」に拡張されます。

##詳細

### 遅延スタック: スクロール コンテンツは表示されている場合にのみ作成されます

([03:27](https://developer.apple.com/videos/play/wwdc2020/10031/?time=207)) 通常の `VStack` はすべてのサンドイッチを列挙し、`ScrollView` が表示されると対応するビューを作成します。トランスクリプト内の質問は非常に具体的です。写真が多いほど、ページが応答するまでに時間がかかります。 Apple は、スクロール方向のコンテンツをオンデマンドでレンダリングできるようにするために、`LazyVStack` と `LazyHStack` を追加しました。```swift
// Fetch sandwiches from the sandwich store
let sandwiches: [Sandwich] = …

ScrollView {
    LazyVStack(spacing: 0) {
        ForEach(sandwiches) { sandwich in
            HeroView(sandwich: sandwich)
        }
    }
}
```キーポイント:

- `ScrollView` は引き続きスクロールを担当します。遅延スタック自体はスクロール機能を提供しません。
- `LazyVStack(spacing: 0)` は元の `VStack(spacing: 0)` を置き換えます。これはパフォーマンス変更のエントリ ポイントです。
- `ForEach(sandwiches)` はデータ駆動型の記述を維持し、各モデルは `HeroView` に対応します。
- セッションは明確に推奨しています: 疑わしい場合は最初に `VStack` または `HStack` を使用し、Instruments を使用してパフォーマンスのボトルネックを見つけてから、遅延スタックを使用します。

### レイジー グリッド: 大画面でのコンテンツ密度を増加します。

([05:48](https://developer.apple.com/videos/play/wwdc2020/10031/?time=348)) サンドイッチ ギャラリーを iPad に配置すると、単一列レイアウトにより画像が大きくなるだけで、画面上のコンテンツの量は増えません。 `LazyVGrid` と `LazyHGrid` は、同じバッチのデータを列または行に配置できるように、`GridItem` を使用してグリッド サイズを記述します。```swift
// Fetch sandwiches from the sandwich store
let sandwiches: [Sandwich] = …

// Define grid columns
var columns = [
    GridItem(.adaptive(minimum: 300), spacing: 0)
]

ScrollView {
    LazyVGrid(columns: columns, spacing: 0) {
        ForEach(sandwiches) { sandwich in
            HeroView(sandwich: sandwich)
        }
    }
}
```キーポイント:

- `GridItem(.adaptive(minimum: 300), spacing: 0)` では、各列の幅が少なくとも 300 ポイントである必要があります。
- `LazyVGrid(columns: columns, spacing: 0)` は列構成を読み取り、利用可能な限り同じ幅の列を生成します。
- `ForEach` と `HeroView` は変更されず、レイアウト コンテナーがリストからグリッドへの変更を引き継ぎます。
- トランスクリプトでは、「.adaptive」が横長の iPad とサイズ変更可能なウィンドウを備えた macOS に適していると具体的に述べています。

### 子のリスト: フラットなリストを階層リストに変換します。

([08:41](https://developer.apple.com/videos/play/wwdc2020/10031/?time=521)) ShapeEdit のサイドバーは、元々は単なるキャンバス グラフィックのリストでした。リストがツリー構造を表現する必要が生じた後も、グラフィックス グループには引き続きサブグラフィックスを含めることができます。 SwiftUI は、パラメーターを使用してリストにデータ ツリーのトラバース方法を指示し、子のキー パスを `List` に追加します。```swift
struct GraphicsList: View {
    var graphics: [Graphic]
    var body: some View {
        List(
            graphics,
            children: \.children
        ) { graphic in
            GraphicRow(graphic)
        }
        .listStyle(SidebarListStyle())
    }
}
```キーポイント:

- `graphics` はツリーのルート ノード配列です。
- `children: \.children` は、各 `Graphic` の子ノードがどこにあるかを `List` に伝えます。
- `GraphicRow(graphic)` は引き続き単一行表示のみを担当し、階層展開は `List` によって処理されます。
- `SidebarListStyle()` はサイドバーのスタイルをもたらします。トランスクリプトでは、iOS 14 の太字ヘッダーもこの方向でのリスト スタイルの改善から来ていると述べています。

### アウトライングループ: カスタム構造でのツリー トラバーサルの再利用

([09:52](https://developer.apple.com/videos/play/wwdc2020/10031/?time=592)) `List(children:)` は、リスト全体がツリーである状況に適しています。 ShapeEdit は各キャンバスに 1 つのセクションと、各セクション内のグラフィックス ツリーを必要とするため、代わりに `OutlineGroup` が使用されます。```swift
// Customizing your outlines

List {
    ForEach(canvases) { canvas in
        Section(header: Text(canvas.name)) {
            OutlineGroup(canvas.graphics, children: \.children)
            { graphic in
                GraphicRow(graphic)
            }
        }
    }
}
```キーポイント:

- 外側の `List` は引き続き、選択、スクロール、およびリストの操作を担当します。
- `ForEach(canvases)` は、キャンバスごとにパーティションを作成します。
- `Section(header: Text(canvas.name))` は、キャンバス名をセクションのタイトルに変換します。
- `OutlineGroup(canvas.graphics, Children: \.children)` は、各パーティション内のツリー グラフィック データを走査します。

### DisclosureGroup: 非ツリー情報の展開を制御します

([13:10](https://developer.apple.com/videos/play/wwdc2020/10031/?time=790)) インスペクターの塗りつぶし、シャドウ、およびテキストのコントロールはルール ツリー構造に属していませんが、これらも折りたたむ必要があります。 「DisclosureGroup」は展開インジケーター、ラベル、コンテンツを提供します。ブール値バインディングが渡された場合、デフォルトの展開を状態によって制御することもできます。```swift
// Progressive display of information
Form {
    DisclosureGroup(isExpanded: $areFillControlsShowing) {
       Toggle("Fill shape?", isOn: isFilled)
       ColorRow("Fill color", color: fillColor)
    } label: {
       Label("Fill", …)
    }
    …
}
```キーポイント:

- 「フォーム」は、設定とコントロールのセットをホストするのに適しています。セッションではmacOSの設定シーンにも利用できることについても触れられていました。
- `DisclosureGroup(isExpanded:)` は展開状態を `areFillControlsShowing` に渡します。
- `Toggle` と `ColorRow` は、折りたたまれたり展開されたりする実際のコントロールです。
- `Label("Fill", …)` はタイトルとアイコンを結合します。 SF シンボルのアイコンはトランスクリプトで使用されます。

## 重要なポイント

- **長いコンテンツ ギャラリー**: 写真、メニュー、または製品ギャラリーを作成するには、最初のバージョンでは `ScrollView` と `LazyVStack` を使用します。最初に、既存のセル ビューを保持し、外側の `VStack` のみを置き換え、次に Instruments を使用して最初の画面の応答とメモリをチェックします。

- **アダプティブ iPad グリッド**: 電話機上の 1 列のコンテンツを iPad または macOS ウィンドウに移動する場合は、`LazyVGrid` と `GridItem(.adaptive(minimum: 300))` を使用します。水平、垂直、ウィンドウの幅に合わせて複数のレイアウトを作成することを避けるために、最小の列幅から始めます。

- **ドキュメント サイドバー ツリー**: アプリにフォルダー、レイヤー、キャンバス オブジェクト、またはタスク グループがある場合、モデルに `children` を公開させ、`List(items,children: \.children)` を使用して展開可能なサイドバーを作成できます。単一行ビューはシンプルに保たれ、ツリーのトラバースは SwiftUI に任せられます。

- **パーティション化されたアウトライン エディタ**: データに複数のキャンバス、複数のプロジェクト、または複数のアカウントなどの複数のルート コレクションがある場合は、`List`、`ForEach`、`Section`、および `OutlineGroup` を組み合わせて使用​​します。このようにして、各パーティションに独自のタイトルが付けられ、各パーティション内でツリーを展開することができます。

- **コンパクトなインスペクター パネル**: あまり使用されないフォーム コントロールを「DisclosureGroup」に配置します。よく使用されるグループはデフォルトで `isExpanded` バインディングで展開され、他のグループは折りたたまれたままとなり、プロパティ パネル、設定ページ、およびエディターのサイドバーに適しています。
