## ハイライト

> VideoToolbox は、新しい低遅延 H.264 ハードウェア エンコード モードを追加します。これにより、フレームの再配置が不要になり、レート コントローラーがネットワークの変更に迅速に適応します。 720p@30fps は遅延を約 100ms 短縮でき、時間領域のスケーラビリティと長期参照フレームをサポートします。

## 主な内容

あなたはビデオ会議アプリケーションを開発します。ユーザーは、会話の遅れや頻繁な中断を報告しました。遅れはどこから来るのでしょうか？

ビデオ エンコーダは通常、(B フレームの圧縮効率を向上させるため) フレーム並べ替えバッファを内部に備えており、これにより 3 ～ 5 フレームの遅延が発生します。レート コントローラーは、ネットワークの変更に対する応答も遅くなります。これらを合計すると、エンドツーエンドの遅延が 200 ミリ秒を超える可能性があります。

VideoToolbox の新しい低遅延モードは、特にこの問題に対処します。

＃＃詳細

### 低遅延モードの仕組み

（[02:05](https://developer.apple.com/videos/play/wwdc2021/10158/?time=125)）

低遅延モードでは、次の 2 つのコア最適化が実行されます。

1. **フレームの再配置を排除**。 1 in 1 out エンコード モードを採用し、各フレームは入力後すぐにエンコードされ、後続のフレームを待たずに出力されます。
2. **高速コード レート適応**。レート コントローラーはネットワークの変化により速く応答し、輻輳による遅延を軽減します。

720p@30fps ビデオの場合、低遅延モードでは遅延を約 100 ミリ秒短縮できます。これはビデオ会議では重要です。

（[03:14](https://developer.apple.com/videos/play/wwdc2021/10158/?time=194)）

**キーポイント:**
- 低遅延モードでは常にハードウェア アクセラレーション エンコーディングが使用されます
- H.264 エンコードのみをサポート
- iOS と macOS の両方でサポートされています
- 圧縮効率はデフォルト モードよりわずかに劣りますが、レイテンシは大幅に低くなります

### 低遅延モードを有効にする

（[05:03](https://developer.apple.com/videos/play/wwdc2021/10158/?time=303)）

有効にする方法は非常に簡単で、圧縮セッションの作成時にフラグを設定するだけです。

```swift
var encoderSpecification: CFMutableDictionary = CFDictionaryCreateMutable(
    kCFAllocatorDefault,
    0,
    &kCFTypeDictionaryKeyCallBacks,
    &kCFTypeDictionaryValueCallBacks
)

// 启用低延迟码率控制
CFDictionarySetValue(
    encoderSpecification,
    kVTVideoEncoderSpecification_EnableLowLatencyRateControl,
    kCFBooleanTrue
)

// 创建 compression session
let session = VTCompressionSessionCreate(
    allocator: kCFAllocatorDefault,
    width: 1280,
    height: 720,
    codecType: kCMVideoCodecType_H264,
    encoderSpecification: encoderSpecification,
    imageBufferAttributes: nil,
    compressedDataAllocator: nil,
    outputCallback: outputHandler,
    refcon: &context,
    compressionSessionOut: &session
)

// 配置码率（和平时一样）
VTSessionSetProperty(
    session,
    key: kVTCompressionPropertyKey_AverageBitRate,
    value: 2000000 as CFNumber  // 2 Mbps
)
```

（[05:03](https://developer.apple.com/videos/play/wwdc2021/10158/?time=303)）

**キーポイント:**
- `kVTVideoEncoderSpecification_EnableLowLatencyRateControl`低遅延モードを有効にする
- その他の設定（ビットレート、解像度）は通常と同じです
- エンコーダはハードウェア アクセラレーションを自動的に使用します
- 出力コールバックでエンコードされたフレームを受信します

### 新しいプロファイルのサポート

（[06:10](https://developer.apple.com/videos/play/wwdc2021/10158/?time=370)）

2 つの新しいプロファイルが低遅延モードに追加されました。

- **Constrained Baseline Profile (CBP)**: 最高の互換性を備えた低コストのアプリケーションに使用されます。
- **Constrained High Profile (CHP)**: より高い圧縮率で、帯域幅が制限されたシナリオに適しています

```swift
// 使用 Constrained Baseline Profile
VTSessionSetProperty(
    session,
    key: kVTCompressionPropertyKey_ProfileLevel,
    value: kVTProfileLevel_H264_ConstrainedBaseline_AutoLevel
)

// 使用 Constrained High Profile
VTSessionSetProperty(
    session,
    key: kVTCompressionPropertyKey_ProfileLevel,
    value: kVTProfileLevel_H264_ConstrainedHigh_AutoLevel
)
```

（[07:35](https://developer.apple.com/videos/play/wwdc2021/10158/?time=455)）

**キーポイント:**
- CBP は互換性が最も高く、ほぼすべてのデコーダーでサポートされています
- CHP 圧縮がより効率的になります
- 相手のデコード能力に基づいてプロファイルを選択します
- `AutoLevel`エンコーダーにレベルを自動的に選択させます

### 時間領域のスケーラビリティ

（[07:54](https://developer.apple.com/videos/play/wwdc2021/10158/?time=474)）

複数の参加者によるビデオ会議では、各受信者の帯域幅が異なります。従来のアプローチは、受信機ごとに異なるコード ストリームをエンコードすることであり、非効率的です。

時間的スケーラビリティは単一のビットストリームのみをエンコードしますが、フレームを 2 つのレイヤーに分割します。

- **ベースレイヤー**: フレームレートの半分が含まれており、独立してデコードできます
- **エンハンスメント レイヤー**: 補足フレームとベース レイヤーがフル フレーム レートを提供します

```swift
// 设置 base layer 帧率比例
VTSessionSetProperty(
    session,
    key: kVTCompressionPropertyKey_BaseLayerFrameRateFraction,
    value: 0.5 as CFNumber  // 一半帧给 base layer
)

// 设置 base layer 码率比例
VTSessionSetProperty(
    session,
    key: kVTCompressionPropertyKey_BaseLayerBitRateFraction,
    value: 0.6 as CFNumber  // 60% 码率给 base layer
)
```

（[11:15](https://developer.apple.com/videos/play/wwdc2021/10158/?time=675)）

**キーポイント:**
- ベースレイヤーのフレームレートは入力の半分です
- 基本層のコード レートは、総コード レートの 60% ～ 80% を占めることが推奨されます。
- 低帯域幅の受信機はベースレイヤーのみを受信します
- 高帯域幅受信機はベース層と拡張層を受信します
- エンハンスメントレイヤーのフレーム損失は他のフレームに影響を与えません

### 最大フレーム量子化パラメータ

（[12:26](https://developer.apple.com/videos/play/wwdc2021/10158/?time=746)）

フレーム QP (量子化パラメータ) は、画質とビット レートを制御します。 QP が低いほど、品質は高くなり、ビット レートも高くなります。

低遅延モードでは、最大許容 QP を設定して、エンコーダーが複雑なシーンで品質を過度に低下させないようにすることができます。

```swift
VTSessionSetProperty(
    session,
    key: kVTCompressionPropertyKey_MaxAllowedFrameQP,
    value: 30 as CFNumber  // QP 上限为 30
)
```

（[14:22](https://developer.apple.com/videos/play/wwdc2021/10158/?time=862)）

**キーポイント:**
- QP範囲は1～51です
- エンコーダはキャップを設定した後、より高い QP を使用しません
- ビットレートの割り当てが不十分な場合、エンコーダーは品質を低下させる代わりにフレームをドロップします。
- 画面共有やクリアテキストが必要なその他のシナリオに適しています

### 長期基準フレーム (LTR)

（[14:45](https://developer.apple.com/videos/play/wwdc2021/10158/?time=885)）

ネットワーク パケットが失われた後、デコーダはリフレッシュ フレームを要求する必要があります。従来のアプローチは I フレーム (キー フレーム) を送信することですが、I フレームはサイズが大きいため、ネットワークが貧弱な場合には輻輳が悪化する可能性があります。

LTR は、リフレッシュに I フレームの代わりに小さい予測フレーム (LTR-P) を使用します。

```swift
// 启用 LTR
VTSessionSetProperty(
    session,
    key: kVTCompressionPropertyKey_EnableLTR,
    value: kCFBooleanTrue
)

// 编码器在输出中标记需要确认的 LTR 帧
// 应用层收到确认后，通过 AcknowledgedLTRTokens 告知编码器

// 请求刷新帧
VTSessionSetProperty(
    session,
    key: kVTCompressionPropertyKey_ForceLTRRefresh,
    value: kCFBooleanTrue
)
```

（[17:07](https://developer.apple.com/videos/play/wwdc2021/10158/?time=1027)）

**キーポイント:**
- LTR フレームは通常の P フレームよりわずかに大きいですが、I フレームよりははるかに小さいです
- アプリケーション層はフレーム確認と再試行ロジックを担当します
- 確認された LTR がない場合、エンコーダは I フレームにフォールバックします
- ネットワークが不安定なシナリオに適しています

## 重要なポイント

1. **ビデオ会議アプリケーションの低遅延エンコードを有効にします**。 1 行の構成により、遅延が約 100 ミリ秒短縮されます。入口API：`kVTVideoEncoderSpecification_EnableLowLatencyRateControl`。

2. **時間的なスケーラビリティを備えたマルチパーティ会議の最適化**。 1 つのコード ストリームが異なる帯域幅の受信機にサービスを提供するため、複数のコード ストリームをエンコードするよりも電力が節約されます。入口API：`kVTCompressionPropertyKey_BaseLayerFrameRateFraction`。

3. **画面共有の最大 QP を設定します**。複雑なシーンでテキストと UI がぼやけるのを防ぎます。入口API：`kVTCompressionPropertyKey_MaxAllowedFrameQP`。

4. **LTR を使用して脆弱なネットワーク回復機能を改善します**。パケット損失後、LTR-P フレームを使用してリフレッシュが行われ、I フレームよりも早く到着します。入口API：`kVTCompressionPropertyKey_EnableLTR`。

5. 相手のデコード機能に基づいて **プロファイルを選択**します。 CBP を使用してローエンド デバイスと通信し、CHP を使用してハイエンド デバイスと通信します。入口API：`kVTCompressionPropertyKey_ProfileLevel`。
