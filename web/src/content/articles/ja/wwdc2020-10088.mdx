## ハイライト

> Design for Intelligence シリーズの第 3 回講義として、Apple は、ショートカット、Siri 提案ウィジェット、検索、ロック画面、共有提案、カレンダー、マップなどのシステム入口に「ディスカバリー」を導入し、ホーム画面の外のユーザーがアプリの機能を見つけられるようにします。

## 主な内容

多くのアプリの問題は、機能が少ないことではなく、入り口が狭すぎることです。ユーザーはアプリ名を覚えて、ホーム画面のアイコンを開き、ナビゲーション階層に従って機能を見つける必要があります。関数が増えるほど、このパスはユーザーのメモリに依存するようになります。ユーザーが忙しければ忙しいほど、アプリが自分の達成に役立つことを積極的に覚えている可能性は低くなります。

JP Racerda は、このセッションでインテリジェンスをシステムとアプリ間のコラボレーションと定義しました。システムはユーザーの目標、習慣、好み、人間関係を理解し​​ます。アプリはその機能をシステムの入り口に接続します。このようにして、App は単なるモノリシック コンテナではなくなります。その機能は、検索、ロック画面、カレンダー、マップ、共有、またはウィジェット スタックに表示されます。

この講義は最初の 2 つの講義に続き、焦点は「なぜインテリジェント設計なのか」と「システムと連携する方法」から「ユーザーがこれらの機能をどのように発見するか」に移ります。逐語的な原稿の例は非常に具体的です。ショートカットはクリックまたは Siri によって実行できます。 Siri の提案ウィジェット、検索およびロック画面では、関連する提案を表示できます。 iOS 14 のスマート スタックは、適切なタイミングでウィジェットをスタックの最上部に配置します。 Siri Event Suggestion は、レストランの予約をカレンダーに取り込み、出発前にロック画面を通じてユーザーにリマインドすることができます。

Apple は評価基準も提供しています。インテリジェンスに取り組んだ後は、トラフィック、ユーティリティ、可視性が目標となります。逐語的な原稿では、ユーザーが初めてアプリの共有提案を使用した後、平均共有数が 2 倍になると述べています。一部の航空会社では、通知チェックインの 82% が Siri イベント提案のチェックイン アクションによるものでした。一部のサードパーティ アプリは、ロック画面、共有、検索、その他の入り口で 1 日平均 5 回表示されます。

＃＃詳細

### インテリジェンスはアプリ内からシステム入口まで拡張されます ([01:24](https://developer.apple.com/videos/play/wwdc2020/10088/?time=84))

講演者は最初に開発者の役割を説明しました。アプリはシステムと統合することでインテリジェンスに参加するため、システムはアプリを単一のコンテナーを超えた機能の集合として扱うことができます。ここで重要なのは、どのアプリの機能がホーム画面の外に表示できるかをシステムに知らせることです。ビジネス ロジックは依然としてアプリ自体の責任です。

```text
App capability
-> system integration
-> suggestion on behalf of the app
-> entry point beyond the Home Screen
```

キーポイント:

- アプリの機能は、ユーザーが本当に完了または取得したいアクションまたはコンテンツです。
- システム統合により、これらの機能が存在し、適切な入り口に表示できることをシステムに知らせます。
- リーチ責任をアプリ内ナビゲーションからシステム レベルまで拡張するためのアプリを代表した提案。
- ホーム画面を超えたエントリ ポイントが、このセッションの主な利点です。

### ショートカットにより、音声、検索、画面ロックにアクションが追加されます ([01:47](https://developer.apple.com/videos/play/wwdc2020/10088/?time=107))

ショートカットが最初の例です。これにより、ユーザーは 1 回タップするか Siri に尋ねることでアプリの操作を完了できます。ショートカット アプリは iOS に組み込まれており、単純なアクションと複数ステップのショートカットおよび自動化の両方を構成できます。アクションがショートカットに入ると、Siri の提案ウィジェット、検索、ロック画面にも表示される場合があります。

```text
Shortcut action
-> tap or Siri
-> Siri Suggestions widget / Search / Lock Screen
```

キーポイント:

- このセッションでは、ショートカットの実装コードについては詳しく説明しませんが、発見ポータルとしてのその価値を強調するだけです。
- 同じアプリ アクションがショートカットに入ると、ユーザーがアクティブに実行したり、関連シナリオでシステムによって提案されたりすることができます。
- ユーザーがすでに明確な目標を持っている場合、ショートカットの価値は、ホーム画面からアプリに入って移動する手順の数を減らすことです。

### ウィジェットとスマート スタックにより、適切なタイミングで情報が表示されます ([02:12](https://developer.apple.com/videos/play/wwdc2020/10088/?time=132))

iOS 14 に追加された新しいスマート スタックは、2 番目のエントリ ポイントです。逐語的なスクリプト内の天気ウィジェットの例は、アプリがウィジェットを提供する場合、スマート スタックが適切なタイミングでそれをスタックの一番上に配置できることを示しています。ここでの「発見」は、ユーザーがホーム画面を見たときに起こります。現時点で最も有用な情報が、見やすい位置に押し出されています。

```text
App vends a widget
-> Smart Stack evaluates timing
-> widget moves to the top of the stack
```

キーポイント:

- ウィジェットはタイムリーな情報を伝えるのに適しており、アプリのホームページの単なる縮小版であってはなりません。
- スマート スタックは時間相関を重視します。アプリは、クイック スキャンに最適な情報をウィジェットに配置する必要があります。
- この入り口は、「ユーザーが機能をクリックする場所」ではなく、「ユーザーがその時点で必要としているもの」に対応しています。

### 共有と Siri イベントの提案により、他のシステム シナリオにコンテンツが取り込まれます ([02:22](https://developer.apple.com/videos/play/wwdc2020/10088/?time=142))

共有の提案はコンテンツの配布を目的としています。デバイス上に写真、ビデオ、その他のコンテンツがある場合、システムはユーザーが最も重要な人物やグループにコンテンツを送信できるように支援します。次に、逐語的なスクリプトは Siri イベントの提案に進みます。レストランの予約はカレンダーに自動的に表示され、ロック画面では交通状況に基づいて出発をリマインドでき、マップではワンクリックで空港までのルートの提案が表示されます。

```text
reservation in the app
-> Calendar
-> Lock Screen leave-time notification
-> Maps direction suggestion
```

キーポイント:

- このタイプのエントリでは、アプリ内で確認ページを表示するだけでなく、アプリが構造化された情報をシステムに取り込む必要があります。
- カレンダー、ロック画面、マップは、ユーザーが同じことを達成するためにたどる継続的なパスをカバーします。
- このセッションでは機会とデザインの価値についてのみ話します。特定の実装については、引き続き Siri イベントの提案セッションを参照してください。

### インテリジェンスの評価は、トラフィック、ユーティリティ、可視性に依存します ([03:20](https://developer.apple.com/videos/play/wwdc2020/10088/?time=200))

講演者はまず指標セクションでプライバシーを強調した。Apple が製品を改善するためにデバイス分析を使用するには、ユーザーのオプトインが必要です。収集された情報は個人を直接特定するものではなく、ユーザーの明示的な同意がある場合にのみ Apple に送信できます。その後、セッションでは 3 つの数字を使用して、アプリに対するインテリジェンスの影響を説明します。

```text
Sharing Suggestion: first engagement -> average sharing volume doubles
Siri Event Suggestion check-in action: 82% of notification check-ins in some airline apps
System visibility: some third-party apps seen five times per day across system entry points
```

キーポイント:

- トラフィックは、エントリによってユーザーがアプリに戻るかどうか、またはアプリの能力を測定します。
- ユーティリティは、システムの提案がユーザーの操作の節約に本当に役立つかどうかを測定します。
- 可視性は、ロック画面、共有、検索などでアプリがユーザーに表示されるかどうかを測定します。
- 指標はプライバシーとユーザーの同意に基づいて構築される必要があります。

## 重要ポイント

### 1. システムエントリマッピングテーブルを作成します。

**やるべきこと**: アプリのコア機能をショートカット、検索、ロック画面、共有、カレンダー、マップ、ウィジェットにグループ化し、各機能が表示されるのに最適な場所にマークを付けます。

**実行する価値がある理由**: セッションの主な目的は、アプリの機能がホーム画面の外のエントリ ポイントに入ることができるようにすることです。最初にマッピングすることによってのみ、どの能力がシステムに推奨する価値があるかを判断できます。

**開始方法**: ユーザーの最も頻繁な 5 つの目標をリストし、各目標の開始時間、必要な情報、理想的な入り口を書き留めます。入り口が不明確な機能は、まずアプリ内に残しておくべきであり、システムの統合を急ぐ必要はありません。

### 2. 繰り返されるアクションをショートカット候補として設計する

**何をすべきか**: ユーザーによって頻繁に繰り返される対象を絞ったアクションを選択し、クリック、Siri、またはショートカットの自動化を通じてそれらをトリガーできるようにします。

**価値がある理由**: 逐語的なテキストには、ショートカットはタップまたは Siri 経由で実行でき、Siri の提案ウィジェット、検索、およびロック画面で提案が利用できると明確に記載されています。

**開始方法**: 再度注文する、記録を開始する、固定ワークフローを開くなど、複雑な閲覧を必要としないアクションから開始します。実装の詳細については、SiriKit、ショートカット、およびインテント関連のセッションを引き続き参照してください。

### 3. ウィジェットに「現時点で最も役立つ」情報を選択します

**何をすべきか**: アプリのホームページを小さなビューに圧縮するのではなく、ユーザーが現時点で最も必要としている小さな情報をウィジェットに表示させます。

**実行する価値がある理由**: iOS 14 のスマート スタックは、適切なタイミングでウィジェットをスタックの最上部に配置できます。情報がタイムリーかどうかは、表示する価値があるかどうかに直接影響します。

**開始方法**: ウィジェットに対する明確な質問を定義します。ユーザーが今一目で知る必要があることは何ですか?次に、時間、場所、またはスケジュールのシナリオに応じて、さまざまな状態の表示コンテンツを準備します。

### 4. 予約と旅程情報をシステムの操作に入力します

**やるべきこと**: アプリがレストランの予約、航空券、ホテル、イベント、または発券を処理する場合は、これらの確認を、カレンダー、ロック画面、マップに入力できる構造化イベントに設計します。

**実行する価値がある理由**: セッション内のレストランとフライトの例は、予約を完了した後、ユーザーが出発リマインダー、ルート計画、チェックインも体験できることを示していますが、これらはすべてアプリの外部で行われます。

**開始方法**: まず、イベント オブジェクトの基本フィールド (時刻、場所、確認ステータス、ユーザーの次のアクション) を整理します。特定の API およびマークアップ ソリューションは、さらなる実装のために Siri イベント提案セッションに組み込まれます。

### 5. システムへの侵入のみの効果を測定する

**何をすべきか**: システム入口用の独立したパフォーマンス ダッシュボードを作成し、入口の露出、トリガー、アプリへの復帰、完了したアクションとその後の保持を追跡します。

**実行する価値がある理由**: Apple は、共有量、通知チェックイン、毎日の可視性を使用してインテリジェンスの価値を説明し、このタイプの統合は結果で検証する必要があることを示しています。

**開始方法**: まず、各ポータルの主な指標を定義します。共有は共有ボリュームを確認し、イベント提案はチェックインまたは到着率を確認し、ウィジェットは開始率またはタスク完了率を確認します。すべての統計はユーザーの同意とプライバシーの境界に準拠する必要があります。
