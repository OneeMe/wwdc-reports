## ハイライト

> 次世代 CarPlay は 4 層 UI アーキテクチャ（Overlay、Remote、Local、Punch-through）と専用コンポジターにより、車両の全画面にコンテンツを提供し、iPhone と車載システムのシームレスな統合を実現します。

---

## 主要内容

CarPlay 登場以来、自動車は大きく変化しました——画面が大きく、数が増え、機能が豊富に。従来 CarPlay は iPhone の 1 本のビデオストリームを車載システムに出力するだけでした。次世代 CarPlay の目標は、計器類、センター、助手席画面など、ドライバー向け全画面にコンテンツを提供し、完全統合インターフェースを形成することです。

アーキテクチャ上最大の変化は単一ビデオストリームから複数ストリームへの拡張。次世代 CarPlay は車内各画面ごとに独立した iPhone ビデオストリームが必要です。数量増に見えますが、新たな技術課題をもたらします。ローカルレンダリングの車載 UI とリモートレンダリングの iPhone UI を視覚的に一体化するには？

Apple の解は UI を 4 層に分割すること。Overlay UI が最上位で、車両固有の警告灯（telltales）と重要インジケーターを含み、完全に車載システムがレンダリング。Remote UI は iPhone 提供のリッチコンテンツ層。地図、オーディオ、タイヤ空気圧、トリップ情報など。Local UI は車載ローカルレンダリングの運転関連メーター。低遅延、Wi-Fi 干渉耐性、高速起動が特徴。Punch-through UI は車両固有 UI（運転支援、外部カメラなど）を体験にシームレス埋め込み可能。

4 層は専用コンポジターが統合処理。iPhone ビデオストリーム、ローカルレンダリング UI、Punch-through UI を受け取り、OpenGL で統一出力フレームに合成し、システムコンポジターに渡して各画面に表示。最も重要な技術はフレームレベル同期——iPhone が UI sync チャネルで画面上 UI 要素の移動を精密に編成し、レンダリング源に関わらず 60fps で一貫性を維持。

## 詳細

次世代 CarPlay アーキテクチャは既存 CarPlay 基盤の上に構築されますが、大量の新能力を追加。ワイヤレス体験で、拡張 Siri、バッファメディア再生、HEVC ビデオストリーミングをサポート。最も重要なアーキテクチャ変化は UI のレンダリングと合成方式です。

### 4 層 UI アーキテクチャ

（[03:03](https://developer.apple.com/videos/play/wwdc2024/10111/?time=183)）UI は 4 層に分割。各層に特定用途:

**Overlay UI** が最上位。車両固有の警告灯（telltales）と重要インジケーター。新体験に合わせ再設計・再配置される場合もあるが、完全に車載システムがレンダリング。

**Remote UI** は iPhone 提供のリッチコンテンツ層。地図とオーディオ app がここで動作。タイヤ空気圧、トリップ情報なども含む。各画面に独立 iPhone ビデオストリームが必要。

**Local UI** は車載ローカルレンダリングの運転関連メーター。低遅延、高頻度応答。Wi-Fi 干渉の影響を受けず、起動が極めて高速。（[05:03](https://developer.apple.com/videos/play/wwdc2024/10111/?time=303)）Local UI は OpenGL レンダラーに基づき、iPhone から転送されたリソースバンドル（画像と動作スクリプト含む）と組み合わせ。リソースバンドルは車両固有。ペアリング時に転送、使用前に車両が真正性を検証。

**Punch-through UI** は車両固有機能（運転支援、外部カメラなど）を体験にシームレス統合。ピクセルは完全に車両がレンダリングするが、精密設計の遷移アニメーションで全体体験に融合。

### コンポジターアーキテクチャ

（[08:02](https://developer.apple.com/videos/play/wwdc2024/10111/?time=482)）3 層（Remote、Local、Punch-through）は専用コンポジターが処理。OpenGL で各画面に統一出力フレームを提供。Overlay UI はこの専用コンポジターをスキップし、直接車両コンポジターへ。

### フレームレベル同期

（[08:51](https://developer.apple.com/videos/play/wwdc2024/10111/?time=531)）滑らかなレイアウト遷移とアニメーションのため、フレームレベル同期を使用。各 iPhone ビデオフレームに表示タイムスタンプ付き。次世代 CarPlay は iPhone から各ディスプレイへの UI sync という専用低遅延チャネルを追加。動作スクリプトがこの情報を解釈し、Local UI、Punch-through UI、Remote UI をフレーム単位でマッチ。60fps 以上を達成。

### 車両状態プロトコル

（[11:03](https://developer.apple.com/videos/play/wwdc2024/10111/?time=663)）次世代 CarPlay は車両システムが常に最新状態情報を提供することに依存。情報のレンダリング位置に応じ複数インターフェース利用可。計器類に専用インターフェース、センター Local UI に類似インターフェース、Remote UI は拡張 Communication plug-in でサポート。この設計はプライバシーも保護——データは必要な場所でのみ使用され、多くの場合車外に出ない。

（[18:29](https://developer.apple.com/videos/play/wwdc2024/10111/?time=1109)）Apple は開発者向けに豊富な車両状態カテゴリを提供:

```text
Audio settings
Charging
Climate control
Closures
Drive state
Driver assistance
Electric engine
Fuel
High voltage battery
Internal combustion engine
Media
Notification history
Notifications
Now playing information
Paired devices
Request content
Seat
Tire
Trip computer
UI control
Units
Vehicle motion
Vehicle resources
```

**キーポイント:**
- これらのカテゴリは車両の主要状態情報をすべてカバー
- データは車両状態プロトコル経由で転送。UI は車両状態を直接反映
- 高頻度更新（速度計など）は継続的に精密値を提供する必要あり
- UI は演算を行わず、車両が送る値をそのまま表示

### カスタマイズと設定

（[21:55](https://developer.apple.com/videos/play/wwdc2024/10111/?time=1315)）自動車メーカーは Automaker App で iPhone 上にカスタム UI を実行し、iOS の全能力を活用可能。カスタム設定は Automaker Settings API で実現。ラベル、アイコン、機能、構造を完全カスタム。ProminenceInfo API で重要設定をトップレベルに引き上げ可能。設定のディープリンクでメーカー独自 iOS App に誘導。

（[25:08](https://developer.apple.com/videos/play/wwdc2024/10111/?time=1508)）カスタム通知も完全柔軟——ラベル、アイコン、ボタンすべてカスタマイズ可。開発者が表示内容、タイミング、削除タイミングを決定。ローカルまたはリモートレンダリングを選択。

## 重要ポイント

1. **レイヤー化アーキテクチャが複雑システムの鍵**。次世代 CarPlay は UI を 4 層に分割し、各層の責務が明確。Overlay は安全クリティカルで車載制御、Remote は iPhone のリッチコンテンツ、Local は低遅延ローカルレンダリング、Punch-through は車両特色。このレイヤー化で異なるレンダリング源がシームレス協調。

2. **フレームレベル同期がレンダリング源横断の滑らかなアニメーションを実現**。ピクセルが iPhone 由来でも車載由来でも、UI sync チャネルと presentation timestamp により全層を 60fps で同期。リアルタイム UI システムの重要参考。

3. **リソースバンドル検証が柔軟性とセキュリティのバランス**。OpenGL レンダラーと更新可能リソースバンドルの組み合わせで UI を時間経過とともに進化させ、検証機構で認可リソースのみ実行。メーカーが体験を継続改善しつつシステムセキュリティを維持。

4. **状態駆動 UI で表示とロジックを分離**。車両状態プロトコルが単一データソース。UI は状態の反映に過ぎない。この一方向データフローで UI はシンプルで予測可能——「UI simply shows what you provide」（[17:07](https://developer.apple.com/videos/play/wwdc2024/10111/?time=1027)）。

5. **プライバシー保護がアーキテクチャに組み込まれている**。データは必要な場所でのみ使用され、多くの場合車外に出ない。このプライバシー優先設計が基盤層——車両状態インターフェースの配布ロジックからデータ最小化原則が決まる。
