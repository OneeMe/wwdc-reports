## ハイライト

> Apple は App Store にアプリ内イベントを追加しました。これにより、開発者は App Store Connect でアプリ内イベントを作成、スケジュール、測定できるようになり、期間限定のチャレンジ、プレミア、イベントが製品ページ、検索結果、推奨事項、編集者のおすすめに直接表示されるようになります。

## 主要内容

アプリでアクティビティを作成しました。ゲームには週末のコンテストがあり、フィットネス アプリには 7 日間のチャレンジがあり、ビデオ アプリには映画のプレミア上映があります。問題は、ユーザーがアプリを表示する前にアプリを開かなければならないことです。

以前のアプローチは主にオフサイトのマーケティングとプッシュに依存していました。プッシュは、インストールされているユーザーのみに到達できます。ソーシャルメディアでは、ユーザーはApp Storeを離れて戻ってくる必要があります。アクティビティ自体はアプリ内で行われますが、検出ポータルはアプリの外部に分散されています。

Apple は WWDC21 でアプリ内イベントを紹介します。イベントは App Store のイベント カードになります。カードには、画像やビデオ、イベント名、簡単な説明、自動的に更新される時間リマインダーを表示できます。

このようにして、アクティビティは App Store 検出リンクに入ります。ユーザーが製品ページを閲覧したり、アプリを検索したり、ゲームやアプリのタブを開いたりすると、アクティビティが表示される場合があります。インストールしたユーザーは、「開く」をクリックしてアプリ内アクティビティに入ることができます。インストールしていないユーザーには、イベントの詳細ページが表示されます。

作成ポータルも App Store Connect に配置されます。開発者はアクティビティ情報、利用可能なエリア、開始時間と終了時間、リリース時間、ディープリンク（ディープリンク）、アクティビティの目的を入力します。イベントの審査が通過すると、スケジュールに従って自動的にリリースされます。

このセッションの焦点は、新しい運用チャネルです。アプリ内の期間限定コンテンツを App Store の表示、リマインダー、検索、推奨、分析システムに接続します。

## 詳細

### アクティビティ カード: アプリ内のアクティビティを App Store に追加します

([01:08](https://developer.apple.com/videos/play/wwdc2021/10171/?time=68)) アプリ内イベントは、イベント カードの形式で App Store に表示されます。カードは画像やビデオをサポートしており、アクティビティ名、簡単な説明、時間インジケーターを表示します。イベントが近づいて開始すると、時間インジケーターが自動的に更新されます。

このフィールドには「コード」タブのコード スニペットはありません。ここでは、コア フィールドを表すために App Store の表示構造が使用されています。

```text
In-App Event Card
- Media: image or video
- Event Name
- Short Description
- Time Indicator: updates before and after start
- Action for installed users: Open
```

キーポイント:

- `Media`これはカードの視覚的なコンテンツであり、写真またはビデオになります。
- `Event Name`は、App Store でユーザーに表示されるアクティビティの名前です。
- `Short Description`アクティビティの内容を短い文で説明します。
- `Time Indicator`App Store によって自動的に更新され、イベントが開始されようとしている、またはすでに開始されていることを示します。
- `Open`インストールされているユーザーの場合、クリックしてアプリに直接アクセスします。

([01:33](https://developer.apple.com/videos/play/wwdc2021/10171/?time=93)) アクティビティ カードは最初に製品ページに表示されます。アプリをダウンロードしたユーザーには、スクリーンショットの上にアクティビティが表示されます。アプリをダウンロードしていないユーザーには、スクリーンショットの下にアクティビティが表示されます。ユーザーがカードをクリックすると、イベントの詳細ページが表示されます。詳細ページには長い説明と大きなメディア アセットが含まれます。

```text
App Product Page
- Installed users: event cards above screenshots
- New users: event cards below screenshots
- Tap event card: Event Details Page
- Direct link: App Store URL + unique event ID
```

キーポイント:

- `Installed users`のアクティビティは、これらのユーザーがすぐに参加できるため、上位に位置しています。
- `New users`アクティビティは引き続き表示されるため、ダウンロードする理由になる可能性があります。
- `Event Details Page`イベントのより完全な説明を主催します。
- `unique event ID`外部マーケティング リンクとしてアプリの App Store URL に追加できます。

### Discovery Portal: 検索、推奨事項、編集者のおすすめ

([02:13](https://developer.apple.com/videos/play/wwdc2021/10171/?time=133)) 開発者はイベントの 2 週間前までウォームアップできます。ユーザーは、イベントの開始時に通知をリクエストできます。この通知は App Store から送信され、インストールされているユーザーをアプリ内アクティビティに導きます。インストールしていないユーザーは、イベント詳細ページに入ります。

```text
Before event starts
- Promote event up to 14 days early
- User requests notification
- App Store sends notification at event start
- Installed user: open app event
- New user: open event details page
```

キーポイント:

- `14 days`これは予熱の上限であり、アクティビティが表示スペースを無制限に占有することはできません。
- `notification`App Store によって送信されるため、開発者はこれを行うために独自のプッシュ システムを使用する必要はありません。
- `Installed user`通知を受け取った後、直接イベントに参加することができます。
- `New user`最初に詳細ページが表示され、ダウンロードするかどうかを決定します。

([02:35](https://developer.apple.com/videos/play/wwdc2021/10171/?time=155)) アプリ内イベントも検索結果に入力されます。ユーザーがアプリを検索するとき、すでにアプリをダウンロードしている場合は、アプリとともにアクティビティ カードが表示されます。ユーザーがイベントを直接検索すると、イベント カードが常にアプリの横に表示されます。

```text
App Store discovery
- Product page
- Search by app name
- Search by event name
- Games tab and Apps tab personalized recommendations
- Today, Games, Apps editorial curation
```

キーポイント:

- `Search by app name`既存のユーザーに対しては、アプリ内で何が起こっているかを理解できるようにしてください。
- `Search by event name`特にイベントを探しているユーザー向け。
- `personalized recommendations`[ゲーム] タブと [アプリ] タブに表示されます。
- `editorial curation`Apple 編集チームによって「Today」、「Games」、「Apps」タブでキュレーションされています。

### App Store Connect: イベントメタデータの作成

([03:28](https://developer.apple.com/videos/play/wwdc2021/10171/?time=208)) App Store Connect でアクティビティの作成が始まります。開発者はアプリを入力し、左側の「機能」の下にある「アプリ内イベント」を選択し、「アプリ内イベントの作成」をクリックします。最初のステップは、参照名を入力することです。これは App Store Connect 内でのみ表示され、長さは最大 64 文字です。

```text
App Store Connect
→ Select app
→ Features
→ In-App Events
→ Create In-App Event
→ Reference Name: up to 64 characters, internal only
```

キーポイント:

- `Select app`アクティビティを既存のアプリでハングさせる必要があることを示します。
- `Features`App Store Connectの左側にある機能入口です。
- `In-App Events`アクティビティを管理するページです。
- `Reference Name`これはチームの内部識別にのみ使用され、App Store には表示されません。

([04:14](https://developer.apple.com/videos/play/wwdc2021/10171/?time=254)) アクティビティ情報フィールドはすべてローカリゼーションをサポートしています。開発者は、イベント名、短い説明、カード メディア、詳細な説明、詳細ページのメディア、バッジを入力する必要があります。名前は最大 30 文字、短い説明は最大 50 文字、長い説明は最大 120 文字にすることができます。ビデオは最大 30 秒間ループします。

```text
Event Information
- Event Name: up to 30 characters
- Short Description: up to 50 characters
- Event Card Media: image or video
- Long Description: up to 120 characters
- Event Details Media: image or video
- Video limit: 30 seconds, loops
- Badge: event type
```

キーポイント:

- `Event Name`カードと詳細ページに表示されます。
- `Short Description`アクティビティを簡単に説明するためにアクティビティ カードで使用されます。
- `Long Description`詳細ページで使用すると、特典やその他の情報を追加できます。
- `Event Card Media`カードのビジュアルコンテンツを決定します。
- `Event Details Media`詳細ページで使用され、サイズが大きくなります。
- `Badge`ユーザーがアクティビティの性質をすぐに判断できるように、アクティビティのタイプを示します。

### 利用可能な地域とスケジュール: 表示時間を制御

([05:57](https://developer.apple.com/videos/play/wwdc2021/10171/?time=357)) アプリ内イベントは、アプリやアプリ内購入と同様、国または地域ごとに利用可能かどうかを設定する必要があります。イベントは、親アプリがすでに利用可能な国または地域でのみ公開できます。

```text
Availability
- Scope: Country or Region
- Constraint: event availability must be inside parent app availability
```

キーポイント:

- `Country or Region`アクティビティの可用性の粒度です。
- `parent app availability`アプリが利用できない地域にはアクティビティを公開できないという厳しい制約があります。

([06:20](https://developer.apple.com/videos/play/wwdc2021/10171/?time=380)) スケジュールには、開始日 (アプリ内でアクティビティが開始される)、終了日 (アプリ内でアクティビティが終了する)、公開日 (アクティビティが App Store に初めて表示される) の 3 つの時間が含まれます。キャンペーンの最小期間は 15 分、最大期間は 31 日間です。開始日は開始日の 14 日前まで指定できます。

```text
Schedule
- Event Start: when the event begins inside the app
- Event End: when the event ends inside the app
- Publish Date: when the event first appears on the App Store
- Duration: 15 minutes to 31 days
- Promotion window: up to 14 days before start
```

キーポイント:

- `Event Start`アプリ内で実際のアクティビティの開始時間を調整します。
- `Event End`アプリ内で実際のアクティビティの終了時間を調整します。
- `Publish Date`App Store がアクティビティの表示を開始するタイミングを制御します。
- `Duration`明確な上限と下限があり、キャンペーンを 15 分未満にしたり、31 日を超えたりすることはできません。
- `Promotion window`開発者は事前にウォームアップを行いますが、14 日前までに準備してください。

([07:09](https://developer.apple.com/videos/play/wwdc2021/10171/?time=429)) イベント終了後は、閲覧や検索で見つけることができなくなります。イベントの詳細ページには、App Store の URL から 30 日間アクセスできます。イベントは 30 日後にアーカイブされました。この 30 日間の期間は自動的に発生し、構成することはできません。開発者は、可用性を変更することで事前にアーカイブできます。

```text
After event ends
- Browsing and search discovery: stops
- Event details page URL: remains accessible for 30 days
- Archive: automatic after 30 days
- Early archive: edit availability in App Store Connect
```

キーポイント:

- `Browsing and search discovery`イベント終了次第終了となります。
- `Event details page URL`この情報は 30 日間保持されるため、短期間でも外部マーケティング リンクを開くことができます。
- `Archive`システムによって自動的に実行されます。
- `Early archive`可用性の変更は、App Store Connect を通じて行われます。

([07:47](https://developer.apple.com/videos/play/wwdc2021/10171/?time=467)) 開発者は、国または地域ごとにスケジュールをカスタマイズすることもできます。カスタム日付はデフォルトの日付から 48 時間以内である必要があります。これは、ヨーロッパの開始時刻と終了時刻がデフォルト時刻に対して移動される場合など、タイムゾーンの違いを処理するのに適しています。

```text
Customize Dates and Times
→ Select Countries or Regions
→ Choose custom start, end, or publish dates
→ Custom dates must be within 48 hours of defaults
→ Done
```

キーポイント:

- `Customize Dates and Times`はオプションの入り口です。
- `Select Countries or Regions`どの地域でカスタム時間を使用するかを決定します。
- `custom start, end, or publish dates`現地時間に合わせるために使用されます。
- `48 hours`これは、デフォルト時間に対するカスタム時間の制限です。

### ディープリンク、活動の目的と優先順位

([08:39](https://developer.apple.com/videos/play/wwdc2021/10171/?time=519)) イベントディープリンクは追加情報に提供する必要があります。ユニバーサル リンクまたはアプリ内の特定の場所をターゲットとするカスタム URL を使用できます。 Apple は、URL 短縮ツールやリダイレクトを追加するサービスを使用しないことをお勧めします。

```text
Event Deep Link
- Type: universal link or custom URL
- Target: specific place in the app
- Avoid: URL shorteners
- Avoid: unnecessary redirects
```

キーポイント:

- `universal link`Web リンクをアプリ内のページに関連付けることができます。
- `custom URL`カスタム スキームを使用してアプリを開くことができます。
- `specific place in the app`イベントのランディングページです。ユーザーは単にアプリのホームページにアクセスするだけではいけません。
- `URL shorteners`そして`unnecessary redirects`開封時のエクスペリエンスに影響を与える可能性があるため、避けてください。

([09:04](https://developer.apple.com/videos/play/wwdc2021/10171/?time=544)) イベントの目的は、このイベントが主にどのユーザーにサービスを提供するかを App Store に通知します。つまり、新しいユーザーの引き付け、アクティブなユーザーへの通知、失われたユーザーの呼び戻し、またはこれらのグループの同時ターゲットを指定します。この選択は、パーソナライズされた推奨事項に参加します。 App Store はアプリの使用状況情報を使用し、このデータをデバイス上で処理してデータ収集を削減し、プライバシーを向上します。

```text
Event Purpose
- Attract new users
- Keep active users informed
- Bring lapsed users back
- All purposes: default selection
- Used for personalized recommendations
- App usage information: processed on device
```

キーポイント:

- `Attract new users`ダウンロードの理由としてアクティビティを使用するのに適しています。
- `Keep active users informed`すでによく使うアプリを利用しているユーザーへの通知に適しています。
- `Bring lapsed users back`しばらくアプリを開いていないユーザーを呼び戻すのに適しています。
- `All purposes`はデフォルト値であり、ほとんどのアクティビティに適しています。
- `processed on device`これは、App Store のパーソナライズされた推奨事項におけるプライバシーの処理方法です。

([09:45](https://developer.apple.com/videos/play/wwdc2021/10171/?time=585)) 優先レベルは、製品ページのアクティビティの順序に影響します。優先度の高いアクティビティは、通常のアクティビティの前に並べ替えられます。同じグループ内では、開始時間によって並べ替えられます。開発者は、アクティビティにアプリ内購入またはサブスクリプションが必要かどうかを示す必要もあります。この情報はカードと詳細ページに表示され、レビュー体験にも影響します。

```text
Product page ordering
1. High-priority events
2. Normal-priority events
3. Start time within each priority group

Monetization disclosure
- Requires In-App Purchase: yes/no
- Requires Subscription: yes/no
```

キーポイント:

- `High-priority events`最も重要なアクティビティに適したものとして、最初に表示されます。
- `Normal-priority events`定期的にご紹介させていただきます。
- `Start time`同じ優先度内のソートを担当します。
- `Requires In-App Purchase`そして`Requires Subscription`ユーザーには、App Store での支払い要件の入力が求められます。

### 監査、ステータスのライフサイクル、および数量制限

([10:34](https://developer.apple.com/videos/play/wwdc2021/10171/?time=634)) 保存後、アクティビティはドラフト状態になります。イベントは投稿する前にレビューする必要があります。開発者は必要なメタデータを入力した後、レビューのためにアクティビティを送信できます。このプロセスでは、アプリの新しいバージョンを作成したり、新しいバイナリ (バイナリ パッケージ) をアップロードしたりする必要はありません。

```text
Submission
- Save event
- State: Draft
- Add for Review after required metadata is complete
- No new app version required
- No new binary required
```

キーポイント:

- `Save event`現在の設定が保存されます。
- `Draft`アクティビティがまだレビューのために送信されていないことを示します。
- `Add for Review`レビューに記入するという行為です。
- `No new app version required`運用活動にかかるリリースコストの削減。
- `No new binary required`これは、App Store Connect メタデータのみを変更できることを意味します。

([11:04](https://developer.apple.com/videos/play/wwdc2021/10171/?time=664)) アクティビティはレビューに合格すると、承認済みステータスになります。今後公開されるアクティビティには、「公開設定」としてマークが付けられます。すでに公開予定のアクティビティは、「公開済み」としてマークされます。過去を入力すると、詳細ページへのリンクは 30 日間アクセスし続けます。 「アーカイブ済み」に入ると、リンクにアクセスできなくなります。

```text
In-App Event lifecycle
Draft
→ Review
→ Approved
→ Set to Publish
→ Published
→ Past
→ Archived
```

キーポイント:

- `Draft`ここまでが編集段階です。
- `Review`App Store の審査段階です。
- `Approved`レビューが承認されたことを示します。
- `Set to Publish`将来の公開日を待っていることを示します。
- `Published`App Storeに表示されていることを示します。
- `Past`イベントは終了しましたが、詳細ページへのリンクは 30 日間アクセスできることを示します。
- `Archived`アクティブなアーカイブとリンクが無効であることを示します。

([11:57](https://developer.apple.com/videos/play/wwdc2021/10171/?time=717)) 各アプリは最大 10 個のアクティビティを承認済みステータスにすることができ、最大 5 つのアクティビティを同時に App Store に公開できます。アクティビティのスケジュールがこれら 2 つの制限を超える場合、開発者はレビューのためにアクティビティを送信できません。

```text
Limits per app
- Approved events: up to 10
- Published events at the same time: up to 5
- Review submission blocked if schedule exceeds limits
```

キーポイント:

- `Approved events`承認済み、リリース待ち、またはリリース中のアクティビティが含まれます。
- `Published events at the same time`App Store に同時に表示されるアクティビティの数を制御します。
- `Review submission blocked`これは、スケジュールが制限を超えると発生します。

### アプリ分析と App Store Connect API

([12:13](https://developer.apple.com/videos/play/wwdc2021/10171/?time=733)) イベントが公開された後、開発者は App Analytics でパフォーマンスを測定できます。アクティビティ ページは、App Analytics の対応するアクティビティ データに直接リンクしています。利用可能な指標には、インプレッション数、ユーザーがアプリまたは詳細ページを開いた回数、アクティビティによるダウンロードと再ダウンロード、通知を購読したユーザーの数が含まれます。

```text
App Analytics for In-App Events
- Impressions
- Where users saw the event: product page, search, other locations
- App opens
- Event details page opens
- Downloads and redownloads from the event
- Notification opt-ins
```

キーポイント:

- `Impressions`App Store でアクティビティが確認された回数を示します。

## 重要ポイント

1. **やるべきこと**: モバイル ゲーム用の毎週の競争イベント カードを作成します。
**実行する価値がある理由**: イベントは最大 14 日前から App Store に表示され、ユーザーは予約をして通知を受け取り始めることができます。
**開始方法**: App Store Connect → 機能 → アプリ内イベントでイベントを作成し、コンテスト名、簡単な説明、30 秒以内のビデオ、イベントのディープリンクを入力します。

2. **やるべきこと**: フィットネス アプリの地域チャレンジを作成します。
**実行する価値がある理由**: さまざまな国や地域で、デフォルト時間の 48 時間以内にカスタム スケジュールを設定できます。これは、現地時間で開始するのに適しています。
**開始方法**: まずデフォルトの開始日、終了日、公開日を設定し、次に日付と時刻のカスタマイズを使用してターゲット領域の時間を調整します。

3. **やるべきこと**: ビデオ アプリに新しい映画のプレミア エントランスを作成します。
**実行する価値がある理由**: イベントの詳細ページでは長い説明と大きなメディア リソースを使用でき、インストールしていないユーザーも App Store でプレミア コンテンツを確認できます。
**開始方法**: プレミア イベント用のカード メディアと詳細ページ メディアを準備し、イベント ディープ リンクをアプリ内の再生または予約ページにポイントします。

4. **やるべきこと**: サブスクリプション アプリの期間限定メンバー ライブ ブロードキャストを作成します。
**実行する価値がある理由**: アクティビティ カードと詳細ページにはサブスクリプションが必要かどうかが表示され、ユーザーは参加する前に参加条件を知ることができます。
**開始方法**: 追加情報で「サブスクリプションが必要」と正確にマークし、長い説明にライブ放送時間とメンバーシップ要件を明確に書き留めます。

5. **やるべきこと**: アクティビティレビューボードを作成します。
**実行する価値がある理由**: App Analytics は、表示、ソース、オープン、ダウンロード、再ダウンロード、通知の予約データを提供し、アクティビティが実際のコンバージョンをもたらしているかどうかを判断します。
**開始方法**: キャンペーンが公開された後、App Store Connect のキャンペーン ページから App Analytics に移動し、商品ページ、検索、その他のソースごとにインプレッションを分割します。
