## ハイライト

> Apple は、Coffee Tracker サンプル アプリを使用して、完了ハンドラー、ディスパッチ キュー、コールバック キューを非同期/待機、アクター、MainActor に段階的に移行することを実証し、既存の Swift プロジェクトがより明確な非同期コードとより安全な状態分離を取得できるようにします。

## 主な内容

Coffee Tracker は watchOS のサンプル アプリです。ユーザーはその日に飲んだコーヒーを記録し、ダイヤルの複雑機構には現在のカフェインレベルが表示されます。

このアプリは小さいですが、実際のプロジェクトに共通する同時実行の問題があります。インターフェイスとモデルはメイン キューで更新されます。バックグラウンド I/O はディスパッチ キューを使用します。 HealthKit の完了ハンドラーは、どのキューからでも返される場合があります。コード サーフェスは UI、モデル、HealthKit の 3 つの層に分割されていますが、ランタイムは複数の実行キューに分散されています。

以前は、この種のコードを保守する場合、開発者は各コールバックがどのキューで実行されたかを覚えておく必要がありました。 HealthKit データを保存するには、完了ハンドラーを作成する必要があります。 HealthKit クエリ結果を読み取ると、コールバックからの処理が続行されます。 SwiftUI モデルを更新する前に、手動でメインスレッドに戻る必要があります。

Apple は、Swift 5.5 で async/await (非同期待機)、アクター (アクター)、および MainActor (メイン アクター) を導入しました。このスピーチで行うことは非常に具体的です。アプリ全体を書き直すのではなく、Coffee Tracker のデータ フローに沿って部分的に移行するだけです。

最初のステップは、既存の非同期 API を次のものに置き換えることです。`await`電話。 2 番目のステップは、非同期バージョンがまだないコールバック API を継続でラップすることです。 3 番目のステップは、共有状態をアクターに入れることです。最後に UI モデルを次のようにマークします。`@MainActor`、コンパイラにメインスレッドの分離を任せます。

### 基礎となる関数から移行を開始する

カフェインのサンプルを保存することから始めるのが良いでしょう。 HealthKit に近く、呼び出しチェーンが短く、変更の範囲が小さいです。

アップルファースト`store.save`完了ハンドラーのバージョンは非同期バージョンに置き換えられます。呼び出し元はクロージャを渡すのではなく、直接渡します。`try await`結果を待ちます。エラー処理は同じ関数内に残ります。

### 古い API は引き続き存在できます

プロジェクトの移行は通常、一度で完了することはできません。音声は完了ハンドラー エントリを保持し、古いメソッドを非推奨としてマークし、それを内部的に作成します。`Task`新しい非同期メソッドを呼び出します。

こうすることで、古い呼び出し元は引き続き動作できます。新しいコードは非同期バージョンを直接使用できます。

### アクターは同時実行境界を型境界に変換します

HealthKitController は、HealthKit の承認、保存、クエリを担当します。その中にはある`isAuthorized`、`anchor`などのステータス。以前は、これらの状態には、異なるキューによって同時にアクセスできました。

バンドル`HealthKitController`に変更します`actor`最後に、状態アクセスはアクターによって分離されます。そのメソッドへの外部呼び出しには次のものが必要です`await`。同時実行境界は型宣言に書き込まれ、呼び出し元がコードから直接確認できます。

### UI モデルを MainActor に渡します

CoffeeData は SwiftUI 用です`ObservableObject`、 その`currentDrinks`インターフェースを駆動します。このオブジェクトはメインスレッドで更新する必要があります。

最初にスピーチをする`updateModel(newDrinks:deletedDrinks:)`マーク`@MainActor`、後で全体を入れます`CoffeeData`タイプは次のようにマークされています`@MainActor`。このようにして、モデルの更新と SwiftUI バインディングはメインの実行環境内に残ります。

### 2. 古い完了ハンドラーに非同期代替エントリを追加します。

([12:13](https://developer.apple.com/videos/play/wwdc2021/10194/?time=733)) 移行プロセス中、古い API が保持されることがあります。 Apple のアプローチは、古いメソッドを非推奨としてマークし、新しい非同期メソッドを内部で呼び出すことです。

```swift
@available(*, deprecated, message: "Prefer async alternative instead")
public func requestAuthorization(completionHandler: @escaping (Bool) -> Void ) {
    Task {
        let result = await requestAuthorization()
        completionHandler(result)
    }
}
```

キーポイント:
- `@available(*, deprecated, message: "Prefer async alternative instead")`代わりに非同期バージョンを使用するよう発信者に通知します。
-`completionHandler`古い通話フォームをそのままにしておきます。
-`Task`同期メソッド内で非同期メソッドを呼び出せるようにします。
-`let result = await requestAuthorization()`新しい認可関数を呼び出します。
-`completionHandler(result)`非同期結果を古いコールバックにブリッジします。

([14:55](https://developer.apple.com/videos/play/wwdc2021/10194/?time=895)) 新しい認証関数は直接戻ります`Bool`。呼び出し元はクロージャ内の結果を読み取る必要がなくなりました。

```swift
public func requestAuthorization() async -> Bool {
    guard isAvailable else { return false }

    do {
        try await store.requestAuthorization(toShare: types, read: types)
        self.isAuthorized = true
        return true
    } catch let error {
        self.logger.error("An error occurred while requesting HealthKit Authorization: \(error.localizedDescription)")
        return false
    }
}
```

キーポイント:
- `async -> Bool`関数が非同期で完了することを示し、承認が成功したかどうかを返します。
-`guard isAvailable else { return false }`まず、デバイスが HealthKit をサポートしていない状況に対処します。
-`try await store.requestAuthorization(toShare: types, read: types)`HealthKit の承認をリクエストします。
-`self.isAuthorized = true`認可の成功ステータスを記録します。
-`catch let error`認可エラーをキャッチします。
- ログに記録して失敗時に戻る`false`。

### 3. 継続を使用して、非同期バージョンを使用せずに HealthKit クエリをラップします。

（[17:43](https://developer.apple.com/videos/play/wwdc2021/10194/?time=1063)）`HKAnchoredObjectQuery`まだ完了ハンドラーを使用しています。ここで使用されます`withCheckedThrowingContinuation`コールバック結果を非同期戻り値に変換します。

```swift
private func queryHealthKit() async throws -> ([HKSample]?, [HKDeletedObject]?, HKQueryAnchor?) {
    return try await withCheckedThrowingContinuation { continuation in
        // Create a predicate that only returns samples created within the last 24 hours.
        let endDate = Date()
        let startDate = endDate.addingTimeInterval(-24.0 * 60.0 * 60.0)
        let datePredicate = HKQuery.predicateForSamples(withStart: startDate, end: endDate, options: [.strictStartDate, .strictEndDate])

        // Create the query.
        let query = HKAnchoredObjectQuery(
            type: caffeineType,
            predicate: datePredicate,
            anchor: anchor,
            limit: HKObjectQueryNoLimit) { (_, samples, deletedSamples, newAnchor, error) in

            // When the query ends, check for errors.
            if let error = error {
                continuation.resume(throwing: error)
            } else {
                continuation.resume(returning: (samples, deletedSamples, newAnchor))
            }
        }
        store.execute(query)
    }
}
```

キーポイント:
- `async throws`クエリがハングするか、エラーがスローされる可能性があることを示します。
-`withCheckedThrowingContinuation`エラーをスローする継続を作成します。
-`endDate`そして`startDate`サンプルを過去 24 時間のものに制限します。
-`HKQuery.predicateForSamples`HealthKit クエリ条件を構築します。
-`HKAnchoredObjectQuery`新しいサンプル、削除されたサンプル、および新しいアンカーをクエリします。
-`if let error = error`クエリの処理に失敗しました。
-`continuation.resume(throwing: error)`非同期呼び出し元へのコールバック エラーを処理します。
-`continuation.resume(returning: (samples, deletedSamples, newAnchor))`クエリ結果を返します。
-`store.execute(query)`HealthKit クエリを開始します。

([20:17](https://developer.apple.com/videos/play/wwdc2021/10194/?time=1217)) パッケージ化が完了したら、上位層の読み込み関数をクエリ、アンカーの更新、データの変換、モデルの更新の順序で記述できます。

```swift
@discardableResult
public func loadNewDataFromHealthKit() async -> Bool {

    guard isAvailable else {
        logger.debug("HealthKit is not available on this device.")
        return false
    }

    logger.debug("Loading data from HealthKit")

    do {
        let (samples, deletedSamples, newAnchor) = try await queryHealthKit()

        // Update the anchor.
        self.anchor = newAnchor

        // Convert new caffeine samples into Drink instances.
        let newDrinks: [Drink]
        if let samples = samples {
            newDrinks = self.drinksToAdd(from: samples)
        } else {
            newDrinks = []
        }

        // Create a set of UUIDs for any samples deleted from HealthKit.
        let deletedDrinks = self.drinksToDelete(from: deletedSamples ?? [])

        // Update the data on the main queue.
        await MainActor.run {
            // Update the model.
            self.updateModel(newDrinks: newDrinks, deletedDrinks: deletedDrinks)
        }
        return true
    } catch {
        self.logger.error("An error occurred while querying for samples: \(error.localizedDescription)")
        return false
    }
}
```

キーポイント:
- `@discardableResult`呼び出し元が戻り値を無視できるようにします。
-`guard isAvailable`HealthKit をサポートしていないデバイスが続行できないようにします。
-`try await queryHealthKit()`新しくラップされたクエリ関数が返されるまで待ちます。
-`self.anchor = newAnchor`次の増分クエリのために位置を保存します。
-`drinksToAdd(from:)`HealthKit サンプルを次のように変換します`Drink`。
- `drinksToDelete(from:)`削除されたレコードを UUID コレクションに変換します。
-`await MainActor.run`モデルの更新をメインの実行環境に切り替えます。
-`catch`ログクエリの失敗とリターン`false`。

```swift
// Begin saving the drink data to disk.
func save(_ currentDrinks: [Drink]) {

    // Don't save the data if there haven't been any changes.
    if currentDrinks == savedValue {
        logger.debug("The drink list hasn't changed. No need to save.")
        return
    }

    // Save as a binary plist file.
    let encoder = PropertyListEncoder()
    encoder.outputFormat = .binary

    let data: Data

    do {
        // Encode the currentDrinks array.
        data = try encoder.encode(currentDrinks)
    } catch {
        logger.error("An error occurred while encoding the data: \(error.localizedDescription)")
        return
    }

    // Save the data to disk as a binary plist file.
    do {
        // Write the data to disk.
        try data.write(to: self.dataURL, options: [.atomic])

        // Update the saved value.
        self.savedValue = currentDrinks

        self.logger.debug("Saved!")
    } catch {
        self.logger.error("An error occurred while saving the data: \(error.localizedDescription)")
    }
}
```

キーポイント:
- `func save(_ currentDrinks: [Drink])`現在の UI モデルのドリンクのリストを受け取ります。
-`if currentDrinks == savedValue`同じデータを繰り返し書き込むことは避けてください。
-`PropertyListEncoder()`plistエンコーダを作成します。
-`encoder.outputFormat = .binary`バイナリ plist を指定します。
-`try encoder.encode(currentDrinks)`配列を次のようにエンコードします`Data`。
- `try data.write(to: self.dataURL, options: [.atomic])`ファイルにアトミックに書き込みます。
-`self.savedValue = currentDrinks`書き込みが成功すると、キャッシュ値が更新されます。
- 二`catch`エンコードの失敗と書き込みの失敗を個別に処理します。

### 7. async を使用して読み込みデータ ストリームを初期化する

（[48:01](https://developer.apple.com/videos/play/wwdc2021/10194/?time=2881)）`CoffeeData`アクターからディスク データを読み取り、期限切れのドリンクをクリーンアップし、モデルを更新し、HealthKit 認証を要求し、新しいデータをロードするという読み込みプロセスを組み合わせることができるようになりました。

```swift
func load() async {
    var drinks = await store.load()

    // Drop old drinks
    drinks.removeOutdatedDrinks()

    // Assign loaded drinks to model
    currentDrinks = drinks

    // Load new data from HealthKit.
    let success = await self.healthKitController.requestAuthorization()
    guard success else {
        logger.debug("Unable to authorize HealthKit.")
        return
    }

    await self.healthKitController.loadNewDataFromHealthKit()
}
```

キーポイント:
- `func load() async`読み込みプロセスがハングすることを示します。
-`await store.load()`から`CoffeeDataStore`アクターはディスク データを読み取ります。
-`drinks.removeOutdatedDrinks()`期限切れの飲み物を削除します。
-`currentDrinks = drinks`SwiftUIで使用されるモデルデータを更新します。
-`await self.healthKitController.requestAuthorization()`HealthKit の承認をリクエストします。
-`guard success else`認証に失敗した場合は早期に復帰します。
-`await self.healthKitController.loadNewDataFromHealthKit()`新しい HealthKit データを取得します。

([49:08](https://developer.apple.com/videos/play/wwdc2021/10194/?time=2948)) イニシャライザを直接非同期としてマークすることはできません。スピーチ用`Task`読み込みを開始します。

```swift
Task { await load() }
```

キーポイント:
- `Task`初期化中に非同期作業を開始します。
-`await load()`今すぐロードプロセスを呼び出してください。
- UI モデルの作成後、タスク内でデータの読み込みが続行されます。

### 8. バックグラウンド更新で完了ハンドラーを置き換える

([52:18](https://developer.apple.com/videos/play/wwdc2021/10194/?time=3138)) watchOSのバックグラウンドタスク処理機能も作成可能`Task`、非同期メソッドを使用して HealthKit の更新を確認します。タスクが完了したら、システム API を呼び出して、バックグラウンド タスクの完了をマークします。

```swift
// Check for updates from HealthKit.
let model = CoffeeData.shared

Task {
    let success = await model.healthKitController.loadNewDataFromHealthKit()

    if success {
        // Schedule the next background update.
        scheduleBackgroundRefreshTasks()
        self.logger.debug("Background Task Completed Successfully!")
    }

    // Mark the task as ended, and request an updated snapshot, if necessary.
    backgroundTask.setTaskCompletedWithSnapshot(success)
}
```

キーポイント:
- `let model = CoffeeData.shared`共有 UI モデルを取得します。
-`Task`非同期バックグラウンド更新ロジックを開始します。
-`await model.healthKitController.loadNewDataFromHealthKit()`HealthKit から新しいデータを取得します。
-`if success`成功した場合にのみ、次のバックグラウンド更新をスケジュールします。
-`scheduleBackgroundRefreshTasks()`watchOS のバックグラウンド更新リズムを継続します。
-`backgroundTask.setTaskCompletedWithSnapshot(success)`タスクが終了したことをシステムに通知します。

## 重要なポイント

### 1. 既存のアプリに対して段階的な非同期/待機移行を実行する

- **対処方法**: システム フレームワークに近い低レベルのサービスから開始し、完了ハンドラー メソッドを非同期メソッドに変更します。
- **実行する価値がある理由**: このスピーチでは、プロジェクト全体を一度に変更することなく、古い方法を維持し、新しい方法で内部の呼び出しチェーンを徐々に置き換えることができることが示されました。
- **開始方法**: 1 つ選択してください`save`、`load`または`requestAuthorization`このような細かい機能が追加されています`async`バージョン;古い完了ハンドラー メソッドによって内部的に使用されます`Task`新しいバージョンを呼び出して追加します`@available(*, deprecated, message: "Prefer async alternative instead")`。

### 2. パッケージにはコールバック API の非同期バージョンがまだありません

- **何をすべきか**: まだ完了ハンドラーに依存しているプロジェクト内のシステム API を非同期関数にラップします。
- **実行する価値がある理由**:`HKAnchoredObjectQuery`この例は、継続によってコールバック結果を次のように変えることができることを示しています。`try await`、上位レベルのビジネス ロジックがよりスムーズになります。
- **開始方法**: プライベート ヘルパーを作成します。`queryHealthKit() async throws`;存在する`withCheckedThrowingContinuation`元のクエリを次の場所に作成します。成功について`resume(returning:)`、失敗したとき`resume(throwing:)`。

### 3. キャッシュとファイルの読み取りと書き込みをアクターに組み込む

- **内容**: ローカル キャッシュ、plist/JSON ファイルの読み取りと書き込み、および最後に保存された値用のプライベート アクターを作成します。
- **実行する価値がある理由**:`CoffeeDataStore`バンドル`savedValue`そして`dataURL`UI モデルのバックグラウンド状態を減らすために、すべてが同じアクターに含まれています。
- **開始方法**: 新規`private actor DataStore`;バンドル`savedValue`、ファイル URL、`save(_:)`、`load()`引っ越してください。外部で使用する`await store.save(value)`そして`await store.load()`電話。

### 4. SwiftUI モデルを @MainActor でマークします。

- **やるべきこと**: ドライバーインターフェイスを配置します`ObservableObject`または次のようにマークされたその更新メソッド`@MainActor`。
- **実行する価値がある理由**: CoffeeData の`currentDrinks`SwiftUI の更新をトリガーします。MainActor の後に配置すると、呼び出し場所が分散されなくなります。`DispatchQueue.main.async`または`MainActor.run`。
- **開始方法**: まず変更させてください`@Published`属性メソッドの追加`@MainActor`; モデル全体が UI 指向の場合、`@MainActor`クラス宣言に。

### 5. バックグラウンドタスクの非同期リンクを書き換えます

- **何をすべきか**: watchOS のバックグラウンド更新、プッシュ処理、スケジュールされた同期、その他の入り口を変更します。`Task`+ 非同期サービス呼び出し。
- **実行する価値がある理由**: スピーチ内の ExtensionDelegate は、システム コールバック エントリを保持し、内部で非同期メソッドを使用して HealthKit データをロードし、最終的にシステム要件に従ってバックグラウンド タスクを終了します。
- **開始方法**: デリゲートメソッドで作成`Task`;タスク中`await`モデルまたはサービスを呼び出します。成功後に次のタスクをスケジュールします。最後にシステムの完了 API を呼び出します。
