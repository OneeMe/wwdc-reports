## Highlight

> Keynote 覆盖了 2025 年所有平台的核心更新，按照 iOS、watchOS、tvOS、macOS、visionOS、iPadOS 和开发者工具的顺序展开。

---

## 核心内容

过去一年开发者面对的是一堆零散问题：自定义控件在 iOS 7 时代的设计语言下越改越笨重；要接入大模型必须走云端，付 token 费，离线就废；自家三端（iOS / macOS / visionOS）的视觉语汇不统一，跨端做产品要重画三套。Craig Federighi 在 Keynote 上把这些痛点摆到台前——iOS 7 之后将近十二年没有大的设计重置，硬件早已不是 A6，软件还停留在那一代的层级结构里。

苹果给出的答案是两条主线同时推进。第一条是 **Liquid Glass**——首个跨平台统一的设计材质，模拟真实玻璃的折射、反射、动态形变，由 visionOS 的物理质感反哺到 iOS / macOS / watchOS。所有原生控件 recompile 即可继承新外观，开发者不需要改一行代码。第二条是 **Foundation Models 框架**——把驱动 Apple Intelligence 的端侧大模型直接开放给第三方 app 调用，零云端费用、离线可用、数据不出设备。Keynote 现场用 Kahoot! 从笔记自动生成测验、AllTrails 在野外推荐徒步路线两个例子说明这两条主线如何落到具体场景。

同时苹果统一了所有平台的版本号——今年秋季发布的所有系统统称 26（覆盖到 2026 年），iOS 26、macOS 26、watchOS 26、visionOS 26 全线对齐，结束了 iOS 18 / macOS 15 / watchOS 11 这种版本号错位的局面。

## 详细内容

### Liquid Glass：一次系统级的材质替换（[09:57](https://developer.apple.com/videos/play/wwdc2025/101/?time=597)）

Liquid Glass 是一种新的「表达性材质」，具备真实玻璃的光学特性：

- **折射与镜面高光**：根据下方内容动态调整颜色，浅色 / 深色环境自动适配。
- **形变响应**：当需要展开更多选项或在视图间切换时，材质会动态形变而不是硬切。
- **同心圆角**：控件几何形状被重新设计成与硬件圆角同心，释放屏幕空间给内容。
- **作用范围**：Lock Screen、通知、Control Center、Dock、App Icon、Widget 全部用同一套材质。

App 图标也被分层重制——支持四种渲染模式：light、dark、彩色 tint、全透明 clear。新工具 Icon Composer 在 Xcode 内置，专门用来设计多层图标。

### Foundation Models 框架（[06:00](https://developer.apple.com/videos/play/wwdc2025/101/?time=360)）

苹果把端侧大模型的 API 开放给第三方 app，关键属性：

- **直接访问 on-device LLM**：调用本地模型，不走云端。
- **无云端 API 费用**：「this happens without cloud API costs」是 Keynote 原话。
- **离线可用**：飞机、地下停车场、野外露营都能跑。
- **隐私默认**：数据不离开设备，无需用户额外授权弹窗。

适合做内容摘要、分类、生成式辅助这类「日常智能」任务，不适合需要最新世界知识或超长上下文的场景。

### iOS 26 的具体改动（[13:08](https://developer.apple.com/videos/play/wwdc2025/101/?time=788)）

- **Lock Screen**：San Francisco 字体的数字会根据壁纸自动调整 weight / width / height，避让照片主体。2D 照片通过 Neural Engine 生成 spatial scene，倾斜手机会有 3D 视差。
- **Camera 应用**：精简成 Photo / Video 两个主模式，其他模式左右滑切换，设置上滑唤出。
- **Photos**：恢复 Library / Collections 双 tab（弥补 iOS 18 取消 tab 的争议）。
- **Phone 应用**：Favorites / Recents / Voicemails 合并成统一视图。新增 **Call Screening**（陌生号码自动接听让对方报来意后再决定是否接）和 **Hold Assist**（自动识别 hold music，保持在队列里，活人坐席接通时再回呼用户）。
- **Messages**：新增背景、群投票（Apple Intelligence 在检测到「周末谁有空」这类对话时主动建议建投票）、群聊 Apple Cash、群聊 typing indicator、端侧 spam detection。
- **Live Translation**：集成进 Messages / FaceTime / Phone，Messages 边输入边翻译，FaceTime 显示翻译字幕但保留原始声音，Phone 通话实时朗读翻译，对方用非 iPhone 也能用。开发者可通过 API 把 Live Translation 接入自己的通信类 app。
- **CarPlay**：新设计延伸到车机；首次支持 Widget 和 Live Activity，而且复用 iPhone 上已开发好的同一份 Widget / Live Activity。
- **Image Playground**：Genmoji 支持「emoji + emoji」混合（树懒 + 灯泡），也支持 emoji + 文字描述；接入 ChatGPT 风格（油画、任意风格），用户必须明确授权才发送到 ChatGPT。

### Apple Music / Maps（[30:24](https://developer.apple.com/videos/play/wwdc2025/101/?time=1824)）

- **Lyrics Translation** 和 **Lyrics Pronunciation**：歌词翻译 + 发音引导，跟唱外语歌。
- **AutoMix**：用智能做歌曲衔接，自动 time stretch 和 beat match。
- **Music Pins**：把艺人 / 专辑 / 歌单 pin 到资料库顶部。
- **Maps** 学习用户日常路线，记住去过的地方。

### CarPlay Ultra

首批车型已于上月上市，把 CarPlay 体验扩展到所有驾驶屏幕：用户可选布局，集成空调和电台等车辆控制。

### 命名统一

所有系统版本号合并为 26，对齐 2026 年。

## 核心启发

- **做什么：把现有 app 在 Xcode 26 上直接 recompile，先看 Liquid Glass 的默认效果**
  - 为什么值得做：标准控件无需改代码就能继承新材质，是投入产出比最高的视觉升级路径。Keynote 明确说明 native frameworks 自动适配。
  - 怎么开始：装 Xcode 26 beta，开旧工程 build → 截图对比 → 列出哪些自定义控件「掉队」了 → 按优先级替换为 SwiftUI / UIKit 原生组件。

- **做什么：用 Foundation Models 把原本要走 OpenAI API 的轻量场景搬到端侧**
  - 为什么值得做：免 token 费、零延迟、离线可用、不需要让用户授权数据外传。Kahoot! 从笔记生成测验、AllTrails 推荐徒步路线就是范本场景。
  - 怎么开始：列出 app 里所有「调一次 LLM 拿一段结构化结果」的场景（摘要、分类、抽取、生成）→ 评估是否需要最新世界知识 → 不需要的就迁到 Foundation Models。

- **做什么：把 iPhone 上已有的 Widget / Live Activity 适配到 CarPlay**
  - 为什么值得做：CarPlay 每天被使用 6 亿次以上，Widget / Live Activity 是首次进入车机；现有代码可直接复用，相当于免费获得一块新屏幕的曝光。
  - 怎么开始：检查现有 WidgetKit / ActivityKit 实现是否满足驾驶场景的简洁性 → 在 CarPlay Simulator 里验证 glance 体验。

- **做什么：通信类 app 接入 Live Translation API**
  - 为什么值得做：跨语种沟通是高频痛点，系统级 API 端侧运行不收费，比自己接入翻译服务成本和延迟都低。
  - 怎么开始：在自家聊天 / 通话场景里加一个「翻译为我的语言」的开关，调系统 API → 注意 Messages 翻译显示位置和原文的视觉权重平衡。

- **做什么：用 Icon Composer 重画 App Icon 的四种模式**
  - 为什么值得做：iOS 26 新增 clear 模式和重制的 tint 模式，老图标在新模式下会很丑。Icon Composer 一次设计多层结构，四种模式都能复用。
  - 怎么开始：把现有图标素材拆成 2-4 个语义层（背景、主体、点缀）→ 在 Icon Composer 里组合 → 在浅色 / 深色 / tint / clear 四个状态下逐一检查。
