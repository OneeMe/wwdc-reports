## Highlight

> Keynote では 2025 年における全プラットフォームのコアアップデートが、iOS、watchOS、tvOS、macOS、visionOS、iPadOS、開発者ツールの順に紹介されました。

---

## 主要内容

この一年、開発者は細々とした課題に直面してきました。カスタムコントロールは iOS 7 時代のデザイン言語のもとで手を入れるたびに重たくなり、大規模言語モデルを組み込もうとすればクラウド経由で token 課金が発生し、オフラインでは使えません。さらに自社の三つのプラットフォーム（iOS / macOS / visionOS）の視覚言語が統一されておらず、クロスプラットフォームで製品を作るには 3 セット分のデザインを描き直す必要がありました。Craig Federighi は Keynote でこれらの痛点を正面から取り上げます。iOS 7 から約 12 年間、大規模なデザインリセットは行われておらず、ハードウェアはとっくに A6 ではないのに、ソフトウェアはあの時代の階層構造に留まっていたわけです。

Apple が提示した答えは 2 本の主軸を同時に進めるというものです。1 本目は **Liquid Glass** ── 初の全プラットフォーム統一デザインマテリアルで、本物のガラスの屈折・反射・動的変形をシミュレートします。visionOS の物理的な質感が iOS / macOS / watchOS にフィードバックされる形で生まれました。すべてのネイティブコントロールは recompile するだけで新しい外観を継承し、開発者は 1 行もコードを変更する必要がありません。2 本目は **Foundation Models フレームワーク** ── Apple Intelligence を駆動するオンデバイス LLM をサードパーティ app から直接呼び出せるよう開放するもので、クラウド料金ゼロ、オフライン動作、データはデバイスから外に出ません。Keynote 当日のデモでは Kahoot! がノートから自動でクイズを生成する例、AllTrails がフィールドでハイキングルートをレコメンドする例の 2 つを通じて、この 2 本の主軸が具体的なシーンにどう落ちるかが示されました。

同時に Apple は全プラットフォームのバージョン番号を統一しました。今年の秋にリリースされる全システムは総称して 26 と呼ばれ（2026 年までをカバー）、iOS 26、macOS 26、watchOS 26、visionOS 26 が一直線に揃います。これで iOS 18 / macOS 15 / watchOS 11 のようなバージョン番号のズレも解消されます。

## 詳細

### Liquid Glass：システムレベルでのマテリアル刷新（[09:57](https://developer.apple.com/videos/play/wwdc2025/101/?time=597)）

Liquid Glass は新しい「表現力のあるマテリアル」で、本物のガラスのような光学特性を備えています。

- **屈折とスペキュラハイライト**：背後のコンテンツに応じて色合いを動的に調整し、ライト / ダーク環境にも自動で適応します。
- **形状の追従**：オプションを展開したりビュー間を遷移する際に、マテリアル自体が動的に変形し、急な切り替わりを起こしません。
- **同心円角**：コントロールの幾何形状はハードウェアの角丸と同心になるよう再設計され、画面領域をコンテンツに譲ります。
- **適用範囲**：Lock Screen、通知、Control Center、Dock、App Icon、Widget まですべてが同じマテリアルで統一されます。

App アイコンも階層構造として作り直され、light、dark、カラー tint、完全透明の clear という 4 種類のレンダリングモードに対応しました。Xcode に組み込まれた新ツール Icon Composer が、こうした多層アイコンの設計を担当します。

### Foundation Models フレームワーク（[06:00](https://developer.apple.com/videos/play/wwdc2025/101/?time=360)）

Apple はオンデバイス LLM の API をサードパーティ app に開放しました。重要なポイントは次のとおりです。

- **オンデバイス LLM への直接アクセス**：ローカルモデルを呼び出し、クラウドを経由しません。
- **クラウド API 料金不要**：Keynote の原文でも「this happens without cloud API costs」と明言されています。
- **オフラインで利用可能**：飛行機内、地下駐車場、フィールドでのキャンプなどでも動作します。
- **プライバシーがデフォルト**：データがデバイスから出ないため、ユーザーに追加のダイアログを出す必要もありません。

要約・分類・生成補助といった「日常的な知能」タスクに向いており、最新の世界知識や超長コンテキストを必要とするシーンには適しません。

### iOS 26 の具体的な変更点（[13:08](https://developer.apple.com/videos/play/wwdc2025/101/?time=788)）

- **Lock Screen**：San Francisco フォントの数字が壁紙に応じて weight / width / height を自動調整し、写真の被写体を避けて配置されます。2D 写真は Neural Engine によって spatial scene に変換され、iPhone を傾けると 3D 視差が現れます。
- **Camera アプリ**：Photo / Video の 2 つをメインモードに簡素化し、その他のモードは左右スワイプで切り替え、設定は上スワイプで呼び出します。
- **Photos**：Library / Collections の 2 タブ構成が復活します（iOS 18 でタブが廃止された件への対応）。
- **Phone アプリ**：Favorites / Recents / Voicemails が単一ビューに統合されます。新たに **Call Screening**（不明な番号からの着信は自動応答させ、相手に用件を述べてもらってから出るかどうか判断する機能）と **Hold Assist**（hold music を自動検知し、キューに残ったまま、人間のオペレーターにつながった瞬間にユーザーへ呼び戻す機能）が追加されます。
- **Messages**：背景、グループ投票（Apple Intelligence が「週末空いてる人いる？」のような会話を検知すると投票作成を提案）、グループチャットでの Apple Cash、グループチャットの typing indicator、オンデバイスのスパム検知が加わります。
- **Live Translation**：Messages / FaceTime / Phone に統合されます。Messages では入力しながら翻訳、FaceTime では翻訳字幕を表示しつつ元の音声も保持、Phone では通話中にリアルタイムで翻訳を読み上げ、相手側が iPhone でなくても利用可能です。開発者は API を介して、自社のコミュニケーション系 app に Live Translation を組み込めます。
- **CarPlay**：新デザインが車載側にも拡張されます。Widget と Live Activity に初対応し、しかも iPhone 上で既に開発済みの同じ Widget / Live Activity をそのまま再利用できます。
- **Image Playground**：Genmoji が「emoji + emoji」の合成（ナマケモノ + 電球など）に対応し、emoji + テキスト記述の組み合わせもサポートします。ChatGPT 風スタイル（油絵や任意のスタイル）にも接続でき、ChatGPT への送信にはユーザーの明示的な許可が必須です。

### Apple Music / Maps（[30:24](https://developer.apple.com/videos/play/wwdc2025/101/?time=1824)）

- **Lyrics Translation** と **Lyrics Pronunciation**：歌詞の翻訳と発音ガイドにより、外国語の曲を一緒に歌えるようになります。
- **AutoMix**：曲のつなぎを賢く処理し、time stretch と beat match を自動で行います。
- **Music Pins**：アーティスト / アルバム / プレイリストをライブラリの先頭に pin できます。
- **Maps** はユーザーの日常的な経路を学習し、訪れた場所を覚えています。

### CarPlay Ultra

最初の対応車種が先月発売され、CarPlay 体験をすべての運転席ディスプレイに拡張します。ユーザーはレイアウトを選べ、エアコンやラジオなどの車両コントロールも統合されます。

### バージョン名の統一

すべてのシステムのバージョン番号が 26 に統合され、2026 年に揃えられます。

## 重要ポイント

- **何をするか：既存 app を Xcode 26 でそのまま recompile し、Liquid Glass のデフォルト見た目をまず確認する**
  - なぜやる価値があるか：標準コントロールはコードを書き換えなくても新マテリアルを継承するため、投入対効果が最も高いビジュアルアップグレードのパスです。Keynote でも native frameworks が自動で適応すると明言されています。
  - 始め方：Xcode 26 beta をインストールし、既存プロジェクトを build → スクリーンショットで比較 → どのカスタムコントロールが「取り残されている」かを洗い出す → 優先順位をつけて SwiftUI / UIKit のネイティブコンポーネントへ置き換えていきます。

- **何をするか：本来 OpenAI API を呼んでいた軽量シーンを Foundation Models に載せ替える**
  - なぜやる価値があるか：token 料金が不要、レイテンシゼロ、オフライン利用可能、ユーザーにデータ外部送信の許諾を求める必要もありません。Kahoot! のノートからのクイズ生成、AllTrails のハイキングルート提案がまさに見本になるシーンです。
  - 始め方：app 内で「LLM を一度叩いて構造化された結果を取り出す」シーン（要約、分類、抽出、生成）を全部リストアップ → 最新の世界知識が必要かどうかを評価 → 不要なものは Foundation Models に移行します。

- **何をするか：iPhone で既に持っている Widget / Live Activity を CarPlay 向けに対応する**
  - なぜやる価値があるか：CarPlay は 1 日に 6 億回以上利用されており、Widget / Live Activity が車載に出るのは初めてです。既存コードをそのまま再利用できるため、新しいスクリーンの露出を実質タダで獲得できる計算です。
  - 始め方：既存の WidgetKit / ActivityKit 実装が運転中のシンプルさ要件を満たしているか確認 → CarPlay Simulator で glance 体験を検証します。

- **何をするか：コミュニケーション系 app に Live Translation API を組み込む**
  - なぜやる価値があるか：多言語間のコミュニケーションは頻出のペインで、システムレベルの API はオンデバイス実行・無料です。自前で翻訳サービスを組むよりコストもレイテンシも有利になります。
  - 始め方：自社のチャット / 通話シーンに「自分の言語に翻訳する」スイッチを追加し、システム API を呼ぶ → Messages の翻訳表示位置と原文の視覚的バランスに注意します。

- **何をするか：Icon Composer で App Icon の 4 モードを描き直す**
  - なぜやる価値があるか：iOS 26 で clear モードが追加され、tint モードも作り直されたため、古いアイコンは新モードでは見栄えが悪くなります。Icon Composer なら多層構造を一度に設計でき、4 つのモードすべてで再利用できます。
  - 始め方：既存のアイコン素材を 2〜4 つの意味層（背景、主体、装飾）に分解 → Icon Composer で組み合わせる → light / dark / tint / clear の 4 状態でひとつずつチェックしていきます。
