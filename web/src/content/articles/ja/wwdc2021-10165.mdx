## ハイライト

> iOS 15 では、Nearby Interaction が互換性のあるサードパーティの UWB アクセサリをサポートできるようになります。開発者は、NINearby AccessoriesConfiguration を使用して、アクセサリから正確な距離と方向の最新情報を取得し、Bluetooth やその他のチャネルを通じて密接な空間関係を判断することが難しいという問題を解決できます。

## 主な内容

スマート スピーカー、ツールボックス ラベル、またはショールームのインスタレーションを作成します。ユーザーが 3 メートル近づくと、アプリは基本的なコントロールを表示しようとします。ユーザーが 1.5 メートル近づくと、アプリはより正確な操作インターフェイスを開こうとします。

以前は安定することが困難でした。 Bluetooth はデータの接続と送信を処理できますが、室内でのユーザーの正確な位置を特定するのには適していません。ネットワーク接続でもステータスを交換できますが、ユーザーがアクセサリの上に立っている方向をアプリに伝える方法はありません。

iOS 14 の Nearby Interaction では、U1 チップを搭載した 2 台の iPhone が距離と方向の情報を交換できるようになりました。問題は、サードパーティのアクセサリがこのセッションに直接参加できないことです。

iOS 15 はこのギャップを埋めます。アップルの新製品`NINearbyAccessoryConfiguration`、互換性のあるサードパーティの UWB (Ultra Wideband) ハードウェアが iPhone の U1 チップと相互運用できるようになります。

この機能は Bluetooth やネットワークに代わるものではありません。アプリには、iPhone とアクセサリの間で構成データを渡すためのデータ チャネルが必要です。 Nearby Interaction は UWB 測距セッションを担当し、データ チャネルはセッションの開始と調整を担当します。

アクセサリ構成データが最初に生成されます。受信後にアプリを作成`NINearbyAccessoryConfiguration`そして始めます`NISession`。次に、システムはデリゲートを通じて共有可能な構成データを生成し、アプリはそれをできるだけ早くアクセサリに送信する必要があります。両側の設定が完了すると、アプリは`NINearbyObject`距離と、ハードウェアでサポートされている場合は方向を含むように更新されました。

＃＃詳細

### 1. 権限が 1 回限りの認証から使用期間付き認証に変更されました

([02:59](https://developer.apple.com/videos/play/wwdc2021/10165/?time=179)) iOS 14 の Nearby Interaction 権限は、アプリのライフサイクルごとに 1 回のみ許可されます。次回、ユーザーが関連プロセスに再入力するときに、プロンプトが再度表示される場合があります。

([03:34](https://developer.apple.com/videos/play/wwdc2021/10165/?time=214)) iOS 15 のプロンプトは「アプリの使用中」認証に変更されます。システムは初めてアプリを実行します`NISession`プロンプトが自動的にポップアップ表示されます。ユーザーが承諾または拒否した後は、プロンプトは再度表示されません。その後、ユーザーは設定で権限を変更できます。

```xml
<key>NSNearbyInteractionUsageDescription</key>
<string>用于在你靠近配件时显示距离相关控制。</string>
```

キーポイント:

- `NSNearbyInteractionUsageDescription`Info.plist の目的の説明です。
- システムは、近くのインタラクション許可プロンプトにこのテキストを表示します。
- 最初の実行`NISession`時点は、「アクセサリを接続する」または「検索を開始する」などの明確なユーザー アクションに対応する必要があります。
- 権限が不足している場合、`NISession`権限関連のエラーのため無効となります。アプリは理由を説明し、設定で変更するようにユーザーに案内する必要があります。

### 2. アクセサリ データを使用して NINearby AccessoriesConfiguration を作成します

([08:43](https://developer.apple.com/videos/play/wwdc2021/10165/?time=523)) サードパーティ製アクセサリは、まず Bluetooth、ローカル ネットワーク、または安全なインターネット接続を介してアクセサリ構成データをアプリに送信します。このデータは、U1 互換の UWB ハードウェアによって所定の形式で生成されます。

([10:45](https://developer.apple.com/videos/play/wwdc2021/10165/?time=645)) アプリはデータを受信した後、それを使用してデータを作成します`NINearbyAccessoryConfiguration`。データ形式が無効な場合、初期化でエラーがスローされます。

```swift
import Foundation
import NearbyInteraction

final class AccessoryStore {
    private var namesByToken: [NIDiscoveryToken: String] = [:]

    func setupAccessory(configurationData: Data, name: String) throws -> NINearbyAccessoryConfiguration {
        let configuration = try NINearbyAccessoryConfiguration(data: configurationData)
        namesByToken[configuration.accessoryDiscoveryToken] = name
        return configuration
    }

    func name(for token: NIDiscoveryToken) -> String? {
        namesByToken[token]
    }
}
```

キーポイント:

- `import NearbyInteraction`Nearby Interaction フレームワークの導入。
- `setupAccessory(configurationData:name:)`アクセサリから送信された構成データとアクセサリ名を受信します。
- `try NINearbyAccessoryConfiguration(data:)`データ形式を確認し、アクセサリ セッション構成を生成します。
- `configuration.accessoryDiscoveryToken`枠いっぱいのアクセサリーディスカバリーロゴです。
- `namesByToken`検出ロゴをアクセサリ名に関連付けて、後で受け取る`NINearbyObject`アップデート時に正しいアクセサリ名が表示されるようになりました。
- メソッドが返す`NINearbyAccessoryConfiguration`、呼び出し側はそれを使用して開始できます`NISession`。

### 3. NISession を開始し、共有可能な構成データをアクセサリに送信します。

([13:02](https://developer.apple.com/videos/play/wwdc2021/10165/?time=782)) アプリが構成を作成した後、`NISession`、デリゲートを設定し、呼び出します`run(_:)`。

([13:19](https://developer.apple.com/videos/play/wwdc2021/10165/?time=799)) アクセサリには、近くのインタラクションからの共有可能な構成データも必要です。システムは、iOS 15 で追加されたデリゲート コールバックを介してそれをアプリに渡します。アプリは、元のデータ チャネルを通じてアクセサリをできるだけ早くアクセサリに送信する必要があります。遅延が過度に大きいと、セッションがタイムアウトになります。

```swift
import Foundation
import NearbyInteraction

protocol AccessoryConnection {
    func send(_ data: Data)
}

final class AccessorySessionController: NSObject, NISessionDelegate {
    private let session = NISession()
    private let configuration: NINearbyAccessoryConfiguration
    private let connection: AccessoryConnection

    init(configuration: NINearbyAccessoryConfiguration, connection: AccessoryConnection) {
        self.configuration = configuration
        self.connection = connection
        super.init()
        session.delegate = self
    }

    func start() {
        session.run(configuration)
    }

    func session(
        _ session: NISession,
        didGenerateShareableConfigurationData shareableConfigurationData: Data,
        for object: NINearbyObject
    ) {
        connection.send(shareableConfigurationData)
    }
}
```

キーポイント:

- `AccessoryConnection`Bluetooth、LAN、またはその他の安全な接続によって実装できる抽象データ チャネル。
- `NISession()`Nearby Interaction セッションを作成します。
- `session.delegate = self`コントローラーがフレーム コールバックを受信できるようにします。
- `session.run(configuration)`アクセサリ構成でセッションを開始します。
- `didGenerateShareableConfigurationData`共有可能な構成データを提供します。
- `connection.send(shareableConfigurationData)`データをそのままアクセサリに送り返します。
- `for object: NINearbyObject`このデータがどのアクセサリに属しているかを示します。これは、複数のアクセサリが並行して実行されている場合に重要です。

### 4. タイムアウトを処理し、構成がまだ有効な間に再試行します。

([15:25](https://developer.apple.com/videos/play/wwdc2021/10165/?time=925)) 共有可能な構成データがアクセサリを時間内に配信しない場合、セッションがタイムアウトになる可能性があります。近くのインタラクションが通過します`didRemove`デリゲートコールバック通知アプリ。

([15:44](https://developer.apple.com/videos/play/wwdc2021/10165/?time=944)) アプリは削除の理由を確認できます。理由があれば`.timeout`、アクセサリがまだ近くにあるとアプリが判断すると、同じ構成でセッションを再実行できます。キャッシュ設定は、アクセサリ側のセッションが終了していない場合にのみ有効です。

```swift
import NearbyInteraction

final class RetryController: NSObject, NISessionDelegate {
    private let session: NISession
    private let configuration: NINearbyAccessoryConfiguration
    private var retryCount = 0

    init(session: NISession, configuration: NINearbyAccessoryConfiguration) {
        self.session = session
        self.configuration = configuration
        super.init()
    }

    func session(
        _ session: NISession,
        didRemove nearbyObjects: [NINearbyObject],
        reason: NINearbyObject.RemovalReason
    ) {
        guard reason == .timeout else { return }
        guard shouldRetry() else { return }

        retryCount += 1
        session.run(configuration)
    }

    private func shouldRetry() -> Bool {
        retryCount < 3
    }
}
```

キーポイント:

- `didRemove nearbyObjects`1 つ以上の近くのオブジェクトが削除されたことを示します。
- `reason == .timeout`セッションタイムアウトシナリオに対応します。
- `shouldRetry()`リトライ回数やアクセサリによる停止通知の有無など、アプリ独自の判定ロジックを配置します。
- `retryCount += 1`無限の再試行を避けるために、現在の再試行回数を記録します。
- `session.run(configuration)`同じ構成でセッションを再度開始します。
- アクセサリ側セッションが終了した場合、アプリはアクセサリ構成データを再取得し、完全な起動プロセスを実行する必要があります。

### 5. 距離に応じて走行エリア関数を更新する

([19:24](https://developer.apple.com/videos/play/wwdc2021/10165/?time=1164)) iPhone とアクセサリが設定されると、アプリは`didUpdate`受け取る`NINearbyObject`更新します。更新には、距離と、ハードウェアがサポートしている場合は方向が含まれます。

([20:26](https://developer.apple.com/videos/play/wwdc2021/10165/?time=1226)) トーク内のシーンでは、半径 1.5 メートルと半径 3 メートルの 2 つのエリアが定義されています。ユーザーが 3 メートルのエリアに入ると機能 A が有効になり、ユーザーが 1.5 メートルのエリアに入ると機能 B が有効になります。 Apple は、ユーザーが突然移動したり、端に立ったりしたときに UI が急激にジャンプしないように、距離を滑らかにすることを推奨しています。

```swift
import NearbyInteraction

final class DistanceZoneController: NSObject, NISessionDelegate {
    private var lastSmoothedDistance: Float?

    func session(_ session: NISession, didUpdate nearbyObjects: [NINearbyObject]) {
        guard let object = nearbyObjects.first else { return }
        guard let distance = object.distance else { return }

        let smoothedDistance = getSmoothedDistance(distance)

        if smoothedDistance < 1.5 {
            enableFunctionalityB()
        } else if smoothedDistance < 3.0 {
            enableFunctionalityA()
        }
    }

    private func getSmoothedDistance(_ distance: Float) -> Float {
        guard let previous = lastSmoothedDistance else {
            lastSmoothedDistance = distance
            return distance
        }

        let alpha: Float = 0.3
        let smoothed = alpha * distance + (1 - alpha) * previous
        lastSmoothedDistance = smoothed
        return smoothed
    }

    private func enableFunctionalityA() {
        // 用户进入 3 米区域后的功能。
    }

    private func enableFunctionalityB() {
        // 用户进入 1.5 米区域后的功能。
    }
}
```

キーポイント:

- `didUpdate nearbyObjects`距離と方向の更新ポータルです。
- `nearbyObjects.first`今回のアップデートのアクセサリーオブジェクトを取り出します。
- `object.distance`フレームによって提供される距離 (メートル単位) です。
- `getSmoothedDistance(_:)`距離を滑らかにして、境界付近の UI のジッターを軽減します。
- `smoothedDistance < 1.5`近い領域に対応して、機能 B がトリガーされます。
- `smoothedDistance < 3.0`より大きな領域に対応して、機能 A がトリガーされます。
- 複数のアクセサリが並行して実行されている場合、アクセサリごとにセッションを作成して実行できます。

## 重要なポイント

1. **対処方法**: スマート スピーカーに「ディスプレイ コントロール パネルを閉じる」を追加します。
**価値がある理由**: Nearby Interaction はアクセサリまでの正確な距離を提供できるため、アプリはユーザーが近づいているかどうかを推測するために Bluetooth 信号の強度に依存する必要がありません。
**開始方法**: スピーカーに Bluetooth 経由でアクセサリ設定データを送信させます。これはアプリで使用できます。`NINearbyAccessoryConfiguration(data:)`起動する`NISession`、存在する`didUpdate`コントロール パネルを 3 メートルのしきい値で表示します。

2. **何をすべきか**: ウェアハウスツールラベルの「クローズ確認」を実行します。
**実行する価値がある理由**: UWB 距離は、ユーザーが本当にターゲット アクセサリの隣に立っているかを判断し、誤操作を減らすのに適しています。
**開始方法**: タグごとにメンテナンスする`accessoryDiscoveryToken`名前へのマッピング、`object.distance`1.5メートル未満の場合は「アクセス確認」ボタンが表示されます。

3. **やるべきこと**: ユーザーが展示物に近づくとコンテンツが自動的に切り替わる展示ホール アプリを作成します。
**実行する価値がある理由**: スピーチ内の 1.5 メートルと 3 メートルのエリア モデルは、直接展示説明レベルに変えることができます。要約は遠くに示され、操作は遠くに示されます。
**開始方法**: 各展示には互換性のある UWB アクセサリが装備されています。アプリは各アクセサリのセッションを作成します。で`didUpdate`距離のしきい値を押すと、ページのステータスが切り替わります。

4. **対処方法**: アクセサリ接続プロセスに回復可能なタイムアウト再試行を追加します。
**実行する価値がある理由**: 共有可能な構成データの送信が遅すぎると、セッションがタイムアウトになります。再試行すると、ユーザーの再接続の数を減らすことができます。
**開始方法**: 実装`session(_:didRemove:reason:)`、いつ`reason == .timeout`再試行回数が制限を超えない場合は、キャッシュされた`NINearbyAccessoryConfiguration`もう一度電話する`session.run(_:)`。

5. **やるべきこと**: アプリ内で明確な Nearby Interaction 権限エントリを設計します。
**価値がある理由**: iOS 15 は初回のみ動作します`NISession`許可プロンプトが表示されるとき、タイミングが不明確であると、ユーザーが許可される可能性が低くなります。
**開始方法**:`session.run(_:)`Info.plist の「アクセサリの検索を開始」ボタンの後に配置します。`NSNearbyInteractionUsageDescription`距離センシングの目的については、「 」で説明します。
