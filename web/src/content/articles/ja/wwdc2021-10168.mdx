## ハイライト

> macOS Monterey では MailKit が導入されており、開発者は App Extension アーキテクチャを使用して、書き込み支援、受信処理、コンテンツ傍受、電子メール セキュリティ機能を Mail に追加できるため、古い Mail プラグインがシステムのアップデートで無効になる問題が解決されます。

## 主な内容

多くのチームの電子メール ルールは Mail にありません。

企業電子メールの一般的な要件は非常に具体的です。機密プロジェクト電子メールは受信者をチェックする必要があり、プロジェクト電子メールは自動的にマークされる必要があり、マーケティング電子メール内のリモート画像は傍受する必要があり、企業証明書システムが署名と暗号化を引き継ぐ必要があります。以前は、Mail を大幅に変革したい場合、開発者は Mail プラグインを作成していました。このプラグインはメールの内部実装に依存しているため、システムの更新後に障害が発生する傾向があります。

Apple は macOS Monterey で MailKit (メール拡張フレームワーク) を提供しています。これはアプリ拡張機能アーキテクチャに基づいて構築されており、Safari アプリ拡張機能や共有シート拡張機能と同じインフラストラクチャを使用します。拡張機能は署名された Mac アプリに配置され、既存のアプリと一緒に App Store に配布することもできます。

このセッションでは 4 種類の入り口が用意されています。 Compose 拡張機能は書き込みプロセスを処理し、Action 拡張機能は新しく受信した電子メールを処理し、Content Blocker 拡張機能は WebKit コンテンツ ブロック ルールを再利用し、Message Security 拡張機能は署名、暗号化、復号化を処理します。

講演の例は、企業の機密性の拡張です。手紙を書くとき、受信者がプロジェクトと照らし合わせてチェックされます。受信すると、火星プロジェクトのメールが赤でマークされます。メールを開くと、拡張復号化が施されていることがわかります。すべての操作はメールのネイティブ インターフェイス内で行われます。

### MailKit 拡張エントリ

([00:27](https://developer.apple.com/videos/play/wwdc2021/10168/?time=27)) MailKit から`MEExtension`始める。拡張プリンシパル クラスはこのプロトコルを実装し、その機能に従って対応するハンドラーを返します。講演で言及された 4 つの機能はすべて、この入り口を介してメールによって呼び出されます。

```swift
import MailKit

class MailExtension: NSObject, MEExtension {
    func handlerForContentBlocker() -> MEContentBlocker {
        return ContentBlocker.shared
    }

    func handlerForMessageActions() -> MEMessageActionHandler {
        return MessageActionHandler.shared
    }

    func handler(for session: MEComposeSession) -> MEComposeSessionHandler {
        return ComposeSessionHandler()
    }

    func handlerForMessageSecurity() -> MEMessageSecurityHandler {
        return MessageSecurityHandler.shared
    }
}
```

キーポイント:

- `import MailKit`メール拡張子関連のプロトコルと種類を紹介します。
- `MailExtension`継承する`NSObject`、そして気づきます`MEExtension`。
- `handlerForContentBlocker()`コンテンツインターセプトハンドラーを返します。メールは、メールの内容を表示するときにルールを読み取ります。
- `handlerForMessageActions()`Mail が新しいメールをダウンロードするときに呼び出す受信処理ハンドラーを返します。
- `handler(for:)`を受け取る`MEComposeSession`、各作成ウィンドウには独立したセッションがあるため、この例では新しいセッションが返されます。`ComposeSessionHandler`。
- `handlerForMessageSecurity()`署名、暗号化、復号化、および証明書ビューを担当する電子メール セキュリティ ハンドラーを返します。

### 拡張機能の作成: 手紙を書くときに受信者を確認する

([04:31](https://developer.apple.com/videos/play/wwdc2021/10168/?time=271)) Compose 拡張機能は、作成ウィンドウで 4 つのことを行うことができます: 受信者アドレスの確認、追加ビューの提供、追加ヘッダーの設定、送信前のエラー報告です。 Speech のプライバシー拡張機能はこれを使用して、受信者が現在のプロジェクトに属しているかどうかを確認します。

```swift
import MailKit

class ComposeSessionHandler: NSObject, MEComposeSessionHandler {
    func mailComposeSessionDidBegin(_ session: MEComposeSession) {
        // Perform any setup necessary for handling the compose session.
    }

    func mailComposeSessionDidEnd(_ session: MEComposeSession) {
        SpecialProjectHandler.sharedHandler.selectedSpecialProject = nil
    }

    func annotateAddressesForSession(_ session: MEComposeSession) async -> [MEEmailAddress: MEAddressAnnotation] {
        var annotations: [MEEmailAddress: MEAddressAnnotation] = [:]

        for address in session.mailMessage.allRecipientAddresses {
            if !SpecialProjectHandler.verifiedEmails.contains(address) {
                let message = "\(SpecialProjectHandler.bannedDomain) is not a valid domain"
                let annotation = MEAddressAnnotation.error(withLocalizedDescription: message)
                annotations[address] = annotation
            }
        }

        return annotations
    }
}
```

キーポイント:

- `MEComposeSessionHandler`拡張機能を作成ウィンドウのライフサイクルに参加させます。
- `mailComposeSessionDidBegin(_:)`新しい作成ウィンドウが開かれたときに呼び出され、現在のウィンドウ状態を初期化するのに適しています。
- `mailComposeSessionDidEnd(_:)`この例は作成の最後に呼び出され、現在選択されている項目をクリアします。
- `annotateAddressesForSession(_:)`受信者のアドレスが編集されたときに呼び出されます。
- `session.mailMessage.allRecipientAddresses`現在のメッセージのすべての受信者アドレスを入力します。
- `MEAddressAnnotation.error(withLocalizedDescription:)`Mail がアドレス トークンに表示するエラー ラベルを作成します。
-戻り値は`[MEEmailAddress: MEAddressAnnotation]`、キーはマークする必要があるアドレス、値は Mail が表示したいマークです。

([07:53](https://developer.apple.com/videos/play/wwdc2021/10168/?time=473)) Compose 拡張機能では、作成ウィンドウにカスタム UI を表示することもできます。この UI は次のものから来ている必要があります`MEExtensionViewController`サブクラス。

```swift
func viewController(for session: MEComposeSession) -> MEExtensionViewController {
    return ComposeSessionViewController(
        nibName: "ComposeSessionViewController",
        bundle: Bundle.main
    )
}

func additionalHeaders(for session: MEComposeSession) -> [String: [String]] {
    guard let project = SpecialProjectHandler.sharedHandler.selectedSpecialProject else {
        return [:]
    }
    return [SpecialProjectHandler.specialProjectsHeader: [project.rawValue]]
}
```

キーポイント:

- `viewController(for:)`作成ウィンドウを埋め込むメール コントローラーを返します。
- `ComposeSessionViewController`は、この例で特別な項目を選択するために使用されるカスタム UI です。
- `additionalHeaders(for:)`電子メールを送信するときに追加のヘッダーを返します。
- 現在の電子メールに追加のヘッダーが必要ないことを示すために、空の辞書を返します。
- ヘッダーの値は文字列配列です。この例では、プロジェクト名が書き込まれます。`SpecialProjectHandler.specialProjectsHeader`。

### アクション拡張機能: 新しいメールが到着したら自動的に処理します

([08:38](https://developer.apple.com/videos/play/wwdc2021/10168/?time=518)) アクション拡張機能は、メールが新しいメッセージをダウンロードするときに実行されます。既読ステータスとフラグを変更したり、ジャンク、ゴミ箱、アーカイブなどのシステム メールボックスに移動したり、メーリング リスト内の電子メールの色を設定したりできます。

```swift
import MailKit

class MessageActionHandler: NSObject, MEMessageActionHandler {
    static let shared = MessageActionHandler()

    func decideAction(for message: MEMessage) async -> MEMessageActionDecision? {
        if SpecialProjectHandler.SpecialProject.allCases.first(where: { message.subject.contains($0.rawValue) }) != nil {
            return MEMessageActionDecision.action(.setBackgroundColor(.yellow))
        }

        if message.rawData == nil {
            return MEMessageActionDecision.invokeAgainWithBody
        }

        if let projects = message.headers?[SpecialProjectHandler.specialProjectsHeader] {
            if projects.contains(SpecialProjectHandler.SpecialProject.marsRemoteOffice.rawValue) {
                return MEMessageActionDecision.action(.flag(.purple))
            } else if projects.contains(SpecialProjectHandler.SpecialProject.apSpaceShuttle.rawValue) {
                return MEMessageActionDecision.action(.flag(.green))
            }
        }

        if let rawData = message.rawData,
           let text = String(data: rawData, encoding: .utf8),
           SpecialProjectHandler.SpecialProject.allCases.first(where: { text.contains($0.rawValue) }) != nil {
            return MEMessageActionDecision.action(.flag(.red))
        }

        return nil
    }
}
```

キーポイント:

- `MEMessageActionHandler`メールでダウンロードされた新しいメッセージを受信します。
- `decideAction(for:)`戻る`MEMessageActionDecision?`、実行するアクションを Mail に伝えます。
- 最初の段落で使用されます`message.subject`テーマを確認し、プロジェクト名をクリックして背景を黄色に設定します。
- `message.rawData == nil`現在、部分的なヘッダーのみが存在し、完全なテキストがないことを示します。
- `MEMessageActionDecision.invokeAgainWithBody`Mail に完全な本文とヘッダーを取得してからハンドラーを再度呼び出すように要求します。
- `message.headers`Compose 拡張機能によって書き込まれたカスタム ヘッダーを読み取ります。
- `.flag(.purple)`、`.flag(.green)`、`.flag(.red)`電子メールにさまざまなフラグを設定します。
- 戻る`nil`この電子メールが処理されないことを示します。

### コンテンツ ブロッカー: Safari コンテンツ ブロック ルールを再利用する

([11:23](https://developer.apple.com/videos/play/wwdc2021/10168/?time=683)) メールのメッセージ コンテンツ ビューは WebKit に基づいています。 Content Blocker 拡張機能を使用すると、コンテンツ ルールを Mail の WebKit 構成に統合して、HTML 内の URL やその他の条件に基づいてリソースが読み込まれるのを防ぐことができます。この講演では、ルール構文が Safari コンテンツ ブロッカーと同じであることが明確に述べられています。

```swift
import MailKit

class ContentBlocker: NSObject, MEContentBlocker {
    static let shared = ContentBlocker()

    func contentRulesJSON() -> Data {
        guard let url = Bundle.main.url(
            forResource: "ContentBlockerRules",
            withExtension: "json"
        ) else { return Data() }

        guard let data = try? Data(contentsOf: url) else { return Data() }

        return data
    }
}
```

キーポイント:

- `MEContentBlocker`メールコンテンツのブロックルールを提供します。
- `contentRulesJSON()`JSONを返します`Data`コーディング。
- アプリバンドルからの読み取りの例`ContentBlockerRules.json`。
- ファイルが見つからない場合、または読み取りに失敗した場合は null を返します。`Data`, メールには利用可能なルールがありません。
- ルール形式は Safari コンテンツ ブロッカーに従い、既存の Safari ルールをメール拡張機能に移行できます。

ルール ファイル自体は JSON です。

```json
[
    {
        "action": {
            "type": "block"
        },
        "trigger": {
            "url-filter": "webkit.svg",
            "resource-type": ["image", "style-sheet"],
            "if-domain": "example.com"
        }
    }
]
```

キーポイント:

- `action.type`に設定`block`、ヒット後にロードが防止されることを示します。
- `trigger.url-filter`URL ルールを使用してリソースを照合します。
- `resource-type`リソースの種類を制限します。ここでは画像とスタイルシートを一致させます。
- `if-domain`ページのドメイン名を制限します。これは次の場合にのみ適用されます。`example.com`発効します。

### メッセージ セキュリティ: 署名、暗号化、復号化を引き継ぎます。

([12:57](https://developer.apple.com/videos/play/wwdc2021/10168/?time=777)) Message Security 拡張機能は電子メールのセキュリティを処理します。送信時に、現在の電子メールに署名および暗号化できるかどうかを Mail に伝えます。 「送信」をクリックすると、RFC822 メッセージ データを受信し、署名または暗号化された RFC822 データを返します。受信時に、Mail はエンコードされた RFC822 データを拡張機能に渡し、拡張機能はデコードされた電子メールを返します。

```swift
import MailKit

class MessageSecurityHandler: NSObject, MEMessageSecurityHandler {
    static let shared = MessageSecurityHandler()

    func encodingStatus(
        for message: MEMessage,
        composeContext: MEComposeContext
    ) async -> MEOutgoingMessageEncodingStatus {
        let invalidRecipients = message.allRecipientAddresses.filter({ address in
            return !SpecialProjectHandler.verifiedEmails.contains(address)
        })

        if !invalidRecipients.isEmpty {
            return MEOutgoingMessageEncodingStatus(
                canSign: false,
                canEncrypt: false,
                securityError: MessageSecurityError.unverifiedEmails(emailAdresses: invalidRecipients),
                addressesFailingEncryption: invalidRecipients
            )
        } else {
            let encoder = MockEncoder.sharedInstance
            let encodingStatus = encoder.securityStatus(for: message)
            return encodingStatus
        }
    }

    func encode(_ message: MEMessage, composeContext: MEComposeContext) async -> MEMessageEncodingResult {
        return MockEncoder.sharedInstance.encodedMessage(for: message, context: composeContext)
    }
}
```

キーポイント:

- `MEMessageSecurityHandler`電子メール セキュリティ ハンドラー プロトコルです。
- `encodingStatus(for:composeContext:)`送信者または受信者が変更されたときに呼び出され、ロックおよび証明書アイコンの状態を制御するために使用されます。
- `message.allRecipientAddresses`現在の受信者のリストを提供します。
- `MEOutgoingMessageEncodingStatus`署名の可否、暗号化の可否、エラー情報、暗号化に失敗したアドレスを返します。
- `encode(_:composeContext:)`電子メールの送信時に呼び出されます。
- サンプルでは、​​実際のコーディング作業は任せます`MockEncoder.sharedInstance.encodedMessage(for:context:)`。

([16:05](https://developer.apple.com/videos/play/wwdc2021/10168/?time=965)) 電子メールの表示中にデコードプロセスが発生します。拡張機能が電子メールを処理できる場合は、戻り値が返されます。`MEDecodedMessage`;処理が必要ない場合はすぐに戻ってください`nil`。

```swift
func decodedMessage(forMessageData data: Data) -> MEDecodedMessage? {
    let decoder = ExampleDecoder.sharedInstance

    if decoder.shouldDecodeMessage(withData: data) {
        return decoder.decodedMessage(from: data)
    }

    return nil
}

func extensionViewController(signers messageSigners: [MEMessageSigner]) -> MEExtensionViewController? {
    let controller = ExampleSigningViewController.sharedInstance
    controller.signers = messageSigners
    return controller
}
```

キーポイント:

- `decodedMessage(forMessageData:)`エンコードされた RFC822 データを受信します。
- `shouldDecodeMessage(withData:)`無関係な電子メールの速度が低下しないように、拡張機能を処理する必要があるかどうかを最初に判断します。
- `decodedMessage(from:)`復号化または署名された電子メール データ、および署名と暗号化のステータスを返します。
- `extensionViewController(signers:)`証明書情報 UI を返します。
- `messageSigners`拡張機能をデコードするときに返された署名者情報から、Mail はそれを証明書ビューに返します。

## 重要なポイント

1. **対処方法**: 企業メールにプロジェクト レベルの受信者検証を追加します。
**実行する価値がある理由**: ユーザーがアドレスを編集すると Compose 拡張機能が返されることがあります`MEAddressAnnotation`の場合、エラーはメール アドレス トークンに直接表示されます。
**開始方法**: メール拡張ターゲットを作成し、セッション ハンドラーの作成を確認し、`annotateAddressesForSession(_:)`読み込む`session.mailMessage.allRecipientAddresses`、エンタープライズ権限テーブルを使用して注釈を生成します。

2. **対処方法**: プロジェクトの電子メールに別の色またはフラグを自動的に付けます。
**実行する価値がある理由**: アクション拡張機能は、新しいメールが受信トレイに入る前に実行されるため、ユーザーはメールを開いたときにすでに分類結果が表示されます。
**開始方法**: 実装`MEMessageActionHandler.decideAction(for:)`、まず確認してください`message.subject`そして`message.headers`、テキストが必要な場合に戻ります`MEMessageActionDecision.invokeAgainWithBody`。

3. **対処方法**: 電子メール内のリモート追跡画像をブロックします。
**実行する価値がある理由**: コンテンツ ブロッカー拡張機能は Safari コンテンツ ブロッカーのルール形式を使用しており、既存の WebKit ルールを再利用できます。
**開始方法**: 実装`MEContentBlocker.contentRulesJSON()`、リモート画像ドメイン名をブロックする JSON ルールをアプリバンドルに追加します。

4. **やるべきこと**: エンタープライズ証明書システムをメール送信プロセスに統合します。
**実行する価値がある理由**: Message Security 拡張機能は、現在の受信者に基づいて署名と暗号化のステータスを返すことができ、Mail はそれをロックと証明書のアイコンでユーザーにフィードバックします。
**開始方法**: 実装`encodingStatus(for:composeContext:)`証明書の利用可能性を確認してから、`encode(_:composeContext:)`エンコードされた RFC822 データを返します。

5. **対処方法**: 暗号化された電子メール用のカスタム証明書の詳細ページを提供します。
**実行する価値がある理由**: メールでは延長による返品が可能です`MEExtensionViewController`署名者またはメッセージのコンテキストを表示し、企業は内部証明書フィールドを表示できます。
**開始方法**: メールをデコードするときに署名者情報を返す、実装する`extensionViewController(signers:)`そして、署名者のデータをカスタム ビューに入力します。
