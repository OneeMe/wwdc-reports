## ハイライト

> Apple は SwiftUI と HealthKit で Apple Watch 運動 App をゼロから構築するデモを行いました。リアルタイムの心拍、エネルギー、距離を収集し、運動記録を保存し、TimelineView で Always On に適応します。

## 主要内容

Apple Watch 運動 App を作る上で、難しいのはボタンの数ではありません。

本当の難しさは運動開始後に始まります。ユーザーが走ったり漕いだりすると、手首は上下し、画面は Always On の低頻度更新に入ります。App は経過時間、エネルギー、心拍、距離を表示し続け、終了後に HealthKit に記録を保存する必要があります。

以前はこのロジックを SwiftUI ビューに散らばせると、UI、権限、セッション状態、データ収集が混ざります。一時停止ボタンはセッション状態を変え、サマリーページは保存完了を待ち、リアルタイム指標は画面の更新頻度に合わせる必要がありました。

この Code-Along では Apple が完全なパスに分解します。SwiftUI の 3 画面構造、`WorkoutManager` による HealthKit セッション管理、Always On 下で指標ページを適切に更新する `TimelineView` です。

### ワンタップで運動を開始

ユーザーが運動 App を開いたとき、最初に複雑な設定を見せるべきではありません。起点は `StartView` で、3 種類の運動——自転車、ランニング、ウォーキングです。各項目は `NavigationLink` で直接運動セッションに入れます。

タップ後、運動画面は watchOS 共通の 3 ページ構成になります。左にコントロール、中央に指標、右に Now Playing。デフォルトは指標ページ——運動開始後、ユーザーが最も気にするのは時間、エネルギー、心拍、距離です。

### 1 つのオブジェクトで運動ライフサイクルを管理

HealthKit の運動セッションには明確なフローがあります。権限要求、設定作成、`HKWorkoutSession` の開始、`HKLiveWorkoutBuilder` によるデータ収集、完了時に `HKWorkout` として保存です。

このセッションではその状態を `WorkoutManager` に置きます。SwiftUI ビューは `@EnvironmentObject` で読み取ります。ボタンは一時停止や終了だけをトリガーし、指標ページは公開されたデータを表示するだけです。

### Always On が更新方式を変える

Apple Watch の Always On は更新頻度を下げます。運動 App は高頻度で百分秒を表示し続けられません——不適切であり、Always On の情報ニーズにも合いません。

解決策は `TimelineView` です。`TimelineScheduleMode` で更新間隔を決め、`context.cadence` で百分秒表示を制御します。画面がアクティブなときは細かい時間、低頻度状態では分と秒だけを表示します。

### 経過時間のフォーマット

（[11:42](https://developer.apple.com/videos/play/wwdc2021/10009/?time=702)) 経過時間は普通の数字では表示できません。`ElapsedTimeView` と `ElapsedTimeFormatter` を作り、`DateComponentsFormatter` で分と秒を出力し、必要に応じて百分秒を追加します。

```swift
struct ElapsedTimeView: View {
    var elapsedTime: TimeInterval = 0
    var showSubseconds: Bool = true
    @State private var timeFormatter = ElapsedTimeFormatter()

    var body: some View {
        Text(NSNumber(value: elapsedTime), formatter: timeFormatter)
            .fontWeight(.semibold)
            .onChange(of: showSubseconds) {
                timeFormatter.showSubseconds = $0
            }
    }
}

class ElapsedTimeFormatter: Formatter {
    let componentsFormatter: DateComponentsFormatter = {
        let formatter = DateComponentsFormatter()
        formatter.allowedUnits = [.minute, .second]
        formatter.zeroFormattingBehavior = .pad
        return formatter
    }()
    var showSubseconds = true

    override func string(for value: Any?) -> String? {
        guard let time = value as? TimeInterval else {
            return nil
        }

        guard let formattedString = componentsFormatter.string(from: time) else {
            return nil
        }

        if showSubseconds {
            let hundredths = Int((time.truncatingRemainder(dividingBy: 1)) * 100)
            let decimalSeparator = Locale.current.decimalSeparator ?? "."
            return String(format: "%@%@%0.2d", formattedString, decimalSeparator, hundredths)
        }

        return formattedString
    }
}
```

キーポイント:
- `ElapsedTimeView` は `TimeInterval` を受け取る。
- `showSubseconds` は百分秒表示を制御する。
- `Text(NSNumber(value:), formatter:)` で SwiftUI にカスタム formatter を使わせる。
- `DateComponentsFormatter` は分と秒を担当する。
- `allowedUnits = [.minute, .second]` で出力単位を限定する。
- `zeroFormattingBehavior = .pad` で `03:15` のようなゼロ埋め形式を保つ。
- `truncatingRemainder(dividingBy: 1)` で小数部分を取得する。
- `Locale.current.decimalSeparator` は現在のロケールの小数点を使う。

### HealthKit 権限のリクエスト

（[29:35](https://developer.apple.com/videos/play/wwdc2021/10009/?time=1775)) 運動 App は workout を書き込み、心拍、エネルギー、距離、アクティビティリングを読み取ります。HealthKit 権限は `WorkoutManager` で一括リクエストします。

```swift
// Request authorization to access HealthKit.
func requestAuthorization() {
    // The quantity type to write to the health store.
    let typesToShare: Set = [
        HKQuantityType.workoutType()
    ]

    // The quantity types to read from the health store.
    let typesToRead: Set = [
        HKQuantityType.quantityType(forIdentifier: .heartRate)!,
        HKQuantityType.quantityType(forIdentifier: .activeEnergyBurned)!,
        HKQuantityType.quantityType(forIdentifier: .distanceWalkingRunning)!,
        HKQuantityType.quantityType(forIdentifier: .distanceCycling)!,
        HKObjectType.activitySummaryType()
    ]

    // Request authorization for those quantity types.
    healthStore.requestAuthorization(toShare: typesToShare, read: typesToRead) { (success, error) in
        // Handle error.
    }
}
```

キーポイント:
- `typesToShare` は書き込む運動記録を宣言する。
- `HKQuantityType.workoutType()` は workout タイプを表す。
- `typesToRead` は読み取る HealthKit データを宣言する。
- `.heartRate` は現在と平均心拍に使う。
- `.activeEnergyBurned` は活動エネルギーに使う。
- `.distanceWalkingRunning` と `.distanceCycling` は歩行・ランニング距離とサイクリング距離に対応する。
- `HKObjectType.activitySummaryType()` はサマリーのアクティビティリングに使う。
- `requestAuthorization` はシステム権限リクエストを開始する。

（[30:20](https://developer.apple.com/videos/play/wwdc2021/10009/?time=1820)) 開始ページが表示されたときに権限をリクエストします。

```swift

```

キーポイント:
- `.onAppear` は開始ページ表示時に実行される。

### 運動セッションの開始

（[27:42](https://developer.apple.com/videos/play/wwdc2021/10009/?time=1662)) リアルタイムの HealthKit 運動は `HKWorkoutSession` と `HKLiveWorkoutBuilder` に依存します。前者がセッション状態、後者がリアルタイムデータ収集と最終 workout 生成を担当します。

```swift
func startWorkout(workoutType: HKWorkoutActivityType) {
    let configuration = HKWorkoutConfiguration()
    configuration.activityType = workoutType
    configuration.locationType = .outdoor

    do {
        session = try HKWorkoutSession(healthStore: healthStore, configuration: configuration)
        builder = session?.associatedWorkoutBuilder()
    } catch {
        // Handle any exceptions.
        return
    }

    builder?.dataSource = HKLiveWorkoutDataSource(
        healthStore: healthStore,
        workoutConfiguration: configuration
    )

    // Start the workout session and begin data collection.
    let startDate = Date()
    session?.startActivity(with: startDate)
    builder?.beginCollection(withStart: startDate) { (success, error) in
        // The workout has started.
    }
}
```

キーポイント:
- `HKWorkoutConfiguration` は運動タイプと位置タイプを保持する。
- `activityType` は開始ページでのユーザー選択から来る。
- `locationType = .outdoor` は屋外運動に設定する。
- `HKWorkoutSession` は HealthKit 運動セッションを作成する。
- `associatedWorkoutBuilder()` はセッションに紐づく builder を取得する。
- `HKLiveWorkoutDataSource` は builder がリアルタイム HealthKit データを取得できるようにする。
- `startDate` はセッションとデータ収集の共通起点である。
- `startActivity(with:)` で運動セッションを開始する。
- `beginCollection(withStart:)` でリアルタイムサンプルの収集を開始する。

（[29:06](https://developer.apple.com/videos/play/wwdc2021/10009/?time=1746)) 運動タイプを選ぶと自動的にセッションが開始されます。

```swift
var selectedWorkout: HKWorkoutActivityType? {

        guard let selectedWorkout = selectedWorkout else { return }
        startWorkout(workoutType: selectedWorkout)
    }
}
```

キーポイント:
- `selectedWorkout` はユーザーが選んだ運動を記録する。
- `didSet` は選択が変わった後に実行される。
- `guard` は nil を除外する。
- `startWorkout(workoutType:)` はナビゲーション選択と HealthKit セッションを接続する。

### 一時停止、再開、終了

（[33:29](https://developer.apple.com/videos/play/wwdc2021/10009/?time=2009)) 運動コントロールは `WorkoutManager` 経由で公開されます。UI ボタンは HealthKit セッションに直接触れず、これらのメソッドだけを呼びます。

```swift
// MARK: - State Control

// The workout session state.
@Published var running = false

func pause() {
    session?.pause()
}

func resume() {
    session?.resume()
}

func togglePause() {
    if running == true {
        pause()
    } else {
        resume()
    }
}

func endWorkout() {
    session?.end()
}
```

キーポイント:
- `@Published var running` は実行状態を SwiftUI に公開する。
- `pause()` は HealthKit セッションを一時停止する。
- `resume()` は HealthKit セッションを再開する。
- `togglePause()` は現在の状態に応じて動作を切り替える。
- `endWorkout()` はセッションを終了する。

（[34:11](https://developer.apple.com/videos/play/wwdc2021/10009/?time=2051)) セッション状態の変化は `HKWorkoutSessionDelegate` で返されます。終了時はまずデータ収集を止め、その後 workout 保存を完了します。

```swift
// MARK: - HKWorkoutSessionDelegate
extension WorkoutManager: HKWorkoutSessionDelegate {
    func workoutSession(_ workoutSession: HKWorkoutSession,
                        didChangeTo toState: HKWorkoutSessionState,
                        from fromState: HKWorkoutSessionState,
                        date: Date) {
        DispatchQueue.main.async {
            self.running = toState == .running
        }

        // Wait for the session to transition states before ending the builder.
        if toState == .ended {
            builder?.endCollection(withEnd: date) { (success, error) in
                self.builder?.finishWorkout { (workout, error) in
                }
            }
        }
    }

    func workoutSession(_ workoutSession: HKWorkoutSession, didFailWithError error: Error) {

    }
}
```

キーポイント:
- `HKWorkoutSessionDelegate` はセッション状態変化を受け取る。
- `didChangeTo` は新状態、旧状態、変化時刻を提供する。
- `DispatchQueue.main.async` で `running` 更新をメインスレッドに戻す。
- `toState == .running` は一時停止ボタン状態の更新に使う。
- `toState == .ended` はセッション終了を意味する。
- `endCollection(withEnd:)` でデータ収集を停止する。
- `finishWorkout` は保存し `HKWorkout` を生成する。

### リアルタイム指標の収集

キーポイント:

- `activeEnergy` は累積活動エネルギーを保持する。

（[41:05](https://developer.apple.com/videos/play/wwdc2021/10009/?time=2465)) `HKLiveWorkoutBuilderDelegate` はどのサンプルタイプに新データがあるかを通知します。

```swift
// MARK: - HKLiveWorkoutBuilderDelegate
extension WorkoutManager: HKLiveWorkoutBuilderDelegate {
    func workoutBuilderDidCollectEvent(_ workoutBuilder: HKLiveWorkoutBuilder) {
    }

    func workoutBuilder(_ workoutBuilder: HKLiveWorkoutBuilder, didCollectDataOf collectedTypes: Set<HKSampleType>) {
        for type in collectedTypes {
            guard let quantityType = type as? HKQuantityType else { return }

            let statistics = workoutBuilder.statistics(for: quantityType)

            // Update the published values.
            updateForStatistics(statistics)
        }
    }
}
```

キーポイント:
- `HKLiveWorkoutBuilderDelegate` は builder の収集イベントを受け取る。
- `didCollectDataOf` は今回の更新に関わるデータタイプを提供する。
- `collectedTypes` には心拍、エネルギー、距離が含まれる場合がある。
- `guard let quantityType` は数量タイプのみを処理する。
- `statistics(for:)` は builder から統計を取得する。
- `updateForStatistics` は HealthKit 統計を UI データに変換する。

（[42:01](https://developer.apple.com/videos/play/wwdc2021/10009/?time=2521)) 指標ごとに異なる単位と統計方法を使います。

```swift
func updateForStatistics(_ statistics: HKStatistics?) {
    guard let statistics = statistics else { return }

    DispatchQueue.main.async {
        switch statistics.quantityType {
        case HKQuantityType.quantityType(forIdentifier: .heartRate):
            let heartRateUnit = HKUnit.count().unitDivided(by: HKUnit.minute())
            self.heartRate = statistics.mostRecentQuantity()?.doubleValue(for: heartRateUnit) ?? 0
            self.averageHeartRate = statistics.averageQuantity()?.doubleValue(for: heartRateUnit) ?? 0
        case HKQuantityType.quantityType(forIdentifier: .activeEnergyBurned):
            let energyUnit = HKUnit.kilocalorie()
            self.activeEnergy = statistics.sumQuantity()?.doubleValue(for: energyUnit) ?? 0
        case HKQuantityType.quantityType(forIdentifier: .distanceWalkingRunning), HKQuantityType.quantityType(forIdentifier: .distanceCycling):
            let meterUnit = HKUnit.meter()
            self.distance = statistics.sumQuantity()?.doubleValue(for: meterUnit) ?? 0
        default:
            return
        }
    }
}
```

キーポイント:
- 空の `statistics` では即座に return する。
- UI 関連状態はメインスレッドで更新する。
- 心拍単位は `count/minute` である。
- `mostRecentQuantity()` は現在の心拍を取得する。
- `averageQuantity()` は平均心拍を取得する。
- 活動エネルギーはキロカロリー単位を使う。
- `sumQuantity()` は累積エネルギーを取得する。
- 歩行・ランニング距離とサイクリング距離はメートルに変換する。
- 未処理タイプは `default` に入る。

### Always On でのタイムライン更新

（[45:51](https://developer.apple.com/videos/play/wwdc2021/10009/?time=2751)) Always On では運動指標の更新頻度を下げる必要があります。`TimelineSchedule` をカスタマイズします。

```swift
private struct MetricsTimelineSchedule: TimelineSchedule {
    var startDate: Date

    init(from startDate: Date) {
        self.startDate = startDate
    }

    func entries(from startDate: Date, mode: TimelineScheduleMode) -> PeriodicTimelineSchedule.Entries {
        PeriodicTimelineSchedule(
            from: self.startDate,
            by: (mode == .lowFrequency ? 1.0 : 1.0 / 30.0)
        ).entries(
            from: startDate,
            mode: mode
        )
    }
}
```

キーポイント:
- `MetricsTimelineSchedule` は `TimelineSchedule` に準拠する。
- `startDate` は運動開始時刻を記録する。
- `entries(from:mode:)` はシステムモードに応じて更新時刻を生成する。
- `mode == .lowFrequency` は低頻度更新を意味する。
- 低頻度では 1 秒ごとに更新する。
- アクティブ状態では `1.0 / 30.0` 秒ごとに更新する。
- `PeriodicTimelineSchedule` は周期的な entries を作る。

### 運動サマリーとアクティビティリング

（[21:00](https://developer.apple.com/videos/play/wwdc2021/10009/?time=1260)) 終了後、サマリーで当日のアクティビティリングを表示できます。SwiftUI は `WKInterfaceObjectRepresentable` で WatchKit の `WKInterfaceActivityRing` をラップします。

```swift
import HealthKit
import SwiftUI

struct ActivityRingsView: WKInterfaceObjectRepresentable {
    let healthStore: HKHealthStore

    func makeWKInterfaceObject(context: Context) -> some WKInterfaceObject {
        let activityRingsObject = WKInterfaceActivityRing()

        let calendar = Calendar.current
        var components = calendar.dateComponents([.era, .year, .month, .day], from: Date())
        components.calendar = calendar

        let predicate = HKQuery.predicateForActivitySummary(with: components)

        let query = HKActivitySummaryQuery(predicate: predicate) { query, summaries, error in
            DispatchQueue.main.async {
                activityRingsObject.setActivitySummary(summaries?.first, animated: true)
            }
        }

        healthStore.execute(query)

        return activityRingsObject
    }

    func updateWKInterfaceObject(_ wkInterfaceObject: WKInterfaceObjectType, context: Context) {

    }
}
```

キーポイント:
- `WKInterfaceObjectRepresentable` は WatchKit オブジェクトを SwiftUI にブリッジする。
- `healthStore` は HealthKit クエリを実行する。
- `WKInterfaceActivityRing` はアクティビティリングコントロールである。
- `dateComponents` は当日の日付を取得する。
- `predicateForActivitySummary` は当日のアクティビティサマリークエリを作る。
- `HKActivitySummaryQuery` はアクティビティサマリーを読み取る。
- `setActivitySummary` はクエリ結果をリングコントロールに設定する。
- `DispatchQueue.main.async` で UI 更新をメインスレッドで行う。

## 重要ポイント

- **何をするか**: 屋外ウォーキング記録器を作り、開始・一時停止・終了と 4 つのコア指標だけを残す。
  **なぜ価値があるか**: このセッションは既に `HKWorkoutSession`、`HKLiveWorkoutBuilder`、指標ページ構造を提供している。
  **どう始めるか**: `workoutTypes` を `.walking` に絞り、`startWorkout(workoutType:)` でセッション開始、`distanceWalkingRunning` と `heartRate` で UI を更新。

- **何をするか**: サイクリング向けのミニマル心拍画面を作る。
  **なぜ価値があるか**: `TimelineView` は Always On でも読みやすい情報を保ち、`monospacedDigit()` は運動中のちらっと見に適している。
  **どう始めるか**: `MetricsTimelineSchedule` を再利用し、`heartRate`、`averageHeartRate`、経過時間だけ表示。`context.cadence == .live` で時間精度を制御。

- **何をするか**: 運動後の振り返りサマリーページを作る。
  **なぜ価値があるか**: `HKWorkout` には既に総時間、総距離、総エネルギーがあり、アクティビティリングは `HKActivitySummaryQuery` で取得できる。
  **どう始めるか**: `finishWorkout` 後に `workout` を保存し、`SummaryMetricView` で `duration`、`totalDistance`、`totalEnergyBurned` を表示し、`ActivityRingsView` を埋め込む。

- **何をするか**: Apple Watch メディアコントロール付きランニング App を作る。
  **なぜ価値があるか**: 運動中は曲の切り替えが必要で、3 ページ構成は既に右側に `NowPlayingView` を置いている。
  **どう始めるか**: `SessionPagingView` に `NowPlayingView().tag(Tab.nowPlaying)` を残し、`PageTabViewStyle` と `isLuminanceReduced` で Always On のページ表示を制御。

- **何をするか**: 走走交替トレーニングなど、特定トレーニング向けの watchOS ツールを作る。
  **なぜ価値があるか**: `running`、`pause()`、`resume()`、`togglePause()` がセッション制御を抽象化し、ビューはトレーニングフローに集中できる。
  **どう始めるか**: `WorkoutManager` 外にトレーニングフェーズ状態を追加し、フェーズ切り替えで SwiftUI テキストを更新。HealthKit は `session?.pause()` と `session?.resume()` を使う。
