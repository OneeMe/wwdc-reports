## ハイライト

> ウィジェット コードの 3 番目のエピソードでは、ウィジェット拡張機能内で URLSession を処理すること、SwiftUI `Link` を使用してアプリ コンテンツにジャンプすること、`WidgetBundle` を使用して複数のウィジェットを公開すること、および Intent Extension を介して構成に動的オプションを提供することを示します。

## 主な内容

エピソード 3 は、基本的なタイムラインがすでにあるプロジェクトの続きです。新しいリーダーボード ウィジェットには、健康状態によって並べ替えられた役割が表示されます。問題が発生します。ウィジェットはデータをフェッチする必要があり、各行はアプリ内のキャラクターの詳細にジャンプする必要があり、元の Ranger Detail ウィジェットと一緒にウィジェット ギャラリーに表示する必要もあります。

これらの要件は、ウィジェット拡張の境界で固定されています。ネットワーク リクエストがホスト アプリによって引き継がれると想定することはできません。クリック可能な領域はウィジェットの SwiftUI ビュー内に収まる必要があります。同じ拡張子内に存在できる「@main」は 1 つだけです。アプリに書き込みメソッドを直接インポートすると、開発者はすぐにこれらの境界に遭遇することになります。

Apple は、このコードに沿って境界を 1 つずつ細分化します。タイムライン プロバイダーは完了ハンドラーを使用して非同期リクエストをサポートします。ウィジェット自体は、バックグラウンド セッションを含む、ウィジェットが作成する URLSession に応答します。 SwiftUI の「Link」は、ウィジェット コンテンツの行をディープ リンク エントリに変換できます。 `WidgetBundle` は複数のウィジェットを同じ拡張機能に配置する役割を果たします。 Intent Extension は、元のハードコーディングされた構成リストを動的なオプションに置き換えます。

最終的には、実際のアプリに近いウィジェットが作成されます。データをフェッチし、指定されたコンテンツにジャンプし、拡張機能に複数のエントリを提供し、構成リストがリモート データの変更に従うことができるようにします。

##詳細

### 1. ウィジェット拡張機能でデータを取得する

([01:28](https://developer.apple.com/videos/play/wwdc2020/10036/?time=88)) Leaderboard ウィジェットのデータは、`CharacterDetail` の `loadLeaderboardData` 非同期リクエストから取得されます。トランスクリプトには、タイムライン プロバイダー API が完了ハンドラーを使用して、ネットワーク フェッチなどの非同期タスクに簡単にアクセスできるようにすることが明確に記載されています。

このセッションには公開されている「コード」タブ スニペットはありません。トランスクリプトに表示される呼び出しフォームのみが以下に保持され、ビジネスの実装は完了していません。```text
CharacterDetail.loadLeaderboardData
URLSession
data task
```キーポイント:

- `loadLeaderboardData` は、リーダーボード データの非同期エントリです。
- タイムライン プロバイダーは、完了ハンドラーに依存して、非同期タスクが完了するのを待ちます。
- セッションは通常のインプロセス URL セッションで示されます。
- このリクエストはローカル ファイルを使用してリモート フェッチをシミュレートします。実際のプロジェクトでは、通常、リモート Web サービスが呼び出されます。

([02:20](https://developer.apple.com/videos/play/wwdc2020/10036/?time=140)) バックグラウンド セッションにはウィジェットに特別な点があります。つまり、完了時に拡張機能のホスティング アプリは起動しません。ウィジェットは、バックグラウンド セッションを含む、ウィジェット自体が作成したすべての URLSession に応答します。```text
onBackgroundURLSessionEvents
sessionIdentifier
completion block
```キーポイント:

- `onBackgroundURLSessionEvents` はウィジェット設定の修飾子です。
- アプリにおける一般的なアプリケーションデリゲートコールバック責任に対応します。
- システムは `sessionIdentifier` と完了ブロックを提供します。
- トランスクリプトでは、管理方法がアプリ内と同じであることのみが説明されており、特定のキューや永続化戦略については詳しく説明されていません。

### 2. SwiftUI Link を使用してウィジェット内にジャンプします

([03:20](https://developer.apple.com/videos/play/wwdc2020/10036/?time=200)) Leaderboard の各行は、「AllCharactersView」の「HStack」です。目標は、キャラクターをクリックすると、そのキャラクターの情報ページが直接開くことです。```swift
Link(destination: character.url) {
    HStack {
        ...
    }
}
```キーポイント:

- 「Link」はセッション内で名前が付けられた新しい SwiftUI API です。
- `destination` はロール独自の URL を使用します。
- 元の `HStack` はこの行の内容を保持しています。
- ウィジェットの行をクリックすると、システムはその行を強調表示し、対応するキャラクターの詳細を開きます。

### 3. WidgetBundle を使用して複数のウィジェットを公開する

([04:36](https://developer.apple.com/videos/play/wwdc2020/10036/?time=276)) プロジェクトにはリーダーボード ウィジェットとレンジャー詳細ウィジェットがありますが、プロセス内に存在できる「@main」は 1 つだけです。解決策は、「@main」を単一のウィジェットからバンドルに移動することです。```text
@main -> WidgetBundle
WidgetBundle -> Leaderboard widget
WidgetBundle -> Ranger Detail widget
```キーポイント:

- `WidgetBundle` は、同じ拡張機能内で複数のウィジェットを宣言するために使用されます。
- `@main` は 2 つのウィジェットに個別に配置されるのではなく、バンドルに配置されます。
- セッションでのデモンストレーションの結果、Leaderboard ウィジェットと Ranger Detail ウィジェットの両方がウィジェット ギャラリーに表示されます。
- この構造は、複数の情報入口を提供するアプリに適しています。

### 4. インテント拡張を使用して動的構成オプションを提供する

([05:31](https://developer.apple.com/videos/play/wwdc2020/10036/?time=331)) 前のエピソードにはすでに構成可能なウィジェットがありましたが、オプションのリストはハードコーディングされていました。 3 番目のエピソードでは、SiriKit インテントのパラメータのタイプがカスタム タイプに変更され、動的リストが Intent Extension によって提供されます。```text
IntentHandler
identifier
displayString
CharacterDetail.remoteCharacters
Intent identifier -> characterFromName
```キーポイント:

- カスタム インテント タイプには、デフォルトで `identifier` と `displayString` という 2 つの属性があります。
- これらの値は `IntentHandler` から取得されます。
・オプション提供処理もタイムライン方式と同様に非同期で呼び出されます。
- ネットワークからより多くの文字を取得することをシミュレートするために、セッションのオプション リストに `CharacterDetail.remoteCharacters` を追加します。
- ウィジェットはユーザーの選択を読み取るときに、インテント識別子を使用して対応するロールを取得します。

([08:01](https://developer.apple.com/videos/play/wwdc2020/10036/?time=481)) 構成インターフェイスが最終的に表示され、元のオプション Power Panda、Egghead、Spouty とリモート オプション Mr Spook、Cake、Octo が表示されます。ユーザーが Mr. Spook を選択すると、ホーム画面のウィジェットにそのキャラクターが表示されます。

## 重要なポイント

### 1. リモートランキングウィジェットを作成する

- **何をすべきか**: サーバーのリーダーボードをホーム画面に表示し、最新のスコアまたはステータスで並べ替えます。
- **実行する価値がある理由**: セッションは、Leaderboard ウィジェットが非同期リクエストを通じてロール リストを取得することを明確に示しています。
- **開始方法**: まず、タイムライン プロバイダーを既存のフェッチ メソッドに接続します。リクエストがバックグラウンドで完了する可能性がある場合は、ウィジェット設定で `onBackgroundURLSessionEvents` を接続します。

### 2. クリック可能なリスト ウィジェットを作成する

- **手順**: ウィジェットの各行で、アプリ内の対応する詳細ページが開かれるようにします。
- **実行する価値がある理由**: セッションでは、「HStack」を SwiftUI の「Link」にラップし、宛先をロール URL に指定する方法を示します。
- **開始方法**: ウィジェット行の外側の `Link(destination:)` を使用して、リスト内の各エンティティの URL を準備します。

### 3. 1 つの拡張機能を使用して複数のウィジェットを提供する

- **内容**: 概要ウィジェットと詳細ウィジェットの両方を提供します。
- **実行する価値がある理由**: このセッションでは、Leaderboard ウィジェットと Ranger Detail ウィジェットが「WidgetBundle」を通じて同時にウィジェット ギャラリーに入ることが示されています。
- **開始方法**: `@main` を `WidgetBundle` に移動し、バンドル本体に複数のウィジェットをリストします。

### 4. サーバー側主導のウィジェットを構成する

- **内容**: ユーザーがウィジェットを構成するときに、最新のプロジェクト、デバイス、ロール、またはフォローしている人々を表示できるようにします。
- **実行する価値がある理由**: セッションは、インテント拡張を通じてハードコーディングされたリストを動的オプションに拡張します。
- **開始方法**: インテント パラメーターをカスタム タイプに変更し、`IntentHandler` の `identifier` と `displayString` でオプションを返し、ウィジェット内の識別子を通じてエンティティを取得します。
