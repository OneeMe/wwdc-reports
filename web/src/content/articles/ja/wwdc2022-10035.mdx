## ハイライト

> MapKit チームの Eric と Yingxiu が、iOS 16 の MapKit への 5 つの主要なアップデートについて説明します。Apple Maps の新しい地図と没入型の Look Around エクスペリエンスがリリースされて以来、対象範囲はカナダ、ヨーロッパの複数の国、日本にまで拡大し、昨年は車線区分線、横断歩道、自転車レーンを備えた 3D 都市エクスペリエンスが導入されました。今年、MapKit はこれらすべての機能をサードパーティ開発者に公開しました。

---

## 主要内容
地図アプリの難しさは「地図を載せること」ではありません。難しいのは、地図とビジネス コンテンツをどのように共存させるかです。

レンタカー、ナビゲーション、旅行、店舗の場所などのアプリは、通常、操作エリア、ルート、興味​​のあるポイント、詳細カードを地図上にオーバーレイします。以前は、このコンテンツは簡単にマップ ラベルを覆い隠したり、3D 都市の建物によって隠されたりする可能性がありました。ユーザーに見えるのはビジネス グラフィックスのレイヤーであり、地図自体の道路、建物、地形は背景に隠れます。

([02:13](https://developer.apple.com/videos/play/wwdc2022/10035/?time=133)) iOS 16 の MapKit は、まずアップグレード コストを削減します。新しい SDK で再コンパイルした後、iOS、macOS、tvOS アプリは自動的に新しい Apple マップを使用し、利用可能なエリアで 3D シティ エクスペリエンスを表示します。次に、MapKit には、構成、オーバーレイ、ブレンディング モード、選択可能な地図機能、Look Around の 5 つの API セットが追加され、ビジネス コンテンツが実際の地図に対して機能できるようになりました。

この講演のサンプル アプリは、サンフランシスコのスクーター レンタル アプリです。これには、エリアの操作、サイクリング ルート、ウォーターフロントの名所の探索、アトラクションの閲覧 Look Around の 4 つの機能があります。後続の各 API は、この特定のシナリオに該当します。

## 詳細
### Map Configuration API を使用してマップをアトミックに構成する

([02:41](https://developer.apple.com/videos/play/wwdc2022/10035/?time=161)) iOS 15 より前、開発者は`MKMapView`マップ上で複数のプロパティを構成します。 iOS 16 では、これらの散在するプロパティをそっと破棄し、`MKMapConfiguration`新しい中央エントランスとして。

`MKMapConfiguration`これは、次の 3 つの特定の構成を持つ抽象基本クラスです。

- `MKImageryMapConfiguration`：衛星画像のみを表示します。
-`MKHybridMapConfiguration`: イメージ マップを表示し、道路ラベルや名所などの地図の機能をオーバーレイします。
-`MKStandardMapConfiguration`: 完全にグラフィカルな標準地図を表示します。

これらの構成は地形も制御します。`elevationStyle`できる`flat`または`realistic`。標準マップもサポート`emphasisStyle`、で`muted`これにより、マップの詳細のコントラストが減り、独自のグラフィック コンテンツに注意が向けられます。

```swift
// 概念示例：根据 transcript 中出现的配置类和属性整理，省略真实项目中的兼容性判断。
let configuration = MKStandardMapConfiguration()
configuration.elevationStyle = .realistic
configuration.emphasisStyle = .muted
configuration.showsTraffic = true

mapView.preferredConfiguration = configuration
```

キーポイント:

- `MKStandardMapConfiguration()`スピーチの「完全にグラフィックベースのマップ」に相当する、グラフィックの標準マップを選択します。
-`elevationStyle = .realistic`現実的な地形をリクエストすると、地図には丘、道路の高低差、3D 都市効果が表示されます。
-`emphasisStyle = .muted`地図の詳細のコントラストを下げて、オーバーレイされたビジネス グラフィックをより目立たせるようにします。
-`showsTraffic = true`標準地図とハイブリッド地図の両方に対応した交通量表示スイッチに対応。
-`preferredConfiguration`これらの選択肢を構成オブジェクトとして渡します`MKMapView`、複数の属性の散在的な変更を避けるため。

([05:42](https://developer.apple.com/videos/play/wwdc2022/10035/?time=342)) 3D City Experience にはハードウェアと地域の制限があります。 iOS には A12 以降のデバイスが必要で、macOS には M1 以降の Mac が必要です。利用できないエリアは平坦なマップに戻ります。他のデバイスでもフラット バージョンが表示されます。講演では、3D フォールバックとフラット フォールバックの両方をテストすることを推奨しています。

### オーバーレイはマップを大まかに押さえつけなくなりました

([06:55](https://developer.apple.com/videos/play/wwdc2022/10035/?time=415)) MapKit のオーバーレイには常に 2 つのレベルがあります。`aboveRoads`そして`aboveLabels`。`aboveLabels`ラベルも含めてすべてをカバーします。 Apple は、データとマップを相互作用させたくない場合にのみこれを使用することをお勧めします。

iOS16`aboveRoads`新しいデフォルトレベルとして。ラベルのコンテキストを維持しながら、地形、道路、土地被覆、水域の上にオーバーレイを配置します。

```swift
// 概念示例：演讲的 Operating Area 功能把 polygon 作为运营区域叠加到地图上。
let operatingArea = MKPolygon(coordinates: coordinates, count: coordinates.count)
mapView.addOverlay(operatingArea, level: .aboveRoads)
```

キーポイント:

- `MKPolygon`スピーチの「ポリゴンオーバーレイ」に相当し、スクーターの操作可能領域を表すために使用されます。
-`addOverlay`ビジネスエリアをマップに追加します。
-`level: .aboveRoads`iOS 16 の推奨レベルを選択すると、オーバーレイはマップ ラベルをカバーしません。
- 選択した場合`aboveLabels`、オーバーレイはマップ コンテキストのより多くをカバーし、いくつかのシナリオにのみ適しています。

([08:11](https://developer.apple.com/videos/play/wwdc2022/10035/?time=491)) iOS 16 では、透明な建物も追加されます。マップに高低がある場合、木や建物が遮る場合`aboveRoads`カバーは自動的に透明になります。ピッチが 0 度に戻ると、競合する地上オブジェクトがビューから消え、カバーが完全に見える状態になります。

デモでは、Yingxiu は操作領域のアルファを次のように変更しました。`0.8`。これにより、地図を傾けなくても下の道路や建物を見ることができます。

```swift
// 概念示例：renderer 中把 polygon 填充改成半透明。
func mapView(_ mapView: MKMapView, rendererFor overlay: MKOverlay) -> MKOverlayRenderer {
    let renderer = MKPolygonRenderer(overlay: overlay)
    renderer.fillColor = UIColor.systemPurple.withAlphaComponent(0.8)
    return renderer
}
```

キーポイント:

- `rendererFor overlay`これは、MapKit がオーバーレイを描画するために使用するデリゲート エントリです。
-`MKPolygonRenderer`ポリゴンの描画を担当します。
-`withAlphaComponent(0.8)`対応する音声で、アルファを次のように変更します。`0.8`手術。
- 半透明のオーバーレイと透明な建物は組み合わせて有効になり、マップは空間コンテキストを保持します。

### ルート オーバーレイは実際の地形に従うことができます

([13:14](https://developer.apple.com/videos/play/wwdc2022/10035/?time=794)) 通常のオーバーレイがリアルな地形マップに追加されると、MapKit は自動的にマップをフラットに切り替えます。最後のオーバーレイを削除した後、リアルに戻します。例外は、Directions API によって返されるルート オーバーレイであり、実際の地形に従います。

デモのライド機能は、プレシディオ パークの入り口からバッテリー スペンサーまで進み、ゴールデン ゲート ブリッジを渡るルートをリクエストします。ルートラインは橋と道路の高低差に沿って表示され、橋脚や木々の前にもルートラインが表示されます。

```swift
// 概念示例：演讲用 Directions API 获取路线，并把 route polyline 加到地图。
let source = MKMapItem(placemark: MKPlacemark(coordinate: startCoordinate))
let destination = MKMapItem(placemark: MKPlacemark(coordinate: endCoordinate))

let request = MKDirections.Request()
request.source = source
request.destination = destination

let directions = MKDirections(request: request)
let response = try await directions.calculate()

if let route = response.routes.first {
    mapView.addOverlay(route.polyline, level: .aboveRoads)
}
```

キーポイント:

- `MKPlacemark`開始座標と終了座標を場所にパックします。
-`MKDirections.Request`ソースと宛先を保存します。
-`MKDirections`道順をリクエストします。
-`route.polyline`Directions API によって返されるルート オーバーレイです。
- このタイプのオーバーレイは、講演で特に述べられた例外です。マップを平坦化するのではなく、現実的な地形を保持します。

([16:28](https://developer.apple.com/videos/play/wwdc2022/10035/?time=988)) 高架ルート ラインは、A12 以降の iOS デバイスをサポートしています。古いデバイスでは、2D マップ上の 2D ルートが自動的に取得されます。

### BlendMode を使用してオーバーレイとマップ間の視覚的な関係を制御する

([17:02](https://developer.apple.com/videos/play/wwdc2022/10035/?time=1022)) カスタム コンテンツをより目立たせることだけが目的の場合は、オーバーレイを配置する必要はありません。`aboveLabels`。 iOS 16が与えるもの`MKOverlayRenderer`追加した`blendMode`プロパティでは、CoreGraphics のブレンド モードを使用できます。

講演では例としてプレシディオ国立公園を使用しています。まず、切り欠きのある大きなオーバーレイを使用してマップ領域をカバーし、次に色相、ハードライト、カラーバーンなどの混合モードをそれぞれ設定します。その結果、公園の外側のエリアは彩度が低くなり、暗くなりますが、公園の内部は焦点が合ったままになります。

```swift
// 概念示例：演讲明确说明 MKOverlayRenderer 新增 blendMode 属性。
func mapView(_ mapView: MKMapView, rendererFor overlay: MKOverlay) -> MKOverlayRenderer {
    let renderer = MKPolygonRenderer(overlay: overlay)
    renderer.fillColor = UIColor.gray
    renderer.blendMode = .colorBurn
    return renderer
}
```

キーポイント:

- `MKOverlayRenderer`すべてのオーバーレイ レンダラーの基本クラスです。
-`blendMode`iOS 16 の新しい属性です。
-`.colorBurn`CoreGraphics ブレンド モードから来ており、より抑制された Presidio ハイライト効果を得るためにプレゼンテーションに使用されます。
- オーバーレイの挿入順序は結果に影響します。下部のオーバーレイが最初にマップと混合され、上部のオーバーレイが前の結果と混合されます。

### ユーザーが地図上の POI、エリア、自然地物を直接選択できるようにします

([20:09](https://developer.apple.com/videos/play/wwdc2022/10035/?time=1209)) 以前は、ユーザーは自分でマップ上に追加した注釈をクリックすることしかできませんでした。 Apple がマップ内で提供する店舗、レストラン、ランドマーク、都市、州、山、湖、その他の要素は背景にすぎません。

iOS 16 の選択可能な地図機能 API はこれを変更します。開発者は、どのマップ機能がオプションであるかを構成し、デリゲートを通じて選択イベントを受け取ることができます。

```swift
// 概念示例：演讲的 Explore 功能只启用 points of interest。
mapView.pointOfInterestFilter = MKPointOfInterestFilter(excluding: [
    .airport,
    .carRental,
    .hospital,
    .laundry
])

mapView.selectableMapFeatures = [.pointsOfInterest]
```

キーポイント:

- `pointOfInterestFilter`スピーチ内の無関係な POI カテゴリを最初に除外するステップに対応します。
-`.airport`、`.carRental`、`.hospital`、`.laundry`は、デモでは名前によって除外されるカテゴリです。
-`selectableMapFeatures`新しいオプションのマップ機能構成エントリです。
- 選択された例のみ`.pointsOfInterest`、スピーチでは、領土と身体的特徴もオプションであるとも述べられました。

([22:41](https://developer.apple.com/videos/play/wwdc2022/10035/?time=1361)) ユーザーがマップ要素をクリックすると、MapKit は 2 つの入り口を受け取ります。新しい`didSelect annotation`選択イベントを処理するコールバック。既存`viewFor annotation`選択した状態の注釈ビューをカスタマイズするためのコールバック。

```swift
// 概念示例：演讲通过 MapFeatureAnnotation 定制选中样式，并发起 MKMapItemRequest。
func mapView(_ mapView: MKMapView, didSelect annotation: MKAnnotation) {
    guard let feature = annotation as? MKMapFeatureAnnotation else { return }

    Task {
        let request = MKMapItemRequest(mapFeatureAnnotation: feature)
        let mapItem = try await request.mapItem
        showInfoCard(for: mapItem)
    }
}

func mapView(_ mapView: MKMapView, viewFor annotation: MKAnnotation) -> MKAnnotationView? {
    guard let feature = annotation as? MKMapFeatureAnnotation else { return nil }

    let view = MKMarkerAnnotationView(annotation: feature, reuseIdentifier: "Feature")
    view.markerTintColor = .systemPurple
    view.glyphImage = feature.iconStyle.image
    view.selectedGlyphImage = feature.iconStyle.image
    return view
}
```

キーポイント:

- `MKMapFeatureAnnotation`これは iOS 16 の新しいタイプであり、ユーザーが選択した地図機能を表します。
-`feature.iconStyle`スピーカーが Apple のアイコンを保存するために使用する POI のアイコンと色の情報を提供します。
-`MKMapItemRequest`地図の特徴に基づいてより完全なものをリクエストする`MKMapItem`。
- `MKMapItem`住所、名前、電話番号、URLが表示されます。
-`viewFor annotation`戻る`nil`カスタム ビューに戻ると、MapKit はデフォルトのグラデーション アノテーションを使用します。カスタム ビューに戻るときに、アプリ独自のブランド カラーを適用できます。

### Look Around を独自のインターフェースに組み込む

([31:14](https://developer.apple.com/videos/play/wwdc2022/10035/?time=1874)) Look Around は、iOS 13 以降のマップ アプリで利用できます。iOS 16 では、MapKit に導入されています。開発者はまずアプリに小さなプレビューを表示し、ユーザーがそれをクリックして全画面の対話型ビューに入ることができます。

使用プロセスには 3 つのステップがあります。ターゲット位置に Look Around データがあるかどうかを確認します。シーンを Look Around ビュー コントローラーまたはスナップショットに渡します。データが利用可能な場合は、UI 表示プレビューを更新します。

```swift
// 概念示例：演讲说明 LookAroundSceneRequest 可用 coordinate 或 map item 初始化。
let request = MKLookAroundSceneRequest(mapItem: mapItem)
let scene = try await request.scene

if let scene {
    lookAroundViewController.scene = scene
    previewContainer.isHidden = false
} else {
    previewContainer.isHidden = true
}
```

キーポイント:

- `MKLookAroundSceneRequest`iOS 16 の新しいクラスで、特定の場所に Look Around データがあるかどうかを確認するために使用されます。
-`scene`はオプションの非同期プロパティです。利用可能な場合はシーンを返し、利用できない場合は返します`nil`、リクエストが失敗するとエラーがスローされます。
- Look Around シーンは不透明なオブジェクトであり、使いやすさと表示に必要なトークンとしてのみ使用されます。
-`lookAroundViewController.scene = scene`スピーチ内で既存のViewControllerにシーンを割り当てる方法に対応します。
-`previewContainer.isHidden`データが利用可能かどうかに基づいて、UI を使用してプレビューを表示または非表示にする必要があることを示します。

([36:44](https://developer.apple.com/videos/play/wwdc2022/10035/?time=2204)) Yingxiu のハイライト機能`MKLookAroundViewController`左下のコンテナに埋め込みます。ユーザーが Ferry Building を選択すると、マップはまず新しいカメラ API を使用してその位置にアニメーションを付けます。アニメーションが完了すると、Look Around シーンが要求されます。データがある場合はプレビューが表示されます。フェリー ビルディングはランドマークであるため、厳選されたカメラのフレーミングが行われます。ドラゴン ゲートはランドマークではないため、真上からの眺めになります。

静止画像のみが必要な場合は、次のようにすることもできます。`MKLookAroundSnapshotter`スナップショットを取得します。

```swift
// 概念示例：演讲提到 snapshotter 适合只需要静态图片的场景。
let request = MKLookAroundSceneRequest(coordinate: coordinate)
if let scene = try await request.scene {
    let snapshotter = MKLookAroundSnapshotter(scene: scene)
    let snapshot = try await snapshotter.snapshot
    imageView.image = snapshot.image
}
```

キーポイント:

- `MKLookAroundSceneRequest(coordinate:)`座標を使用して空き状況を確認します。
-`MKLookAroundSnapshotter`受け取りシーン。
-`snapshot`静的なプレビュー画像を返す非同期プロパティです。
- この方法はリスト カード、検索結果、または軽量のプレビューに適しており、最初から完全な対話型コントローラーを埋め込む必要はありません。

## 重要ポイント
### 1. 都市部の自転車走行エリアの地図を作成する

- **何をすべきか**: 地図上に走行可能なエリア、駐車禁止ゾーン、推奨駐車スポットを表示します。
- **実行する価値がある理由**:`aboveRoads`、透明な建物、半透明のポリゴンにより、操作エリアが道路、ラベル、建物を覆い隠すことがなくなります。
- **開始方法**: を使用します`MKPolygon`に挿入される領域を表します`.aboveRoads`、次に使用します`MKPolygonRenderer`半透明の塗りつぶしを設定します。

### 2. 実際の高低差のある都市のウォーキング ルートを作成する

- **機能**: 橋、ランプ、公園ルートの地形に適したルート ラインを表示します。
- **価値がある理由**: Directions API によって返されるルート ポリラインは、通常のオーバーレイの例外であり、現実的な地形を保持します。
- **開始方法**: を使用します`MKDirections.Request`道順をリクエストして、`route.polyline`マップに追加し、A12 以降のデバイスで 3D 効果をテストします。

### 3. クリック可能なアトラクション探索マップを作成する

- **何をすべきか**: ユーザーが地図上のレストラン、ランドマーク、または美術館をクリックすると、ブランド情報カードがポップアップ表示されます。
- **実行する価値がある理由**: 選択可能な地図機能を使用すると、Apple Maps の組み込み POI をインタラクティブなオブジェクトにすることができるため、すべての注釈データを自分で管理する必要がなくなります。
- **開始方法**: 設定`selectableMapFeatures = [.pointsOfInterest]`、存在する`didSelect`中国語での使用`MKMapItemRequest`住所、URL、電話番号を取得します。

### 4. 視覚的に強調した公園やビジネス街の地図を作成する

- **何をすべきか**: ターゲットエリアを強調表示し、周囲のマップを暗くするか彩度を下げます。
- **実行する価値がある理由**:`MKOverlayRenderer.blendMode`ラベル上のレイヤーを覆うよりも自然な、オーバーレイとマップ ベースマップの混合方法を制御できます。
- **開始方法**: ターゲット領域ポリゴンと外側マスク ポリゴンを準備し、順番にオーバーレイを挿入し、実験します`.hue`、`.hardLight`、`.colorBurn`などブレンドモード。

### 5. 景色の良い「Look Around」プレビュー カードを作成する

- **操作方法**: ユーザーがランドマークを選択すると、地図の隅に小さな Look Around ウィンドウが表示され、クリックすると全画面ストリート ビューが表示されます。
- **実行する価値がある理由**:`MKLookAroundSceneRequest`空白の UI を避けるために、まずデータが存在するかどうかを判断できます。
- **開始方法**: マップ アイテムを使用してリクエストを作成し、シーンを取得して割り当てます。`MKLookAroundViewController`; シーンがない場合はプレビュー コンテナを非表示にします。
