## 主な内容

過去 1 年間、Safari と WebKit は 7 つのバージョンを連続してリリースしました。 WebKit チームは冒頭で、今年は合計 162 の Web プラットフォーム機能と改善がもたらされたと述べました ([01:18](https://developer.apple.com/videos/play/wwdc2022/10048/?time=78))。これらの更新は、開発者が長い間報告してきたいくつかの質問に答えることに重点を置いています。CSS コンポーネントの再利用が難しい、親状態を選択するのが難しい、レイアウトのデバッグが直感的ではない、Web アプリとネイティブ アプリの間には機能のギャップが依然として存在します。

このセッションでは、衣類交換 Web サイトを使用してすべてを結び付けます。このページには、アイテムをリクエストするためのポップアップ、リクエストを受信するためのカルーセル、さまざまな幅で再利用される製品カード、ウィンドウ間で同期される在庫ステータス、オフラインで保存する必要がある下書きが含まれています。各機能は、Safari 15 ～ 16 の新しい機能セットに対応しています。

### HTML: カスタム ポップアップ ウィンドウとインタラクティブな状態の記述を減らす

以前は、ポップアップ ウィンドウを作成する場合、通常、フォーカス、背景マスク、キーボード ナビゲーション、アクセシビリティを自分で処理する必要がありました。 Safari がサポートされるようになりました`<dialog>`そして`::backdrop`、ポップアップとマスクをブラウザのネイティブ機能に戻すことができます ([02:58](https://developer.apple.com/videos/play/wwdc2022/10048/?time=178))。ページ上にカルーセルまたは隠しパネルがある場合、`inert`また、プロパティでは、クリック、キーボード ナビゲーション、支援技術へのアクセスから最新以外のコンテンツが除外されます ([03:49](https://developer.apple.com/videos/play/wwdc2022/10048/?time=229))。

画像の読み込みには、HTML を直接書き込むこともできます。スクロールせずに見える範囲外の製品画像については、`loading="lazy"`、ユーザーが画像の近くをスクロールすると、ブラウザーはそれらを読み込みます ([04:20](https://developer.apple.com/videos/play/wwdc2022/10048/?time=260))。このタイプの機能は、サイト上の最も一般的なカスタム コードを最初に置き換える場合に適しています。

### CSS: コンポーネントはコンテナに従って動作します

CSS セクションの焦点はアーキテクチャです。 WebKit チームは、新しい Web テクノロジーに対する開発者の最大のリクエストがコンテナ クエリであることを明らかにし、それが Safari 16 でリリースされることを発表しました ([05:10](https://developer.apple.com/videos/play/wwdc2022/10048/?time=310))。製品カードは、サイドバーに垂直に、メイン領域に水平に、または中程度の幅で 2 列に配置できます。判断の基準は、ビューポート全体からだけでなく、コンポーネントが配置されているコンテナからもたらされます。

`@layer`別の種類の長期的な問題を解決します。大規模なプロジェクトでは、設計システム、ツール クラス、およびビジネス カバレッジ スタイルが混在し、セレクターの優先順位を制御することがますます困難になります。カスケード レイヤーを使用すると、開発者は独自のレイヤーを定義できます。レイヤー全体の順序は、単一のセレクターの特異性よりも高くなります ([07:14](https://developer.apple.com/videos/play/wwdc2022/10048/?time=434))。

`:has()`これにより、親要素は子要素の状態に基づいてスタイルを適用できるようになります ([08:30](https://developer.apple.com/videos/play/wwdc2022/10048/?time=510))。 「緊急ですか？」フォーム内のチェックボックスが選択されている場合、状態を維持するために追加の JavaScript を必要とせずに、メッセージ フォーム全体の色を直接変更できます。

### Web API と JavaScript: Web アプリは完全なアプリケーションに似ています

Web API 部分は Web Push から始まります。 Safari 16 は macOS Ventura で Web プッシュをサポートしており、iOS と iPadOS のサポートは来年提供される予定です ([20:22](https://developer.apple.com/videos/play/wwdc2022/10048/?time=1222))。これは標準ベースの実装であり、既存の Web プッシュ コードが他のブラウザで動作する場合、Safari で変更する必要はありません ([20:41](https://developer.apple.com/videos/play/wwdc2022/10048/?time=1241))。

### ネイティブ ポップアップ ウィンドウ:`<dialog>`そして`::backdrop`

([02:58](https://developer.apple.com/videos/play/wwdc2022/10048/?time=178)) 衣装交換 Web サイトには「アイテムのリクエスト」ポップアップ ウィンドウが必要です。`<dialog>`リクエストフォームのホストに適したネイティブオーバーレイコンテナを提供します。

```html
<!-- <dialog> element -->

<dialog method="dialog">
  <form id="dialogForm">
    <label for="givenName">Given name:</label>
    <input class="focus" type="text" name="givenName">
    <label for="familyName">Family name:</label>
    <input class="focus" type="text" name="familyName">
    <label>
      <input type="checkbox"> Can trade in person
   </label>
   <button>Send</button>
  </form>
</dialog>
```

キーポイント:

- `<dialog method="dialog">`ネイティブ ダイアログ コンテナーを宣言します。
-`<form id="dialogForm">`送信コンテンツをダイアログ ボックス内に配置します。
- 2つのグループ`<label>`そして`<input>`依頼者の名前を収集します。
・チェックボックスは「対面取引が可能かどうか」という要望条件を表します。
-`button`フォームの送信を担当します。

([03:08](https://developer.apple.com/videos/play/wwdc2022/10048/?time=188)) ポップアップ ウィンドウの背後にあるマスクには追加の DOM は必要ありません。`::backdrop`ダイアログの背景レイヤーを直接選択します。

```css
/* ::backdrop pseudo-element */

dialog::backdrop {
  background: linear-gradient(rgba(233, 182, 76, 0.7), rgba(103, 12, 0, 0.6));
  animation: fade-in 0.5s;
}

@keyframes fade-in {
  from {
    opacity: 0;
  }
  to {
    opacity: 1;
  }
}
```

キーポイント:

- `dialog::backdrop`モーダルの背後にあるブラウザを確認して、背景レイヤーを生成します。
-`background`背景レイヤーにグラデーションカラーを追加します。
-`animation`フェード アニメーションを背景レイヤーにバインドします。
-`@keyframes fade-in`透明から不透明への変化を定義します。

### インタラクションが無効になりました:`inert`

([03:49](https://developer.apple.com/videos/play/wwdc2022/10048/?time=229)) カルーセル内の現在のカードのみがインタラクティブである必要があります。`inert`要素とその子へのクリック、キーボード ナビゲーション、支援技術アクセスを無効にします。

```js
// inert attribute

function switchToIndex(index) {
  this.items.forEach(item => item.inert = true);
  this.items[index].inert = false;
  this.currentIndex = index;
}
```

キーポイント:

- `switchToIndex(index)`ターゲットのカルーセル項目インデックスを受け取ります。
-`this.items.forEach(...)`まず、すべてのカルーセル項目を不活性に設定します。
-`this.items[index].inert = false`現在の項目の対話性のみが復元されます。
-`this.currentIndex = index`以降の切り替えのために現在のインデックスを保存します。

### コンテナクエリ: コンポーネントは独自のスペースに応じてレイアウトを切り替えます

([06:35](https://developer.apple.com/videos/play/wwdc2022/10048/?time=395)) 同じ製品カードがサイドバー、メインコンテンツ領域、グリッドに表示されます。 Container Queriesを使用した後、コンポーネント内にレイアウト判定を記述します。

```css
/* Container queries */

.container {
  container-type: inline-size;
  container-name: clothing-card;
}
.content {
  display: grid;
  grid-template-rows: 1fr;
  gap: 1rem;
}
@container clothing-card (width > 250px) {
  .content {
    grid-template-columns: 1fr 1fr;
  }
  /* additional layout code */
}
```

キーポイント:

- `.container`測定されるコンテナ要素です。
-`container-type: inline-size`クエリコンテナのインライン方向のサイズを表します。
-`container-name: clothing-card`コンテナに名前を付けて使いやすくする`@container`で引用。
-`.content`まず、基本的な 1 列のグリッド レイアウトを定義します。
-`@container clothing-card (width > 250px)`コンテナの幅が 250px を超える場合に内部スタイルを適用します。
-`grid-template-columns: 1fr 1fr`コンテンツを 2 列に切り替えます。

### カスケード レイヤー: スタイルの優先順位をアーキテクチャに変える

([07:14](https://developer.apple.com/videos/play/wwdc2022/10048/?time=434)) カスケード レイヤーを使用すると、チームはツール クラス、ビジネス カバレッジ、ユーザーのデフォルト スタイルを異なるレイヤーに配置できます。レベル間の順序は、個々のセレクターの特異性よりも優先されます。

```css
/* Author Styles - Layer A */
@layer utilities {
  div {
    background-color: red;
  }
}

/* Author Styles - Layer B */
@layer customizations {
  div {
    background-color: teal;
  }
}

/* Author Styles - Layer C */
@layer userDefaults {
  div {
    background-color: yellow;
  }
}
```

キーポイント:

- `@layer utilities`ツールスタイルレイヤーを定義します。
-`@layer customizations`アイテムオーバーライドスタイルレイヤーを定義します。
-`@layer userDefaults`著者スタイルレイヤーの別のセットを定義します。
- 各レイヤー内で同じものを使用します`div`セレクタ。
- 最終的な優先順位は、ここでのセレクターの違いではなく、レイヤーが定義されている順序によって決まります。

### `:has()`: 親要素は子要素の状態に応じてスタイルを変更します

([08:54](https://developer.apple.com/videos/play/wwdc2022/10048/?time=534)) メッセージフォームでは、チェックボックスをオンにするとフォーム全体の色が変わります。以前は、JavaScript を使用してクラスを親要素に追加するのが一般的でした。`:has()`この状態を CSS に直接保持します。

```html
<!-- :has() pseudo-class -->

<style>
  form:has(input[type="checkbox"]:checked) {
    background: #ff927a;
  }
</style>

<form class="message">
  <textarea rows="5" cols="60" name="text" 
    placeholder="Enter text"></textarea>
  <div class="checkbox">
    <input type="checkbox" value="urgent"> 
    <label>Urgent?</label>
  </div>
  <button>Send Message</button>
</form>
```

キーポイント:

- `form:has(...)`指定された要素の状態を含むフォームと一致します。
-`input[type="checkbox"]:checked`選択したチェックボックスを指します。
-`background: #ff927a`親フォームの背景をプロンプトの色に変更します。
-`textarea`メッセージのテキストです。
- チェックボックス`value="urgent"`このメッセージの緊急性を表現してください。

### オリジンプライベートファイルシステム: サイトプライベートファイル

([22:49](https://developer.apple.com/videos/play/wwdc2022/10048/?time=1369)) ファイル システム アクセス API のオリジン プライベート ファイル システムは、各オリジンに独立したプライベート ストレージ スペースを提供します。スピーチの草稿文書の例は、読み書きの入門を示しています。

// Accessing the origin private file system

### 共有ワーカー: バックグラウンド タスクを共有する同一オリジン ページ

([25:08](https://developer.apple.com/videos/play/wwdc2022/10048/?time=1508)) 複数の相同ページでバックグラウンド計算が必要な場合、ワーカーを共有して、ワーカーの重複によって引き起こされるメモリ負荷を軽減できます。

```js
// Create Shared Worker
let worker = new SharedWorker("SharedWorker.js");

// Listen for messages from Shared Worker
worker.port.addEventListener("message", function(event) {
  console.log("Message received from worker: " + event);
});

// Send messages to Shared Worker
worker.port.postMessage("Send message to worker");
```

キーポイント:

- `new SharedWorker("SharedWorker.js")`共有ワーカーを作成します。
-`worker.port.addEventListener("message", ...)`ワーカーから返信されたメッセージをリッスンします。
-`console.log(...)`メッセージ受信時に内容を出力します。
-`worker.port.postMessage(...)`ポート経由でワーカーにメッセージを送信します。

### 配列末尾の操作:`findLast()`、`findLastIndex()`そして`at()`

([25:56](https://developer.apple.com/videos/play/wwdc2022/10048/?time=1556)) 配列の末尾から検索する場合、最初に検索する必要はありません`reverse()`配列を変更します。

```js
const list = ["shirt","pants","shoes","hat","shoestring","dress"];
const hasShoeString = (string) => string.includes("shoe");

console.log(list.findLast(hasAppString));
// shoestring

console.log(list.findLastIndex(hasAppString));
// 4
```

キーポイント:

- `list`検索する製品名の配列です。
-`hasShoeString`を含む一致です`shoe`コールバック関数。
-`findLast(...)`配列の末尾から前方に向かって最初に一致するものを検索します。
-`findLastIndex(...)`配列の末尾から前方に向かって最初に一致する項目のインデックスを検索します。
- コードスニペットでの呼び出し名の記述`hasAppString`;以前に宣言されたマッチング関数は、コンテキストに従って渡される必要があります。

（[26:17](https://developer.apple.com/videos/play/wwdc2022/10048/?time=1577)）`at()`負のインデックスをサポートし、末尾近くの要素を読み取るのに適しています。

```js
const list = ["shirt","pants","shoes","hat","shoestring","dress"];

// Instead of this:
console.log(list[list.length - 2]);

// It's as easy as:
console.log(list.at(-2));
```

キーポイント:

- `list[list.length - 2]`その長さを使用して最後から 2 番目の要素を計算します。
-`list.at(-2)`最後から 2 番目の要素を直接読み取ります。
- 負のインデックスを使用すると、末尾のアクセスが短くなり、手書きの長さの計算も短縮されます。

### CSP Level 3：`strict-dynamic`

([29:04](https://developer.apple.com/videos/play/wwdc2022/10048/?time=1744)) コンテンツ セキュリティ ポリシー レベル 3`strict-dynamic`nonce を含むスクリプトを信頼し、このスクリプトによって読み込まれる後続のスクリプトに信頼を拡張して、明示的なドメイン名の許可リストを減らすことができます。

```http
// strict-dynamic source expression

// Without strict-dynamic
Content-Security-Policy: script-src desired-script.com dependent-script-1.com
  dependent-script-2.com dependent-script-3.com; default-src "self";

// With strict-dynamic
Content-Security-Policy: default-src "self"; script-src "nonce-desired" "strict-dynamic";
```

キーポイント:

- 最初のポリシーでは、ターゲット スクリプトと複数の依存スクリプト ドメイン名をリストする必要があります。
- 許可リストが長いと、ロードが許可されるスクリプトの範囲を簡単に拡張できます。
- 2 番目のポリシーは、ノンスを使用して信頼できるスクリプトをマークします。
-`strict-dynamic`信頼されたスクリプトによってロードされたスクリプトに信頼を渡します。
