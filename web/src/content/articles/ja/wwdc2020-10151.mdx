## ハイライト

> CareKit 2020 アップデートにより、このオープンソース健康管理フレームワークは SwiftUI タスク カード、watchOS サポート、HealthKit ドライバー タスク、FHIR マッピング、リモート同期 API にアクセスできるようになり、開発者はケア プラン、健康データ、臨床記録、iPhone/Apple Watch のステータスを同じアプリケーション構造に同期できるようになります。

## 主な内容

健康管理アプリを作成する場合、インターフェースとデータは簡単に分離できます。ユーザーが目にするのは、毎日のストレッチ、投薬、アンケート、症状の記録、グラフです。開発者は舞台裏でタスクのスケジュール、完了ステータス、HealthKit データ、臨床システムの記録を維持し、iPhone と Apple Watch の間の同期を処理する必要があります。 CareKit の目標は、これらのケア シナリオを再利用可能な UI、データ モデル、同期レイヤーに分割することです。

このセッションでは、まず CareKit のモジュール境界を示します。`CareKitStore`健康分野におけるデータモデルとコアデータ永続化レイヤーを提供し、`CareKitUI`タスク、チャート、連絡先を表示する静的なビューを提供します。`CareKit`ストア内のデータ変更が自動的にインターフェースに反映されるように、UI とストアを接続します。 ([00:31](https://developer.apple.com/videos/play/wwdc2020/10151/?time=31))

2020 年の変化は、これらの境界を外側に拡大し続けることです。 UI レイヤーは、タスク カードと情報カードの SwiftUI バージョンを追加します。同期ビューは、ストア内のタスクをインターフェイスに自動的にマッピングできます。 CareKit、CareKitUI、および CareKitStore はすべて watchOS に組み込むことができます。ストア層には、HealthKit パススルー、FHIR コーダー、およびリモート同期プロトコルが追加されます。その結果、開発者は健康データ、ケアタスク、クロスデバイスステータスを 3 つのサイロ化されたプロセスに分離する必要がなくなります。

セッションのデモンストレーションは非常に具体的です。同じ看護アプリで、ユーザーは iPhone で筋肉のけいれんを記録し、Apple Watch でストレッチタスクを完了します。 iPhoneのタスクカード、アディクションリング、チャートも同時に更新されます。 CareKit は、いくつかのデフォルト カードだけでなく、ここでのアプリケーション構造を担当します。

### CareKitUI は SwiftUI タスク カードを追加します

（[02:23](https://developer.apple.com/videos/play/wwdc2020/10151/?time=143)）`SimpleTaskView`UIKit API はすでに存在しており、2020 年に新しい SwiftUI API が追加されました。最小限の使用法では、タイトル、詳細、完了ステータスのみが必要です。

```swift
import CareKitUI
import SwiftUI

struct MySimpleTaskView: View {

    var body: some View {
        SimpleTaskView(
            title: Text("Stretches"),
            detail: Text("15 minutes"),
            isComplete: false)
    }
}
```

キーポイント:

- `CareKitUI`提供されるのは静的なビューであり、準備されたタスク データを表示するのに適しています。
-`title`そして`detail`引き継ぐ`Text`, そのため、SwiftUI のビュー修飾子を引き続き使用できます。
-`isComplete`プレビュー、静的フィード、またはカスタム データ ソースに適したタスク カードの完了ステータスを制御します。

([03:42](https://developer.apple.com/videos/play/wwdc2020/10151/?time=222)) このカードはクローズドコンポーネントではありません。開発者はカスタム ヘッダーを挿入し、任意の方向にコンテンツを追加できます。スピーチで使用される`HeaderView`デフォルトのヘッダーを変換するアクセントバーと、`CardView`タスク カード、仕切り、キャプションをラップして、単純な完了カードをケア タスクの説明に変えます。

([05:08](https://developer.apple.com/videos/play/wwdc2020/10151/?time=308)) UI アップデートの同じバッチには以下も含まれます`LabeledValueTaskView`、`NumericProgressTaskView`、`OCKFeaturedContentView`、`OCKDetailView`そして`LinkView`。これらのビューには、心拍数の値、運動目標の進捗状況、健康コンテンツの推奨事項、HTML 詳細ページ、内部および外部リンクの入り口が含まれます。これらはすべて、看護アプリのフィードで一般的なカード形式です。

### 同期ビューマップはデータを SwiftUI に保存します

([08:56](https://developer.apple.com/videos/play/wwdc2020/10151/?time=536)) 静的ビューは表示の問題を解決し、同期ビューはデータ変更の問題を解決します。`CareKit.SimpleTaskView`引き継ぐ`taskID`、`OCKEventQuery`そして`OCKSynchronizedStoreManager`、ストアからその日のタスクを見つけて、UI を自動的に更新します。

```swift
// Synchronized Task View

import CareKit
import CareKitUI
import SwiftUI

struct MySynchronizedTaskView: View {

    let storeManager: OCKSynchronizedStoreManager

    var body: some View {
        CareKit.SimpleTaskView(
            taskID: "stretch",
            eventQuery: OCKEventQuery(for: Date()),
            storeManager: storeManager)

    }
}
```

キーポイント:

- `taskID`ビューがケア タスクを見つけるために依存するストア内のタスクの安定した識別子です。
-`OCKEventQuery(for: Date())`クエリのスコープを特定の日のイベントに収束します。
-`OCKSynchronizedStoreManager`ストアの変更を監視し、タスクの完了ステータスが変化した後にインターフェイスを更新します。

([09:26](https://developer.apple.com/videos/play/wwdc2020/10151/?time=566)) デフォルトのマッピングでは不十分な場合、イニシャライザはクロージャも提供します。クロージャでは、コントローラ、タスクデータ、ビューモデルにアクセスし、それらを自分で作成できます。`CareKitUI.SimpleTaskView`。この講義では、このポータルを使用して CareKit タスクを ResearchKit 調査ポータルに変換します。このポータルは、ユーザーがタスク カードをクリックするとポップアップします。`ResearchKitSurvey()`。

### HealthKit はタスクを CareKit ストアに送り込みます

([12:52](https://developer.apple.com/videos/play/wwdc2020/10151/?time=772)) CareKit は主に以下に依存していました`OCKStore`。 2020年の新機能`OCKHealthKitPassthroughStore`、信頼できる情報源として HealthKit を使用し、それを Core Data バージョンと統合します。`OCKStore`一緒にぶらぶら`OCKStoreCoordinator`優れた。データを読み取るとき、コーディネーターは内部ストアを集約します。データを書き込むときは、トランザクション境界を明確に保つために、一度に 1 つのストアにのみ書き込みます。

```swift
// Setting up the Store

import CareKit
import CareKitStore

let coreDataStore = OCKStore(name: "core-data-store")
let healthKitPassthroughStore = OCKHealthKitPassthroughStore(name: "hk-passthrough—store")

let coordinator = OCKStoreCoordinator()
coordinator.attach(store: coreDataStore)
coordinator.attach(eventStore: healthKitPassthroughStore)

let storeManager = OCKSynchronizedStoreManager(wrapping: coordinator)
```

キーポイント:

- `OCKStore`現在も CareKit 独自のデータ モデルと永続性を担当しています。
-`OCKHealthKitPassthroughStore`HealthKit データをイベント ストアとして CareKit クエリに参加させます。
-`OCKStoreCoordinator`2 つの店舗をラッピングすることで、外観上は 1 つの店舗と同様の利用が可能になります。
- 結局まだ使っています`OCKSynchronizedStoreManager`同期されたビューに提供されます。

([14:15](https://developer.apple.com/videos/play/wwdc2020/10151/?time=855)) HealthKit 主導のタスクの例は、毎日午前 8 時に 30 分間の運動を行うという目標です。ミッションは成功しました`OCKHealthKitLinkage`に接続します`.appleExerciseTime`、タイプは累積、単位は分です。 HealthKit で運動時間の目標に達すると、CareKit のタスクを自動的に完了できます。

```swift
// Adding HealthKit Linked Tasks to the Store

let schedule = OCKSchedule.dailyAtTime(
    hour: 8,
    minutes: 0,
    start: Date(),
    end: nil,
    text: nil,
    duration: .allDay,
    targetValues: [OCKOutcomeValue(30.0, units: "Minutes")])

let link = OCKHealthKitLinkage(
    quantityIdentifier: .appleExerciseTime,
    quantityType: .cumulative,
    unit: .minute())

let steps = OCKHealthKitTask(
    id: "exerciseMinutes",
    title: "Exercise Minutes",
    carePlanUUID: nil,
    schedule: schedule,
    healthKitLinkage: link)

storeManager.store.addAnyTask(steps)
```

キーポイント:

- `OCKSchedule.dailyAtTime`看護タスクが発生する時期と目標値を定義します。
-`targetValues`で`OCKOutcomeValue(30.0, units: "Minutes")`タスクビューで目標を表示するために使用されます。
-`OCKHealthKitLinkage`CareKit タスクを HealthKit 数量にバインドします。
-`OCKHealthKitTask`入店後もご利用いただけます`NumericProgressTaskView`進捗状況と目標を示す。

### FHIR コーダーは臨床データのマッピングを担当します

([15:23](https://developer.apple.com/videos/play/wwdc2020/10151/?time=923)) 医療業界の多くのシステムは、FHIR を使用してデータを交換します。 CareKit 2020 では、FHIR 互換性が追加され、新しいオープンソース フレームワーク FHIRModels を通じて FHIR リリースがマップされます。講演では、CareKit が DSTU2 と R4 をサポートし、CareKit エンティティと FHIR データの間で変換するコーダーを提供していることが明確に述べられました。

```swift
// Encoding and Decoding FHIR Data

import CareKitStore
import CareKitFHIR

let coder = OCKR4PatientCoder()

// CareKit entity to FHIR data
let patient = OCKPatient(...)
let json = try! coder.encode(patient)

// FHIR data to CareKit entity
let data: Data = //...
let resourceData = OCKFHIRResourceData<R4, JSON>(data: data)
let patient: OCKPatient = try! coder.decode(resourceData)
```

キーポイント:

- `CareKitFHIR`coder を含む Swift Package Manager パッケージです。
-`OCKR4PatientCoder`患者リソースと`OCKPatient`変換。
-`OCKFHIRResourceData<R4, JSON>`間違ったバージョンのデータがコーダーに渡されるのを避けるために、タイプ層で FHIR リリースとエンコード形式をマークします。
- この機能は、臨床システムまたは HealthKit 臨床記録からの FHIR データを看護アプリに取り込むのに適しています。

([17:49](https://developer.apple.com/videos/play/wwdc2020/10151/?time=1069)) FHIR モデルと CareKit モデルは必ずしも 1 対 1 に対応しているわけではありません。セッションでは例として患者名を使用します。デフォルトのマッピングでフィールドが失われる場合、開発者はクロージャを提供し、CareKit 名を FHIR に書き込む方法を決定できます。`HumanName`。

```swift
// Customizing the Data Mapping

// Encoding process
coder.setFHIRName = { name, fhirPatient in // ModelsR4.Patient

    let humanName = HumanName()
    humanName.family = name.familyName.map { FHIRPrimitive(FHIRString($0)) }
    humanName.given = name.givenName.map { [FHIRPrimitive(FHIRString($0))] }

    fhirPatient.name = [humanName]
}
```

キーポイント:

- `setFHIRName`CareKit 名と FHIRModel を公開する患者オブジェクト。
-`HumanName.family`そして`HumanName.given`FHIRMode のプリミティブ タイプに従ってカプセル化する必要があります。
- カスタム マッピングの目的は、CareKit と FHIR が行き来するときに臨床データがセマンティクスを失うのを防ぐことです。

### リモート同期カバレッジサーバーと Apple Watch

([19:16](https://developer.apple.com/videos/play/wwdc2020/10151/?time=1156)) CareKitは、「CareKitアプリ内のデータをサーバーにどのように同期するか」という問題を解決するために、リモート同期APIを追加しました。アプリ側の入り口は`OCKStore`: 初期化中にリモートを渡して、リモート同期を有効にします。電話`synchronize`ローカル ストアとリモート ストア間の同期をトリガーします。サーバーまたはクラウドプロバイダーは実装する必要があります`OCKRemoteSynchronizable`、デリゲート、自動同期スイッチ、変更のフェッチ、リビジョンのプッシュ、および競合解決戦略を処理します。

([25:54](https://developer.apple.com/videos/play/wwdc2020/10151/?time=1554)) このスピーチでは、同じリモート同期 API を使用して iPhone と Apple Watch を同期します。鍵となるクラスは、`OCKWatchConnectivityPeer`。リモート同期プロトコルに準拠しており、iPhone と Apple Watch がお互いをリモート ストアとして扱うことができます。

```swift
private lazy var remote = OCKWatchConnectivityPeer()
```

キーポイント:

- `OCKWatchConnectivityPeer`CareKit が提供する WatchConnectivity リモートです。
- watchOS 側がそれを渡します`OCKStore`、ストアにはペアリングされたiPhoneと同期するための入り口があります。
- 同期プロトコルの抽象化はサーバーに関連付けられていないため、同じ一連の概念をデバイス間の同期に使用できます。

([26:33](https://developer.apple.com/videos/play/wwdc2020/10151/?time=1593)) WatchConnectivity のセッション デリゲートは依然として開発者が所有しています。 CareKit では、開発者はメッセージを受信したときにメッセージをリモートに転送し、CareKit によって生成された応答を iPhone に送り返す必要があります。

```swift
class SessionDelegate: NSObject, WCSessionDelegate {

    let remote: OCKWatchConnectivityPeer
    let store: OCKStore

    init(remote: OCKWatchConnectivityPeer, store: OCKStore) {
        self.remote = remote
        self.store = store
    }

    func session(
        _ session: WCSession,
        activationDidCompleteWith activationState: WCSessionActivationState,
        error: Error?) {

        print("New session state: \(activationState)")
    }

    func session(
        _ session: WCSession,
        didReceiveMessage message: [String: Any],
        replyHandler: @escaping ([String: Any]) -> Void) {

        print("Received message from peer!")
    }
}
```

キーポイント:

- `activationDidCompleteWith`最初の同期に適した場所です。演説は後ほどここで呼びかけます。`store.synchronize`。
- `didReceiveMessage`これは、CareKit メッセージが watchOS アプリに入るエントリ ポイントです。
- 実際の転送ロジックの使用`remote.reply(to:store:)`応答を生成してから WatchConnectivity を呼び出します`replyHandler`。
- この連携が完了すると、Apple Watch上でストレッチタスクが完了し、iPhone上で同じストアに登録されているビューが同時に更新されます。

## 重要なポイント

1. **術後の回復タスク フィードを作成する**

- **やるべきこと**: 毎日のストレッチ、氷、投薬、痛みのログを CareKit タスク カードに作成します。
   - **実行する価値がある理由**:`SimpleTaskView`、`InstructionsTaskView`そして`NumericProgressTaskView`タスクの説明、完了ボタン、目標の進捗状況について説明しました。
   - **開始方法**: 最初に使用します`OCKStore`タスクと結果を再利用のために保存する`OCKSynchronizedStoreManager`その日の SwiftUI タスク リストを推進します。

2. **HealthKit によって自動的に完了する運動目標を作成します**

- **やるべきこと**: ユーザーが毎日の運動目標を 30 分に設定できるようにし、HealthKit の運動時間に達すると CareKit タスクを自動的に完了します。
   - **実行する価値がある理由**: セッション中`OCKHealthKitTask`HealthKit データがタスク完了の基礎となるのはこのモデルです。
   - **開始方法**: 作成する`OCKHealthKitPassthroughStore`、合格`OCKHealthKitLinkage(quantityIdentifier: .appleExerciseTime, quantityType: .cumulative, unit: .minute())`タスクをバインドします。

3. **アンケートをもとにした看護プロセスを作成する**

- **何をすべきか**: ユーザーが CareKit タスク カードをクリックした後、ResearchKit アンケートを開いて症状または副作用を記録します。
   - **実行する価値がある理由**: 同期ビューを閉じると、タスク データの UI へのマッピングをカスタマイズでき、音声サンプルが直接ポップアップ表示されます。`ResearchKitSurvey()`。
   - **開始方法**: を使用します`CareKit.SimpleTaskView`カスタム初期化子は次のように読み取ります。`controller.viewModel`、スイッチが作動中`@State`そしてアンケートをレンダリングします。

4. **iPhone と Apple Watch の間でケアタスクを同期させる**

- **やるべきこと**: iPhone には完全なケア プランとチャートが表示されますが、Apple Watch にはその日の最も重要なタスク カードが 2 枚だけ表示されます。
   - **価値がある理由**: CareKit 2020 は watchOS をサポートしており、以下を提供します`OCKWatchConnectivityPeer`リモート同期 API を再利用します。
   - **開始方法**: watchOS 拡張機能で作成します`OCKStore(name:remote:)`、成し遂げる`WCSessionDelegate`、受信したメッセージをに渡します`remote.reply(to:store:)`。

5. **臨床記録をインポートした後にケアプランを作成します**

- **作業内容**: 医療機関から返された FHIR 患者または投薬指示を CareKit エンティティに変換します。これは、フォローアップ ケア タスクの生成に使用されます。
   - **価値がある理由**: CareKitFHIR と FHIRModel を使用すると、CareKit が DSTU2 や R4 などの FHIR リリースを処理できるようになります。
   - **開始方法**: データのバージョンに基づいてコーダーを選択します。たとえば、`OCKR4PatientCoder`、必要に応じて使用します`setFHIRName`このタイプのクロージャはフィールド マッピングを修正します。
