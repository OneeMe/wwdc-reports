## ハイライト

> Apple Silicon のユニファイド メモリ アーキテクチャにより、CPU-GPU のゼロコピー データ転送が可能になります。 TBDR アーキテクチャに基づくタイル シェーディングとメモリレス アタッチメントにより、イメージ フィルタ パイプラインを完全にオンチップ タイル メモリ内で実行できるようになり、メモリ帯域幅が大幅に削減されます。

## 主な内容

画像処理アプリケーションはカメラからフレームを取得し、一連のフィルターを適用して、結果を表示します。個別の GPU では、各ステップに CPU メモリから GPU メモリへのデータのコピーと、フィルタ間でのテクスチャの受け渡しが含まれます。これらのコピーは、多くの時間とバッテリーを消費します。

Apple Silicon はそれを変えます。 CPU と GPU は同じ物理メモリを共有するため、データをコピーする必要はありません。

### ユニファイド メモリ アーキテクチャの利点

（[00:52](https://developer.apple.com/videos/play/wwdc2021/10153/?time=52)）

Apple Silicon のすべてのコンポーネント (CPU、GPU、ニューラル エンジン、メディア エンジン) は、統合メモリ インターフェイスを通じて同じシステム メモリにアクセスします。

これはつまり：
- 使用`MTLBuffer`作成されたバッファは、CPU によって直接読み書きでき、GPU によって直接使用できます。
- `IOSurface`そして`CVPixelBuffer`コピーせずにCPUとGPU間で転送
- 画像処理パイプラインの各ステップをその場で実行可能

```swift
// 从相机获取的 CVPixelBuffer
let pixelBuffer: CVPixelBuffer = ...

// 直接创建 Metal texture，零拷贝
let texture = CVMetalTextureCacheCreateTextureFromImage(
    allocator: kCFAllocatorDefault,
    textureCache: textureCache,
    sourceImage: pixelBuffer,
    textureAttributes: nil,
    pixelFormat: .bgra8Unorm,
    width: width,
    height: height,
    planeIndex: 0
)
```

（[02:30](https://developer.apple.com/videos/play/wwdc2021/10153/?time=150)）

**キーポイント:**
- `CVMetalTextureCache`ピクセルバッファとメモリを共有するテクスチャを作成する
- CPU-GPU間のデータコピーなし
- 処理パイプライン全体が GPU 上で実行されます
- リアルタイムカメラフィルターシーンに適しています

### タイル シェーディング: タイル メモリで処理されます。

（[03:45](https://developer.apple.com/videos/play/wwdc2021/10153/?time=225)）

Apple GPU の TBDR アーキテクチャは画像を小さなタイルに分割し、各タイルはオンチップのタイル メモリで処理されます。タイル メモリの帯域幅は、メイン メモリよりも 1 桁高いです。

画像処理の場合、これは、複数のフィルターを 1 つのレンダー パスに結合し、中間結果をタイル メモリに残すことができることを意味します。

```metal
// 传统方式：每个滤镜一个 compute pass，写回主内存
kernel void blurPass1(...) { ... }  // 写主内存
kernel void blurPass2(...) { ... }  // 写主内存
kernel void sharpen(...) { ... }    // 写主内存

// 优化方式：tile shader，中间结果留在 tile 内存
[[kernel]] void imageProcessingTileShader(
    texture2d<float> source [[texture(0)]],
    device ImageProcessingParams* params [[buffer(0)]],
    uint2 gid [[thread_position_in_grid]]
) {
    // 读取源图像
    float4 color = source.read(gid);

    // 应用多个滤镜，数据留在 tile memory
    color = applyBlur(color, params->blurRadius);
    color = applySharpen(color, params->sharpenAmount);
    color = applyColorAdjust(color, params->brightness, params->contrast);

    // 只写最终结果回主内存
    destination.write(color, gid);
}
```

（[05:20](https://developer.apple.com/videos/play/wwdc2021/10153/?time=320)）

**キーポイント:**
- タイル シェーダはタイル メモリ内で実行されます
- 複数のフィルターを 1 つのカーネルに結合します
- 中間結果はメインメモリに書き込まれません
- メモリ帯域幅を大幅に削減

### Memoryless Attachment

（[10:53](https://developer.apple.com/videos/play/wwdc2021/10153/?time=653)）

レンダー パスの中間アタッチメントは、タイル メモリ内にのみ存在し、メイン メモリには書き込まれないメモリレスとしてマークできます。

```swift
let descriptor = MTLRenderPassDescriptor()

// 中间 G-Buffer attachment，memoryless
descriptor.colorAttachments[0].texture = intermediateTexture
descriptor.colorAttachments[0].storeAction = .dontCare  // 不写回主内存
intermediateTexture.storageMode = .memoryless

// 最终输出 attachment
descriptor.colorAttachments[1].texture = outputTexture
descriptor.colorAttachments[1].storeAction = .store  // 写回主内存
```

（[10:53](https://developer.apple.com/videos/play/wwdc2021/10153/?time=653)）

**キーポイント:**
- `.memoryless`ストレージ モードはタイル メモリ内にのみ存在します
- `.dontCare`ストアアクションはメインメモリに書き込みません
- G-Buffer および中間処理結果に適しています
- 最終出力用`.store`保存

### Uber シェーダーの最適化

（[12:25](https://developer.apple.com/videos/play/wwdc2021/10153/?time=745)）

画像処理アプリケーションには多くのフィルターの組み合わせが存在することがよくあります。組み合わせごとに個別のシェーダーを作成すると、シェーダーの数が爆発的に増加します。 uber-shader は条件付き分岐を持つすべてのフィルターを処理しますが、レジスタープレッシャーが発生します。

解決策: 関数定数を使用して、コンパイル時に有効なフィルターを決定します。

```metal
[[function_constant(0)]] const bool enableBlur = false;
[[function_constant(1)]] const bool enableSharpen = false;
[[function_constant(2)]] const bool enableVignette = false;

fragment float4 imageFilterFragment(...) {
    float4 color = source.sample(sampler, uv);

    if (enableBlur) {
        color = applyBlur(color, uv);
    }
    if (enableSharpen) {
        color = applySharpen(color, uv);
    }
    if (enableVignette) {
        color = applyVignette(color, uv);
    }

    return color;
}
```

（[13:32](https://developer.apple.com/videos/play/wwdc2021/10153/?time=812)）

**キーポイント:**
- 関数定数はコンパイル時に決定されます
- 無効なフィルターコードは削除されます
- レジスターの圧力を下げる
- 組み合わせごとにパイプライン状態を作成する必要がある

### 画像処理フィルターチャート

（[23:02](https://developer.apple.com/videos/play/wwdc2021/10153/?time=1382)）

複雑な画像処理アプリケーションでは、フィルター間の依存関係を管理する必要があります。典型的なフィルター図:

```
Input Image → Blur → Blend with Original → Sharpen → Color Adjust → Output
                ↑___________________________|
```

Apple Silicon では、この画像は 1 つのレンダー パスで実行できます。

```swift
// 设置 render pass，所有中间结果用 memoryless
let descriptor = MTLRenderPassDescriptor()
descriptor.colorAttachments[0].storeAction = .dontCare
descriptor.colorAttachments[0].texture.storageMode = .memoryless

// 编码所有滤镜为一个 render command
encoder.setRenderPipelineState(uberPipeline)
encoder.setFragmentTexture(input, index: 0)
encoder.setFragmentBytes(&filterParams, length: ...)
encoder.drawPrimitives(...)
```

（[23:02](https://developer.apple.com/videos/play/wwdc2021/10153/?time=1382)）

**キーポイント:**
- フィルターの依存関係を分析して、組み合わせることができるステップを見つける
- 中間結果にはメモリレス添付ファイルを使用する
- 最終出力用`.store`
- レンダーパスの切り替えとメモリ帯域幅を削減します。

## 重要なポイント

1. **CVMetalTextureCache を使用してゼロコピー カメラ フィルターを実装します**。カメラから取得したピクセル バッファーは直接メタル テクスチャに変換され、処理パイプライン全体が GPU 上で完了します。入口API：`CVMetalTextureCacheCreateTextureFromImage`。

2. **複数のフィルターを単一のタイル シェーダーに結合します**。中間結果はタイル メモリに残り、最終結果のみが書き込まれます。入口API：`[[kernel]] tileShader`。

3. **中間アタッチメントにはメモリレス ストレージを使用します**。 G バッファと一時テクスチャはメイン メモリに永続化する必要はありません。入口API：`texture.storageMode = .memoryless` + `storeAction = .dontCare`。

4. **関数定数を使用して uber-shader を最適化します**。現在有効なフィルターの組み合わせに基づいて専用シェーダーをコンパイルし、レジスタープレッシャーを軽減します。入口API：`[[function_constant(N)]]`。

5. **ディスクリート GPU から移行する場合はデータ フローを再設計します**。 Apple Silicon は CPU と GPU のコピーを必要とせず、元の複雑な設計を簡素化してコピーを最小限に抑えます。エントランスAPI：ユニファイドメモリ+`MTLStorageMode.shared`。
