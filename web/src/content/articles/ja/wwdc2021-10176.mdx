## ハイライト

> SwiftUI 2021 年の新機能`.searchable`、`isSearching`、`searchCompletion`そして`.onSubmit(of: .search)`、開発者は宣言型コードを使用して、検索フィールド、検索結果、検索候補をクロスプラットフォーム アプリケーションに追加できます。

## 主な内容

リストアプリが大きくなると検索が必須になります。天気予報アプリには都市リスト、音楽アプリには曲リスト、デザイン ツールにはカラー パレット リストがあります。ユーザーは何を探しているのかわかっていますが、最初から最後までスクロールする必要があります。

以前は検索を行う場合、最初のステップは検索ボックスを設置することでした。 2 番目のステップは、入力を状態に同期することです。 3 番目のステップは、入力に基づいて結果リストを切り替えることです。 iPadOS、macOS、watchOS、tvOS に関しては、検索ボックスの場所と操作方法を個別に扱う必要があります。

SwiftUI 2021 では、これらのものをモディファイアに収集します。`.searchable`。バインディング文字列を受け取り、環境を介して検索フィールドをビュー ツリーに渡します。`NavigationView`この検索フィールドは、プラットフォームに応じて認識され、適切な場所に配置されます。

Weather の例は、基本モデルを示しています。インターフェイスはそのままです`NavigationView`リストを追加します。開発者は置いた`.searchable(text:)`ナビゲーションビューに置きます。検索するときはパスしてください`isSearching`環境値と検索テキストによって、結果が表示されるかどうかが決まります。

Colors の例は、クロスプラットフォームの動作を示しています。同じ 2 列ナビゲーション ビュー コードは、iOS および iPadOS では検索バーをサイドバーに関連付け、macOS では検索ボックスをツールバーの右端に移動し、watchOS ではビューの一番上に移動します。 tvOSの構造が違います。検索は通常タブなのでコードのみ`.searchable`検索タブに移動します。

検索ボックスは入力の問題を解決し、検索候補は「ユーザーが何を検索すればよいかわからない」という問題を解決します。`.searchable`提案の終了を受け取ることができます。提案は、データベース内のホットワードである場合もあれば、サーバーから送信される場合もあります。`searchCompletion`通常のビューをクリック可能な候補に変え、検索テキストを自動的に入力し、選択後に候補パネルを閉じることができます。

＃＃詳細

### `.searchable`: 検索フィールドをSwiftUIに引き渡します。

（[01:17](https://developer.apple.com/videos/play/wwdc2021/10176/?time=77)）

SwiftUIの新機能`searchable`ビュー修飾子。その中心的な入力は、`Binding<String>`。文字列には現在の検索クエリが保持され、SwiftUI は検索フィールドをプラットフォームの適切な場所にレンダリングする役割を果たします。

```swift
import SwiftUI

struct ContentView: View {
    @State private var text = ""

    var body: some View {
        NavigationView {
            List(filteredCities, id: \.self) { city in
                Text(city)
            }
            .navigationTitle("Weather")
        }
        .searchable(text: $text)
    }

    private var filteredCities: [String] {
        let cities = ["Cupertino", "San Francisco", "London", "Tokyo"]

        if text.isEmpty {
            return cities
        }

        return cities.filter { city in
            city.localizedCaseInsensitiveContains(text)
        }
    }
}
```

キーポイント:
- `@State private var text = ""`検索クエリを保存すると、変更を入力するとビューが更新されます。
- `NavigationView`セッション内の天気と色の例を開始するナビゲーション構造を提供します。
- `List(filteredCities, id: \.self)`フィルタリングされた配列に基づいて都市を表示します。
- `.searchable(text: $text)`検索フィールドをバインドします`text`。
- `filteredCities`使用`text`結果を計算します。空のクエリは完全なリストを表示し、空でないクエリは一致を表示します。

（[02:15](https://developer.apple.com/videos/play/wwdc2021/10176/?time=135)）

`searchable`検索フィールドを環境に配置します。もし`NavigationView`このフィールドを使用すると、フィールドが検索バーとして表示されます。ビューがそれを使用しない場合、SwiftUI はツールバーに検索フィールドを配置するデフォルトの実装を提供します。

```swift
ContentView()
    .searchable(text: $text)
```

キーポイント:
- `ContentView()`は、検索可能としてマークするコンテンツです。
- `.searchable(text: $text)`このコンテンツが検索をサポートしていることを宣言します。
- `$text`バインディングの場合、検索ボックスとアプリケーションの状態は同じクエリ テキストを共有します。

### `isSearching`: 検索時に結果ビューをオーバーライドします。

（[03:11](https://developer.apple.com/videos/play/wwdc2021/10176/?time=191)）

検索フィールドは単なるエントリ ポイントです。実際のアプリケーションでは、結果をどこに表示するかを決定する必要もあります。セッションがおすすめです`isSearching`環境値は、ユーザーが検索しているかどうかを決定し、次の値を使用します。`overlay`検索操作によってメイン インターフェイスの状態がリセットされないように結果を表示します。

```swift
import SwiftUI

struct WeatherList: View {
    @Binding var text: String

    @Environment(\.isSearching)
    private var isSearching: Bool

    var body: some View {
        WeatherCitiesList()
            .overlay {
                if isSearching && !text.isEmpty {
                    WeatherSearchResults(text: text)
                }
            }
    }
}

struct WeatherCitiesList: View {
    var body: some View {
        List(["Cupertino", "San Francisco", "London"], id: \.self) { city in
            Text(city)
        }
    }
}

struct WeatherSearchResults: View {
    var text: String

    var body: some View {
        List(["Search result for \(text)"], id: \.self) { result in
            Text(result)
        }
    }
}
```

キーポイント:
- `@Binding var text: String`外層を受け取る`.searchable`同じクエリ テキストが使用されます。
- `@Environment(\.isSearching)`SwiftUIで設定した検索ステータスを読み取ります。
- `WeatherCitiesList()`マスターリストを維持してください。
- `.overlay { ... }`検索結果をメインリストの上にオーバーレイします。
- `if isSearching && !text.isEmpty`ユーザーが検索ボックスをクリックしただけで、すぐに空の結果が表示されないようにします。
- `WeatherSearchResults(text: text)`現在のクエリを使用して結果ビューを構築します。

### NavigationView: プラットフォームごとに検索場所を選択します

（[05:07](https://developer.apple.com/videos/play/wwdc2021/10176/?time=307)）

カラーアプリケーションはダブルカラムを使用します`NavigationView`。バンドル`.searchable`ナビゲーション ビューに配置すると、SwiftUI は列の数とプラットフォームに基づいてデフォルトの関連付けられた列を選択します。 2 列構造により、iOS および iPadOS では検索バーがサイドバーに関連付けられます。 macOS では、検索フィールドがツールバーの末尾の位置に配置されます。

```swift
import SwiftUI

struct ColorsContentView: View {
    @State var text = ""

    var body: some View {
        NavigationView {
            Sidebar(text: $text)
            DetailView()
        }
        .searchable(text: $text)
    }
}

struct Sidebar: View {
    @Binding var text: String

    var body: some View {
        List(filteredPalettes, id: \.self) { palette in
            Text(palette)
        }
    }

    private var filteredPalettes: [String] {
        let palettes = ["Ocean", "Sunset", "Forest", "iMac"]

        if text.isEmpty {
            return palettes
        }

        return palettes.filter { palette in
            palette.localizedCaseInsensitiveContains(text)
        }
    }
}

struct DetailView: View {
    var body: some View {
        Text("Select a palette")
    }
}
```

キーポイント:
- `NavigationView { Sidebar(text: $text); DetailView() }`2 列のインターフェイスを構築します。
- `.searchable(text: $text)`それをナビゲーション ビューに配置し、SwiftUI にデフォルトの列を選択させます。
- `Sidebar`引き継ぐ`text`、クエリを使用してパレット リストをフィルタリングします。
- `DetailView`詳細ペインの内容を保持し、macOS では結果を詳細ペインに表示できます。
- 検索フィールドを他の列に関連付けるには、次のようにします。`.searchable`ターゲット列ビューに移動します。

（[07:15](https://developer.apple.com/videos/play/wwdc2021/10176/?time=435)）

tvOS での一般的な検索エクスペリエンスはタブです。セッション内のメソッドは次のとおりです。tvOS では、コンテンツを次のように置き換えます。`TabView`、バンドル`.searchable`検索タブ;他のプラットフォームでも引き続き`.searchable`ナビゲーションビューに配置します。

```swift
import SwiftUI

struct ColorsContentView: View {
    @State var text = ""

    var body: some View {
        NavigationView {
            #if os(tvOS)
            TabView {
                Sidebar(text: $text)
                    .tabItem { Text("Library") }

                ColorsSearch(text: $text)
                    .searchable(text: $text)
                    .tabItem { Text("Search") }
            }
            #else
            Sidebar(text: $text)
            DetailView()
            #endif
        }
        #if !os(tvOS)
        .searchable(text: $text)
        #endif
    }
}

struct ColorsSearch: View {
    @Binding var text: String

    var body: some View {
        if text.isEmpty {
            Text("Search palettes")
        } else {
            List(["Result for \(text)"], id: \.self) { result in
                Text(result)
            }
        }
    }
}
```

キーポイント:
- `#if os(tvOS)`tvOS に別個のナビゲーション構造を提供します。
- `TabView`tvOS の共通のタブ構造を作成します。
- `ColorsSearch(text: $text).searchable(text: $text)`検索タブのみを検索可能としてマークします。
- `#if !os(tvOS)`他のプラットフォームのデフォルトのナビゲーション ビューの検索動作を保持します。
- `ColorsSearch`クエリが空の場合はプレースホルダーのコンテンツが表示され、クエリが空でない場合は結果が表示されます。

### 提案: 検索提案を使用して、何を検索するかをユーザーに伝えます

（[09:09](https://developer.apple.com/videos/play/wwdc2021/10176/?time=549)）

検索候補により、ユーザーが何を入力すればよいかわからない場合の試行錯誤のコストが削減されます。`.searchable`提案クロージャはビューの配列を返すことができます。セッションには 2 つのモードが表示されます。ボタンを使用してテキストを手動で書き込むか、`searchCompletion`自動的に完了します。

```swift
import SwiftUI

struct ColorsContentView: View {
    @State var text = ""

    private let suggestions = [
        ColorSuggestion(text: "Ocean"),
        ColorSuggestion(text: "Sunset"),
        ColorSuggestion(text: "Forest")
    ]

    var body: some View {
        NavigationView {
            Sidebar(text: $text)
            DetailView()
        }
        .searchable(text: $text) {
            ForEach(suggestions) { suggestion in
                ColorsSuggestionLabel(suggestion)
                    .searchCompletion(suggestion.text)
            }
        }
    }
}

struct ColorSuggestion: Identifiable {
    let id = UUID()
    let text: String
}

struct ColorsSuggestionLabel: View {
    let suggestion: ColorSuggestion

    init(_ suggestion: ColorSuggestion) {
        self.suggestion = suggestion
    }

    var body: some View {
        Text(suggestion.text)
    }
}
```

キーポイント:
- `suggestions`これは動的な提案データであり、セッションではアプリケーション データベースまたはサーバーから取得できると述べられています。
- `.searchable(text: $text) { ... }`末尾のクロージャは、推奨されるビューを提供します。
- `ForEach(suggestions)`提案ごとにラベルを生成します。
- `ColorsSuggestionLabel(suggestion)`非対話型ビューです。
- `.searchCompletion(suggestion.text)`ラベルを選択可能な候補に変換し、検索テキストを更新し、選択後に候補を閉じます。

（[09:43](https://developer.apple.com/videos/play/wwdc2021/10176/?time=583)）

選択動作を自分で制御したい場合は、候補にボタンを配置することもできます。ボタンをクリックした直後に同じものを変更します`text`バインディング。

```swift
import SwiftUI

struct ManualSuggestionsView: View {
    @State private var text = ""

    private let suggestions = [
        ColorSuggestion(text: "Blue"),
        ColorSuggestion(text: "Green"),
        ColorSuggestion(text: "Purple")
    ]

    var body: some View {
        NavigationView {
            List(suggestions) { suggestion in
                Text(suggestion.text)
            }
        }
        .searchable(text: $text) {
            ForEach(suggestions) { suggestion in
                Button {
                    text = suggestion.text
                } label: {
                    ColorsSuggestionLabel(suggestion)
                }
            }
        }
    }
}
```

キーポイント:
- `@State private var text = ""`検索ボックスと候補ボタンで共有される状態です。
- `Button { text = suggestion.text }`クリックすると、提案されたテキストがクエリに書き込まれます。
- `label`同じものを使う`ColorsSuggestionLabel`、表示ロジックを再利用できます。
- この書き方は、追加のカスタム動作が必要な提案に適しています。

### `.onSubmit(of: .search)`: ユーザーが送信した後にクエリを開始します

（[10:21](https://developer.apple.com/videos/play/wwdc2021/10176/?time=621)）

一部の検索は、入力されたすべての文字に適しているわけではありません。たとえば、サーバー側のクエリ、全文検索、高価なデータベース リクエストなどです。 SwiftUIの新機能`onSubmit`修飾子 (修飾子を送信)、渡されます`.search`最後に、ユーザーが検索クエリを送信すると、クロージャが実行されます。セッションへのメンションは通常、検索候補を選択するか、ハードウェア キーボードで Enter キーを押すことによってトリガーされます。

```swift
import SwiftUI

struct SearchSubmitView: View {
    @State private var text = ""
    @State private var results: [String] = []

    var body: some View {
        NavigationView {
            List(results, id: \.self) { result in
                Text(result)
            }
        }
        .searchable(text: $text) {
            MySearchSuggestions()
        }
        .onSubmit(of: .search) {
            fetchResults()
        }
    }

    private func fetchResults() {
        results = ["Submitted query: \(text)"]
    }
}

struct MySearchSuggestions: View {
    var body: some View {
        Text("Ocean")
            .searchCompletion("Ocean")
    }
}
```

キーポイント:
- `.searchable(text: $text)`クエリの入力を担当します。
- `MySearchSuggestions()`実現可能な提案を提供します。
- `.onSubmit(of: .search)`検索の送信のみをリッスンします。
- `fetchResults()`送信後に結果の配列を更新します。
- セッションについても言及`onSubmit`利用可能`TextField`そして`SecureField`非検索送信シナリオ。

## 重要なポイント

1. **手順**: ローカルのお気に入りリストに検索バーを追加します。
**実行する価値がある理由**:`.searchable(text:)`検索フィールドは、iOS、iPadOS、macOS、watchOS の通常どおりに配置されます。
**開始方法**: お気に入りページを含めます`NavigationView`、増加`@State private var text = ""`、バンドル`.searchable(text: $text)`ナビゲーション ビューまたはターゲット列に配置します。

2. **対処方法**: 「検索中に結果を一時的に上書きする」リストを作成します。
**実行する価値がある理由**:`isSearching`通常のブラウジングと検索インタラクションを区別できる`overlay`元のリストのスクロール位置や選択状態を保持できます。
**開始方法**: リストビューで読む`@Environment(\.isSearching)`、いつ`isSearching && !text.isEmpty`ときに使用されます`.overlay`結果ビューを表示します。

3. **操作方法**: 人気のある検索と過去の検索を検索ボックスに追加します。
**実行する価値がある理由**: 提案クロージャは、データベースまたはサーバーのデータに基づいて提案を生成できます。`searchCompletion`クエリ テキストは自動的に入力され、提案はオフになります。
**開始方法**: 1 つを維持します`suggestions`配列、内`.searchable(text:) { ForEach(suggestions) { ... } }`ラベルごとに追加`.searchCompletion(suggestion.text)`。

4. **対処方法**: サーバー側の検索を「送信後のクエリ」に変更します。
**実行する価値がある理由**:`.onSubmit(of: .search)`ユーザーによって明示的に送信された場合にのみ実行され、ネットワーク要求や全文検索に適しています。
**開始方法**:リクエスト関数を入れます`.onSubmit(of: .search) { fetchResults() }`、現在を読み取ります`text`。

5. **やるべきこと**: tvOS アプリケーション用に別の検索タブを作成します。
**実行する価値がある理由**: セッションでは、tvOS では通常、検索がタブとして表示され、元の構造に検索ボックスを詰め込むよりも別の検索ページの方がプラットフォームの習慣に近いことが指摘されました。
**開始方法**:`#if os(tvOS)`支店での使用`TabView`、バンドル`.searchable(text:)`入れます`ColorsSearch`このページで。
