## 詳細

### Web サイトと App Clip の間の関連付けを確立する

([05:04](https://developer.apple.com/videos/play/wwdc2020/10146/?time=304)) App Clip Web サイト URL のコンテンツをレンダリングするには、システムはまず Web サイトと App Clip の間の関係を検証する必要があります。メソッドはサーバーのルートディレクトリにあります`.well-known`apple-app-site-association ファイルをディレクトリに配置し、ルート辞書に追加します。`appclips`エントリ。

```json
{
    "appclips": {
        "apps": [ "ABCDE12345.example.fruta.Clip" ]
    }
}
```

キーポイント:
- `appclips`は、apple-app-site-association ルート辞書の新しいエントリであり、次と組み合わせることができます。`webcredentials`、`applinks`既存のエントリが共存するまで待ちます。
-`apps`この例では、配列には App Clip アプリ識別子が含まれています`ABCDE12345.example.fruta.Clip`チーム ID と App Clip バンドル識別子を表します。
- Xcode 側では、関連ドメイン機能を App Clip ターゲットに追加し、`appclips:your-website-domain`。

### SwiftUI アプリのライフサイクルで起動 URL を処理する

([06:17](https://developer.apple.com/videos/play/wwdc2020/10146/?time=377)) 関連するドメインを構成した後、App Clip はシステムから渡された Web 閲覧アクティビティを読み取る必要があります。 SwiftUI アプリのライフサイクルは直接実行できます。`WindowGroup`ルートビューにぶら下がっています`onContinueUserActivity`。

```swift
import SwiftUI

@main
struct AppClip: App {
    var body: some Scene {
        WindowGroup {
           ContentView()
              .onContinueUserActivity(NSUserActivityTypeBrowsingWeb) { userActivity in
                  guard let incomingURL = userActivity.webpageURL,
                        let components = NSURLComponents(url: incomingURL,
                            resolvingAgainstBaseURL: true)
                  else {
                      return
                  }

                  // Direct to the linked content in your app clip.
              }
        }
    }
}
```

キーポイント:
- `NSUserActivityTypeBrowsingWeb`これを Web ページ URL からの起動のみを処理するように制限します。
-`userActivity.webpageURL`これは、App Clip をトリガーする完全な URL です。実際のビジネスでは、通常、パスまたはクエリ文字列からタスク パラメーターを取得します。
-`NSURLComponents`コードが URL を解析できるようにします (デモで URL を読み取るなど)。`smoothie=BerryBlue`次に、データ ソースを対応するドリンクに切り替えます。
- ユーザーがフル アプリにアップグレードすると、同じリンクでフル アプリが開かれるため、フル アプリにも対応するユニバーサル リンク処理ロジックが必要です。

### UIKit シーンのライフサイクルで同じことを処理します

([06:54](https://developer.apple.com/videos/play/wwdc2020/10146/?time=414)) App Clip が UIKit シーンベースのライフサイクルを使用する場合、入り口は次のとおりです。`UISceneDelegate`。ロジックは SwiftUI と同じです。アクティビティの種類を確認し、URL を取得して、ユーザーをリンク コンテンツに誘導します。

```swift
// Handle NSUserActivity in UISceneDelegate.

class SceneDelegate: UIResponder, UIWindowSceneDelegate {

    func scene(_ scene: UIScene, continue userActivity: NSUserActivity)
    {
        // Get URL components from the incoming user activity
        guard userActivity.activityType == NSUserActivityTypeBrowsingWeb,
            let incomingURL = userActivity.webpageURL,
            let components = NSURLComponents(url: incomingURL,
                resolvingAgainstBaseURL: true)
        else {
            return
        }

        // Direct to the linked content in your app clip.
    }

}
```

キーポイント:
- `scene(_:continue:)`シーンベースのアプリ受信ですか`NSUserActivity`入り口。
-`activityType`チェックすると、Web ページによって開始されないアクティビティをブロックできます。
-`incomingURL`解析が成功したら、ホームページに止まらず、URL に対応するメニュー、予約、レンタル、または支払いのページを直接開く必要があります。

### デフォルトおよび高度な App Clip エクスペリエンスを構成する

([08:32](https://developer.apple.com/videos/play/wwdc2020/10146/?time=512)) App と App Clip を含むビルドを送信すると、App Store Connect に App Clip 構成領域が表示されます。デフォルトのエクスペリエンスでは、カード画像、字幕、アクション動詞が使用されます。 Safari スマート アプリ バナー、メッセージ リンク バブル、およびデフォルトのアプリ クリップ カードはすべて、このメタデータのセットを使用します。

([09:17](https://developer.apple.com/videos/play/wwdc2020/10146/?time=557)) App Clip を NFC、QR コード、マップ、Siri の近くの候補などから起動する場合は、高度な App Clip エクスペリエンスを設定する必要があります。それぞれの高度なエクスペリエンスは URL にバインドされており、独立した画像、タイトル、字幕、動作動詞を設定したり、物理的な場所を関連付けたりできます。

([11:20](https://developer.apple.com/videos/play/wwdc2020/10146/?time=680)) URL マッチングでは、最も具体的なプレフィックス マッチングが使用されます。短いプレフィックスを登録すると、多数の同様のリンクをカバーでき、より具体的な URL を登録すると、特別な店舗や特別なタスクのカードを変更できます。登録 URL がプレフィックスとしてのみ使用されている場合でも、App Clip は登録 URL とまったく同じ起動を処理できなければなりません。これは、近くにあるマップや Siri の提案がこの URL で直接開かれる可能性があるためです。

### Safari ページで App Clip を開かせる

([14:35](https://developer.apple.com/videos/play/wwdc2020/10146/?time=875)) Safari スマート アプリ バナーは、HTML メタ タグを介して App Clip にアクセスします。ウェブページは残ります`app-id`、App Clip バンドル識別子を追加します。このようにして、iOS 14 では App Clip エントリを表示でき、古いシステムでも完全な App の App Store リンクにフォールバックできます。

```html
<meta name="apple-itunes-app"
    content="app-clip-bundle-id=com.example.fruta.Clip,
    app-id=123456789">
```

キーポイント:
- `name="apple-itunes-app"`スマートアプリバナーのメタタグ名を継承します。
-`app-clip-bundle-id`App Clipのバンドル識別子へのポインタ。
-`app-id`引き続き完全なアプリを指し、古いシステムを提供し、アプリのダウンロード シナリオを完了します。
- Safari は、バナーを表示する前に、Web サイトと App Clip のドメインの関連付けを検証します。

## 重要ポイント

### QR コードをスキャンしてストアで注文します App Clip

- **やるべきこと**: レストラン、コーヒーショップ、飲料屋台用のテーブルタグ QR コードまたは NFC タグを生成し、それを開いて現在の店舗の注文ページに直接入力します。
- **実行する価値がある理由**: セッションの Fruta デモは、URL が特定のタスク パラメーターを運ぶことができ、App Clip がそれを読み取った後、対応する製品またはストアを直接選択できることを証明しています。
- **開始方法**: ストア URL プレフィックスを登録し、App Store Connect で高度なエクスペリエンスを構成し、SwiftUI で構成します`onContinueUserActivity`クエリ項目を解析し、現在のメニュー状態を設定します。

### 備品レンタル入口

- **手順**: 自転車、モバイルバッテリー、ロッカー、その他の機器に固有の URL を添付し、コードをスキャンして、対応する機器のレンタルまたはロック解除のページにアクセスします。
- **実行する価値がある理由**: プレフィックス マッチでは、リース プレフィックスのみを登録できるため、クエリ文字列を通じてさまざまなデバイス ID を区別できるため、各デバイスのエクスペリエンスを登録するメンテナンス コストが不要になります。
- **開始方法**: URL クエリ文字列にデバイス ID を入力し、App Clip で使用します`NSURLComponents`パラメータを解析すると、バックエンドはデバイス ID ごとにステータスと実行可能なアクションを返します。

### チェーン店向けのレイヤードカード

- **対処方法**: ほとんどのストアは同じ App Clip カードを使用し、旗艦店やイベント ストアはカスタマイズされた画像と字幕を使用します。
- **実行する価値がある理由**: 高度なエクスペリエンスでは、最も具体的なプレフィックス マッチが使用されるため、ユニバーサル プレフィックスと特別な URL を共存できます。
- **開始方法**: まずは登録してください`https://brand.example/store/`この種の一般的なプレフィックスは、キー ストアのより具体的な URL を登録し、App Store Connect でさまざまなメタデータを構成するために使用されます。

### Web サイトのページから App Clip にアクセス

- **内容**: 予約、簡単な購入、注文の順番待ちなど、App Clip でより迅速に完了できる Web ページに Safari スマート アプリ バナーを表示します。
- **価値がある理由**: スマート アプリ バナーは、アプリ全体の整合性を維持しながら、Web ページへのアクセスを App Clip に変換して開くことができます。`app-id`後退する。
- **開始方法**: ウェブ上で参加します`apple-itunes-app`メタタグ、記入してください`app-clip-bundle-id`そしてフルアプリ`app-id`をクリックし、AASA ファイルと関連ドメインが展開されていることを確認します。

### TestFlight エクスペリエンス マトリックス

- **やるべきこと**: オンラインにする前に、デフォルトのエクスペリエンス、NFC/QR エクスペリエンス、特別なストア エクスペリエンス、Safari バナー エクスペリエンスをカバーする、各タイプの入り口のテスト コール ポイントを確立します。
- **実行する価値がある理由**: セッションでは、TestFlight が App Clip 呼び出しポイントを追加でき、テスターはさまざまな URL に対応する App Clip カードとジャンプを検証できると述べました。
- **開始方法**: 各キー URL を TestFlight の App Clip テスト入口に書き込み、テスターに​​カードのメタデータ、開始結果、およびランディング ページ パラメーターを記録するよう要求します。
