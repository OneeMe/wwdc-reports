## ハイライト

> UIKit アプリは、書き換えることなくvisionOS 上で実行できます。新しいターゲットを追加し、使用できない API を処理し、セマンティック カラーとホバー効果を使用してプラットフォーム スタイルに適応し、Ornament と RealityKit を通じてコン​​テンツを 3 次元空間に拡張します。

## 主な内容

### ステップ 1: iPad アプリをvisionOS に移動する

UIKit で書かれた iPad アプリがあり、それをvisionOS 上で実行したいと考えています。最初のステップは、Xcode の [全般] タブに新しい実行ターゲットを追加することです。

visionOSのアプリケーションアイコンも非常に特殊です。これは、ユーザーがアイコンを見ると動的な反応を生み出す 3 つの重ねられた画像で構成されています。この階層化されたアイコンのセットをアセット カタログに追加する必要があります。

（[02:01](https://developer.apple.com/videos/play/wwdc2023/111215/?time=121)）

ターゲットを追加した後に直接コンパイルすると、エラーが発生する可能性があります。 visionOS はまったく新しいプラットフォームであり、一部の API は適用されなくなりました。

### 使用できない API の処理

visionOS は、iOS 14 より前に廃止された API をサポートしていません。また、プラットフォーム機能の違いにより、一部の API は使用不可としてマークされています。

- **UIDeviceOrientation**: デバイスは回転できると仮定します。visionOS には適用されません。
- **UIScreen**: 単一画面プレゼンテーションの概念は、このプラットフォームでは成立しません。
- **UITabBar の Leading AccessoriesView/trailing AccessoriesView**: タブ バーのレイアウト方向が異なります

（[03:22](https://developer.apple.com/videos/play/wwdc2023/111215/?time=202)）

この例のピクセル アート アプリケーションでは、`UIPencilInteraction`、visionOS は Apple Pencil をサポートしていないため、この API は利用できません。解決策は、条件付きコンパイルを使用してそれを除外することです。

```swift
#if !os(xrOS)
// Apple Pencil interaction code
let pencilInteraction = UIPencilInteraction()
pencilInteraction.delegate = self
view.addInteraction(pencilInteraction)
#endif
```

コンパイル エラーを修正すると、アプリを共有スペースで実行できるようになります。ガラス マテリアルの背景とホバー効果は、システムによってデフォルトで提供されます。

### セマンティックな色とマテリアル: アプリケーションをプラットフォームに統合する

このアプリは、iPad では白の背景に黒のタイトル テキストで見栄えがしますが、visionOS のガラスの背景では不快に見えます。

このプラットフォームでは、セマンティック カラーが特に重要です。`UIColor.label`、`UIColor.secondaryLabel`システムの色は、プラットフォーム、外観、アクセシビリティの設定に自動的に適応します。 UILabel は、セマンティック カラーを使用すると、デフォルトで鮮やかな効果を得ることができます。

（[06:58](https://developer.apple.com/videos/play/wwdc2023/111215/?time=418)）

### ホバー効果: インタラクションを知覚できるようにする

visionOS では、ユーザーが要素を見るとホバー効果が発生します。システム コントロールにはデフォルトでホバー効果が付属していますが、カスタム ビューにホバー効果を追加することもできます。

UIViewが追加されました`hoverStyle`財産。に設定できます`.highlight`または`.lift`エフェクトを使用することもできます`UIShape`API のカスタム形状。に設定`nil`次にホバー効果を削除します。

（[10:49](https://developer.apple.com/videos/play/wwdc2023/111215/?time=649)）

### 入力方法の変更

visionOS では、新しい入力システムが導入されています。

- **視線+ピンチリリース** = タップジェスチャ
- **視線 + ピンチして手を動かす** = パン ジェスチャ
- **近距離での直接接触** = 物理的な接触
- **トラックパッド** = ペアリング後に使用可能
- **アクセシビリティ** = VoiceOver とスイッチ コントロールの両方がサポートされています

このプラットフォームは、最大 2 つの同時入力 (両手に 1 つずつ) をサポートします。サンプル アプリケーションは当初、4 本指のスワイプを使用してすべてのコンテンツを削除していました。 visionOS では、2 本指スワイプに変更できます。

### 空間 UIKit プレゼンテーション

UIKit プレゼンテーションは、visionOS で空間スタイルを取得します。

**シート**: 表示中のビュー コントローラーを押し戻し、押し出すと暗くなります。 iPadとは異なり、シートの外側をタップしてもシートは自動的に閉じられません。

**警告**: アプリ アイコンの 2D 表現を上部に配置します。プッシュバックする必要があるビュー コントローラーから常に存在します。

**ポップオーバー**:visionOS では、シーンの境界に制限されず、アプリケーション ウィンドウを超えることができます。でも気をつけてね`permittedArrowDirections`設定。

（[14:26](https://developer.apple.com/videos/play/wwdc2023/111215/?time=866)）

### コード例: ポップオーバーの矢印の方向を修正する

```swift
import UIKit

extension EditorViewController {

    @objc func showDocumentPopover(sender: UIBarButtonItem) {
        let controller = DocumentInfoViewController(document: pixelDocument)
        controller.modalPresentationStyle = .popover
        if let presentationController = controller.popoverPresentationController {
            presentationController.barButtonItem = sender
            if traitCollection.userInterfaceIdiom == .reality {
                presentationController.permittedArrowDirections = .any
            } else {
                presentationController.permittedArrowDirections = .right
            }
        }
        present(controller, animated: true, completion: nil)
    }

}
```

キーポイント:
- `traitCollection.userInterfaceIdiom == .reality`visionOS で実行されているかどうかを確認する
-visionOS のポップオーバーはシーンの境界に制限されません。`.any`システムに最適な場所を選択させます
- iPad に保存しておく`.right`ポップオーバーが画面を超えないように制限する

### 装飾: コンテンツをシーンの外に配置する

オーナメントは、アプリケーション シーンの周囲にコンテンツを配置できるようにする、visionOS の新しい概念です。システム コンポーネントも使用されます。SwiftUI の TabView はタブ バーを先端の装飾に配置し、Safari は装飾を使用してナビゲーション バーを配置し、Freeform は装飾を下部のツールバーとして使用します。

装飾をメインコンテンツの前に高めて、奥行き感を加えています。これらはビュー コントローラーのライフ サイクルにバインドされており、シートがレンダリングされるときに相対位置を維持します。

（[17:15](https://developer.apple.com/videos/play/wwdc2023/111215/?time=1035)）

### コード例: オーナメントの作成

```swift
import UIKit
import SwiftUI

extension EditorViewController {

    func showEditingControlsOrnament() {
        let ornament = UIHostingOrnament(
            sceneAlignment: .bottom,
            contentAlignment: .center
        ) {
            EditingControlsView(model: controlsViewModel)
                .glassBackgroundEffect()
        }

        self.ornaments = [ornament]
        editorView.style = .edgeToEdge
    }

}
```

キーポイント:
- `UIHostingOrnament`SwiftUI コンテンツのホスティング (必須)`import SwiftUI`
- `sceneAlignment: .bottom`オーナメントをシーンの下端に配置します
-`contentAlignment: .center`コンテンツを端の中央に配置する
-`.glassBackgroundEffect()`飾りにガラスの背景を追加する
-`ornaments`オーナメントの配列を受け入れる UIViewController の新しいプロパティです
- オーナメントはビュー コントローラーのライフサイクルにバインドされています。ビュー コントローラーを削除すると、装飾は自動的に消えます。

### コード例: プラットフォームに基づいてジェスチャを調整する

func fourFingerSwipe() {
    let gesture = UISwipeGestureRecognizer(
        target: self,

### RealityKit と UIKit の使用

RealityView は、RealityKit コンテンツをホストするための新しい SwiftUI ビューです。合格`UIHostingController`を使用すると、アプリ全体を書き換えることなく、UIKit アプリに RealityView を埋め込むことができます。

（[21:56](https://developer.apple.com/videos/play/wwdc2023/111215/?time=1316)）

### コード例: UIKit への RealityView の埋め込み

```swift
import UIKit
import SwiftUI
import RealityKit

extension EditorViewController {

    func showEntityPreview() {
        let entityView = PixelArtEntityView(model: entityViewModel)
        let controller = UIHostingController(rootView: entityView)
        addChild(controller)
        view.addSubview(controller.view)
        controller.didMove(toParent: self)
        prepareEditorInteractions()
    }

}
```

キーポイント:
- `UIHostingController`SwiftUI ビューを UIKit ビュー階層に埋め込む
-`PixelArtEntityView`社内使用`RealityView`RealityKit エンティティのレンダリング
- 標準の子ビュー コントローラーのライフサイクル管理:`addChild` → `addSubview` → `didMove(toParent:)`- この方法により、既存の UIKit アプリケーションが書き換えることなく 3D 機能を獲得できるようになります。

## 重要なポイント

- **既存の iPad アプリをvisionOS に移植**
  - **やるべきこと**:visionOS ターゲットを既存の UIKit アプリケーション (描画ツール、メモ作成アプリケーション、リーダーなど) に追加し、スペース内で実行できるようにします。
  - **実行する価値がある理由**: UIKit アプリケーションは、ほぼゼロのコストで新しい実行環境を取得し、ユーザーはより大きな仮想空間でアプリケーションを使用できるようになります。
  - **開始方法**: Xcode の [全般] タブにvisionOS ターゲットを追加し、コンパイル エラー (非推奨の API およびプラットフォーム互換性のない API) を処理し、ハードコードされた色をセマンティック カラーに置き換えます。

- **オーナメントを使用してツールバーを再設計**
  - **何をすべきか**: 従来の下部ツールバーまたはサイドバーを装飾に抽出して、メイン コンテンツ領域を最大化します。
  - **実行する価値がある理由**: オーナメントは 2D ウィンドウの境界を打ち破ります。ツール コントロールはメイン コンテンツの周りに一時停止されており、ブロックされておらず、すぐにアクセスできます。
  - **開始方法**: を使用します`UIHostingOrnament`SwiftUI ツールバー ビューをラップし、適切な設定を行います`sceneAlignment`そして`contentAlignment`、飾りに加えます`.glassBackgroundEffect()`

- **3D プレビュー機能をアプリに追加します**
  - **内容**: RealityView を UIKit アプリに埋め込んで、ユーザーが 3D コンテンツをあらゆる角度から表示できるようにします
  - **実行する価値がある理由**: アプリケーション全体を書き直す必要はなく、1 つだけ書き直すだけです。`UIHostingController`3D 機能を既存のインターフェースに注入できる
  - **開始方法**: 以下を含む SwiftUI ビューを作成します。`RealityView`、使用`UIHostingController`UIKitのビューコントローラに埋め込まれ、子ビューコントローラのライフサイクルを通じて管理されます。

- **空間ポップオーバー インタラクションをデザイン**
  - **やるべきこと**: シーンの境界に制限されないvisionOSのポップオーバー機能を使用して、より柔軟なコンテキスト メニューを設計します。
  - **実行する価値がある理由**: ポップオーバーはアプリケーション ウィンドウを超えて拡張でき、より自然な方向性のインタラクションを提供できます。
  - **開始方法**: 確認してください`permittedArrowDirections`、visionOS で使用される`.any`システムが最適な場所を自動的に選択し、ハードコードされたプラットフォームの想定を回避します。
