## ハイライト

> iOS 14 では、UIKit のページ コントロール、カラー ピッカー、日付ピッカー、メニュー、UIAction に新しいシステム レベルの動作が導入され、開発者は既製のコントロールを使用して色の選択、コンパクトな日付入力、非同期メニュー、および統合イベント コールバックを処理できるようになります。

## 主な内容

このセッションは、非常に一般的なインターフェイスの問題を解決します。アプリには小さなインタラクションが多数あり、開発者自身がそれに取り組むことがよくあります。ページング インジケーターは多くのページをサポートする必要があり、色の選択はスポイトとお気に入りの色をサポートする必要があり、日付入力はフォームに挿入する必要があり、一連のコンテキスト アクションをボタンの横にハングする必要があります。これらの機能を自分で実行する場合、インタラクションの詳細、アクセシビリティ、ポインタ入力、および Catalyst の外観を見逃しがちです。 ([00:24](https://developer.apple.com/videos/play/wwdc2020/10052/?time=24))

Apple は、これらのインタラクションを iOS 14 の UIKit コントロールに組み込みました。「UIPageControl」は、固定幅内の無制限のページとカスタム インジケーター画像をサポートします。 `UIColorPickerViewController` は、カラー グリッド、スペクトル、RGB、16 進数、コレクション カラー、およびスポイトを担当します。 `UIDatePicker` はコンパクトなインライン スタイルを追加し、フォームと大きな画面の両方で同じ API セットを使用できます。 ([03:20](https://developer.apple.com/videos/play/wwdc2020/10052/?time=200))

後半ではメニューとアクションに焦点が当てられます。 iOS 14では、「UIMenu」を「UIButton」や「UIBarButtonItem」に直接アタッチできるようになり、長押しやタッチで開くことができます。 `UIDeferredMenuElement` を使用すると、メニュー項目を非同期に生成でき、`updateVisibleMenu` を使用すると、表示されたメニューを更新できます。 `UIAction` は、ボタン、バー ボタン アイテム、およびセグメント化されたコントロールのイベント処理をコントロールが作成された場所に配置し、散在するターゲット アクション コードを削減します。 ([11:15](https://developer.apple.com/videos/play/wwdc2020/10052/?time=675))

これらの機能は iPad および Mac Catalyst にも役立ちます。講演の中で何度も言及されたのは、最適化された Catalyst アプリでは標準コントロールが macOS に近い外観を採用するということです。日付ピッカーのコンパクトなスタイルは、ポインター入力にも適しています。開発者が作成するカスタム コントロールの量が減り、アプリはシステム プラットフォームの違いに容易に対応できるようになります。 ([01:38](https://developer.apple.com/videos/play/wwdc2020/10052/?time=98))

### ページ コントロールは、固定スペースでより多くのページをホストできます

([04:34](https://developer.apple.com/videos/play/wwdc2020/10052/?time=274)) `UIPageControl` の新しい外観により、コントロールは固定サイズ内の任意の数のページをサポートできるようになります。スペースが不十分な場合、ユーザーはページポイント間をスクラブしたりスクロールしたりできます。また、ブックマーク ページやコレクション ページなどの特別な意味を持つページに適した、インジケーターの画像と背景スタイルのカスタマイズも追加されます。```swift
let pageControl = UIPageControl()
pageControl.numberOfPages = 5

pageControl.backgroundStyle = .prominent

pageControl.preferredIndicatorImage =
    UIImage(systemName: "bookmark.fill")

pageControl.setIndicatorImage(
    UIImage(systemName: "heart.fill"), forPage: 0)
```キーポイント:
- `numberOfPages` は引き続き元の API を使用しており、移行コストは低くなっています。
- `backgroundStyle = .prominent` により、背景領域を継続的に表示できます。これは、ページ コントロールをメイン コントロールとして使用するインターフェイスに適しています。
- `preferredIndicatorImage` はすべてのページのデフォルト画像を設定します。
- `setIndicatorImage(_:forPage:)` は特定のページに別のアイコンを設定できます。スピーチでは、0 ページにハートの形を使用して収集を示します。

### カラーピッカーは完全な色選択プロセスを担当します

([06:56](https://developer.apple.com/videos/play/wwdc2020/10052/?time=416)) `UIColorPickerViewController` は、シートまたはポップオーバーとして表示できるビュー コントローラーです。ユーザーは、グリッド、スペクトル、RGB、16 進値から色を選択したり、頻繁に使用する色を保存したりできます。 iPadOS のスポイトは画面上のどこからでも色を選択でき、Mac Catalyst では標準の macOS カラー パネルが使用されます。```swift
var color = UIColor.blue
var colorPicker = UIColorPickerViewController()

func pickColor() {
    colorPicker.supportsAlpha = true
    colorPicker.selectedColor = color
    self.present(colorPicker,
        animated: true,
      completion: nil)
}

func colorPickerViewControllerDidSelectColor(_
  viewController: UIColorPickerViewController) {
    color = viewController.selectedColor
}

func colorPickerViewControllerDidFinish(_
  viewController: UIColorPickerViewController) {
    // Do nothing
}
```キーポイント:
- `supportsAlpha` は、透明度を許可するかどうかを制御します。
- `selectedColor` は表示する前に現在の色を書き込み、ユーザーはそれを開いた後に既存の値を確認できます。
- `present` はシステム カラー ピッカーの表示を担当します。アプリ自体でスポイトやコレクションの色を実装する必要はありません。
- ユーザーが色を選択した後、`colorPickerViewControllerDidSelectColor` は `selectedColor` を読み取ります。
- ユーザーのキャンセルを処理する必要はありません。講義内の「DidFinish」サンプルでは、​​空の実装を明示的に選択しました。

### 日付ピッカーは同じ API を使用してコンパクト スタイルとインライン スタイルを切り替えます

([10:04](https://developer.apple.com/videos/play/wwdc2020/10052/?time=604)) iOS 14 および iPadOS 14 の `UIDatePicker` により、コンパクトなスタイルが追加されます。日付と時刻がフィールドとして表示され、日付をクリックするとカレンダーが開き、時刻をクリックするとキーボード入力が開きます。表形式またはフォームでのコンパクトなレイアウトに適しています。インライン スタイルは、日付の選択がインターフェイスの主なタスクであるシナリオに適しています。この講演では、新しいスタイルによって「UIDatePicker」の基礎となる API が変更されないことが強調されています。```swift
let datePicker = UIDatePicker()
datePicker.date = Date(timeIntervalSinceReferenceDate:
                       timeInterval)

datePicker.preferredDatePickerStyle = .compact

datePicker.calendar = Calendar(identifier: .japanese)
datePicker.datePickerMode = .date

datePicker.addTarget(self,
             action: #selector(dateSet),
                for: .valueChanged)
```キーポイント:
- `date` は引き続き元のメソッドを使用して初期値を設定します。
- `preferredDatePickerStyle = .compact` は表示のみを変更します。
・「カレンダー」を和暦などの暦法に変更し、対応した内容を新しいスタイルで表示します。
- `datePickerMode = .date` は選択を日付に制限し、無関係な時間入力を非表示にします。
- `addTarget(_:action:for:)` は、値の変更をリッスンする `UIControl` として扱います。

### メニューは非同期的に生成したり、表示されているコンテンツを更新したりできます。

([14:20](https://developer.apple.com/videos/play/wwdc2020/10052/?time=860)) iOS 14 では、`UIButton` と `UIBarButtonItem` が `menu` を直接サポートできるようになります。デフォルトでは長押しするとメニューが表示されます。 `UIButton`は、`showsMenuAsPrimaryAction`を通じてタッチするとすぐに表示できます。メニューがあり、主要なアクションがない場合、「UIBarButtonItem」はタッチ時にも表示されます。複雑なメニューは、「UIDeferredMenuElement」を使用して遅延生成できます。```swift
button.menu = UIMenu(title: "", children: [
    UIMenu(title: "", options: .displayInline, children: (1...2).map { UIAction(title: "Static Item \($0)") { action in }}),
    UIDeferredMenuElement({ completion in
        DispatchQueue.main.asyncAfter(deadline: .now() + 2.0) {
            completion([UIMenu(title: "", options: .displayInline, children: (1...2).map { UIAction(title: "Dynamic Item \($0)") { action in }})])
        }
    }),
])
```キーポイント:
- `button.menu` はメニューをボタンに直接ハングし、UIKit がその表示を担当します。
- 最初の `UIMenu` は静的項目を保持し、`options: .displayInline` はそれらをインラインで表示します。
- `UIDeferredMenuElement` のクロージャは `completion` を非同期的に呼び出します。これは、メニュー項目を追加する前にデータの準備ができるのを待つのに適しています。
- UIKit は待機期間中に標準の読み込み UI を表示し、生成されたアイテムを後続の表示でキャッシュします。

([14:50](https://developer.apple.com/videos/play/wwdc2020/10052/?time=890)) 開いているメニューも更新できます。 `UIContextMenuInteraction` の `updateVisibleMenu` は、現在のメニューのコピーを渡し、現在の表示コンテンツを置き換える新しいメニューを返します。```swift
self.contextMenuInteraction.updateVisibleMenu { currentMenu -> UIMenu in
    currentMenu.children.forEach { element in
        guard let action = element as? UIAction else { return }

        action.state = Bool.random() ? .off : .on
        action.attributes = Bool.random() ? [.hidden] : []
    }
    return currentMenu
}
```キーポイント:
- `updateVisibleMenu` は、ユーザーに表示されているメニューのみを処理します。
- `currentMenu.children` は現在のメニュー項目を横断できます。
- この例では `UIAction` のみを更新し、他のメニュー要素は直接スキップされます。
- `state` は選択状態を切り替えることができ、`attributes` は項目を非表示にすることができます。
- iOS 14 の `UIMenu` は子を不変にすることを強制しなくなったので、受信メニューを更新して直接戻ることができます。

### UIAction はイベント処理をコントロール作成サイトに戻します

([16:05](https://developer.apple.com/videos/play/wwdc2020/10052/?time=965)) `UIAction` は iOS 13 で導入され、iOS 14 ではさらに多くのコントロールに拡張されました。 `UIBarButtonItem` は、アクションを実行するだけのボタン、メニューを表示するだけのボタン、またはタップ アクションと長押しメニューの両方をサポートするボタンを作成できる新しいイニシャライザを追加します。```swift
let saveAction = UIAction(title: "") { action in }
let saveMenu = UIMenu(title: "", children: [
    UIAction(title: "Copy", image: UIImage(systemName: "doc.on.doc")) { action in },
    UIAction(title: "Rename", image: UIImage(systemName: "pencil")) { action in },
    UIAction(title: "Duplicate", image: UIImage(systemName: "plus.square.on.square")) { action in },
    UIAction(title: "Move", image: UIImage(systemName: "folder")) { action in },
])
let optionsImage = UIImage(systemName: "ellipsis.circle")
let optionsMenu = UIMenu(title: "", children: [
    UIAction(title: "Info", image: UIImage(systemName: "info.circle")) { action in },
    UIAction(title: "Share", image: UIImage(systemName: "square.and.arrow.up")) { action in },
    UIAction(title: "Collaborate", image: UIImage(systemName: "person.crop.circle.badge.plus")) { action in },
])
let revertAction = UIAction(title: "Revert") { action in }
self.toolbarItems = [
    UIBarButtonItem(systemItem: .save, primaryAction: saveAction, menu: saveMenu),
    .fixedSpace(width:20.0),
    UIBarButtonItem(image: optionsImage, menu: optionsMenu),
    .flexibleSpace(),
    UIBarButtonItem(primaryAction: revertAction),
]
```キーポイント:
- `primaryAction` はクリックを処理し、`menu` はその他のアクションを処理します。
- `UIAction` は、メニュー項目としても、バー ボタン項目のメイン アクションとしても使用できます。
- 画像とメニューがあるが主なアクションがないバー ボタン項目は、タッチするとメニューが表示されます。
- `.fixedSpace(width:)` と `.flexibleSpace()` は、スピーチで示された新しいツールバー項目の設定メソッドです。
- 同じツールバーで、保存、その他のオプション、および元に戻す操作を混在させることができます。

([17:41](https://developer.apple.com/videos/play/wwdc2020/10052/?time=1061)) `UISegmentedControl` は、`UIAction` によって作成されたセグメントもサポートします。各セグメントのハンドラーは設定された位置の近くにあり、ユーザーがセグメントを選択すると、対応するアクションのみが呼び出されます。講演では、ケースが追加されたときに構成と応答ロジックが一緒に更新されるように、列挙型を使用してアクションを生成することを提案しました。

## 重要なポイント

- **ブランドカラーをサポートするエディター設定ページを作成します**: `UIColorPickerViewController` を使用して、ユーザーがテーマカラーを選択できるようにします。すでにグリッド、スペクトル、RGB、16 進数、コレクション カラー、スポイトを処理しています。実装のエントリ ポイントは、ピッカーを表示し、`selectedColor` を設定し、選択内容をデリゲート コールバックに保存することです。

- **フォームの日付フィールドを再加工**: スペースを消費するスクロール ホイールを `UIDatePicker` コンパクト スタイルに変更します。テーブルビューまたは複数フィールドのフォームに適しています。実装エントリでは、`preferredDatePickerStyle = .compact` を設定し、`datePickerMode` を使用して日付または時刻のみの選択を制限します。

- **長押しメニューをツールバー ボタンに追加**: 保存、詳細、共有などのボタンには、主要なアクションとメニューを同時に含めることができます。実装エントリは、`UIBarButtonItem(systemItem:primaryAction:menu:)` または `UIBarButtonItem(image:menu:)` を使用して、共通アクションと拡張アクションを整理することです。

- **ネットワーク データを必要とするメニューを遅延読み込みに変更**: フォルダー、プロジェクト リスト、コラボレーター リストなどのメニュー項目は、`UIDeferredMenuElement` を使用して生成できます。ユーザーがメニューを開いた後、最初にシステムの読み込み UI が表示されます。データが返された後、「completion」が呼び出されてメニューにデータが入力されます。

- **セグメント化されたコントロールのオプションと処理ロジックを統合する**: `UIAction` を使用して各セグメントを作成し、`selectedSegmentIndex` を使用してスイッチを書き込むのを避けます。エントリ ポイントは、enum を使用して一連のアクションを生成し、それらを `UISegmentedControl` の新しいイニシャライザに渡すことです。
