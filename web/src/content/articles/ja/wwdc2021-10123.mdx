## ハイライト

> Apple は、iOS および iPadOS 15 で Screen Time API を導入しました。これにより、ペアレンタル コントロール アプリは、アプリと Web サイトの使用状況データをデバイス上に残しながら、ファミリー コントロール、デバイス アクティビティ、および管理対象設定を通じて保護者の承認を要求し、使用時間を監視し、制限を強制することができます。

## 主な内容

ペアレンタルコントロールアプリの主な問題は常に子供のデバイスにありました。

親がルールを設定すると、通常、子供はアプリを積極的に開かなくなります。開発者にとって、適切なタイミングでコードを実行し、ルールが常に有効であることを確認することは困難です。たとえば、夜の 10 時以降にゲームをブロックしたり、学習アプリを 30 分間使用した後にエンターテイメント アプリのブロックを解除したりすることができます。従来のバックグラウンド タスクは、このシナリオには適していません。

プライバシーの問題はよりデリケートです。ペアレンタルコントロールアプリは、アプリの使用記録、Web サイトのアクセス記録、カテゴリの選択などの情報に遭遇します。開発者は何を制限するかを知る必要がありますが、子供がどのアプリを使用したか、どの Web サイトにアクセスしたかをサーバーに送信すべきではありません。

Screen Time API は、これを 3 つのフレームワークに分類します。

ファミリー コントロールは、承認とプライバシーの境界を担当します。これはファミリー共有に依存しており、保護者はスクリーンタイム API を使用してアプリを承認する必要があり、アプリ、Web サイト、カテゴリを表すために不透明なトークンを使用します。

デバイス アクティビティは、アプリが起動していないときに拡張機能を実行する責任があります。開発者は時間枠と使用量のしきい値を宣言し、時間の開始時、終了時、またはしきい値に到達したときに、システムが内線番号を呼び出します。

管理設定は実際に制限を適用する責任があります。拡張機能を有効にすると、アカウントのロック、パスワード変更の禁止、Web トラフィックのフィルタリング、アプリのブロック、または以前に設定した設定のブロック解除を行うことができます。

これら 3 つのフレームワークは相互に接続されて完全なプロセスを形成します。保護者が子デバイスで承認し、親デバイスがルールを選択し、ルールが子デバイスに同期され、管理設定の制限が子デバイスのデバイス アクティビティ拡張機能によってトリガーされます。

### ファミリーコントロール: 最初に保護者に許可してもらいます

([07:22](https://developer.apple.com/videos/play/wwdc2021/10123/?time=442)) 宿題デモの最初のステップは、アプリの起動時にファミリーコントロールの認証をリクエストすることです。この演説では、この要請には家族の後見人の承認が必要であることが明らかになった。初めて実行するとき、システムは認証プロンプトを表示します。保護者が「許可」をクリックした後、Apple ID とパスワードで認証する必要があります。

```swift
import FamilyControls
import SwiftUI

@main
struct HomeworkApp: App {
    @StateObject private var model = HomeworkModel()

    var body: some Scene {
        WindowGroup {
            ContentView()
                .environmentObject(model)
                .task {
                    AuthorizationCenter.shared.requestAuthorization { result in
                        switch result {
                        case .success:
                            model.isAuthorized = true
                        case .failure:
                            model.isAuthorized = false
                        }
                    }
                }
        }
    }
}

final class HomeworkModel: ObservableObject {
    @Published var isAuthorized = false
}
```

キーポイント:
- `import FamilyControls`ファミリーコントロールフレームワークの紹介。
- `AuthorizationCenter.shared`共有認証センターを使用してリクエストを開始します。
- `requestAuthorization`保護者の承認プロセスが開始されます。
- `.success`現在の子供のデバイスが認証されていることを示します。
- `.failure`これは、トークの 08:06 で言及されている、ファミリー共有の子アカウントの一部ではない iCloud アカウントにログインしたときに発生する可能性があります。

([08:25](https://developer.apple.com/videos/play/wwdc2021/10123/?time=505)) 認証が成功すると、システムレベルの保護も行われます。子供のデバイスは iCloud からサインアウトできません。アプリにネットワーク拡張機能に基づくデバイス上の Web コンテンツ フィルターが含まれている場合、そのフィルターは自動的にインストールされ、子供による削除が防止されます。

### デバイスアクティビティ: 時間枠に従って拡張機能を実行します。

([09:31](https://developer.apple.com/videos/play/wwdc2021/10123/?time=571)) 子供たちはペアレンタルコントロールアプリを積極的に開かないので、宿題はデバイスアクティビティスケジュールを使用して毎日ブロックを設定します。講演では、スケジュールは時間枠であり、システムは時間枠の最初と最後にアプリ拡張機能を呼び出すと述べました。

```swift
import DeviceActivity

final class HomeworkMonitor: DeviceActivityMonitor {
    override func intervalDidStart(for activity: DeviceActivityName) {
        // 时间窗口开始后，系统第一次使用设备时调用这里。
    }

    override func intervalDidEnd(for activity: DeviceActivityName) {
        // 时间窗口结束后，系统第一次使用设备时调用这里。
    }
}
```

キーポイント:
- `DeviceActivityMonitor`拡張プリンシパルクラスです。
- `intervalDidStart`対応する時間枠が始まります。
- `intervalDidEnd`対応する時間枠が終了します。
- トークでは 10:14 で、デバイスが初めて使用されるとき、つまり時間の開始時または終了後にこれら 2 つのメソッドが呼び出されることが説明されています。

([10:26](https://developer.apple.com/videos/play/wwdc2021/10123/?time=626)) メインアプリはアクティビティ名とスケジュールを作成する必要があります。名前は、拡張機能内のアクティビティを識別するために使用されます。スケジュールは、監視の時間範囲を示すために使用されます。宿題のデモ アクティビティに名前を付けます`daily`、毎日繰り返すように設定します。

```swift
import DeviceActivity
import Foundation

let daily = DeviceActivityName("daily")

let schedule = DeviceActivitySchedule(
    intervalStart: DateComponents(hour: 0, minute: 0),
    intervalEnd: DateComponents(hour: 23, minute: 59),
    repeats: true
)

let center = DeviceActivityCenter()
try center.startMonitoring(daily, during: schedule)
```

キーポイント:
- `DeviceActivityName("daily")`この監視ルールに名前を付けると、内線コールバックも同じ名前を受け取ります。
- `DeviceActivitySchedule`時間の境界を定義します。
- `repeats: true`このルールが繰り返し実行されることを示します。
- `DeviceActivityCenter`登録の監視を担当します。
- `startMonitoring`システムに名前とスケジュールを指定すると、システム コールによって拡張されます。

### ファミリー アクティビティ ピッカー: 保護者がアプリ、ウェブサイト、カテゴリを選択できるようにします

([11:09](https://developer.apple.com/videos/play/wwdc2021/10123/?time=669)) 制限する前に、保護者が何を制限したいのかを知る必要があります。 Family Controls は、SwiftUI コンポーネント Family Activity Picker を提供します。保護者は家族が利用するアプリやWebサイト、カテゴリからアイテムを選択できる。

```swift
import FamilyControls
import SwiftUI

struct ContentView: View {
    @State private var isPickerPresented = false
    @State private var selection = FamilyActivitySelection()

    var body: some View {
        Button("Select discouraged apps") {
            isPickerPresented = true
        }
        .familyActivityPicker(
            isPresented: $isPickerPresented,
            selection: $selection
        )
    }
}
```

キーポイント:
- `FamilyActivitySelection`ガーディアンの選択を保存します。
- `Button`セレクター表示をトリガーします。
- `familyActivityPicker`それはスピーチで言及された SwiftUI ビュー修飾子です。
- `selection`App モデルにバインドすると、ガーディアンの選択の更新がモデルに書き戻されます。
- 選択結果は不透明なトークンであり、対応するアプリ、Web サイト、カテゴリを制限または監視するために使用されます。

([04:08](https://developer.apple.com/videos/play/wwdc2021/10123/?time=248)) これらのトークンは、設計上のプライバシーの鍵です。このシステムでは、アプリが制限や監視のためにトークンを使用することを許可していますが、トークンはアプリや Web サイトの読み取り可能な ID を明らかにするものではなく、ファミリー共有グループ以外のユーザーは子供が具体的に何を使用しているかを知ることができません。

### 管理設定: 拡張機能でのブロックとブロック解除

([11:59](https://developer.apple.com/videos/play/wwdc2021/10123/?time=719)) 拡張機能は、ガーディアンの選択を取得した後、時間ウィンドウの開始時にアプリケーション ブロックを設定し、時間ウィンドウの終了時にブロックをクリアします。講演では、アプリケーション シールドの制限にアクセスするには管理設定モジュールをインポートする必要があることが明確に述べられていました。

```swift
import DeviceActivity
import ManagedSettings

final class HomeworkMonitor: DeviceActivityMonitor {
    private let store = ManagedSettingsStore()
    private let model = HomeworkModel.shared

    override func intervalDidStart(for activity: DeviceActivityName) {
        store.shield.applications = model.discouragedSelection.applicationTokens
    }

    override func intervalDidEnd(for activity: DeviceActivityName) {
        store.shield.applications = nil
    }
}
```

キーポイント:
- `import ManagedSettings`制限機能を導入します。
- `ManagedSettingsStore`デバイスに適用する制限を保存します。
- `store.shield.applications`スピーチにおけるアプリケーションシールド制限に対応。
- `model.discouragedSelection.applicationTokens`ファミリー アクティビティ ピッカーからの不透明なトークン。
- `nil`以前に設定したアプリブロックを削除することを示します。この操作については、12:14 のスピーチで直接説明されています。

([12:30](https://developer.apple.com/videos/play/wwdc2021/10123/?time=750)) 管理設定はアプリのブロックに限定されません。演説で挙げられた制限には、アカウントの作成や削除のブロック、アプリやウェブサイトの完全なブロック、年齢によるメディアコンテンツの制限も含まれる。メディア アプリは、映画やテレビのコンテンツ制限を読み取ることもでき、ファミリー コントロールの承認は必要ありません。

### デバイスアクティビティイベント: 使用量のしきい値による制限なし

([13:51](https://developer.apple.com/videos/play/wwdc2021/10123/?time=831)) 宿題デモの 2 番目のルールは、子供たちが刺激的なアプリを十分に使用した後、エンターテイメント アプリのブロックを解除することです。ここでは、デバイス アクティビティ イベントを使用して、使用量のしきい値を監視します。

```swift
import DeviceActivity
import FamilyControls
import Foundation

let daily = DeviceActivityName("daily")
let encouraged = DeviceActivityEvent.Name("encouraged")

let event = DeviceActivityEvent(
    applications: model.encouragedSelection.applicationTokens,
    threshold: DateComponents(minute: 30)
)

let center = DeviceActivityCenter()
try center.startMonitoring(
    daily,
    during: schedule,
    events: [encouraged: event]
)
```

キーポイント:
- `DeviceActivityEvent.Name("encouraged")`イベントに名前を付けます。拡張コールバックはこの名前を使用してイベントを識別します。
- `applications`保護者が選んだ心強いアプリトークンを使用してください。
- `threshold`蓄積される使用時間を示します。音声では使用しきい値と呼ばれます。
- `events`13:41に記載されているスケジュールに登録してください。
- しきい値に達すると、システムはデバイス アクティビティ モニター拡張機能を呼び出します。

([14:46](https://developer.apple.com/videos/play/wwdc2021/10123/?time=886)) 拡張機能が通過しました`eventDidReachThreshold`通知を受け取ります。宿題が届いています`encouraged`イベント後、アプリのブロックを次のように設定します。`nil`、以前にブロックされたアプリを再び利用できるようになります。

```swift
import DeviceActivity
import ManagedSettings

final class HomeworkMonitor: DeviceActivityMonitor {
    private let store = ManagedSettingsStore()

    override func eventDidReachThreshold(
        _ event: DeviceActivityEvent.Name,
        activity: DeviceActivityName
    ) {
        if event == DeviceActivityEvent.Name("encouraged") {
            store.shield.applications = nil
        }
    }
}
```

キーポイント:
- `eventDidReachThreshold`使用量のしきい値に達すると呼び出されます。
- `event`トリガーされたイベントの名前を示します。
- `activity`イベントがどのスケジュールに属しているかを示します。
- 裁判官`encouraged`次に、ブロックを解除して、他のイベントによる誤ったトリガーを回避します。
- `store.shield.applications = nil`以前のブロック解除方法を再利用します。

### カスタム シールド: システム シールド ページを独自のエクスペリエンスにします

([15:27](https://developer.apple.com/videos/play/wwdc2021/10123/?time=927)) デフォルトのブロック ページはスクリーン タイムからのものです。管理設定には 2 つの拡張ポイントも用意されています。1 つはシールド ページの外観をカスタマイズするためのもの、もう 1 つはシールド ページのボタン アクションを処理するためのものです。

```swift
import ManagedSettings
import UIKit

final class HomeworkShieldConfigurationProvider: ShieldConfigurationProvider {
    override func configuration(shielding application: Application) -> ShieldConfiguration {
        ShieldConfiguration(
            backgroundBlurStyle: .systemMaterial,
            backgroundColor: .systemBackground,
            icon: UIImage(systemName: "book.closed.fill"),
            title: ShieldConfiguration.Label(text: "Homework first", color: .label),
            subtitle: ShieldConfiguration.Label(text: "Read for 30 minutes to unlock this app.", color: .secondaryLabel),
            primaryButtonLabel: ShieldConfiguration.Label(text: "Ask for Access", color: .white),
            primaryButtonBackgroundColor: .systemBlue,
            secondaryButtonLabel: ShieldConfiguration.Label(text: "OK", color: .systemBlue)
        )
    }
}
```

キーポイント:
- `ShieldConfigurationProvider`外観カスタマイズ拡張機能のメインクラスです。
- `configuration`現在ブロックされているアプリケーションを受信します。
- `ShieldConfiguration`背景効果、背景色、アイコン、タイトル、サブタイトル、ボタンのラベルを返します。
- システムは、宿題によってブロックされたアプリにこの設定を表示します。これについては、トークで 16:37 で説明されています。

([16:50](https://developer.apple.com/videos/play/wwdc2021/10123/?time=1010)) 2 番目の拡張ポイントはボタンを処理します。拡張機能は継承する必要があります`ShieldActionHandler`、書き換えます`handle`、完了ハンドラーを呼び出してシールド アクションの応答を返します。トークに記載されている対応には、ブロックされたアプリを閉じるか、アクションを遅らせてブロック構成を再描画することが含まれます。

```swift
import ManagedSettings

final class HomeworkShieldActionHandler: ShieldActionHandler {
    override func handle(
        action: ShieldAction,
        for application: ApplicationToken,
        completionHandler: @escaping (ShieldActionResponse) -> Void
    ) {
        switch action {
        case .primaryButtonPressed:
            completionHandler(.defer)
        case .secondaryButtonPressed:
            completionHandler(.close)
        @unknown default:
            completionHandler(.close)
        }
    }
}
```

キーポイント:
- `ShieldActionHandler`ボタンアクション拡張のメインクラスです。
- `handle`ユーザーが主ボタンを押したか副ボタンを押したかを内線に伝えます。
- `application`現在ブロックされているアプリトークンを示します。
- `completionHandler`を呼び出す必要があり、スピーチではこの要件が 17 時 14 分に明らかにされています。
- `.defer`保護者のアクションを待機し、ブロック ページにステータスを更新させるために使用できます。
- `.close`ブロックされているアプリを閉じます。

## 重要なポイント

### 1. 子供向けのエンターテイメント モードを変更する方法を学ぶ

- **対処法**: 子供が読書、学習、クリエイティブなアプリを 30 分間使用した後、ゲーム アプリやビデオ アプリのロックが自動的に解除されます。
- **実行する価値がある理由**: デバイス アクティビティ イベントは、推奨されるアプリの使用量のしきい値を監視でき、管理設定は以前のブロックを削除できます。
- **開始方法**: ファミリー アクティビティ ピッカーを使用して、保護者が 2 セットのアプリを選択できるようにします。使用`DeviceActivityEvent`アプリを監視し、奨励します。で`eventDidReachThreshold`ミドルハンドル`store.shield.applications`に設定`nil`。

### 2. 一定時間フォーカスモード

- **対処法**: 毎日、夕食後から就寝前まで、ソーシャル、ゲーム、短いビデオ アプリを自動的にブロックします。
- **価値がある理由**: デバイス アクティビティ スケジュールは、繰り返し時間枠の開始時と終了時に拡張機能を呼び出すことができるため、子供が積極的にアプリを開く必要がありません。
- **開始方法**: 作成する`DeviceActivitySchedule`、設定`repeats: true`;存在する`intervalDidStart`ブロックを設定します。で`intervalDidEnd`シールドをクリアします。

### 3. ホーム Web フィルタリング ツール

- **対処方法**: 子供のデバイスにエンドサイド Web コンテンツ フィルターをインストールし、保護者のルールに従ってアクセス範囲を調整します。
- **実行する価値がある理由**: スピーチでは、ファミリー コントロールが承認されると、アプリ内のネットワーク拡張機能の Web コンテンツ フィルターが自動的にインストールされ、子供が削除することはできないと述べられました。
- **開始方法**: まずファミリー コントロール機能を追加します。保護者の承認を要求します。 Web フィルタリング ロジックを Network Extensions 拡張機能に組み込み、管理設定を使用して関連する制限を管理します。

### 4. コンテンツ アプリの年齢制限保護

- **内容**: ビデオまたはテレビ アプリは、デバイス上の映画とテレビの制限に基づいて、不適切なコンテンツを非表示にします。
- **実行する価値がある理由**: 管理設定は、映画やテレビのコンテンツ制限を読み取るための API を提供します。講演では、この読み取りにはファミリー コントロールの承認が必要ないことが説明されています。
- **開始方法**: メディア アプリが起動するとき、またはコンテンツ リストを更新するときに、システムのメディア制限を読みます。制限の結果を使用してコンテンツ リストをフィルタリングし、許可された年齢を超えるコンテンツが表示されないようにします。

### 5. ブランドのブロック ページ

- **対処方法**: デフォルトのスクリーン タイム ブロック ページを、アプリのブランド、理由の説明、および [アクセスのリクエスト] ボタンを含むページに変更します。
- **価値がある理由**: カスタム シールドを使用すると、背景、アイコン、タイトル、字幕、ボタンを設定し、拡張機能にボタンのアクションを処理させることができます。
- **開始方法**: 実装`ShieldConfigurationProvider`カスタムに戻る`ShieldConfiguration`;成し遂げる`ShieldActionHandler`主ボタンと副ボタンを処理します。主ボタンが戻る`.defer`保護者の確認を待ちます。
