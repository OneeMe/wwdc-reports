## ハイライト

> Safari 15 では、Web 拡張機能に 3 つの重要な改善が加えられています。メモリ使用量を削減する非永続的なバックグラウンド ページ、高パフォーマンスのコンテンツ インターセプトを実現する declarativeNetRequest API、および新しいタブ ページをカスタマイズする機能です。iOS と iPadOS は Web Extensions を初めてサポートします。

## 主な内容

ブラウザ拡張機能の開発者は長年、パフォーマンスの問題に直面してきました。バックグラウンド ページが一度開かれると、ユーザーが拡張機能を数時間使用しなかったとしても、そのページは永久に実行され、メモリと CPU を消費します。

Safari 15 では、非永続的な背景ページを使用してこの問題を解決します。バックグラウンド ページは必要な場合にのみロードされ、イベントの処理後に自動的にアンロードされます。これは iOS デバイスにとって特に重要です。リソースに制約のあるモバイル デバイスでは、複数のバックグラウンド プロセスを常駐させることができません。

### 非永続的な背景ページ

従来の拡張機能のバックグラウンド ページは永続的です。

```json
{
  "background": {
    "scripts": ["background.js"]
  }
}
```

これにより、バックグラウンド プロセスが永久に実行されます。非永続的なものに変更します。

```json
{
  "background": {
    "scripts": ["background.js"],
    "persistent": false
  }
}
```

キーポイント:
- イベント リスナーはスクリプトの最上位に登録する必要があり、コールバック内に登録することはできません。
- 使用`browser.storage`API はグローバル変数の代わりに状態を保存します
- 取り除く`webRequest`リスナー、イベント頻度が高すぎるため、非永続ページと互換性がありません
- 使用`browser.alarms`交換する`setTimeout`/`setInterval`

### ストレージ API を使用して状態を保存する

```javascript
// background.js

// 错误：全局变量会在页面卸载后丢失
let replacementCount = 0;

// 正确：使用 storage API
let replacementCount = 0;

browser.storage.local.get('count').then(result => {
    replacementCount = result.count || 0;
});

browser.runtime.onMessage.addListener((message, sender, sendResponse) => {
    if (message.action === 'replace') {
        replacementCount += message.count;
        browser.storage.local.set({ count: replacementCount });
    } else if (message.action === 'getCount') {
        sendResponse({ count: replacementCount });
    }
});
```

キーポイント:
- `browser.storage.local`これは非同期 API であり、データはディスクに保存されます。
- マニフェストに追加する必要があります`storage`権限
・イベントリスナーは以下に登録されています。`storage.get()`コールバックの外側では、ページの読み込み時にコールバックが登録されていることを確認してください。

### declarativeNetRequest コンテンツのインターセプト

これは Chrome によって導入され、Safari 15 によってサポートされる API です。ルールは JSON 形式で宣言され、ブラウザーは内部でルールを照合します。拡張機能はリクエストの内容を確認するために JavaScript を実行する必要はありません。

manifest.json：

```json
{
  "permissions": ["declarativeNetRequest"],
  "declarative_net_request": {
    "rule_resources": [
      {
        "id": "ruleset_1",
        "enabled": true,
        "path": "rules.json"
      }
    ]
  }
}
```

（[08:37](https://developer.apple.com/videos/play/wwdc2021/10027/?time=517)）

rules.json：

```json
[
  {
    "id": 1,
    "priority": 1,
    "action": {
      "type": "block"
    },
    "condition": {
      "regexFilter": ".*\\.(jpg|png|gif)$",
      "resourceTypes": ["image"]
    }
  },
  {
    "id": 2,
    "priority": 2,
    "action": {
      "type": "allow"
    },
    "condition": {
      "urlFilter": "||wikipedia.org",
      "resourceTypes": ["image"]
    }
  }
]
```

（[09:49](https://developer.apple.com/videos/play/wwdc2021/10027/?time=589)）

キーポイント:
- `priority`ルールを適用する順序を決定し、値が大きいルールを優先します。
- `action.type`できる`block`、`allow`または`upgradeScheme`
- `resourceTypes`含む`main_frame`、`script`、`image`、`stylesheet`待って
- `domainType`ファーストパーティリクエストとサードパーティリクエストを区別する
- 延長は必要ありません`webRequest`権限を設定してコンテンツをブロックし、プライバシーを向上させることができます。

### 新しいタブ ページをカスタマイズする

拡張機能は Safari の新しいタブ ページを引き継ぐことができます。

```json
{
  "chrome_url_overrides": {
    "newtab": "newtab.html"
  }
}
```

newtab.html：

```html
<!DOCTYPE html>
<html>
<head>
    <title>My New Tab</title>
    <meta name="theme-color" content="#ff6b6b">

    <h1>Welcome!</h1>
    <p>Fun fact of the day...</p>
```

ユーザーが拡張機能を開くと、Safari は拡張機能が新しいタブ ページを引き継ぐことを許可するかどうかを尋ねます。この選択は、Safari の設定でいつでも変更できます。

### 非永続的なバックグラウンド ページのデバッグ

Safari の [開発] メニューに新しい [Web 拡張機能の背景ページ] オプションがあり、背景ページの読み込みステータスを表示できるようになります。

```javascript
// 检查后台页面是否已加载
browser.runtime.getBackgroundPage().then(page => {
    if (page) {
        console.log("Background page is active");
    } else {
        console.log("Background page is unloaded");
    }
});
```

キーポイント:
- `getBackgroundPage()`ページがアンロードされている場合は null を返し、ページは自動的に起動されません。
- 背景ページを起動するには、メッセージを送信するだけです
- [開発] メニューの背景ページをクリックすると、すぐにロードされます。

### iOS に関する特別な考慮事項

iOS 拡張機能では、非永続的なバックグラウンド ページを使用する必要があります。マニフェストで省略された場合`persistent`フィールド、デフォルトは`true`、iOS で拡張機能の読み込みに失敗します。

```json
{
  "background": {
    "scripts": ["background.js"],
    "persistent": false
  },
  "permissions": ["storage", "declarativeNetRequest"]
}
```

### ルールセットの動的更新

```javascript
// 启用或禁用特定规则集
browser.declarativeNetRequest.updateEnabledRulesets({
    disableRulesetIds: ['ruleset_1'],
    enableRulesetIds: ['ruleset_2']
});

// 获取当前规则集状态
browser.declarativeNetRequest.getEnabledRulesets().then(ids => {
    console.log("Enabled rulesets:", ids);
});
```

## 重要ポイント

**1. iOS 用の広告/コンテンツ ブロック拡張機能を開発**

declarativeNetRequest API を使用して軽量のインターセプターを構築すると、ルール ファイルをレビューのために App Store に送信せずにリモートで更新できます。入口API:`declarativeNetRequest` + `updateEnabledRulesets()`。

**2.クロスプラットフォームのパスワード マネージャー拡張機能を作成します**

非永続的なバックエンド ページとストレージ API を使用してユーザーの認証情報を保存し、コンテンツ スクリプトを通じて Web フォームに自動的に入力します。入口API:`browser.storage.local` + `content_scripts`。

**3.生産性クラスの新しいタブ ページ拡張機能を開発します**

Safari の新しいタブを引き継いで、ToDo、天気、またはその日の言葉を表示します。使用`theme-color`メタ タグは、タブ バーの色を拡張機能のスタイルと統一します。入口API:`chrome_url_overrides` + `newtab`。

**4.開発者ツール拡張機能の構築**

Web ページにコンテンツ スクリプトを挿入して、要素のレイアウト情報、カラー値、またはパフォーマンス データを表示します。使用`browser.runtime.sendMessage`バックグラウンド ページと通信してデータを集約します。入口API:`content_scripts` + `browser.runtime.onMessage`。

**5. Web ページにダークモードの強制切り替えを実装します**

コンテンツ スクリプトを使用して Web ページの現在のテーマを検出したり、declarativeNetRequest を通じて CSS ファイル リクエストをインターセプトして変更したり、JavaScript を直接使用して色を反転するスタイルを挿入したりできます。入口API:`content_scripts` + `CSS`注射。
