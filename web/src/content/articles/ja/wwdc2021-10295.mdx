## ハイライト

> Apple は、カスタム製品ページと製品ページの最適化を App Store 製品ページに追加しました。開発者は、さまざまなユーザー向けに最大 35 の独立したページを準備し、最大 3 つの処理グループを使用してデフォルトのページ素材のダウンロード変換効果をテストできます。

## 主要内容

通常、アプリは複数のタイプのユーザーにサービスを提供します。登山アプリでは、リアルタイムのライブ放送を見たい人もいれば、GPS の軌跡だけを気にする人もいます。ゲームでは、キャラクターに惹かれる人もいれば、ゲームプレイモードに惹かれる人もいます。以前は、デフォルトの製品ページは 1 つしかなく、アイコン、スクリーンショット、プレビュー ビデオ、プロモーション コピーがすべての作業を同時に行う必要がありました。

その結果、簡単に妥協が生じる可能性があります。ライブ ブロードキャスト ユーザーには GPS スクリーンショットが表示され、チーム ユーザーにはライブ ブロードキャストのセールス ポイントが表示されます。広告の配置では全員を同じページに誘導することしかできず、その後の分析では全体的なコンバージョン率のみを確認できます。

Apple は WWDC21 で 2 つの新機能を提供します。 1 つ目はカスタム製品ページです。各アプリは最大 35 ページを作成でき、それぞれに独自のプレビュー ビデオ、スクリーンショット、プロモーション コピー、ローカライズされたコンテンツ、および一意の URL が含まれます。

2 つ目は商品ページの最適化です。デフォルトの製品ページはテストに使用できます。開発者は、さまざまなアイコンを準備し、ビデオやスクリーンショットをプレビューし、トラフィックの一部を処理グループ (処理) に割り当てます。その後、App Analytics を使用して、ベンチマークと比較したインプレッション、ダウンロード、コンバージョン、改善を表示します。

これら 2 つの機能により、同じ問題が解決されます。製品ページは、発売前の推測だけに依存しなくなりました。まず、さまざまなチャネルに対応するページを準備し、次にデータを使用して、どの素材がダウンロードを促進する可能性が高いかを判断できます。

## 詳細

### カスタマイズされた製品ページ: さまざまなユーザーに異なる入り口を提供します

([01:02](https://developer.apple.com/videos/play/wwdc2021/10295/?time=62)) カスタム製品ページでは、アプリにさまざまな機能やコンテンツを表示できます。各ページには、異なるアプリのプレビュー ビデオ、スクリーンショット、プロモーション テキストを含めることができます。各ページはローカリゼーションをサポートしており、独自の一意の URL を持ちます。

これは App Store の製品ページで行われ、その目的は、ユーザーがダウンロードする前に、より関連性の高いコンテンツを表示することです。

```yaml
customProductPage:
  goal: "highlight-live-streaming"
  audience: "people following climbers in real time"
  assets:
    appPreviewVideos:
      - "live-streaming-preview.mov"
    screenshots:
      - "summit-live-feed-1.png"
      - "climber-broadcast-2.png"
    promotionalText: "Watch climbers reach the summit live."
  localization:
    - "en-US"
    - "ja-JP"
  sharing:
    url: "unique App Store URL for this page"
```

キーポイント:

- `goal`このページの目的を明確に書きます。 Session では、まず目標を計画してからページを作成することをお勧めします。
- `audience`このページが対象としている人々に対応します。この例は、講演中の Mountain Climber アプリから引用したものです。
- `appPreviewVideos`、`screenshots`、`promotionalText`カスタム商品ページ用に個別に設定できる素材です。
- `localization`これは、すべてのページを完全にローカライズできることを意味します。
- `sharing.url`ページが承認された後、一意の URL を通じて共有できることを示します。

([01:27](https://developer.apple.com/videos/play/wwdc2021/10295/?time=87)) App Analytics は、カスタム製品ページごとに独立した指標を提供します。講演で挙げられた指標には、インプレッション数、ダウンロード数、コンバージョン率、維持データ、有料ユーザーあたりの平均収益などが含まれる。

```yaml
customProductPageMetrics:
  impressions: "tracked in App Analytics"
  downloads: "tracked in App Analytics"
  conversionRate: "tracked in App Analytics"
  retentionData: "tracked after download"
  averageProceedsPerPayingUser: "tracked after download"
```

キーポイント:

- `impressions`このページが何回閲覧されたかを示します。
- `downloads`このページからダウンロードを記録します。
- `conversionRate`訪問をダウンロードに変換するページの能力を判断するために使用されます。
- `retentionData`ダウンロードを超えて分析を拡張します。
- `averageProceedsPerPayingUser`特定の種類のページから誘導された有料ユーザーの価値を判断するのに役立ちます。

([02:53](https://developer.apple.com/videos/play/wwdc2021/10295/?time=173)) カスタム製品ページを準備するには 3 つの手順があります。まず目標を決定し、次に強調表示する機能またはコンテンツを選択し、最後にメタデータを準備します。関数の起動後、新しいアプリ バージョンを送信しなくても、これらのメタデータを App Store Connect で送信できます。

```yaml
customProductPagePreparation:
  - planGoals
  - chooseFeaturesOrContent
  - prepareMetadata:
      appPreviewVideos: true
      screenshots: true
      promotionalText: true
  - submitInAppStoreConnect
  - shareAfterApproval
```

キーポイント:

- `planGoals`スピーチの「明確な目的を持つ」に相当します。
- `chooseFeaturesOrContent`同じタイプのユーザー向けにページを繰り返し作成することを避けるために使用されます。
- `prepareMetadata`スピーチで明示的に言及された 3 つのカテゴリの資料が含まれています。
- `submitInAppStoreConnect`ページが App Store Connect を通じて送信されたことを示します。
- `shareAfterApproval`これは、ページが審査され承認された後にのみ固有の URL が共有されることを意味します。

### 製品ページの最適化: テストを使用してデフォルトのページ素材を決定します

([03:59](https://developer.apple.com/videos/play/wwdc2021/10295/?time=239)) 製品ページの最適化は、デフォルトの製品ページをテストするために使用されます。開発者は、さまざまな処理グループを設定し、アイコン、プレビュービデオ、またはスクリーンショットを比較して、どのバージョンがダウンロードを促進する可能性が高いかを確認できます。

プレゼンテーションで示された例は、青いアイコンと赤いアイコンでした。システムは、デフォルトの製品ページに入るトラフィックを元のページと処理グループに分割し、ダウンロード コンバージョンを測定します。

```yaml
productPageOptimizationTest:
  baseline:
    appIcon: "blue-icon"
  treatments:
    - name: "red-icon-treatment"
      appIcon: "red-icon"
  measurement:
    primaryMetric: "download conversion"
  possibleAction:
    applyTreatmentMetadataToDefaultProductPage: true
```

キーポイント:

- `baseline`現在のデフォルトの製品ページです。
- `treatments`これはベータ版です。各テストには最大 3 つの治療グループを含めることができます。
- `primaryMetric`音声から変換をダウンロードします。
- `possibleAction`より良い検査結果を示す場合、治療グループのメタデータをデフォルトの製品ページに適用できます。

([04:35](https://developer.apple.com/videos/play/wwdc2021/10295/?time=275)) 処理グループは、さまざまなアプリのアイコン、さまざまなアプリのプレビュー ビデオ、またはさまざまなスクリーンショットをテストできます。テストごとに最大 3 つの治療グループ。テスト トラフィックに入力するユーザーの数を選択できます。

30% のトラフィックを選択し、3 つの処理グループを設定した場合、各処理グループは合計トラフィックの 10% を取得します。

```yaml
trafficAllocation:
  audiencePercentageInTest: 30
  numberOfTreatments: 3
  trafficPerTreatment: 10
  baselineTraffic: 70
```

キーポイント:

- `audiencePercentageInTest`テストに入る合計トラフィックの割合です。
- `numberOfTreatments`3 を超えることはできません。
- `trafficPerTreatment`講義例ごとに、30% を 3 で割った値になります。
- `baselineTraffic`これは、処理グループに入っていないトラフィックであり、引き続きデフォルト ページが表示されます。

([05:04](https://developer.apple.com/videos/play/wwdc2021/10295/?time=304)) アイコンのテストには特別な要件があります。テスト アイコンを表示してアプリをダウンロードしたユーザーには、自分のデバイスにも同じアイコンが表示されます。これを行うには、バリアント アイコン リソースが、該当するデバイスのすべてのサイズと App Store で使用される 1024x1024 バージョンを含む、アプリの現在のオンライン バージョンのバイナリに含まれている必要があります。

```yaml
iconTreatmentRequirements:
  binary: "currently live app version"
  includedAssets:
    deviceIconSizes: "all applicable devices"
    appStoreIcon: "1024x1024"
  userExperience:
    productPageIconMatchesInstalledAppIcon: true
```

キーポイント:

- `binary`現在のオンライン バージョンを指します。講演では、テストするアプリのバージョンのバイナリにバリアント アイコンを組み込むことが強調されました。
- `deviceIconSizes`適用機器の必要寸法をカバーします。
- `appStoreIcon`App Store で必要な 1024x1024 のアイコンです。
- `productPageIconMatchesInstalledAppIcon`製品ページからホーム画面まで同じアイコンがユーザーに表示されるようにします。

([05:42](https://developer.apple.com/videos/play/wwdc2021/10295/?time=342)) テストは、特定のローカライズされたバージョンに制限できます。製品ページが英語、日本語、韓国語をサポートしていると仮定すると、テストは日本語ページでのみ実行できます。英語または韓国語でページを閲覧したユーザーは、このテストに参加できません。

```yaml
localizedTest:
  availableLocalizations:
    - "English"
    - "Japanese"
    - "Korean"
  testLocalizations:
    - "Japanese"
  excludedFromTest:
    - "English"
    - "Korean"
```

キーポイント:

- `availableLocalizations`これは製品ページの現在のローカライズです。
- `testLocalizations`テストが実際に実行される言語です。
- `excludedFromTest`これらのロケールのユーザーがテストに参加しないことを示します。
- この機能は、特定の市場にのみ関連する重要な変更に適しています。

([06:12](https://developer.apple.com/videos/play/wwdc2021/10295/?time=372)) テストの実行中、App Analytics には、ベースラインと比較した各治療グループのインプレッション、ダウンロード、コンバージョン、改善 (改善) が表示されます。結果を表示した後、処理グループをデフォルトの製品ページに適用できます。

別のアプリ アイコンを適用する場合は、次のアプリ バージョンのバイナリ ファイル内のデフォルト アイコンを更新する必要があります。

```yaml
optimizationResults:
  metrics:
    - impressions
    - downloads
    - conversion
    - improvementAgainstBaseline
  applyWinner:
    metadata: "apply to default product page"
    differentAppIcon: "update default icon in next app binary"
```

キーポイント:

- `impressions`、`downloads`、`conversion`はテスト中に監視できる指標です。
- `improvementAgainstBaseline`デフォルトページと比較して処理グループのパフォーマンスを判断するために使用されます。
- `metadata`共通マテリアルをデフォルトの商品ページに適用できることを示します。
- `differentAppIcon`はアイコンの変更に関する制限です。デフォルトのアイコンは、次のアプリのバージョンで更新する必要があります。

### App Store Connect API のサポート

([07:50](https://developer.apple.com/videos/play/wwdc2021/10295/?time=470)) 講演の最後に、カスタム製品ページと製品ページの最適化の両方が App Store Connect API をサポートすると述べられました。完全な API 仕様は、その年後半にリリースされる予定です。

このセッションは、エンドポイント、リクエスト本文、または SDK 呼び出しを提供しません。決定できる唯一の事実は、2 つの機能が API でカバーされ、開発者は関連プロセスを自動化システムに組み込むことができるということです。

```yaml
appStoreConnectApiSupport:
  customProductPages: true
  productPageOptimization: true
  apiSpec: "published later this year"
```

キーポイント:

- `customProductPages`カスタム製品ページが API をサポートすることを示します。
- `productPageOptimization`商品ページの最適化が API をサポートすることを示します。
- `apiSpec`未公開のインターフェイスの作成を避けるために、プレゼンテーション内のタイミング情報を保持します。

## 重要ポイント

1. **やるべきこと**: 広告チャネル専用の製品ページを作成します。
**価値がある理由**: カスタム商品ページには、異なる広告クリエイティブを異なるページに移動できる固有の URL があります。
**開始方法**: 3 つの主要なチャネルをリストアップして、それぞれに 1 つずつ書きます。`goal`を作成し、対応するプレビュー ビデオ、スクリーンショット、プロモーション コピーを準備します。

2. **やるべきこと**: アプリのコア機能ごとにランディング ページを作成します。
**価値がある理由**: アプリごとに最大 35 のカスタム製品ページがあり、さまざまな機能やコンテンツを強調するのに最適です。
**開始方法**: ダウンロードする前にユーザーが最も懸念する機能のリストを作成し、最初の 5 つの機能のスクリーンショット グループと宣伝文を準備します。

3. **やるべきこと**: 製品ページの最適化を使用してアイコンの色またはスタイルをテストします。
**実行する価値がある理由**: 製品ページの最適化では、デフォルト ページのアプリ アイコンで処理グループ テストを実行し、ダウンロード変換を使用して結果を判断できます。
**開始方法**: 現在のオンライン バージョンのバイナリにバリアント アイコンを配置し、デバイス サイズと 1024x1024 の App Store アイコンを完成させて、App Store Connect でテストをセットアップします。

4. **やるべきこと**: 新しいスクリーンショットは、単一のローカライズされた市場でのみテストしてください。
**実施する価値がある理由**: テストは、結果に影響を与える無関係な市場を避けるために、特定のローカライズされたページに限定できます。
**開始方法**: 明確な成長目標を持つ言語バージョンを選択し、この言語のスクリーンショットとプレビュー ビデオを準備し、このローカリゼーションのみをテストに追加します。

5. **やるべきこと**: 製品ページの指標を毎週の成長レビューに統合します。
**価値がある理由**: App Analytics は、カスタム製品ページと処理グループごとに、インプレッション、ダウンロード、コンバージョン、維持、支払いユーザーの収益を提供します。
**開始方法**: 各ページの目標、マテリアルのバージョン、公開日を記録し、毎週 App Analytics の指標と比較して、ページを保持するか、調整するか、オフラインにするかを決定します。
