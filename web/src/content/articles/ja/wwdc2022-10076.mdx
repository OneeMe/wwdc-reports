## ハイライト

> iOS アプリを Mac に導入するには 2 つの方法があり、どちらも今年新しく追加されました。

## 主要内容

多くの iOS アプリがすでに M1 Mac App Store で入手可能です。アクティブに終了しない限り、ユーザーは検索時に「iPhone および iPad アプリ」ラベルの下にそれらのアプリを表示します ([03:09](https://developer.apple.com/videos/play/wwdc2022/10076/?time=189))。

このパスは最もコストがかかりません。問題も単純明快です。タッチ入力、画面サイズ、全画面起動が必ずしも実際の Mac アプリと似ているわけではありません。

Apple はこのセッションでパスを 2 つに分割します。

1 つ目は、iOS アプリを M1 Mac 上でネイティブに実行し続けることです。開発者は 2 つを追加できます`Info.plist`キーを使用すると、ゲームやマルチメディア アプリが実際の画面サイズを使用し、起動時に直接全画面に移行できるようになります ([03:29](https://developer.apple.com/videos/play/wwdc2022/10076/?time=209))。また、タッチ代替機能を使用して、キーボード、マウス、トラックパッドの入力を iOS アプリが期待するマルチタッチ ジェスチャに変換することもできます ([04:52](https://developer.apple.com/videos/play/wwdc2022/10076/?time=292))。

2 番目のステップは、Mac Catalyst の宛先をプロジェクトに追加することです。これにより、アプリがすべての Mac で実行され、Mac Catalyst API を使用してより詳細なカスタマイズが可能になります ([07:35](https://developer.apple.com/videos/play/wwdc2022/10076/?time=455))。[Mac 向けに最適化] を選択すると、UIKit コントロールは AppKit スタイルになり、テキストはネイティブ Mac フォントを使用してレンダリングされます ([07:52](https://developer.apple.com/videos/play/wwdc2022/10076/?time=472))。

これは一度行ったら終わりという仕事ではありません。これははしごに似ています。まずアプリを Mac 上に表示させ、次に入力と表示を追加し、次に Catalyst を使用してツールバー、ウィンドウ、メニュー、ポップアップ レイヤーのデスクトップ機能を引き継ぎます。

## 詳細

### 1. ネイティブ iOS アプリ: 2 つのスタートアップ キー

([03:29](https://developer.apple.com/videos/play/wwdc2022/10076/?time=209)) Apple は、`Info.plist`鍵。これらは SDK バージョンに拘束されず、macOS 12.1 より前の iOS および Mac では無視されるため、既存のアプリに安全に追加できます。

```xml
<!-- Info.plist -->
<key>UISupportsTrueScreenSizeOnMac</key>
<true/>
<key>UILaunchToFullScreenByDefaultOnMac</key>
<true/>
```

キーポイント:

- `UISupportsTrueScreenSizeOnMac`アプリが Mac 上のさまざまなディスプレイ サイズとピクセル密度を処理する準備ができていることを示します。
- 有効にすると、アプリは互換性のある iPad サイズではなく、実際の画面サイズと実際のピクセル密度を取得します。
- `UILaunchToFullScreenByDefaultOnMac`アプリが起動直後に全画面表示になりたいことを示します。
- 両方のキーは一緒に使用するのに適しています。このビデオでは、ゲームやマルチメディア アプリがピクセル完璧な、端から端までのフルスクリーン エクスペリエンスを実現できると明確に述べています。

このタイプの変更では、UI アーキテクチャを変更する必要はありません。「画像が互換ウィンドウに入れられてしまう」という問題を解決します。

### 2. Touch Alternatives: plist を使用して入力変換を記述します。

([04:52](https://developer.apple.com/videos/play/wwdc2022/10076/?time=292)) iOS ゲームは多くの場合、タッチとデバイスのモーションのみを処理します。Mac ユーザーにはキーボード、マウス、トラックパッドが付属します。

Touch Alternatives は、これらの Mac 入力を、iOS アプリが期待するマルチタッチ ジェスチャとデバイスの動きに自動的に変換します。

自動タッチ代替機能をオンにするには、次の名前のファイルを作成します。`com.apple.uikit.inputalternatives.plist`ファイル ([05:35](https://developer.apple.com/videos/play/wwdc2022/10076/?time=335))。

```xml
<!-- com.apple.uikit.inputalternatives.plist -->
<key>defaultEnablement</key>
<string>enabled</string>
<key>requiredOnboarding</key>
<array>
  <string>tap</string>
  <string>tilt</string>
  <string>drag</string>
  <string>swipe</string>
</array>
```

キーポイント:

- `defaultEnablement`に設定`enabled`、アプリの起動時にすぐに Touch Alternatives が開かれることを示します。
- `requiredOnboarding`最初の起動チュートリアルで注目するコントロールをリストする配列です。
- ビデオには、タップ、傾け、ドラッグ、スワイプ、トラックパッドからの直接タッチ入力など、表示可能なコントロールがリストされています。
- Touch Alternatives を有効にすると、すべての制御方法が有効になります。`requiredOnboarding`チュートリアルで何に重点を置くかを決めてください。

([07:02](https://developer.apple.com/videos/play/wwdc2022/10076/?time=422)) Apple はまた、キーボードとカーソルのサポートを直接実装する方が良いと強調しています。こうすることで、アプリはキーボードを備えた iPad と Mac の両方で同じように動作します。Touch Alternatives は、Mac 上の既存のタッチ アプリのブリッジング レイヤーとして適しています。

### 3. Mac 向けに最適化: UIKit 構造を Mac 表現に変換します。

([07:35](https://developer.apple.com/videos/play/wwdc2022/10076/?time=455)) Xcode で Mac Catalyst 宛先を追加すると、アプリはすべての Mac で実行できる完全な Mac Catalyst アプリになります。

Mac 向けに最適化を有効にすると、システムはいくつかのことを実行します ([08:18](https://developer.apple.com/videos/play/wwdc2022/10076/?time=498)):

```text
UINavigationBar        -> NSToolbar
center item controls   -> NSToolbarItems
UISearchTextField      -> hosted inside an NSToolbarItem

```

キーポイント:

- `UINavigationBar`に翻訳されます`NSToolbar`、ネイティブ AppKit コントロールを使用します。
- 中央エリアのコントロールは次のようになります。`NSToolbarItem`。
- 検索バーは、最初はツールバーに検索ボタンとして表示され、クリックすると検索バーに展開されます。
- 検索候補メニューと検索スコープ バーもネイティブ AppKit コントロールに変換されます。
- Mac イディオムのテキストは、ビデオでピクセルパーフェクト スケールと呼ばれる Mac ネイティブ フォントを使用してレンダリングされます。

([09:49](https://developer.apple.com/videos/play/wwdc2022/10076/?time=589)) Catalyst アプリが独自のツールバーを作成しない場合は、システムが自動的にツールバーを提供します。すでに自分で管理している場合`NSToolbar`、システムはそれを回避し、実装をカバーしません。

### 4. ファイル メニュー: レスポンダー チェーンを使用してファイル メニューをキャッチします

([10:42](https://developer.apple.com/videos/play/wwdc2022/10076/?time=642)) デスクトップレベルの iPad API を採用した後、ドキュメント アプリは新しいファイル メニュー項目 (複製、移動、名前変更、名前を付けてエクスポート) を自動的に取得します。

これらのメニュー項目を有効にする条件は、レスポンダー チェーンにオブジェクト カバレッジがあることです。`UIResponder`の複製、移動、名前変更、エクスポート機能（[10:53](https://developer.apple.com/videos/play/wwdc2022/10076/?time=653)）。

アプリがこれらのドキュメント メニュー項目を必要としない場合は、アプリ デリゲートのメニュー項目に追加できます。`buildMenu`内部で使用`UIMenuBuilder`取り除く。これらのドキュメント メニュー項目を説明するビデオ`UIMenuIdentifier`値は`.document`（[11:07](https://developer.apple.com/videos/play/wwdc2022/10076/?time=667)）。

```swift
func buildMenu(with builder: UIMenuBuilder) {
    builder.remove(menu: .document)
}
```

キーポイント:

- `buildMenu(with:)`メニューの場所を制御するアプリのデリゲートです。
- `UIMenuBuilder`システムメニューの追加、削除、変更を担当します。
- `.document`このドキュメント関連のメニュー項目のセットを指します。
- アプリが対応するドキュメント操作を提供していない場合は、無効なエントリを残すよりもメニューを削除する方が Mac の習慣と一致します。

### 5. ウィンドウのジオメトリ: 補助ウィンドウのサイズと動作を設定します。

([13:56](https://developer.apple.com/videos/play/wwdc2022/10076/?time=836)) Catalyst アプリが使用されました`UIWindowScene`マルチウィンドウをサポートします。macOS Ventura には、ウィンドウ フレーム、ウィンドウ コントロール ボタン、全画面動作用のカスタム API がさらに追加されています。

ビデオの例では、Markdown アプリが Markdown ヒント補助ウィンドウを開きます。ウィンドウが小さくなり、最小化ボタンとズーム ボタンが無効になります ([14:22](https://developer.apple.com/videos/play/wwdc2022/10076/?time=862))。

以下は、呼び出しシーケンスを説明するためにトランスクリプト内の API 名ごとに整理された概念コードです。

```swift
func scene(
    _ scene: UIScene,
    willConnectTo session: UISceneSession,
    options connectionOptions: UIScene.ConnectionOptions
) {
    guard let windowScene = scene as? UIWindowScene else { return }

    var frame = windowScene.effectiveGeometry.systemFrame
    frame.size = CGSize(width: 480, height: 360)

    let preferences = UIWindowScene.GeometryPreferences.Mac(systemFrame: frame)
    windowScene.requestGeometryUpdate(preferences) { error in
        // The system can reject the request and report details here.
    }

    windowScene.windowingBehaviors.miniaturizable = false
    windowScene.sizeRestrictions?.allowsFullScreen = false
}
```

キーポイント:

- `effectiveGeometry`現在のフレームを提供します。動画の提案は常にそこから始まります。
- シーンが作成される前に、現在のフレームは次のように初期化されます。`CGRectNull`、システムは最初に作成されたときにこれらの値を無視することを認識しています。
- 改訂`systemFrame`その後、パスします`requestGeometryUpdate()`リクエストを送信します。
- これはコマンドではなくリクエストです。システムはそれを拒否し、エラー ハンドラーを介して詳細を返すことができます。
- `windowingBehaviors.miniaturizable`黄色の最小化ボタンを制御します。
- `sizeRestrictions.allowsFullScreen`緑色のボタンを全画面表示にする機能を制御します。

([16:53](https://developer.apple.com/videos/play/wwdc2022/10076/?time=1013)) ウィンドウ ジオメトリにも 2 つのスケーリング ルールがあります。`systemFrame`Mac デスクトップ座標を使用すると、1 ポイントは常に 1 AppKit ポイントになります。アプリが iPad に合わせて拡大縮小モードの場合、アプリと UI 要素の間には 77% の拡大縮小の差があります。座標原点はメインディスプレイの左上隅です。

### 6. ツールバーの UIView とポップアップ レイヤー

([18:46](https://developer.apple.com/videos/play/wwdc2022/10076/?time=1126)) このセッションの最後の API セットは、Mac ツールバーを調整するために使用されます。

Mac Catalyst の新機能:`UIView`アイテムとして入れられる`NSToolbar`。新しいデスクトップレベルの iPad API を使用する場合、`UIBarButtonItem`の`customView`これは自動的にラップされ、ツールバーに追加されます ([19:04](https://developer.apple.com/videos/play/wwdc2022/10076/?time=1144))。

自分で管理するなら`NSToolbar`、新しいものを使用できます`NSUIViewToolbarItem`。それはです`NSToolbarItem`のサブクラス。`UIView`（[19:37](https://developer.apple.com/videos/play/wwdc2022/10076/?time=1177)）。

```swift
func toolbar(
    _ toolbar: NSToolbar,
    itemForItemIdentifier itemIdentifier: NSToolbarItem.Identifier,

    return NSUIViewToolbarItem(itemIdentifier: itemIdentifier, view: wordCountView)

```

キーポイント:

([20:43](https://developer.apple.com/videos/play/wwdc2022/10076/?time=1243)) このアイテムは、ポップオーバーのアンカー ポイントとしても使用できます。ビデオ内の Markdown アプリの文字数項目をクリックすると、段落数、章数、読書時間などの詳細がポップアップ表示されます。

キーポイント:

- `sourceItem`現在のツールバー項目に設定すると、ポップアップ レイヤーがツールバー ボタンに固定されます。
- このタイプのモードは、Mac ツールバーの概要情報や二次的な操作に適しています。

### 7. UINavigationBar を翻訳するかどうかを選択します

```swift
navigationController.navigationBar.preferredBehavioralStyle = .pad
```

キーポイント:

- デフォルト値は次のとおりです。`automatic`。

- このスイッチは、カスタム ツールバー ソリューションをすでに備えている Catalyst アプリに適しています。

## 重要ポイント

- **iOS ゲームの真のフルスクリーン Mac バージョンを作成します**: を使用します。`UISupportsTrueScreenSizeOnMac`そして`UILaunchToFullScreenByDefaultOnMac`ディスプレイを操作し、タッチ代替機能を使用してキーボードとマウスの入力を受け取ります。既存のタッチ ゲームをまず Mac でプレイできるようにするのに最適です。

- **iPad ツールバーを Mac ツールバーにアップグレード**: デスクトップレベルの iPad API を使用して、`UINavigationBar`、中央の項目と検索バーは自動的にマッピングされます。`NSToolbar`。すでにツールバーを自分で管理している場合は、次を使用します。`.pad`自動翻訳をオフにします。

- **補助情報用に別の小さなウィンドウを作成**: を使用します。`UIWindowScene`ジオメトリ リクエストは、次のようにして初期寸法を設定します。`windowingBehaviors`そして`sizeRestrictions`不適切なウィンドウボタンを無効にします。Markdown ヘルプ、インスペクター、パレットなどの補助パネルに適しています。

- **ステータス ビューをツールバーに配置**: 使用します`customView`自動的にツールバーに入るか、次のコマンドを使用します。`NSUIViewToolbarItem`パック`UIView`。クリック後、ポップオーバーを使用して、単語数、読書時間、同期ステータスなどの詳細なコンテンツを表示します。
