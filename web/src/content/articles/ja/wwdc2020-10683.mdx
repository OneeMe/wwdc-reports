## ハイライト

> 第 3 章では、プレイヤーはスワン リールのリズムを次のように変換する必要があります。`Pitch`、`NoteProtocol`そして一定間隔`Timer`、次に使用します`ToneOutput`さまざまな長さの音符を演奏します。

## 主要内容

第 2 章では、1 つの音符の長さ、固定間隔のみを扱います。`Timer`チャレンジを完了するには十分です。第 3 章でトカゲの小屋に戻った後、スワンの新しい巻物では、プレイヤーはリズムの違いでメロディーを演奏する必要があります。四分音符、二分音符、付点二分音符はすべて可能です。元のループは同じビートに従って進むだけで、長い音に遭遇すると表現力を失います。

Apple はまず問題を 2 つのモデルに分類します。`Pitch`伝える責任がある`ToneOutput`どの周波数を再生するか、`NoteProtocol`音のトーンと長さを説明する役割を果たします。長さは 4 分音符の倍数で表現されるため、2 分音符が返されます。`2.0`、8分音符が戻ります`0.5`。

難点はタイマーです。逐語草案は明らかに次のことを思い出させます。`ToneOutput`やめるよう求められるまで声を出し続けます。このセッションのメソッドは、`Timer`サポートされている最も短いノート間隔に固定され、長いノートは複数のピッチ コマンドに分割されます。このようにして、ループはシンプルなままですが、さまざまな長さの音符を表現できます。

## 詳細

### ピッチを使用して周波数を説明します

（[01:50](https://developer.apple.com/videos/play/wwdc2020/10683/?time=110)）`Music.swift`プレイヤーが実装するために予約されているプロトコルがあります。最初のステップは、リールの各ピッチを周波数にマッピングすることです。`ToneOutput`使用。

```
// Example Pitch implementation

public enum Pitch: Double, PitchProtocol {
    case a4 = 440.0

    var frequency: Double {
        return self.rawValue
    }
}
```

キーポイント:

- `Pitch`従う`PitchProtocol`、使用`Double`生の値は周波数を保持します。
- `.a4`440.0 に対応する逐語的スクリプトでは、プレーヤーはスワン リールの各ピッチにケースを追加する必要があります。
- `frequency`生の値を直接返します。次のようになります。`Tone`この周波数が読み取られます。

### NoteProtocol を使用して音符の長さを記述する

([02:08](https://developer.apple.com/videos/play/wwdc2020/10683/?time=128)) ピッチが解決された後、音符がどのくらい続くかを表現する必要もあります。公式クリップはノートを 2 つの属性に分割します: 再生用`tone`、四分音符を基準に`length`。

```
// Music.swift

public protocol NoteProtocol {

    /// Play this Note through a ToneOutput
    var tone: Tone { get }

    /// The duration of this Note as a multiple of quarter notes,
    /// e.g., a half note is 2.0, an eighth note is 0.5
    var length: Float { get }
}
```

キーポイント:

- `tone`贈り物です`ToneOutput`音のオブジェ。
- `length`四分音符をベースにすると二分音符は`2.0`、8分音符は`0.5`。
- このプロトコルにより、同じメロディー配列でピッチとリズムの両方の情報を運ぶことができます。

公式の音符の実装では、まず最小の形式である 4 分音符のケースをカバーし、ピッチを次のように変換します。`Tone`、固定長に戻ります。

```
// Example Note implementation

public enum Note: NoteProtocol {
    case quarter(pitch: Pitch)

    var tone: Tone {
        switch self {
        case .quarter(let pitch):
            return Tone(pitch: pitch.frequency, volume: 0.3)
        }
    }

    var length: Float {
        switch self {
        case .quarter(_):
            return 1.0
        }
    }
}
```

キーポイント:

- `quarter(pitch:)`ピッチを 4 分音符にラップします。
- `tone`ピッチを使用する`frequency`作成する`Tone`、ボリュームは次のように設定されています。`0.3`。
- `length`四分音符の返品`1.0`、プレーヤーはリール内の他の長さのケースを追加し続ける必要があります。

### 固定タイマー間隔

([03:18](https://developer.apple.com/videos/play/wwdc2020/10683/?time=198)) オリジナル`Timer`音符の長さは自動的には認識されません。解決策は、まずサポートされている最短の音符の長さをプロトコルに伝え、次にこの値を使用してタイマー間隔を計算することです。スピーカーは例として 120 BPM を使用し、4 分音符の長さは 500 ミリ秒です。

```
// Music.swift

public protocol NoteProtocol {

    /// Play this Note through a ToneOutput
    var tone: Tone { get }

    /// The duration of this Note as a multiple of quarter notes,
    /// e.g., a half note is 2.0, an eighth note is 0.5
    var length: Float { get }

    /// Length of the smallest Note supported
    static var shortestSupportedNoteLength: Float { get }
}
```

キーポイント:

- `shortestSupportedNoteLength`タイプレベルの属性であり、すべてのノートが同じ最短単位を共有します。
- 逐語原稿の白鳥スクロールは最短単位として 4 分音符を使用しているため、例では 4 分音符を選択しています。
- `Timer`以降、この最短ユニットの押下がトリガーとなり、ピッチコマンドを繰り返すことで長い音を表現します。

### 長い音符をピッチコマンドに分割する

([04:15](https://developer.apple.com/videos/play/wwdc2020/10683/?time=255)) 長い音符は一連のピッチに分割する必要があります。 4 分音符は 1 つのコマンドを与え、2 分音符は 2 つのコマンドを与え、付点 2 分音符は 3 つのコマンドを与えます。このステップの正式名称は`subdivide()`。

```swift
// Music.swift

public protocol NoteProtocol {
    associatedtype PitchType: PitchProtocol

    /// Play this Note through a ToneOutput
    var tone: Tone { get }

    /// The duration of this Note as a multiple of quarter notes,
    /// e.g., a half note is 2.0, an eighth note is 0.5
    var length: Float { get }

    /// Length of the smallest Note supported
    static var shortestSupportedNoteLength: Float { get }

    /// Subdivide into a series pitches, according to the shortest
    /// supported note
    func subdivide() -> [PitchType]
}
```

キーポイント:

- `associatedtype PitchType`ノートプロトコルを特定のピッチタイプに接続します。
- `subdivide()`ピッチの配列を返します。その長さは、音符の長さとサポートされている最短の長さによって決まります。
- タイマー ループはノートを直接消費しなくなり、拡張されたピッチを消費します。

### 再生ループを完了する

([04:30](https://developer.apple.com/videos/play/wwdc2020/10683/?time=270)) 最後のステップは、すべてのノートを次のように展開することです。`pitches`、その後、一定の間隔を置きます`Timer`一つずつプレイしてください。

```
// Play more than one tone redux

let toneOutput = ToneOutput()
let notes = [Note.quarter(pitch: .a4), .half(pitch: .a4), .quarter(pitch: .a4)]
var pitches = [Pitch]()
for note in notes {
    pitches.append(contentsOf: note.subdivide())
}
var index = 0

let interval = TimeInterval(Note.shortestSupportedNoteLength * 0.5)
Timer.scheduledTimer(withTimeInterval: interval, repeats: true) { timer in
    guard index < pitches.count else {
        timer.invalidate()
        owner.endPerformance()
        return
    }
    toneOutput.play(tone: Tone(pitch: pitches[index].frequency, volume: 0.3))
    index += 1
}
```

キーポイント:

- `notes`元のスコア構造を維持し、`pitches`再生前の展開結果です。
- `for note in notes`それぞれの音符を入れる`subdivide()`結果は同じ配列に追加されます。
- `interval`使用`shortestSupportedNoteLength * 0.5`、そのままのドラフトの 120 BPM の例に対応します。
- `guard index < pitches.count`終了時間に達したらタイマーを停止し、パフォーマンスを終了します。
- `toneOutput.play`現在の音程を押すたびに`frequency`サウンド、サイクルバイ`index += 1`どうぞ。

## 重要ポイント

- **やるべきこと**: リズム練習の遊び場を作ります。 **実行する価値がある理由**: このセッションでは、4 分音符、2 分音符、付点 2 分音符の長さの関係を明確に説明しました。 **開始方法**: を使用します`PitchProtocol`そして`NoteProtocol`少数のピッチと長さを定義し、次を使用します。`ToneOutput`ユーザーがアレンジしたノートを演奏します。
- **やるべきこと**: 楽譜チェッカーを作成します。 **やる価値がある理由**: スワンのチャレンジでは、プレイヤーはリール上の「歓喜の歌」を再生可能なコードに変換する必要があります。 **開始方法**: まずユーザーが入力した音符配列を渡します`subdivide()`展開して、展開されたピッチ番号が予想されるビートと一致するかどうかを確認します。
- **やるべきこと**: メロディーにベースパートを追加します。 **実行する価値がある理由**: このサイド クエストでは、複数のタイマーを使用してトーンを積み重ね、メイン メロディーの下にベース コードを置くことができることを明確に思い出させます。 **開始方法**: メインメロディーのタイマーを維持し、ベースノート用に 2 番目のセットを準備します。`pitches`2 番目のタイマーは同じテンポベースを使用します。
- **内容**: 再生デバッグ出力を作成します。 **実行する価値がある理由**: 使用できる公式の完全なクリップ`index`ひとつずつ進めて`pitches`、現在の再生位置を公開するのに最適です。 **開始方法**: 再生ループの隣に現在のインデックス、ピッチ周波数、残りのピッチ数を記録します。これにより、学習者は細分化後の実際の再生シーケンスを見ることができます。
