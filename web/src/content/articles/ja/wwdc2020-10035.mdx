## ハイライト

> このコードは、小さなウィジェットを最初のエピソードから systemMedium まで拡張し、処理が完了する前に `TimelineReloadPolicy` を使用して複数のタイムライン エントリを生成し、SiriKit カスタム インテント、`widgetURL` および SwiftUI `Link` を介したユーザー構成とディープ リンクをサポートします。

## 主な内容

最初のエピソードではすでに絵文字レンジャーのパワーパンダがホーム画面に表示されていますが、これはまだ単なるシステムの小さなウィジェットです。ユーザーがウィジェット ギャラリーを開いたとき、ウィジェットが複数のサイズをサポートしている場合、システムはユーザーに異なるファミリを選択するように求めます。問題は、小さいバージョンでは 1 つのアバターを入れるのに十分な大きさしかなく、中バージョンの余分なスペースにはより多くのキャラクター情報が含まれる必要があることです。

このコードアロングはまずファミリーの適応を完了し、次に実際のタイムラインに入ります。キャラクターは時間の経過とともに健康状態を回復し、アプリはキャラクターがいつ完全に回復するかをすでに認識しています。ウィジェットが更新を要求できるようにし続けると、システムのスケジュール設定の機会が無駄になります。より良いアプローチは、復元が完了するまでプロバイダーでタイムライン エントリを 1 回生成し、WidgetKit に時間に従ってそれを表示させることです。

後半では、このウィジェットを固定の役割から構成可能なエクスペリエンスに進化させます。ユーザーはホーム画面でウィジェットを長押ししてウィジェットの編集に入り、Power Panda、Egghead、または Spouty を選択できます。キャラクターを選択した後、ウィジェットをクリックすると、対応するキャラクターの詳細ページが直接表示されます。 WidgetKit は表示を担当し、SiriKit カスタム インテントは設定を担当し、`widgetURL` と SwiftUI `Link` はアプリへのジャンプバックを担当します。

##詳細

### 1. 同じウィジェットが小規模と中規模をサポートします

([03:46](https://developer.apple.com/videos/play/wwdc2020/10035/?time=226)) 最初のステップは、前のエピソードで「systemSmall」のみをサポートしていたウィジェットを「systemMedium」に拡張することです。 WidgetKit は「widgetFamily」環境値を提供し、ビューは現在のファミリーに基づいて異なるレイアウトを返すことができます。

このセッションには公式の「コード」タブ クリップはありません。コードの形状を示すために、トランスクリプトに明確に現れる API とビューの構造のみを以下にまとめます。```swift
supportedFamilies([.systemSmall, .systemMedium])

@Environment(\.widgetFamily) var family

switch family {
case .systemSmall:
    AvatarView(character: selectedCharacter)
default:
    HStack {
        AvatarView(character: selectedCharacter)
        Text(selectedCharacter.bio)
    }
}
```キーポイント:

- 「supportedFamilies」は、最初のエピソードの単一ファミリーから「systemSmall」と「systemMedium」に拡張されました。
- `widgetFamily` は、同じエントリ ビューにどのファミリーを使用してレンダリングされているかを知らせます。
- `systemSmall` は引き続き `AvatarView` を使用します。
- 中バージョンでは、`HStack` に `AvatarView` を配置し、その横にキャラクターのプロフィールを表示します。
- トランスクリプトでは、小と中両方に背景色と前景色を追加して、プレビューを実際のホーム画面効果に近づけることも実証しました。

### 2. 不必要な更新ではなく完全なタイムラインを使用する

([01:12](https://developer.apple.com/videos/play/wwdc2020/10035/?time=72)) WidgetKit には、「atEnd」、「after」、「never」の 3 つのタイムライン リロード ポリシーがあります。 `atEnd` は、最後のエントリが表示された後に更新のスケジュールを開始します。 「after」は指定された日付にスケジュールを開始します。 「決して」は、システムが独立して更新されないことを意味し、開発者はウィジェット センター API を通じて明示的にリロードする必要があります。

([07:39](https://developer.apple.com/videos/play/wwdc2020/10035/?time=459)) 絵文字レンジャーのキャラクターは時間の経過とともに再生されます。アプリが完全復元の「endDate」を認識したので、プロバイダーは文字復元が完了するまで 1 分間隔でエントリを生成できます。```swift
let selectedCharacter = configuration.hero
let endDate = selectedCharacter.fullHealthDate
let interval = oneMinute
var currentDate = Date()
var entries: [Entry] = []

while currentDate < endDate {
    entries.append(Entry(date: currentDate, character: selectedCharacter))
    currentDate += interval
}

Timeline(entries: entries, policy: .atEnd)
```キーポイント:

- `selectedCharacter` は、現在のウィジェットによって表示される文字です。
- `endDate` は、キャラクターが完全に復元される時点です。
- トランスクリプトには、更新間隔が「currentDate」から開始して 1 分であることが明示的に示されています。
- 各ループは `currentDate` を持つエントリを作成し、時間を 1 ステップ進めます。
- WidgetKit は、タイムラインが使い果たされる前にデータを取得するためにプロバイダーを再度呼び出す必要はありません。
- `atEnd` と `after` は最も早い更新時間にすぎず、システムはユーザー エクスペリエンスとスケジュール条件に基づいて実際の更新を調整します。

### 3. 関連性を使用してスマート スタックを促す

([09:00](https://developer.apple.com/videos/play/wwdc2020/10035/?time=540)) タイムライン エントリにはオプションの「関連性」もあります。ウィジェットがスタック内にある場合、システムはこのプロンプトに基づいてウィジェットをより適切な位置に回転できます。```swift
let relevance = selectedCharacter.healthLevel

Entry(
    date: currentDate,
    character: selectedCharacter,
    relevance: relevance
)
```キーポイント:

- 「関連性」の値の範囲は開発者によって定義されます。
- 完全回復がこのウィジェットにとって最も重要な状態であるため、セッションはキャラクターの健康状態を直接使用することを選択します。
- 関連性はシステムからのインテリジェントなプロンプトであり、強制的な表示コマンドではありません。

### 4. ホーム画面設定に SiriKit カスタム インテントを使用する

([09:56](https://developer.apple.com/videos/play/wwdc2020/10035/?time=596)) タイムラインが完了した後も、ウィジェットには Power Panda のみが表示されます。次に、デモでは SiriKit インテント定義ファイルを使用して構成項目を追加し、ユーザーがホーム画面でロールを選択できるようにします。```swift
Intent Definition file
category: information view
parameter: hero
enum values: Panda, Egghead, Spouty

StaticConfiguration -> IntentConfiguration
TimelineProvider -> IntentTimelineProvider
intent: CharacterSelectionIntent
snapshot(configuration)
timeline(configuration)
```キーポイント:

- インテント定義ファイルには、ウィジェット ターゲットとアプリ ターゲットの両方が含まれている必要があります。
- デモではインテント カテゴリが情報ビューに設定されています。
- `hero` パラメータは enum で、デモでは Panda、Egghead、Spouty が完成しています。
- ウィジェットのタイプが「StaticConfiguration」から「IntentConfiguration」に変更されました。
- プロバイダーがタイムライン プロバイダーからインテント タイムライン プロバイダーに変更されました。
- スナップショット メソッドとタイムライン メソッドは追加の「構成」パラメーターを受け取り、プロバイダーはその構成をアプリ内のロール定義にマップします。

### 5. ウィジェットをクリックして、対応するコンテンツに戻ります

([02:54](https://developer.apple.com/videos/play/wwdc2020/10035/?time=174)) ウィジェットにはアニメーションやカスタム インタラクションはありませんが、アプリに深くリンクできます。 「systemSmall」は完全なクリック可能な領域です。 `systemMedium` と `systemLarge` は、SwiftUI `Link` を使用して複数のクリック可能な領域を作成できます。

([13:42](https://developer.apple.com/videos/play/wwdc2020/10035/?time=822)) 構成の完了後にビューに「widgetURL」修飾子を追加する方法を示します。このようにして、ユーザーが現在のロールのウィジェットをクリックすると、対応するロールの詳細ページに直接アクセスできます。```swift
AvatarView(character: selectedCharacter)
    .widgetURL(selectedCharacter.detailURL)

Link(destination: selectedCharacter.detailURL) {
    AvatarView(character: selectedCharacter)
}
```キーポイント:

- `widgetURL` は小規模および中規模のビューで使用され、クリックで現在のロールに入ることができます。
- ユーザーがお気に入りのレンジャーを切り替えると、ジャンプ先も構成に応じて変わります。
- 中規模および大規模なファミリーでは、複数のクリック領域に余裕がある場合に SwiftUI `Link` を使用できます。

## 重要なポイント

### 1. 回復カウントダウン ウィジェットを作成する

**やるべきこと**: ゲームのキャラクター、フィットネスの回復、学習のクールダウン時間など、終了時間がわかっている状態をホーム画面に配置します。

**実行する価値がある理由**: セッションの中心的な例は、キャラクターが時間の経過とともに復元され、アプリが完全な復元の「endDate」を認識していることです。

**開始方法**: タイムライン プロバイダーでは、現在の時刻から「endDate」まで 1 分ごとにエントリが生成されます。ポリシーは最初に `.atEnd` を使用します。

### 2. 同じコンテンツに対して、小規模と中規模の 2 つの読書方法を設計します。

**何をすべきか**: 小は主要なステータスのみを表示し、中は補足情報を追加します。

**実行する価値がある理由**: トランスクリプトは、Small が引き続き `AvatarView` を使用し、Medium が `HStack` を使用してキャラクターのプロフィールを追加していることを示しています。

**開始方法**: `widgetFamily` 環境値を読み取り、`switch` を使用してさまざまなレイアウトをさまざまなファミリーに返し、プライマリ ビューとプレースホルダーを同時に更新します。

### 3. ユーザーにホーム画面構成エントリを提供します。

**手順**: ユーザーにウィジェットを長押しして、表示するロール、プロジェクト、またはアカウントを選択させます。

**実行する価値がある理由**: セッションは「CharacterSelectionIntent」を使用して、ユーザーが編集ウィジェットで Power Panda、Egghead、または Spouty を選択できるようにします。

**開始方法**: インテント定義ファイルを作成し、カテゴリを情報ビューに設定し、enum パラメーターを追加して、ウィジェットを `IntentConfiguration` に変更します。

### 4. ソート信号をスマートスタックに提供する

**やるべきこと**: 状態が最も重要な時点でのウィジェットの関連性を改善します。

**実行する価値がある理由**: セッションがウィジェットがスタック内にあることを明示的に示すと、システムは関連性に基づいてウィジェットをインテリジェントに回転できます。

**開始方法**: 優先度を表す数値を選択します。完全回復が最も重要な状態であるため、絵文字レンジャーは健康レベルを使用します。

### 5. クリック操作により正しい詳細ページが表示されるようにします。

**対処方法**: ユーザーはウィジェットをクリックし、現在の構成に対応する詳細ページに直接アクセスします。

**実行する価値がある理由**: セッション デモを Spouty として設定した後、ウィジェットをクリックすると Spouty 情報ページが表示されます。

**開始方法**: `widgetURL` を小/中ビューに追加します。中規模または大規模のターゲット領域が複数ある場合は、SwiftUI の「Link」を使用してローカルのクリック領域を切り離します。
