## ハイライト

> Swift 5.7 では文字列処理が導入されています`Regex`型、通常のリテラル構文、および`RegexBuilder`DSL を使用すると、開発者は文字列コンテンツをタイプセーフな方法で照合、抽出、変換し、Foundation の日付/数値パーサーを正規表現に直接埋め込むことができます。

## 主要内容

文字列の操作は、プログラミングで最も一般的なタスクの 1 つです。ログの解析からデータ検証に至るまで、開発者は毎日、さまざまな文字列一致コードを作成します。

Swift 5.7 より前では、正規表現の処理は主に次のものに依存していました。`NSRegularExpression`。この API は Objective-C 時代のものであり、使用するのが面倒です。一致する結果は次のとおりです。`NSTextCheckingResult`、キャプチャ グループには数値インデックスを介してアクセスする必要があり、タイプはすべて`String`または`Range`、間違いを犯しやすいです。

Swift 5.7 は、新しい通常のソリューションをもたらします。核となるのは次の 3 つです。

1. **`Regex`Type**: 標準ライブラリの新しい通常の型。厳密に型指定され、構成可能です。
2. **通常のリテラル**: コンパイラーは構文をチェックし、Xcode は構文の強調表示をサポートします。
3. **`RegexBuilder`DSL**: Swift コードを使用して規則的なパターンを記述し、自然言語に近い可読性を実現します。

これら 3 つを組み合わせると、文字列処理が「黒魔術」から通常の Swift コードに変わります。

### 文字列からタイプセーフなマッチングへ

テキストからユーザー ID を抽出したいとします。

```
name:  John Appleseed,  user_id:  100
```

以前に使用した`NSRegularExpression`大量の定型コードを記述する必要があります。 Swift Regex を使用するようになったので、3 つの記述方法から選択できます。

**文字列から作成** (実行時解析):

```swift
let regex = try Regex(#"user_id:\s*(\d+)"#)
```

**通常のリテラル** (コンパイル時チェック):

```swift
let regex = /user_id:\s*(\d+)/
```

**RegexBuilder DSL** (最高の可読性):

```swift
import RegexBuilder

let regex = Regex {
    "user_id:"
    OneOrMore(.whitespace)
    Capture(.localizedInteger)
}
```

3つの書き方で作成`regex`全て`Regex`統合マッチング アルゴリズムに渡すことができるタイプ。

### マッチングアルゴリズムのリスト

Swiftの標準ライブラリは、`String`そして`Substring`規則性主導のアルゴリズムのバッチを拡張しました ([03:49](https://developer.apple.com/videos/play/wwdc2022/110358/?time=229)):

```swift
let input = "name:  John Appleseed,  user_id:  100"
let regex = /user_id:\s*(\d+)/

input.firstMatch(of: regex)           // 找第一个匹配
input.wholeMatch(of: regex)           // 整个字符串必须匹配
input.prefixMatch(of: regex)          // 前缀匹配
input.starts(with: regex)             // 是否以模式开头
input.replacing(regex, with: "456")   // 替换匹配内容
input.trimmingPrefix(regex)           // 去掉前缀匹配部分
input.split(separator: /\s*,\s*/)     // 按正则分割
```

規則性は次のような場合にも使用できます。`switch`声明の中で：

```swift
switch "abc" {
case /\w+/:
    print("It's a word!")
}
```

### 銀行取引明細書を解析する

Foundation のパーサーを直接埋め込むことが可能`RegexBuilder`（[05:14](https://developer.apple.com/videos/play/wwdc2022/110358/?time=314)）：

```swift
let statement = """
    DSLIP    04/06/20 Paypal  $3,020.85
    CREDIT   04/03/20 Payroll $69.73
    """

let regex = Regex {
    Capture(.date(format: "\(month: .twoDigits)/\(day: .twoDigits)/\(year: .twoDigits)"))
    OneOrMore(.whitespace)
    OneOrMore(.word)
    OneOrMore(.whitespace)
    Capture(.currency(code: "USD").sign(strategy: .accounting))
}
```

ここ`.date()`そして`.currency()`Foundation が提供するパーサーで、ローカリゼーションをサポートし、さまざまなエッジ ケースを処理します。日付解析ロジックを自分で記述する必要はありません。

## 詳細

### Capture を使用してデータを抽出する

マッチングは最初のステップにすぎず、データの抽出が鍵となります。`Capture`一致した部分文字列を保存し、出力タプルに追加できます ([10:28](https://developer.apple.com/videos/play/wwdc2022/110358/?time=628))。

```swift
let regex = Regex {
   "a"
   Capture("b")
   "c"
   /d(e)f/
}

if let match = "abcdef".wholeMatch(of: regex) {
    let (wholeMatch, b, e) = match.output
    // wholeMatch = "abcdef"
    // b = "b"
    // e = "e"
}
```

キーポイント:
- `match.output`タプルです。最初の要素は一致全体で、その後に各要素が続きます。`Capture`
- 通常のリテラルのかっこ`()`キャプチャーグループでもある
- 出力タプルの型はコンパイル時に決定されます

### 実戦: XCTest ログの解析

テスト スイートのログを解析するとします。

```
Test Suite 'RegexDSLTests' started at 2022-06-06 09:41:00.001
Test Suite 'RegexDSLTests' failed at 2022-06-06 09:41:00.001.
Test Suite 'RegexDSLTests' passed at 2022-06-06 09:41:00.001.
```

最初のステップは、基本的な規則ルールを記述することです ([06:24](https://developer.apple.com/videos/play/wwdc2022/110358/?time=384)):

```swift
import RegexBuilder

let regex = Regex {
    "Test Suite '"
    /[a-zA-Z][a-zA-Z0-9]*/
    "' "
    ChoiceOf {
        "started"
        "passed"
        "failed"
    }
    " at "
    OneOrMore(.any)
    Optionally(".")
}
```

キーポイント:
- `ChoiceOf`複数のオプションの 1 つと一致する
- `Optionally`0 回または 1 回一致
- 通常のリテラル`/[a-zA-Z][a-zA-Z0-9]*/`DSLに埋め込み可能

プラス`Capture`データを抽出します ([11:10](https://developer.apple.com/videos/play/wwdc2022/110358/?time=670)):

```swift
let regex = Regex {
    "Test Suite '"
    Capture(/[a-zA-Z][a-zA-Z0-9]*/)
    "' "
    Capture {
        ChoiceOf {
            "started"
            "passed"
            "failed"
        }
    }
    " at "
    Capture(OneOrMore(.any))
    Optionally(".")
}

for line in testInputs {
    if let (whole, name, status, dateTime) = line.wholeMatch(of: regex)?.output {
        print("\(name), \(status), \(dateTime)")
    }
}
```

### 貪欲なマッチングの問題への対処

上記のコードを実行すると、次のことがわかります`dateTime`最終ピリオドも含みます。その理由は、`OneOrMore(.any)`デフォルトは熱心で、できるだけ多くの文字に一致します ([11:51](https://developer.apple.com/videos/play/wwdc2022/110358/?time=711))。

修正するには、消極モードに変更します。

```swift
Capture(OneOrMore(.any, .reluctant))
```

キーポイント:
- `.reluctant`重複が一致する文字数をできるだけ少なくする
- エンジンはまず次のパターンとの一致を試み、失敗した場合はバックトラックしてさらに多くの文字を消費します。
- も使用できます`.repetitionBehavior(.reluctant)`正規表現全体のデフォルトの動作を変更する

### キャプチャの変換: 部分文字列から特定の型へ

キャプチャされたコンテンツのデフォルトは、`Substring`、通常は、より意味のある型に変換する必要があります。`Capture`サポート`transform`閉鎖 ([15:20](https://developer.apple.com/videos/play/wwdc2022/110358/?time=920)):

```swift
Regex {
    Capture {
        OneOrMore(.digit)
    } transform: {
        Int($0)  // 输出类型变成 Int?
    }
}
```

変換が失敗する可能性がある場合は、次を使用します。`TryCapture`、これはオプションのタイプを「フラット化」します ([15:55](https://developer.apple.com/videos/play/wwdc2022/110358/?time=955)):

```swift
Regex {
    TryCapture {
        OneOrMore(.digit)
    } transform: {
        Int($0)  // 输出类型是 Int，不是 Int?
    }
}
```

キーポイント:
- `TryCapture`変換は戻ります`Optional`、ただし出力タイプはオプションではありません
- 変換が失敗すると、エンジンは自動的にバックトラックし、他の一致するパスを試行します。
- 失敗可能なイニシャライザでの使用に適しています

### Foundation パーサーを使用した日付の処理

ステータスを列挙に変換し、タイムスタンプを次のように変換します。`Date`（[16:21](https://developer.apple.com/videos/play/wwdc2022/110358/?time=981)）：

```swift
enum TestStatus: String {
    case started, passed, failed
}

let regex = Regex {
    "Test Suite '"
    Capture(/[a-zA-Z][a-zA-Z0-9]*/)
    "' "
    TryCapture {
        ChoiceOf { "started"; "passed"; "failed" }
    } transform: {
        TestStatus(rawValue: String($0))
    }
    " at "
    Capture(.iso8601(
        timeZone: .current,
        includingFractionalSeconds: true,
        dateTimeSeparator: .space))
    Optionally(".")
}
// 输出类型: Regex<(Substring, Substring, TestStatus, Date)>
```

キーポイント:
- `.iso8601()`Foundation が提供する日付パーサーです
- 出力タプルの最後の要素は直接`Date`タイプ
- 手動で二次分析を行う必要はありません

### カスタム パーサー: C ライブラリへのアクセス

既存の C パーサーにプラグインしたい場合は、次のようにすることができます。`CustomConsumingRegexComponent`プロトコル ([19:16](https://developer.apple.com/videos/play/wwdc2022/110358/?time=1156)):

```swift
import Darwin

struct CDoubleParser: CustomConsumingRegexComponent {
    typealias RegexOutput = Double

    func consuming(
        _ input: String,
        startingAt index: String.Index,
        in bounds: Range<String.Index>
    ) throws -> (upperBound: String.Index, output: Double)? {
        input[index...].withCString { startAddress in
            var endAddress: UnsafeMutablePointer<CChar>!
            let output = strtod(startAddress, &endAddress)
            guard endAddress > startAddress else { return nil }
            let parsedLength = startAddress.distance(to: endAddress)
            let upperBound = input.utf8.index(index, offsetBy: parsedLength)
            return (upperBound, output)
        }
    }
}
```

カスタム パーサーの使用 ([20:13](https://developer.apple.com/videos/play/wwdc2022/110358/?time=1213)):

```swift
let regex = Regex {
    "Test Case "
    OneOrMore(.any, .reluctant)
    "("
    Capture {
        CDoubleParser()
    }
    " seconds)."
}

if let match = input.wholeMatch(of: regex) {
    print("Time: \(match.1)")  // Double 类型
}
```

キーポイント:
- `consuming`このメソッドは、一致の上限インデックスと解析結果を返します。
- 戻る`nil`一致が失敗し、エンジンがバックトラックすることを示します
- これは、既存の解析ライブラリ (JSON、YAML パーサーなど) へのブリッジです。

## 重要ポイント

**1.ログパーサー**

何をすべきか: コンパイル エラーと警告を抽出するプロジェクト用の Xcode ビルド ログ パーサーを作成します。

実行する価値がある理由: 使用する`RegexBuilder`ログ形式を記述するには、次を使用します。`TryCapture`エラー情報を構造化データに変換します。これは、通常の文字列よりも保守が容易です。

開始方法: を定義します。`BuildLogEntry`構造、用途`RegexBuilder`マッチ`error:` / `warning:`接頭辞、使用`Capture`ファイル名、行番号、エラーの説明を抽出します。

**2.スマート クリップボード ツール**

何をすべきか: クリップボードの内容を自動的に認識し、重要な情報 (配送番号、携帯電話番号、URL など) を抽出する macOS ツールを作成します。

実行する価値がある理由: Swift Regex`firstMatch`そして`wholeMatch`クリップボードの文字列に直接使用できます。`TryCapture`一致した結果を特定の型に変換します。

開始方法: 使用する`NSPasteboard`クリップボードの変更を監視し、テキスト コンテンツで複数の規則的なパターンを試し、一致が成功した後に抽出結果を表示します。

**3.設定ファイルバリデータ**

やるべきこと: チームの内部構成ファイル形式の検証ツールを作成し、構文エラーをチェックし、わかりやすいプロンプトを表示します。

実行する価値がある理由:`RegexBuilder`読みやすいため、構成ルールが一目で明確になり、新しいメンバーも検証ロジックをすぐに理解できます。

開始方法: 構成ファイルの各行を次のように定義します。`Regex`、使用`wholeMatch`検証。失敗した場合は、特定のエラー位置と予期される形式を返します。

**4.データ移行スクリプト**

対処方法: 古いシステムのテキスト ログを新しいデータベースに移行するスクリプトを作成し、正規表現を使用してフィールドを抽出し、型を変換します。

実行する価値がある理由:`TryCapture`協力する`Date` / `Int` / `Double`イニシャライザ、正規表現 1 行で抽出と変換を完了でき、二次解析は必要ありません。

開始方法: Foundation を使用する`.date()`そして`.currency()`日付および金額フィールドを処理するパーサー、カスタム`CustomConsumingRegexComponent`特殊な形式を処理します。
