## ハイライト

> 2020 年に、Apple は Schoolwork 2.0、ClassKit Catalog API、Apple School Manager と Classroom の統合、共有 iPad 一時セッション、および Mac 上の自動評価構成を教育アプリケーション アクセス ルートの同じセットに組み込みました。

---

## 主な内容

教育アプリで難しいのは、多くの場合、レッスンそのものではなく、それが学校の日常の流れにどのように適合するかということです。教師はアクティビティを割り当てる必要があり、生徒は宿題の正しい内容を入力する必要があり、IT 管理者はアカウント、デバイス、アプリをバッチで管理する必要があります。せっかくよくできた学習機能が、スクールワークやクラスルーム、共有iPadのプロセスに登場しなければ、学校で安定して利用することは難しいでしょう。

このセッションでは、まず入り口をわかりやすく説明しましょう。スクールワーク 2.0 には、新しい配布物ビューと生徒ビューが追加されました。教師は、アプリ アクティビティ セレクターから ClassKit アプリ アクティビティを宿題に追加できます。新しいセレクターにはサムネイルと概要情報が表示され、課題の詳細ページには時間、完了率、クイズのスコアが表示されます。ここでの展示効果はスクールワークだけでは完成しません。メタデータの提供と ClassKit の進行はアプリに依存します。

次に、Apple はコンテンツ検出をネイティブ コンテキスト ストアからより初期の段階に推し進めました。以前は、教師はアプリをダウンロードして開き、アクティビティを参照してからアプリを起動する必要がよくありました。`CLSContext`ClassKit に公開します。 ClassKit Catalog API で変更されるのは、この検出パスです。開発者は Web API を使用してアプリの公開アクティビティを公開でき、アプリがインストールされている限り、教師はスクールワークのアクティビティ セレクターでこれらのアクティビティを確認できます。

学校側の意思統一も進んでいる。 Apple School Manager によって作成されたクラスは、Classroom と Schoolwork に自動的に表示されます。学生は、管理対象 Apple ID でログインした後、対応するクラスに入ります。 Classroom は、アプリを起動して適切な ClassKit アクティビティを実行することもできます。共有 iPad には新しい一時セッションが追加されました。 Apple ID を持たない学生も一時的にデバイスを使用できます。このデータはログアウトすると削除されます。

最後の部分は試験です。自動評価構成フレームワークが Mac に導入され、iOS、macOS、および Catalyst がサポートされます。試験アプリを使用すると、システムは、画面共有、ユニバーサル クリップボード、ディクテーション、およびテスト中の公平性に影響を与える可能性のあるその他の機能を無効にすることができます。 Apple はまた、古い UIKit 評価モードが iOS では廃止され、新しい評価フレームワークがそれに続くエントリであることを開発者に思い出させています。

＃＃詳細

### Schoolwork 2.0 はアプリに依存して、より豊富なアクティビティ データを提供します

([01:12](https://developer.apple.com/videos/play/wwdc2020/10658/?time=72)) スクールワークのアプリ アクティビティ セレクターは、教師が配布物にアプリ アクティビティを追加する場所です。 2020 年の新しいデザインでは、アクティビティのサムネイルと概要情報が表示され、配布物の詳細ページにはクラスと個々の生徒の進捗状況も表示されます。

キーポイント:

- アクティビティがスクールワーク配布プロセスに入る前に、アプリは ClassKit フレームワークを使用する必要があります。
- アクティビティ セレクターの新しいメタデータ フィールド、サムネイル、概要は、教師がコンテンツを迅速に識別する能力に直接影響します。
- アプリは、費やした時間、完了率、クイズのスコアを ClassKit に報告できます。
- 進捗状況は、アクティビティを割り当てられた生徒に対応する教師など、許可された人にのみ表示されます。

### ClassKit カタログ API 変更アクティビティ検出パス

([03:10](https://developer.apple.com/videos/play/wwdc2020/10658/?time=190)) 以前は、アプリはまずアクティビティを次のように扱う必要がありました。`CLSContext`教師がスクールワークで選択できるように、ローカルの ClassKit ストアに公開します。このプロセスは、コンテンツにすでに精通している教師には適していますが、コースのリソースを初めて探している教師には適していません。

キーポイント:

- ClassKit カタログは、アプリの公開アクティビティの一元的なカタログです。
- アプリがインストールされている限り、スクールワークはローカル コンテキスト ストアだけに依存することなく、カタログからアプリのアクティビティを検出できます。
- 開発者はWeb API経由でアクティビティデータを公開します。
- カタログには、教師がコンテンツを検索して識別するのに役立つ新しいメタデータ フィールドも含まれています。
- このセッションはカタログ リクエストの形式を拡張するものではありませんが、同年の「ClassKit の新機能」を指します。

### Apple School Manager、スクールワーク、クラスルームがクラスデータの共有を開始

([04:29](https://developer.apple.com/videos/play/wwdc2020/10658/?time=269)) Apple School Manager は、学校がアカウント、デバイス、コンテンツを管理するための Web ポータルです。 2020 年の焦点は、スクールワークとクラスルームとのより緊密な統合です。 Apple School Manager によって作成されたクラスは Classroom と Schoolwork に自動的に表示され、その後の更新も同期されます。

キーポイント:

- IT 管理者は、Apple School Manager でクラスを作成し、教師と生徒のログイン資格情報を管理できます。
- このシステムは、学生情報システム、SFTP、および Microsoft Active Directory に基づく統合認証をサポートしています。
- モバイル デバイス管理を通じてデバイスをリモートで登録できるため、配布前に管理者が各デバイスに連絡する必要がなくなります。
- アプリと書籍エリアは学校がコンテンツを購入する場所であり、教育アプリは調達と展開のパスを検討する必要があります。

### Classroom は生徒を正しいアプリのアクティビティに誘導できます

([06:08](https://developer.apple.com/videos/play/wwdc2020/10658/?time=368)) Classroom を使用すると、教師はすべての生徒の iPad で同じアプリを同時に開いたり、生徒グループに応じて異なるアプリを開いたりできます。アプリが ClassKit に接続されている場合、教師はアプリを開いて正しいアクティビティを開くこともできます。

キーポイント:

- Classroom は生徒の iPad 画面の表示をサポートし、ズームにピンチを追加します。
- 教師は、AirPlay クラス コード ボタンを通じてクラス参加情報を Apple TV に表示できます。
- Apple School Manager とスクールワークを使用して作成されたクラスが Classroom に表示されます。
- 2020 年秋には、教師が Classroom でクラスを作成し、Apple School Manager およびスクールワークで使用できるようになります。

### 共有 iPad では、アプリが生徒データをクラウドに同期する必要があります

([07:20](https://developer.apple.com/videos/play/wwdc2020/10658/?time=440)) 共有 iPad を使用すると、学生は共有デバイスにログインして自分の iPad として使用できます。学生がログアウトするとデータは保持されなくなる可能性があるため、開発者はこの学生のローカル データが存在しないと想定する必要があります。

キーポイント:

- アプリは個人用デバイスと同様に共有 iPad でも動作する必要がありますが、ユーザー データはクラウドから同期する必要があります。
- 一時セッションでは、学生は Apple ID なしで共有 iPad を使用できます。
- 一時セッションからログアウトすると、このセッションで作成されたデータは削除されます。
- 一時セッションはデフォルトでオンになっています。 MDM 開発者は、新しい監視付き制限を使用して、顧客がそれをオフにすることを選択できるようにすることができます。
- Apple は、学生のログアウト後のバックグラウンド同期をサポートするために、longLived CKOperations と UIBackgroundTasks について明示的に言及しています。

### 自動評価構成が Mac に登場

([08:48](https://developer.apple.com/videos/play/wwdc2020/10658/?time=528)) 自動評価構成フレームワークにより、試験アプリはテスト中に安全な環境を提供できます。この機能は、過去に iPad の標準化された試験シナリオで初めて登場し、2020 年に Mac にも拡張され、iOS、macOS、および Catalyst をサポートしています。

キーポイント:

- 学生はテスト中、試験アプリにロックされます。
- 画面共有、ユニバーサル クリップボード、ディクテーションなどのシステム機能は、試験中は自動的に無効になります。
- 開発者は新しい資格を申請する必要があります。
- iOS の古い UIKit 評価モードは廃止されたため、新しいフレームワークに切り替える必要があります。
- iOS では、設定オプションを通じて試験中に利用できるシステム機能をカスタマイズすることもできます。

## 重要なポイント

### 1. コースアクティビティを最初にスクールワークに組み込みます

**やるべきこと**: 教育アプリでコース、単元、演習用の ClassKit アクティビティを作成し、サムネイル、概要、進捗状況のフィールドに値を入力します。

**実行する価値がある理由**: スクールワーク 2.0 のアクティビティ セレクターには、より豊富なアクティビティ情報が表示され、配布物の詳細ページもアプリによって報告される進捗データに依存します。

**開始方法**: まず、教師が割り当てることができるアプリ内のアクティビティを分類し、それらを ClassKit アクティビティとして公開し、次にサムネイル、概要、費やした時間、完了率、またはクイズのスコアを各アクティビティに追加します。

### 2. 公開コースのコンテンツを ClassKit カタログに送信する

**やるべきこと**: 教師がまだ閲覧していない公開コンテンツのカタログ送信プロセスを作成し、スクールワークがこれらのアクティビティを直接発見できるようにします。

**実行する価値がある理由**: ローカル`CLSContext`カタログ API を使用すると、教師が最初にアプリにアクセスしてコンテンツを閲覧することに依存するのではなく、教師が課題を割り当てる前にアクティビティを検出できるようになります。

**開始方法**: まず、パブリックで安定しており、宿題を割り当てるのに適したアクティビティを選択し、ClassKit Catalog API のドキュメントに従ってメタデータとリリース プロセスを準備します。

### 3. 共有 iPad のクラウド回復パスを作成する

**機能**: 共有 iPad からログインしたときに、学生がコースのステータス、下書き、学習の進捗状況を復元できるようにします。

**実行する価値がある理由**: 一時セッションには Apple ID は必要なく、ログアウト後にローカル データは保持されません。教育アプリは、デバイス上に残っている最後のローカル キャッシュに依存することはできません。

**開始方法**: すべての生徒データにクラウド ソースがあるかどうかを確認し、UIBackgroundTasks で LongLived CKOperations を使用して、ログアウトの前後にバックグラウンド同期を処理します。

### 4. 試験アプリを新しい評価フレームワークに移行する

**何をすべきか**: 古い UIKit 評価モードに依存する試験フローを自動評価構成に移行します。

**価値がある理由**: 新しいフレームワークは iOS、macOS、Catalyst をカバーしており、Mac も制御された試験環境に入ることができます。

**開始方法**: まず資格を申請し、「評価の新機能」のプロセスに従って試験の開始、終了、失敗、および中断の処理を確立します。

### 5. アクティビティに深くリンクするための Classroom エクスペリエンスを準備する

**内容**: 教師が Classroom からアプリを起動したときに、生徒が割り当てられた ClassKit アクティビティに直接移動できるようにします。

**価値がある理由**: Classroom では、クラス全体または生徒のグループを同じアプリに参加させたり、ClassKit 対応アプリで適切なアクティビティを開いたりできます。

**開始方法**: アプリのアクティビティが ClassKit に接続されていることを確認し、教師が Classroom からアプリを起動した後、生徒に通常のホームページの代わりに対応するアクティビティが表示されることをテストします。
