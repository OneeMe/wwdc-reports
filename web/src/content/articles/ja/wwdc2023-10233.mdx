## ハイライト

> iOS 17 と macOS 14 では、AirPods の自動切り替え、プレスミュート、空間オーディオの統合が開発者にとってほぼゼロコストになります。メディア アプリは Now Playing を登録することで自動切り替えに参加でき、CallKit アプリは自動的にプレスミュートを取得し、空間オーディオは AVPlayer アプリと AudioQueue アプリですぐに利用できます。

## 主な内容

AirPods は世界で最も人気のあるワイヤレス ヘッドフォンで、毎日何億人もの人々が音楽を聴いたり、ビデオを見たり、ビデオ会議を行ったりするために使用しています。 iOS 17 と macOS 14 では、AirPods エクスペリエンスをよりシームレスにするために 3 つの重要な改善が加えられています。

### 自動切り替え

macOS 14 は AirPods の自動切り替えのサポートを開始します。ユーザーは iPhone で音楽を聴いており、Mac で会議通知を受信し、Mac のロックを解除すると AirPods が自動的に接続してバナー確認を表示し、iPhone の音楽が自動的に一時停止されます。 ([01:33](https://developer.apple.com/videos/play/wwdc2023/10233/?time=93))

良いニュースは、すべての App Store アプリとサンドボックス外のアプリは追加の調整を行う必要がないことです。自動切り替えアルゴリズムは、再生中の登録と入力オーディオ アクティビティに基づいてルーティングを決定します。

ただし、エクスペリエンスを最適化するためのベスト プラクティスがいくつかあります: ([05:17](https://developer.apple.com/videos/play/wwdc2023/10233/?time=317))

- システムがルーティングの優先順位を正しく設定できるように、メディア/ストリーミング メディア アプリの再生中を登録することをお勧めします。
- 会議/ゲーム アプリ Now Playing への登録は推奨されません
- Audio Services API を使用して通知効果音を再生し、通知とメディア コンテンツを区別します
- 会議アプリは通話中のみマイクをオンにし、通話終了後すぐにオフにします。
- メディア アプリは、ユーザーが選択したデフォルト ルートを使用してオーディオを再生します。
- ユーザーが一時停止した後に無音の再生を避け、必要に応じて 2 秒に制限します

### 押すとミュートになります

iOS 17 と macOS 14 は、AirPods のステムを押してミュート/ミュート解除をサポートします。ユーザーが押すと、システムはマイクのステータス バナーを表示し、サウンドを再生します。 ([02:26](https://developer.apple.com/videos/play/wwdc2023/10233/?time=146))

iOS では、追加のコードを必要とせずに、すべての CallKit アプリがこの機能を自動的に取得します。 CallKit 以外の通信アプリは新しいものを使用する必要があります`AVAudioApplication`API アクセス。 ([07:03](https://developer.apple.com/videos/play/wwdc2023/10233/?time=423))

macOS での動作は少し異なります。アプリはミュート ジェスチャ通知を受信した後、アップストリーム オーディオをミュートします。 ([09:47](https://developer.apple.com/videos/play/wwdc2023/10233/?time=587))

### 空間オーディオ

Apple Music の加入者の 80% 以上が空間オーディオを使用して聴いています。 iOS 16 で導入されたパーソナライズされた空間オーディオは、iOS 17 でも引き続きサポートを拡張します。 ([12:05](https://developer.apple.com/videos/play/wwdc2023/10233/?time=725))

macOS 14 は、AVPlayer および AVSampleBufferAudioRenderer の空間オーディオをサポートします。 iOS と tvOS は、AURemoteIO と AudioQueue をさらにサポートします。後者の 2 つは API インターフェイスを持たず、Now Playing を登録するアプリに対して自動的に有効になります。ユーザーはコントロール センターでこれらを設定できます。

### iOS のミュート アクセスを押します

```swift
import AVFAudio
import Combine

class AudioManager: ObservableObject {
    @Published var isMuted = false
    private var cancellables = Set<AnyCancellable>()

    init() {
        let center = NotificationCenter.default
        center.publisher(for: AVAudioApplication.inputMuteStateChangeNotification)
            .sink { [weak self] notification in
                guard let self = self,
                      let userInfo = notification.userInfo,
                      let muteState = userInfo[AVAudioApplication.muteStateKey] as? Bool else {
                    return
                }
                self.isMuted = muteState
            }
            .store(in: &cancellables)
    }

    func toggleMute() {
        let instance = AVAudioApplication.shared
        instance.setInputMuted(!instance.isInputMuted)
    }
}
```

**キーポイント:**
- `AVAudioApplication`AVAudioSession ファミリの新しいメンバーであり、アプリケーション レベルのオーディオ動作を管理します
-`inputMuteStateChangeNotification`ミュート状態が変化すると通知がトリガーされます
-`muteStateKey`通知から`userInfo`新しいミュート ステータスを抽出します
-`setInputMuted()`システムステータスの同期を保つためにアプリ内でミュートがトリガーされたときに呼び出されます
-`isInputMuted`現在のミュート状態を読み取る
- 通知を購読すると、アプリはプレストゥミュート機能にオプトインします

### macOS 押すとアクセスがミュートされます

```swift
import AVFAudio
import CoreAudio

class MacAudioManager {
    let instance = AVAudioApplication.shared

    func setupMuteHandler() {
        instance.setInputMuteStateChangeHandler { isMuted in
            // 静音上行音频
            self.muteUplinkAudio(isMuted)

            // 更新 UI 状态
            DispatchQueue.main.async {
                self.updateMuteUI(isMuted)
            }

            // 返回是否成功处理
            return true
        }
    }

    func muteUplinkAudio(_ isMuted: Bool) {
        var propertyAddress = AudioObjectPropertyAddress(
            mSelector: kAudioHardwarePropertyProcessInputMute,
            mScope: kAudioObjectPropertyScopeInput,
            mElement: kAudioObjectPropertyElementMain
        )

        var muteValue: UInt32 = isMuted ? 1 : 0
        let size = UInt32(MemoryLayout.size(ofValue: muteValue))

        AudioObjectSetPropertyData(
            kAudioObjectSystemObject,
            &propertyAddress,
            0,
            nil,
            size,
            &muteValue
        )
    }

    func updateMuteUI(_ isMuted: Bool) {
        // 更新麦克风状态指示器
    }
}
```

**キーポイント:**
- macOS 上`setInputMuteStateChangeHandler`これは必要である。システムは通知のみを担当します。ミュートロジックはアプリによって実装されます。
- ハンドラーが戻ります`Bool`処理が成功し、不適切なミュート操作を拒否できるかどうかを示します。
-`kAudioHardwarePropertyProcessInputMute`これは CoreAudio の新しいプロパティです。有効にすると、プロセスのすべての入力音声がミュートされますが、IO は実行されたままになります。
- UI の更新にはハンドラーを使用しないでください。UI の更新を渡す必要があります。`inputMuteStateChangeNotification`通知の処理
-`AudioObjectSetPropertyData`この操作はシステム レベルのオーディオ オブジェクトであり、エラー コードは正しく処理される必要があります。

### プレイ中登録

Media App Registration Now Playing は、自動切り替えと空間オーディオを活用するための鍵となります。

```swift
import MediaPlayer

func setupNowPlaying() {
    var nowPlayingInfo = [String: Any]()
    nowPlayingInfo[MPMediaItemPropertyTitle] = "Song Title"
    nowPlayingInfo[MPMediaItemPropertyArtist] = "Artist Name"
    nowPlayingInfo[MPNowPlayingInfoPropertyPlaybackRate] = 1.0

    MPNowPlayingInfoCenter.default().nowPlayingInfo = nowPlayingInfo

    let commandCenter = MPRemoteCommandCenter.shared()
    commandCenter.playCommand.addTarget { _ in
        // 处理播放
        return .success
    }
    commandCenter.pauseCommand.addTarget { _ in
        // 处理暂停
        return .success
    }
}
```

**キーポイント:**
- `MPNowPlayingInfoCenter`再生中のコンテンツをシステムに登録する
- 登録後、システムはユーザーが選択したデバイスにオーディオを正しくルーティングできるようになります。
- 空間オーディオ ペア AudioQueue と AURemoteIO は、Now Playing に登録されたアプリに対して自動的に有効になります
- 自動切り替えアルゴリズムの干渉を避けるため、会議/ゲーム アプリには Now Playing を登録しないでください。

### オーディオルーティング変更の監視

```swift
import AVFAudio

func setupRouteChangeMonitoring() {
    NotificationCenter.default.addObserver(
        self,
        selector: #selector(handleRouteChange),
        name: AVAudioSession.routeChangeNotification,
        object: nil
    )
}

@objc func handleRouteChange(_ notification: Notification) {
    guard let userInfo = notification.userInfo,
          let reasonValue = userInfo[AVAudioSessionRouteChangeReasonKey] as? UInt,
          let reason = AVAudioSession.RouteChangeReason(rawValue: reasonValue) else {
        return
    }

    let session = AVAudioSession.sharedInstance()
    let currentRoute = session.currentRoute

    switch reason {
    case .newDeviceAvailable:
        // AirPods 已连接
        let hasHeadphones = currentRoute.outputs.contains { port in
            port.portType == .headphones || port.portType == .bluetoothA2DP
        }
        if hasHeadphones {
            print("AirPods connected")
        }
    case .oldDeviceUnavailable:
        // AirPods 已断开
        print("AirPods disconnected")
    case .categoryChange:
        // 音频类别变化
        break
    default:
        break
    }
}
```

**キーポイント:**
- `routeChangeNotification`オーディオルーティングが変更されるとトリガーされます
-`AVAudioSessionRouteChangeReason`変更の理由を列挙で説明します
-`currentRoute.outputs`すべての電流出力ポートを含む
-`.bluetoothA2DP`そして`.headphones`AirPodsの接続状態を検出できる
- 正しく扱ってください`.oldDeviceUnavailable`AirPodsが接続されていないときに再生を一時停止できます

## 重要なポイント

**1.インテリジェントな会議アシスタント**
対処法: AirPods のプレストゥミュートをビデオ会議アプリに統合し、マイクのステータスを UI にリアルタイムで表示します。
実行する価値がある理由: AVAudioApplication を使用すると、わずか数行のコードでミュート アクセスを押すだけで、会議中のユーザーの効率が大幅に向上します。
開始方法: 購読する`inputMuteStateChangeNotification`、使用`@Published`ツールバーにミュート アイコンを表示する、プロパティ駆動型の SwiftUI のマイク ステータス インジケーター。

**2.クロスデバイスのオーディオステータスの同期**
対処法: iPhone から Mac に切り替えるときに AirPods を自動的に一時停止し、元に戻すときに再生の進行を再開するポッドキャスト アプリまたは音楽アプリを作成します。
実行する価値がある理由: 自動切り替えはシステムレベルの機能ですが、アプリレベルの再生ステータスの同期は開発者自身が実装する必要があります。
開始方法: モニタリング`routeChangeNotification`、存在する`.oldDeviceUnavailable`現在の再生の進行状況を保存する`.newDeviceAvailable`同じ AirPods のペアであるかどうかを確認し、再生を再開します。

**3.空間オーディオ ゲーム**
何をすべきか: プレイヤーの頭の方向に基づいて空間オーディオをゲームに追加し、敵の位置を音で判断できるようにします。
その価値がある理由: 空間オーディオは AURemoteIO および AudioQueue アプリで自動的に有効になり、マルチチャンネル コンテンツを提供するだけです。
開始方法: 空間オーディオ (Dolby Atmos など) をサポートするオーディオ形式でゲームのサウンド効果をエンコードし、AudioQueue を通じて再生すると、システムが自動的にヘッド トラッキングを処理します。

**4. AirPods 接続対応 UI**
対処法: オーディオ アプリで AirPods の接続ステータスを検出し、接続されている場合は空間オーディオ スイッチを表示し、切断された場合は最高のエクスペリエンスを得るためにヘッドフォンを接続するようにユーザーに促します。
価値がある理由: エクスペリエンスはオーディオ デバイスによって大きく異なるため、デバイスの種類に基づいて UI を調整すると、ユーザーの満足度が向上します。
始め方：定期点検`AVAudioSession.sharedInstance().currentRoute.outputs`、ポートの種類に応じてインターフェイス要素を動的に調整します。
