## ハイライト

> iPadOS 14 的设计目标是为 iPad 带来更多的桌面级生产力体验，同时保留触屏操作的直观性。Session 介绍了 iPadOS 14 中四个核心的 UI 模式更新。

## 主要内容

iPad の画面は十分大きいですが、多くの iPad アプリは依然として iPhone の 1 列のナビゲーションを使用しています。ユーザーは、「メール」でメールボックスと電子メールを同時にチェックしたい、「メモ」でツールを選択しながら書き込みを続けたい、「ホーム」で部屋やデバイスをすばやく切り替えたいと考えています。古いインターフェースでは、多くの場合、続行する前にページ間を行ったり来たりしたり、ポップアップ レイヤーを閉じたりする必要があります。

iPadOS 14 では、このパスが UIKit に追加されます。`UISplitViewController`インターフェースを列ごとに編成するための新しい初期化メソッドが追加されました。アプリは 2 列または 3 列のレイアウトを直接宣言し、プライマリ、補足、セカンダリ、コンパクト、その他の列に対応するビュー コントローラーを提供できます。UIKit は、サイズ クラスに応じて適切な列を表示し、列を表示または非表示にするためのボタンとジェスチャを自動的に提供します。

列里的列表也换成了现代做法。Apple 推荐用 `UICollectionView`協力する`UICollectionLayoutListConfiguration` 创建 sidebar 外观，再用 `UICollectionView.CellRegistration` 和 `UICollectionViewDiffableDataSource`セルにデータを受信します。このようにして、iPadOS 14 のサイドバー スタイルを取得できるだけでなく、コレクション ビューのドラッグ並べ替え、アウトライン、スワイプ アクション、およびカスタマイズ可能なセルを引き続き使用することもできます。

Session 后半段用 Shortcuts 做案例。Shortcuts 在 regular width 里把 tab bar 换成 collapsible sidebar，在 compact width 里仍然使用适合小屏的 tab bar 和列表。它没有维护两套完全割裂的 app，而是把两种导航流程放进同一个 `UISplitViewController`，再在 size class 切换时恢复用户正在看的 detail 状态。

## 詳細

### 複数列レイアウトはUISplitViewControllerから始まります

（[01:57](https://developer.apple.com/videos/play/wwdc2020/10105/?time=117)）iOS 14 的 `UISplitViewController`新しいイニシャライザは、`style`、アプリに 2 列が必要か 3 列が必要かを宣言するために使用されます。二重の列はプライマリとセカンダリと呼ばれ、3 つの列は中央に補助を追加します。

```swift
let splitViewController = UISplitViewController(style: .doubleColumn)
```

キーポイント:
- `style: .doubleColumn`この分割ビューがナビゲーション列とコンテンツ列を担当することを示します。
- 这个 initializer 会启用 session 中展示的新列管理 API。
- Apple は、列に構造化されたアプリを直接実行することを推奨しています。`UISplitViewController` 作为 window 的 root view controller。

（[02:13](https://developer.apple.com/videos/play/wwdc2020/10105/?time=133)）创建 split view 后，把具体 view controller 放进指定列。Home 的例子是 primary 放 sidebar，secondary 放首页内容。

```swift
splitViewController.setViewController(sidebarViewController, for: .primary)
splitViewController.setViewController(myHomeViewController, for: .secondary)
```

キーポイント:
- `.primary`通常は、メールボックス リスト、ルーム リスト、ショートカット カテゴリなどのナビゲーション ポータルをホストします。
- `.secondary` 承载用户当前操作的主要内容。
- UIKit 会根据 regular width 或 compact width 决定这些列怎样出现。

（[02:28](https://developer.apple.com/videos/play/wwdc2020/10105/?time=148)）如果 app 的信息层级需要三列，可以把 style 换成 `.tripleColumn`，再为 supplementary 列提供中间层内容。Mail 的 mailbox、message list、message detail 就是这种模型。

```swift
let splitViewController = UISplitViewController(style: .tripleColumn)
splitViewController.setViewController(inboxViewController, for: .supplementary)
```

キーポイント:
- `.tripleColumn` 适合导航、列表、详情同时存在的生产力 app。
- `.supplementary` 是 primary 和 secondary 之间的中间列。
- この API は構造のみを担当し、列内の特定のインタラクションは引き続きそれぞれのビュー コントローラーによって管理されます。

### compact width 可以使用不同导航流

([04:02](https://developer.apple.com/videos/play/wwdc2020/10105/?time=242)) 標準幅では複数の列を表示できますが、コンパクト幅では水平方向のスペースが不足します。Session は、通常の幅でサイドバーを使用し、コンパクトな幅でタブ バー コントローラーを提供するというショートカットのアプローチを示しています。

```swift
splitViewController.setViewController(tabBarController, for: .compact)
```

キーポイント:
- `.compact`列は、iPhone の縦向き、iPad の Slide Over など、幅の狭い環境で使用されます。
- compact flow 可以和 regular width 的 sidebar flow 不同。
- ロジックの切り替え`UISplitViewController` 根据 trait collection 处理，app 需要负责保持用户所在位置。

([05:29](https://developer.apple.com/videos/play/wwdc2020/10105/?time=329)) 複数列インターフェイスは単なる固定レイアウトではありません。`preferredSplitBehavior`ボタンとエッジ ジェスチャが異なる表示モード間でどのように移動するかを決定します。

```swift
splitViewController.preferredSplitBehavior = .tile
splitViewController.preferredSplitBehavior = .displace
splitViewController.preferredSplitBehavior = .overlay
```

キーポイント:
- `.tile` 偏向把列并排摆放，适合希望内容始终可见的 app。
- `.displace`3 つの列が表示されると、2 番目の部分が押しのけられます。
- `.overlay`ナビゲーション情報を簡単に表示するのに適した、セカンダリ列をオーバーレイする追加の列を用意します。

([05:56](https://developer.apple.com/videos/play/wwdc2020/10105/?time=356)) アプリは、列の非表示または表示をアクティブにリクエストすることもできます。UIKit はスムーズな遷移を実行し、自動生成されたボタンを各列のナビゲーション バーまたはツールバーに配置します。

```swift
splitViewController.hideColumn(.primary)

splitViewController.showColumn(.supplementary)
```

キーポイント:
- `hideColumn` 适合让用户专注当前内容，例如只看文档或邮件正文。
- `showColumn`ナビゲーション列または中央のリストを戻すことができます。
- session 还提到 `presentsWithGesture` 和 `showsSecondaryOnlyButton`，它们控制边缘手势和只显示 secondary 的按钮。

### sidebar list 用 UICollectionView 搭起来

([08:06](https://developer.apple.com/videos/play/wwdc2020/10105/?time=486)) 列は単なるコンテナであり、サイドバーのリストはコレクション ビューを使用する必要があります。iOS 14で利用可能`UICollectionLayoutListConfiguration`，可以直接指定 sidebar 外观。

```swift
let configuration = UICollectionLayoutListConfiguration(appearance: .sidebar)
let layout = UICollectionViewCompositionalLayout.list(using: configuration)
let collectionView = UICollectionView(frame: frame, collectionViewLayout: layout)
```

キーポイント:
- `.sidebar` 会给 primary 列提供 iPadOS 14 的 sidebar 视觉样式。
- `UICollectionViewCompositionalLayout.list(using:)` 生成垂直滚动的 list layout。
- `UICollectionView`コレクション ビューの柔軟性は引き続き維持され、後でアクセサリを追加したり、ドラッグして並べ替えたり、アウトラインやスワイプ アクションを実行したりできます。

（[09:36](https://developer.apple.com/videos/play/wwdc2020/10105/?time=576)）cell 不再需要为了简单列表就写 subclass。`CellRegistration`登録と構成を 1 か所にまとめて渡す`defaultContentConfiguration()` 写入文字和图片。

```swift
let cellRegistration = UICollectionView.CellRegistration<UICollectionViewListCell, MyItem>
{ cell, indexPath, item in

    var content = cell.defaultContentConfiguration()

    content.text = item.title
    content.image = item.image

    cell.contentConfiguration = content
}
```

キーポイント:
- `UICollectionViewListCell` 是 list 场景的标准 cell 类型。
- `MyItem` 是 app 自己的数据类型，session 示例里包含 title 和 image。
- `defaultContentConfiguration()` 会按当前 list/sidebar 环境返回合适的默认样式。
- 設定`cell.contentConfiguration`最後に、セルのテキスト、画像、パディングはシステム構成によって均一に管理されます。

（[10:31](https://developer.apple.com/videos/play/wwdc2020/10105/?time=631)）最后用 diffable data source 把数据源接到 collection view。它负责根据 section 和 item 生成 cell。

```swift
let dataSource = UICollectionViewDiffableDataSource<Section, MyItem>
   (collectionView: collectionView)
{ collectionView, indexPath, item in
   return collectionView.dequeueConfiguredReusableCell(using: cellRegistration,
                                                       for: indexPath,
                                                       item: item)
}
```

キーポイント:
- `Section`そして`MyItem` 描述列表的数据结构。
- closure 在 collection view 需要 cell 时被调用。
- `dequeueConfiguredReusableCell`再利用と構成を同時に完了して、再利用識別子の手動管理を回避します。
- Session は、ほとんどのリストがレイアウト、セル登録、および比較可能なデータ ソースの組み合わせに従うことを強調しています。

（[11:29](https://developer.apple.com/videos/play/wwdc2020/10105/?time=689)）如果 supplementary 列展示的是内容列表，而不是导航入口，Human Interface Guidelines 建议用 `sidebarPlain`。

```swift
let configuration = UICollectionLayoutListConfiguration(appearance: .sidebarPlain)
let layout = UICollectionViewCompositionalLayout.list(using: configuration)
let collectionView = UICollectionView(frame: frame, collectionViewLayout: layout)
```

キーポイント:
- `.sidebarPlain`フォルダー アイテム、コレクション アイテム、メーリング リストなどのコンテンツ リストに適しています。
- session 里提到它会呈现白色背景、分隔线和更偏内容的视觉处理。
- primary column 常用 `.sidebar`，supplementary column 常见 `.sidebarPlain`。

### 大文字と小文字の文字列の構造と状態をまとめたショートカット

（[15:35](https://developer.apple.com/videos/play/wwdc2020/10105/?time=935)）Shortcuts 的 regular width 版本用 double column split view。左侧 sidebar 负责导航，用户选中项目后，右侧显示 detail。

```swift
let splitViewController = UISplitViewController(style: .doubleColumn)

// Primary column

let sidebar = SidebarViewController()
splitViewController.setViewController(sidebar, for: .primary)


// Secondary column

func collectionView(_ collectionView: UICollectionView, didSelectItemAt indexPath: IndexPath) {
    splitViewController.showDetailViewController(DetailViewController(), sender: self)
}
```

キーポイント:
- `SidebarViewController`プライマリ列に入れます。
- サイドバーからイベントを選択します`UICollectionViewDelegate`の`didSelectItemAt`。
- `showDetailViewController` 把新的 detail 放入 secondary column。
- transcript 说明 Shortcuts 会在 size class 变化时重建当前 detail，避免用户从 split view 切到 compact width 后丢失当前位置。

（[20:39](https://developer.apple.com/videos/play/wwdc2020/10105/?time=1239)）Shortcuts 的 sidebar 也是 collection view。它用 section provider 读取当前 layout environment，在 compact width 下把 header 改成 section 的第一个 item，在 regular width 下不显示 header。

```swift
let layout = UICollectionViewCompositionalLayout(sectionProvider: sectionProvider,
         configuration: UICollectionViewCompositionalLayoutConfiguration())

func sectionProvider(_ section: Int, environment: NSCollectionLayoutEnvironment)
-> NSCollectionLayoutSection {
    var configuration = UICollectionLayoutListConfiguration(appearance: .sidebar)

    if (environment.traitCollection.horizontalSizeClass == .compact) {
        configuration.headerMode = .firstItemInSection
    } else {
        configuration.headerMode = .none
    }

    return NSCollectionLayoutSection.list(using: configuration, layoutEnvironment: environment)
}
```

キーポイント:
- `sectionProvider` 让每个 section 可以根据环境生成不同布局。
- `environment.traitCollection.horizontalSizeClass`コンパクト/レギュラーの判断基準となります。
- `headerMode = .firstItemInSection` 让 compact width 里仍能表达分组。
- `NSCollectionLayoutSection.list`実際のリストセクションを返します。

### モダリティを減らすことがインタラクション レベルでの目標です

（[12:27](https://developer.apple.com/videos/play/wwdc2020/10105/?time=747)）session 还强调，iPad app 应该减少会挡住任务流的 transient UI。Notes 的 color picker 会在用户开始绘制时自动消失，Contacts 的菜单允许用户点按菜单外侧后继续用同一次触摸滚动。这里没有固定 API 配方，Apple 给出的判断标准是观察用户是否已经开始下一步操作，例如滚动、绘制或响应外部事件。

キーポイント:
- これは、iOS 14 の UIKit によって行われたシステムレベルのインタラクションの改善です。
- app 自己也应该观察滚动、绘制、 incoming events 等信号。
- 目标是让用户继续当前任务，而不是先处理关闭弹窗这一步。

## 重要ポイント

- **データベースのアプリに 3 列読み取りモードを追加**
  做什么：把「分类、列表、详情」同时放在 iPad 横屏界面里。
実行する価値がある理由: 10105 が示す`.tripleColumn` 和 supplementary column，适合邮件、笔记、知识库、文件管理这类信息层级明确的 app。
開始方法: 使用する`UISplitViewController(style: .tripleColumn)` 建根容器，把分类放 `.primary`、アイテムリストが配置されます`.supplementary`，详情放 `.secondary`。

- **把旧 tab bar 导航迁移成 collapsible sidebar**
  做什么：在 regular width 中把底部 tab bar 换成可折叠 sidebar，同时为 compact width 保留 tab bar。
実行する価値がある理由: ショートカットは、サイドバーを介してより多くのナビゲーション エントリを提供し、`.compact` 列保留小屏流程。
  怎么开始：为 split view 设置 primary sidebar view controller，再用 `setViewController(tabBarController, for: .compact)`幅の狭いバージョンもございます。

- **コレクション ビューを使用してサイドバー、コンテンツ リスト、アウトラインを統合します**
  做什么：把 iPad app 里的 table view 列表逐步替换成 collection view list。
行う価値がある理由: セッションは明らかに推奨されます`UICollectionView` 作为现代 list 方案，它能继续扩展 accessories、拖拽排序、outline 和 swipe actions。
  怎么开始：先用 `UICollectionLayoutListConfiguration(appearance: .sidebar)` 搭 primary sidebar，再接 `CellRegistration`そして`UICollectionViewDiffableDataSource`。

- **サイドバーのコンテンツ列のシンプルなルック アンド フィールを選択します**
対処方法: ナビゲーション リストとコンテンツ リストを区別し、補足列をファイル、メール、またはプロジェクト リストに近づけます。
実行する価値がある理由: セッションのヒューマン インターフェイス ガイドラインによって指定されたルールは次のとおりです: コンテンツ コレクションまたはフォルダー内のアイテムにはサイドバー プレーンを使用します。
開始方法: 補足列のコレクション ビューを作成するときに使用します。`UICollectionLayoutListConfiguration(appearance: .sidebarPlain)`。

- **主动收起挡住任务流的临时界面**
  做什么：当用户继续绘制、滚动或处理输入时，自动关闭已经完成使命的 popover、menu 或 transient control。
  为什么值得做：session 用 Notes 和 Contacts 说明，多余的 dismiss tap 会打断 iPad 上的连续操作。
  怎么开始：从 app 中最常见的 popover 或 menu 开始，找到用户下一步动作信号，在动作发生时关闭临时 UI 并让原动作继续。
