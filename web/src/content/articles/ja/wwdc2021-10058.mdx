## ハイライト

> `AsyncSequence`Swift 5.5で導入されたコアプロトコルであり、同期です`Sequence`の非同期同等物。のように`for item in sequence`同期シーケンスをたどるのと同じように、`for await item in asyncSequence`非同期的に生成された要素を反復処理することができます。

## 主な内容

存在する`async/await`以前は、一連の非同期値を処理するには、コールバック、プロキシ パターン、または Combine Publisher が必要でした。これらのアプローチにはそれぞれ独自の複雑さがあり、ネストされたコールバックは「コールバック地獄」を引き起こし、エージェントは複数のメソッドに分散しており、Combine には急な学習曲線があります。

`AsyncSequence`最も単純なものを使用する`for-await-in`ループ処理はこの問題を解決します。これにより、非同期シーケンスの処理が同期シーケンスとほぼ同じように見えます。コンパイラは舞台裏で次のように動作します。`for-await-in`ペアに変換する`makeAsyncIterator()`電話をかけ、それを繰り返します`await iterator.next()`。

システムフレームワークのAPIが多数提供されている`AsyncSequence`インタフェース。`URL.lines`テキスト ファイルは 1 行ずつ非同期で読み取ることができます。`URLSession`の`bytes(from:)`戻る`AsyncBytes`。`NotificationCenter`の`notifications(named:)`通知シーケンスを返します。`FileHandle`非同期読み取りもサポートされています。

セッションでも紹介しています`AsyncStream`そして`AsyncThrowingStream`、従来のコールバック/デリゲート パターンを次のように変換します。`AsyncSequence`橋。使用できます`AsyncStream`Timer と CLLocationManager のデリゲート コールバックをラップします。`AsyncSequence`。

### AsyncSequence のトラバース

（[04:28](https://developer.apple.com/videos/play/wwdc2021/10058/?time=268)）

```swift
for await quake in quakes {
    if quake.magnitude > 3 {
        displaySignificantEarthquake(quake)
    }
}
```

キーポイント:
- `for await`Swift 5.5 のトラバース用の新しい構文です`AsyncSequence`
- シーケンスでエラーが発生する可能性がある場合は、次を使用します。`for try await`
- `break`そして`continue`存在する`for-await-in`正常に動作しています

```swift
for try await quake in quakeDownload {
    if quake.location == nil {
        break
    }
    if quake.magnitude > 3 {
        displaySignificantEarthquake(quake)
    }
}
```

### コンパイラーが非同期反復を処理する方法

（[03:52](https://developer.apple.com/videos/play/wwdc2021/10058/?time=232)）

```swift
// 同步迭代
var iterator = quakes.makeIterator()
while let quake = iterator.next() {
    if quake.magnitude > 3 {
        displaySignificantEarthquake(quake)
    }
}

// 异步迭代
var iterator = quakes.makeAsyncIterator()
while let quake = await iterator.next() {
    if quake.magnitude > 3 {
        displaySignificantEarthquake(quake)
    }
}
```

キーポイント:
- コンパイラ`for-in`に変換`while let` + `makeIterator()` + `next()`
- コンパイラ`for await-in`に変換`while let await` + `makeAsyncIterator()` + `next()`
- 各反復がハングし、次の値の到着を待機する可能性があります

### 同時反復

```swift
    do {
        for try await quake in quakeDownload {
            updateMap(with: quake)
        }
    } catch {
        handleError(error)
    }

// 后续可以取消

iteration2.cancel()
```

キーポイント:
- バンドル`for-await-in`つける`Task`クロージャ内で複数の反復を同時に実行可能
- `Task`提供された`cancel()`メソッド、反復は外部からキャンセル可能
- 無限に実行される可能性のあるシーケンス (通知フローなど) の場合、この方法でライフ サイクルを管理できます。

### AsyncStream の使用

（[11:10](https://developer.apple.com/videos/play/wwdc2021/10058/?time=670)）

```swift
class QuakeMonitor {
    var quakeHandler: (Quake) -> Void
    func startMonitoring()
    func stopMonitoring()
}

let quakes = AsyncStream(Quake.self) { continuation in
    let monitor = QuakeMonitor()
    monitor.quakeHandler = { quake in
        continuation.yield(quake)
    }
    continuation.onTermination = { @Sendable _ in
        monitor.stopMonitoring()
    }
    monitor.startMonitoring()
}

let significantQuakes = quakes.filter { quake in
    quake.magnitude > 3
}

for await quake in significantQuakes {
    displaySignificantEarthquake(quake)
}
```

キーポイント:
- `AsyncStream`コンストラクターはクロージャーを受け入れます。`continuation`値を生成するために使用される
- `continuation.yield()`シーケンスに値をポストする
- `continuation.onTermination`リソースをクリーンアップするためにシーケンスがキャンセルされるときに呼び出されます
- `AsyncStream`一緒にいることができます`filter`、`map`他の演算子と組み合わせて使用​​する

### AsyncStream 処理エラー

エラーをスローする必要がある場合は、次を使用します`AsyncThrowingStream`：

```swift
let events = AsyncThrowingStream(Event.self) { continuation in
    let monitor = EventMonitor()
    monitor.eventHandler = { result in
        switch result {
        case .success(let event):
            continuation.yield(event)
        case .failure(let error):
            continuation.finish(throwing: error)
        }
    }
    monitor.start()
}
```

キーポイント:
- `AsyncThrowingStream`の`continuation.finish(throwing:)`エラーを報告するため
- 反復処理時に必要`for try await`
- エラーが発生するとシーケンスが終了します。`next()`コールリターン`nil`

## 重要ポイント

### 1. URL.lines を使用して大きなファイルを処理する

アプリで大きなテキスト ファイル (ログ、CSV、JSON 行) を処理する必要がある場合は、それらを一度にメモリに読み込まないでください。使用`url.lines`行ごとに処理され、メモリ使用量は一定です。

実装アイデア: 置き換える`String(contentsOfFile:)`のために`for try await line in url.lines`。ループ内で 1 行ずつ解析し、必要な情報を抽出して破棄します。

### 2. AsyncStream を使用してタイマー コールバックをラップする

伝統的`Timer.scheduledTimer`これはターゲット メソッドで処理する必要があるため、ロジックの邪魔になります。使用`AsyncStream`ラップ後、すべての時間指定イベントをループで処理できます。

実装アイデア: 作成する`AsyncStream`、存在する`Timer`コールバックで呼び出される`continuation.yield(())`。次に、使用します`for await _ in timerStream`スケジュールされたタスクを処理します。

### 3. AsyncStream を使用して、NotificationCenter コールバックをラップします。

一部の通知は、特定の条件によってトリガーする必要があります。従来の方法では、最初にオブザーバーを追加してから、コールバックで条件を判断する必要があります。使用`notifications(named:)`の`first(where:)`条件を満たす通知を直接待つことができます。

実装アイデア: 置き換える`addObserver(forName:object:queue:using:)`のために`await center.notifications(named:).first { 条件 }`。コードがよりクリーンになり、意図がより明確になります。

### 4. AsyncStream を使用してネットワーク ページングの読み込みをラップする

Web API のページ読み込みでは、多くの場合、次のページへの再帰呼び出しが必要になります。使用`AsyncStream`ページング シーケンスを線形反復に変えることができます。

実装アイデア: 作成する`AsyncStream`、非同期クロージャの最初のページをロードします。`continuation.yield`各データを返し、次のページを再帰的に読み込みます。発信者が行う必要があるのは、`for await item in paginatedStream`。

### 5. AsyncStream を使用して CoreLocation コールバックをラップする

`CLLocationManager`デリゲート コールバックは複数のメソッドに分散されます。使用`AsyncStream`位置情報の更新は均一に処理できます。

実装アイデア: 必要なイベントごとに作成`AsyncStream`（のように`didUpdateLocations`、`didFailWithError`)、デリゲート メソッドで対応するメソッドを呼び出します。`continuation.yield`。
