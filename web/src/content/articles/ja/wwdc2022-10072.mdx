## 主な内容

ヘルスケアアプリもこの問題に悩まされています。多くの健康データの視覚化があり、UIKit コードはすでに既存のモデルとナビゲーションをホストしています。Sara Frederixon 氏は冒頭で、このセッションの目標は、アプリケーション構造を書き直すことなく、既存の UIKit アプリケーションに SwiftUI を組み込むことであると説明しました ([00:18](https://developer.apple.com/videos/play/wwdc2022/10072/?time=18))。

### UIHostingController はまだ入り口です

`UIHostingController`SwiftUIを含むビュー階層です。`UIViewController`。モーダル、ポップオーバー、子ビュー コントローラーなど、ビュー コントローラーが必要な UIKit 内のどこにでも表示できます ([01:33](https://developer.apple.com/videos/play/wwdc2022/10072/?time=93))。

```swift
// Presenting a UIHostingController

let heartRateView = HeartRateView() // a SwiftUI view
let hostingController = UIHostingController(rootView: heartRateView)

// Present the hosting controller modally
self.present(hostingController, animated: true)
```

キーポイント:

- `HeartRateView()`は SwiftUI ビューであるため、UIKit は内部でどのようにレイアウトされているかを知る必要はありません。
- `UIHostingController(rootView:)`SwiftUI ビューを UIKit ビュー コントローラーにラップします。
- `present(_:animated:)`これは依然として標準の UIKit API であり、呼び出し方法は変更されていません。

ページをポップアップの代わりに埋め込む必要がある場合は、ホスティング コントローラーを子ビュー コントローラーに追加できます ([02:31](https://developer.apple.com/videos/play/wwdc2022/10072/?time=151))。

```swift
// Embedding a UIHostingController

let heartRateView = HeartRateView() // a SwiftUI view
let hostingController = UIHostingController(rootView: heartRateView)

// Add the hosting controller as a child view controller
self.addChild(hostingController)
self.view.addSubview(hostingController.view)
hostingController.didMove(toParent: self)

// Now position & size the hosting controller’s view as desired…
```

キーポイント:

- `addChild(_:)`SwiftUI ホスティング コントローラーを UIKit のビュー コントローラー階層に接続します。
- `addSubview(_:)`ホスティング ビューを現在のビューに配置することのみを担当します。
- `didMove(toParent:)`子ビュー コントローラーのライフサイクル通知を完了します。
- 最後の行は、開発者に UIKit のレイアウト メソッドを使用してこのビューを配置し、制限することを思い出させます。

iOS 16が与えるもの`UIHostingController`追加した`sizingOptions`。SwiftUI コンテンツが変更されると、ホスティング コントローラーは自動的に更新されます。`preferredContentSize`または、ビューの固有のコンテンツ サイズ。コンテンツ サイズに依存するポップオーバーなどのシナリオでは、直接的なメリットが得られます ([02:43](https://developer.apple.com/videos/play/wwdc2022/10072/?time=163))。

### 外部データは最初に値によって渡され、次に ObservableObject を使用して自動的に更新されます。

UIKit アプリケーションのデータは通常、既存のモデル レイヤーによって保持されます。SwiftUI ビューは新しく追加されたインターフェイス レイヤーであるため、`@State`そして`@StateObject`SwiftUI によって作成および所有されるこの種のデータは、ここには当てはまりません。Session は最初に最も直接的な方法を提供します。値を SwiftUI ビューに渡し、次に UIKit 側でホスティング コントローラーを手動で更新します。`rootView`（[05:06](https://developer.apple.com/videos/play/wwdc2022/10072/?time=306)）。

```swift
// Passing data to SwiftUI with manual UIHostingController updates

struct HeartRateView: View {
    var beatsPerMinute: Int

    var body: some View {
        Text("\(beatsPerMinute) BPM")
    }
}

class HeartRateViewController: UIViewController {
    let hostingController: UIHostingController< HeartRateView >
    var beatsPerMinute: Int {
        didSet { update() }
    }

    func update() {
        hostingController.rootView = HeartRateView(beatsPerMinute: beatsPerMinute)
    }
}
```

キーポイント:

- `HeartRateView`1つだけ受け取る`Int`、それ自体はデータ ソースを所有しません。
- `Text("\(beatsPerMinute) BPM")`渡された値を使用してインターフェイスを生成します。
- `beatsPerMinute`UIKitビューコントローラーに保存します。
- `didSet { update() }`UIKit 側のデータが変更された後、更新をアクティブにトリガーする必要があることを示します。
- `hostingController.rootView = ...`SwiftUI ルート ビューを再作成し、最新の値をそこに送信します。

この方法は簡単ですが、データが変更されるたびに手動で更新する必要があります。その後、セッションは既存のモデルを次のように変更することを推奨します。`ObservableObject`、変更される属性を次のようにマークします。`@Published`、そして SwiftUI ビューに使用させます`@ObservedObject`それをお読みください ([06:49](https://developer.apple.com/videos/play/wwdc2022/10072/?time=409))。

```swift
// Passing an ObservableObject to automatically update SwiftUI views

class HeartData: ObservableObject {
    @Published var beatsPerMinute: Int

    init(beatsPerMinute: Int) {
       self.beatsPerMinute = beatsPerMinute
    }
}

struct HeartRateView: View {
    @ObservedObject var data: HeartData

    var body: some View {
        Text("\(data.beatsPerMinute) BPM")
    }
}
```

キーポイント:

- `HeartData: ObservableObject`この外部モデルを SwiftUI で監視できるようにします。
- `@Published var beatsPerMinute`リフレッシュ信号をトリガーする属性です。
- `@ObservedObject var data`外部モデルを SwiftUI ビューに接続します。
- `Text("\(data.beatsPerMinute) BPM")`モデルのプロパティを直接読み取ります。
- 属性が変更された後、SwiftUI は関連するビューを自動的に更新するため、UIKit はそれを再度変更する必要はありません。`rootView`。

UIKit ビュー コントローラーを初期化するときは、同じモデルを保存して SwiftUI ビューに渡すだけです ([08:30](https://developer.apple.com/videos/play/wwdc2022/10072/?time=510))。

```swift
// Passing an ObservableObject to automatically update SwiftUI views

class HeartRateViewController: UIViewController {
    let data: HeartData
    let hostingController: UIHostingController<HeartRateView>

    init(data: HeartData) {
        self.data = data
        let heartRateView = HeartRateView(data: data)
        self.hostingController = UIHostingController(rootView: heartRateView)
    }
}
```

キーポイント:

- `data`UIKit側が保持しているものと同じです`HeartData`例。
- `HeartRateView(data: data)`モデル参照をSwiftUIに与えます。
- `UIHostingController(rootView:)`初期化中にのみ SwiftUI ビューをラップします。
- 後続の心拍数サンプルが 78 から 94 に変化すると、`@Published`SwiftUI 更新インターフェイス ([09:14](https://developer.apple.com/videos/play/wwdc2022/10072/?time=554)) を駆動します。

### UIHostingConfiguration SwiftUI をセルに配置します

iOS 16の新機能`UIHostingConfiguration`、セルの内容の構成です。開発者はそれを次のように割り当てます。`UICollectionViewCell`または`UITableViewCell`の`contentConfiguration`, セルに直接 SwiftUI を記述することができます。ここに追加のビューやビュー コントローラーを埋め込む必要はありません ([09:52](https://developer.apple.com/videos/play/wwdc2022/10072/?time=592))。

```swift
cell.contentConfiguration = UIHostingConfiguration {
  // Start writing SwiftUI here!
}
```

キーポイント:

- `contentConfiguration`これは、UIKit セルの最新の構成エントリ ポイントです。
- `UIHostingConfiguration { ... }`SwiftUIを受信する`ViewBuilder`。
- SwiftUI ビューを中括弧内に直接記述します。

このセッションでは心拍数セルを使用して、移行の利点を示します。元の複雑なカスタム セル レイアウトは、いくつかの SwiftUI の小さなビューに分割できます ([11:02](https://developer.apple.com/videos/play/wwdc2022/10072/?time=662))。

```swift
// Building a custom cell using SwiftUI with UIHostingConfiguration

cell.contentConfiguration = UIHostingConfiguration {
    HeartRateTitleView()
}

struct HeartRateTitleView: View {
    var body: some View {
        HStack {
            Label("Heart Rate", systemImage: "heart.fill")
                .foregroundStyle(.pink)
                .font(.system(.subheadline, weight: .bold))
            Spacer()
            Text(Date(), style: .time)
                .foregroundStyle(.secondary)
                .font(.footnote)
        }
    }
}
```

キーポイント:

- `HeartRateTitleView()`入れられる`UIHostingConfiguration`, セルの内容になります。
- `Label("Heart Rate", systemImage:)`タイトルとシステムアイコンを表示します。
- `.foregroundStyle(.pink)`そして`.font(...)`標準の SwiftUI モディファイアを使用してスタイルを調整します。
- `Spacer()`左にタイトルを押し、右に時間を押します。
- `Text(Date(), style: .time)`SwiftUIの日付テキストを使用して現在時刻を表示します。

拡張し続ける場合は構成で組み合わせるだけ`VStack`、`HStack`およびその他の SwiftUI ビュー。セッションには Swift チャートも配置されます`Chart`セルに入れて使用します`LineMark`心拍数曲線を表示します ([13:25](https://developer.apple.com/videos/play/wwdc2022/10072/?time=805))。

### diffable データ ソースはコレクションのみを変更します。ObservableObject はセル内の更新を担当します。

コレクション ビューまたはテーブル ビューのセルが SwiftUI で構築される場合、データ フローは 2 つのカテゴリで処理されます。最初のカテゴリは、挿入、削除、再配置などのコレクションの変更です。引き続き diffable データ ソース スナップショット処理を使用します。各スナップショットは次の場所に配置する必要があります。`MedicalCondition`これにより、diffable データ ソースが ID を正確に計算できるようになります ([18:41](https://developer.apple.com/videos/play/wwdc2022/10072/?time=1121))。

2 番目のカテゴリは、単一モデルの属性変更です。従来の UIKit メソッドでは通常、スナップショット内の項目を再構成または再ロードする必要があります。SwiftUIセルを使用する場合、次のようにモデルを作成できます。`ObservableObject`、SwiftUIビューで使用させます`@ObservedObject`観察してください。`@Published`属性が変更された後、セル内の SwiftUI ビューは、最初に diffable データ ソースまたはコレクション ビューを経由せずに直接更新されます ([20:35](https://developer.apple.com/videos/play/wwdc2022/10072/?time=1235))。

iOS 16 ではサイズの問題も修正されています。`UIHostingConfiguration`UIKit の新しい自動サイズ変更セルを利用します。SwiftUI セルの内容が変更されると、それを含むセルが変更されます。`UICollectionViewCell`または`UITableViewCell`サイズは必要に応じて自動的に調整されます。この機能はデフォルトで有効になっています ([21:44](https://developer.apple.com/videos/play/wwdc2022/10072/?time=1304))。

最後に、SwiftUI はデータをモデルに書き戻すこともできます。セッション用`MedicalCondition`例: モデルは`ObservableObject`，`text`はい`@Published`。SwiftUI ビューは、この公開された属性の双方向バインディングを作成でき、ユーザーは編集後にそれをモデルに直接書き戻すことができます ([22:48](https://developer.apple.com/videos/play/wwdc2022/10072/?time=1368))。

```swift
// Creating a two-way binding to data in SwiftUI

class MedicalCondition: Identifiable, ObservableObject {
    let id: UUID

    @Published var text: String
}

struct MedicalConditionView: View {
    @ObservedObject var condition: MedicalCondition

    var body: some View {
        HStack {

            Spacer()
        }
    }
}
```

キーポイント:

- `MedicalCondition: Identifiable`diff 可能なデータ ソースが使用できる安定した ID を提供します。
- `ObservableObject`このモデルを SwiftUI で監視できるようにします。
- `@Published var text`SwiftUI で読み取ってインターフェースを更新できるプロパティです。
- `@ObservedObject var condition`セルに対応するモデルをSwiftUIビューに接続します。
- 逐語的な説明、読み取り専用にする`Text`に変更します`TextField`、そして与える`condition.text`追加`$`プレフィックスを追加すると、モデルに書き戻すバインディングを作成できます ([23:47](https://developer.apple.com/videos/play/wwdc2022/10072/?time=1427))。

### 2 つのベアラー モード間の境界

セッションの終わりには、簡単にステップできる境界線が提供されます。`UIHostingController`ビューコントローラーです。これを使用する場合、ビュー コントローラーとそのビューを UIKit 階層に追加する必要があります。ツールバー、キーボード ショートカット、使用法`UIViewControllerRepresentable`SwiftUI ビューはすべて、UIKit ビュー コントローラー階層 ([24:33](https://developer.apple.com/videos/play/wwdc2022/10072/?time=1473)) に依存しています。

`UIHostingConfiguration`セルに使用されますが、作成されません`UIViewController`。ほとんどの SwiftUI 機能をサポートしていますが、次のものに依存します。`UIViewControllerRepresentable`SwiftUI ビューはセルに配置できません ([25:01](https://developer.apple.com/videos/play/wwdc2022/10072/?time=1501))。

## 重要ポイント

- **何をすべきか**: 複雑な UIKit カスタム セルを次のように変更します。`UIHostingConfiguration`。
**実行する価値がある理由**: セルの内部レイアウトを SwiftUI の小さなビューに分割できるため、スタイル、グラフ、ステータス表示を簡単に組み合わせることができます。
**開始方法**: 既存のコレクション ビューまたはテーブル ビューを保持し、セルの置換のみを行います。`contentConfiguration`。

- **何をすべきか**: 既存の UIKit 詳細ページの部分カードを SwiftUI に変更します。
**実行する価値がある理由**:`UIHostingController`ページ全体を置き換える必要がなく、子ビュー コントローラーとして埋め込むことができます。
**開始方法**: 次を使用して SwiftUI カード ビューを作成します。`UIHostingController(rootView:)`運ぶ、渡す`addChild`既存のビューコントローラーに接続します。

- **内容**: UIKit モデルへの変更により、SwiftUI の部分的なインターフェイスの更新が自動的に行われるようにします。
**実行する価値がある理由**: 手動変更`rootView`見逃しやすい、`ObservableObject`そして`@Published`更新をデータ変更にバインドする機能。
**開始方法**: 既存のモデルを`ObservableObject`、SwiftUI ビューで使用されます`@ObservedObject`保存してください。

- **何をすべきか**: SwiftUI のスワイプ アクションをリスト セルに追加します。
**実行する価値がある理由**: リストのインタラクションは引き続き UIKit によって管理され、インライン アクションは SwiftUI 修飾子を使用してコンテンツの近くに記述できます。
**開始方法**:`UIHostingConfiguration`ルートの SwiftUI ビューに追加する`.swipeActions`、アクション内のアイテムの安定した ID を使用します。

- **何をすべきか**: 編集可能なセルの双方向データ フローを確立します。
**実行する価値がある理由**: SwiftUI のユーザー`TextField`入力後、引き続きUIKit側で使用するモデルオブジェクトを直接書き戻すことができます。
**開始方法**: モデルの編集可能なフィールドに使用させます`@Published`、SwiftUIで渡されます`$condition.text`入力コントロールに渡されます。
