## ハイライト

> Apple は Siri の音声体験を System Intents、custom intents、Shortcuts、Suggestions、Automations、silent/voice モードに分解し、どの App 機能が音声に適するか、会話文案をどう書くかの設計指針を示します。

## 主要内容

多くの App では核心タスクが UI の数層の奥に隠れています。新規ユーザーはメニューと階層で機能を理解する必要がありますが、熟練ユーザーはよく1つのことを直接完了したいだけです。アーティストの新アルバムを再生する、いつものスープを注文する、目立たない設定を開く。これらの動作をそのまま音声に持ち込み、フォーム項目を1つずつ答わせると体験は遅くなります。

このセッションの切り口は Siri の設計境界です。Apple はまず Siri を Voice、Touch、Automation すべてで使えるシステム能力と定義し、開発者が統合できる部分を Intents、Shortcuts、Suggestions、Automations に分けます。System Intents にはシステムが書いた自然言語フローが既にあります。custom intents では開発者自身がタスク手順、必要情報、質問順序、失敗フィードバックを整理する必要があります。

本当に音声に適した機能には共通点があります。手順が多い、繰り返しが頻繁、ユーザーの目標が明確、またはユーザーが運転中、歩行中、AirPods 着用で App を開きにくい。音声の価値は、既に慣れた UI 階層を飛ばして目標動作に直接到達することです。

Apple は silent mode と voice mode の両方を設計するよう開発者に促します。iOS 14 では iPhone の着信音スイッチがミュートのとき、Siri はデフォルトで話さず、画面上の UI と文字会話でタスク情報を提示します。custom intents では画面を見ているときと見ていないときで別々の対話と UI を指定する必要があります。

## 詳細

### Siri は入口の集合（[00:32](https://developer.apple.com/videos/play/wwdc2020/10071/?time=32)）

セッションは Siri Human Interface Guidelines の定義を引用します。Siri は Voice、Touch、Automation で日常タスクを素早く完了するのを助けます。講者は続けて音声体験を assistant、Intents、Shortcuts、Suggestions、Automations に分解します。開発者がやることは、どの App 機能がシステムレベルの入口に入れるかを判断することです。

キーポイント:
- Voice は Siri の1モダリティに過ぎず、同じタスクは音声、タッチ、自動化ですべて利用可能であるべきです。
- Intents は開発者と Siri の共通言語で、「メッセージ送信」「コーヒー注文」などのタスクに何の情報が必要かを記述します。
- Shortcuts、Suggestions、Automations は App 動作をユーザーの日常パスに持ち込みます。

### まず System Intents と custom intents を判断する（[01:45](https://developer.apple.com/videos/play/wwdc2020/10071/?time=105)）

System Intents は一部の一般的 domain をカバーします。メッセージ送信では、システムは受信者と本文を集め、リクエスト完了に必要な会話フローを既に持っています。開発者は自分のデータを接続し、システム会話に入れたとき自然に読めるか、エラーや非対応が Siri のフィードバックにマップできるかを確認します。

custom intents はシステム domain がカバーしないタスク向けです。セッションは「コーヒー注文」を例にします。App チームがビジネスを最もよく知るので、会話フローを自分で定義します。まず3つ答えます。ユーザーが完了するのに何ステップ必要か、各ステップで何の情報が必要か、どの順序で尋ねるか。

キーポイント:
- System Intents が使えるときは、システムの自然言語能力と会話フローを優先します。
- custom intents では設計は「1つのコマンドを書く」から「タスクを完了する会話を書く」に変わります。
- エラー分岐は別途設計が必要。情報不足、非対応コンテンツ、App が完了できない、をユーザーが知る必要があります。

### Shortcuts は動作の出現位置を広げる（[03:49](https://developer.apple.com/videos/play/wwdc2020/10071/?time=229)）

Shortcuts は複数能力の総称です。ユーザーは Shortcuts app でプリセット動作を見つけ、自分の routine を作り、動作を他人と共有できます。Siri Suggestions は少なくとも1回実行した動作を提案したり、過去の行動から未実行の動作を提案したりします。

Automations は時間、位置、特定イベントなどの条件でデバイス上や Home 環境で動作を実行します。Voice は custom intents で App を開かずにタスクを完了させ、App 動作を自動化に加えます。

キーポイント:
- Shortcuts は単一入口ではなく、Suggestions、Shortcuts app、Automations、Voice を含みます。
- 動作は Shortcut になって初めて、ユーザーが組んだ routine に載れます。
- 音声入口は「今すぐ完了」タスク向き、自動化は「条件を満たしたら実行」向きです。

### 音声に適した機能を選ぶ（[05:21](https://developer.apple.com/videos/play/wwdc2020/10071/?time=321)）

講者は明確に、Voice はフォーム入力だけではいけないと述べます。良い音声タスクは通常、多段階で頻繁なインタラクションを簡略化します。音楽の例では、App を開いてアーティストを検索し、新アルバムを見つけて再生をタップする必要はなく、「DaBaby の最新アルバムを再生」と言えば App が目標を解釈して実行します。

Soup Chef の例は一般 App に近いです。新規ユーザーはメニューを読む必要がありますが、常連はトマトビスクを知っています。音声は常連がメニューを飛ばして直接注文できます。講者は、メイン画面にない高度な機能も音声向きだと述べます。パワーユーザーはより速い経路を求めるからです。

キーポイント:
- 音声向き動作は通常、高頻度で明確、繰り返し可能なタスクです。
- 音声は既に慣れたナビゲーション階層を迂回できます。
- 運転、歩行、AirPods シーンは音声入口の価値を増幅します。

### silent mode と voice mode を分けて設計する（[07:16](https://developer.apple.com/videos/play/wwdc2020/10071/?time=436)）

iOS 14 では iPhone の着信音スイッチがミュートのとき、Siri はデフォルトで silent mode に入ります。Siri は話さず、画面上の UI と文字会話がタスク情報を提示します。voice mode は利用可能な画面に UI を表示し続けながら、タスク完了に必要な情報を話します。

System Intents はこれらのモードを既に処理します。custom intents では、画面を見ているときと見ていないときの対話と UI を開発者が指定する必要があります。Siri は適切なタイミングで該当ピースを使います。

キーポイント:
- 同じ intent は画面の有無で同じ表現に頼れません。
- 画面が見えるとき、文字と UI が詳細を担えます。
- 画面なしや voice mode では、話す対話は短くしつつ完了に必要な情報は残します。

### 会話文案は話し言葉のように（[08:32](https://developer.apple.com/videos/play/wwdc2020/10071/?time=512)）

Siri チームは適切な場面で話す内容を減らします。設定変更の初回リクエストでは Siri はより多くの情報を出せます。以降はユーザーがフローを知っているので同じ説明は不要です。Attribution も同様です。custom intent が良く、ユーザーが shortcut を頻繁に使えば、Siri は情報源の繰り返し説明を止めます。

責任は開発者に戻ります。custom intent の対話は自然である必要があります。セッションのルールは明快です。ユーザーに追加情報を求めるときは質問を使う。業界用語を避ける。書き言葉ではなく話し言葉で書く。短くする。ユーザーは長い音声を覚えにくいからです。

キーポイント:
- 質問は明確な対話マーカーで、ここで回答が必要だと伝えます。
- 行話はユーザーに考えさせ、音声シーンでは特にリズムを損ないます。
- 慣れた後の短い対話はタスク状態を保ち、繰り返し説明だけ減らします。

## 重要ポイント

### 1. 高頻度動作を Siri に直結する

**何をするか**：ユーザーがよく繰り返す動作を Siri intent で起動可能にする。例：いつもの注文、常用設定、固定再生タスク。

**なぜ価値があるか**：セッションの音楽と Soup Chef の例は、音声が熟練ユーザーに多層 UI を飛ばして明確な目標を完了させるのに最適だと示す。

**始め方**：ログから繰り返し率高く、パラメータが少なく、失敗説明が容易な動作を探す。System Intent が合えばシステム domain を使う。なければ custom intents で質問順序と確認文案を明確に書く。

### 2. custom intent に二重モダリティ応答を用意する

**何をするか**：各 custom intent に silent mode と voice mode の応答戦略を用意する。

**なぜ価値があるか**：iOS 14 はミュートスイッチで Siri がデフォルトで話さなくなる。画面を見るかどうかで必要な情報密度が異なる。

**始め方**：各 intent の結果を「話す必要がある情報」と「UI に表示できる情報」に分ける。voice mode は完了と確認に必要な短い文だけ残し、silent mode は UI で詳細を補う。

### 3. Shortcuts でユーザーの routine を受け止める

**何をするか**：App の繰り返し可能な動作を Shortcuts app に入れ、ユーザーが個人フローと Automations に追加できるようにする。

**なぜ価値があるか**：セッションは Shortcuts を Suggestions、Shortcuts app、Automations、Voice の集合と見なす。動作はこの体系に入って初めてより多くのシステム入口に現れる。

**始め方**：組み合わせに適した動作を選び、パラメータ名を明確にし、Shortcuts app の動作説明を確認して、何をするか、どんな入力が必要かをユーザーが知れるようにする。

### 4. 音声入口向け会話レビュー表を作る

**何をするか**：Siri 統合を出荷する前に、質問文、エラー文、確認文、成功文を表で1行ずつレビューする。

**なぜ価値があるか**：セッションは自然な会話を具体ルールに還元する。回答が必要なら質問、用語回避、口語、長さ制御。

**始め方**：各 custom intent の happy path と error path を実際の会話として書く。各行で行話、過長、次に何をすべきか分かるかを確認する。
