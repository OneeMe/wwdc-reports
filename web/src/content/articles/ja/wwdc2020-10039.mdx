## ハイライト

> SwiftUI の `DocumentGroup` を使用すると、アプリはシーンを使用してドキュメントのオープンと管理の機能を宣言でき、システムはドキュメント ブラウザ、標準のドキュメント コマンド、macOS のステータス追跡とハンドオフ、iOS ドキュメントの閲覧と共有インターフェイスを提供します。

---

## 主な内容

ユーザーは、タグ、クラウド ファイル プロバイダー、外部ストレージ デバイスを使用して、Finder アプリとファイル アプリでファイルを整理します。ファイルを開くとき、ユーザーはアプリが元のドキュメントを直接編集することを期待します。アプリがファイルを独自のデータベースにインポートするだけの場合、ユーザーはコピーを変更することになりますが、元のファイルはそれに応じて変更されません。

このような機能は、プロのクリエイティブ ツールに限定されたものではありません。 Pixelmator、Keynote、Final Cut Pro の主な仕事はドキュメント管理を中心に展開しています。 Xcode、Mail、および Console では、メイン インターフェイスの外でプロジェクト、EML ファイル、またはクラッシュ レポートも開きます。重要な点は、ファイルをアプリのプライベート データに飲み込むのではなく、ファイル自体を開いて編集することです。

SwiftUI は、この機能を `DocumentGroup` に組み込みます。アプリは依然としてアプリ、シーン、ビューで構成されています。 Scene が `DocumentGroup` に置き換えられると、このアプリが特定の種類のドキュメントを開いて管理することをサポートすると宣言することになります。次に、SwiftUI は、macOS のステータス追跡やハンドオフ、iOS のドキュメント ブラウザ、ナビゲーション バーの検索、共有ポータルなどのプラットフォーム動作を追加します。

デモは、iPad Playground での描画プロトタイプから始まります。 Tina はそれを ShapeEdit というマルチプラットフォーム アプリに組み込み、最初にシステムが認識できるドキュメント タイプを設定し、次にドキュメント モデルに `FileDocument` を実装させ、最後にデフォルトの `TextEditor` をキャンバスに置き換えました。最終的には、描画アプリを使用して描画を保存し、後で再度開くことができるようになります。

##詳細

### DocumentGroup はドキュメント管理を Scene に接続します

([02:00](https://developer.apple.com/videos/play/wwdc2020/10039/?time=120)) SwiftUI アプリケーションは、App、Scene、View で構成されます。ドキュメント サポートを追加する場合、新しいシーン タイプは `DocumentGroup` になります。アプリのシーンとして単独で使用することも、同じアプリ内の複数の `DocumentGroup` または `WindowGroup` と組み合わせて使用​​することもできます。

([02:12](https://developer.apple.com/videos/play/wwdc2020/10039/?time=132)) 公式の「コード」タブの最小限の例はテキストエディタです。```swift
@main
struct TextEdit: App {
    var body: some Scene {
        DocumentGroup(newDocument: TextDocument()) { file in
            TextEditor(text: file.$document.text)
        }
    }
}
```キーポイント:

- `@main` はアプリの入り口をマークし、`body` はシーンを返します。
- `DocumentGroup(newDocument: TextDocument())` は、新しいドキュメントを作成するときに使用されるベースドキュメントを宣言します。
- `file` は、`DocumentGroup` クロージャによって渡されるファイル コンテキストです。
- `file.$document.text` は読み書きバインディングを提供し、`TextEditor` はドキュメント内のテキストを直接編集できます。
- トランスクリプトは、06:49 で、このバインディングによりテキストが更新されたことを SwiftUI に知らせ、元に戻すことを登録し、ドキュメントをダーティ状態にマークする責任があると説明しています。

### ドキュメント タイプにより、まずシステムがファイルを認識します。

([04:43](https://developer.apple.com/videos/play/wwdc2020/10039/?time=283)) Xcode のドキュメント アプリ テンプレートは、Document Type を Info.plist に追加します。内部の識別子はUniform Type Identifierで、システムがディスク上のファイルをアプリに関連付けるために使用します。

([05:07](https://developer.apple.com/videos/play/wwdc2020/10039/?time=307)) プレーンテキスト このタイプの型は他の場所で宣言されており、アプリはそれをインポートするだけで済みます。 ShapeEdit は独自の描画形式を定義する必要があるため、エクスポートされたタイプ識別子を入力する必要があります。形式の説明を記述し、公開データおよび公開コンテンツに準拠させてから、ファイル拡張子を割り当てます。

([08:24](https://developer.apple.com/videos/play/wwdc2020/10039/?time=504)) トランスクリプトでは、「importedAs」と「exportedAs」を明確に区別します。インポートされた型は、インストールされているアプリによって値が変わる可能性があるため、計算変数です。エクスポートされた型は現在のアプリによって所有され、定数として宣言できます。

### FileDocument はディスク上のドキュメントを定義します

([07:41](https://developer.apple.com/videos/play/wwdc2020/10039/?time=461)) ShapeEdit のドキュメント タイプは値タイプであり、「FileDocument」プロトコルに準拠します。このプロトコルはディスク上のドキュメントを表します。最初のステップは、「UTType」の配列である「readableContentTypes」を定義することです。 SwiftUI はこの配列を使用して、ユーザーが開こうとしているファイルの種類がアプリでサポートされているかどうかを判断します。

([09:11](https://developer.apple.com/videos/play/wwdc2020/10039/?time=551)) ドキュメントを読み取るとき、初期化メソッドは `FileWrapper` と `contentType` を取得します。デモではテンプレートコードを削除した上で「JSONDecoder」を使用しているため、ドキュメントタイプは「Codable」に準拠する必要があります。

([09:43](https://developer.apple.com/videos/play/wwdc2020/10039/?time=583)) ドキュメントを書き出すとき、メソッドはターゲットの `FileWrapper` と `contentType` も受け取ります。 `FileWrapper` は inout パラメータで、新しいラッパーを作成したり、既存のラッパーを更新したりできます。デモでは「JSONEncoder」を使用してドキュメントをファイルに書き戻します。

([10:12](https://developer.apple.com/videos/play/wwdc2020/10039/?time=612)) ドキュメント モデルは構造体であるため、値型のコピーオンライト動作は保持されます。トランスクリプトによって得られる実際の利点は、ユーザーがまだ描画している間に、アプリがすでに保存を開始できることです。

### テキスト テンプレートから描画ドキュメントに切り替える

([10:32](https://developer.apple.com/videos/play/wwdc2020/10039/?time=632)) ドキュメント サポートの準備ができたら、プレイグラウンドのキャンバス コードをプロジェクトに追加するデモを行います。プロジェクトにはグラフィック プロパティを記述するグラフィック タイプと、グラフィックを表示するキャンバス ビューがあります。

([10:56](https://developer.apple.com/videos/play/wwdc2020/10039/?time=656)) 次に、ドキュメントのデータ型をテキストからグラフィック型に変更し、初期グラフィックを追加して、「TextEditor」をキャンバスに置き換えます。最後に ShapeEdit を実行すると図面を保存でき、後で同じ図面を開くことができます。

## 重要なポイント

- **テキストドキュメントエディタ**

  **内容**: 生のテキスト ファイルを開く軽量エディタを作成します。
  **実行する価値がある理由**: `DocumentGroup` はすでにドキュメントを開いて管理する処理を行っており、`TextEditor` は `file.$document.text` に直接バインドできます。
  **開始方法**: まず、公式スニペットを使用して `DocumentGroup(newDocument:)` を実行し、次にドキュメント タイプを `FileDocument` に準拠させ、読み取り可能なタイプを `readableContentTypes` に置きます。

- **描画またはホワイトボード アプリ**

  **やるべきこと**: iPad Playground の描画プロトタイプを、ファイルを保存できるマルチプラットフォーム アプリに移行します。
  **実行する価値がある理由**: セッションの ShapeEdit デモは、キャンバスのプロトタイプから始まり、図面を保存して再度開くことで終了します。
  **開始方法**: まずグラフィック タイプと Canvas View を定義し、次にドキュメント データをテキストからグラフィック タイプに変更し、`JSONDecoder` と `JSONEncoder` を使用して読み取りおよび書き込みレイヤーを処理します。

- **ログまたはクラッシュ レポート ビューアー**

  **何をすべきか**: EML、クラッシュ レポート、またはログ ファイルを開くためのエントリを共通ツール アプリに追加します。
  **実行する価値がある理由**: トランスクリプトでは、メールとコンソールのメイン インターフェイスがドキュメント ベースではないことを明確に述べていますが、それでも追加のファイルを開くことはサポートされています。
  **開始方法**: 元の `WindowGroup` を保持し、それを `DocumentGroup` と組み合わせて、ファイルを開くシナリオを特別に処理します。

- **カスタム形式のプロジェクト ファイル**

  **何をすべきか**: デザインドラフト、エンジニアリング構成、または創造的なプロジェクト用に独自のファイル形式を定義します。
  **実行する価値がある理由**: システムでは、UTI がディスク ファイルをアプリに関連付ける必要があります。 ShapeEdit は、エクスポートされたタイプ識別子を通じて独自の形式を宣言します。
  **開始方法**: Info.plist のドキュメント タイプとエクスポートされたタイプ識別子で同じタイプ識別子を使用し、タイプをパブリック データおよびパブリック コンテンツに準拠させ、拡張子を割り当てます。
