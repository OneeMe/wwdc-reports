## Highlight

> 以前 Visual Intelligence 基本是系统级特权，第三方开发者只能在旁边看着。现在 Apple 把 `SemanticContentDescriptor` 和 `IntentValueQuery` 打通了——系统把用户框选的图像转成 `pixelBuffer` 直接喂给你的 App，你在本地用 Vision 框架跑图像相似度匹配，然后通过 `@UnionValue` 把多种业务实体混排返回。电商、媒体、票务类 App 相当于在系统相机和截图界面开了一个免唤醒的超级流量入口。

---

## 核心内容

### 1. 这场演讲解决什么问题

Visual Intelligence 让用户可以通过相机或截图"看图搜内容"。以前这是系统专属能力（识别植物、查商品价格），第三方 App 无法参与。今年 Apple 开放了这个能力：

- 用户框选图像 → 系统转成 `SemanticContentDescriptor` → 传给第三方 App
- App 在本地处理图像 → 返回匹配结果 → 系统展示在 Visual Intelligence 界面中
- 用户可以直接点击结果进入 App，或者执行操作（如添加到日历）

这对电商、媒体、票务等内容驱动型 App 来说，相当于在系统级入口开了一个免唤醒的流量通道。

### 2. 定义 App Entity

第一步是定义你要返回的内容类型。用 App Intents 框架的 `AppEntity`：

```swift
import AppIntents

struct AlbumEntity: AppEntity {
    var id: String
    @Property var name: String
    @Property var artistName: String
    var coverArtData: Data

    var displayRepresentation: DisplayRepresentation {
        DisplayRepresentation(
            title: "\(name)",
            subtitle: "\(artistName)",
            image: .init(data: coverArtData)
        )
    }

    static let defaultQuery = AlbumEntityQuery()
    static var typeDisplayRepresentation: TypeDisplayRepresentation { "Album" }
}

struct AlbumEntityQuery: EntityQuery {
    @Dependency var catalog: AlbumCatalog
    func entities(for identifiers: [String]) async throws -> [AlbumEntity] {
        catalog.albums(for: identifiers)
    }
}
```

关键点：

- `DisplayRepresentation` 决定结果在 Visual Intelligence 界面中的展示方式，只有约三行文本空间。
- 缩略图不要用原图，准备 200x200 级别的 thumbnail，否则滚动时会掉帧。
- `defaultQuery` 是必需的，系统通过它获取实体详情。

### 3. 实现 IntentValueQuery

`IntentValueQuery` 是 Visual Intelligence 和你的 App 之间的桥梁。系统把图像数据传进来，你返回匹配结果：

```swift
import AppIntents
import VisualIntelligence

struct SearchHandler: IntentValueQuery {
    @Dependency var catalog: AlbumCatalog
    @Dependency var concertFinder: ConcertFinder

    func values(for input: SemanticContentDescriptor) async throws -> [VisualSearchResult] {
        guard let pixelBuffer = input.pixelBuffer else {
            return []
        }

        let albums = try await catalog.search(matching: pixelBuffer)
        return albums.map { VisualSearchResult.album($0) }
    }
}
```

关键点：

- `SemanticContentDescriptor` 包含用户框选区域的像素数据。
- 处理必须在本地完成，网络 IO 来不及响应 Visual Intelligence 的实时交互。
- 返回 `VisualSearchResult` 数组，系统负责渲染结果卡片。

### 4. 用 Feature Print 做本地图像匹配

视觉相似度匹配的核心是 Vision 框架的 `GenerateImageFeaturePrintRequest`：

```swift
import Vision

@Observable
class AlbumCatalog {
    static let shared = AlbumCatalog()

    struct CatalogEntry: Sendable {
        let album: AlbumEntity
        let featurePrint: FeaturePrintObservation
    }

    private(set) var entries: [CatalogEntry] = []

    private func generateFeaturePrint(for image: CGImage) async throws -> FeaturePrintObservation {
        let request = GenerateImageFeaturePrintRequest()
        let result = try await request.perform(on: image)
        return result
    }
}
```

搜索时计算查询图像和目录中每张专辑的距离：

```swift
func search(matching pixelBuffer: CVReadOnlyPixelBuffer, limit: Int = 10, maxDistance: Double = 1.0) async throws -> [AlbumEntity] {
    var cgImage: CGImage?
    _ = pixelBuffer.withUnsafeBuffer { VTCreateCGImageFromCVPixelBuffer($0, options: nil, imageOut: &cgImage) }
    guard let cgImage else { return [] }

    let queryPrint = try await generateFeaturePrint(for: cgImage)

    return try entries.compactMap { entry -> (album: AlbumEntity, distance: Double)? in
        let distance = try queryPrint.distance(to: entry.featurePrint)
        guard distance <= maxDistance else { return nil }
        return (entry.album, distance)
    }
    .sorted { $0.distance < $1.distance }
    .prefix(limit)
    .map { $0.album }
}
```

关键点：

- `FeaturePrintObservation` 是图像的特征向量，比直接存储图像小得多。
- `distance(to:)` 计算两个特征向量的距离，值越小越相似。
- `maxDistance` 过滤掉不相关的结果，避免返回"硬凑"的匹配。
- 特征向量应该预计算并持久化，不要每次搜索时重新生成。

### 5. 返回多种结果类型（UnionValue）

一个图像可能匹配多种内容。比如专辑封面可能同时匹配专辑和 upcoming concert：

```swift
@UnionValue
enum VisualSearchResult {
    case album(AlbumEntity)
    case concert(ConcertEntity)
}
```

扩展 Query 返回混排结果：

```swift
struct SearchHandler: IntentValueQuery {
    @Dependency var catalog: AlbumCatalog
    @Dependency var concertFinder: ConcertFinder

    func values(for input: SemanticContentDescriptor) async throws -> [VisualSearchResult] {
        guard let pixelBuffer = input.pixelBuffer else { return [] }

        let albums = try await catalog.search(matching: pixelBuffer)
        let artists = albums.map { $0.artistName }
        let concerts = await concertFinder.findNearby(byArtists: artists)

        return albums.map { VisualSearchResult.album($0) }
            + concerts.map { VisualSearchResult.concert($0) }
    }
}
```

关键点：

- `@UnionValue` 让系统知道你的结果可能包含多种类型。
- 每种类型需要对应一个 `OpenIntent`，让用户点击后能进入正确的页面。
- 混排结果按相关性排序，不要把所有类型堆在一起没有优先级。

### 6. Open Intent 让用户直达正确页面

用户点击搜索结果后，需要打开 App 的对应页面：

```swift
import AppIntents

struct OpenAlbumIntent: OpenIntent {
    static let title: LocalizedStringResource = "Open Album"

    @Parameter(title: "Album")
    var target: AlbumEntity

    @Dependency var appState: AppState

    func perform() async throws -> some IntentResult {
        await appState.openAlbum(id: target.id)
        return .result()
    }
}
```

关键点：

- `OpenIntent` 的执行环境很特殊——它在 App 被唤起并进入前台的过程中运行。
- 不要在 `perform()` 里做重度初始化或弹复杂的 Modal。
- 直接修改全局的 `AppState` 或路由栈，让 UI 层自己去响应状态变化。

### 7. 接入系统数据存储（Calendar 示例）

Visual Intelligence 提取的信息可以写入系统存储，你的 App 自动读取：

```swift
import EventKit

@Observable
class UpcomingConcertManager {
    private let eventStore = EKEventStore()
    var upcomingConcerts: [EKEvent] = []

    func requestAccessAndFetch() async throws {
        let granted = try await eventStore.requestFullAccessToEvents()
        guard granted else { return }
        await fetchUpcomingConcerts()

        // 监听日历变化
        for await _ in NotificationCenter.default.notifications(named: .EKEventStoreChanged) {
            await fetchUpcomingConcerts()
        }
    }

    func fetchUpcomingConcerts() async {
        let predicate = eventStore.predicateForEvents(
            withStart: .now,
            end: .now.addingTimeInterval(90 * 24 * 60 * 60),
            calendars: nil
        )

        let events = eventStore.events(matching: predicate)
        upcomingConcerts = events.filter { event in
            AlbumCatalog.shared.entries.contains { entry in
                event.title?.localizedCaseInsensitiveContains(entry.album.artistName) == true
            }
        }
    }
}
```

关键点：

- 用户用 Visual Intelligence 把演唱会信息添加到日历后，你的 App 通过 `EKEventStore` 自动读取。
- 监听 `EKEventStoreChanged` 通知，保持数据同步。
- 这种"系统存储作为桥梁"的模式也适用于 Contacts、Reminders 等。

## 最佳实践

- **已有项目迁移**：不要试图把后端的图像识别 API 直接包装成 App Intent。Visual Intelligence 要求毫秒级响应，网络 IO 根本来不及。把核心商品或内容的 Feature Print 随业务数据一起下发，在 App 启动或后台刷新时预计算并持久化到本地 SQLite 或 Core Data 中。

- **新项目采用**：`DisplayRepresentation` 里的缩略图千万不要用原图 URL。系统结果页是双列卡片布局，加载 2MB 的高清封面只会让滚动掉帧。专门准备一套 200x200 级别的 thumbnail 数据，或者在端上裁剪好再传给 `DisplayRepresentation`。

- **实战中容易踩的坑**：
  - `OpenIntent` 的 `perform()` 方法里不要做重度初始化，直接改状态让 UI 响应。
  - `FeaturePrint` 的 `maxDistance` 阈值需要针对你的数据集调优，不同类别的图像合适的阈值不同。
  - 多平台支持：Visual Intelligence 今年扩展到了 iPad 和 macOS，确保你的 `IntentValueQuery` 在这些平台上也能正常工作。
  - 用 `@UnionValue` 时，每种 case 都要有对应的 `OpenIntent`，否则用户点击某些结果会没有反应。
