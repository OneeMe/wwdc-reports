## Highlight

> Apple 彻底拥抱 W3C Web Extensions 标准，现在开发 Safari 扩展不再需要 Xcode：一个代码编辑器、一个 `manifest.json`、HTML/CSS/JS 就能在 Safari 里直接加载调试。只有上架 App Store 或 TestFlight 时才需要用 Xcode 的打包工具。已有 Chrome/Firefox 扩展可以几乎零成本迁移到 Safari。

---

## 核心内容

### 1. 这场演讲解决什么问题

以前开发 Safari 扩展的门槛很高：

- 必须创建 Xcode 工程，配置多个 Target
- API 和 Chrome/Firefox 不兼容，需要大量改造
- 调试流程复杂，纯前端开发者很难上手

现在 Apple 全面转向 W3C Web Extensions 标准，开发体验完全变了：

- **不需要 Xcode**：任何代码编辑器都能开发，Safari 直接加载未签名扩展
- **标准 API**：Chrome/Firefox 扩展代码可以直接复用
- **跨平台**：同一个扩展同时支持 iOS、iPadOS、macOS 和 visionOS

### 2. 从零构建一个扩展

每个扩展都需要一个 `manifest.json`：

```json
{
    "manifest_version": 3,
    "name": "Shiny OnTrack",
    "description": "Stay on track while you browse the web",
    "version": 1.0,

    "icons": {
        "512": "images/icon.svg"
    },

    "options_ui": {
        "page": "options.html"
    }
}
```

在 Safari 设置里开启"为 Web 开发者显示功能"，然后"允许未签名的扩展"，选择扩展文件夹即可加载。

### 3. 内容拦截：declarativeNetRequest

用 `declarativeNetRequest` API 拦截、修改或重定向网络请求：

```json
{
    "permissions": ["declarativeNetRequest"],
    "declarativeNetRequest": {
        "rule_resources": [
            {
                "id": "ruleset_id",
                "enabled": true,
                "path": "rules.json"
            }
        ]
    }
}
```

静态规则写在 `rules.json` 里：

```json
{
    "id": 1,
    "priority": 1,
    "action": { "type": "block" },
    "condition": {
        "urlFilter": "||webkit.org",
        "resourceTypes": ["main_frame"]
    }
}
```

动态规则通过 JavaScript 添加：

```javascript
await browser.declarativeNetRequest.updateDynamicRules({
    addRules: [rule]
});
```

### 4. 权限模型：最小化请求

Safari 推荐用 `declarativeNetRequestWithHostAccess` 配合 `optional_host_permissions`，按需请求权限：

```json
{
    "permissions": ["declarativeNetRequestWithHostAccess"],
    "optional_host_permissions": ["*://*/*"]
}
```

在运行时动态请求权限：

```javascript
const granted = await browser.permissions.request({
    origins: [`*://${host}/*`, `*://*.${host}/*`]
});
if (!granted) return;
```

### 5. 内容脚本：修改网页

内容脚本可以注入 JS 和 CSS 到匹配的页面：

```json
{
    "content_scripts": [
        {
            "js": ["content.js"],
            "css": ["content.css"],
            "matches": ["*://*.webkit.org/*"]
        }
    ]
}
```

也可以动态注册：

```javascript
let script = {
    id: "id",
    js: ["content.js"],
    css: ["content.css"],
    matches": ["*://*.webkit.org/*"],
    persistAcrossSessions: true
};
await browser.scripting.registerContentScripts([script]);
```

### 6. 数据持久化：storage API

```javascript
// 存储数据
await browser.storage.local.set({ hosts: hosts });

// 读取数据
const { hosts = [] } = await browser.storage.local.get("hosts");
```

### 7. 原生通信：Native Messaging

扩展可以通过 Native Messaging 与宿主 App 通信，调用 Touch ID、Keychain 等平台能力：

```javascript
// 扩展侧发送消息
const response = await browser.runtime.sendNativeMessage({
    message: "requestBioAuth"
});
```

```swift
// App 侧处理消息
class SafariWebExtensionHandler: NSObject, NSExtensionRequestHandling {
    func beginRequest(with context: NSExtensionContext) {
        let message = request?.userInfo?[SFExtensionMessageKey] as? [String: Any]
        if message?["message"] as? String == "requestBioAuth" {
            let context = LAContext()
            // ...执行生物识别验证
        }
    }
}
```

### 8. 打包和分发

开发完成后，用 Xcode 的命令行工具打包：

```bash
xcrun safari-web-extension-packager --copy-resources /path/to/extension
```

然后像普通 App 一样通过 App Store Connect 分发，支持 TestFlight 内测。

## 最佳实践

- **已有 Chrome 扩展迁移**：如果已经是 Manifest V3，直接复用 95% 的代码。重点检查 `background` 脚本，Safari 强制使用 Service Worker，不支持 persistent background pages。把 `<all_urls>` 这种宽泛权限拆成 Optional Host Permissions
- **新项目架构建议**：采用"核心逻辑纯 Web + 平台特性 Native"的架构。把 UI、网络拦截、DOM 操作全部用标准 Web API 写好，这部分代码可以跨浏览器复用。只有当需要用到 Touch ID、Keychain 或跨 App 通信时，才在 Xcode 里写一层薄薄的 Native Wrapper
- **调试技巧**：在 Safari 设置里开启"允许未签名的扩展"后，每次修改代码不需要重启 Safari，只需在扩展管理面板点一下"重新加载"。但如果修改了 `manifest.json` 里的权限，建议彻底关掉 Safari 再重开
