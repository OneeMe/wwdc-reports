## Highlight

> Safari 27 不是堆新功能的版本，而是一次"质量革命"——WebKit 团队在过去一年修复了超过 1100 个兼容性和可靠性问题，从 emoji 输入截断到 SVG 标准对齐，从 CSS Grid Lanes 到 Customizable Select，让 Web 在 Apple 平台上更可靠、更强大。

---

## 核心内容

### 1. 这场演讲解决什么问题

作为 Web 开发者，你可能遇到过这些 frustrations：

- 用户在 Safari 里输入 emoji，网站上却显示了完全不同的字符
- 某个 CSS 特性在 Chrome 里工作正常，在 Safari 里行为不一致
- 用了多年的 `.fromCharCode` 突然在处理新 Unicode 字符时出问题
- SVG 在不同浏览器里渲染结果不一样

WebKit 团队今年的重点是**解决这些真实的问题**，而不是一味追逐新特性。他们修复了超过 1100 个问题，创下了历史新高。

---

### 2. 兼容性改进：让真实网站为真实用户工作

#### 2.1 Emoji 输入修复

一个典型的例子：用户在网站上输入 emoji（比如"含泪笑脸"），结果出现了完全不同的字符。

原因：`KeyboardEvent.keyCode` 和 `String.fromCharCode()` 只能处理 16 位以内的 Unicode 码点。但许多 emoji 需要 17 位，导致截断后映射到错误的字符。

WebKit 的解决方案：当用户输入的字符码点超过 16 位时，**直接发送文本内容而不是数字码点**。这样即使网站还在用老旧的 `.fromCharCode`，也不会出现截断问题。

```javascript
// 老代码：在 Safari 27 之前可能出问题
document.addEventListener('keydown', (e) => {
    const char = String.fromCharCode(e.keyCode); // emoji 会被截断！
});

// 现在：WebKit 直接发送文本，无需修改网站代码
```

这个改动不需要网站开发者做任何修改——WebKit 在引擎层面解决了问题。

#### 2.2 基础架构重写

WebKit 团队还重写了多个超过 20 年历史的核心模块：

- **block-in-inline 布局**：原来处理行内元素嵌套块级元素的代码已经超过 20 年，错综复杂。重写后修复了一系列边缘 case。
- **SVG 标准对齐**：WebKit 团队重新启动了 SVG Working Group，推动 SVG 2 标准澄清。仅 Safari 27 就做了 75+ 项 SVG 改进。
- **CSS 标准跟进**：Anchor Positioning、View Transitions 等新特性持续更新，同时修复了 `min()` / `max()` 在 `sizes` 属性中的支持（2014 年引入 `sizes`，2018 年引入 `min()`/`max()`，但两者直到今年才正确集成）。

### 3. 五大新特性

#### 3.1 CSS Grid Lanes

CSS Grid Lanes 已经在 Safari 26.4 中发布，它让你可以用纯 CSS 实现** masonry 瀑布流布局**，不需要 JavaScript。

```css
.container {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    grid-template-rows: masonry;
    gap: 1rem;
}
```

关键点：

- `grid-template-rows: masonry` 自动处理不同高度元素的对齐
- 支持完整的 Grid 功能（定义轨道、命名区域等）
- 可以反向使用（`grid-template-columns: masonry` 做水平 masonry）
- 支持 `flow-tolerance` 微调 tab 键导航顺序

更多示例和交互式演示见 [gridlanes.webkit.org](https://gridlanes.webkit.org/)。

#### 3.2 Customizable Select

Safari 27 彻底改造了 HTML `<select>` 元素的可定制性：

```css
select {
    appearance: base-select;
}

::picker(select) {
    appearance: base-select;
}
```

新能力：

- `<select>` 内部可以放入任意 HTML：图片、副文本、自定义布局
- 新的伪元素：`::checkmark`、`::picker-icon` 等
- 下拉菜单可以用 Grid 或 Flexbox 布局
- **自动保持无障碍访问性**（accessibility）

```html
<select>
    <option>
        <img src="icon.png" alt="">
        <span class="title">Option 1</span>
        <span class="subtitle">Additional description</span>
    </option>
</select>
```

#### 3.3 HTML `<model>` 元素

去年在 visionOS 的 Safari 中首次亮相的 `<model>` 元素，今年来到了 iOS、iPadOS 和 macOS：

```html
<model src="product.usdz" alt="3D product view">
    <img src="fallback.jpg" alt="Product photo">
</model>
```

- 在支持的平台上显示交互式 3D 模型
- 不支持的浏览器自动回退到 `<img>`
- 支持 USDZ 格式（Apple 的 3D 文件格式）

#### 3.4 `img sizes=auto`

响应式图片的 `sizes` 属性现在支持 `auto`：

```html
<img srcset="small.jpg 400w, large.jpg 800w" 
     sizes="auto" 
     alt="Responsive image">
```

浏览器会自动根据图片的实际渲染宽度选择合适的源，不需要手动计算 `sizes`。

#### 3.5 Web Extensions 改进

Safari 27 继续完善 Web Extensions 支持：

- 改进与 App Store Connect 的集成，简化分发流程
- 更好的 API 兼容性，让更多 Chrome/Firefox 扩展可以移植到 Safari

## 最佳实践

- **测试 Safari Technology Preview**：WebKit 团队强烈建议开发者在最新的 Safari Technology Preview 或 Safari beta 中测试项目。很多问题已经被修复，但你可能还在 workaround。
- **报告问题**：如果遇到 WebKit 的问题，通过 [bugs.webkit.org](https://bugs.webkit.org/) 提交。团队明确说"我们依赖开发者的反馈来确定优先级"。
- **渐进使用新特性**：CSS Grid Lanes 和 Customizable Select 都有良好的回退策略。可以用 `@supports` 检测支持情况：

```css
@supports (grid-template-rows: masonry) {
    .container {
        grid-template-rows: masonry;
    }
}
```

- **检查旧的 workaround**：如果你之前因为 Safari 的某个 bug 写了 workaround 代码，现在可能是时候检查是否还需要了。特别是涉及 SVG、滚动、媒体播放和表格布局的部分。
- **利用 `<model>` 做电商**：如果你在做电商网站，`<model>` 元素让用户可以直接在网页上查看产品的 3D 模型，不需要跳转到 App。回退机制确保旧浏览器也能正常显示图片。
