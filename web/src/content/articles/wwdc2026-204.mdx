# What’s new in WebKit for Safari 27

---

## Highlight

> 今年 WebKit 团队的 KPI 明显从“卷新特性”转向了“还技术债”和“填补体验鸿沟”。他们修了 1100 多个底层 bug，重写了二十多年没动过的 block-in-inline 布局引擎，甚至为了兼容老旧网站的 `.fromCharCode` 16位截断问题，在引擎层做了 emoji 输入的 hack。

---

## 核心内容

今年 WebKit 团队的 KPI 明显从“卷新特性”转向了“还技术债”和“填补体验鸿沟”。他们修了 1100 多个底层 bug，重写了二十多年没动过的 block-in-inline 布局引擎，甚至为了兼容老旧网站的 `.fromCharCode` 16位截断问题，在引擎层做了 emoji 输入的 hack。

对前端和 visionOS 开发者来说，最实在的产出是表单和 3D 渲染的原生化解法。`<select>` 元素通过 `appearance: base-select` 开放了深度样式定制，`<model>` 标签则让 3D 模型和 visionOS 沉浸式环境（Immersive API）有了原生 HTML 级别的入口。同时，Safari Web Extension Packager 彻底解除了对 Mac 和 Xcode 的打包强依赖。


### 最佳实践

已有项目如果用了 Headless UI 或自研的 Select 组件，建议先在新表单中试用 `appearance: base-select`，验证无障碍阅读器的兼容性后再逐步替换。对于 3D 展示需求，果断抛弃网页内嵌 Canvas 的方案，改用 `<model>` 标签，这不仅能白嫖系统底层的 Metal 渲染优化，还能直接支持用户长按触发 AR Quick Look 把模型投射到现实桌面。

Web 扩展开发者现在可以使用 Safari Web Extension Packager 在 Windows 或 Linux 上直接打包提交 App Store Connect。但这不意味着你能脱离 Mac 开发，调试 Safari 特有的 API（如 `safari.extension`）和排查 WebKit 渲染差异，依然需要一台 Mac 跑 Safari Technology Preview。
