## Highlight

> macOS 27 让 Virtualization.framework 从"能跑虚拟机"进化到了"能生产化跑虚拟机"。`VZMacGuestProvisioningOptions` 让你用代码跳过开机向导自动创建用户；Accessory Access 框架把 USB 直通做得像 iOS 外接设备一样优雅；DiskImageKit 引入了类似 Docker 的分层镜像；还开放了 Custom Virtio 让你自己写虚拟硬件驱动。

---

## 核心内容

### 1. 这场演讲解决什么问题

用 Virtualization.framework 搞虚拟机，以前有几个核心痛点：

- 装完 macOS 要手动点 Setup Assistant 创建用户，无法自动化
- USB 设备挂载没有标准 API，各家用各自的 hack
- 磁盘镜像随便一搞就几十上百 GB，克隆慢、占空间
- 网络配置只能用基本的 NAT 或 Bridge，高级拓扑做不了

macOS 27 把这四个问题全部解决了。

### 2. 自动配置 macOS 客户机

`VZMacGuestProvisioningOptions` 让你第一次启动虚拟机时自动完成用户创建：

```swift
import Virtualization

let provisioningOptions = VZMacGuestProvisioningOptions()
provisioningOptions.fullName = fullName
provisioningOptions.username = username
provisioningOptions.password = password
provisioningOptions.logsInAutomatically = true
provisioningOptions.enablesRemoteLogin = true

let startOptions = VZMacOSVirtualMachineStartOptions()
try startOptions.setGuestProvisioning(provisioningOptions)

try await virtualMachine.start(options: startOptions)
```

关键点：
- 只在客户机首次启动时生效，已设置好的系统会忽略这些参数
- 建议从 Keychain 或配置文件读取密码，不要硬编码
- 可以启用自动登录和 SSH 远程登录，方便后续自动化操作

### 3. USB 设备直通：Accessory Access

Accessory Access 框架让 USB 设备直通变得标准化：

```swift
import AccessoryAccess

let criteria: [AAUSBAccessoryMatchingCriteria] = []
let accessories = try await AAUSBAccessoryManager.shared.registerListener(
    self,
    matchingCriteria: criteria
)
```

响应设备连接：

```swift
import AccessoryAccess
import Virtualization

class AccessoryListener: NSObject, AAUSBAccessoryListener {
    func usbAccessoryDidConnect(_ usbAccessory: AAUSBAccessory) {
        virtualMachine.queue.async {
            do {
                let configuration = VZUSBPassthroughDeviceConfiguration(
                    device: usbAccessory
                )
                let device = try VZUSBPassthroughDevice(configuration: configuration)
                self.virtualMachine.usbControllers.first?.attach(device: device) { error in
                    // 处理错误
                }
            } catch {
                // 处理错误
            }
        }
    }
}
```

关键点：
- 用户通过菜单栏显式控制哪些设备附加到哪个 App
- 支持热插拔，不需要重启虚拟机
- 必须妥善处理 `usbAccessoryDidDisconnect`，及时清理挂载点，否则客户机文件系统可能损坏

### 4. 自定义网络拓扑：vmnet

用 `vmnet` 框架创建自定义网络：

```swift
import Virtualization
import vmnet

var status: vmnet_return_t = .VMNET_FAILURE
guard let networkConfiguration = vmnet_network_configuration_create(
    .VMNET_SHARED_MODE, &status
) else { /* 错误处理 */ }

guard let network = vmnet_network_create(networkConfiguration, &status) else { /* 错误处理 */ }

let attachment = VZVmnetNetworkDeviceAttachment(network: network)
let networkDeviceConfiguration = VZVirtioNetworkDeviceConfiguration()
networkDeviceConfiguration.attachment = attachment

virtualMachineConfiguration.networkDevices = [networkDeviceConfiguration]
```

### 5. 分层磁盘镜像：DiskImageKit

DiskImageKit 引入了类似 Docker 镜像的分层概念：

```swift
import DiskImageKit
import Virtualization

let baseImage = try DiskImage(opening: .open(url: baseLayerURL, mode: .readOnly))
let cacheImage = try baseImage.appending(.asifLayer(url: cacheLayerURL, type: .cache))
let overlayImage = try DiskImage(opening: .open(url: overlayLayerURL))
let stackedImage = try cacheImage.appending(overlayImage)

let storageDeviceAttachment = try VZDiskImageStorageDeviceAttachment(
    diskImage: stackedImage
)
let storageDeviceConfiguration = VZVirtioBlockDeviceConfiguration(
    attachment: storageDeviceAttachment
)

virtualMachineConfiguration.storageDevices = [storageDeviceConfiguration]
```

关键点：
- 基础镜像只读，多个虚拟机共享
- 缓存层加速读取
- 覆盖层保存每个虚拟机的独立修改
- 实现"秒级克隆"：新虚拟机只需要创建一个新的覆盖层

### 6. 自定义 Virtio 设备

如果你需要虚拟化标准设备不支持的特殊硬件，可以用 Custom Virtio：

```swift
import Virtualization

let deviceConfiguration = VZCustomVirtioDeviceConfiguration()

// Virtio 熵设备
deviceConfiguration.deviceID = 4
deviceConfiguration.pciClassID = 0x10
deviceConfiguration.pciSubclassID = 0x00
deviceConfiguration.virtioQueueCount = 1

deviceConfiguration.provider = VZCustomVirtioDeviceDelegateProvider(
    deviceQueue: deviceQueue,
    delegate: provider
)

virtualMachineConfiguration.customVirtioDevices = [deviceConfiguration]
```

处理 Virtio 队列元素：

```swift
class DeviceDelegate: NSObject, VZCustomVirtioDeviceDelegate {
    func customVirtioDevice(_ device: VZCustomVirtioDevice,
                            didReceiveNotificationFor queue: VZVirtioQueue) {
        while let element = queue.nextElement() {
            // 处理元素...
            element.returnToQueue()
        }
    }
}
```

## 最佳实践

- **已有项目迁移**：如果你在做类似 UTM 的虚拟机 App，立刻把存储层重构为 DiskImageKit。提供"秒级克隆"和"共享基础镜像"功能，这会成为你最大的卖点。同时，把以前那些 hack 出来的 USB 挂载代码全删了，换上 Accessory Access，能帮你省去 80% 的崩溃客诉
- **新项目建议**：做 CI/CD 虚拟机池的团队，用 `VZMacGuestProvisioningOptions` 配合自动化工具，把节点初始化时间从几分钟压缩到几十秒。网络方面，直接用 `vmnet` 框架配置自定义 DHCP 和端口转发，别再在宿主机上折腾 dnsmasq 或 pf 脚本了
- **安全注意**：处理 `VZMacGuestProvisioningOptions` 时，密码不要硬编码。建议从 Keychain、配置文件或环境变量读取。另外，Provisioning 选项只在首次启动时生效，不要依赖它在后续启动中修改已有用户的密码
- **USB 安全**：用户随时可能通过菜单栏断开设备。你的 App 必须妥善实现 `usbAccessoryDidDisconnect` 回调，及时清理 VM 内部的挂载点，否则 Guest OS 的文件系统可能会因为底层设备突然消失而损坏
