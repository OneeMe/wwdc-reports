## Highlight

> 用户在取消订阅前的那几秒，是你最后能留住他们的机会。Retention Messaging 让你在 App Store 的取消流程中展示自定义消息和优惠，平均 save rate 提升 82%，促销优惠消息最高提升 223%。今年还新增了实时 Retention Messaging API，让你可以根据用户行为动态响应。

---

## 核心内容

### 1. 这场演讲解决什么问题

订阅业务的痛点：用户点击"取消订阅"后，流程就结束了。你没有任何机会解释价值、提供替代方案或挽留用户。

Retention Messaging 在 App Store 的取消确认页面插入你的消息，支持三种形式：

1. **纯消息** — 提醒用户订阅的价值
2. **消息 + 图片** — 增加视觉吸引力
3. **消息 + 优惠** — 提供促销激励用户留下

数据：采用 Retention Messaging 的订阅平均 save rate 提升 +1.4 个百分点（相当于 82% 增长），促销优惠消息最高提升 +5.5 个百分点（223% 增长）。

### 2. 在 App Store Connect 中配置

配置流程：

1. 在 Subscriptions 页面点击"Get Started"
2. 命名 retention message（如"Yoga Message"）
3. 编辑消息文本（支持多语言本地化）
4. 可选：从 Asset Library 选择图片
5. 选择适用的订阅和优惠
6. 右侧实时预览更新

关键规则：

- 消息文本必填，图片和优惠可选
- 一个 retention message 可以关联多个订阅
- App Store 会自动为符合条件的用户选择最佳优惠
- 当用户符合优惠条件时，图片会被优惠替代
- App Store Connect API 也支持 Retention Messaging 配置

### 3. 测试与验证

Retention Messaging 完全支持 sandbox 测试：

- 在 sandbox 中取消订阅时会显示 retention message
- 如果配置了 retention offer，可以验证 signed transaction 中的 offer 相关字段
- 新的 `offerType: 5` 表示 retention offer

Transaction 中的 retention offer 字段：

```json
{
    "bundleId": "com.example.app",
    "productId": "Yoga_summer_2026",
    "type": "Auto-Renewable Subscription",
    "transactionReason": "RENEWAL",
    "offerType": 5,
    "offerIdentifier": "Yoga_2026_cancel_free_3m",
    "offerDiscountType": "FREE_TRIAL",
    "offerPeriod": "P3M",
    "transactionId": "1000098916194",
    "originalTransactionId": "1000011859217"
}
```

### 4. 实时 Retention Messaging API

实时 API 让你设置一个服务端 endpoint，在用户取消时接收 App Store 的实时请求并返回个性化响应。

**API 端点概览：**

```
// URL 配置
PUT /realtime/url
GET /realtime/url
DELETE /realtime/url

// 消息配置
PUT /message/{messageIdentifier}
DELETE /message/{messageIdentifier}
GET /message/list
PUT /default/{productId}/{locale}
DELETE /default/{productId}/{locale}
GET /default/{productId}/{locale}

// 图片配置
PUT /image/{imageIdentifier}
DELETE /image/{imageIdentifier}
GET /image/list

// 性能测试（仅 Sandbox）
POST /performanceTest
GET /performanceTest/result/{requestId}
```

**实时请求格式：**

```json
{
    "originalTransactionId": "123456789",
    "appAppleId": 6745974591,
    "productId": "Yoga_summer_2026",
    "userLocale": "en-US",
    "requestIdentifier": "c03248af-dd76-4e9b-9c1e-4489cd19a768",
    "environment": "Production",
    "signedDate": 1780920000000
}
```

**三种响应格式：**

1. **返回消息**：

```json
{
    "message": {
        "messageIdentifier": "551ee7c0-c097-418e-9dd5-2a98533a7390"
    }
}
```

2. **返回替代方案（switch plan）**：

```json
{
    "alternateProduct": {
        "messageIdentifier": "ed7f25fc-5741-46a3-8502-062e0fb8afd0",
        "productId": "Yoga_summer_2026_annual"
    }
}
```

3. **返回促销优惠**：

```json
{
    "promotionalOffer": {
        "messageIdentifier": "80135e2b-ae15-4ec4-8c5c-9ecc8045c0dc",
        "promotionalOfferSignatureV2": "eyJhbGciOiJFUzI..."
    }
}
```

### 5. 降级策略

实时响应有严格的超时要求。如果服务端未及时响应，App Store 会按以下顺序降级：

1. 你的实时响应（最高优先级）
2. App Store Connect 中配置的 Retention Messaging（包括符合条件的优惠）
3. Retention Messaging API 中配置的默认消息

### 6. 上线流程

1. 在 sandbox 中设置测试消息和图片
2. 设置 endpoint 接收测试请求
3. 通过性能测试（`POST /performanceTest`）
4. 在生产环境设置消息、图片和 endpoint
5. 开始响应 App Store 的实时请求

**支持 12 个月承诺的月订阅**：对于 iOS 26.5 引入的月付年约计划，实时 API 支持通过 `billingPlanType` 字段提供 switch plan。

## 最佳实践

- **消息要突出价值**：不要只说"请不要取消"，要提醒用户即将失去的具体功能
- **优惠要有吸引力**：促销优惠的 save rate 提升效果最显著
- **实时 API 需要快速响应**：必须通过 sandbox 性能测试才能上线
- **保持消息更新**：定期更新 retention message 内容，反映产品的最新价值
- **测试完整流程**：在 sandbox 中验证 transaction 中的 offer 字段是否正确
- **利用降级策略**：即使实时 API 故障，App Store Connect 配置的消息仍可作为兜底
