## Highlight

> 你的音频 App 还在自己管理锁屏界面和控制中心吗？NowPlaying 框架用一套基于 `@Observable` 的 Swift API，把媒体播放状态自动同步到锁屏、控制中心、Dynamic Island、CarPlay 和 StandBy。更厉害的是，Remote Media Sessions 让你的 App 可以控制外接音箱，并在系统 UI 中展示完整的播放控制。

---

## 核心内容

### 1. 这场演讲解决什么问题

媒体 App 的一个常见痛点：播放状态需要手动同步到各种系统界面。锁屏、控制中心、Dynamic Island、CarPlay、Apple Watch、Apple TV — 每个平台都有自己的集成方式，代码分散且复杂。

NowPlaying 框架提供统一的 Swift API，通过 `MediaSessionRepresentable` 协议让系统"理解"你的播放内容。系统会自动处理所有界面的同步。

### 2. Media Sessions：本地播放集成

核心协议 `MediaSessionRepresentable`：

```swift
import Observation
import NowPlaying

@Observable
final class PlayerModel {
    let player: SoundPlayer
    var sound: Sound { player.currentSound }

    init(player: SoundPlayer) {
        self.player = player
    }
}

extension PlayerModel: MediaSessionRepresentable {
    var id: String { "ambient-sound-session" }

    var content: (any MediaContentRepresentable)? {
        return GenericContent(
            id: sound.id,
            title: sound.name,
            subtitle: sound.description,
            type: .audio,
            duration: .live,
            artwork: Artwork(id: sound.id) { size in
                let data = try await self.artworkData(size: size)
                return try ArtworkRepresentation(data: data)
            }
        )
    }

    var playbackSnapshot: MediaPlaybackSnapshot? {
        MediaPlaybackSnapshot(
            state: player.isPlaying ? .playing() : .paused
        )
    }

    var commands: [MediaCommand] {[
        .play { self.player.play() },
        .pause { self.player.pause() },
        .previous { self.player.previous() },
        .next { self.player.next() }
    ]}
}
```

关键点：

- `id`：session 的唯一标识符
- `content`：描述当前播放内容，支持 `GenericContent`、`MusicContent`、`PodcastContent`、`MovieContent` 等类型
- `playbackSnapshot`：当前播放状态，包括 `.playing()`、`.paused`，以及可选的 `elapsedTime`
- `commands`：支持的命令列表，每个命令带一个闭包，系统调用时执行
- `Artwork` 用 async closure 懒加载，系统需要时按指定尺寸请求

初始化 `MediaSession`：

```swift
import NowPlaying

struct PlayerController {
    let player: SoundPlayer
    let model: PlayerModel
    let session: MediaSession<PlayerModel>

    init() {
        self.player = SoundPlayer()
        self.model = PlayerModel(player: player)
        self.session = MediaSession(model)
    }
}
```

`MediaSession` 会自动观察 `@Observable` model 的变化，保持所有系统界面同步更新。

### 3. Remote Media Sessions：外接设备控制

如果你的 App 可以控制外接音箱（如智能扬声器），用 Remote Media Sessions 在系统 UI 中展示这些远程播放状态。

**架构流程**：

1. 用户与外接设备交互（如音箱切换歌曲）
2. 音箱通知你的服务器状态变化
3. 服务器通过 APNs 发送 push 通知到 iPhone
4. 系统启动 App Extension，传入更新后的状态
5. App Extension 提供更新的 session representation
6. 系统更新锁屏/控制中心等界面

**App Extension 配置**：

```swift
import ExtensionFoundation
import NowPlaying

@main
final class SampleAppExtension: @MainActor RemoteMediaSessionExtension {
    var configuration: some AppExtensionConfiguration {
        RemoteMediaSessionExtensionConfiguration(extension: self)
    }

    var extensionPoint: AppExtensionPoint {
        AppExtensionPoint.Identifier(host: "com.apple.nowplaying", name: "remote-media")
    }

    func session(_ state: RemotePlayerState) async throws -> RemotePlayerModel {
        RemotePlayerModel(state: state)
    }
}
```

**Remote Media Session Representation**：

```swift
import NowPlaying

extension RemotePlayerModel: @MainActor RemoteMediaSessionRepresentable {
    var id: String { state.sessionID }

    var content: (any MediaContentRepresentable)? {
        GenericContent(
            id: state.sound.id,
            title: state.sound.name,
            subtitle: state.sound.description,
            type: .audio,
            duration: .live,
            artwork: Artwork(id: state.sound.id) { size in
                let data = try await self.artworkData(size: size)
                return try ArtworkRepresentation(data: data)
            }
        )
    }

    var playbackSnapshot: MediaPlaybackSnapshot? {
        MediaPlaybackSnapshot(
            state: state.isPlaying ? .playing() : .paused
        )
    }

    var commands: [MediaCommand] {[
        .play { try await self.client.send(.play) },
        .pause { try await self.client.send(.pause) },
        .previous { try await self.client.send(.previous) },
        .next { try await self.client.send(.next) }
    ]}

    var devices: [MediaDevice] {
        state.devices.map { device in
            MediaDevice(
                id: device.id,
                name: device.name,
                type: .speaker,
                capabilities: [
                    .absoluteVolume(device.volume) { volume in
                        // 发送音量变更到服务器
                    }
                ]
            )
        }
    }

    func update(_ state: RemotePlayerState) {
        self.state = state
    }
}
```

Remote session 特有的属性：

- `devices`：告知系统播放设备列表，包括名称、类型和音量控制能力
- `update(_:)`：收到 push 通知更新状态时被调用
- 命令闭包中发送请求到服务器，服务器再通知音箱执行

### 4. Media Sharing Extensions

Media Sharing Extensions 让你用系统的设备选择器来路由媒体到各种扬声器/TV，而不需要在 App 中嵌入各种协议的 SDK。

传统方式：每个媒体协议需要嵌入对应的 SDK。Media Sharing Extensions 把协议实现移到系统层面管理，你的 App 只需要关注内容本身。随着新协议推出，App 无需更新即可支持。

## 最佳实践

- **尽早初始化 MediaSession**：在设置音频引擎的同一位置初始化
- **使用 `@Observable` model**：NowPlaying 会自动观察变化并更新系统界面
- **为 Artwork 提供 async closure**：系统会按需按尺寸请求，避免一次性加载所有尺寸
- **为远程命令添加错误处理**：网络请求可能失败，要优雅处理
- **device ID 要跨 session 稳定**：同一设备在不同 session 中应有相同标识
- **考虑使用 Media Sharing Extensions**：减少 SDK 依赖，让系统处理设备发现
