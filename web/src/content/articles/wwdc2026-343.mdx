## Highlight

> 以前做 Siri 适配，用户必须像念咒语一样精准匹配参数。现在通过自定义对话响应、交互捐赠、屏幕感知注解和结构化搜索，Siri 能真正理解用户屏幕上显示的内容，还能在运行时追问澄清问题。

## 核心内容

### 1. 这场演讲解决什么问题

基础版 App Intents 能让 Siri 执行你的 App 动作，但体验还很生硬：Siri 的回复是系统默认的机械音、无法追问用户、不知道屏幕上显示什么、也搜不到 App 里的海量内容。

这场 Session 教你把 Siri 体验从"能用"打磨到"好用"。核心围绕四个方向：自定义对话响应、内容可发现性、屏幕感知、系统集成注解。

### 2. 自定义 Siri 对话响应

Siri 默认会自己生成回复，但你可以接管，让回复匹配 App 的品牌语气。

```swift
@AppIntent(schema: .audio.addToPlaylist)
struct AddToPlaylistIntent {
    func perform() async throws -> some IntentResult & ProvidesDialog {
        // 添加歌曲到播放列表
        return .result(
            dialog: IntentDialog(
                full: "Added \(song.title) to the \(playlist.title) mix tape.",
                supporting: "Added"
            )
        )
    }
}
```

`full` 字符串会在纯语音设备（如 AirPods）上朗读，必须能独立描述发生了什么。`supporting` 是带 UI 时显示的简短版本。

还可以在执行过程中追问用户：

```swift
@AppIntent(schema: .clock.createTimer)
struct CreateTimerIntent {
    var duration: Duration
    var label: String?
    var isSleepTimer: Bool

    func perform() async throws -> some ReturnsValue<TimerEntity> {
        // 如果已有定时器在运行，追问用户命名
        label = try await $label.requestValue(
            "You already have a timer running. What should we call this one?"
        )
        return .result(value: timerEntity)
    }
}
```

### 3. 让内容被 Apple Intelligence 发现

内容量小的 App 可以用 `IndexedEntity` 把数据塞进 Spotlight 语义索引。内容量大或依赖服务端的数据，用 `IntentValueQuery` 做实时结构化搜索。

```swift
// 结构化搜索歌曲和播放列表
struct AudioIntentValueQuery: IntentValueQuery {
    func values(for input: AudioSearch) async throws -> [AudioEntity] {
        switch input.criteria {
        case .searchQuery(let query):
            return try await searchResults(for: query)
        case .unspecified:
            return try await likedSongResults()
        }
    }
}
```

用户通过 Siri 搜索后，你还可以在 App 内复用同样的搜索条件：

```swift
@AppIntent(schema: .system.searchInApp)
struct SearchAudioLibraryIntent {
    var criteria: StringSearchCriteria

    func perform() async throws -> some IntentResult {
        navigation.searchText = criteria.term
        navigation.selectedTab = .library
        return .result()
    }
}
```

### 4. 屏幕感知 (Onscreen Awareness)

这是今年最关键的新能力。Siri 需要知道用户屏幕上显示的是什么，才能理解"把这个发给 Kevin"里的"这个"指的是什么。

三种注解方式：

```swift
// (a) 屏幕上只有一个主实体 —— NSUserActivity
struct NowPlayingView: View {
    var body: some View {
        VStack { /* 播放器 UI */ }
        .userActivity("cosmotunes.nowPlaying", isActive: playback.currentTrack) { activity in
            activity.title = playback.currentTrack?.title
            activity.appEntityIdentifier = EntityIdentifier(
                for: SongEntity.self,
                identifier: playback.currentTrack.id
            )
        }
    }
}

// (b) 多个实体中的一个 —— View Entity annotation
struct AlbumView: View {
    private var header: some View {
        VStack {
            // ...
        }
        .appEntityIdentifier(
            EntityIdentifier(for: AlbumEntity.self, identifier: session.id.uuidString)
        )
    }
}

// (c) 列表和集合 —— Collection annotation
struct PlaylistDetailView: View {
    var body: some View {
        List {
            ForEach(playlist.tracks) { track in
                PlaylistTrackRow(track: track)
            }
        }
        .appEntityIdentifier(forSelectionType: GeneratedTrack.ID.self) { trackID in
            EntityIdentifier(for: SongEntity.self, identifier: trackID)
        }
    }
}
```

### 5. 交互捐赠 (Interaction Donations)

让 Siri 学习用户偏好，下次更智能地推荐。

```swift
@ModelActor
actor ModelManager {
    func sendMessage(_: ..., donateIntent: Bool = false) async throws -> [Message.ID] {
        if donateIntent {
            let intent = SendMessageIntent()
            intent.destination = .recipients(conversation.recipients.map(\.entity))
            let result = messages.map(\.entity)
            Task {
                try await IntentDonationManager.shared.donate(
                    intent: intent,
                    result: .result(value: result)
                )
            }
        }
    }
}
```

捐赠时带上参数和结果，Siri 才能理解"用户通常在什么场景下执行这个动作"。

### 6. 系统集成注解

把 Entity 注解扩展到通知、Now Playing、闹钟等系统集成点：

```swift
// 用户通知
func scheduleNotification(message: Message, author: Contact) {
    let content = UNMutableNotificationContent()
    content.title = author.name
    content.body = message.body
    content.appEntityIdentifiers = [
        EntityIdentifier(for: MessageEntity.self, identifier: message.id)
    ]
    // 安排通知...
}

// Now Playing
final class CosmoTunesMediaSession: MediaSessionRepresentable {
    var content: (any MediaContentRepresentable)? {
        var content = MusicContent(id: track.id.uuidString, songTitle: track.title)
        content.appEntityIdentifiers = [
            EntityIdentifier(for: SongEntity.self, identifier: track.id),
            EntityIdentifier(for: ArtistEntity.self, identifier: track.session.artistName),
            EntityIdentifier(for: PlaylistEntity.self, identifier: currentPlaylist.id),
        ]
        return content
    }
}
```

## 最佳实践

- **已有项目迁移**：别急着把所有 Entity 都加上 `IndexedEntity`。先盘点数据量级，超过几千条的动态数据直接上 `IntentValueQuery`。优先把高频使用的核心视图加上 `appEntityIdentifier`，跑通"屏幕感知"的最小闭环。
- **新项目建议**：从一开始就把 AppEntity 的设计融入数据模型层。定义 Entity 时把 `DisplayRepresentation` 的 title、subtitle 和 image 配齐，这能免费让你的 App 在 Spotlight、Siri 和快捷指令里看起来更专业。
- **容易踩的坑**：使用 `ShowsSnippetView` 返回自定义 SwiftUI 视图时，必须同时提供 `ProvidesDialog` 的 full string。如果只给视图不给完整对话，AirPods 用户听到的将是一片死寂。
