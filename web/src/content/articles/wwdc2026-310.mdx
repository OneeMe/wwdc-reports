## Highlight

> Shortcuts 今年新增了三种自动化触发器（截图、键盘、通知），Use Model action 可以调用 Apple Intelligence 模型并检查 transcript 来调试，Storage 功能让 shortcut 能跨设备持久化数据。这意味着你的 App 内容可以深度融入系统自动化流程，甚至让 AI 基于你的 App 数据做智能决策。

---

## 核心内容

### 1. 这场演讲解决什么问题

开发者想让用户用 App 内容构建自动化，但面临几个问题：

1. **触发器不够丰富** — 用户只能在有限场景下自动运行 shortcut
2. **AI 集成不透明** — Use Model action 输出不可预测，难以调试
3. **数据无法持久化** — shortcut 每次运行都是独立的，无法记住状态

这场演讲的三个更新分别解决这三个问题。

### 2. 新自动化类型

自动化现在直接集成在 Shortcuts 编辑器中，新增三种触发器：

| 触发器 | 触发时机 |
|---|---|
| Screenshot | 保存截图时 |
| Keyboard | 外接键盘连接/断开时 |
| Notification | 收到特定 App 的通知时 |

**通知自动化的实际例子**：Soup Chef App 在外卖即将送达时发送通知"Driver Alex arriving in 5 minutes"。用户创建一个 shortcut，在收到 Soup Chef 的通知且内容包含"arriving"时自动打开门廊灯，并用 HomePod 播报"Soup is arriving"。

关键：通知内容要简洁、信息丰富、包含可识别的关键词，这样用户才能用过滤器精确触发。

### 3. Use Model action 与 Transcript 调试

Use Model action 现在可以访问更强大的 Apple Intelligence 模型，包括能联网获取最新信息的模型。所有模型都能处理 App 内容。

**调试问题**：当模型输出不符合预期时，你需要知道模型到底看到了什么。新增 **Transcript** 功能让你查看传递给模型的原始内容。

```swift
import AppIntents

struct SoupEntity: AppEntity, Identifiable {
    static var typeDisplayRepresentation = TypeDisplayRepresentation(
        name: "Soup",
        numericFormat: "\(placeholder: .int) soups"
    )
    static var defaultQuery = SoupEntityQuery()
    
    var id: Soup.ID
    
    @Property var name: String
    
    @Property(title: "Available Today")
    var isAvailableToday: Bool
    
    @Property(title: "Ingredients")
    var ingredients: String
    
    var displayRepresentation: DisplayRepresentation {
        DisplayRepresentation(title: "\(name)", subtitle: SoupStore.description(for: id))
    }
}
```

**实际调试场景**：

1. 创建一个"Soup of the Day" shortcut，让模型根据辣度偏好选汤
2. 模型选了 Chicken Tortilla Soup，但用户想要更辣的
3. 添加 Show Content action，选择 Transcript 属性
4. 发现模型只看到 `name` 和 `isAvailableToday`，没有 `ingredients`
5. 在 `SoupEntity` 中添加 `ingredients` 属性
6. 重新运行，模型正确选择了 Tom Yum Soup

关键点：

- Transcript 显示传递给模型的结构化表示，包括所有属性和值
- 通过检查 Transcript 可以精确知道模型"看到"了什么
- 给模型提供足够的上下文信息是获得准确输出的关键

### 4. Storage：跨设备持久化

Storage 让 shortcut 可以在多次运行之间保存数据，且数据会同步到用户的所有设备。

**使用场景**：

- 记录每天喝的咖啡数量
- 跟踪跨多次运行的 richer context
- 让模型记住过去的选择以避免重复

**Soup of the Day 的例子**：

1. 用"Get Value"action 读取"Previous Soups"列表
2. 将列表传给模型，要求避免选最近的汤
3. 模型返回新选择
4. 用"Add to List"将新选择追加到列表
5. 用"Set Value"保存更新后的列表

**跨设备同步的注意事项**：

- Entity 需要在所有设备上有稳定的标识符
- 不要用设备相关的值（如设备 UUID）作为 entity ID
- 用后端数据库的行 ID 或其他全局唯一标识

```swift
// 好的做法：使用数据库行 ID，所有设备一致
var id: String { soup.databaseRowID }

// 避免：使用设备相关标识
// var id: UUID { UUID() } // 每次运行都不同！
```

## 最佳实践

- **设计好的通知内容**：包含具体名称、可识别的动词、可操作的时间信息，方便用户构建自动化
- **给 Entity 足够的属性**：Use Model 的准确性取决于传递给模型的信息质量
- **使用 Transcript 调试**：当模型输出不符合预期时，先检查它看到了什么
- **选择稳定的 Entity ID**：确保跨设备同步时 entity 能被正确识别
- **测试 Storage 的跨设备同步**：在 iPhone 上保存，在 iPad 上读取验证
- **参考 HIG 设计通知**：遵循 Human Interface Guidelines 的通知最佳实践
