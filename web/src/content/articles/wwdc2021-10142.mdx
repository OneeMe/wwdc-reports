# HLS 无缝媒体过渡

## Highlight

> Gapless HLS Playback 允许将多个 playlist 拼接成连续播放序列，播放器自动处理编码参数变化、时间戳对齐和缓冲协调，实现剧集连播、专辑无缝播放和场景平滑切换。

## 核心内容

流媒体应用中有一个常见但棘手的需求：让多个独立的媒体资源连续播放，用户感知不到切换。播客应用需要剧集自动连播，音乐应用需要专辑曲目无缝衔接，视频平台需要从片头到正片到片尾一气呵成。

传统方案中，每个资源用独立的 AVPlayerItem 播放，切换时需要销毁旧播放器、创建新播放器——不可避免地产生卡顿。WWDC2021 引入的 Gapless HLS Playback 将多个 playlist 视为一个连续播放序列，播放器自动处理时间戳映射、缓冲协调和编码参数适配，切换过程对用户完全透明。

## 详细内容

### 无缝切换的挑战

媒体切换时的卡顿来自多个层面：
- **解码器重新初始化**：编码参数变化（SDR 到 HDR、1080p 到 4K）需要重新配置解码器
- **缓冲中断**：新资源的初始段需要重新下载和缓冲
- **时间戳不连续**：不同资源的 PTS/DTS 没有对齐，播放器需要手动处理跳转
- **音频格式变化**：采样率、声道数变化导致音频渲染中断

### Gapless HLS 的核心机制

Gapless HLS Playback 通过以下机制解决上述问题：

**Playlist 级联**：主 playlist 通过 `EXT-X-STREAM-INF` 引用多个子 playlist，每个子 playlist 对应一个独立资源（如一集播客或一首歌曲）。播放器将整个级联视为一个连续的时间轴。

**时间戳映射**：播放器自动将后续资源的时间戳映射到全局时间轴上。第一首歌曲的时长是 180 秒，第二首从 180 秒开始计时，用户 seek 时看到的是连续的时间。

**缓冲协调**：播放器在播放当前资源时，提前在后台缓冲下一个资源的初始段。当切换点到达时，新资源已经准备就绪，无需等待。

**编码参数适配**：当编码参数变化时（如从 SDR 切换到 HDR），播放器在后台预初始化新的解码器管道，切换瞬间完成交接。

### HLS Playlist 结构

实现 gapless 播放的 playlist 结构示例：

```
#EXTM3U
#EXT-X-TARGETDURATION:6
#EXT-X-VERSION:6
#EXT-X-PLAYLIST-TYPE:VOD
#EXT-X-INDEPENDENT-SEGMENTS

# 第一首歌曲
#EXTINF:6.000,
song1_segment1.m4s
#EXTINF:6.000,
song1_segment2.m4s
#EXTINF:3.000,
song1_segment3.m4s

# 第二首歌曲（无缝衔接）
#EXT-X-DISCONTINUITY
#EXTINF:6.000,
song2_segment1.m4s
#EXTINF:6.000,
song2_segment2.m4s
```

`EXT-X-DISCONTINUITY` 标记编码参数或内容的变化点，但播放器通过内部时间戳映射保证连续性。

### 关键标签

**EXT-X-GAP**：标记 playlist 中的占位段。当某个时段的内容尚未就绪时，用 GAP 段占位，播放器知道这里内容缺失但不会报错，等实际内容到达后替换（04:15）。

```
#EXT-X-GAP
#EXTINF:6.000,
gap.m4s
```

这在直播场景中特别有用：广告内容尚未决策完成时，先用 GAP 占位，广告素材就绪后无缝替换。

**编码一致性要求**：
- 切换点的 I-frame 必须对齐
- 使用相同的 codec profile 和 level
- 时间戳必须连续或播放器能够正确映射
- 音频采样率和声道数保持一致

### AVFoundation API

播放器自动处理 gapless 播放，无需特殊 API。对于需要监听切换事件的应用：

```swift
let player = AVPlayer(playerItem: item)

// 监听当前播放项变化
player.observe(\.currentItem) { player, _ in
    // 切换到新的子资源
}

// 监听时间轴变化（gapless 序列中的全局时间）
let timeObserver = player.addPeriodicTimeObserver(
    forInterval: CMTime(seconds: 1, preferredTimescale: 1),
    queue: .main
) { time in
    // time 是全局时间轴上的位置
}
```

### 场景应用

**播客剧集连播**：用户听完一集后自动播放下一集，保持相同的播放速度和睡眠定时器状态。

**音乐专辑播放**：专辑内曲目之间没有间隙，与 CD 的无缝播放体验一致。

**视频场景切换**：纪录片中从正片切换到资料片段再切换回来，过渡平滑无感知。

**直播频道切换**：线性电视频道之间的切换，保持 EPG 时间轴的连续性。

## 核心启发

1. **统一编码参数**：所有参与 gapless 序列的资源使用相同的编码配置文件（分辨率阶梯、码率、帧率、GOP 大小、codec profile）。参数不一致会导致解码器重新初始化，产生卡顿。

2. **I-frame 对齐切换点**：确保每个资源在切换边界处都有 I-frame，且时间戳连续。这需要在编码阶段就规划好分段策略。

3. **用 EXT-X-GAP 处理动态内容**：直播或广告场景中，内容尚未就绪时用 GAP 段占位，避免播放器报错。内容到达后更新 playlist，播放器自动替换。

4. **测试时关注音频连续性**：人耳对音频间断比眼睛对画面跳帧敏感得多。0.5ms 的音频断裂都能被察觉，测试时应使用专业音频分析工具。

5. **预缓冲策略**：播放器自动在后台缓冲下一个资源，但应用可以通过调整 `preferredForwardBufferDuration` 控制缓冲深度，在网络不稳定时提供更长的缓冲保护。
