## Highlight

> Apple 在 Metal 里加入 Binary Archives、Dynamic Libraries 和新的离线工具链，让开发者可以收集、序列化并随 App 分发 GPU 二进制，减少首次创建 Pipeline State Object 时的后端编译成本。

## 核心内容

一个大型 Metal 游戏第一次启动时，最容易卡在 Pipeline State Object（PSO，管线状态对象）创建上。即使 shader 已经在 Xcode 离线编译成 AIR（Apple Intermediate Representation，中间表示），设备仍要在创建 PSO 时把 AIR 编译成当前 GPU 可执行的机器码。每个 pipeline 都要走一遍这条路，系统缓存只有在运行过后才有用。

开发者常见的补救办法是提前创建 pipeline，把卡顿挪到 loading screen。这个办法能减少游戏中的 hitch，却会拉长首次启动。更大的问题是，多个 pipeline 使用同一段 utility shader 代码时，机器码也会重复生成和重复占用内存。

这场 session 给出三段式答案。Metal Binary Archives 负责把已经编译好的 pipeline 函数收集到文件里。Metal Dynamic Libraries 负责把 utility 函数做成可链接、可复用、可分发的机器码。新的 Metal Developer Tools 把这些工作流带到命令行和 Windows 构建环境，让图形团队可以把 GPU 二进制当作资产管理。

## 详细内容

### Binary Archives：把 pipeline 编译结果变成可分发资产

（[03:03](https://developer.apple.com/videos/play/wwdc2020/10615/?time=183)）Metal 以前已经有系统级 shader cache，但应用不能显式管理它。Binary Archives 给了应用一层可控缓存：你可以收集编译后的 pipeline 函数，按使用场景拆成多个 archive，从设备上收割，再分发到同 GPU、同系统版本的兼容设备。

创建空 archive 的代码很短。

```swift
let descriptor = MTLBinaryArchiveDescriptor()
descriptor.url = nil
let binaryArchive = try device.makeBinaryArchive(descriptor:descriptor)
```

关键点：

- `MTLBinaryArchiveDescriptor` 是创建和加载 archive 的入口。
- `descriptor.url = nil` 表示创建新的空 archive。
- `device.makeBinaryArchive` 从当前 `MTLDevice` 创建 archive，所以结果与 GPU 能力相关。

（[06:47](https://developer.apple.com/videos/play/wwdc2020/10615/?time=407)）archive 需要显式填充。开发者要把关心的 render、compute 或 tile render pipeline descriptor 加入 archive。加入时，Metal 会执行后端编译，把机器码写入 archive。

```swift
// Render pipelines
try binaryArchive.addRenderPipelineFunctions(with: renderPipelineDescriptor)

// Compute pipelines
try binaryArchive.addComputePipelineFunctions(with: computePipelineDescriptor)

// Tile render pipelines
try binaryArchive.addTileRenderPipelineFunctions(with: tileRenderPipelineDescriptor)
```

关键点：

- `addRenderPipelineFunctions` 对应 render pipeline。
- `addComputePipelineFunctions` 对应 compute pipeline。
- `addTileRenderPipelineFunctions` 对应 tile render pipeline。
- 这里加入的是 pipeline descriptor 描述的函数集合，目标是提前生成后端机器码。

（[06:56](https://developer.apple.com/videos/play/wwdc2020/10615/?time=416)）复用 archive 时，把它放进 pipeline descriptor 的 `binaryArchives` 数组。Metal 会按数组顺序搜索。命中后，PSO 创建可以跳过后端编译，也不会影响系统 shader cache。

```swift
// Reusing compiled functions to build a pipeline state object from a file

let renderPipelineDescriptor = MTLRenderPipelineDescriptor()
// ...
renderPipelineDescriptor.binaryArchives = [ binaryArchive ]

let renderPipeline = try device.makeRenderPipelineState(descriptor:
                                                          renderPipelineDescriptor)
```

关键点：

- `binaryArchives` 是 pipeline descriptor 上的新入口。
- 数组顺序决定 archive 搜索顺序。
- `makeRenderPipelineState` 仍然是创建 PSO 的调用点，只是编译结果可能直接来自 archive。

（[07:15](https://developer.apple.com/videos/play/wwdc2020/10615/?time=435)）收集完成后，把 archive 序列化到磁盘。下一次启动时，再用同一个 URL 加载。

```swift
let documentsURL = FileManager.default.urls(for: .documentDirectory, in: .userDomainMask).first!
let archiveURL = documentsURL.appendingPathComponent("binaryArchive.metallib")

try binaryArchive.serialize(to: NSURL.fileURL(withPath: archiveURL))
```

关键点：

- `serialize` 把 archive 写成 `.metallib` 文件。
- 这个文件可以被打包、收割或用于下一次运行。
- session 特别提醒，archive 文件会 memory-map 进进程；不用时释放 archive，可以释放虚拟地址空间。

加载已有 archive 的代码只需要把 `url` 指向文件。

```swift
let documentsURL = FileManager.default.urls(for: .documentDirectory, in: .userDomainMask).first!
let serializeURL = documentsURL.appendingPathComponent("binaryArchive.metallib")

let descriptor = MTLBinaryArchiveDescriptor()
descriptor.url = NSURL.fileURL(withPath: serializeURL)
let binaryArchive = try device.makeBinaryArchive(descriptor: descriptor)
```

关键点：

- `descriptor.url` 指向已有 archive 时，Metal 会加载文件。
- 加载后的 archive 可以立即用于后续 pipeline 创建。
- 如果 GPU 或系统版本不兼容，Metal 会回退到运行时编译。

（[10:35](https://developer.apple.com/videos/play/wwdc2020/10615/?time=635)）Apple 和 Epic 用 Fortnite 的 PSO workload 做了量化。测试里有超过 11,000 个 pipeline state object。预置一个收集了 1,700 个 pipeline state object 函数变体的 archive 后，pipeline build 时间从 1 分 26 秒降到 3 秒，约 28 倍加速。

### Dynamic Libraries：让 compute utility 代码只编译、存储一次

（[13:52](https://developer.apple.com/videos/play/wwdc2020/10615/?time=832)）很多 compute shader 会共享同一批 utility 函数。旧模型下，每个 pipeline 生成 PSO 时都可能为这些 utility 代码支付后端编译成本，多个 pipeline 还会保存重复的机器码。`MTLDynamicLibrary` 把这部分代码做成可动态链接的机器码集合。

运行时创建动态库，需要把 `MTLCompileOptions` 标成 `.dynamic`，并给它一个 install name。

```swift
let options = MTLCompileOptions();
options.libraryType = .dynamic;
options.installName = "@executable_path/myDynamicLibrary.metallib"
let utilityLib = try device.makeLibrary(source: dylibSrc, options: options)
let utilityDylib = try device.makeDynamicLibrary(library: utilityLib)
```

关键点：

- `libraryType = .dynamic` 告诉 Metal 这份 `MTLLibrary` 要作为动态库使用。
- `installName` 是 pipeline 创建时 linker 查找动态库的名字。
- `makeDynamicLibrary` 把 Metal 代码后端编译成机器码，session 说这是创建动态库时唯一需要编译动态库的地方。

（[17:59](https://developer.apple.com/videos/play/wwdc2020/10615/?time=1079)）编译依赖动态库的 kernel 时，把动态库传给 `MTLCompileOptions.libraries`。编译阶段会检查至少有一个匹配函数签名，真正选择实现会推迟到 pipeline 创建时。

```swift
let options = MTLCompileOptions()
options.libraries = [ utilityDylib ]
let library = try device.makeLibrary(source: kernelStr, options: options)
```

关键点：

- `options.libraries` 声明 kernel 依赖哪些动态库。
- 编译阶段检查符号是否存在，避免缺少函数签名。
- 链接推迟到 pipeline 创建时，因此可以在运行时切换实现。

（[19:37](https://developer.apple.com/videos/play/wwdc2020/10615/?time=1177)）动态库还能通过 compute pipeline descriptor 的 `insertLibraries` 替换符号实现。session 把它类比为 `DYLD_INSERT_LIBRARIES`：linker 会先搜索插入的库，再搜索原本链接的库。

```swift
let descriptor = MTLComputePipelineDescriptor()
descriptor.computeFunction = kernelFunction
descriptor.insertLibraries = [replacementDylib]
let pipeline = try device.makeComputePipelineState(descriptor: descriptor,
                                                   options: [],
                                                   reflection: nil)
```

关键点：

- `insertLibraries` 来自 transcript 中描述的动态替换工作流。
- `replacementDylib` 需要导出与原库匹配的函数签名。
- 这适合做可替换后处理、middleware hook，或让用户提供自定义 compute 行为。

### Metal Developer Tools：把 GPU 构建流程搬到命令行

（[23:55](https://developer.apple.com/videos/play/wwdc2020/10615/?time=1435)）session 后半段介绍了新的 Metal Developer Tools。工具链刻意模仿 CPU 构建流程：先用 `metal` 把 shader 源码编译成 AIR，再用库工具和 linker 组合成 executable、static 或 dynamic MetalLib。

```sh
xcrun -sdk iphoneos metal -c Lighting.metal -o Lighting.air
xcrun -sdk iphoneos metal -c Materials.metal -o Materials.air
xcrun -sdk iphoneos metal-libtool -static Lighting.air Materials.air -o libUtility.metallib
xcrun -sdk iphoneos metal Main.air -lUtility -o AppShaders.metallib
```

关键点：

- `metal -c` 生成 AIR 文件。
- `metal-libtool -static` 把多个 AIR 文件归档成静态库。
- `-lUtility` 让 linker 链接 utility 库。
- 静态链接生成的 executable MetalLib 自包含，但多个 executable 可能重复包含同一份 utility 代码。

（[26:05](https://developer.apple.com/videos/play/wwdc2020/10615/?time=1565)）动态库的命令行入口是 linker 的 `-dynamiclib` 和 `-install_name`。这对应前面 API 里的 `libraryType` 和 `installName`。

```sh
xcrun -sdk iphoneos metal Utility.air -dynamiclib \
  -install_name @loader_path/libUtility.metallib \
  -o libUtility.metallib

xcrun -sdk iphoneos metal Main.air -lUtility -o AppShaders.metallib
```

关键点：

- `-dynamiclib` 生成动态 MetalLib。
- `-install_name` 会被记录到 load command，运行时 loader 用它定位动态库。
- `@loader_path` 指向包含 load command 的 MetalLib 所在路径。
- 动态库需要随应用一起部署，运行时找不到会导致 executable MetalLib 无法工作。

（[29:53](https://developer.apple.com/videos/play/wwdc2020/10615/?time=1793)）动态链接还带来符号可见性问题。默认情况下，Metal 会导出库里的所有符号。session 建议用 `metal-nm` 检查导出符号，用 `static`、匿名 namespace、visibility attributes、namespace 和 `exported-symbols-list` 控制接口边界。

```sh
xcrun -sdk iphoneos metal-nm libUtility.metallib
```

关键点：

- `metal-nm` 用来检查 MetalLib 导出的符号名。
- 如果两个动态库导出同名函数，loader 可能在运行时绑定到非预期实现。
- 控制导出符号可以减少命名冲突，也能让动态库接口更清楚。

（[31:02](https://developer.apple.com/videos/play/wwdc2020/10615/?time=1862)）收割自设备的 MetalLib 可能包含多个 slice。`metal-lipo` 用来查看和合并这些 slice。session 的例子中，一个 A13 设备收割出的 MetalLib 同时包含 A13 后端编译 slice 和通用 AIR slice；在 A13 上可以跳过后端编译，在其他设备上仍可用 AIR 回退。

```sh
xcrun -sdk iphoneos metal-lipo -info libUtility.metallib
xcrun -sdk iphoneos metal-lipo -create libUtility-A13.metallib libUtility-A12.metallib \
  -output libUtility-universal.metallib
```

关键点：

- `metal-lipo -info` 查看 MetalLib 里有哪些架构 slice。
- `metal-lipo -create` 可以合并多个收割结果。
- slice 越多，App bundle 越大，需要按目标设备和启动收益取舍。

（[34:40](https://developer.apple.com/videos/play/wwdc2020/10615/?time=2080)）最后一个工具链更新是 Metal Developer Tools on Windows。Apple 明确说，Xcode 工具链支持的 workflow，也被 Windows hosted tools 支持。这对已有 Windows 资产构建农场的游戏团队很重要。

## 核心启发

- **做什么**：给大型游戏做首启 pipeline 资产包。**为什么值得做**：Binary Archives 可以把关键 PSO 的后端编译结果随 App 分发，session 中 Fortnite workload 的 pipeline build 时间从 1 分 26 秒降到 3 秒。**怎么开始**：在自动化测试或构建设备上运行覆盖主要关卡的场景，调用 `addRenderPipelineFunctions`、`addComputePipelineFunctions` 收集 archive，再把 `.metallib` 打进 bundle。

- **做什么**：把常用 compute 后处理函数抽成 Metal 动态库。**为什么值得做**：`MTLDynamicLibrary` 可以让多个 compute pipeline 共享同一份 utility 机器码，减少重复编译和重复存储。**怎么开始**：先把 utility shader 编译为 `.dynamic` library，为它设置 `installName`，再在 kernel 编译时通过 `MTLCompileOptions.libraries` 声明依赖。

- **做什么**：做一个可替换的图像滤镜插件点。**为什么值得做**：`insertLibraries` 允许在 pipeline 创建时优先搜索插入的动态库，session 的示例就是用动态库改变全屏后处理的像素颜色函数。**怎么开始**：定义稳定的函数签名和 header，让默认库与替换库导出同名函数，在创建 compute pipeline 时传入用户选择的 replacement dylib。

- **做什么**：把 shader 构建拆成可审计的 CI 步骤。**为什么值得做**：`metal-libtool`、`metal-nm`、`metal-lipo` 让 MetalLib 的归档、符号检查和 slice 合并都可以在脚本里完成。**怎么开始**：CI 中先生成 AIR，再构建 static 或 dynamic MetalLib，随后用 `metal-nm` 检查导出符号，用 `metal-lipo -info` 记录发布包包含的 GPU slice。
