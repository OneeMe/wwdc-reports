## Highlight

> Xcode 27 把 String Catalogs 积累了三年的代码上下文（字符串在哪里用、怎么用、周围有什么相关术语）全部喂给 Coding Agent，让 AI 翻译不再是"盲翻"。你只需要在 Xcode 里点一下"New Conversation"，Agent 就会自动 Build 项目、提取字符串、分批派发给子 Agent 翻译，还能处理复数变化和语序差异。

---

## 核心内容

### 1. 这场演讲解决什么问题

App 本地化一直是独立开发者和小团队的痛点：

- 找外包翻译又贵又慢
- 用通用机翻，"book" 到底是"书"还是"预订"完全靠猜
- 处理复数形式（one item / two items）需要手动维护多条规则
- 不同语言的语序差异（如日语的动词在句尾）让格式化字符串经常出错

Xcode 27 的解法很直接：**让 Agent 用代码上下文来做软件本地化**。

### 2. String Catalogs 的上下文积累

Apple 从三年前开始为 String Catalogs 积累上下文：

- **第一年**：记录字符串在代码中的位置
- **第二年**：记录字符串的使用方式，自动生成描述性注释
- **今年（Xcode 27）**：把所有上下文整合，直接驱动 Agent 翻译

这意味着 Agent 翻译时知道：
- 这个字符串出现在哪个 UI 组件里
- 周围有哪些使用相同术语的字符串
- 这个字符串在其他语言里是怎么翻译的

### 3. Agent 翻译的工作流程

整个流程完全自动化：

1. **准备项目**：Agent 让 Xcode 添加目标语言 → Build 所有 Target → 自动创建 String Catalogs
2. **选择字符串**：Agent 读取所有需要翻译的 String Catalog
3. **分批翻译**：Agent 把字符串拆成批次，委派给多个子 Agent 并发处理
4. **上下文注入**：Xcode 给每个子 Agent 提供代码位置、相关术语、其他语言参考等上下文

```swift
// SwiftUI 中自动暴露给本地化的字符串
Text("Hello, world!", comment: "A standard greeting")

// 使用自定义 table name 组织字符串
Text("Hello, world!", tableName: "Greetings", comment: "A standard greeting")

// 非 SwiftUI 场景下的本地化
String(localized: "Hello, world!", comment: "A standard greeting")
LocalizedStringResource("Hello World!", bundle: #bundle, comment: "A standard greeting")
```

### 4. 复数形式和语序处理

Agent 能自动处理复数变化。比如 `%lld items` 这个字符串：

- 英语：`one item` / `two items`
- 加拿大法语：`un élément` / `deux éléments`
- Agent 会根据目标语言的复数规则自动生成正确的变体

Xcode 会确保子 Agent 始终知道目标语言需要多少种复数变体，不需要你手动配置。

### 5. 迭代和审阅

翻译完成后，你可以直接在 Xcode 里审阅和迭代：

- 在 Scheme 设置里切换 App 语言，直接运行看效果
- 对不满意的翻译，让 Agent 基于你的反馈重新调整
- Agent 会找到所有相关字符串并统一更新（比如修改 App 名称后，所有引用该名称的地方都会同步）

XLIFF 导出时，机器翻译的字符串会标记 `state-qualifier="leveraged-mt"`，方便你和专业翻译人员协作：

```xml
<trans-unit id="Grand Canyon" xml:space="preserve">
  <source>Grand Canyon</source>
  <target state="translated" state-qualifier="leveraged-mt">Grand Canyon</target>
  <note>Name of the 'Grand Canyon' landmark.</note>
</trans-unit>
```

## 最佳实践

- **已有项目迁移**：先别急着让 Agent 翻译全量。先在一个小模块里跑通 String Catalogs 的提取流程，检查自动生成的 `comment` 是否准确。把历史遗留的 `.strings` 文件全部转换为 `.xcstrings` 格式，这是 Agent 工作的前提
- **新项目建议**：默认开启 String Catalogs，并在写代码时养成顺手写 `comment` 的习惯。把 AI 当成你的结对编程同事，你给的上下文越具体，它翻译得越准
- **避免动态拼接**：`"Score: " + String(score)` 这种写法 Agent 无法处理复数和语序问题。必须改成 `"Score: %lld"` 的格式化字符串，让 Agent 去处理不同语言的语序差异
- **专有名词处理**：App 名称、品牌词等专有名词，建议在第一次翻译时手动确认，然后让 Agent 以此为基准统一处理后续出现
