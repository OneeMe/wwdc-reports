## Highlight

> SwiftUI 今年在三个维度同时发力：Liquid Glass 设计自动升级无需改代码；全新的 Document API 支持直接磁盘访问和 snapshot-based diffing，大文件处理不再卡 UI；Toolbar 终于有了可见性优先级和溢出菜单，iPad/Mac 的多窗口体验终于像样了。

---

## 核心内容

### 1. 这场演讲解决什么问题

SwiftUI 开发者长期面临几个痛点：

- 文档类 App 处理大文件时，`FileDocument` 要把整个文件读进内存，保存时 UI 冻结
- Toolbar 按钮在窗口缩小时被系统随意隐藏，重要操作找不到
- List 以外的容器（Grid、Stack）不支持拖拽排序
- Swipe Actions 只能在 List 里用
- `@State` 包裹 class 类型时每次视图更新都创建临时实例，浪费内存

今年的更新一次性解决了这些问题。

### 2. Liquid Glass 设计更新（自动，零代码）

用 Xcode 27 编译的 App 自动获得 Liquid Glass 更新：

- 更深的边缘 + 更亮的高光，增强层次感
- 透明度滑块：用户可以在设置中调节 Liquid Glass 的透明度
- macOS 支持 `show borders` 环境值
- iPad 非活跃窗口自动变暗，图标和文字 dimming
- 自定义 Liquid Glass 元素可以标记为 `interactive`，鼠标点击响应更流畅

```swift
struct SidebarFooterView: View {
    @Environment(\.appearsActive) private var appearsActive

    var body: some View {
        MyAccountView()
            .opacity(appearsActive ? 1 : 0.5)  // 非活跃窗口自动变暗
    }
}
```

### 3. Toolbar 改进：终于能控制按钮优先级了

```swift
StickerPageView()
    .toolbar {
        ToolbarItemGroup {
            UndoButton()
            RedoButton()
        }
        .visibilityPriority(.high)  // 空间不足时优先保留

        ToolbarOverflowMenu {
            ChoosePhotoButton()
            ExportAsImageButton()
            ClearAllStickersButton()
        }

        ToolbarItem(placement: .topBarPinnedTrailing) {
            ShareButton()  // 始终固定在右侧
        }
    }
```

- `.visibilityPriority(.high/.low)`：空间不足时按优先级保留或隐藏
- `.topBarPinnedTrailing`：不受 toolbar 重排影响，始终固定
- `ToolbarOverflowMenu`：自动收纳低优先级按钮到溢出菜单
- `toolbarMinimizeBehavior(.onScrollDown)`：滚动时自动收起导航栏

### 4. 全新 Document API：直接磁盘访问 + Snapshot Diffing

旧的 `FileDocument` 协议要求把整个文件读进内存。新的 `WritableDocument` / `ReadableDocument` 协议支持：

- 直接通过 URL 访问磁盘，不需要把大文件加载到内存
- Snapshot-based diffing：只保存变化的部分，而不是整个文件
- 异步读写，不阻塞主线程
- 支持进度报告

```swift
@Observable
final class StickerDocument: WritableDocument {
    static let writableDocumentTypes: [UTType] = [.stickerDocument]

    @MainActor
    func snapshot(contentType: UTType) async throws -> sending PageSnapshot {
        makeSnapshot()
    }

    func writer(configuration: sending WriteConfiguration) -> sending Writer {
        Writer(contentType: configuration.contentType)
    }
}

struct Writer<Snapshot>: DocumentWriter {
    typealias Snapshot = PageSnapshot
    let contentType: UTType

    nonisolated func write(
        snapshot: sending PageSnapshot,
        to destination: URL,
        previous: sending PageSnapshot?,
        progress: consuming Subprogress
    ) async throws {
        // 直接写磁盘，支持进度报告
    }
}
```

支持多格式导出：

```swift
@Observable
final class StickerDocument: WritableDocument {
    static let writableContentTypes: [UTType] = [.stickerDocument, .png]
}
```

### 5. 交互改进：Reorderable 和 Swipe Actions 扩展到任意容器

**Reorderable 不再仅限 List**：

```swift
List {
    ForEach(stickers) { sticker in
        StickerListItemView(sticker: sticker)
    }
    .reorderable()
}
.reorderContainer(for: Sticker.self) { difference in
    difference.apply(to: &stickers)
}

// Grid 也可以
LazyVGrid {
    ForEach(stickers) { sticker in
        StickerListItemView(sticker: sticker)
    }
    .reorderable()
}
.reorderContainer(for: Sticker.self) { difference in
    difference.apply(to: &stickers)
}
```

**Swipe Actions 扩展到任意可滚动容器**：

```swift
ScrollView {
    LazyVStack {
        ForEach(stickers) { sticker in
            StickerListItemView(sticker: sticker)
                .swipeActions {
                    DeleteButton(sticker: sticker)
                }
        }
    }
}
.swipeActionsContainer()  // 让父容器接收 swipe 事件
```

### 6. 性能提升（无需改代码）

- `@State` 改为宏实现，class 类型的状态对象延迟初始化，避免重复创建临时实例
- `AsyncImage` 自动使用 HTTP 缓存
- SwiftUI、AppKit、UIKit 共享更多底层控件实现
- 嵌套 Stack 布局的测量计算优化，resize 速度提升 2 倍

```swift
// 以前：每次视图更新都创建 StickerStore 临时实例
@Observable class StickerStore { }
struct StickerStoreView: View {
    @State private var store = StickerStore()  // 现在延迟初始化
    // ...
}
```

### 7. Presentation API 扩展

`confirmationDialog` 和 `alert` 现在支持 item binding：

```swift
struct StickerCanvasView: View {
    var stickers: [Sticker]
    @State private var stickerToDelete: Sticker?

    var body: some View {
        ZStack {
            ForEach(stickers) { sticker in
                PlacedStickerView(sticker: sticker)
                    .contextMenu { /* ... */ }
            }
        }
        .confirmationDialog("Delete?", item: $stickerToDelete) { sticker in
            DeleteStickerButton(sticker)
        }
    }
}
```

## 最佳实践

- **文档类 App 立刻迁移到新 Document API**：大文件场景下直接磁盘访问能彻底解决 UI 冻结问题
- **用 `visibilityPriority` 替代硬编码的 size class 判断**：把 Toolbar 排布控制权交还给系统
- **Grid/Stack 里的拖拽排序直接用 `.reorderable()`**：不需要再依赖第三方库或自己实现
- **注意 `@State` 宏的初始化变化**：如果之前在 `init` 里给 `@State` 赋值，现在需要去掉默认值才能编译通过
