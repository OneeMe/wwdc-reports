## Highlight

> `AVCaptureSession` 启动时初始化沉重的 `AVCaptureOutput`（如 `AVCapturePhotoOutput`）极其耗时，导致首帧预览慢半拍，用户经常错过精彩瞬间。iOS 26 把启动流程拆成两半——预览层先跑起来，拍照和录像的 Output 延后初始化。配合全新的 `AVProVideoStorage` API，高码率视频写入时的 I/O 抖动问题也迎来了终结。

---

## 核心内容

### 1. 这场演讲解决什么问题

相机 App 的启动速度直接决定用户能不能"抓拍到瞬间"。但 `AVCaptureSession` 的启动流程存在天然的性能瓶颈：

1. App 启动（二进制加载、静态初始化、UI 创建）
2. Session 配置和启动（初始化 capture session、commit configuration、start running）
3. Output 初始化（每个 `AVCaptureOutput` 的创建和配置）
4. 首帧预览（视频流开始输出到屏幕）

第 2、3 步尤其耗时，因为 `AVCapturePhotoOutput` 和 `AVCaptureMovieFileOutput` 需要大量系统资源分配。以前所有 Output 必须在 `startRunning()` 前配置好，导致预览被"堵"在后面。

### 2. Deferred Start：延迟启动策略

iOS 26 引入了 Deferred Start 机制，把 Output 分成两类：

- **立即启动**：`AVCaptureVideoPreviewLayer`（预览层）
- **延迟启动**：`AVCapturePhotoOutput`、`AVCaptureMovieFileOutput` 等重型 Output

**自动延迟启动模式：**

```swift
import AVFoundation

let captureSession = AVCaptureSession()
captureSession.beginConfiguration()
captureSession.automaticallyRunsDeferredStart = true

let videoPreviewLayer = AVCaptureVideoPreviewLayer(session: captureSession)
videoPreviewLayer.isDeferredStartEnabled = false  // 预览层立即启动

let photoOutput = AVCapturePhotoOutput()
photoOutput.isDeferredStartEnabled = true  // 拍照输出延迟启动
captureSession.addOutput(photoOutput)

captureSession.setDeferredStartDelegate(deferredStartDelegate, deferredStartDelegateCallbackQueue: sessionQueue)

captureSession.commitConfiguration()
captureSession.startRunning()
```

Delegate 实现：

```swift
class DeferredStartDelegate: NSObject, AVCaptureSessionDeferredStartDelegate {
    func sessionWillRunDeferredStart(_ session: AVCaptureSession) {
        // 延迟启动开始前调用
    }

    func sessionDidRunDeferredStart(_ session: AVCaptureSession) {
        // 所有延迟输出初始化完成后调用
    }
}
```

关键点：

- `automaticallyRunsDeferredStart = true` 让系统自动管理延迟启动。
- 每个 Output 通过 `isDeferredStartEnabled` 单独控制是否延迟。
- Delegate 在延迟启动的开始和结束时分发回调，可以在这里更新 UI（比如显示"相机准备中"）。

**手动延迟启动模式：**

如果你需要更精细的控制，可以用手动模式：

```swift
captureSession.beginConfiguration()
captureSession.automaticallyRunsDeferredStart = false

let videoOutput = AVCaptureVideoDataOutput()
captureSession.addOutput(videoOutput)
videoOutput.isDeferredStartEnabled = false  // 视频输出立即启动

let photoOutput = AVCapturePhotoOutput()
photoOutput.isDeferredStartEnabled = true   // 拍照输出延迟
captureSession.addOutput(photoOutput)

captureSession.setDeferredStartDelegate(deferredStartDelegate, deferredStartDelegateCallbackQueue: sessionQueue)

captureSession.commitConfiguration()
captureSession.startRunning()
```

在首帧预览上屏后手动触发延迟启动：

```swift
import AVFoundation
import QuartzCore

private var firstFramePresented = false

guard let drawable = layer.nextDrawable()
if (!firstFramePresented) {
    drawable.addPresentedHandler({ drawable in
        // 首帧已上屏，设置延后显示的 UI 元素
        captureSession.runDeferredStartWhenNeeded()
    })
    firstFramePresented = true
}
```

关键点：

- 手动模式适合需要精确控制时机的场景。
- `runDeferredStartWhenNeeded()` 在合适的时机触发延迟输出的初始化。
- 通过 `CAMetalDrawable` 的 `addPresentedHandler` 可以精确知道首帧何时上屏。

### 3. Responsive Capture：响应式拍摄

除了启动优化，拍照响应速度也有新 API：

```swift
import AVFoundation

func configurePhotoOutput(for session: AVCaptureSession, device: AVCaptureDevice) {
    let photoOutput = AVCapturePhotoOutput()

    guard session.canAddOutput(photoOutput) else { return }
    session.addOutput(photoOutput)

    photoOutput.maxPhotoQualityPrioritization = .quality
    // 启用响应式拍摄，让 photo output 立即响应拍摄请求
    photoOutput.isResponsiveCaptureEnabled = photoOutput.isResponsiveCaptureSupported
}
```

关键点：

- `isResponsiveCaptureEnabled` 让拍照输出在尚未完全初始化时也能响应拍摄请求。
- 需要检查 `isResponsiveCaptureSupported`，不是所有设备都支持。
- 和 Deferred Start 配合使用，实现"预览先出、拍摄随按随有"的体验。

### 4. 监控系统压力

相机是资源密集型功能，需要持续监控系统压力：

```swift
import AVFoundation

let captureSession = AVCaptureSession()
let device = activeVideoInput?.device

captureSession.beginConfiguration()
// ... 配置 session ...
captureSession.commitConfiguration()

// 检查硬件成本是否可承受
guard captureSession.hardwareCost <= 1.0 else {
    print("hardwareCost \(captureSession.hardwareCost) — cannot start session. Reconfiguring.")
    setupLowCostConfiguration()
}

captureSession.startRunning()

// 监听系统压力变化
let systemPressureObserver = device?.observe(\.systemPressureState,
                                               options: [.initial, .new],
                                               changeHandler: { device, change in
    // 根据压力状态调整配置
    handleSystemPressureChange(change.newValue)
})
```

关键点：

- `hardwareCost` 表示当前配置的资源消耗，超过 1.0 说明配置太重，需要降级。
- `systemPressureState` 实时反映设备 thermal 状态，压力升高时需要降低分辨率或帧率。
- 观察者在设备对象上注册，压力变化时自动回调。

### 5. AVProVideoStorage：确定性视频写入

高码率视频（如 ProRes）写入时的 I/O 抖动会导致掉帧。iOS 26 引入了 `AVProVideoStorage`：

```swift
import AVFoundation

func configureProVideoStorage() {
    guard AVProVideoStorage.isSupported else { return }
    let storage = AVProVideoStorage.shared
    guard storage.remainingCapacity != 0 else {
        storage.openSettings()
        return
    }
}
```

在录制时使用：

```swift
guard AVProVideoStorage.isSupported else { return }
guard let pvs = AVProVideoStorage.shared else { return }

// 配置 AVCaptureSession、AVCaptureConnections 和格式
// ...

let movieOutput = AVCaptureMovieFileOutput()

guard movieOutput.isProVideoStorageSupported else { return }
guard !pvs.isBusy else { return }

let movieFileURL = FileManager.default.temporaryDirectory
    .appendingPathComponent(UUID().uuidString)
    .appendingPathExtension("mov")

movieOutput.usesProVideoStorage = true  // AVAssetWriter 也支持
movieOutput.startRecording(to: movieFileURL, recordingDelegate: delegate)
```

关键点：

- `AVProVideoStorage` 提供确定性的文件写入速度，消除 I/O 抖动。
- 需要检查 `isSupported` 和 `isProVideoStorageSupported`，不是所有设备都支持。
- `remainingCapacity` 检查存储空间，不足时引导用户清理。
- `usesProVideoStorage = true` 同时支持 `AVCaptureMovieFileOutput` 和 `AVAssetWriter`。

### 6. UI 启动优化

启动速度不只是底层 API 的问题，UI 设计也至关重要：

**两阶段启动策略：**

- **第一阶段**（立即显示）：相机预览 + 快门按钮
- **第二阶段**（Deferred Start 完成后淡入）：相册缩略图、模式选择器、滤镜等

```swift
// 伪代码示意
struct CameraView: View {
    @State private var isPreviewReady = false

    var body: some View {
        ZStack {
            CameraPreview()
            ShutterButton()

            // 第二阶段 UI，延迟显示
            if isPreviewReady {
                PhotoThumbnail()
                    .transition(.opacity)
                ModePicker()
                    .transition(.opacity)
            }
        }
        .onReceive(deferredStartPublisher) { _ in
            withAnimation {
                isPreviewReady = true
            }
        }
    }
}
```

## 最佳实践

- **已有项目迁移**：最快的方式是直接升级到 iOS 26 SDK 并重新编译。Apple 把 `automaticallyRunsDeferredStart` 默认设为了 `true`，只要你没有写死复杂的 Session 状态机，通常能白嫖到启动速度的提升。然后逐步把重型 Output 标记为 `isDeferredStartEnabled = true`。

- **新项目建议**：直接采用手动 Deferred Start 模式。把 UI 也分两阶段：第一阶段只渲染取景框和快门，第二阶段（首帧上屏后）再淡入相册缩略图、滤镜选择器等重型 UI。同时启用 `isResponsiveCaptureEnabled` 确保用户随时能按下快门。

- **实战中容易踩的坑**：
  - `AVCaptureSession` 的 `startRunning()` 和 `commitConfiguration()` 依然是同步阻塞调用。千万别在 `viewDidLoad` 里直接调，老老实实 dispatch 到专门的 `sessionQueue` 串行队列里执行。
  - Deferred Start 只延迟 Output 的初始化，Input（摄像头）仍然需要在 `startRunning()` 前配置好。
  - `hardwareCost` 超过 1.0 时不要强行启动，否则会导致系统不稳定或崩溃。
  - `AVProVideoStorage` 需要独占存储空间，如果用户同时运行多个使用 Pro Video Storage 的 App，可能会互相抢占资源。
  - 系统压力观察者的回调可能在任意线程，记得 dispatch 到主线程更新 UI。
