## Highlight

> 几台 Mac 用 Thunderbolt 5 线连起来，通过 RDMA 直接内存访问和 JACCL 集合通信库，就能组成一个能跑百亿参数模型推理和微调的分布式集群——不需要云 GPU，不需要 InfiniBand，你的桌面就是数据中心。

---

## 核心内容

### 1. 这场演讲解决什么问题

本地 LLM 推理和训练面临一个硬瓶颈：**单台设备的内存和算力有限**。

- 一个 70B 参数的 FP16 模型需要约 140GB 内存，超过了大多数单台 Mac 的容量。
- 即使模型能塞进内存，生成速度也会随着 batch size 和序列长度急剧下降。
- 微调（fine-tuning）需要同时保存模型参数、梯度和优化器状态，内存需求是推理的 3-4 倍。

传统的解决方案是租用云 GPU，但成本高、数据要出域、延迟不可控。

Apple 的解法是：**把多台 Mac 组成集群，用高速互联分担负载**。从 macOS 26.2 开始，Thunderbolt 5 支持 RDMA（Remote Direct Memory Access），让一台 Mac 可以直接读写另一台的内存，绕过 CPU 和操作系统开销。

---

### 2. 硬件和软件栈

分布式 MLX 需要三层基础设施：

**物理层 —— Thunderbolt 5 + RDMA**

- Thunderbolt 5 提供 80Gbps 双向带宽。
- RDMA 让数据直接从一台 Mac 的内存传输到另一台，不需要经过 CPU 拷贝或系统内核。
- 这意味着 All-Reduce 等集合通信操作的延迟极低，接近单机多 GPU 的体验。

**通信层 —— JACCL**

JACCL（Just Another Collective Communication Library）是 Apple 开源的集合通信库，基于 RDMA 实现：

- `all_sum`：所有节点的数据求和，结果分发回所有节点（用于梯度同步）。
- `all_gather`：收集所有节点的数据片段，拼接成完整结果。
- `broadcast`：一个节点发送数据到所有节点。

**计算层 —— MLX**

MLX 框架自动处理：

- 模型分片（sharding）：把大模型的层或张量切分到不同设备。
- 流水线并行（pipeline parallelism）：把模型的不同层放在不同 Mac 上，数据按顺序流过。
- 张量并行（tensor parallelism）：把同一层的张量切分到多个设备并行计算。

### 3. 配置集群

**第一步：创建 hostfile**

hostfile 描述集群中每台机器的网络配置：

```json
[
  {
    "ssh": "m3-ultra-0",
    "ips": ["192.168.1.10"],
    "rdma": [null, "rdma_en5", "rdma_en4", "rdma_en3"]
  },
  {
    "ssh": "m3-ultra-1",
    "ips": ["192.168.1.11"],
    "rdma": ["rdma_en5", null, "rdma_en4", "rdma_en3"]
  },
  {
    "ssh": "m3-ultra-2",
    "ips": ["192.168.1.12"],
    "rdma": ["rdma_en5", "rdma_en4", null, "rdma_en3"]
  },
  {
    "ssh": "m3-ultra-3",
    "ips": ["192.168.1.13"],
    "rdma": ["rdma_en5", "rdma_en4", "rdma_en3", null]
  }
]
```

`rdma` 数组中的 `null` 表示"这台机器和对应索引的机器之间不需要 RDMA 连接"（通常是自己和自己）。非 null 值是 RDMA 网卡接口名。

**第二步：自动生成配置**

```bash
mlx.distributed_config \
    --hosts m3-ultra-0,m3-ultra-1,m3-ultra-2,m3-ultra-3 \
    --output "m3-ultra-jaccl.json" \
    --env MLX_METAL_FAST_SYNCH=1 \
    --auto-setup \
    --backend jaccl
```

`--auto-setup` 会自动配置 SSH 免密登录和 RDMA 网络。`MLX_METAL_FAST_SYNCH=1` 启用 Metal 快速同步，减少 GPU 等待时间。

### 4. 分布式推理

**单设备 vs 分布式对比：**

```bash
# 单机推理
mlx_lm.chat --model "Qwen/Qwen3.6-27B" --max-tokens 2048

# 分布式推理（4 台 Mac）
mlx.launch --hostfile "m3-ultra-jaccl.json" -- \
    /remote/path/to/mlx_lm.chat --model "Qwen/Qwen3.6-27B" --max-tokens 2048
```

代码完全一样，只是用 `mlx.launch` 包装一下。MLX 自动把模型切分到集群中的每台 Mac 上。

**超大模型的流水线并行：**

对于内存需求超过集群总容量的模型（如 1T 参数的 Kimi-K2.6），用流水线并行：

```bash
# 张量并行（默认）
mlx.launch --hostfile "m3-ultra-jaccl.json" -- \
    /remote/path/to/mlx_lm.chat --model "moonshotai/Kimi-K2.6" \
                                 --max-tokens 2048

# 流水线并行（加 --pipeline 标志）
mlx.launch --hostfile "m3-ultra-jaccl.json" -- \
    /remote/path/to/mlx_lm.chat --model "moonshotai/Kimi-K2.6" \
                                 --max-tokens 2048 \
                                 --pipeline
```

关键点：

- 张量并行适合模型能放进集群总内存的场景，通信开销小。
- 流水线并行适合超大模型，每层放在不同设备上，但会有气泡（bubble）延迟。

---

### 5. 分布式微调

微调时，batch size 可以随设备数量线性扩展：

```bash
# 单机微调
mlx_lm.lora --model "Qwen/Qwen3.5-9B" \
             --data "mlx-community/wikisql" \
             --train --batch-size 4

# 分布式微调（4 台设备，batch size 乘以 4）
mlx.launch --hostfile "hostfile.json" -- \
    /remote/path/to/mlx_lm.lora --model "Qwen/Qwen3.5-9B" \
                                  --data "mlx-community/wikisql" \
                                  --train --batch-size 16
```

MLX 自动处理梯度同步：每个设备计算本地梯度 → JACCL 的 `all_sum` 汇总所有梯度 → 平均后更新模型参数。

### 6. Python API：自定义分布式逻辑

如果 CLI 工具不能满足需求，直接用 Python API：

```python
import mlx.core as mx
from mlx_lm import stream_generate
from mlx_lm.utils import sharded_load

# 初始化分布式后端
group = mx.distributed.init(strict=True, backend="jaccl")

# 定义并行策略：张量并行 + 可选流水线并行
tensor_group, pipeline_group = group, None

# 加载分片模型
model, tokenizer = sharded_load("moonshotai/Kimi-K2.6", pipeline_group, tensor_group)

# 流式生成
for response in stream_generate(model, tokenizer, prompt, max_tokens=1024):
    if group.rank() == 0:
        print(response.text, end="", flush=True)
```

**自定义分片层：**

```python
import mlx.core as mx
import mlx.nn as nn

# 初始化分布式
group = mx.distributed.init(strict=True, backend="jaccl")

# 创建一个线性层并按列分片
layer = nn.Linear(1024, 1024)
sharded_layer = nn.layers.distributed.shard_linear(
    layer, strategy="all-to-sharded", group=group
)

# 前向传播
data = mx.random.normal((1, 1, 1024))
output = sharded_layer(data)
mx.eval(output)
```

**All-Reduce 操作（Python / Swift / C++）：**

```python
# Python
import mlx.core as mx
world = mx.distributed.init(strict=True, backend="jaccl")
data = mx.full((4,), float(world.rank()), dtype=mx.float32)
result = mx.distributed.all_sum(data, group=world)
mx.eval(result)
```

```swift
// Swift
let group = try DistributedGroup(strict: .ring)
let data = rank == 0
    ? MLXArray(converting: [1.0, 2.0, 3.0])
    : MLXArray(converting: [5.0, 6.0, 7.0])
let result = try group.allSum(data)
```

```cpp
// C++
namespace mx = mlx::core;
auto world = mx::distributed::init(/* strict */ true, "jaccl");
mx::array data = mx::full({4}, static_cast<float>(world.rank()), mx::float32);
mx::array result = mx::distributed::all_sum(data, world);
mx::eval(result);
```

三种语言的 API 设计一致，方便在不同场景下切换。

## 最佳实践

- **先用 CLI 验证集群**：在写 Python 代码之前，先用 `mlx_lm.chat` 和 `mlx.launch` 确认物理连接和 RDMA 配置正确。物理层的坑比代码难排查。

- **Thunderbolt 5 是必须的**：不要用 Wi-Fi 或普通 USB-C 线。80Gbps 的 Thunderbolt 5 带宽是张量并行的生命线，降级到 USB4 或 Wi-Fi 会让分布式优势荡然无存。

- **检查 RDMA 启用状态**：在系统设置中确认 RDMA 没有被安全策略拦截。macOS 默认可能因防火墙规则阻止直接内存访问。

- **batch size 随设备数扩展**：分布式微调时，把 batch size 设为单机值的 N 倍（N 是设备数量）。MLX 会自动同步梯度，不需要手动处理。

- **从张量并行开始**：如果模型能放进集群总内存，优先用张量并行（默认）。流水线并行只在模型实在太大时才需要，因为它会引入气泡延迟。
