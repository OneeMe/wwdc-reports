## Highlight

> 作为 Design for intelligence 系列第三讲，Apple 把“发现”落到 Shortcuts、Siri Suggestions widget、Search、Lock Screen、Sharing Suggestions、Calendar 和 Maps 等系统入口，让 App 功能在主屏之外被用户找到。

## 核心内容

很多 App 的问题不在功能少，而在入口太窄。用户必须记得 App 名称，打开主屏图标，再沿着导航层级找到某个功能。功能越多，这条路径越依赖用户记忆；用户越忙，越不会主动想起你的 App 可以帮他完成什么。

JP Lacerda 在这场 session 里把 intelligence 定义成系统和 App 的协作。系统理解用户的目标、习惯、偏好和关系；App 则把自己的能力接到系统入口里。这样，App 不再只是一个 monolithic container。它的功能可以出现在 Search、Lock Screen、Calendar、Maps、Sharing 或 widget stack 里。

这一讲接在前两讲之后，重点从“为什么要智能设计”和“如何与系统协作”转向“用户怎样发现这些能力”。逐字稿里的例子很具体：Shortcuts 可以通过点击或 Siri 运行；Siri Suggestions widget、Search 和 Lock Screen 可以展示相关建议；iOS 14 的 Smart Stack 会在合适时间把 widget 放到栈顶；Siri Event Suggestions 可以把餐厅预约带进 Calendar，并在出发前通过 Lock Screen 提醒用户。

Apple 还给了评估标准。参与 intelligence 后，目标落在 traffic、utility 和 visibility 上。逐字稿里提到，用户首次使用某个 App 的 Sharing Suggestion 后，平均分享量会变成之前的两倍；部分航空公司看到 82% 的 notification check-ins 来自 Siri Event Suggestion check-in action；一些第三方 App 平均每天会在 Lock Screen、Sharing、Search 和其他入口被看到五次。

## 详细内容

### Intelligence 从 App 内扩展到系统入口（[01:24](https://developer.apple.com/videos/play/wwdc2020/10088/?time=84)）

讲者先给出开发者的角色：App 通过与系统集成参与 intelligence，系统因此能把 App 视为超出单一容器的能力集合。这里的关键在于让系统知道哪些 App 能力可以在主屏之外出现；业务逻辑仍由 App 自己负责。

```text
App capability
-> system integration
-> suggestion on behalf of the app
-> entry point beyond the Home Screen
```

关键点：

- App capability 是用户真正想完成的动作或获取的内容。
- system integration 让系统知道这些能力存在，并能在合适入口展示。
- suggestion on behalf of the app 把触达责任从 App 内导航扩展到系统层。
- entry point beyond the Home Screen 是本场 session 的核心收益。

### Shortcuts 把动作带到语音、Search 和 Lock Screen（[01:47](https://developer.apple.com/videos/play/wwdc2020/10088/?time=107)）

Shortcuts 是第一个例子。它让用户通过一次点击或询问 Siri 完成 App 动作。Shortcuts app 内置在 iOS 中，既能配置简单动作，也能配置多步骤 shortcuts 和 automations。动作进入 Shortcuts 后，还可能出现在 Siri Suggestions widget、Search 和 Lock Screen。

```text
Shortcut action
-> tap or Siri
-> Siri Suggestions widget / Search / Lock Screen
```

关键点：

- 这场 session 没有展开 Shortcuts 的实现代码，只强调它作为发现入口的价值。
- 同一个 App 动作进入 Shortcuts 后，可以被用户主动运行，也可以被系统在相关场景中建议。
- 如果用户已经有明确目标，Shortcuts 的价值是减少从主屏进入 App 再导航的步骤。

### Widget 和 Smart Stack 让信息在正确时间出现（[02:12](https://developer.apple.com/videos/play/wwdc2020/10088/?time=132)）

iOS 14 新增的 Smart Stack 是第二个入口。逐字稿里的 Weather widget 例子说明，如果 App 提供 widget，Smart Stack 可以在合适时间把它放到栈顶。这里的“发现”发生在用户扫一眼主屏时：当前最有用的信息被推到更容易看到的位置。

```text
App vends a widget
-> Smart Stack evaluates timing
-> widget moves to the top of the stack
```

关键点：

- widget 适合承载及时信息，不能只是缩小版 App 首页。
- Smart Stack 强调时间相关性，App 应该把最适合被快速扫读的信息放进 widget。
- 这个入口解决的是“用户此刻可能需要什么”，而不是“用户在哪里点开功能”。

### Sharing 和 Siri Event Suggestions 把内容带进其他系统场景（[02:22](https://developer.apple.com/videos/play/wwdc2020/10088/?time=142)）

Sharing Suggestions 面向内容分发。设备上有照片、视频等内容时，系统会帮助用户把内容发给最重要的人或群组。逐字稿随后切到 Siri Event Suggestions：餐厅预约可以自动出现在 Calendar，Lock Screen 可以按交通状况提醒出发，Maps 可以一键给出去机场的路线建议。

```text
reservation in the app
-> Calendar
-> Lock Screen leave-time notification
-> Maps direction suggestion
```

关键点：

- 这类入口要求 App 把结构化信息带到系统里，而不是只在 App 内显示确认页。
- Calendar、Lock Screen 和 Maps 覆盖了用户完成同一件事的连续路径。
- session 只讲机会和设计价值；具体实现应继续看 Siri Event Suggestions 专场。

### 评估 intelligence 要看 traffic、utility 和 visibility（[03:20](https://developer.apple.com/videos/play/wwdc2020/10088/?time=200)）

讲者在指标部分先强调隐私。Apple 使用设备分析来改进产品时，需要用户选择加入；收集的信息不直接识别个人，并且只能在用户明确同意后发送给 Apple。随后，session 用三个数字说明 intelligence 对 App 的影响。

```text
Sharing Suggestion: first engagement -> average sharing volume doubles
Siri Event Suggestion check-in action: 82% of notification check-ins in some airline apps
System visibility: some third-party apps seen five times per day across system entry points
```

关键点：

- traffic 衡量入口是否把用户带回 App 或 App 的能力。
- utility 衡量系统建议是否真的帮用户省下操作。
- visibility 衡量 App 是否在 Lock Screen、Sharing、Search 等入口被用户看见。
- 指标要建立在隐私和用户同意之上。

## 核心启发

### 1. 做一张系统入口映射表

**做什么**：把 App 的核心能力按 Shortcuts、Search、Lock Screen、Sharing、Calendar、Maps 和 widget 分组，标出每个能力最适合出现的位置。

**为什么值得做**：session 的主线是让 App capability 进入主屏之外的 entry points。先做映射，才能判断哪些能力值得交给系统推荐。

**怎么开始**：列出用户最高频的 5 个目标，为每个目标写下触发时机、需要的信息和理想入口；入口不明确的功能先留在 App 内，不急着做系统集成。

### 2. 把重复动作设计成 Shortcut 候选

**做什么**：挑出用户经常重复、目标明确的动作，让它们能通过点击、Siri 或 Shortcuts 自动化被触发。

**为什么值得做**：逐字稿明确说 Shortcuts 可以通过 tap 或 Siri 运行，并能在 Siri Suggestions widget、Search 和 Lock Screen 中获得相关建议。

**怎么开始**：从不需要复杂浏览的动作开始，例如再次下单、开始一段记录、打开某个固定工作流；实现细节继续参考 SiriKit、Shortcuts 和 intents 相关 session。

### 3. 为 widget 选择“此刻最有用”的信息

**做什么**：让 widget 展示用户当前最可能需要的一小块信息，而不是把 App 首页压缩进一个小视图。

**为什么值得做**：iOS 14 的 Smart Stack 可以在合适时间把 widget 放到栈顶，信息是否及时会直接影响它是否值得被展示。

**怎么开始**：为 widget 定义一个清晰问题：用户现在看一眼，需要知道什么；再按时间、地点或日程场景准备不同状态的展示内容。

### 4. 让预订和行程信息进入系统旅程

**做什么**：如果 App 处理餐厅预约、航班、酒店、活动或票务，把这些确认信息设计成可以进入 Calendar、Lock Screen 和 Maps 的结构化事件。

**为什么值得做**：session 中的餐厅和航班例子说明，用户完成预约后还会经历出发提醒、路线规划和 check-in，这些都发生在 App 外。

**怎么开始**：先整理事件对象的基本字段：时间、地点、确认状态、用户下一步动作；具体 API 和 markup 方案放到 Siri Event Suggestions 专场继续实现。

### 5. 单独衡量系统入口带来的效果

**做什么**：为系统入口建立独立的效果看板，跟踪入口曝光、触发、回到 App、完成动作和后续留存。

**为什么值得做**：Apple 用 sharing volume、notification check-ins 和 daily visibility 解释 intelligence 的价值，说明这类集成需要用结果验证。

**怎么开始**：先为每个入口定义一个主要指标：Sharing 看分享量，Event Suggestions 看 check-in 或到达率，widget 看打开或任务完成率；所有统计都要遵守用户同意和隐私边界。
