## Highlight

> Reality Composer Pro 3 的 Script Graph 让你不写一行代码就能构建完整的 3D 交互体验。从拖拽手势到自定义事件，从动画到 SwiftUI 附件，visionOS 游戏开发从未如此简单。

## 核心内容

### 1. 这场演讲解决什么问题

想为 visionOS 做 3D 内容，但不想写代码？Reality Composer Pro 3 的 Script Graph 是答案。它是基于节点的可视化脚本系统，让你通过事件驱动逻辑来构建游戏和交互体验。

### 2. Script Graph 是什么

Script Graph 是 Reality Composer Pro 3 的节点式可视化脚本系统。核心概念：

- **事件驱动**：逻辑由事件触发（如捏合手势、拖拽、碰撞）
- **节点连接**：把事件节点连接到动作节点来定义行为
- **实时测试**：在 Reality Composer Pro 和 Vision Pro 上直接测试

### 3. 基础示例：让物体可拖拽

假设你有一个 Nut Entity，想让用户可以捏住并拖动它：

**第一步：给 Entity 添加组件**

- `InputTargetComponent`：让它成为注视目标
- `CollisionComponent`：定义注视目标的大小
- `HoverEffectComponent`：注视时显示高亮效果

**第二步：创建 Script Graph**

1. 在 Project Browser 中右键 → New → Script Graph
2. 命名为 `dragNut`
3. 给 Nut Entity 添加 `ScriptingComponent`，并分配 `dragNut` Script Graph

**第三步：连接节点**

1. 添加 **On Drag** 事件节点
2. 添加 **Set Transform** 动作节点
3. 把 On Drag 的输出连接到 Set Transform 的触发输入
4. 把 On Drag 的 `Scene Location` 连接到 Set Transform 的 `translation` 输入

这样就完成了——用户可以在 visionOS 中捏住 Nut 并拖动它。

### 4. 实时测试和迭代

Script Graph 最大的优势是快速迭代：

- 在 Reality Composer Pro 中按 Play 按钮，直接在视口中测试
- 切换到 "Preview on Device" 模式，在 Vision Pro 上实时测试
- 不需要编译、构建、部署的循环

### 5. 自定义事件

你可以创建自定义事件来实现更复杂的逻辑。比如当角色到达特定路径点时，触发关卡滚动：

```swift
// 在 Swift 代码中订阅自定义事件
if let scene = entity.scene {
    scene.subscribe(forEventName: "squirrelTalk", on: { event in
        if let sayThis: String = try? event.value("sayThis") {
            self.sayThis = sayThis
        }
    }).store(in: &cancellables)
}
```

### 6. SwiftUI 附件

Script Graph 可以与 SwiftUI 结合，在 3D 场景中添加 2D UI：

```swift
} attachments: {
    Attachment(id: "squirrelTalk") {
        SquirrelTalkAttachmentView(text: sayThis)
    }
}
```

这在游戏中非常有用，比如显示对话气泡、状态面板或交互提示。

### 7. 更复杂的交互模式

演讲演示了一个完整的游戏：

- **捏合事件**：控制树叶的开合动画
- **拖拽事件**：让玩家拖动物体
- **自定义事件**：角色到达路径点时触发关卡滚动
- **碰撞检测**：检测物体之间的交互

所有这些都不需要写代码——只需要在 Script Graph 中连接节点。

## 最佳实践

- **从简单开始**：先实现一个基础交互（如拖拽），测试通过后再添加复杂度
- **利用实时预览**：频繁在 Vision Pro 上测试，确保交互感觉自然
- **组件化设计**：把逻辑拆分成多个 Script Graph，每个负责一个功能
- **结合 SwiftUI 附件**：对于复杂的 UI（如对话、菜单），用 SwiftUI 而不是在 3D 中重建
- **注意性能**：Script Graph 虽然方便，但复杂场景仍然需要关注性能
