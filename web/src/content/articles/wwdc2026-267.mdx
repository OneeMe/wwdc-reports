## Highlight

> Swift Testing 和 XCTest 现在可以和平共处了——同一个测试 target 里既能写 `@Test` 也能写 `XCTestCase`，两种框架的断言可以互相调用。这意味着你不需要一次性重构所有老测试，而是可以逐文件、逐模块地迁移，让 CI 始终绿灯。

---

## 核心内容

### 1. 这场演讲解决什么问题

Swift Testing 去年推出后，很多团队面临一个尴尬局面：

- 新项目想用 Swift Testing，但老项目有几千行 XCTest 代码，重构 ROI 太低
- 两种测试框架不能混用，必须选边站
- 迁移过程中测试覆盖率可能下降，风险太大

今年的测试框架互操作性（Test framework interoperability）解决了这个问题：**同一个 target、同一个文件里，XCTest 和 Swift Testing 可以共存。**

### 2. 核心概念对照

| XCTest | Swift Testing | 说明 |
|--------|---------------|------|
| `XCTestCase` | `@Test` | 声明测试函数 |
| `XCTAssertEqual` | `#expect` | 断言相等 |
| `XCTAssertTrue` | `#expect(...)` | 通用断言 |
| `XCTFail` | `Issue.record` | 无条件失败 |
| `XCTSkip` | `Test.cancel` / `.enabled(if:)` | 跳过测试 |
| `setUp`/`tearDown` | `init`/`deinit` | 测试生命周期 |
| 嵌套循环测试 | `@Test(arguments:)` | 参数化测试 |

### 3. 互操作实战

**在 Swift Testing 中调用 XCTest 断言**：

```swift
import Testing

func checkedTransmitAndReceive(on radio: Radio,
                               packet: Packet,
                               expectedByteCount: Int) throws -> [UInt8] {
    try radio.transmit(bytes: packet.data)
    let bytes = try radio.receive()
    XCTAssertEqual(bytes.count, expectedByteCount)  // XCTest 断言
    return bytes
}

@Test
func pingTest() throws {
    let radio = Radio()
    let bytes = try checkedTransmitAndReceive(on: radio, packet: .ping, expectedByteCount: 8)
    #expect(bytes == [0x00, 0x00, 0xf0, 0x37, 0x0f, 0xc7, 0x00, 0x01])  // Swift Testing 断言
}
```

**在 XCTest 中调用 Swift Testing 断言**：

```swift
class RadioTests: XCTestCase {
    func testPingPacketTransmission() {
        let radio = Radio()
        let bytes = try checkedTransmitAndReceive(on: radio,
                                                  packet: .ping,
                                                  expectedByteCount: 8)
        #expect(bytes == [0x00, 0x00, 0xf0, 0x36, 0x0f, 0xc7, 0x00, 0x02])  // Swift Testing 断言
    }
}
```

**把 XCTFail 迁移到 Issue.record**：

```swift
// 迁移前（XCTest）
func assertUnique(_ fruits: [Fruit], file: StaticString = #filePath, line: UInt = #line) {
    var uniqueNames = Set<String>()
    for name in fruits.map(\.name) {
        if !uniqueNames.insert(name).inserted {
            XCTFail("Duplicate name: \(name)", file: file, line: line)
        }
    }
}

// 迁移后（Swift Testing）
import Testing

func assertUnique(_ fruits: [Fruit], sourceLocation: SourceLocation = #sourceLocation) {
    var uniqueNames = Set<String>()
    for name in fruits.map(\.name) {
        if !uniqueNames.insert(name).inserted {
            Issue.record("Duplicate name: \(name)", sourceLocation: sourceLocation)
        }
    }
}
```

### 4. 常见迁移模式

**跳过测试**：

```swift
// XCTest
func testSwallowFallMigration() async throws {
    try XCTSkipIf(!isFall, "Wrong season for migration")
    // ...
}

// Swift Testing（推荐用 trait）
@Test(.enabled(if: isFall, "Wrong season for migration"))
func `Swallow fall migration`() async throws {
    // ...
}
```

**参数化测试替代嵌套循环**：

```swift
// 迁移前：一个测试函数里嵌套循环
struct BirdTests {
    @Test func `Birds flap wings successfully`() async throws {
        for bird in Aviary.birds {
            for count in (40...100) {
                try await bird.flapWings(count: count)
            }
        }
    }
}

// 迁移后：参数化测试，每个组合独立运行
struct BirdTests {
    @Test(arguments: Aviary.birds, 40...100)
    func `Birds flap wings successfully`(bird: Bird, count: Int) async throws {
        try await bird.flapWings(count: count)
    }
}
```

参数化测试的优势：

- 每个参数组合独立运行，一个失败不影响其他
- 并行执行，测试速度更快
- 失败信息精确指出哪个参数组合出了问题

**测试 precondition failure**：

```swift
// 测试初始化时的 preconditionFailure
@Test func `Bird with empty name crashes`() async throws {
    await #expect(processExitsWith: .failure) {
        _ = Bird(name: "")
    }
}
```

### 5. 严格互操作模式

从命令行运行测试时可以启用严格模式，确保两种框架的测试都能正确执行：

```bash
SWIFT_TESTING_XCTEST_INTEROP_MODE=strict swift test
```

## 最佳实践

- **增量迁移，不要重写**：老测试如果稳定运行，不要动它。新测试用 Swift Testing 写，逐步替换高频修改模块的 XCTest
- **同一个文件可以混用**：直接在老的 `.swift` 测试文件底部 `import Testing`，添加 `@Test` 函数
- **保留 XCTest 的场景**：UI 自动化（XCUITest）和性能测试（`measure`）目前仍需要 XCTest
- **注意 ObjC 异常**：如果业务代码混编了 Objective-C 且可能抛出 `NSException`，必须用 XCTest（ObjC 版本）来测，Swift 代码无法安全捕获 ObjC 异常
- **用参数化测试替代嵌套循环**：把 `for` 循环里的测试逻辑改成 `@Test(arguments:)`，获得更好的并行性和失败定位
