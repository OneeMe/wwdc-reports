## Highlight

> Widget 的核心就三个词：Glanceable（一目了然）、Relevant（相关）、Personalizable（可个性化）。这场演讲从 Widget Extension 的架构讲起，到 Timeline 的刷新机制，再到 Tinted 模式下的渲染适配——帮你把 App 的核心信息推到用户每天看最多的地方。

## 核心内容

### 1. 这场演讲解决什么问题

你的 App 内容再好，用户也得主动打开才能看到。Widget 的价值在于把最关键的信息推到用户每天接触最多的地方：主屏幕、锁屏、StandBy、Apple Watch 表盘、Mac 通知中心。

但做好 Widget 不是简单地把 App 的某个页面缩小。系统对 Widget 的刷新频率、内存占用、渲染模式都有严格限制。这场演讲从架构到细节，讲清楚 Widget 的正确打开方式。

### 2. Widget 的架构：Extension + Timeline

Widget 运行在独立的 Extension 进程中，通过 Timeline 机制向系统提供内容。

```swift
struct DailyReadingGoalWidget: Widget {
    let kind = "DailyReadingGoalWidget"

    var body: some WidgetConfiguration {
        StaticConfiguration(
            kind: kind,
            provider: DailyReadingGoalProvider()
        ) { entry in
            DailyReadingGoalView(
                book: entry.book,
                message: entry.message,
                timeOfDay: entry.timeOfDay
            )
            .environment(\.colorScheme, .dark)
            .containerBackground(for: .widget) {
                Background()
            }
        }
    }
}
```

关键点：

- Widget Extension 是独立进程，App 和 Widget 之间需要通过 App Group 共享数据（如 SwiftData 数据库或 UserDefaults）
- `StaticConfiguration` 用于无需用户配置的 Widget；`AppIntentConfiguration` 用于支持用户自定义的 Widget
- Timeline 由多个 TimelineEntry 组成，每个 entry 对应一个时间点的渲染数据
- 系统会归档渲染好的视图，在对应时间点直接展示，不需要 Widget 进程常驻

### 3. 支持多种尺寸和 Deep Link

Widget 可以支持多种尺寸，通过 `.supportedFamilies` 指定：

```swift
StaticConfiguration(
    kind: kind,
    provider: DailyReadingGoalProvider()
) { entry in
    DailyReadingGoalView(book: entry.book,
                         message: entry.message,
                         timeOfDay: entry.timeOfDay)
    .environment(\.colorScheme, .dark)
    .containerBackground(for: .widget) {
        Background()
    }
    .widgetURL(URL(string: "bookclub://reading/\(book.bookID)"))
}
.supportedFamilies([.systemMedium])
```

关键点：

- `.supportedFamilies` 限制 Widget 可选择的尺寸，避免在小尺寸上展示过多内容
- `.widgetURL` 给整个 Widget 添加点击跳转链接，用户点击 Widget 时打开对应 App 页面
- 对于需要更细粒度交互的 Widget，可以用 `Link` 或 `Button` 配合 App Intents

### 4. Tinted 模式下的渲染适配

iOS 18 引入了 Tinted Widget 模式，系统会自动把 Widget 内容反色或着色以匹配壁纸色调。如果你的 Widget 包含图片或复杂渐变，需要显式控制渲染模式：

```swift
struct BookCoverImage: View {
    let imageName: String

    var body: some View {
        Image(imageName: bundle: .main)
            .widgetAccentedRenderingMode(.fullColor)
    }
}
```

关键点：

- `.widgetAccentedRenderingMode(.fullColor)` 告诉系统这个图片保持原色，不要被 Tinted 模式着色
- 默认情况下系统会对 Widget 内容应用着色，可能导致图片"毁容"
- 文字和图标通常应该跟随系统着色，保持与壁纸协调；照片和插图应该用 `.fullColor`

## 最佳实践

- **刷新策略**：别滥用 `WidgetCenter.reloadAllTimelines()`。系统对刷新有预算限制，只在数据确实变化且用户可能看到时触发。实时性要求高的内容用 Live Activities，不是 Widget
- **数据共享**：App 和 Widget 通过 App Group 共享 `ModelContainer` 或 `UserDefaults`。SwiftData 数据库放在共享容器里，Widget 用同样的 schema 读取
- **内存控制**：Widget 的内存配额比 App 小得多，避免加载大图或复杂计算。TimelineProvider 应该快速返回数据，不要阻塞
- **背景处理**：使用 `.containerBackground(for: .widget)` 设置 Widget 背景，这是 iOS 17+ 的推荐做法，能正确适配各种模式和尺寸
- **预览支持**：在 Xcode Previews 中为每种 Widget family 和 color scheme 创建预览，确保 Tinted 模式下的效果也正确
