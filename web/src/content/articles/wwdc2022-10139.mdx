## Highlight

> 好的 SharePlay 体验不只是把内容同步播放——它让分隔两地的人感觉像在同一个房间里。这场 session 从设计角度出发，教你识别 App 中适合共享的活动、设计自然的群组交互，以及处理不同活动类型的切换。

## 核心内容

SharePlay 自 2021 年推出后，FaceTime 通话中共享内容的能力已经被不少 App 接入。但仅仅把画面同步过来，不等于做好了 SharePlay 体验。

这场 session 的核心问题是：什么样的活动适合共享？怎么设计才能让群组成员之间的互动自然、直觉化？答案不在 API 层面，而在设计层面。

演讲者指出，好的 SharePlay 体验有三个特征：第一，它选择的共享活动本身就适合多人参与——比如一起看电影、一起听歌、一起锻炼；第二，它让每个参与者都能感受到自己的存在——不只是被动观看，而是可以主动操作；第三，它处理好了"活动切换"这个容易被忽视的场景——从聊天切换到共享内容，再从共享内容切回聊天，这个过程要流畅。

设计 SharePlay 体验的第一步，不是写代码，而是审视 App 中的活动。演讲者建议问自己三个问题：这个活动多人一起做会不会更好？每个人在活动中能做什么？不同参与者看到的内容是否应该不同？这些问题的答案决定了共享体验的基本形态。

在实际设计中，有几个关键细节。首先是"共享状态指示"——用户需要清楚地知道当前正在共享什么、谁在参与。其次是"公平的交互权"——不要让某个参与者成为旁观者，每个人应该有合理的操作空间。最后是"优雅降级"——当某个参与者网络不好或设备性能不足时，体验不能完全中断。

## 设计要点

### 识别适合共享的活动

不是 App 里所有内容都适合 SharePlay。好的共享活动通常有以下特征：

- 活动本身具有社交属性——看电影、听音乐、锻炼、玩游戏
- 每个参与者都能从中获得价值——不管是主动参与还是被动观看
- 活动有自然的开始和结束边界——比如一部电影的时长、一节课的节奏
- 共享状态下体验明显优于单独使用——这是 SharePlay 存在的理由

### 群组交互设计

多人同时操作同一内容时，交互设计需要特别注意：

- 用清晰的视觉语言标识"谁在操作"——比如高亮当前操作者的头像
- 避免冲突操作——如果一个人正在翻页，另一个人不能同时翻页
- 提供"旁观者视角"——不操作的人能看到完整的内容，而不是被操作干扰
- 状态同步要即时——延迟超过几百毫秒就会破坏"在一起"的感觉

### 活动切换

用户在 FaceTime 通话中会自然地在聊天和共享内容之间切换。好的设计要做到：

- 进入共享状态时，过渡动画要平滑，不能让用户感到突兀
- 共享内容的 UI 不能完全遮挡通话界面——用户需要随时能看到参与者
- 退出共享时，保留必要的上下文——而不是直接回到空白状态

## 核心启发

- **先列活动清单，再写代码**：把 App 中所有功能列出来，逐一判断是否适合共享。适合共享的活动数量通常比你想象的多——不仅是媒体播放，协作编辑、一起锻炼、共同浏览都可能是好的候选。

- **设计"每个人都能参与"的模式**：避免设计出只有一个人能操作、其他人只能看的体验。即使是不操作的人，也应该有参与感——比如表情反应、简单的投票或标记。

- **把活动切换当成核心流程来设计**：不要只设计共享状态的 UI，也要设计"进入共享"和"退出共享"这两个过渡状态。这两个过渡体验的好坏，直接决定了用户是否愿意再次使用 SharePlay。

- **用真实多人场景做测试**：单人开发时很难发现群组交互的问题。至少找两个人做真实测试，观察他们在自然对话中如何使用共享功能。
