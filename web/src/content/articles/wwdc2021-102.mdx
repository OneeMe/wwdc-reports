## Highlight

> WWDC 2021 带来了 Xcode Cloud 持续集成服务、Swift 5.5 的 async/await 与 actors 并发模型、RealityKit 2 的 Object Capture（用 iPhone 拍照生成 3D 模型）、Swift Playgrounds 4 在 iPad 上直接构建并提交 App Store 应用，以及 SharePlay 和 Focus 两套新框架。

## 核心内容

每年的 Platforms State of the Union 都是 WWDC Keynote 的"续集"——Keynote 告诉你新功能是什么，PSoU 告诉你这些功能怎么用。今年的内容分成三大板块：开发工具与框架、图形与 AR、用户连接与专注。

Xcode Cloud 是这个板块的重头戏。以前做持续集成，你需要自己搭 Jenkins 或 GitHub Actions，管理证书、配置模拟器、跑测试矩阵，每一步都是手工活。Xcode Cloud 把这一切搬到了苹果的云端，和 Xcode 深度集成，四个步骤就能启动第一次云端构建。

Swift 语言层面，今年最大的变化是并发。async/await、Structured Concurrency、actors 三个特性构成了一个完整的并发编程模型，从语言层面消灭了 completion handler 嵌套和 data race 两大顽疾。

SwiftUI 继续推进全平台覆盖。今年苹果自家 App（Maps、Photos、Shortcuts、Weather、Find My）开始大规模使用 SwiftUI，API 成熟度到了一个新阶段。List 增加了 swipe action、pull-to-refresh、search；新增了 Material 材质效果；macOS 上有了 Table 组件。

RealityKit 2 的 Object Capture 解决了一个很实际的痛点：3D 模型制作又贵又慢。现在用 iPhone 拍一组照片，调用 Photogrammetry API，几分钟就能生成可用于 AR 的 USDZ 模型。

SharePlay 是今年的"社交"基础设施。GroupActivities 框架让你在 FaceTime 通话中同步 App 状态——不只是视频播放，白板协作、一起浏览、一起听音乐都可以用同一个框架实现。

### Xcode Cloud：云端 CI/CD

开发 App 的流程远不止写代码。测试、代码审查、合并、签名打包、分发 TestFlight，每个步骤都需要在不同工具之间切换。Xcode Cloud 把这些步骤整合到一个地方。

创建一个 Xcode Cloud workflow 只需要四步（[02:47](https://developer.apple.com/videos/play/wwdc2021/102/?time=167)）：

1. 选择 Product 和平台
2. 确认 workflow 的默认行为（每次推送都构建）
3. 授权源代码访问
4. 关联 App Store Connect

一分钟内就能完成首次云端构建。构建结果直接显示在 Xcode 的报告导航器中。

Workflow 可以定制得很精细（[06:12](https://developer.apple.com/videos/play/wwdc2021/102/?time=372)）：指定触发条件（每次 PR、每次合并到 main）、选择 Xcode 和 macOS 版本、添加测试计划、配置模拟器矩阵。测试可以在多平台、多设备、多 OS 版本上并行执行。

```swift
// Xcode Cloud workflow 配置示例（在 Xcode UI 中操作）
// 1. 创建 workflow，命名为 "Pull Requests"
// 2. 设置触发条件：target main branch 的每个 Pull Request
// 3. 选择 Xcode/macOS 版本：Public Beta
// 4. 添加 Test Action，选择 iOS test plan
// 5. Xcode Cloud 自动推荐测试用模拟器组合
// 6. 添加 Notify post-action，发送到 Slack
```

关键点：

- Workflow 的 start conditions 控制触发时机，支持分支和 PR 过滤
- 测试可以并行运行在多个模拟器上，包括 beta 版 OS
- Post-action 支持通知（Slack）、自动分发 TestFlight 等
- Xcode 13 新增 gallery view，用截图网格对比不同配置下的 UI 效果
- 崩溃日志从 TestFlight 直接回传到 Xcode Organizer，附带用户反馈

Xcode Cloud 初期免费限量 beta 开放，Developer Program 账户可以在 developer.apple.com 注册（[17:46](https://developer.apple.com/videos/play/wwdc2021/102/?time=1066)）。

### Swift 并发：async/await、Structured Concurrency、Actors

completion handler 写异步代码有三个问题：嵌套导致代码难以阅读、错误处理不一致、容易忘记调用 completion 导致挂起。Swift 5.5 从语言层面解决了这三个问题。

**async/await**（[20:44](https://developer.apple.com/videos/play/wwdc2021/102/?time=1244)）：用 `async` 标记异步函数，用 `await` 等待结果。代码从上到下顺序执行，不再需要嵌套闭包。

```swift
// 旧方式：completion handler 嵌套
func prepareForShow(completion: @escaping () -> Void) {
    dancers.warmUp { _ in
        crew.fetchScenery { scenery in
            stage.set(scenery)
            completion()
        }
    }
}

// 新方式：async/await
func prepareForShow() async {
    await dancers.warmUp()
    let scenery = await crew.fetchScenery()
    stage.set(scenery)
}
```

关键点：

- `async` 关键字标记函数为异步，调用时必须用 `await`
- `await` 表示当前任务可以挂起，让出线程给其他工作
- 错误处理用标准的 `throws` / `try`，和同步代码一致
- 控制流（if/for/while）完全不受影响

**Structured Concurrency**（[23:02](https://developer.apple.com/videos/play/wwdc2021/102/?time=1382)）：用 `async let` 创建并发子任务，编译器保证子任务在父任务返回前完成。

```swift
func prepareForShow() async {
    async let dancersReady = dancers.warmUp()
    async let scenery = crew.fetchScenery()
    // 上面两个任务并发执行，和 prepareForShow 的其他代码并行
    // ...
    let ready = await dancersReady
    let set = await scenery
    // await 保证在这里拿到结果
}
```

关键点：

- `async let` 创建的子任务和父任务并发执行
- 访问 `async let` 变量时必须 `await`，编译器强制检查
- 子任务在作用域结束前必须完成，不会出现"悬空"任务

**Actors**（[24:31](https://developer.apple.com/videos/play/wwdc2021/102/?time=1471)）：actor 是一个保护自身状态的并发原语，同一时间只有一个任务能访问 actor 的内部状态。

```swift
actor TemperatureLogger {
    var measurements: [Double] = []

    func record(_ temp: Double) {
        measurements.append(temp)
    }
}

let logger = TemperatureLogger()
await logger.record(98.6)
// 从外部访问 actor 方法必须用 await，编译器保证互斥
```

关键点：

- `actor` 替代 `class` 声明，自动提供互斥访问
- 外部调用 actor 方法需要 `await`
- actor 内部可以直接访问自己的属性
- `@MainActor` 属性标记必须在主线程执行的 API，编译器自动检查

SDK 层面，苹果重写了大量异步 API 来适配 async/await。URL 加载、文件 I/O、通知中心等都有了 async 版本（[27:42](https://developer.apple.com/videos/play/wwdc2021/102/?time=1662)）。

### SwiftUI：List 增强、Material、Table

SwiftUI 今年的更新集中在三个方向：补齐常用组件、增强跨平台能力、改善开发体验。

**List 增强**（[30:14](https://developer.apple.com/videos/play/wwdc2021/102/?time=1814)）：swipe action、pull-to-refresh、search 都是新 API，每个只需一行代码。

```swift
List(smoothies) { smoothie in
    SmoothieRow(smoothie)
}
.swipeActions {
    Button { smoothie.favorite() } label: {
        Label("Favorite", systemImage: "heart")
    }
}
.refreshable {
    await model.refresh()
}
.searchable(text: $searchText) {
    ForEach(suggestions) { suggestion in
        Text(suggestion.name)
            .searchCompletion(suggestion.name)
    }
}
```

关键点：

- `.swipeActions` 添加滑动操作，支持 leading/trailing
- `.refreshable` 一行实现下拉刷新，自动适配平台样式
- `.searchable` 添加搜索栏，`.searchCompletion` 提供搜索建议
- 新 modifier 支持平台限定：通过 `#if os(iOS)` 或条件编译控制

**Material 材质**（[32:52](https://developer.apple.com/videos/play/wwdc2021/102/?time=1972)）：在背景上叠加 `.background(.regularMaterial)`，内容自动获得 vibrant 渲染效果——文字、符号、分隔线都会根据背景动态调整对比度。

```swift
ZStack {
    Image("background")
    VStack {
        Text("Smoothie of the Day")
            .font(.title)
        Text("Green Detox")
            .font(.headline)
    }
    .padding()
    .background(.regularMaterial)
}
```

关键点：

- `.background(.regularMaterial)` 一行实现磨砂玻璃效果
- 文字、SF Symbols、分隔线自动 vibrant 渲染
- 支持 `.thinMaterial`、`.thickMaterial`、`.ultraThinMaterial` 等变体

**Table 组件**（[31:40](https://developer.apple.com/videos/play/wwdc2021/102/?time=1900)）：macOS 上终于有了原生的多列表格组件。

```swift
Table(smoothies) {
    TableColumn("Name") { smoothie in
        Text(smoothie.name)
    }
    TableColumn("Calories") { smoothie in
        Text("\(smoothie.calories)")
    }
    TableColumn("Rating") { smoothie in
        StarsView(rating: smoothie.rating)
    }
}
```

关键点：

- `Table` 和 `TableColumn` 声明列结构
- 自动支持排序、选择
- 配合 `.searchable` 自动过滤

### Swift Playgrounds 4：iPad 上构建并发布 App

Swift Playgrounds 之前只用于学习编程和快速实验。今年 Swift Playgrounds 4 可以创建完整的 SwiftUI App 项目，在 iPad 上完成编码、预览、上传 App Store Connect 的全流程（[33:41](https://developer.apple.com/videos/play/wwdc2021/102/?time=2021)）。

关键变化：

- 新项目类型：App 项目，不再是 Playground 文件
- 左侧代码、右侧实时预览，和 Xcode Previews 同款技术
- 代码补全出现在插入点下方，支持 SwiftUI 视图、modifier、SF Symbols
- 内置 Snippets 库，可浏览和插入 SwiftUI 组件
- 应用设置面板：名称、强调色、App 图标
- 上传到 App Store Connect，支持 TestFlight 和正式发布
- 项目格式基于 Swift Package，可以和 Xcode 无缝切换

这意味着你可以在 iPad 上开始一个 App 项目，然后切到 Mac 用 Xcode 继续开发，或者反过来（[34:34](https://developer.apple.com/videos/play/wwdc2021/102/?time=2074)）。

### RealityKit 2 与 Object Capture

做 AR App 最难的一步是获取 3D 模型。传统方式需要建模师花数小时、花费数千美元。Object Capture 把这个流程压缩到几分钟，成本降为零（[40:23](https://developer.apple.com/videos/play/wwdc2021/102/?time=2423)）。

流程分两步：

1. 用 iPhone/iPad 围绕物体拍摄一系列照片，覆盖所有角度（包括底部）
2. 在 Mac 上调用 Photogrammetry API 生成 3D 模型

```swift
import RealityKit

// 创建 photogrammetry session
let inputFolder = URL(fileURLWithPath: "/path/to/images")
let session = try PhotogrammetrySession(input: inputFolder)

// 生成模型，指定细节级别
let request = PhotogrammetrySession.Request.modelFile(
    url: outputURL,
    detail: .medium
)
try session.process(requests: [request])

// 监听进度
for try await output in session.outputs {
    switch output {
    case .processingComplete:
        print("模型生成完成")
    case .requestComplete(let request, let result):
        print("请求完成: \(result)")
    default:
        break
    }
}
```

关键点：

- `PhotogrammetrySession` 是入口，指向图片文件夹
- `Request.modelFile` 指定输出 URL 和细节级别（`.preview`、`.reduced`、`.medium`、`.full`、`.raw`）
- 支持自动前景分割，不需要手动抠图
- 输出格式：USDZ（AR Quick Look 优化）、USD、OBJ
- 生成结果可直接拖入 Xcode，用 RealityKit 添加自定义着色器效果

RealityKit 2 还开放了更多渲染控制（[43:24](https://developer.apple.com/videos/play/wwdc2021/102/?time=2604)）：Custom Surface Shader、Procedural Geometry API、Compute Shader 和 Geometry Modifier。可以用来做发光、蒸汽、火焰、粒子等效果。

### Focus 与通知系统重构

iOS 15 重构了通知系统，核心是让用户控制"什么时候被打扰"。新增四个 API 层面：

**Interruption Level**（[52:00](https://developer.apple.com/videos/play/wwdc2021/102/?time=3120)）：通知有四种中断级别。

```swift
// Passive: 静默，不亮屏
let content = UNMutableNotificationContent()
content.interruptionLevel = .passive

// Active: 默认，有声音/触觉
content.interruptionLevel = .active

// Time Sensitive: 突出显示，可突破 Focus
content.interruptionLevel = .timeSensitive

// Critical: 即使静音也响，需要特殊授权
content.interruptionLevel = .critical
```

关键点：

- `.passive` 适合不紧急的通知，用户下次拿起手机时才会看到
- `.timeSensitive` 会突破 Focus 模式和通知摘要，直接送达
- `.critical` 需要 entitlement 审批，仅限健康和安全场景

**Communication Notifications**（[53:17](https://developer.apple.com/videos/play/wwdc2021/102/?time=3197)）：通讯类 App 可以通过新 API 标记消息和来电通知，系统会自动显示头像并优化呈现方式。

**Notification Summary**（[54:00](https://developer.apple.com/videos/play/wwdc2021/102/?time=3240)）：用户可以设置定时摘要，将不紧急的通知打包在指定时间统一推送。开发者可以通过 `relevanceScore` 影响通知在摘要中的排序。

```swift
content.relevanceScore = 0.8 // 0.0 到 1.0，越高越靠前
// 有缩略图的通知也会优先显示
```

**Focus Status API**（[55:40](https://developer.apple.com/videos/play/wwdc2021/102/?time=3340)）：通讯 App 可以请求读取用户的 Focus 状态，在 App 内同步显示"已开启专注模式"。

### Screen Time API

Screen Time API 为家长控制 App 提供了三套新框架（[57:49](https://developer.apple.com/videos/play/wwdc2021/102/?time=3469)）：

- **Managed Settings**：设置应用限制、锁定账户、过滤网页、限制 App 访问，类似系统 Screen Time 的功能
- **Family Controls**：通过 iCloud 凭据授权家长管理，提供系统级的 App/网站选择器，返回 opaque token 而非原始 bundle ID 和 URL 来保护隐私
- **Device Activity**：注册时间窗口，监听 App 使用活动，在超时前发出警告、超时后触发限制

这套 API 的核心设计理念是"家长控制但不泄露隐私"——选择器返回的 token 不暴露孩子具体用了什么 App 和网站，只让控制 App 知道"该不该限制"。

### Widgets 更新

Widget 今年的改进围绕两个方向：iPad 支持和智能建议（[01:02:09](https://developer.apple.com/videos/play/wwdc2021/102/?time=3729)）。

iPad 上新增 extra-large widget 尺寸，支持在 Home Screen 上放置 widget（之前只能在 Today View）。

Widget Suggestions 是更重要的变化：系统会根据用户使用 App 的习惯，自动建议将你的 widget 加入 Smart Stack，即使这个 widget 之前不在 Stack 中（[01:04:14](https://developer.apple.com/videos/play/wwdc2021/102/?time=3854)）。

```swift
// 捐赠 Intent 交互，让系统了解用户行为
let intent = OrderSmoothieIntent()
intent.smoothie = smoothie
let interaction = INInteraction(intent: intent, response: nil)
interaction.donate()

// 也可以主动捐赠相关 Intent 来触发 widget 建议
// 比如生日时赠送免费 smoothie
let birthdayIntent = BirthdayFreeSmoothieIntent()
let birthdayInteraction = INInteraction(intent: birthdayIntent, response: nil)
birthdayInteraction.donate()
```

关键点：

- Widget Suggestions 基于 on-device intelligence，不需要服务端配置
- 两种触发方式：用户行为学习 + 主动 Intent 捐赠
- 用户长按即可将建议的 widget 固定到 Stack

### SharePlay 与 GroupActivities

SharePlay 的核心是 GroupActivities 框架（[01:05:50](https://developer.apple.com/videos/play/wwdc2021/102/?time=3950)）。它在 FaceTime 通话之上建立了一个共享状态通道，让所有参与者的 App 保持同步。

框架提供两种同步方式：

1. **媒体播放同步**：通过 AVPlayer 的 playback coordinator，一行代码实现帧级同步
2. **自定义数据通道**：通过 GroupSessionMessenger 发送任意数据，端到端加密

```swift
import GroupActivities

// 1. 定义 Activity
struct WatchTogether: GroupActivity {
    let contentURL: URL
    var metadata: GroupActivityMetadata {
        var metadata = GroupActivityMetadata()
        metadata.title = "Watch Together"
        metadata.type = .watchTogether
        return metadata
    }
}

// 2. 启动共享播放
func play() {
    let activity = WatchTogether(contentURL: currentVideo.url)
    Task {
        let result = await activity.prepareForActivation()
        switch result {
        case .activationPreferred:
            // 用户确认共享播放
            break
        case .activationDisabled:
            // 不在 FaceTime 通话中
            break
        default:
            break
        }
    }
}

// 3. 同步播放器
func configure(session: GroupSession<WatchTogether>) {
    let player = AVPlayer()
    player.playbackCoordinator.coordinateWithSession(session)
    // 不需要更多代码，系统自动同步播放、暂停、seek
}
```

关键点：

- `GroupActivity` 协议定义共享内容，需要提供 metadata
- `prepareForActivation()` 展示系统确认弹窗，不在 FaceTime 通话中直接返回
- `playbackCoordinator.coordinateWithSession()` 一行实现帧级同步
- 数据通道基于 Group FaceTime 基础设施，端到端加密
- 非媒体 App 可以用 `GroupSessionMessenger` 发送自定义数据

## 核心启发

基于今年 PSoU 的新能力，以下是几个可以立刻动手的方向：

- **做一个 Object Capture 到 AR 的完整 pipeline**：用 iPhone 拍照，Mac 上生成 USDZ，嵌入 AR Quick Look 网页。适合电商、教育、博物馆等场景。从 RealityKit 的 `PhotogrammetrySession` 入手，配合 AR Quick Look 的 HTML embed。

- **把现有 App 的通知升级到 iOS 15 通知系统**：添加 Interruption Level，标记通讯类通知，设置 relevanceScore。这几个 API 改动量很小（每个通知推送加几行代码），但用户的推送体验会明显改善。从 `UNMutableNotificationContent` 的 `interruptionLevel` 属性开始。

- **用 async/await 重构现有网络层**：如果你用 URLSession 做网络请求，iOS 15 的 SDK 已经内置了 async 版本。`await URLSession.shared.data(from: url)` 替代 completion handler，代码量减半。先从最外层的 API 调用开始，逐步向内重构。

- **给 iPad App 加上 extra-large widget**：新尺寸特别适合展示图表、日历、照片网格等内容。用 WidgetKit 的 `.systemExtraLarge` 尺寸，结合 TimelineProvider 提供全天内容更新。

- **集成 SharePlay 到内容类 App**：如果你的 App 涉及视频、音频、或任何"一起消费"的内容，GroupActivities 框架的接入成本很低。先实现 `GroupActivity` 协议，再接入 `playbackCoordinator`。对于非媒体 App，用 `GroupSessionMessenger` 同步状态。
