## Highlight

> iOS 27 给 Wallet Pass 带来了 Poster Generic 新样式、4 种新条码格式、Featured Actions API，以及最重要的——Apple 官方的 Pass Designer 可视化编辑器和 Pass Builder Swift on Server 库。再也不用手写 pass.json 和折腾第三方签名脚本了。

---

## 核心内容

### 1. 这场演讲解决什么问题

开发 Wallet Pass 一直是个"玄学"过程：

- 在文本编辑器里盲写 `pass.json`，靠脑补最终效果
- 图片尺寸和格式要求繁琐，经常因为一张图不对导致整个 Pass 无法加载
- 签名和打包依赖第三方库（Python、Node.js），证书过期或 OpenSSL 版本冲突是常态
- 条码类型有限，某些场景下无法兼容现有扫码设备

Apple 今年给出了完整的官方解决方案：**设计工具 + 服务器库 + 新样式/新条码**。

---

### 2. Poster Generic：全新的 Pass 样式

#### 2.1 样式特点

Poster Generic 是 iOS 27 新增的 Pass 样式，专为**会员系统、忠诚度计划、储值卡**设计：

- **大幅背景图**占据主要视觉区域
- **主 Logo** 叠加在背景上
- **Header Fields**：顶部信息（如会员编号）
- **Primary Fields**：主要内容（如姓名、等级）
- **Footer Field**：底部信息（如商家名称）
- **条码**（可选）

```json
{
  "posterGeneric": {
    "headerFields": [
      {
        "key": "memberID",
        "label": "Guest No.",
        "value": "102035"
      }
    ],
    "footerFields": [
      {
        "key": "membershipType",
        "value": "Family Pass"
      }
    ]
  }
}
```

注意：Poster Generic 只支持**一个 footer field**，如果提供了多个，只有第一个会显示。

#### 2.2 向后兼容

Poster Generic 需要 iOS 27+。为了支持旧版本用户，建议同时提供 `generic` 样式作为 fallback：

```json
{
  "posterGeneric": {
    "headerFields": [...],
    "footerFields": [...]
  },
  "generic": {
    "headerFields": [...],
    "footerFields": [...]
  }
}
```

iOS 27 会优先使用 `posterGeneric`，iOS 26 及更早版本会回退到 `generic`。

### 3. 新条码格式

#### 3.1 四种新类型

iOS 27 新增支持四种条码格式：

- **EAN-13**：国际商品条码
- **Code 39**：常用于工业和医疗领域
- **Codabar**：常用于图书馆和血库
- **ITF**（Interleaved 2 of 5）：常用于物流和仓储

```json
{
  "barcodes": [
    {
      "format": "PKBarcodeFormatCodabar",
      "message": "123456789",
      "messageEncoding": "iso-8859-1"
    }
  ]
}
```

#### 3.2 向后兼容策略

旧版本 iOS 不支持这些新条码格式。强烈建议提供**条码数组**，按优先级排序：

```json
{
  "barcodes": [
    {
      "format": "PKBarcodeFormatCodabar",
      "message": "123456789",
      "messageEncoding": "iso-8859-1"
    },
    {
      "format": "PKBarcodeFormatQR",
      "message": "123456789",
      "messageEncoding": "iso-8859-1"
    }
  ]
}
```

系统会按顺序尝试渲染，优先使用新格式，如果不支持则回退到 QR Code。

#### 3.3 无法提供多条码时的备选方案

如果业务上只能提供一种条码类型：

1. **在 Pass 字段中显示凭证 ID**：使用 `primaryField` 或 `headerField` 把凭证 ID  prominently 展示出来
2. **培训一线员工**：确保工作人员知道在条码无法扫描时可以手动输入

一个无法扫描的 Pass 不应该让用户卡在那里。

### 4. Featured Actions：Pass 下方的快捷操作

#### 4.1 从事件票扩展到所有 Pass

iOS 18 的第二代事件票支持在 Pass 下方显示语义化操作（如"查看活动日程"）。iOS 27 把这个能力扩展到了**所有 Pass 样式**。

```json
{
  "featuredActions": [
    {
      "identifier": "my-offer-id",
      "type": "membershipBenefits",
      "url": "https://www.example.com/offers"
    }
  ]
}
```

每个 action 包含：

- **identifier**：唯一标识
- **type**：操作类型（如 `membershipBenefits`、`viewOffers` 等）
- **url**：点击后跳转的链接

Wallet 会在 Pass 下方渲染一个带有彩色图标和本地化文案的操作按钮。

#### 4.2 使用限制

- 每个 Pass 最多 **2 个 featured actions**
- 按优先级顺序提供，最重要的放在前面
- 只提供最相关、最有意义的操作

### 5. 官方开发工具链

#### 5.1 Pass Designer（Mac App）

Pass Designer 是一个**所见即所得的可视化编辑器**：

- 左侧边栏编辑 Pass 属性（样式、图片、条码、字段）
- 右侧实时预览 iOS 上的真实渲染效果
- 支持拖拽图片、调整颜色、配置字段
- 保存为 `.pkpasstemplate` 模板文件

使用流程：

1. 打开 Pass Designer
2. 选择 Pass 样式（如 Poster Generic）
3. 拖拽背景图、Logo
4. 添加 header/primary/footer 字段
5. 配置条码类型
6. 调整颜色等视觉细节
7. 保存为 `.pkpasstemplate`

#### 5.2 Pass Builder（Swift on Server）

Pass Builder 是一个 **Swift on Server 包**，用于在服务器端批量生成和签名 Pass：

```swift
// Package.swift
import PackageDescription

let package = Package(
    name: "MyServer",
    dependencies: [
        .package(path: "./path/to/PassBuilder")
    ],
    targets: [
        .target(
            name: "MyServer",
            dependencies: [
                .product(name: "PassBuilder", package: "PassBuilder")
            ]
        )
    ]
)
```

```swift
// CreatePass.swift
import PassBuilder

func createPass(for member: MemberModel) async throws -> URL {
    var package = PassPackage(url: "template.pkpasstemplate")
    
    // 注入动态数据
    package.pass.fields.setValue(member.name, forKey: "DOG_NAME")
    package.pass.fields.setValue(member.id, forKey: "MEMBER_ID")
    package.background = PassImage(url: member.photoURL)
    
    // 配置条码
    package.pass.barcodes = [
        Pass.Barcode(message: member.id, format: .pdf417)
    ]
    
    // 配置 Featured Actions
    package.featuredActions = [
        Pass.Action(id: "action-1", type: "viewMembership", url: member.membershipURL)
    ]
    
    // 签名
    let passCertificate = try PassCertificate(url: "pass.p12", password: "s3cr3t")
    let wwdrCertificate = try PassCertificate(url: "wwdr.cer")
    let signer = PassSigner(
        passCertificate: passCertificate,
        wwdrCertifiate: wwdrCertificate
    )
    
    let destinationURL = URL(string: "/www/passes/" + member.id)!
    try signer.signPass(package, writingTo: destinationURL)
    
    return destinationURL
}
```

#### 5.3 设计-构建分离的工作流

推荐的工作流程：

1. **设计师**在 Mac 上用 Pass Designer 设计模板，导出 `.pkpasstemplate`
2. **后端开发者**把模板文件放到服务器上
3. **运行时**根据用户数据填充模板、签名、分发

这样 UI 调整完全在设计师手中，不需要后端参与。

## 最佳实践

- **迁移到官方工具链**：如果你还在用 Python/Node.js 的第三方库生成 Pass，建议迁移到 Pass Builder。这能彻底解决证书过期、OpenSSL 版本冲突等运维问题。
- **采用设计-构建分离模式**：让设计师用 Pass Designer 管理视觉，后端只负责数据注入和签名。把 UI 调整从代码中剥离出去。
- **条码兼容性**：永远在 `barcodes` 数组里提供一个广泛支持的 fallback（如 QR Code 或 PDF417）。不要假设所有扫码设备都支持最新格式。
- **测试旧版本**：在 iOS 26 设备上测试 fallback 行为，确保旧版本用户也能正常使用 Pass。
- **Featured Actions 要精准**：每个 Pass 最多 2 个 action，只放最有价值的操作。不要把"关于我们"这种低价值链接放进去。
- **凭证 ID 要可见**：如果条码可能无法扫描，确保凭证 ID 在 Pass 的 header 或 primary field 中 prominently 显示。
