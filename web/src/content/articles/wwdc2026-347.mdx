## 核心内容

### 1. 这场演讲解决什么问题

LLM 成为 App 的核心组件后，引入了一个全新的攻击面：**间接提示词注入 (Indirect Prompt Injection)**。攻击者在用户不可控的内容里（日历事件、邮件、网页、社交动态）嵌入指令，试图劫持 Agent 的执行流程。

这场 Session 不讲模型安全（model safety）或绕过防护（jailbreak），而是聚焦外部攻击者如何 compromise 你的应用，以及如何用平台 API 防御。

### 2. 威胁建模：你的 App 是不是目标

检查三个条件：

1. **访问私有数据**（日历、照片、通讯录）
2. **暴露于不可信内容**（读取网页、邮件、用户生成的内容）
3. **具备外部副作用**（发消息、扣款、控制设备）

如果三个全中，你的 App 就是攻击者的首选目标。

### 3. Foundation Models 框架的安全机制

#### 3.1 Tool 定义与 Profile 配置

```swift
struct OrderTeaTool: Tool {
    let name = "orderTeaTool"
    let description = "Orders a particular quantity of a tea from the store."
    // 参数定义和实现...
}

struct PostAndFetchPublicFeedTool: Tool {
    let name = "postAndFetchPublicFeedTool"
    let description = "Posts a message to the public feed."
    // 参数定义和实现...
}

class LooseLeafAgent {
    struct DefaultProfile: LanguageModelSession.DynamicProfile {
        var body: some DynamicProfile {
            Profile {
                Instructions("You are a helpful, tea-loving assistant ...")
                OrderTeaTool()
                PostAndFetchPublicFeedTool()
            }
            .model(SystemLanguageModel())
        }
    }
    
    let session: LanguageModelSession
    
    public init() {
        self.session = LanguageModelSession(profile: DefaultProfile())
    }
}
```

#### 3.2 onToolCall — 高风险操作强制用户确认

对于涉及金钱、隐私或不可逆操作的 Tool，在调用前强制弹窗确认：

```swift
var body: some DynamicProfile {
    Profile {
        Instructions("You are a helpful, tea-loving assistant ...")
        OrderTeaTool() // 有财务影响，高风险
    }
    .onToolCall { call in
        guard call.toolName == "orderTeaTool" else { return }
        guard ConfirmationAction.confirmWithUser() else {
            throw LooseLeafError.userConfirmationDenied
        }
    }
}
```

#### 3.3 historyTransform — 标记和脱敏不可信数据

从公共 feed 等不可信来源返回的数据，需要用分隔符标记，防止模型把它当成可信指令：

```swift
var body: some DynamicProfile {
    Profile {
        Instructions("You are a helpful, tea-loving assistant ...")
        PostAndFetchPublicFeedTool() // 返回不可信数据，需要标记
    }
    .historyTransform { entries in
        entries.map { entry in
            guard case .toolOutput(var toolOutput) = entry,
                  toolOutput.toolName == "postAndFetchPublicFeedTool"
            else { return entry }
            
            toolOutput.segments = toolOutput.segments.map { segment in
                delimit(segment: segment,
                        startDelimiter: "<<UNTRUSTED>>",
                        endDelimiter: "<</UNTRUSTED>>")
            }
            return .toolOutput(toolOutput)
        }
    }
}
```

敏感信息（PII）可以直接脱敏：

```swift
.historyTransform { entries in
    entries.map { entry in
        guard case .toolOutput(var toolOutput) = entry,
              toolOutput.toolName == "postAndFetchPublicFeedTool"
        else { return entry }
        
        toolOutput.segments = toolOutput.segments.map { segment in
            redactPII(segment: segment, placeHolder: "[REDACTED]")
        }
        return .toolOutput(toolOutput)
    }
}
```

## 最佳实践

- **做一遍"致命三连"威胁建模**：在接入 Agent 前，检查你的 App 是否同时具备访问私有数据、暴露于不可信内容、具备外部副作用这三个条件。如果全中，必须上最高级别的拦截。
- **Tool 设计原则**：把 Tool 拆细。不要做一个万能的 `ExecuteActionTool`，而是拆成 `ReadDataTool`（无副作用，随便调）和 `WriteDataTool`（有副作用，加 `onToolCall` 拦截）。
- **已有项目迁移**：如果你之前是用 Swift 代码手动拼 Prompt 和解析 JSON 调用函数，尽快迁移到 Foundation Models 框架的 `Tool` 协议。原生的 `onToolCall` 比你自己写正则匹配和函数路由要安全、稳定得多。
- **容易踩的坑**：`historyTransform` 是在每次模型调用前执行的，不是一次性处理。如果对话历史很长，注意性能开销。对于高频调用的 Tool，考虑把脱敏逻辑放在 Tool 实现内部，而不是依赖 historyTransform。
