## Highlight

> Xcode 的 Coding Agent 不是替你设计的工具，而是帮你快速验证想法的协作伙伴——用精准的 Prompt 一次生成多个 UI 变体，在 Preview 里实时对比，把"试试这个布局"的时间从几小时压缩到几分钟。

---

## 核心内容

### 1. 这场演讲解决什么问题

做 UI 设计时，最耗时间的往往不是"实现最终方案"，而是"在十几个方案里找到对的那个"。

传统的流程是：设计师在 Figma 里画稿 → 工程师在 Xcode 里复刻 → 发现不合适 → 回到 Figma 修改 → 再复刻。一个按钮的圆角半径、一个列表的间距，可能要来回倒腾三四轮。

Apple 的解法是把 **Coding Agent** 和 **Xcode Previews** 绑在一起：用自然语言描述你想要的界面，Agent 生成多个变体的 SwiftUI 代码，Previews 实时渲染，你在同一个窗口里就能对比、挑选、组合。

关键是：Agent 生成的是真正的 Swift 代码，不是 mock。选中的方案可以直接作为项目代码继续开发。

---

### 2. 写好 Prompt：从模糊到精准

Agent 的效果完全取决于你的 Prompt。演讲用一个"读书会 App"的例子展示了 Prompt 质量对结果的影响。

**不好的 Prompt：**

```
创建一个管理读书会的 App
```

结果：Agent 自行脑补了投票功能、照片画廊、奇怪的自定义导航栏——很多你根本不需要的功能。

**好的 Prompt：**

```
为读书会管理 App 生成 3 个不同的首页变体。
每个变体必须包含：当前阅读书籍、下次会议时间和地点、成员列表。
不要添加任何我未提及的功能。
每个变体使用独立的 Swift Preview，命名为 ClubHub、Cozy、Minimal。
Cozy 变体使用 New York 字体，营造温暖的咖啡馆氛围。
```

关键点：

- **明确功能范围**：列出必须包含的内容，加上"不要添加未提及的功能"，防止 Agent 脑补。
- **要求多个变体**：一次生成多个方案，而不是在一个方案上反复修改。
- **指定 Preview 名称**：每个变体有独立的名字，方便在 Canvas 里切换对比。
- **给出风格方向**：字体、配色、氛围的描述帮助 Agent 生成更贴合你意图的代码。

---

### 3. 用 Previews 迭代设计

生成多个变体后，Xcode Canvas 里会同时显示所有 Preview。你可以：

1. **横向对比**：一眼看出哪个布局更适合你的内容
2. **实时调整**：修改代码中的参数（如间距、圆角），Preview 立即刷新
3. **组合最佳元素**：把变体 A 的导航栏和变体 B 的卡片样式组合成最终方案

演讲演示了一个典型 workflow：

1. 输入精准 Prompt，Agent 生成 10 个变体
2. 在 Canvas 里点击切换，快速排除明显不合适的
3. 对入围的 2-3 个变体，让 Agent 生成"带实时参数调整滑块"的 Preview
4. 拖动滑块调整圆角、间距、透明度，找到最佳参数
5. 把最终参数写回代码

这种方式把"视觉微调"从"改代码 → 编译 → 看效果"的循环，变成了"拖动滑块 → 实时看到效果"的直观操作。

---

### 4. 用真实内容填充原型

空状态的原型看起来总是比实际好看。演讲建议在 Prompt 中要求 Agent 生成" lived-in "（有生活气息）的内容：

```
用真实的书籍名称、会议时间和地点填充界面。
成员头像使用随机生成的占位图。
添加一条"刚刚加入"的通知横幅。
```

这样你能提前看到：

- 超长书名会不会把布局撑坏
- 成员名字长度不一时列表是否还对齐
- 通知横幅会不会遮挡重要内容

这比在真机上才发现"德语版界面文字溢出"要高效得多。

---

### 5. 动画和交互的微调

SwiftUI 的动画参数（弹簧系数、阻尼、延迟）很难一次调对。演讲展示了让 Agent 生成调试面板的做法：

```swift
// Agent 生成的调试面板示例
struct AnimationTuningView: View {
    @State private var damping = 0.7
    @State private var stiffness = 100.0

    var body: some View {
        VStack {
            // 你的实际 UI 组件
            MyCard()
                .animation(.spring(damping: damping, stiffness: stiffness), value: isExpanded)

            // 实时调整滑块
            Slider(value: $damping, in: 0...1, step: 0.05) {
                Text("Damping: \(damping, specifier: "%.2f")")
            }
            Slider(value: $stiffness, in: 50...200, step: 10) {
                Text("Stiffness: \(stiffness, specifier: "%.0f")")
            }
        }
    }
}
```

在 Preview 里拖动滑块，动画效果实时变化。找到满意参数后，把数值写回生产代码。

## 最佳实践

- **控制 Prompt 的颗粒度**：不要一上来就要求"做一个完整的电商 App"。先让 Agent 生成核心组件（商品卡片、结算按钮）的多个变体，确定视觉基调后再扩展。

- **明确排除不需要的功能**：在 Prompt 里加上"不要添加任何我未提及的导航栏或额外功能"，能避免 Agent 脑补出投票、相册、积分系统等多余模块。

- **用真实数据填充原型**：要求 Agent 用真实长度的文本、不同尺寸的图片填充界面，提前发现布局在极端情况下的问题。

- **为边缘状态生成 Preview**：让 Agent 生成"空数据、超长文本、网络错误"等边缘状态的 Preview 变体，比手动造假数据快得多。

- **不要放弃批判性思维**：Agent 是协作工具，不是设计决策者。最终的用户体验判断权在你手里。
