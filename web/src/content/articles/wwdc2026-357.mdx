## 核心内容

### 1. 这场演讲解决什么问题

把 D3D12 游戏搬到 Mac，最折磨人的不是调 API，而是踩 Apple Silicon 统一内存和 Tile-Based GPU 架构的暗坑。你需要了解：

- Metal 4 的显式同步屏障 (Explicit barrier model)
- 参数缓冲区 (Argument buffer) 的布局差异
- 驻留集 (Residency sets) 的内存管理
- MetalFX 的运动向量和抖动配置

GPTK 4 的 Agentic Skills 把这些领域知识编码成了 AI 助手的"肌肉记忆"。

### 2. GPTK 4 的技能体系

技能分两类：

- **Expert Skills**：提供具体的技术指导，覆盖 Metal 4 API、MetalFX 集成、着色器转换、性能调优等
- **Workflow Skills**：提供结构化的移植方法论，包括发现、计划、执行、验证四个阶段

所有技能通过一个 Porting Assistant Agent 协调，Agent 会自动在正确的里程碑加载对应的 Expert Skills。

安装方式：

```
/plugin marketplace add apple/game-porting-toolkit
/plugin install game-porting-skills@game-porting-toolkit
```

### 3. 发现-计划-执行-验证工作流

**发现 (Discover)**：Agent 分析你的代码库，抓取参考帧 (Reference frames)，询问你的偏好（目标帧率、画质等级等）。

**计划 (Plan)**：你和 Agent 一起制定里程碑目标。整个移植通常太大，需要拆成多个 Session。

**执行 (Execute)**：每个里程碑，Agent 自动加载必要的 Expert Skills，执行代码修改。你在旁边做决策和引导。

**验证 (Validate)**：Agent 检查每个技能的反模式和最佳实践，并与评估环境的参考帧做视觉对比。

### 4. Expert Skills 实战示例

#### 驻留集管理

```
// 使用 Skill 后
residencySet->addAllocation(texture);
residencySet->commit();
// ...
argumentTable->setAddress(texture->gpuAddress(), bindPoint);

// 不使用 Skill（容易遗漏 residency 管理）
argumentTable->setAddress(texture->gpuAddress(), bindPoint);
```

#### 参数缓冲区偏移查询

```
// 使用 Skill
IRRootSignatureGetResourceLocations(m_MtlCurIRRootSig, locations);
size_t offset = locations[i].topLevelOffset;

// 不使用 Skill（硬编码偏移，容易出错）
size_t offset = paramIndex * descriptorSize;
```

#### D3D12 状态到 Metal 4 阶段的映射

```
// 使用 Skill：精确映射 producer/consumer 阶段
m_MtlPendingProducerStages |= MtlProducerStageFromD3D12(OldState);
m_MtlPendingConsumerStages |= MtlConsumerStageFromD3D12(NewState);
// ...
m_ComputeEncoder->barrierAfterStages(
    m_MtlPendingProducerStages,
    m_MtlPendingConsumerStages,
    MTL4::VisibilityOptionDevice);

// 不使用 Skill：粗暴的全局屏障
m_ComputeEncoder->barrierAfterStages(
    MTL::StageDispatch,
    MTL::StageAll,
    MTL4::VisibilityOptionDevice);
```

#### Shader 反射参数计数

```
// 使用 Skill：通过反射获取准确参数数量
IRShaderReflection* refl = IRShaderReflectionCreate();
IRObjectGetReflection(compiledObj, IRShaderStageCompute, refl);
// ...
s_RootSignature.Reset(4, 2); // 反射揭示：4 个参数

// 不使用 Skill：硬编码猜测
s_RootSignature.Reset(5, 2);
```

### 5. 验证机制

Agent 的验证不只是"编译通过"。它会：

- 对比渲染输出和参考帧的像素差异
- 检查反模式（如不必要的全局 barrier）
- 验证 MetalFX 运动向量的符号约定
- 确认 Dedicated present thread 是否正确配置

Agent 会把每次里程碑学到的经验存储下来，跨 Session 复用。

## 最佳实践

- **已有项目的迁移策略**：别一开始就让 Agent 跑全量代码。先跑窗口与帧率控制（Windowing and frame pacing）阶段，确保呈现逻辑和 Metal Display Link 完美契合，再让 Agent 碰 Shader 和渲染循环。
- **新项目的采用建议**：直接用 GPTK 4 的发现阶段生成参考帧，作为后续 Agent 验证的基准真相。没有视觉基准，Agent 的验证阶段就是形同虚设。
- **实战避坑**：Agent 在处理 MetalFX 升频时，经常会忽略运动向量的符号约定和抖动配置。必须在计划阶段把 MetalFX 的专用呈现线程和 HUD 调试覆层作为强制验证项。
