## Highlight

> App Schemas 让 Siri 从"语音遥控器"变成了真正理解你 App 的系统级 Agent——用户说"把这张照片发给 Kevin"，Siri 知道"这张照片"是屏幕上当前展示的那一张，"Kevin"是通讯录里的那个人，不需要你写一句自然语言解析代码。

## 核心内容

### 1. 这场演讲解决什么问题

以前的 Siri 集成体验很生硬：

- 用户必须像念咒一样说出精确指令："打开某某 App，执行某某操作"
- App 的数据对 Siri 是黑盒，Siri 不知道你的 App 里有什么内容
- 跨 App 操作几乎不可能，比如"把这条消息里的地址添加到地图"

今年 Apple Intelligence 重构了 Siri，核心变化是三个"能"：

1. **能访问 App 的内容** —— Siri 可以直接查询你 App 里的消息、任务、照片等实体
2. **能执行 App 的操作** —— 用户用自然语言描述意图，Siri 翻译成 App Intents 执行
3. **能理解屏幕上下文** —— Siri 知道用户当前在看什么，"这个"和"那个"有了具体指向

实现这些能力的关键是 **App Schemas**。

---

### 2. App Schemas：让系统理解你的数据模型

App Schemas 是 Apple 预定义的一套常见 App 类型的数据结构标准。包括：

- Messages（消息）
- Communication（通讯）
- Photos（照片）
- Tasks（任务）
- Notes（笔记）
- ...

你的 App 只要把数据模型映射到对应的 Schema，Siri 就能理解你的内容，不需要你定义自然语言模板。

**定义一个遵循 Schema 的实体：**

```swift
import AppIntents

@AppEntity(schema: .messages.message)
struct MessageEntity: IndexedEntity {
    // 消息正文
    @Property(indexingKey: \.textContent)
    var body: AttributedString?

    // 其他属性...
    var id: String
    var sender: ContactEntity
    var timestamp: Date

    static let defaultQuery = MessageQuery()
}
```

关键点：

- `@AppEntity(schema: .messages.message)` 告诉系统：这个实体是一条消息。
- `IndexedEntity` 协议让内容自动进入 Spotlight 语义索引，用户可以在 Spotlight 里搜到你的 App 内容。
- `@Property(indexingKey:)` 标记哪些字段可以被 Siri 搜索和理解。

**实现实体查询：**

```swift
struct ContactQuery: EntityStringQuery {
    func entities(matching string: String) async throws -> [ContactEntity] {
        let predicate = #Predicate<Person> { person in
            person.name.localizedStandardContains(string)
        }
        let descriptor = FetchDescriptor<Person>(predicate: predicate)
        let matches = try modelContext.fetch(descriptor)
        return matches.map(\.entity)
    }
}
```

当用户说"发给 Kevin"时，Siri 调用 `ContactQuery` 查找匹配"Kevin"的联系人，不需要你写任何自然语言解析代码。

### 3. View Annotations：让 Siri 看懂屏幕

这是今年最实用的功能之一。把 SwiftUI 视图和底层数据实体关联起来，Siri 就能理解"这个"指的是什么：

```swift
List {
    ForEach(messages) { message in
        MessageRow(message: message)
            .appEntityIdentifier(
                EntityIdentifier(
                    for: MessageEntity.self,
                    identifier: message.id
                )
            )
    }
}
```

关键点：

- `.appEntityIdentifier()` 把 UI 上的每一行和背后的数据实体绑定。
- 用户说"把这条消息转发给 Mom"，Siri 知道"这条消息"就是屏幕上高亮的那一行。
- 用户说"解释一下这个"，Siri 知道"这个"是当前展示的实体内容。

这种"屏幕内容即语义上下文"的能力，让语音交互从"精确指令"进化到了"自然对话"。

### 4. 跨 App 内容传递

App Schemas 的另一个威力是跨 App 操作。当多个 App 遵循同一个 Schema 时，Siri 可以在它们之间传递内容：

**导出实体到另一个 App：**

```swift
extension ContactEntity: Transferable {
    static var transferRepresentation: some TransferRepresentation {
        IntentValueRepresentation(
            exporting: \.person
        )
    }
}
```

**导入并处理来自其他 App 的实体：**

```swift
extension ContactEntity: Transferable {
    static var transferRepresentation: some TransferRepresentation {
        IntentValueRepresentation(
            exporting: \.person,
            importing: { intentPerson in
                let contact = Contact(importing: intentPerson)
                ContactManager.shared.contacts.append(contact)
                return contact.entity
            }
        )
    }
}
```

**查询从其他 App 传入的实体：**

```swift
struct ContactEntityQuery: IntentValueQuery {
    func values(for input: [IntentPerson]) async throws -> [ContactEntity] {
        let names = input.map(\.displayName)
        let descriptor = FetchDescriptor<Contact>()
        let contacts = try model.mainContext.fetch(descriptor)
        let matches = contacts.filter { contact in
            names.contains(where: { name in
                contact.name.localizedStandardContains(name)
            })
        }
        return matches.map(\.entity)
    }
}
```

典型跨 App 场景：

- "把这张照片发给 Kevin" —— Photos App 的 `PhotoEntity` → Messages App 的 `sendMessage` Intent
- "用地图导航到这条消息里的地址" —— Messages App 的地址实体 → Maps App 的导航 Intent
- "把这个联系人添加到我的任务指派列表" —— Contacts 实体 → Tasks App 的 `assignTask` Intent

## 最佳实践

- **从核心实体开始接入**：不要试图一次性把全量数据接入 App Schemas。先挑出 App 里最核心的名词（电商 App 的 Product、社交 App 的 Post、通讯 App 的 Message），让它们遵循对应的 Schema。Xcode 会在编译时通过 Fix-It 提示你缺少哪些关联 Schema，顺着提示补齐即可。

- **把 Entity 当作领域模型**：在架构设计阶段就把 App Intents 和 Entity 作为一等公民。不要等 UI 写完了再去硬凑数据模型。让 Entity 成为 App 的领域模型，UI 和 Intent 都去消费它。

- **分层测试**：不要直接对着 Siri 喊话来调试。遵循测试金字塔：
  1. 用 App Intents Testing 框架跑单元测试验证业务逻辑
  2. 在 Shortcuts App 里检查 Intent 的参数映射
  3. 用 Spotlight 搜索确认 `IndexedEntity` 索引生效
  4. 最后上真机测 Siri 端到端

- **为 View 添加 Entity Identifier**：任何可能被用户用 Siri 引用的视图，都应该加 `.appEntityIdentifier()`。这是实现"这个"、"那个"自然引用的基础。

- **实现双向 Transferable**：如果你的 App 既接收内容也发送内容，确保 `Transferable` 的导入和导出都实现了。单向支持会让跨 App 体验断裂。
