## Highlight

> Session 覆盖了 App Store Connect 在 Web、iOS App 和 API 三个层面的更新。

---

## 核心内容

App Store Connect 的麻烦常常不在一个按钮上。

一次营销活动可能同时需要新版 App、应用内活动、自定义产品页和产品页优化测试。以前这些项目容易被拆散处理，审核上下文也会分散。被拒的项目还会影响发布节奏，团队需要反复判断哪些内容可以继续，哪些内容要重新提交。

这场 session 把 2022 年的变化分成两条线：提交体验和 API 自动化。

提交体验把多个审核项目放进同一个 review submission。App Review 可以在同一个上下文里审核它们。多数情况下，团队还可以在已有已批准 iOS 版本之后，单独提交应用内活动、自定义产品页和产品页优化测试，不再为了这些内容准备新二进制。

API 线则面向自动化。App Store Connect API 2.0 会把资源数量扩大 60%，并加入应用内购买、订阅、用户评论回复、App hang 诊断等能力。对有发布后台、运营系统或质量平台的团队来说，这些更新把更多 App Store Connect 操作从网页迁移到可编排流程中。

## 详细内容

### 把多个审核项目组成一次提交

（[01:24](https://developer.apple.com/videos/play/wwdc2022/10043/?time=84)）新的 enhanced App Store submission experience 允许把多个 review items 放入一个 review submission。session 明确列出的 review items 包括 App versions、in-app events、custom product pages 和 product page optimization tests。

一个 review submission 只需要一个 item 就能提交。把多个 item 分组的好处是：App Review 会在同一上下文中审核它们。演讲还说明，review submissions 通常会在 24 小时内完成审核，不受 item 数量或类型影响。

这个机制有一个重要规则：只有 submission 里的所有 items 都被接受，里面的 items 才会被批准。若有项目被拒，团队有两种处理方式：修改被拒项目后重新提交，或把被拒项目移出当前 submission，让已接受的项目完成审核。

```text
review submission
├─ app version
├─ in-app event
├─ custom product page
└─ product page optimization test

if all items are accepted:
  every item becomes approved
else:
  edit rejected items and resubmit
  or remove rejected items and submit them later
```

关键点：
- `review submission` 是送审容器，不是单个功能页面。
- `app version`、`in-app event`、`custom product page` 和 `product page optimization test` 是 session 中明确列出的可提交项目。
- `all items are accepted` 对应演讲里的批准规则：提交内所有项目都接受后，项目才会获批。
- `edit` 与 `remove` 对应被拒后的两种继续方式。

### 不带新版二进制提交营销项目

（[03:24](https://developer.apple.com/videos/play/wwdc2022/10043/?time=204)）新的提交流程还解决了另一个常见问题：营销内容不一定要跟着新版二进制走。

演讲说明，每个 submission 都有关联平台，每个平台支持特定的 review items。App Review 会用一个 App version 作为审核基准。如果 submission 中包含 App version，就用这个版本；如果不包含新版，则需要已有的已批准版本。

这意味着：第一个 iOS 版本获批后，团队可以在任意时间提交 in-app events、custom product pages 和 product page optimization tests，不需要新的 App binary。

```text
approved iOS app version
└─ review against this version
   ├─ in-app events
   ├─ custom product pages
   └─ product page optimization tests
```

关键点：
- `approved iOS app version` 是不带新版提交的前提。
- `review against this version` 来自演讲中“items will be reviewed against this version”的规则。
- 三个子项都是 session 点名可以在首个 iOS 版本获批后单独提交的内容。

### 在 Web、iOS 和 iPadOS 上管理审核

（[04:40](https://developer.apple.com/videos/play/wwdc2022/10043/?time=280)）App Store Connect Web 新增专门的 App Review 页面。进入 App 后，左侧导航的 App Review 可以查看 submissions 概览，也可以进入单个 submission 看详情。

（[05:04](https://developer.apple.com/videos/play/wwdc2022/10043/?time=304)）同一套 enhanced submission experience 也进入 App Store Connect 的 iOS 和 iPadOS App。团队可以从移动设备提交 Ready for Review 的 submissions，跟踪审核进度，接收状态通知，移除 items，查看 rejection reasons，并回复 App Review。

```text
App Review page
├─ submission overview
├─ submission details
├─ App Review messages
└─ recently completed submissions

App Store Connect app on iOS and iPadOS
├─ submit Ready for Review submissions
├─ track review progress
├─ receive status notifications
├─ remove items
├─ view rejection reasons
└─ reply to App Review
```

关键点：
- `App Review page` 是 Web 端集中管理审核流程的新入口。
- `submission overview` 和 `submission details` 对应页面里能看到的总览与详情。
- iOS/iPadOS 列表中的每一项都来自 transcript 中对移动端能力的描述。
- 这里没有新增业务 API，核心变化是审核操作的入口和可移动处理能力。

### App Store Connect API 2.0 扩大自动化范围

（[05:53](https://developer.apple.com/videos/play/wwdc2022/10043/?time=353)）App Store Connect API 用来定制和自动化 App 工作流。演讲提到，上一年 API 已支持 App Clips、Xcode Cloud、in-app events、custom product pages、product page optimization 和 enhanced App Store submission experience。

2022 年夏季的 2.0 release 会让 API resources 数量增加 60%。新增能力集中在三个方向：

```text
App Store Connect API 2.0
├─ in-app purchase and subscription lifecycle
│  ├─ create
│  ├─ edit
│  ├─ delete
│  ├─ manage pricing
│  ├─ submit for review
│  ├─ create special offers
│  └─ create promo codes
├─ customer reviews
│  ├─ fetch reviews
│  └─ respond to reviews
└─ app hangs diagnostics
   ├─ diagnostic signatures
   └─ diagnostic logs relationship
```

关键点：
- `in-app purchase and subscription lifecycle` 覆盖创建、编辑、删除、定价、送审、优惠和兑换码。
- `customer reviews` 增加获取和回复评论能力，用于构建客服或用户互动流程。
- `app hangs diagnostics` 增加 hang 诊断类型，不只提供 hang rate。
- `diagnostic logs relationship` 可获取 hang signatures 的详细 stack traces。

### XML feed 开始退场

（[08:05](https://developer.apple.com/videos/play/wwdc2022/10043/?time=485)）Apple 把 App Store Connect API 2.0 称为四年开发后的重要节点，并表示 REST APIs 是 App Store Connect automation 的未来。因此，XML feed 会在当年秋季开始 decommission。

对已有集成来说，这是一条迁移信号。依赖 XML feed 的发布、报表或内部系统，应该转向 App Store Connect API。

```text
legacy XML feed integration
└─ migrate to App Store Connect API
   ├─ submission workflows
   ├─ in-app purchase workflows
   ├─ customer review workflows
   └─ power and performance diagnostics
```

关键点：
- `legacy XML feed integration` 表示仍在使用旧 XML feed 的系统。
- `migrate to App Store Connect API` 是演讲给出的方向。
- 后续四个 workflow 都来自本 session 提到的 API 自动化范围。

## 核心启发

- **做一个营销内容发布面板**：把应用内活动、自定义产品页和产品页优化测试按 campaign 组织。**为什么值得做**：review submission 可以把多个项目放在同一上下文中审核。**怎么开始**：先在 App Store Connect Web 中按 submission 建模，记录每个 item 的审核状态和被拒原因。

- **把运营发布从 App 发版中拆出来**：让运营团队在首个 iOS 版本获批后独立提交应用内活动和页面实验。**为什么值得做**：session 明确说明这些项目多数情况下不需要新 App binary。**怎么开始**：制定规则：只有涉及二进制功能变化才进入 App 版本发布，其余营销项目走单独 submission。

- **搭建应用内购买后台**：用 App Store Connect API 2.0 管理应用内购买和订阅的创建、定价、送审、优惠和兑换码。**为什么值得做**：API 2.0 把完整生命周期开放给自动化系统。**怎么开始**：从 App Store Connect API 文档中的 in-app purchase 与 subscription resources 开始，把人工操作先映射成内部状态机。

- **集中处理 App Store 评论**：把评论拉入客服系统，再从同一系统回复。**为什么值得做**：API 2.0 增加 fetch 和 respond customer reviews。**怎么开始**：先按 App、国家地区、评分和版本号建立评论队列，再接入回复审批流程。

- **把 hang 诊断接进质量看板**：定期读取 hang diagnostic signatures 和对应 logs。**为什么值得做**：新的 hang diagnostic type 可以定位贡献最多的 hang 位置，并通过 diagnostic logs relationship 查看 stack traces。**怎么开始**：把 hang signature 聚合到现有性能看板，按影响用户数或发生率排序。
