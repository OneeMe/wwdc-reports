## Highlight

> Apple 宣布 Mac 从 Intel 处理器转向自研 Apple Silicon，同时发布 macOS Big Sur、iOS 14（Widgets + App Clips）、iPadOS 14（Sidebar + Scribble）、watchOS 7（SwiftUI 表盘组件）和 Xcode 12。统一架构使未修改的 iPhone/iPad 应用首次可直接在 Mac 上运行。

---

## 核心内容

WWDC 2020 是 Apple 平台历史上转折点最多的一年。这场 Platforms State of the Union 串联了当天 Keynote 宣布的所有重大变化，并给出开发者需要知道的技术细节。

### Mac 转向 Apple Silicon

过去十年，Apple 为 iPhone、iPad、Apple Watch 设计了超过 20 亿颗 SoC。这些芯片在每瓦性能上的积累，现在要带回 Mac。

为什么做这个转变？Apple 的解释很直接：硬件和软件的深度整合带来了其他平台无法提供的体验——统一内存架构让 GPU 无需拷贝就能访问数据、Secure Enclave 保护用户密钥、Neural Engine 加速机器学习推理。把这些能力引入 Mac，意味着 Mac 在性能、能效、安全性上都会有一次飞跃（[01:35](https://developer.apple.com/videos/play/wwdc2020/102/?time=95)）。

对开发者来说，最直接的影响是：**需要构建 Universal 应用**。一个 Universal 应用包含 Apple Silicon 和 Intel 两份二进制代码（arm64 和 x86_64 slice），macOS 根据硬件架构自动选择正确的版本运行（[17:14](https://developer.apple.com/videos/play/wwdc2020/102/?time=1034)）。

构建 Universal 应用只需在 Xcode 12 中选择"Any Mac"目标，Xcode 会自动为两种架构编译。大部分使用标准架构设置（Standard Architectures）的项目开箱即用。Mac Catalyst 应用同样适用——它们虽然使用 UIKit API，但编译为 Mac 原生二进制，一键即可转为 Universal。

对于暂时来不及移植的应用，macOS Big Sur 内置了 **Rosetta 2** 转译层（[23:35](https://developer.apple.com/videos/play/wwdc2020/102/?time=1415)）。Rosetta 2 在安装时就会提前翻译（AOT 编译），Metal 图形指令直接透传给 GPU。演示中 DiRT Rally 在 Rosetta 2 下运行没有掉帧，Affinity Photo 加载 82MP 图像也没有额外内存开销。

另一个重大变化：**未修改的 iPhone/iPad 应用可以直接在 Apple Silicon Mac 上运行**（[32:00](https://developer.apple.com/videos/play/wwdc2020/102/?time=1920)）。因为 iOS 框架在 Apple Silicon Mac 上是二进制兼容的。iOS 应用会自动获得菜单栏、偏好设置窗口、可调整大小的窗口等 Mac 行为。演示中 Monument Valley 和 Documents by Readdle 在 Mac 上运行完整，iOS 的 Photos 编辑扩展也在 Mac Photos 应用中自动出现。开发者可以选择是否将自己的 iOS 应用上架 Mac App Store。

Apple 还提供了 Developer Transition Kit（DTK）：一台外形像 Mac mini、内置 A12Z 处理器的原型机，预装 macOS Big Sur 预览版和 Xcode 12（[16:03](https://developer.apple.com/videos/play/wwdc2020/102/?time=963)）。

### macOS Big Sur 的全新设计

macOS Big Sur 的 UI 经历了一次全面翻新（[37:47](https://developer.apple.com/videos/play/wwdc2020/102/?time=2267)）。核心变化：

**工具栏**：更高，窗口标题与工具栏控件对齐。搜索栏在空间不足时折叠为图标，使用时展开。新增 `NSToolbar` API 和对应的 Mac Catalyst API 来表达三栏布局中的工具栏分区。

**侧边栏**：全高度内容视图加分屏控制器自动适配新结构。SF Symbols 图标支持配置大小和粗细，侧边栏图标大小变化时自动匹配。

**强调色**：应用可以在 Info.plist 中定义专属强调色，影响侧边栏图标、选中色和标准控件颜色。Mail 用蓝色、Notes 用黄色。

**Control Center 和 Notification Center** 首次来到 Mac。Notification Center 完全用 SwiftUI 构建，通知和 Widget 同时展示。macOS 的版本号也从 10.x 跳到了 **macOS 11**（[46:10](https://developer.apple.com/videos/play/wwdc2020/102/?time=2770)）。

Mac Catalyst 也有改进：新增 **Mac idiom**，让 Catalyst 应用以 Mac 原生分辨率运行而非 iPad 比例的缩放界面（[43:12](https://developer.apple.com/videos/play/wwdc2020/102/?time=2592)）。Messages 应用本身就用 Mac Catalyst 重写，获得了 Mac 版的功能对等。

### iPadOS 14：Sidebar、新 Picker 和 Scribble

iPad 应用的交互模式在这一年有了明显变化（[46:28](https://developer.apple.com/videos/play/wwdc2020/102/?time=2788)）。

**Sidebar**：新的三栏布局在所有尺寸的 iPad 上可用，包括竖屏。底层基于 UIKit 和 SwiftUI 已有的 API，增加了 outline 层级展示和折叠功能。Photos 应用把原本在底部 Tab Bar 的 Library 和 Albums 移到了 Sidebar，把更深层的 Favorites 和 Places 也提升到了一级导航。

```swift
// SwiftUI 中启用 sidebar
NavigationView {
    List {
        Label("Library", systemImage: "photo.on.rectangle")
        Label("Albums", systemImage: "rectangle.stack")
    }
    .listStyle(SidebarListStyle())
    Text("Content")
}
```

关键点：
- `SidebarListStyle()` 让 List 自动获得 sidebar 外观
- 在 UIKit 中使用 `UICollectionView` 的新 sidebar 布局样式
- 支持 outline 展示，包含可折叠的层级项目

**新 Picker**：日期选择器支持内联日历样式和紧凑样式（[48:46](https://developer.apple.com/videos/play/wwdc2020/102/?time=2926)）。新增颜色选择器 API 提供标准颜色选择体验，包括保存常用颜色和吸管取色。

**Scribble**：任何 `UITextField` 自动支持手写转文字（[53:44](https://developer.apple.com/videos/play/wwdc2020/102/?time=3224)）。PencilKit 新增 Canvas API 和 Stroke API，Stroke API 在用户书写时实时提供笔触数据（角度、压力、墨水类型、精确位置）：

```swift
// PencilKit Stroke API 获取实时笔触数据
func canvasViewDrawingDidChange(_ canvasView: PKCanvasView) {
    let strokes = canvasView.drawing.strokes
    for stroke in strokes {
        let path = stroke.path          // 笔触路径
        let ink = stroke.ink            // 墨水类型
        let renderBounds = stroke.renderBounds
        // path 中包含每个点的 force、azimuth、altitude 等属性
    }
}
```

关键点：
- `PKCanvasView.drawing.strokes` 返回所有笔触
- 每个 stroke 包含 `path`（带力度的贝塞尔路径）、`ink`（墨水类型）和 `renderBounds`
- `PKStrokePath` 的每个点都有 `force`（压力）、`azimuth`（方位角）、`altitude`（高度角）
- 新增 `DrawingPolicy` API 可以区分手指滚动和 Pencil 绘制区域

### iOS 14：WidgetKit 和 App Clips

iOS 14 最重要的两个新特性（[56:56](https://developer.apple.com/videos/play/wwdc2020/102/?time=3416)）。

**WidgetKit**：Widget 首次可以放在主屏幕。基于 SwiftUI 构建，通过时间线（timeline）机制驱动内容更新。Widget 的渲染不走进程——系统将 SwiftUI 视图序列化为轻量归档文件，在 GPU 上异步渲染，不需要 app 持续运行。

```swift
struct EmojiRangersWidget: Widget {
    var body: some WidgetConfiguration {
        StaticConfiguration(
            kind: "com.example.rangers.widget",
            provider: TimelineProvider()
        ) { entry in
            CharacterStatusView(entry: entry)
        }
        .configurationDisplayName("Character Status")
        .description("See your character's status at a glance.")
    }
}

// TimelineProvider 提供内容更新计划
struct TimelineProvider: IntentTimelineProvider {
    func snapshot(for configuration: ConfigurationIntent,
                  with context: Context,
                  completion: @escaping (Entry) -> Void) {
        // 返回单个 entry 用于 Widget Gallery 预览
    }

    func timeline(for configuration: ConfigurationIntent,
                  with context: Context,
                  completion: @escaping (Timeline<Entry>) -> Void) {
        // 返回一组 entry 和时间表
        let entries = [Entry(date: Date(), character: myCharacter)]
        let timeline = Timeline(entries: entries, policy: .after(.now + 3600))
        completion(timeline)
    }
}
```

关键点：
- `Widget` 协议只需要返回一个 `WidgetConfiguration`
- `TimelineProvider` 决定何时展示什么内容
- `relevance` 分数告诉系统当前内容有多重要，用于 Smart Stack 自动轮换
- Widget 支持三种尺寸：`systemSmall`、`systemMedium`、`systemLarge`
- 通过 Intents 框架实现可配置的 Widget，配置 UI 由系统自动生成

**Smart Stack** 利用 on-device intelligence，根据 relevance score 自动将最重要的 Widget 旋转到栈顶（[59:42](https://developer.apple.com/videos/play/wwdc2020/102/?time=3582)）。

**App Clips**：用户不需要下载完整应用就可以使用 app 的某个功能（[01:03:53](https://developer.apple.com/videos/play/wwdc2020/102/?time=3833)）。App Clip 有 10MB 大小限制，通过 Apple 设计的 App Clip Code 或 NFC 标签触发，支持 Apple Pay 和 Sign in with Apple。

```swift
// App Clip 检测是否从正确位置唤起
import AppClip

if let url = await AppClip.verifyLightweightCode() {
    // App Clip 从预期的物理位置唤起
    // 可以信任此上下文
}
```

关键点：
- 在 Xcode 中新建 App Clip target，将需要的代码加入 target membership
- 去掉不需要的第三方库以保持在 10MB 以内
- App Clip 可以发送 8 小时内有效的通知
- 通过 StoreKit overlay 引导用户下载完整应用，用户数据自动迁移
- `AppClip.verifyLightweightCode()` 验证唤起位置的真实性

### watchOS 7：SwiftUI 表盘组件和 Face Sharing

watchOS 7 将 SwiftUI 扩展到了表盘组件（[01:08:36](https://developer.apple.com/videos/play/wwdc2020/102/?time=4116)）。开发者可以用 SwiftUI 视图构建 complication，支持多个 complication 描述符，每个可以用不同模板。

```swift
// 创建多个 complication descriptor
func getComplicationDescriptors(
    handler: @escaping ([CLKComplicationDescriptor]) -> Void
) {
    var descriptors: [CLKComplicationDescriptor] = []

    // 每个观测站一个 complication
    for station in viewingStations {
        let descriptor = CLKComplicationDescriptor(
            identifier: "station-\(station.id)",
            displayName: station.name,
            supportedFamilies: [
                .graphicCorner,
                .graphicCircular,
                .graphicRectangular
            ]
        )
        descriptors.append(descriptor)
    }

    // 快速记录目击的 complication
    descriptors.append(CLKComplicationDescriptor(
        identifier: "log-sighting",
        displayName: "Log Sighting",
        supportedFamilies: [.graphicCircular]
    ))

    handler(descriptors)
}
```

关键点：
- `CLKComplicationDescriptor` 描述一个 complication 实例
- 每个 descriptor 有唯一 `identifier`，可用于导航到 app 的不同页面
- `supportedFamilies` 指定支持的模板类型
- `getComplicationDescriptors` 返回数组的顺序决定编辑表盘时的显示顺序
- Face Sharing 允许分享表盘配置，接收方可直接从 App Store 下载缺失的 app

### Xcode 12 和 SwiftUI 进展

Xcode 12 的 UI 与 macOS Big Sur 新设计保持一致（[01:13:22](https://developer.apple.com/videos/play/wwdc2020/102/?time=4402)）。文档标签页是编辑器的最大改进，支持双击或 Option+点击在新标签页打开文件，标签页可以按组分批关闭。

StoreKit 测试是另一大亮点。`StoreKitTest` 框架可以在项目中直接配置内购和订阅信息，无需部署到 App Store 即可测试。Xcode 新增 StoreKit Transaction Manager，支持在调试时查看、购买、退款交易，应用实时更新。

SwiftUI 这一年有三个关键进展：

**Lazy Stacks**：在现有 Stack 前加 `Lazy` 前缀即可让大列表按需加载（[01:21:30](https://developer.apple.com/videos/play/wwdc2020/102/?time=4890)）。演示中 20,000 张照片从 500MB 内存降到极低水平，同时保持快速滚动。

```swift
// LazyVStack 替代 VStack，实现按需加载
ScrollView {
    LazyVStack {
        ForEach(photos) { photo in
            PhotoView(photo: photo)
        }
    }
}

// LazyVGrid 用于网格布局
let columns = [GridItem(.adaptive(minimum: 80))]
ScrollView {
    LazyVGrid(columns: columns) {
        ForEach(photos) { photo in
            PhotoView(photo: photo)
        }
    }
}
```

**应用级声明式 API**：用 `@main` 标记应用入口，用 `DocumentGroup` 管理文档创建和打开（[01:24:11](https://developer.apple.com/videos/play/wwdc2020/102/?time=5051)）。

```swift
@main
struct TextEditorApp: App {
    var body: some Scene {
        DocumentGroup(newDocument: TextFile()) { file in
            TextEditor(text: file.$document.text)
        }
        #if os(macOS)
        Settings {
            EditorSettings()
        }
        #endif
    }
}
```

关键点：
- `@main` 标记应用入口，替代 `@UIApplicationDelegate` / `@NSApplicationMain`
- `App` 协议用声明式语法描述应用结构
- `DocumentGroup` 自动管理文档的创建、打开、保存和撤销
- 平台特定功能通过条件编译（`#if os(macOS)`）添加
- Settings scene 在 macOS 上自动生成 Preferences 菜单项

## 核心启发

**1. 为现有 app 制作 Widget**

WidgetKit 让 app 的精华信息直接出现在用户主屏幕。为一个现有 app 添加三种尺寸的 Widget，用 timeline 驱动内容更新。从 `TimelineProvider` 协议入手，为每种尺寸设计不同的 SwiftUI 视图，用 `relevance` 分数让 Smart Stack 在合适的时机展示你的 Widget。

**2. 提取核心功能做成 App Clip**

如果你的 app 有"快速完成一件事"的场景（点单、停车付费、租借），提取这部分功能做成 App Clip。Xcode 中新建 App Clip target，将核心类加入 target membership，通过 URL 路由唤起。去掉不必要的第三方库以保持在 10MB 以内。

**3. 用 Lazy Stacks 优化列表性能**

把现有 SwiftUI 列表中的 `VStack`/`HStack` 替换为 `LazyVStack`/`LazyHStack`。对于网格布局，使用 `LazyVGrid` 和 `LazyHGrid`。这个改动通常只改一个字就能带来数量级的内存改善，对大列表效果尤为明显。

**4. 用 PencilKit Stroke API 做手写批注工具**

PencilKit 的 Stroke API 提供了实时笔触数据（角度、压力、位置）。可以做 PDF 批注工具：在 PencilKit 画布上叠加 PDF 页面，用 Stroke API 追踪批注路径并保存到 PDF annotation 层。所有 `UITextField` 自动支持 Scribble 手写识别。

**5. 将 macOS 应用适配到 Apple Silicon**

打开 Xcode 12，将项目构建目标改为 "Any Mac"，重新编译。大部分 AppKit 应用无需修改代码即可生成 Universal 二进制。有 DriverKit 驱动的外设厂商应趁机从内核扩展迁移到 DriverKit。
