## Highlight

> Apple 与 Google 合作，将 Gemini 技术整合进 Apple Foundation Models。端侧模型在设备本地运行，复杂任务通过 Private Cloud Compute 处理，数据加密后处理即删。年下载量低于 200 万的 App，调用云端模型零费用。Foundation Models framework、App Intents Schema、Core AI 三个框架，构成了今年 Apple Intelligence 的核心技术栈。

---

## 1. 今年的变化从哪来

去年 WWDC25，Apple Intelligence 的核心是端侧模型。好处是隐私安全、零网络依赖；限制也很明显——设备算力有限，稍微复杂的生成任务就力不从心。想做重度 AI 功能的开发者，最终还是要自己接入 OpenAI、Claude 或 Gemini 的 API，自己处理计费、服务器运维和隐私合规。

今年的 Platforms State of the Union 给出了完全不同的路径：Apple 直接与 Google 合作，基于 Gemini 技术构建了下一代 Foundation Models。端侧跑简单任务，复杂推理走 Private Cloud Compute（苹果自己的云端服务器），数据全程加密，处理完成后立即删除，Apple 无法访问具体内容。

（[02:18](https://developer.apple.com/videos/play/wwdc2026/102/?time=138) 开始介绍 Apple Intelligence 架构）

最关键的数字是这个：年下载量低于 200 万的 App，Private Cloud Compute 完全免费。不是试用额度，没有调用次数限制。对独立开发者和小团队来说，这意味着 AI 推理的基础设施成本被直接抹掉了。

## 2. 模型怎么调用

Foundation Models framework 提供统一的 Swift API，覆盖三种调用路径：

1. **端侧模型**：iPhone 本地运行，适合简单任务，零成本、零延迟
2. **Private Cloud Compute**：复杂任务走苹果云端，数据加密处理完即删
3. **第三方 Server models**：需要 Claude、Gemini 等特定模型时，统一协议接入

（[03:18](https://developer.apple.com/videos/play/wwdc2026/102/?time=198) 公布免费额度）

代码层面的变化很直接。去年的 `LanguageModelSession` 是固定配置，今年引入了 **Dynamic Profiles**，允许在同一会话中切换不同模型配置：

```swift
import FoundationModels

let session = LanguageModelSession {
    Profile("Brainstorm") {
        ModelConfiguration(
            model: .privateCloudCompute,
            temperature: 1.0
        )
    }
    Profile("DeepThink") {
        ModelConfiguration(
            model: .privateCloudCompute,
            reasoning: .deep
        )
    }
    Profile("Quick") {
        ModelConfiguration(
            model: .systemLanguageModel
        )
    }
}

session.activeProfile = appState == .brainstorming ? "Brainstorm" : "DeepThink"
```

关键点：

- `Profile` 内部独立配置模型来源、temperature、reasoning 级别
- 切换 Profile 时对话历史连续，不需要重复 prompt
- `.privateCloudCompute` 走苹果云端，`.systemLanguageModel` 走端侧
- 今年新增图像输入能力，可以图文同时传给模型

今年还新增了 **服务器模型** 支持。如果 Private Cloud Compute 不够用，可以通过统一协议接入第三方模型（如 Claude、Gemini），API 形态保持一致，切换时不需要重写调用逻辑。

## 3. App 怎么被系统理解

模型再强，如果它不知道你的 App 在做什么，用户还是只能"打开某某 App"，然后手动翻找。今年 Apple 解决这个问题的方式是 **Schema** 和 **View Annotations**。

（[04:02](https://developer.apple.com/videos/play/wwdc2026/102/?time=242) 讲解 App Intents 与系统 AI 的连接）

**Schema** 是给不同类型的 App 预定义的标准结构。笔记 App 按笔记 Schema 暴露内容，音乐 App 按音乐 Schema 来。系统 AI 不需要开发者教它"用户这句话是什么意思"，它自己就能识别"这是在找一首歌"还是"这是在查一条笔记"。

**View Annotations** 更进一步。在 SwiftUI 里给视图加 `.entity()`，Siri 就知道屏幕上当前展示的具体内容。演示中的例子：用户说"把我上周在海边拍的照片发给 Kevin"，Siri 从相册找到照片、生成消息、确认发送，全程没有打开相册 App。

实现代码只需要在数据模型上加一个注解：

```swift
import AppIntents

@AppEntity(schema: .communication.message)
struct MessageEntity: IndexedEntity {
    var id: String
    var content: String
    static let defaultQuery = MessageQuery()
}
```

关键点：

- `@AppEntity(schema:)` 声明实体所属类别
- `IndexedEntity` 协议让内容自动进入 Spotlight 语义索引
- `.entity()` modifier 把 SwiftUI 视图与底层数据模型关联
- Schema 定义必须精准，类型错误会导致系统 AI 过滤掉你的 App

## 4. 自己的模型怎么跑在 iPhone 上

Foundation Models 适合调用现成的模型。如果你需要跑自己训练的模型（比如识别植物病害的视觉模型、特定领域的分类器），要用 **Core AI**。

（[13:13](https://developer.apple.com/videos/play/wwdc2026/102/?time=793) Core AI 框架发布）

Core AI 是今年的新框架，专门解决"PyTorch 模型如何高效运行在 Apple 设备上"。

转换流程：

```python
from coreai.tools import convert

convert(
    source="my_model.pt",
    target="MyModel.coreai",
    optimization="apple_silicon"
)
```

Swift 端调用：

```swift
import CoreAI

let model = try await CoreAIModel(contentsOf: modelURL)
let result = try await model.predict(input: imagePixelBuffer)
```

关键点：

- Python 工具链一键转换，不需要手写转换脚本
- 自动利用 GPU 和 Neural Engine，开发者不需要管底层调度
- 自带可视化调试器，tensor 值可回溯到原始 Python 源码
- 从 iPhone 轻量模型到 Mac 大模型，同一套 API
- 完全离线运行，零服务器依赖

这个能力直接解决了一个老问题：垂直领域的小模型（识鸟、手语、乐器音准）以前很难部署到移动端，现在训练完转换一下，塞进 App 就能用。

## 5. SwiftUI 和开发工具的变化

AI 能力之外，平台本身也有不少实用更新。

（[21:07](https://developer.apple.com/videos/play/wwdc2026/102/?time=1267) platform improvements）

**SwiftUI 交互扩展：**

- `.reorderable()`：Grid、HStack、VStack 都支持拖拽排序，不再局限于 List
- `.swipeActions()`：走出 List，ScrollView 里的卡片也能左滑删除、右滑收藏
- `.visibilityPriority`：Toolbar 空间不足时，低优先级按钮自动收进 overflow menu
- iOS App 在 iPhone Mirroring 和 iPad 上可调整大小，重新编译后自动支持

**Liquid Glass 自动升级：** 去年已采用 Liquid Glass 的 App，今年自动获得更深的边缘、更亮的高光、用户可调透明度，不需要重新编译。

（[44:16](https://developer.apple.com/videos/play/wwdc2026/102/?time=2656) Xcode 27 演示）

**Xcode 27：**

- **Agent Client Protocol**：任何兼容的 AI Agent 都能接入 Xcode，不限制模型来源
- **Device Hub**：Simulator 和真机管理合并为一个窗口，支持 pinch、双指滚动、动态调整 App 尺寸
- **Xcode Cloud**：一键开启，不需要先配置 App Store Connect，构建速度提升 2 倍
- **Apple silicon only**：安装包减小 30%，启动速度更快

## 6. 什么时候该用，什么时候不该用

**Foundation Models framework 适合：**

- 需要大模型推理但不想自建基础设施的 App
- 对隐私敏感、希望数据不出设备的场景（端侧模型）
- 需要复杂推理但下载量低于 200 万的独立 App（免费云端额度）

**Core AI 适合：**

- 有自己训练的 PyTorch 模型需要部署到移动端
- 垂直领域的识别任务（视觉、音频、手势）
- 需要完全离线运行的场景

**App Intents Schema 必须做：**

- 任何希望被 Siri 和系统 AI 理解的 App
- 核心业务操作（创建、搜索、分享）需要包装成 Intent

**需要注意的限制：**

- Private Cloud Compute 免费额度有下载量上限（200 万），超出后的计费策略尚未公布
- Core AI 转换后的模型体积仍然受设备存储限制
- App Intents Schema 定义错误会导致系统 AI 无法正确匹配
- Xcode 27 不再支持 Intel Mac

---

## 7. 小结

WWDC26 的 Platforms State of the Union 核心是三件事：

1. **Foundation Models framework** 让大模型调用变成系统能力，小团队也能零成本使用云端 AI
2. **App Intents Schema** 让系统理解你的 App，Siri 从"打开 App"进化到"操作 App 里的具体内容"
3. **Core AI** 让自定义 PyTorch 模型高效运行在 Apple 设备上，完全离线

这三个框架叠加，改变了独立开发者做 AI 功能的成本结构。以前需要服务器、API Key、隐私合规的一套流程，现在几行 Swift 代码就能实现。

如果你今天就想试，建议从 App Intents 开始。给一个核心数据模型加上 `@AppEntity(schema: ...)`，重新编译，用户就能通过 Siri 直接操作你的 App 内容。这是门槛最低、回报最直接的一步。
