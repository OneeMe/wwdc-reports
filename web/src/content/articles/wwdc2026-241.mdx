## Highlight

> Foundation Models 框架今年开源了，新增 `LanguageModel` 协议让你可以无缝切换端侧、云端和第三方模型，Dynamic Profiles 用声明式语法管理 Agent 状态，还有内置的 Evaluations 框架让你像写单元测试一样测 AI 准确率。

---

## 核心内容

### 1. 这场演讲解决什么问题

去年 Foundation Models 框架首次亮相时，开发者反馈了几个核心痛点：

1. **模型锁定**：只能用 Apple 的端侧模型，不能换其他模型。
2. **状态管理复杂**：长对话的上下文窗口管理、工具切换、Prompt 拼接，全靠手写胶水代码。
3. **难以评估**：AI 功能的测试靠"肉眼 debug"，没法自动化验证。

今年的更新直接回应了这三个问题：

- **开源**：核心框架和 Utilities 包全部开源
- **`LanguageModel` 协议**：统一抽象层，端侧、PCC、第三方模型无缝切换
- **Dynamic Profiles**：声明式管理模型配置和工具集
- **Evaluations 框架**：像写单元测试一样评估 AI 输出质量

---

### 2. LanguageModel 协议：模型无关的编程

`LanguageModel` 协议是今年的核心抽象。它定义了一组通用能力，任何符合协议的模型都可以接入：

```swift
let model = SystemLanguageModel()

// 查询模型能力
print(model.contextSize)  // 8192

// 计算 token 数量
let count = try await model.tokenCount(
    for: "What are the Japanese characters for origami?"
)
print(count)
```

关键点：

- `contextSize` 让你知道当前模型的上下文上限，据此调整对话历史长度。
- `tokenCount` 帮你精确计算输入占用了多少 token，避免超出窗口。
- 符合 `LanguageModel` 协议的具体实现包括：
  - `SystemLanguageModel` —— Apple 端侧模型
  - `PrivateCloudComputeLanguageModel` —— Apple 云端模型（隐私保护）
  - 第三方模型（通过自定义 executor 接入）

**编程时面向协议，不面向具体实现：**

```swift
// 不要这样
let session = LanguageModelSession(model: SystemLanguageModel())

// 要这样
func createSession(with model: any LanguageModel) -> LanguageModelSession {
    return LanguageModelSession(model: model)
}

// 运行时根据条件选择模型
let model: any LanguageModel = useLocal ? SystemLanguageModel() : PrivateCloudComputeLanguageModel()
let session = createSession(with: model)
```

这样切换模型时，业务代码完全不用改。

### 3. 多模态输入：LLM 能看图了

Foundation Models 今年支持图像输入，API 和文本一样自然：

```swift
let response = try await session.respond {
    "What animal is this?"
    Attachment(UIImage(...))
}
```

关键点：

- `Attachment` 支持 `UIImage`、`CGImage`、`CVPixelBuffer` 等多种图像类型。
- 端侧模型就能处理图像理解，不需要联网。
- 可以图文混合输入，比如"这张 flyer 上的活动是什么时候？"

### 4. 用量监控：知道钱花在哪

使用云端模型时，了解 token 消耗很重要：

```swift
let response = try await session.respond(
    to: "Recommend a craft that doesn't require scissors.",
    contextOptions: ContextOptions(reasoningLevel: .light)
)

print(response.usage.input.totalTokenCount)
print(response.usage.input.cachedTokenCount)
print(response.usage.output.totalTokenCount)
print(response.usage.output.reasoningTokenCount)
```

关键点：

- `input.totalTokenCount` —— 输入总共用了多少 token。
- `input.cachedTokenCount` —— 被缓存的 token 数（重复内容会被缓存，减少计费）。
- `output.reasoningTokenCount` —— 推理过程消耗的 token（Chain-of-Thought 的中间步骤）。
- `reasoningLevel: .light` —— 控制推理深度，`.light` 更快更省 token，`.deep` 更精确但更贵。

### 5. Dynamic Profiles：声明式管理 Agent 配置

Dynamic Profiles 是今年最重磅的新 API。它让你用类似 SwiftUI 的声明式语法定义不同场景下的模型配置：

```swift
struct CraftProfile: LanguageModelSession.DynamicProfile {
    var body: some DynamicProfile {
        Profile {
            Instructions {
                """
                You are an expert crafting assistant. \
                Record craft project image analyses   \
                using the recordImageAnalysis tool.
                """
            }
            RecordImageAnalysisTool()
        }
    }
}

let session = LanguageModelSession(profile: CraftProfile())
```

**根据应用状态切换 Profile：**

```swift
@Observable
final class AppStates {
    var mode: Mode
}

let appStates: AppStates
var session: LanguageModelSession?

func updateSession() {
    let originalTranscript = session?.transcript.dropFirstInstructions() ?? Transcript()

    switch appStates.mode {
    case .craftAnalysis:
        session = LanguageModelSession(
            tools: [RecordImageAnalysisTool(), SwitchModeTool(states: appStates)],
            instructions: "Analyze the user's craft project...",
            transcript: originalTranscript
        )
    case .brainstorm:
        session = LanguageModelSession(
            tools: [RecordBrainstormTool()],
            instructions: "Brainstorm some ideas...",
            transcript: originalTranscript
        )
    }
}

// 状态变化时自动切换
withObservationTracking {
    appStates.mode
} onChange: {
    updateSession()
}
```

关键点：

- 每个 `Profile` 可以有自己的 `Instructions`、`tools` 和 `model` 配置。
- 切换 Profile 时，通过 `transcript: originalTranscript` 保留对话历史，模型不会"失忆"。
- `withObservationTracking` 让状态变化自动触发 Profile 切换。

**带条件的 Dynamic Profile：**

```swift
struct CraftProfile: LanguageModelSession.DynamicProfile {
    let states: CraftProjectStates

    var body: some DynamicProfile {
        switch states.mode {
        case .craftAnalysis:
            Profile {
                Instructions { /* ... */ }
                RecordImageAnalysisTool()
                SwitchModeTool(states: states)
            }
        case .brainstorm:
            Profile {
                Instructions { /* ... */ }
                BrainstormRecordTool()
            }
            .model(states.privateCloudCompute)
            .reasoningLevel(.deep)
        }
    }
}
```

- `.model()` 切换模型来源（端侧 vs 云端）。
- `.reasoningLevel(.deep)` 在需要深度推理时启用更强的推理能力。

### 6. Foundation Models SDK for Python

除了 Swift，今年还发布了 Python SDK：

```python
import apple_fm_sdk as fm

model = fm.SystemLanguageModel()

# 检查模型可用性
is_available, reason = model.is_available()

if is_available:
    # 创建会话
    session = fm.LanguageModelSession(model=model)

    # 生成响应
    response = await session.respond(prompt="Hello!")
    print(response)
```

Python SDK 让服务端脚本、Jupyter Notebook 和机器学习 pipeline 也能使用 Foundation Models。

## 最佳实践

- **面向 LanguageModel 协议编程**：不要硬编码 `SystemLanguageModel`。写一个工厂方法，根据设备条件、网络状态和用户偏好动态选择模型。这样切换模型时业务代码零改动。

- **用 Dynamic Profiles 替代手动状态管理**：如果你现在在手动拼接 System Prompt、维护 Tool 数组、截断 Transcript，迁移到 Dynamic Profiles。它能帮你删掉几百行容易出错的胶水代码。

- **监控 token 用量**：使用云端模型时，定期检查 `response.usage` 的 token 消耗。设置预算告警，避免意外超支。

- **合理选择 reasoningLevel**：简单问答用 `.light`，复杂推理用 `.deep`。不要所有请求都开深度推理，浪费 token。

- **把 Evaluations 接入 CI/CD**：用 Evaluations 框架写测试用例，设定准确率阈值。每次改 Prompt 或换模型都在 CI 里跑一遍，达标再发版。
