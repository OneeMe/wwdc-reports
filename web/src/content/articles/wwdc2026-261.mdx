## Highlight

> Xcode Cloud 今年把入门门槛降到了"连接代码仓库即自动构建"——不需要预先配置 App Store Connect，不需要写复杂的 YAML，甚至不需要离开 Xcode。同时新增的 webhook 和仓库管理工具让高级 CI/CD 工作流也能在云端跑起来。

---

## 核心内容

### 1. 这场演讲解决什么问题

随着 Xcode Agent 的引入，开发者写代码的速度变快了，迭代更频繁了。但问题也随之而来：

- 本地跑完整测试套件越来越慢，拖慢开发节奏
- 手动打包、上传 TestFlight 容易出错且浪费时间
- 团队扩大后，不同开发者的本地环境差异导致"在我机器上能跑"
- 没有系统化的 CI/CD 流程，bug 和性能问题经常漏到用户手里

Xcode Cloud 的解法是：**把构建和测试搬到云端，并行跑在多设备多系统版本上，分发一键完成。**

### 2. 入门：连接仓库即自动构建

今年的 onboarding 流程大幅简化：

1. 在 Xcode 的 Report navigator 中选择 Cloud 标签页，点击 Get Started
2. 选择工作空间中的 product（Xcode 自动匹配 Signing & Distribution 设置的 Developer Team）
3. 连接源代码仓库（GitHub、GitLab、Bitbucket 等都支持）
4. 完成——Xcode Cloud 会自动开始构建和测试

**关键安全说明**：Xcode Cloud 的构建在临时虚拟机上运行，源码只在构建时拉取，构建完成后立即销毁。Apple 不存储源码，也无法访问。

### 3. 分发：从构建到 TestFlight / App Store

构建和测试通过后，可以直接配置分发：

- **TestFlight**：自动把构建版本推给内部测试员或外部测试组
- **App Store**：准备好上架时，同一套配置直接提交审核
- 不需要预先在 App Store Connect 里做复杂设置

### 4. 高级工作流：Webhook 和仓库管理

对于需要更复杂流程的团队：

- **Webhook**：支持自定义 webhook，把 Xcode Cloud 的构建事件（成功、失败、开始）推送到 Slack、Teams、自定义服务器等
- **仓库管理工具**：内置的仓库管理功能让你可以直接在 Xcode Cloud 界面中查看分支、提交历史、PR 状态
- **并行构建**：同时在多个设备和 OS 版本上跑测试，缩短反馈时间
- **构建速度提升**：今年 Xcode Cloud 的构建速度比去年快了两倍

---

## 最佳实践

- **新项目直接上 Xcode Cloud**：不需要等 App 成熟，从第一个 commit 开始就用 Xcode Cloud 跑构建和测试，养成好习惯
- **渐进式配置分发**：先配置 TestFlight 内部分发，让团队每天都能拿到最新构建；等准备发布时再开启 App Store 分发
- **利用 webhook 做通知自动化**：把构建失败通知推到 Slack 频道，确保团队第一时间知道 regression
- **注意构建配额**：Xcode Cloud 有月度构建分钟数限制，合理安排触发条件（比如不在每次本地 push 时都触发，只在 PR 和 main 分支触发）
