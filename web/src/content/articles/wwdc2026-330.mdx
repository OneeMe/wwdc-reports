## Highlight

> Metal TensorOps 现在原生支持量化数据类型（FP8、4-bit 整数等），并且 Cooperative Tensors 可以直接在 matmul 算子之间传递而无需写回内存——这意味着你可以在 Metal 层面手写 FlashAttention，同时榨干 M5 芯片新加入的 Neural Accelerator。

---

## 核心内容

### 1. 这场演讲解决什么问题

大模型推理的瓶颈已经从算力变成了内存带宽。量化（把 16bit 权重压缩到 4bit 或 8bit）是必经之路，但以前在 Metal 里手写量化算子需要处理解包、缩放、内存对齐等繁琐细节。TensorOps 库提供了高层抽象，让你专注于算法而不是硬件细节。

这场演讲从量化数据类型讲起，然后展示如何用 TensorOps 构建自定义 ML kernel（以 FlashAttention 为例），充分利用 M5/A19 的 Neural Accelerator。

### 2. 量化 Tensor：数据类型和 Scale Plane

TensorOps 现在原生支持多种量化数据类型，包括 4-bit/8-bit 整数、4-bit/8-bit 浮点数、以及 2-bit 整数。创建量化 tensor 和创建普通 tensor 几乎一样：

```objc
#define RANK 2

MTLTensorDescriptor *tensorDesc = [MTLTensorDescriptor new];
tensorDesc.dataType = MTLTensorDataTypeMetalFloat8E4M3;
tensorDesc.usage = MTLTensorUsageCompute;

NSInteger dimensions[RANK] = {NumCols, NumRows};
tensorDesc.dimensions = [[MTLTensorExtents alloc] initWithRank:RANK values:dimensions];

NSError *err = nil;
id <MTLTensor> tensor = [device newTensorWithDescriptor:tensorDesc error:&err];
```

量化权重需要 scale factor（比例因子）来把低精度值映射回原始范围。在 macOS/iOS 27 中，scale factor 可以作为 tensor 的附加 plane 直接打包进同一个 `MTLTensor` 对象：

```objc
MTLTensorAuxiliaryPlaneDescriptor *planeDesc = [MTLTensorAuxiliaryPlaneDescriptor new];
planeDesc.dataType = MTLTensorDataTypeMetalFloat8UE8M0;

NSInteger blockFactors[RANK] = {32, 1};
planeDesc.blockFactors = [[MTLTensorExtents alloc] initWithRank:RANK values:blockFactors];

MTLTensorAuxiliaryPlaneDescriptorMap *auxiliaryPlanes =
    [MTLTensorAuxiliaryPlaneDescriptorMap new];
[auxiliaryPlanes setDescriptor:planeDesc forPlane:MTLTensorPlaneTypeScales];

tensorDesc.auxiliaryPlanes = auxiliaryPlanes;
id <MTLTensor> tensor = [device newTensorWithDescriptor:tensorDesc error:&err];
```

关键点：

- `MTLTensorDataTypeMetalFloat8E4M3` 是 8-bit 浮点，4bit 指数 + 3bit 尾数
- `MTLTensorDataTypeMetalFloat8UE8M0` 是 scale factor 专用格式
- `blockFactors` 定义每个 scale 元素覆盖的数据块大小
- 数据、scale 和元数据全部打包在一个 tensor 对象中，简化内存管理

### 3. Metal Shading Language 中的 Tensor 类型

在 MSL 中，量化 tensor 通过模板类型表达：

```metal
#include <metal_tensor>
using namespace metal;

// 定义带 scale plane 的 MXFP8 tensor 类型
using scales_plane = tensor_blockwise<tensor_plane_scales,
                                      device metal_fp8_ue8m0_format,
                                      32, 1>;

using mxfp8_tensor = tensor<device metal_fp8_e4m3_format,
                            dextents<int, 2>,
                            tensor_handle,
                            scales_plane>;

kernel void matmul(mxfp8_tensor matrixA [[buffer(0)]],
                   mxfp8_tensor matrixB [[buffer(1)]],
                   tensor<device half, dextents<int, 2>> matrixC [[buffer(2)]])
{
    // ...
}
```

也可以在栈上内联创建 tensor（不需要堆分配）：

```metal
using mxfp8_tensor_inline = tensor<device metal_fp8_e4m3_format,
                                   dextents<int, 2>,
                                   tensor_inline,
                                   scales_plane>;

mxfp8_tensor_inline matrixA(dataBufferA,
                             dextents<int, 2>(K, M),
                             array<int, 2>({ 1, K }),
                             scales_plane(scalesBufferA));
```

### 4. TensorOps：自动解量化的矩阵乘法

TensorOps 的 `matmul2d` 会自动处理量化 tensor 的解量化，你不需要手动写 bit-shift 和缩放：

```metal
// 切片提取当前 tile
auto tA = matrixA.slice(0, tgid.y * TILEM);
auto tB = matrixB.slice(tgid.x * TILEN, 0);
auto tC = matrixC.slice(tgid.x * TILEN, tgid.y * TILEM);

// 设置 matmul descriptor
constexpr auto descriptor = matmul2d_descriptor(TILEM,
                                                TILEN,
                                                dynamic_length_v<int>,
                                                false,
                                                false);

matmul2d<descriptor, execution_simdgroups<4>> op;

// 运行——TensorOps 自动处理解量化
op.run(tA, tB, tC);
```

关键点：

- `slice()` 提取 tensor 的子区域，零拷贝
- `matmul2d_descriptor` 在编译期确定 tile 大小和矩阵属性
- `execution_simdgroups<4>` 指定用 4 个 simdgroup 协作计算
- TensorOps 内部自动读取 scale plane 并应用缩放，输出是正常精度

### 5. 用 Cooperative Tensors 实现 FlashAttention

FlashAttention 的核心优化是避免把巨大的注意力矩阵写回内存。TensorOps 的 Cooperative Tensors 可以在 matmul 算子之间直接传递中间结果：

```metal
// Q x K 乘法
constexpr auto mul_qk_op_desc = matmul2d_descriptor(/* ... */);
matmul2d<mul_qk_op_desc, execution_simdgroups> mul_qk_op;

auto tQSlice = tQ.slice<D, ROWS_PER_SIMD>(0, sgid * ROWS_PER_SIMD);
auto tKSlice = tK.slice<D, BK>(0, k);

auto ctQK = mul_qk_op.get_destination_cooperative_tensor<
                decltype(tQSlice), decltype(tKSlice), float>();
mul_qk_op.run(tQSlice, tKSlice, ctQK);

// SoftMax：行方向求最大值
auto ctTileRowMax = mul_qk_op.get_row_reduction_destination_cooperative_tensor<
                        decltype(tQSlice), decltype(tKSlice), float>();
reduce_rows(ctQK, ctTileRowMax, reduction_operation::max, -INFINITY);

// 逐元素计算 SoftMax
#pragma clang loop unroll(full)
for (auto it = ctQK.begin(); it != ctQK.end(); it++) {
    auto row_it = ctTileRowMax.map_iterator(it);
    *it = exp(*it - *row_it);
}

// SoftMax x V：复用 cooperative tensor 作为输入
constexpr auto mul_sv_op_desc = matmul2d_descriptor(/* ... */);
matmul2d<mul_sv_op_desc, execution_simdgroup> mul_sv_op;

if (mul_sv_op.is_compatible_as_left_input<float, half, float>(ctQK)) {
    auto ctQKIn = mul_sv_op.get_left_input_cooperative_tensor<
                      float, half, float>(ctQK);
    mul_sv_op.run(ctQKIn, tVSlice, ctO);
} else {
    // 布局不兼容时，通过 threadgroup memory 中转
    ctQK.store(tgTensor);
    simdgroup_barrier(mem_flags::mem_threadgroup);
    auto ctQKIn = mul_sv_op.get_left_input_cooperative_tensor<
                      float, half, float>();
    ctQKIn.load(tgTensor);
    mul_sv_op.run(ctQKIn, tVSlice, ctO);
}
```

关键点：

- `cooperative_tensor` 是 simdgroup 级别的共享存储，不需要写回全局内存
- `get_destination_cooperative_tensor` 为 matmul 输出分配 cooperative tensor
- `map_iterator` 把行 reduction 结果映射到对应元素，用于 SoftMax 的逐行归一化
- `is_compatible_as_left_input` 检查 cooperative tensor 能否直接作为下一个 matmul 的输入，避免不必要的数据搬运
- M5 的 Neural Accelerator 专门加速这种密集的 compute-bound 工作负载

## 最佳实践

- **量化是内存带宽问题的标准解法**：对于大模型推理，4-bit/8-bit 量化可以把内存占用和带宽需求降到原来的 1/4 到 1/2
- **用 TensorOps 而不是手写 kernel**：TensorOps 自动适配不同代 Apple Silicon 的硬件加速，包括 M5 的 Neural Accelerator
- **Cooperative Tensors 减少内存流量**：在 FlashAttention 这类算法中，尽量让中间结果在 cooperative tensor 中流转，避免写回全局内存
- **注意量化 block factor 的选择**：block factor 影响精度和性能的平衡，太小则 scale 开销大，太大则精度损失严重
- **从高层框架开始，只在必要时下沉到 Metal**：Core AI 和 MLX 已经处理了大部分场景，自定义 Metal kernel 只在研究新算子或极致优化时使用
