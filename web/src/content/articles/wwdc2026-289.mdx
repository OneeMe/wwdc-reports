## Highlight

> AppKit 作为 macOS 的元老级框架，历史包袱太重，很多老代码还在用 `mouseDown:` 和追踪循环硬写鼠标交互。macOS 27 终于把 UIKit 早就用熟的 Gesture Recognizers、Control Events 和 State Restoration 全面补齐，还新增了 `NSViewCornerConfiguration` 让圆角对齐自动化，加上 Liquid Glass 材质的自动演进，AppKit 在视觉和交互上终于向现代框架看齐。

## 核心内容

### 1. 这场演讲解决什么问题

AppKit 是 macOS 上最古老的 UI 框架，积累了三十多年的 API。很多"祖传代码"还在用 `mouseDown:`、`mouseDragged:`、`mouseUp:` 这种原始事件处理模式。这不仅代码冗长、容易出 bug，还和 SwiftUI、UIKit（通过 Mac Catalyst）的输入模型完全割裂。

这场 Session 的核心信息是：**Apple 要把 Gesture Recognizers 和 Control Events 作为 AppKit 处理输入的"唯一正解"**。同时，macOS 27 在视觉细节（圆角对齐、Liquid Glass）和用户体验（状态恢复、键盘导航）上也做了大量自动化改进。

### 2. 告别 mouseDown，拥抱 Gesture Recognizers

AppKit 现在全面支持 Gesture Recognizers，和 UIKit、SwiftUI 统一了输入处理模型。

**常见的 mouseDown _override 场景及替代方案：**

| 原来用 mouseDown 做的事 | 现代替代方案 |
|---|---|
| 追踪选择状态 | 观察 `NSCollectionViewItem.selected` 或 delegate 回调 |
| 显示右键菜单 | `NSView.defaultMenu` / `NSResponder.menu` / `menuForEvent(_:)` |
| 拖放 | 现代 dragging delegate，如 `tableView(_:pasteboardWriterForRow:)` |
| 文本选择 | `NSTextSelectionManager`（macOS 27 新 API） |

现代的 dragging delegate 写法：

```swift
func tableView(_ tableView: NSTableView,
        pasteboardWriterForRow row: Int) -> (any NSPasteboardWriting)? {
    let pasteboardItem = NSPasteboardItem()
    pasteboardItem.setString("...", forType: .string)
    return pasteboardItem
}
```

`NSTextSelectionManager` 是 macOS 27 的新 API，它自带 Gesture Recognizers，给任意视图带来双向选择、拖拽、切换等经典 macOS 文本选择行为：

```swift
// 附加到视图并设置文本选择数据源
let selectionManager = NSTextSelectionManager()
// 支持双向选择、拖放、toggle 等
```

### 3. Control Events 来到 AppKit

UIKit 开发者熟悉的 Control Events 现在也在 AppKit 里了。不需要子类化 `NSButton`，直接给标准控件注册事件：

```swift
let button = NSButton()
button.addTarget(
    self,
    action: #selector(trackingEndedOutsideHandler),
    for: .trackingEndedOutside
)
```

关键点：

- 大部分 Control Events 从 macOS 10.11 就开始支持，现在 Apple 正式推荐作为默认方案。
- 可以响应用户驱动的追踪状态变化，不用自己写复杂的 mouseDown 追踪逻辑。
- 和 UIKit 的 API 风格一致，跨框架代码更容易复用。

### 4. 键盘导航自动化

两个 Window 级别的属性，解决两个长期痛点：

```swift
window.autorecalculatesKeyViewLoop = true
```

让 Tab 键导航自动适应视图的增删。以前每次添加或移除输入框，都要手动更新 key view loop，现在系统帮你维护。

```swift
window.preventsApplicationTerminationWhenModal = false
```

确保非关键 Sheet 不会在系统夜间重启更新时阻挡整个 Mac 关机。这对用户来说是"我的 Mac 为什么不能自动更新"的终极解决方案。

### 5. 状态恢复（State Restoration）

macOS 27 让状态恢复变得系统化。你需要做三件事：

**给 Window 设置标识符：**

```swift
@MainActor class MainWindowController: NSWindowController, NSWindowDelegate {
    convenience init() {
        let window = NSWindow(...)
        window.identifier = NSUserInterfaceItemIdentifier(WindowIdentifiers.mainWindow)
        window.setFrameAutosaveName(WindowIdentifiers.mainWindow)
        window.isRestorable = true
        window.restorationClass = WindowRestorationHandler.self
    }
}
```

**保存状态：**

```swift
override func encodeRestorableState(with coder: NSCoder) {
    super.encodeRestorableState(with: coder)
    coder.encode(selectedProduct?.identifier.uuid,
                forKey: RestorationKeys.productIdentifier)
}
```

**恢复状态：**

```swift
override func restoreState(with coder: NSCoder) {
    super.restoreState(with: coder)
    if let productId = coder.decodeObject(
        of: [NSString.self],
        forKey: RestorationKeys.productIdentifier) as? String {
        splitViewController?.selectedProductId = productId
    }
}
```

**在 Window 层级恢复：**

```swift
class WindowRestorationHandler: NSObject, NSWindowRestoration {
    static func restoreWindow(
        withIdentifier identifier: NSUserInterfaceItemIdentifier,
        state: NSCoder,
        completionHandler: @escaping (NSWindow?, Error?) -> Void
    ) {
        if identifier == .mainWindow,
           let window = appDelegate.mainWindowController?.window {
            completionHandler(window, nil)
        } else if identifier == .imageWindow {
            let controller = ImageWindowController()
            appDelegate.imageWindowControllers.append(controller)
            completionHandler(controller.window, nil)
        } else {
            completionHandler(nil, error)
        }
    }
}
```

关键点：

- 状态恢复只存 UI 状态（比如选中的产品 ID），不存业务数据。
- 当视图层级变化时调用 `invalidateRestorableState()` 触发重新编码。
- `restorationClass` 负责在 App 重启后重建 Window 实例。

### 6. 圆角对齐自动化（Corner Concentricity）

macOS 27 引入了 `NSViewCornerConfiguration`，让子视图自动贴合父视图的圆角：

```swift
class LocalWeatherView: NSView {
    override var cornerConfiguration: NSViewCornerConfiguration? {
        let radius: NSViewCornerRadius = .containerConcentric(minimumCornerRadius)
        return .uniformCorners(radius: radius)
    }
}
```

关键点：

- `.containerConcentric` 让子视图的圆角半径自动计算，和父视图完美同心。
- 配合 Liquid Glass 材质使用时，视觉效果更加统一。
- 不需要手动算 padding 或套 mask。

### 7. 菜单栏扩展界面（Expanded Interface）

macOS 27 给 `NSStatusItem` 增加了扩展界面能力，点击菜单栏图标可以展开一个自定义窗口：

```swift
@main class LightAppDelegate: NSObject, NSApplicationDelegate {
    lazy var lightStatusItem: NSStatusItem = { ... }()

    func applicationDidFinishLaunching(_ notification: Notification) {
        lightStatusItem.expandedInterfaceDelegate = self
    }
}

extension LightAppDelegate: NSStatusItemExpandedInterfaceDelegate {
    func statusItem(_ statusItem: NSStatusItem, didBegin session: NSStatusItemExpandedInterfaceSession) {
        // 显示窗口
    }

    func statusItemDidEndExpandedInterfaceSession(_ statusItem: NSStatusItem, animated: Bool) {
        // 隐藏窗口
    }

    func selectedAction() {
        // 执行操作，然后取消会话关闭窗口
        lightStatusItem.expandedInterfaceSession?.cancel()
    }
}
```

## 最佳实践

- **老项目迁移不要想着"一键替换"**。先全局搜索 `mouseDown:` 和 `mouseDragged:`，把那些只为了处理"点击"和"拖拽"的代码换成 `NSClickGestureRecognizer` 和 `NSPanGestureRecognizer`。对于列表选择、右键菜单和拖放，直接用 AppKit 现成的基于视图的 API。

- **新项目必须把 `autorecalculatesKeyViewLoop` 和 `preventsApplicationTerminationWhenModal`** 作为 Window Controller 的标配。前者让键盘导航自动适应，后者确保系统更新不被阻塞。

- **状态恢复只存 UI 状态，不存数据**。不要把整个文档数据塞进 `encodeRestorableState`，只存类似 `selectedProductId` 这样的标识符。数据本身从数据库或文件系统读取。

- **圆角配置配合 Liquid Glass 使用**。macOS 27 编译的 App 自动使用 Liquid Glass，Xcode 27 不再支持回退到旧设计。确保你的自定义视图也正确配置了 `cornerConfiguration`。
