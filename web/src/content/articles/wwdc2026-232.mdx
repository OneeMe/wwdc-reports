## Highlight

> MLX 让 Mac 变成了本地 AI Agent 的完整工作站——不需要 API Key、不需要联网、不需要担心隐私，一条 `pip install` 命令就能在 Apple Silicon 上跑起支持工具调用的 Code Agent，整个 Agentic loop 完全在你的设备内闭环。

---

## 核心内容

### 1. 这场演讲解决什么问题

AI Agent 的概念火了之后，开发者面临三个现实问题：

1. **成本**：跑一个完整的代码重构循环，OpenAI 或 Anthropic 的 API 费用可能让个人开发者破产。
2. **隐私**：把公司核心代码传到第三方服务器，合规团队不可能批准。
3. **延迟**：云端 API 的往返延迟让交互体验卡顿，尤其是需要多轮工具调用的 Agent 场景。

本地运行是理想的解决方案，但之前的问题也很明显：模型量化后质量下降、长上下文下性能崩溃、缺乏与现有 Agent 框架的兼容性。

Apple 的解法是 **MLX 四层本地 AI 栈**：

| 层级 | 组件 | 作用 |
|------|------|------|
| 应用层 | OpenCode、Xcode Agent | 用户交互界面 |
| 协议层 | MLX-LM Server (OpenAI-compatible) | 提供标准 HTTP API |
| 模型层 | MLX-LM | 模型加载、量化、推理 |
| 计算层 | MLX | Apple Silicon 上的数组计算和 Metal 加速 |

这个栈的关键设计是 **MLX-LM Server 完全兼容 OpenAI 的 API 协议**。这意味着任何支持自定义 API endpoint 的 Agent 工具（如 OpenCode、Claude Code、Continue.dev）都可以直接指向本地服务器，零代码改动。

### 2. 五分钟搭建本地 Agent

**第一步：安装 MLX-LM**

```bash
pip install mlx-lm
```

**第二步：启动本地服务器**

```bash
mlx_lm.server --model mlx-community/Qwen-3.5-4B-8bit
```

这一步会自动从 HuggingFace 下载量化后的模型（约 4GB），然后在 `http://127.0.0.1:8080` 启动一个兼容 OpenAI API 的服务器。

**第三步：验证服务器**

```bash
curl -X POST \
  http://127.0.0.1:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"default_model","messages":[{"role":"user","content":"Hello!"}]}'
```

**第四步：配置 Agent 使用本地服务器**

以 OpenCode 为例，在配置文件中添加 MLX provider：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "mlx/default_model",
  "small_model": "mlx/default_model",
  "provider": {
    "mlx": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "MLX (local)",
      "options": {
        "baseURL": "http://127.0.0.1:8080/v1"
      },
      "models": {
        "default_model": {
          "name": "Default MLX Model"
        }
      }
    }
  }
}
```

关键点：

- `baseURL` 指向本地服务器，数据不会离开你的机器。
- `mlx-community/Qwen-3.5-4B-8bit` 是一个 4B 参数的量化模型，在 M3 Mac 上推理速度足够支撑代码补全和简单重构。
- 模型第一次启动时会下载到本地缓存，之后离线也能用。

### 3. Agent 能做什么：从聊天到工具调用

传统的 LLM 聊天是"你问一句，它答一句"。Agent 的核心区别是**模型可以决定调用工具**。

Agentic loop 的工作流程：

1. 用户给 Agent 一个任务（如"总结最近的 PR"）
2. Agent 把任务发给本地模型
3. 模型决定需要调用哪些工具（如 `gh pr list`）
4. Agent 执行工具，把结果返回给模型
5. 模型基于工具输出决定下一步（如"读取 PR #42 的 diff"）
6. 循环直到任务完成

演讲演示了一个实际场景：让本地 Agent 获取 MLX 仓库的最近 PR、总结变更、识别需要关注的内容。整个过程中：

- 模型运行在本地 MLX 上
- GitHub CLI 命令访问网络获取 PR 数据
- 只有 git 命令出网，代码和对话完全本地

### 4. 从单设备到分布式

如果你的 Mac 内存不够跑大模型，或者想让推理更快，MLX 支持把多台 Mac 组成集群。

```bash
mlx.launch --hostfile hosts.json \
  --backend jaccl \
  /remote/path/to/mlx_lm.server \
  --model mlx-community/Qwen-3.5-122B-A3B-8bit
```

关键点：

- `hostfile` 描述集群中的每台 Mac 的 SSH 地址和网络配置。
- `jaccl` 是 Apple 开源的集合通信库，利用 Thunderbolt 5 的 RDMA 实现高速互联。
- 四台 M3 Ultra 可以跑起 122B 参数的模型，延迟和吞吐量接近云端 API。

分布式推理的详细配置在 Session 233 中深入讲解。

### 5. MLX 的硬件加速

MLX 是专门为 Apple Silicon 设计的数组计算框架，几个关键优化让本地 LLM 推理变得实用：

- **统一内存架构**：CPU 和 GPU 共享同一块内存，不需要在 PCIe 上传输数据。M3 Max 的 128GB 统一内存可以直接加载 70B 参数的量化模型。
- **Metal 性能着色器**：矩阵乘法、注意力计算等核心操作都用 Metal 加速。
- **懒加载（Lazy Evaluation）**：计算图在真正需要结果时才执行，方便做全局优化。
- **量化支持**：MLX-LM 自动处理 4-bit 和 8-bit 量化，把模型体积压缩到原来的 1/4 到 1/2，精度损失可控。

## 最佳实践

- **从云端迁移到本地**：如果你目前在用 OpenAI 或 Anthropic API 做代码补全或文本处理，迁移成本很低。把 `baseURL` 从 `https://api.openai.com/v1` 换成 `http://127.0.0.1:8080/v1`，其余代码基本不用改。

- **选择合适的模型尺寸**：不是所有任务都需要 70B 模型。代码补全用 4B-7B 就够了；复杂推理才需要 30B+。MLX 社区提供了大量预量化模型，按场景选择即可。

- **管理上下文长度**：Agent 循环会产生极长的上下文。如果本地模型越跑越慢甚至 OOM，检查 Agent 框架是否做了上下文截断或摘要。启动服务器时可以用 `--max-tokens` 限制输出长度。

- **利用 Xcode Agent 集成**：MLX 本地服务器可以直接接入 Xcode 27 的 Coding Agent。在 Xcode 设置中添加自定义模型 endpoint，Agent 的所有操作都在本地完成。

- **多台 Mac 组集群**：如果你有多台 Mac（比如工作室环境），用 Session 233 介绍的分布式配置把它们组成集群，可以跑更大的模型或同时服务多个开发者。
